# 画面キャプチャによる見た目の比較

CSSのリファクタリングのように「**中身は作り直すが見た目は1画素も変えない**」
変更を、目視ではなく機械で確かめるための仕組み。

```
tests/visual/run.sh base      # 変更前を撮る   → shots/base/
   （ここでリファクタリングする）
tests/visual/run.sh head      # 変更後を撮る   → shots/head/
tests/visual/run.sh compare   # 1画素ずつ突き合わせる（差分画像は shots/diff/）
```

`shots/` は `.gitignore` 済み。撮り直せば同じものが得られるのでコミットしない。

## 撮り比べを成立させるためにしていること

同じコードで2回撮っても、何もしなければ**45枚中22枚がずれた**。
原因を潰した順に:

| 揺れの原因 | 対処 |
|---|---|
| 画面内の時計・経過時間（JS側） | `Date` を `2026-08-06T09:30+09:00` に固定 |
| アニメーション・遷移・キャレットの点滅 | `transition/animation:none`・`caret-color:transparent` |
| データの残り | 撮る前に `tests/make_fixture.py` で種データへ戻す |
| スクロールバーの有無 | 幅0にする |
| **サーバーが計算して返す経過分** | **撮影直前に画面の数字をすべて `0` に置換** |

最後のものが厄介だった。タイムラインの「◯分経過」やダッシュボードの見込み分は
**サーバー側の時刻**から計算されるため、ブラウザの `Date` を固定しても進む。
サーバーに検証専用の分岐を入れるのは本番コードを汚すので、表示側を均している。

- base と head に**同じ変換**をかけるので、残った差は必ずCSS起因。
- 桁数は変えないため、折り返し・列幅・文字の位置はそのまま検証できる。
- 値そのものの正しさは `tests/run_all.sh` の担当。ここは見た目だけを見る。

## 比較の実装

`pngdiff.py` は **標準ライブラリ(zlib)だけ**でPNGを読む。Pillow や pixelmatch を
使うと、実機(Windows)側の検証環境にも同じ依存を用意することになるため。
8bitのRGB/RGBA/グレースケール・非インターレース（Playwrightの出力形式）に対応し、
それ以外は明示的に落とす。

差分画像は「変わった画素を赤、変わらない画素を薄く」描くので、どこが動いたかを
目で追える。

## 撮っている画面

一覧（仕掛・品質）／作業スケジュール（個別・全体・各ポップアップ）／
ダッシュボード3ビュー／実績カレンダー／マスタ管理16タブ／データ一覧／
測定画面（基本情報・品質等級・幅分割情報・測定データ分析・入力内容2種・
条割ダイアログ・異常位置判定・帳票）／表示サイズ xs・xl ／メニュー畳み込み／
幅1280 の計45枚。

新しい画面を足したら `capture.js` の巡回にも足すこと。撮っていない画面は
「変わっていないこと」を誰も保証しない。
