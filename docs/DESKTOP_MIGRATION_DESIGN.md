本物の WebView2（Windows）の自己診断は CI（`.github/workflows/desktop.yml`）が受け持ち、**20/20 で通った**（数値は§9.546）。以下は最初の事前確認。

Tauri/Rust/Python に変換し、ポートによる影響や得意な分野ごとに分けて対応させたい。心配は、データベースの共有管理が

## 1. 結論（共有DBの管理は保てるか）

**保てる。ただし条件が1つと、移し替えが要る物が1つある。**

- **条件: 共有DBを扱う層は Python のまま動かす**（DPA と同じ分け方。Rust へは移さない）。共有の仕組みは
  「共有フォルダ上のファイル（錠・改訂番号・目印・在席）」と「書込役の LAN の受け口」でできていて、
  **画面のポート（127.0.0.1:5029）を1か所も使っていない**（§3 の E1＝0件）。窓口がポートからパイプに
  変わっても、同じ Python のコードが同じファイルへ同じ手順で書く。ブラウザ版の PC とデスクトップ版の PC が
  混ざっても、互いに同じ作法で錠を取り合う。
- **移し替えが要る物: 端末の中の測定データ（IndexedDB と localStorage の写し）。** 置き場がブラウザの
  「オリジン」ごとに分かれるので、`127.0.0.1:5029` から `wavelog.localhost` へ変わると**見えなくなる**。
  共有へまだ送れていない記録（`syncState.status!=='synced'`）は**ここにしか無い**。移行の段取りに
  端末の作業場所の「控え」へ常に写す（§8。P3）。

## 4. 共有DBとは別に、手当てが要る所

窓口とオリジンが変わることで動きが変わる所。どれも共有DBの手順そのものには触らない。

1. **終わり方。** いまは「タブが0件になって8秒（届かなければ90秒）」で `watchdog.teardown()` を通って終わる。
   デスクトップ版では**窓を閉じる→標準入力が閉じる→同じ `teardown()` を通って終わる**ようにする
   （片付けの1箇所はそのまま。通る道を1本足す）。Rust が強制終了されても、OS がパイプを閉じるので Python は残らない。
   **P1 で済み**（0.02秒）。画面の終了ボタン（`/api/app/quit`）は今と同じく Python が片付けて終わるので、窓は
   「中身が終わった」を見て自分も閉じる（P2）。
2. **端末の設定（localStorage 約62件・sessionStorage 1件）。** 列の並び・窓の位置・プリセット・ICASコピーの規則
   （`scLotCopyRulesV1`・端末にしか無い）・使用設備（`AccessMeasurementConfiguredEquipment`・端末にしか無い）など。
   DPA の §4 と同じく、端末の作業場所の控えへ「変わった名前だけ」重ね、新しいオリジンで開いたときに戻す。
3. **LotData-Link。**【[§9.550](decisions/9.550.md)で済んだ】Edge の拡張は WebView2 の中では動かない。LotDsp を開く（`window.open`）のは外のブラウザ（PC の既定のブラウザ。Edge が既定なら LotData-Link が効く）へ
   回すので、**ロット問い合わせと自動ログインは今までどおり使える**。使えなくなるのは、WaveLog の画面が拡張を見つける
   合図（`<html data-lotdsp-ext>`）と、そこから開く登録画面（`wl:lotdsp-options`）。使用設備の設定③は
   「入っていない」と誤って言わず、「デスクトップ版からは確かめられない・Edge で登録する」と言い分ける。
4. **ファイルのドロップ。** マスタ管理の取り込み（`master-maint.js`）はエクスプローラーからのドロップを読む。
   Tauri は既定で窓へのファイルのドロップを横取りするので、窓の設定で切る（`dragDropEnabled:false`）。
   `text/uri-list` で渡る道が WebView2 で同じかは**分からない**（実機で確かめる）。
5. **印刷と保存。** 隠した `<iframe>` からの印刷・`@page` の差し込み・`Blob` の保存・`Content-Disposition` の
   ダウンロードは、WebView2 でも動く見込みだが、**Windows の実機では確かめていない**（DPA も同じく未確認）。
6. **クリップボード。** `navigator.clipboard` は安全な文脈でだけ使える。`http://wavelog.localhost` は
   `*.localhost` なので安全な文脈に入る見込み（自己診断で確かめる）。

## 6. 役割の分け方（得意な分野ごと）

| 受け持つもの | 何を | 理由 |
| --- | --- | --- |
| **Rust**（`desktop/`） | 窓、起動と終了、1つだけ起動、起動画面（`loading.html` の役）、`/static/` の配信、Python の監督と起こし直し（「再起動待ち」・§9.200 も殻が起こし直せる）、外のリンク | OS の窓・プロセス・ファイルを直接扱える。ポートのための推し量りが要らなくなる |
| **Python**（`backend/`・そのまま） | 画面の HTML・API のすべて、**共有DBの書込サイクル・写し・在席・書込役**、RNE 抽出（Navigator の DLL）、Excel の読み書き、計算 | 共有の手順は網で固めてあり、移行のあいだブラウザ版と**同じコード**で動くことが混在の安全の根拠になる。遅さの原因は意図した待ち（錠の確かめ）で、言語の速さではない |
| **画面**（WebView2） | これまでと同じ HTML/JS/CSS。問い合わせは相対の `fetch` のまま | 変えない |

**Rust へ移さない物: 共有DBの書込サイクル・写し・在席・書込役。** 移すと、移行のあいだ Python の PC と
1バイト違わない手順で錠と改訂番号を取り合う必要が生まれ、利点（速さ）に対して危うさ（黙って上書き）が大きい。
`/css/*.css` の連結（`routes/core.py`）は Python が答える（殻の `/static/` 直配りの対象外）。

## 7. 利用者の答え（2026-10-02）と、exe を手元へ写す理由

1. **exe は端末の手元へ写してから使う。**
2. Defect-Pitch-Analyzer の署名の無い exe は**社内の PC で動いた**（SmartScreen・AppLocker の懸念は解けた）。
3. 移行のあいだは**ブラウザ版と併存**し、PC ごとに切り替える。
4. P1 から始める。

**Box の上の exe を直に起動しない理由**（写さない場合に起きうること）:

- **動いている exe は置き換えられない**（確か）。Windows は実行中の exe のファイルを掴んだまま
  使う（中身を少しずつ読み込む）ので、上書きも削除もできない。
- **更新がその PC だけ止まる**（見込み・Box Drive の実機では未確認）。新しい版を Box へ置いたとき、exe を
  開いたままの PC では Box Drive が手元の写しを置き換えられず、その PC だけ古い exe が残る（同期の失敗として
  後で再試行される）。**`.py`・`.js` は読み終えると掴まないので先に新しくなる**——結果、
  「窓（Rust）は古い版・中身（Python）は新しい版」という食い違った組み合わせで動く。
  枠の約束（ヘッダーの鍵・知らせの種類）が変わる更新では、窓口が話せなくなる。
- **更新を置く側も詰まる**。開発の PC で exe を開いたまま新しい版を置こうとすると、自分の PC で置き換えが
  失敗し、Box に「競合のコピー」ができうる（見込み）。
- **「オンラインのみ」のファイル**だと、起動のたびに Box から取り寄せる（数十MB）。

写す方式では、版ごとのフォルダ（`%LOCALAPPDATA%\WaveLog\desktop\<版>\`）へ写して起動する。動いている古い版の
ファイルには触らないので置き換えで詰まらず、次の起動から新しい版になる。古い版は**動いていないときだけ**
片付ける（消えても取り直せるもの・§9.249）。exe は `program/` の隣に無くなるので、`program/` の場所は
起動するとき窓へ渡す。窓と中身の版のずれは、窓口の「準備できた」の知らせにある枠の約束の版（`protocol`）で
窓が見分け、「開き直してください」と言う（P1 で知らせに入れた）。

## 8. 端末の中の測定データ（P3・済み——[§9.545](decisions/9.545.md)）

**ファイルは作る。ただし一時置き場（`%TEMP%`）ではなく、端末の作業場所に「控え」として置き、1回きりではなく
保存のたびに写し続ける。**

なぜ一時置き場ではないか:
- `%TEMP%` は Windows のストレージセンサー・ディスククリーンアップが消す。**共有へ送れていない記録は
  そこにしか無くなる**ので、消えうる場所には置かない。
- `db/`（Box の上）にも置かない——他の PC へ同期され、端末ごとの持ち物が混ざる。

なぜ1回きりの引き継ぎではないか:
- **併存する**（答え3）。同じ PC でブラウザ版とデスクトップ版を行き来するので、片方へ1回写しただけでは、
  その後に片方で直した記録がもう片方に見えない。
- **アドレスを同じにしても解けない**。WebView2 と Edge は保存領域（ユーザーデータのフォルダ）そのものが別なので、
  ブラウザの設定ではどうやっても互いの IndexedDB を見られない。両方が届くのは Python だけ。

形:
- 置き場: 端末の作業場所（`paths.local_root()/terminal/terminal.sqlite3`）の SQLite 1つ。読み書きするのは **Python だけ**
  （ブラウザ版の Python とデスクトップ版の Python のどちらも）。**窓（Rust）は Start.vbs と同じ Python を使う**ので、
  Microsoft Store 版の Python でも両方が同じ写しを見る（窓が控えを直に読むことはしない）。
- 中身: 測定の記録の全件（記録ID・更新時刻・中身・送ったかどうか）、消した印（消した時刻）、端末にしか無い設定
  （使用設備・ICAS コピーの決まり・送り待ちの削除・画面の設定の控え）。
- 書くとき: 画面が端末へ保存する瞬間（`reliablePut`／削除）と同じときに控えへも書く。**手元のディスクなので、
  共有が落ちていても書ける**（共有へ送れないときこそ要る）。
- 読むとき: 画面を開いたら、ブラウザの保存領域と控えを記録IDごとに突き合わせ、**更新時刻の新しいほう**を採る
  （物差しは今の「共有のほうが新しい」と同じ`updatedAt`）。消した印が新しければ消す（消したものが戻らない）。
- 順序: ① P3 の変更を**先にブラウザ版で配る**（開いた時点で手元の全件を控えへ吸い上げ、印を付ける）。
  ② デスクトップ版は初めて開いたとき控えから戻す。③ 安全網として、窓は Edge に`127.0.0.1:5029`の保存領域が
  在る（フォルダが在るかだけを見る）のに吸い上げの印が無ければ、「ブラウザ版を1回開いてください（自動で
  引き継ぎます）」と言う。
- 副産物: 今のブラウザ版でも、Edge の「閲覧データの削除」で IndexedDB が消えると未送信の記録は失われる。
  控えがあれば戻せる——**今ある危険も同時に消える**。

評価関数 E6（`test_terminal.js`・2つのオリジンで測る）: 共有へ送っていない記録がもう一方の窓で開ける・
新しいほうが両方向に勝つ・消した記録が戻らない・設定が両方向に届く・初めての窓は手元が正・送る前に読み直した
変更は手元が勝つ——**23/23**（[§9.545](decisions/9.545.md)）。

## 9. 分からないこと（利用者の確認が要る）

- Box Drive が、開いている exe の更新をどう扱うか（§7 の「見込み」）。P5 で写す方式にするので、実害は出ない見込み。
- Microsoft Store 版の Python。殻（Rust）は Python が `AppData` に書いた物を**読めない**ことがある（§9.318・§9.496）。
  殻が読む物は殻が書くか、`paths.browser_dir()` を通す。殻が書いて Python が読む向きは問題ない見込み。
