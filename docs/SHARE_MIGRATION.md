# 共有の置き場への移行手順（`\\nlmsrvngy03\工場内共有\検査データ\Records`）

対象は3つ。**それぞれ直す場所も効くタイミングも違う**ので、
分けて書く。画面での確認は **マスタ管理 > 共通設定 > 段「置き場」** が答える（いまどこか・種類・直す場所・効くタイミング）。

**直す場所はすべて マスタ管理 > 共通設定 > 段「置き場」** です（VER2.148.0）。
1枚に並ぶので、いまどこにあるかも同じ画面で確かめられます。

| | いま何が入るか | 保存先 | 効くタイミング |
|---|---|---|---|
| ① 測定データ | `<置き場>\<設備>\records.sqlite3` | パス設定マスタ | 再起動 |
| ② 作業予定 | `<置き場>\schedule.sqlite3` | パス設定マスタ | 再起動 |
| ③ マスタ | `<置き場>\master.sqlite3` | `config\local.json` | 再起動 |

**置き場が無ければ、その行の「無いので作る…」で作れます**（作る前に、
何ができるのかを1つずつ出して確認します）。保存しただけでまだ効いていない
置き場も先に作れるので、再起動を待つ必要はありません。

推奨の置き方（1つのフォルダの下に3つとも置く）:

```
\\nlmsrvngy03\工場内共有\検査データ\Records\
├─ master.sqlite3          … ③ マスタ（全端末で1つ）
├─ schedule.sqlite3        … ② 作業予定（全端末で1つ）
├─ LS4\records.sqlite3     … ① 測定データ（設備ごと）
├─ LS5\records.sqlite3
└─ _未設定\records.sqlite3  … 設備の記録が無い古いデータの受け皿
```

---

## 0. 先にやること（全端末共通）

1. **アプリを止める**（`stop.bat`）。動かしたまま置き場を変えない。
2. **いまの `db\` フォルダをまるごとコピーして控える**
   （`master.sqlite3` / `records.sqlite3`）。以下はどれも元のファイルを
   消さないが、控えがあれば「戻す」が一手で済む。
3. 共有フォルダ `\\nlmsrvngy03\工場内共有\検査データ\Records` を作り、
   **全端末から読み書きできること**を確かめる（エクスプローラーで開いて
   テキストファイルを1つ置いてみる）。

---

## 1. マスタ（③）を先に移す

**この順番には理由がある**——①②の設定はパス設定マスタ＝`master.sqlite3`
の中に入っているので、マスタを移したあとに①②を設定すれば
「移す前の端末に書いた設定が置いていかれる」ことがない。

### 1-1. ファイルを置く

いちばん整っている端末（ふだんマスタを直している端末）の
`db\master.sqlite3` を共有へコピーする:

```
copy "C:\...\WaveLog\db\master.sqlite3" "\\nlmsrvngy03\工場内共有\検査データ\Records\master.sqlite3"
```

### 1-2. 各端末で置き場を指定する

マスタ管理 > 共通設定 > 段「置き場」 > **① この端末の中** の
「マスタ」の行へ、共有のパスを入れる（「参照…」でも、エクスプローラーから
**ドラッグ&ドロップ**でも入る）:

```
\\nlmsrvngy03\工場内共有\検査データ\Records\master.sqlite3
```

「共通設定を保存」を押すと `config\local.json` に書かれる。
**このファイルだけはマスタの中に置けない**（マスタの置き場を決める設定を
マスタの中に書くと、読みに行く先が分からなくなる）ので、端末を1台増やす
たびにこの1行だけは手で入れる。直す前の内容は `local.json.bak` に控える。

`config\local.json` を直接編集してもよい。**この移行で要るのは1行だけ**:

```json
{
  "master_db_path": "\\\\nlmsrvngy03\\工場内共有\\検査データ\\Records\\master.sqlite3"
}
```

> JSONなので `\` は2つ重ねる。UNCの先頭 `\\` は `\\\\` になる。

### 書ける4つの意味

**どれも「この端末のファイルをどこに置くか」の話**で、みんなで使う置き場の
設定ではない（そちらは共通設定 > 段「置き場」）。

| キー | 何を指すか | 形 | ふつうは |
|---|---|---|---|
| `db_dir` | この端末が持つ**2つのDBファイル**（`master.sqlite3` / `records.sqlite3`）を置く**フォルダ** | フォルダ | 空欄 |
| `master_db_path` | `master.sqlite3` **1ファイル**の場所 | **ファイル名まで** | 共有を指す |
| `records_db_path` | この端末の `records.sqlite3` **1ファイル**の場所 | **ファイル名まで** | 空欄 |
| `master_share_mode` | マスタを共有に置いたときの守り方 | `auto`/`on`/`off` | 空欄（=auto） |

**優先順位**は「個別指定 > `db_dir` > 既定」:

```
master.sqlite3  … master_db_path  →  db_dir\master.sqlite3   →  アプリの場所\db\master.sqlite3
records.sqlite3 … records_db_path →  db_dir\records.sqlite3  →  アプリの場所\db\records.sqlite3
```

画面にも「出どころ」として、どの段で決まったかが出る。

### よくある取り違え

- **`db_dir` は「作業用のコピー置き場」ではない。** 共有からの写し・
  作業コピー・バイトコードの置き場は**アプリが自動で決める**（設定は無い）。
  `db_dir` が手元ならそこを、共有・クラウド同期フォルダの上なら
  `%LOCALAPPDATA%\WaveLog\work\<識別子>` を使う。いまどちらかは
  段「置き場」の「作り直せるファイル」の行に出る。
- **`records_db_path` は「測定データの置き場の大元」ではない。**
  あれは**この端末1台ぶんの控え1ファイル**。みんなで見る測定データの
  大元は `records_share_dir`（共通設定 > 段「置き場」 > 「測定データ（共有）」）で、
  こちらはマスタの中に入るので `local.json` には書かない。
- **環境変数が使える。** `%LOCALAPPDATA%\WaveLog` のように書ける。
  **書いたまま保存され、使うときに展開される**ので、同じ `local.json` を
  全端末へ配れる。中身が空の変数はエラーで断る（黙って変な場所へ書かない）。

### 1-3. 起動して確かめる

アプリを起動し、**マスタ管理 > 共通設定 > 段「置き場」** の
「マスタ」の行が共有のパスを指していることを見る。

このとき**自動で共有向けの動きに切り替わる**（§9.263）:

- **読み**は手元の写し（`%LOCALAPPDATA%\WaveLog\work\...\master.local.sqlite3`）
  から。共有を毎回開かないので一覧も設定画面も速い。
- **書き**はロック → 写しを取り直す → 当てる → 改訂番号 → 丸ごと置換 → 解放。
  作業予定と同じサイクルなので、2台が同時に保存しても片方が消えない。
- 誰かが書いている最中に保存すると **409（誰々が編集中）** が返る。
  数秒で解けるので押し直せばよい。

切り替えの判定は置き場の綴りで行う（UNC・クラウド同期フォルダなら共有と
みなす）。**手で決めたいときは** `config\local.json` に
`"master_share_mode": "on"`（常に共有扱い）／`"off"`（常に手元扱い）を書く。
既定は `"auto"`。

## 2. 作業予定（②）

### 2-1. 画面で置き場を決める

マスタ管理 > 共通設定 > 段「置き場」 > **② みんなで使う** の
「作業予定」の行に、フォルダを入れるだけでよい:

```
\\nlmsrvngy03\工場内共有\検査データ\Records
```

ファイル名まで書いても構わない（`...\Records\schedule.sqlite3`）。
フォルダを入れた場合は `schedule.sqlite3` が補われる。
**フォルダが無ければ作り、ファイルが無ければ作り、あればそれを使う**
（§9.262。登録の手間を増やさないため）。

### 2-2. 既にある予定を持って行く

いま使っている共有の `schedule.sqlite3` があるなら、新しい置き場へ
**コピーしてから**設定を変える（設定を先に変えると空の予定表が作られる）。

### 2-3. 再起動して確かめる

段「置き場」の「作業予定」の行が新しいパスを指し、
作業スケジュール表に予定が並ぶこと。

## 3. 測定データ（①）

### 3-1. 置き場を決める

マスタ管理 > 共通設定 > 段「置き場」 > **② みんなで使う** の
「測定データ（共有）」の行へ:

```
\\nlmsrvngy03\工場内共有\検査データ\Records
```

「共通設定を保存」を押し、**アプリを再起動**する
（接続先は起動時に1回だけ決まる）。フォルダがまだ無ければ、
保存したあと同じ行の「無いので作る…」で先に作っておける。

### 3-2. いまの記録を設備ごとへ振り分ける

再起動したあと、マスタ管理 > **測定データの保存** > 段「置き場と引っ越し」 >
**「今ある測定データを設備ごとに振り分ける」** で:

1. **「どうなるか見る」** を押す — どの設備へ何件行くかが出る。まだ1件も書かない。
2. 中身を確かめて **「振り分ける」** を押す。

`<置き場>\<設備名>\records.sqlite3` が設備ごとに作られ、記録が入る。
**元の `db\records.sqlite3` は消さない**——読む側は旧い置き場も一緒に見るので、
振り分けの途中で止めても記録は1件も消えないし、二重にも出ない
（同じ記録IDは新しい方だけを採る）。

設備の記録が無い古いデータは `_未設定` フォルダへ入る。
その記録を開いて設備を入れてから保存し直せば、正しいフォルダへ移る。

### 3-3. なぜ設備ごとに分けるのか

**1つのファイルを書くのはいつも1台だけ**という状態を、設定ではなく
**構造として**作るため。測定端末は1設備に1台なので、クラウド同期や
ファイル共有でデータが壊れる唯一の条件（同じファイルを2台が同時に変える）が
消える。閲覧端末は全設備のフォルダを読むので、今までどおり全部見える。

### 3-4. 閲覧用の複製は不要になる

「閲覧用の複製（`records_backup_export_path`）」は役目を終える——
閲覧端末が設備ごとのファイルを直接読むので写しが要らず、しかも写しは
**全端末が同じ1ファイルへ書く**形なので、残すと消したばかりの危険を
1つだけ残すことになる。置き場を決めると「置き場」の行に
「役目を終えました」と出るので、そこで欄を空にしてよい。

## 4. 移行後の確認（1台ずつ）

- [ ] マスタ管理 > 共通設定 > 段「置き場」の本体3行が**すべて新しいパス**を指す
- [ ] どの行にも「まだありません」「再起動待ち」が残っていない
- [ ] 「3つとも同じ場所の下です: …」と出る
- [ ] マスタを1つ直して保存 → **別の端末**を開き直して反映されている
- [ ] 作業スケジュール表に予定が出る／1本足して別の端末で見える
- [ ] 測定を1件保存 → `<置き場>\<設備>\records.sqlite3` の更新日時が動く
- [ ] データ一覧に他の設備の記録も出る（閲覧端末で）

## 5. 運用上の注意

- **バックアップは共有フォルダを丸ごと**。3つとも1つのフォルダの下に
  入るので、フォルダ単位の世代バックアップがそのまま効く。
- **クラウド同期フォルダ（Box/OneDrive等）へ置くときは**、同期の対象から
  外さないこと。アプリは置き場の種類を見分けて、ロックを確かめるまでの
  待ちを長めに取る（結果整合性のため）。
- **共有が落ちても測定は止まらない**——書けなければ手元の
  `db\records.sqlite3` へ落として理由をログに残す。マスタも前に落とした
  写しで読み続ける。共有が戻ったら次の保存で追いつく。
- **端末を1台追加するとき**は「マスタ」の行だけ入れればよい。①②の設定は
  マスタの中にあるので、マスタを共有にした時点で新しい端末にも届く。
- **`db_dir` を `%LOCALAPPDATA%` のような端末ごとの場所にしてよい**——
  むしろ推奨。共有・クラウド同期フォルダの上に置いたときだけ、
  作り直せるファイル（写し・作業コピー）が自動で手元へ逃げる。
