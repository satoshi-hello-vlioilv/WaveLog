# §9.199 上部メニューを1行に／親ロットの印は「親」か「子N」／差し込みの当たり判定を境目へ絞る（利用者の指示）

利用者の指示は3つ。①「親バッジですが、数字がついているので、この付け方だと
『子』の方が意味的に適切です。親ロットにつけるバッジは『親』か『子*』として、
親の場合には数字なし、子の場合は数字を表示するようにして切り替えられるように」
②「メニューが伸びてきれいに収まっていません。ボタンのアイコン化やフローティング
モーダルやアコーディオン的なボタンも駆使しながら、タイトルを除く、上部メニュー
バーは1行で収まるように」③「スケジュールのみだと、マウスオーバーで挿入箇所が
出るのですが、判定が範囲が広く、通常のスケジュール移動したい場合のロットの
選択などにやや支障が出ます。通常のロットもD&Dできるように挿入位置の出る判定を
少し絞ってほしい」。

**① 親ロットの印は「親」（数字なし）か「子N」（件数つき）から選ぶ。**
§9.198で入れた `親2` は**数字の意味と名前が食い違っていた**——`2` は畳んで
ある子ロットの件数なので、そのまま読むと「2件の親」になる。数字を出すなら
名前は `子`、名前を `親` にするなら数字を出さない、のどちらかしか成り立たない。
**既定は `子N`**——件数は開かなくても分かる情報で、§9.198で「消すと何件畳んで
あるか開くまで分からない」として残した値打ちをそのまま保つ。狭さを優先したい
現場のために `親`（数字なし。実測26px / `子2`は32px）も選べる。
置き場は**この端末の設定**（`scLayoutPrefsV1.childBadge`）——読み方の好みで、
PCごとに違ってよい（共有マスタへ入れると全員が同じ形に縛られる）。
**数字を出していないときは`title`にそう書く**（設定でそうしていることが
分からないと、件数が「出ない」のか「無い」のかを推測させる）。

**② 操作列は1行。畳んだ先の状態はボタンに書く。**
§9.198で11個のボタンを4つの塊へ束ねたが、**塊にしても総量は減らない**ので
実測3行（114px）に折り返していた。折り返した操作列は「同じ位置に同じものが
ある」という前提を壊し、本文の高さも表示のたびに変わる。**面積を頻度×重要度で
配り直した**（§1）:

| 何 | 前 | 後 |
|---|---|---|
| 見え方の設定7つ | 834px（選択欄2つ＋ボタン3つ＋起点） | **「表示」1ボタン183px**（浮きパネルへ畳む） |
| 追加3つ | 334px | 311px（狭いときはアイコンのみ121px） |
| 状態2つ | 275px | 250px（「〜に取り込み」→「〜に取込」） |
| 印刷・再計算 | 127px | 127px（狭いときは印刷をアイコンのみ） |
| 合計（右側） | 1570px＝3行 | **908px＝1行**（1004pxの器でも826pxで1行） |

**「表示」パネル(`#scViewPop`)は見え方の設定を集めた1枚。** 以前は「まとめ」
「さかのぼり」がバーの素の選択欄、「表示列」がモーダル、「行の見せ方」「配置」が
別々の浮きパネルで、**同じ「この画面の見え方」の話が4通りの形で散っていた**
（探す前に、どの形で出るのかを思い出す必要があった）。上2つ（押す頻度が高い）は
畳まずに置き、下3つは**アコーディオン**で**常に1つだけ**開く。
`#scLayoutPop`／`#scRowStylePop` は**同じ要素のまま**この中へ移してあるので、
中身・保存・その場適用の作法(§9.179/§9.198)はそのまま効く。
**誰に効くかを段ごとに書く**（全員に効きます／設備ごと／この端末だけ）
——同じパネルに共有の設定と端末の設定が並ぶので、書かないと取り違える。

**畳んだ先の設定はボタンに連れて出す**（`#scViewState`＝「まとめなし・過去8時間」）
——畳んだだけでは「思い出させない」に反する。**基準（現場歴／太陽暦）は
要約でも落とさない**（そこが分からないのが§9.198で直した問題そのもの）。
**中身が1つも無い場面（全体俯瞰）では入口ごと消す**（§4）。

**狭い器では自分で減らす**（`@container schead`）。器は`.sc-head`——ヘッダーへ
相乗りしているので、ビューポート幅ではなく**相乗り先の幅**で判断する。
**しきい値は`em`で置く**——`em`はコンテナ自身の文字サイズで解けるので、
表示サイズを上げるとしきい値も同じ比で上がる（pxで書くと中身だけが1.1倍に
なって、大きい表示でだけ溢れる・§9.127）。98em(≒1176px)で状態の要約、
87em(≒1044px)で塊の見出しとボタンの文字を落としてアイコンだけにし
（意味は`title`が持っているので押す前に読める）、74em(≒888px)で隙間を詰める。
**捨てる順は「読めば分かるもの」から**——ボタンそのものと状態の文字は
最後まで消さない（いつ読んだ内容かは色では伝えられない・§3）。
**塊の中は折り返さない**が（`.sc-tools{flex-wrap:nowrap}`。「追加」の3つが
2行に割れると束ねた意味が消える）、**器そのものは折り返せるまま**にしてある
——ここまで削っても入らない極端に狭い窓（実測: 1100px幅 × 表示サイズ「大」＝
器824px）では、切り落として見えなくするより2行になったほうがよい。
実測では1280px幅でも表示サイズ3段すべてが1行に収まる。

**③ 差し込みの当たり判定は境目のそば（±`insertEdgeBand()`px）だけ。**
以前は行のどこにカーソルがあっても**いちばん近い境目**の帯を出していた。
そのため①行の真ん中を指しても帯と吹き出しが出る ②吹き出しは押せる箱なので
**下の行のドラッグを食う**（吹き出しは境目の8px下から2段・高さ約34pxで、
28pxの行を丸ごと覆っていた）。帯を出すのは境目から上下8px（行の高さの1/4を
6〜10pxで頭打ち）までにして、**行の中央は掴む場所として空ける**。
幅を行の高さから作るのは、行間を詰めても表示サイズを上げても比が保たれるため
（直値のpxは表示サイズに追随しない・§9.127）。
**掴んで運んでいる最中は今までどおり「いちばん近い境目」へ寄せる**——落とす
先を探しているので、境目を狙わせるのは酷（`insertSlotAt(y,edgeOnly)`の
`edgeOnly`で分ける）。
吹き出しは**1行のピルにして境目に跨がらせ**（高さ18px＜行28px）、
左は**取っ手の列を空ける**（掴む場所そのものを覆わない）。
見えている帯・押せる帯・出る帯は**同じ±8px**にそろえる——ずれていると
「出たのに押せない」「押せるのに出ない」が生まれる。
`.sc-timeline.sc-insertable .sc-row-line{cursor:default}` も**掴めない行だけ**に
限り、掴める行は`grab`にした（掴めるのに掴めなさそうに見えていた）。

固定は`tests/test_scbar.js`。**「行の中央では出ないこと」を必ず見る**
——出るかどうかだけを見ると、全面が判定だった頃の実装でも通ってしまう。
