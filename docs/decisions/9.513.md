# §9.513 接続状況に版と接続の記録——「誰に新しい版を配るか」を決められるように（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「マスタ管理のところの接続状況のところで、接続ユーザー、接続PC、接続時刻、接続時間、接続したアプリのVER情報、
ユーザー別累計接続回数などわかるように改良してください。特にバージョンアップを管理する上で、ユーザーが古い
バージョンで使用していないか、誰に新しいバージョンファイルを配布すればよいか判断する方法となります。また、
最新バージョンをこの接続状況で見ることにより、運用環境下で最も新しいバージョンがわかるため、ここのデータを基に
古いバージョンを使用しているユーザーにメッセージを出すことも可能になります。そういったデータの2次利用も考えた
うえでわかりやすい使いやすいUIUX設計で改良をお願いします。」

## 測った（評価関数・直す前）

依頼の項目が画面で読めるか（1728×1050・マスタ管理 > 接続状況）。

| 項目 | 前 | 後 |
| --- | --- | --- |
| 接続ユーザー・接続PC | 読める | 読める |
| 接続した時刻・接続時間 | **無い**（最後の応答だけ） | 読める |
| 接続したアプリの版 | **無い**（在席に版を書いていない） | 読める（最新／要更新の語つき） |
| 利用者ごとの累計接続回数・時間 | **無い**（在席はTTLの4倍で消え、記録が残らない） | 読める（端末ごと／利用者ごと） |
| 運用中の最新版 | **無い** | 要約の1マス目 |
| 最新でない端末の数（配る相手） | **無い** | 要約の3マス目（うち接続中も） |
| いま繋いでいない端末（しばらく使っていない端末の版） | **無い** | 記録の表 |
| 2次利用（表計算・メールへ） | **無い** | 表をコピー（タブ区切り）・CSVで保存（BOMつき） |
| 合計 | **2/9** | 9/9 |

## 決めたこと
- **記録は端末ごとに1ファイル**（`presence/history/<端末キー>.json`）。書くのはその端末だけ（在席と同じ理由・§9.272）。
  版・最初と最後に使った時刻・接続の回数・累計の接続時間・使った版の履歴（新しい順10）。在席の掃除（`*.json`）は
  下の階層を辿らないので記録は消えない。
- **接続の数え方**: TTL（75秒）より長く途切れたら新しい接続。途切れたあいだは接続時間に数えない（TTLで頭打ち）。
  タブを閉じたら（`leave()`）終わりまでの時間を書き足す。書くのは始まり・終わりと60秒ごと（在席は20秒ごと）。
- **運用中の最新版＝見えているすべての版の最大**（記録・接続中・この端末）。版は数として比べる（2.10.0＞2.9.3）。
  **版が空＝記録を書かない古い版**（VER2.400.0より前）なので「要更新」に数える。答えは`fleet_summary()`の1箇所
  （最新版・端末ごと・利用者ごと・件数）で、画面は並べるだけ。並びは**要更新が先**（配る相手から読める）。
- 画面: 要約（1枚のカードに4マス: 最新版／接続中／最新でない端末（うち接続中）／これまでに接続）→ いま接続している端末
  （版・接続した時刻・接続時間を足した）→ これまでに接続した端末（端末ごと｜利用者ごと・最新でない版だけ・表をコピー・CSVで保存）。
  コピーとCSVは**見えている表のまま**（見たものと写したものを違えない）。
- 使わなくなった端末の記録は消せる（開発者・メンテナンス者・`role_can('presence:forget')`）。**接続中の端末は消さない**
  （すぐ作り直され、回数と時間が0に戻るだけ＝数字を壊す）。
- 「古い版の利用者へ知らせを出す」は、この記録の答え（`fleet.latestVersion`）を各端末が読めば作れる形にしてある。
  **画面に新しい帯を出すことになるので、入れるかは利用者に確かめてから**（§CLAUDE E）。
