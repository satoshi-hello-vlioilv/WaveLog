# §9.361 設定窓の未保存の変更を、遅れて届いた再読み込みで捨てない

利用者の指摘:「**黙って戻るのは問題だし、戻ること自体望んでいないはずなので、
直してください。**」

## 症状

操業データ項目の設定窓で単位の置き場・配置・意匠などを選ぶと、**約1秒後に
選んだ値が保存値へ戻る**。画面は何も言わない。手が速いほど踏みやすい。

## 原因

設定窓の変更は `touch()` が**その場の項目オブジェクトへ積む**（保存を押すまで
サーバーへは行かない）。ところが `loadOpItemMaint()` は

```js
opState.items=(it.items||[]).map(x=>({...x}));
```

で**一覧を丸ごと入れ替える**ので、積んだ変更ごと消える。そのあと末尾の
`renderOpModal()` が保存値で描き直す——これが「黙って戻る」の正体。

再読み込みは**利用者が起こしていない**ところからも来る（選択肢をその場で
足す・消す、他の画面からの流れ）。**§9.331 の「いつの分の応答か」で描く**が、
この窓には効いていなかった。

## 直したこと

**「新しいほうを残す」**。未保存の変更を持つ項目の id を `opState.dirty` に
覚え、再読み込みで**その1件だけ今の物を残す**（他は新しい値で更新する）。

| 場所 | すること |
| --- | --- |
| `opState` の宣言 | `dirty:''` を**宣言に書く**（後付けの鍵を作らない） |
| `touch()` | 触った項目の id を覚える |
| `loadOpItemMaint()` | その1件だけ差し替えない。項目自体が消えていたら覚えを捨てる |
| 保存・削除・窓を閉じる | 覚えを落とす |

**保存できたら覚えを落としてから読み直す**ので、サーバーが正した値は
そのまま入る（ローカルの古い値が居座らない）。

## 網

`test_opunit` に1件足した。**待つのではなく、再読み込みを実際に起こす**——
`WL.mm.special['op-item'].load(true)` を呼び、選んだ置き場が残ることを見る。
レースそのものを作るので、速い機械でも遅い機械でも同じことを見る。
欠陥注入（覚えを外す）で「再読み込み前=内部 / 後=外下左」と落ちることを
確かめた。

## この不具合が教えたこと

**§9.360 で「不安定な網」を見分けられるようにしたら、その1本目がこれだった。**
`test_opunit` は単独で3回に1回落ちており、通しでは「順番のせい」に見えていた。
1回だけ回して緑なら順番依存、と決めつけていた間は**製品の不具合が網の
ゆらぎに紛れていた**。§9.360 で入れた「単独で2回回す」が無ければ、
この不具合はまだ見つかっていない。

**網が不安定なとき、疑うのは網だけではない。**
