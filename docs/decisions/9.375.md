# §9.375 予定に組み込んだロットの元データが変わったら取り込む（利用者の指示）

利用者の指示（作業スケジュール一覧の要望 ⑤）:

> スケジュールに組み込まれたデータの更新を行いたいです。例えば「出荷日」など
> 変わる可能性がある部分、設計情報と多岐にわたるので、変更箇所を検知したら、
> 自動で更新してほしいです。(設定で、自動更新と確認して更新と切り替えられる
> ようにしたいです。)

## 何が起きていたか

予定の行が持っているのは、**投入した時点の仕掛データの写し**
（`buildScheduleDetail()`・§9.18）。これは意図した設計で、並べ替えても
仕掛が入れ替わっても予定に出る文字は変わらない——「その時点の見え方を
固定したスナップショット」だった。

問題は、**動かなくてよい項目と、あとから決まる項目が同じ写しに同居して
いた**こと。ロット番号・製造材質は凍ってよいが、**出荷日・納期・設計情報**は
仕掛の側で後から確定する。凍らせたままだと、予定表に出ている値が
**そのうち嘘になる**——しかも「いつの値なのか」がどこにも書いていないので、
読む側には嘘だと分からない。

## どう決めたか

| 問い | 答え |
| --- | --- |
| 何と比べるか | 予定の写し（`detail`）と、**いまの仕掛の行** |
| いつ比べるか | スケジュールを開いた（読み直した）とき。設備×読み込み時刻で1回 |
| どの項目を見るか | **画面に出している内容の項目すべて**（利用者の指示）。式の列・結合で足された列は元データに無いので外す |
| 既定 | **自動で更新**。ただし黙らない——「3件を最新にしました」を出し、中身も開ける |
| 切り替え | 「確認して更新」。帯で件数を言い、旧→新を見せてから取り込む |
| 設定の範囲 | **アプリ全体で1つ**（パス設定マスタ `schedule_source_sync`。LIVE キーなので再起動は要らない） |
| 誰が書くか | **編集権を持っている端末だけ**（閲覧の端末が共有を書き換えない） |

## 往復を増やさない

**比べる材料は、もう取りに行っている。** §9.368 ② で「予定に載っている
ロットの在席をまとめて1度確かめる」ようになっており、その問い合わせが
`/api/table` で仕掛の行を引いている。今までは `columns=ロット番号` の
1列だけを頼んでいたので、**頼む列を増やすだけ**で済む。

- `presenceColumns()` … ロット番号＋見る項目の**別名の両側**（§9.87）。
  実在しない名前はサーバーが落とす（`columns=` は当たった名前だけを残し、
  1つも当たらなければ絞らない・fail-open）ので、多めに並べてよい。
- `scWorkRow` … 正規化ロット → いまの仕掛の行。在席（`scInWork`）と同じ
  1往復で埋まり、仕掛一覧を取り直したら一緒に捨てる。

だから**この機能のために増えた往復はゼロ**。

## 空は「変わった」と読まない

仕掛の側の値が空のときは、**何もしない**。

頼んだ列が返ってこなかったのか、現場がその値を消したのかを、画面からは
見分けられない。消したぶんを取りこぼす代わりに、**取り違えて写しを空に
することを防ぐ**——§3（確かめられないものを黙って消さない）と同じ倒し方で、
§9.368 の「不明なら戻す」と向きをそろえてある。

## 写しは全置換にしない

書き戻すのは `plan_merge_detail()` で、**渡した鍵だけ**を重ねる。

写しには画面が今出していない項目も入っている（投入した時期によって
キーの流儀も違う——古い予定は alias 名だけ、新しい予定は alias 名と
生カラム名の両方・§9.18）。全置換にすると、**出していない項目が黙って
消える**（§9.113 の「渡す設定を1つでも書き漏らさない」の裏返し）。

どの綴りへ書くかは `detailKeysFor()` が答える。**既に写しに在る綴りだけ**を
書き換え、1つも無ければ選んだ綴りで1つ足す——別名を総当たりで足すと、
写しが呼び名の数だけふくらみ、そのぶんがそのまま共有DBの大きさになる。

書き換えてよいのは**種別が「作業」の行だけ**。枠は `plan_set_frame()`
（§9.238 ②）、設備停止・申し送りは明細JSONを別の意味で使っている。

## 画面

- **自動** … 取り込んでから知らせる。「3件を最新にしました」＋変わった
  ロットと項目名、押せば旧→新の一覧が開く（§3 出どころ・根拠を画面に出す）。
- **確認** … `#scSrcBanner`（共有の見張りの帯と同じ見た目）に
  「3件に変更あり。仕掛の側で 7項目が変わっています」＋「中身を見る」。
  窓は**ロット／項目／いまの予定／元データ**の4列で、新しい側を濃く、
  古い側は取り消し線（§3 色だけで伝えないので、見出しでも言い分ける）。
  「取り込む」で当たり、「あとで」なら帯が残る。

設定は「置き場」の節の畳みへ（共通設定 > 置き場 > 元データが変わったとき）。

## 固定する網

`tests/test_srcsync.js`。

1. 予定の応答が設定を運ぶ（画面が綴りを覚えない・§9.163）
2. `detail` を渡した更新は**重ねる**。渡さなかった鍵は消えない
3. 枠の行は断る
4. 自動: 写しが古い予定は、開いたときに最新へ直り、**黙らない**
5. 確認: 帯で件数を言い、**押すまで直らない**。押したら直る

材料（写しが古い予定）は網が自分で置き、設定も**触る前の値へ戻す**
（§9.284。触った本が既定を書き換えたままにしない）。
