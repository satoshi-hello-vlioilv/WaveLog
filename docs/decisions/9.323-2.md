# §9.323 ⑤⑥ 紙の「混入位置」の赤太字と、更新履歴の余白（利用者の指示）

### ⑤ 何条目かを赤太字で

「条混入位置で何条目という表示の部分の大事な文字情報を赤太字で表示してほしい」

現場が紙から拾うのはこの数字なので、`OSから **N** 条目（M条）` を赤太字にする。

- **色だけで伝えない**（§3）——「条目」の字は必ず残す
- **条番号そのものはさらに太く**（800 → 900）。範囲や複数条のときも数字が
  先に目に入る
- **赤は `--rp-hit` の1つ**（§9.163）——「該当条」の欄と違う赤だと、同じことを
  言っているのに読む側が読み替えることになる
- **距離（／OSから ◯mm）は地の色のまま**——全部を赤くすると、どれが結論なのか
  色が語らなくなる
- **製品に掛かっていない箇所（屑側）は赤くしない**——赤は「該当した」の意味

固定は `tests/test_rpdefect.js` の §9.323 ⑤。**宣言ではなく描かれた色で見る**
（§9.229 ⑥）。**本物の紙のCSSの中で測る**（§9.311 C）。**片側だけ見ない**
——「赤い」だけを見る網は、距離まで赤くした実装も通す。

### ⑥ 更新履歴の窓は中身の長さから決める

「更新履歴が表示されるエリアと改行の位置がずれていて余白が広すぎます」

幅が `1180px` の直値で、本文の行長（`li{max-width:76ch}`）と**何の関係も
無かった**。

実測（評価関数 = 器の内寸と、文字が実際に置かれた右端の差）:

| | 直す前 | 直したあと |
|---|---|---|
| `.cl-main` の使える幅 | 868px | 617px |
| いちばん長い行 | 591px | 587px |
| **右の余り** | **277px（32%）** | **30px** |
| 行数（＝行長が変わっていないか） | 498 | 498 |

- **`ch` は半角「0」の幅**なので、日本語の本文では意味を持たない単位
  （76ch＝全角42文字。読みやすさとしては妥当だが、そう読めない）
- 行長は `--cl-text-w` の1箇所が持ち、**器も本文も同じ数から作る**ので必ず揃う
- **`em` で持たないこと**（§9.257 ①）——カスタムプロパティの `em` は使った場所の
  文字サイズで解けるので、器と本文で違う数になる。`calc(42 * var(--fs))`
- **幅の式に内訳を全部足すこと**——1つでも落とすと本文がそのぶん切られる
  （実測: 「いま動いている版」のカードの内側24pxを落として3px足りず、
  `li` が 588→561px で折り返していた）
- `scrollbar-gutter:stable` も置く（バーの出入りで内寸が動くと、中身から
  決めた意味が無くなる・§9.227 ②）

**網は画面比で見ないこと**（§9.200）——§9.286 ⑦の「窓が画面の6割以上」は
620px の既定から広げたことを固定する網だったが、物差しが**画面の何割か**
だったため、**この指摘と正面から反対**になった。守りたいのは「既定へ戻って
いないこと」なので、**レール＋行長が収まっているか**で見る。
**行長も一緒に見る**——器を詰めるついでに行を短くしては本末転倒。
