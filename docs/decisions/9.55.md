# §9.55 測定画面 左ペインの情報再配置(常時スクロールの解消)

三分割レイアウトの左ペインが縦に収まらず、**常時スクロールバーが出ていた**
(実測: 表示873pxに対し中身999px、126pxはみ出し)。原因は情報量ではなく
**並べ方**だった。

| 何が縦を食っていたか | 内訳 |
|---|---|
| 全項目がラベル上・値下の2段 | 1項目48px × 13項目 |
| 短い値まで全幅で1行 | 取引先・納入先・コース3件で5行 |
| 作業時間が見出し+入力の2段 | 1枠78px × 2枠 |
| 常時2行の案内文・比較なしの空枠 | 38px + 54px |

**再配置の考え方**

- **かたまりに分ける(Miller / Gestaltの近接)**: 13項目を
  「主識別 → 識別番号 → 製品 → コース」の4つへ束ね、小さな見出しと余白で
  区切る。罫線は増やさない(線を足すほど視覚的な要素数が増える)。
- **ラベルと値を1行に(走査効率)**: 参照用の項目はラベルを右揃えの弱い字で
  左に置き、値を右に並べる。値の列が縦に揃うので、目的の値まで視線が
  真下に落ちる。1項目48px→27px。
- **重みは1つだけ(視覚的階層)**: ロット№だけ大きく残す。一覧から開いた
  直後の最初の行動は「今どれを見ているか」の確認で、そこにだけ重みが要る。
- **文脈が与えている語は繰り返さない**: 作業時間の枠内では「作業開始時刻」
  ではなく「開始」で足りる。短くしたぶんを日時の表示幅へ回した
  (打刻した時刻が読めることが最優先。実測で176px確保、切れない)。
- **「無い」ことの説明に常設の場所を与えない**: 比較対象が無いときの
  実績比較枠は囲みを外して1行の注記に落とす。

**結果**(1700×1000):

| | 改善前 | 改善後 |
|---|---|---|
| 基本情報カード | 578px | 411px |
| 作業時間パネル | 325px | 215px |
| はみ出し | +126px | **0px(スクロールなし)** |

表示サイズ5段階のすべて(特大を含む)でスクロールが出ない。**項目は1つも
減らしていない**(13項目のまま)。

> 画面高768px級の端末では収まらない(左ペインの表示高が643pxまで落ちるため)。
> ここから先は情報を削るしかなく、それは目的に反するのでしていない。

**DOMの約束**: `.field` + `<label>` + `<output>` の形は変えていない。
`renderScheduleInfo()`(作業予定)・`renderCourseHierarchy()`(コース3件)・
`renderResidualCourseEverywhere()`(残コース)がラベル文字列で挿入位置を
探して後から差し込む作りのため、ここを崩すと差し込みが効かなくなる。
コース3件の差し込み先だけ、見出し`.info-group-course`の直後へ変えた。

**コース3件だけは2列に載せない(VER1.82.2)**

上の「短い値まで全幅で1行」を減らす方針の**唯一の例外**。設計/実績/残コースは
設備が連なる文字列で、実機の長さは

| | 長さ | 2列の半分(≒280px)に入るか |
|---|---|---|
| 平均 | 4文字×10 ≒ 40文字 | 入らない(2行ぶん必要) |
| 最長 | 「3文字＋空白」×25 ≒ 100文字 | 入らない(3〜4行ぶん必要) |

**3項目とも縦に1行ずつ、常に全幅**へ置く(`.course-stack-field`)。
一時期「入りきらないものだけ全幅(`.is-long`)」にしていたが、平均的な長さ
ですら半分幅に入らないのでほぼ常に全幅になり、しかも短い値のロットだけ
2列へ戻って**下の項目の位置がロットごとに上下していた**。形が値に依らない
方が読み取りは速い。

縦が3行になるぶんは、コース行だけ上下パディングと行送りを詰めて相殺する
(特大表示で左ペインが1px溢れるところまで実測して決めた)。ラベル列も
コースだけ`max-content`にして、値へ渡す横幅を稼ぐ。
回帰は`tests/test_course.js`(平均・最長の両方を注入し、切れない・縦に並ぶ・
短い値でも形が変わらないことを見る)と`tests/test_maint.js`(表示サイズ
5段階でスクロールが出ない)。
