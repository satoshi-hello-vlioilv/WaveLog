# §9.195 現場歴（日を跨ぐ勤務の日付補正）（利用者の指示）

**「日付＋勤務」でまとめると、日を跨ぐ勤務が2つに割れていた。** 3直
23:00〜翌7:00 は1回の勤務なのに、23:30の行は「8/18 3直」・翌2:00の行は
「8/19 3直」となる。利用者の指示は「通常の太陽暦ではなく現場歴を実装し、
日を跨ぐものは跨いだ部分の日付をカウントせず、そのままの日付で表示して
ほしい」「日付の演算をハードコーディングせず、マスタ（勤務形態マスタ）で
修正できるように」。

**① 日付補正は勤務区分マスタの1列**（`[日付補正]`）。**跨いだ後の時間帯に
だけ当てる**——3直 23:00〜翌7:00 なら 23:00〜24:00は0・0:00〜7:00は-1。
未設定は-1（現場歴の既定）、0を明示すれば太陽暦へ戻せる。
**跨がない区分には持たせない**（当てる時間帯が無い。効かない値が保存されて
いると「設定したのに変わらない」と読まれる）。判定は
`schedule_repo.segment_day_offset()`／`crosses_midnight()`の1箇所。

**② 現場日は1箇所でまとめて決める**（`schedule_calc`が`workDate`を返す）。
予定・着手中・完了で代表となる時刻が違うので、各所で計算すると「まとめた
見出しと行の日付が食い違う」形の食い違いが必ず起きる。代表時刻の決め方は
画面の`rowTimeOf()`と同じ。

**③ 画面は現場日を出し、暦とずれていることを書く。** 日付の列は`workDate`を
出し、点線の下線＋ツールチップで「勤務『3直』の日付補正 -1日。実際の時計は
…」と言う（黙ってずらすと時計と食い違って見える）。まとめ（日付／日付＋勤務）
も同じ`workDate`で束ねるので、見出しと行が食い違わない。
**`new Date('2026-08-18')`で組み立てないこと**——UTCの0時として読まれるため、
地方時へ直すと日付が1日ずれる端末がある。文字列のまま組み立てる。

**④ 時刻はHH:MMへそろえて保存する**（`pad_hm`）。`8:15`のように1桁で
保存された区分は、編集画面の`input[type=time]`が**空欄になり、そのまま
保存すると400で断られる**——旧フラットマスタからの移行分が実際にそうなって
おり、移行された勤務体系は一度も編集できない状態だった。

**⑤ 勤務形態マスタの画面を組み直した**（利用者の指摘「設備のチェックボックス
的なUIや幅の過剰な長さ」）。名称の入力欄は`--w-xl`で頭打ちにし（20字ほどの
名前に600px超を与えていた）、適用設備は**そろったマス目**に並べ（`flex-wrap`
だと名前の長さなりに折り返して左端がずれる）、選択の要約を文字で出す。
勤務区分は**見出しと本文で同じグリッド定義を共有する**1行＝1区分の表にした。

固定は`tests/test_workdate.py`・`tests/test_shift.js`・`tests/test_workable.js`。
