# §9.105 列の設定: 出どころで分類し、右半分を「読める順」に組み直す

「デザインが古臭い」「モーダル内の右半分が質素」という指摘。飾りの問題
ではなかった——**右ペインは書いてあることが少なすぎた**。ラベルと入力欄が
同じ重さで4つ並ぶだけで、どれが説明でどれが操作か、どの順に触ればよいか、
そもそもこの列が何者なのかが**形からも文字からも分からない**状態だった。

#### 出どころ(origin)で分類する

列を前にして人が最初に思うのは「この項目はどこから来たのか」。出どころが
違えばできることも違う——結合列は元データを直しても変わらないし、計算列は
値を持たないので書式が無い。**分類が見えていないと、利用者はそれを一つずつ
試して覚えるしかない。**

| 分類 | 中身 | 色 |
|---|---|---|
| 元データ | 読み込んだデータがそのまま持つ項目 | 基調の青緑 |
| 結合 | 別のデータソースからキー一致で足された項目 | 紫寄り |
| 計算・操作 | アプリが足した列(行番号・分割・測定・予定) | 無彩色寄り |

**3つだけにする**(増やすと色の意味を覚える手間のほうが大きくなる)。
色相はアプリの基調から離しすぎない——ここだけ原色が並ぶと一覧の落ち着きから
浮いて「別のアプリ」に見える。そして**色だけで意味を伝えない**: 分類名と
件数を必ず文字で書き、行頭の点は見分けを速くする補助に留める。

**結合された列の名前はサーバーが返す**(`/api/table`の
`joinQuality.addedColumnNames`)。以前は件数(`addedColumns`)しか返して
おらず、画面側は「何列増えたか」しか言えなかった。**列名から推測しない
こと**——どのデータソースをどのキーで結合したかを知っているのはサーバー
だけで、名前に手がかりは無い。

#### 右ペインは「素性 → ①②③ → 結果」

上から読める順に置き、手順に番号を振る。

1. **この列は何者か**(カード): 分類チップ・列名・元の項目名・
   **値のある行 / 値の種類 / 値の見た目の推測**。この数字は飾りではなく
   **書式を決める手がかり**で、これが分かって初めて「数値にするか」を選べる。
2. **① 見せ方**(表示名・幅)
3. **② 値の整え方**(書式。種別は素のラジオをやめ、押せる面にした)
4. **③ 読み替え**(ルール)
5. **結果**: 元の値 → 一覧に出る値。**1件では「たまたま」と区別が付かない**
   ので違う値を3件並べ、変わらない行にはそう書く。

計算列は②③を出さず、代わりに**なぜ無いのか**を書く(空欄を見せるより、
理由が書いてあるほうが短く済む)。

#### 押した通りに動かなかった箇所を直した

作り直しの検証で見つかった。**`#`・分割・測定・予定のチェックを外しても、
一覧は今までどおりその列を出していた**——パネルは外れたように見えるのに
一覧は変わらない。`WL.columnLayout.apply()`はデータ列の並べ替えしか見ておらず、
番号・ボタンの列は`renderGridInner()`が無条件に描いていたため。
`shows(target,key)`を足して、見出し・colgroup・セル・イベント配線の4箇所を
揃えた。**測定はボタンを消しても行のダブルクリックで開ける**ようにしてある
(列を隠しただけで機能ごと失われるのは行き過ぎ)。

#### そのほか

- 既定の大きさ 1180×760 → **1440×820**(右ペインが5段になったため)。
  **保存キーも`V4`へ変える**——古い大きさを覚えている端末があると、
  新しい既定が誰にも見えない(§9.90と同じ理由)。
- 見出しは「小さく分野 → 画面名 → 一言の説明」の3段。
  **`.sc-float-header`より詳細度を上げること**——共通の浮き窓の指定は
  70-schedule.cssにあり、同じ詳細度なら後ろのファイルが勝つので、
  `.lc-header`だけでは`display:flex`に負けて説明文が題名の隣へ並ぶ(実際にそうなった)。
- 「すべて出す/隠す」は**いま絞り込んで見えている列だけ**に効かせる
  (見えていない列まで動くと、何が起きたのか画面から分からない)。

固定は`tests/test_lcpanel.js`(分類・絞り込み・まとめて操作・右ペインの
順序・計算列の扱い)と`tests/test_tablequery.py`(結合列の名前を返すこと)。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **列の設定パネルは「出どころ」で分類する**（§9.105、`static/js/list/list-columns.js`）:
  元データ／結合／計算・操作の3つ。**3つより増やさない**（色の意味を覚える
  手間のほうが大きくなる）。**色だけで意味を伝えないこと**——分類名と件数を
  必ず文字で出し、行頭の点は補助に留める。**結合された列の名前はサーバーが
  返す**（`/api/table`の`joinQuality.addedColumnNames`）ので、列名から
  推測する判定を画面側に書かない。右ペインは「素性→①見せ方→②値の整え方
  →③読み替え→結果」の順で、**結果は実データ3件**（1件では「たまたま」と
  区別が付かない）。既定は1440×820で、大きさの保存キーは`V4`
  （既定を変えたらキーも変える。古い値を覚えている端末に新しい既定が
  届かない）。固定は`tests/test_lcpanel.js`。
- **番号・ボタンの列も「出す/出さない」に従う**（§9.105）:
  `#`／`分割`／`測定`／`予定`は`WL.columnLayout.shows(target,key)`で判定する。
  以前は`apply()`がデータ列しか見ておらず、`renderGridInner()`が無条件に
  描いていたため、**パネルでチェックを外しても一覧は変わらなかった**。
  見出し・colgroup・セル・イベント配線の**4箇所を必ず揃える**（1つ忘れると
  列がずれる）。**測定はボタンを消しても行のダブルクリックで開ける**まま
  にすること（列を隠しただけで機能ごと失うのは行き過ぎ）。
