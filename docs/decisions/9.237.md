# §9.237 紙を「画面の一覧の見た目」へそろえる: 枠線を本当に消す・角丸と色・折り返し・列幅が効かない4つの原因（利用者の指示）

§9.236で「枠線ON/OFF・列の範囲・列幅を自然体へ」を入れたが、実機で刷った
利用者からの返答は次のとおりで、**方向は合っていたが1つも効いていなかった**。

> 画面印刷ボタンを押して、メニューや不要なスクロールバーがなく、すべての
> スケジュールをきれいに印刷できるようなイメージに仕上げてほしかったのですが、
> 実装してもらった機能で枠線を消す形でチェックを外しても薄く残るのと、
> 折角の角丸ベースのデザインも失ったカクカクデザインだったり、カラムの帯
> デザインもカラーなくグレーの感じで列の折り返しを無くした形で列を整えても
> 印刷側できちんと反映されないので困っています。
> **画面印刷の時に映るスケジュール一覧表の見た目を正にしてその見た目に
> 近づけてほしいです。**

指摘は4つあり、**原因はそれぞれ別**だった。以下、指摘ごとに原因と直し方。

#### ① 「枠線を消しても薄く残る」——§9.236の判断を撤回する

§9.236 ①では、§9.196（区切りが無いと15列が横一列の文字の並びに見える）を
根拠に「OFFでも極細の薄い灰色は残す」と決めていた。**利用者の指示で撤回する**
——外したのに残るなら、その入切は嘘になる（§4「できないことは、できないと
書く」の裏返しで、**できると書いたことはできなければならない**）。

`data-borders="off"` は**表の格子を本当に0**にする。残すのは線ではなく:

- **面**——見出しの帯（`--surface-2`）、まとまりの帯、設備停止行の淡い面。
  面は「枠線」ではないので、消す対象に入れない（これが§9.196の心配に
  対する答えでもある。区切りは線でなく面が担う）。
- **記入欄の下線**——`.sp-c-write`／`.sp-c-check` だけ `border-bottom` を残す。
  記入欄は「ここへ書く」ことが用なので、枠が1本も無いと書く場所が分からない。
  **チェックの説明文にもそう書く**（黙って残すと「消えていない」と読まれる）。

**網は太さで見ること。** 色で見ると、`border:0` のときも
`borderTopColor` は `currentColor` を返すので**素通りする**（§9.236の網が
実際にそうなっていた）。

#### ② 「角丸が無くカクカク・帯がグレー」——紙は完全なモノクロだった

紙のCSSが使っていた色は `#000 / #fff / #333 / #555 / #e8e8e8 / #f0f0f0 /
#d8d8d8` の7色だけで、`--radius-*` も色トークンも**1つも使っていなかった**。
「カラムの帯がグレー」は `.sp-table th{background:#e8e8e8}` と
`.sp-row-group td{background:#d8d8d8}` そのもの。

- **色は `:root` のトークンから取る。** `--ui-scale` が掛からないので紙でも
  安全（「寸法だけがmm/px固定」という既存の約束は変えない）。
- **表は角丸の器に入れる**（`.sp-table-wrap`）。`border-collapse:collapse`
  では角丸が効かないので `separate`＋`border-spacing:0` にする。
- **`.sp-*` は `border-radius` のリテラル例外に入っていない**
  （`tests/test_csslint.py` の例外は `rp-`／`df-` だけ）。必ず
  `var(--radius-*)` で書く。
- 罫線は画面（§9.197）と同じ「行の下線＋列と列のあいだの細線」だけにする。

**`print-color-adjust:exact` を `.sp-page` へ必ず付けること。**
ブラウザは既定（`economy`）で印刷時に背景色を落とすので、付けないと帯も
バッジも真っ白で刷られる——**画面のプレビューでは色が出ているのに紙だけ白い**
という、いちばん気付きにくい形になる。逆に **`:root` や `body` へは付けない**
——`templates/index.html` の `<html style="background:#0d2029">` の濃紺が
紙全面に刷られる（`@page{margin:0}` なので `.sp-page` の外側は即ページ端）。
このプロパティは継承するので `.sp-page` の1箇所で足りる。

#### ③ 「列の折り返しを無くした形で列を整えても反映されない」

紙だけ `word-break:break-all` で、画面の §9.90「列の見出しは折り返さない
（足りなければ余白を削り、次に省略記号）」が当たっていなかった。しかも
`overflow:hidden` があっても `break-all` が先に効いて**縦へ逃げる**ので、
「はみ出し」を見る網（`over`／`clipped`／`wide`）には1件も出ない。

- 画面と同じ `white-space:nowrap` ＋ `text-overflow:ellipsis` にする。
- **収まらないときは幅と一緒に文字も縮める**（`--sp-fit`）。幅の比だけ詰めると
  同じ文字が入らなくなるので、折り返しが省略記号に変わるだけで終わる。
  下限は `MIN_FIT=.62`（これ以下は現場のコピー機で読めない）。
- **下限で止めたら、縮めたことをプレビューに文字で書く**（§4／§6）。
  「列幅 設定どおり／N%に縮小」と、縮んだときだけ打つ手（A3・横にする／
  「見える範囲の列だけ」を選ぶ）を添える。

#### ④ 「設定した列幅が活きない」——原因が2つあった

**(a) `.sp-table{width:100%}` が残っていた。** `table-layout:fixed` は
colgroup の合計が表の幅より小さいと**余りを各列へ配り直す**ので、
§9.236 ③で入れた「収まるならそのまま使う」は**一度も効いていなかった**
（実測 2.150倍に引き伸ばされていた）。表の幅には**列幅の合計**を入れる
（一覧の §9.119 とまったく同じ理由・同じ直し方）。器（`.sp-table-wrap`）も
`align-self:flex-start` で表の幅ぶんだけにする。

**この不具合が網を素通りしたのは、テストが `<col style="width:…">` という
宣言値しか読んでいなかったから。** 描画後の実幅で見ること。

**(b) `columnEffWidthPx()` が保存値しか見ていなかった。** 画面の
`applyTimelineContentColumns()` は、幅を指定していない内容の列を
`minmax(calc(110px * var(--ui-scale)),1fr)` で置く——つまり**器の余りを
分け合って伸びている**。`columnEffWidthPx()` はそれを知らず常に 110 を返すので、
画面で「折り返さない幅」に整えたつもりの列が紙では 110px 相当（29mm）へ痩せる。

**実際に描かれている見出しのセルを測る**のが唯一の正しい答え。ただし:

- **表示サイズ（`--ui-scale`）は割り戻す。** 紙は倍率へ追随させない約束
  なので、掛けたまま渡すと表示サイズ特大の端末で刷っただけで紙の列が1.1倍に
  なり、収まっていた紙が収まらなくなる。
- **成り代わり中（`withEquipment`）は測らない。** 目の前の設備の幅を別の設備の
  紙へ当ててしまう。`#scTimeline` に `data-equipment` を刻んで見分け、
  違えば今までどおり保存値→既定へ落ちる。
- `visibleColumnKeys()` の予算も**同じ物差しに揃える**（器の幅を割り戻し、
  取っ手の列のぶんを引く）。混ぜると特大の端末で入る列を少なく数える。

#### ⑤ 下限つきの比例配分は1回では解けない

`Math.max(4, natural*scale)` は、床（4mm）に着いた列のぶんだけ合計が膨らむ。
実測で**16列A4縦のとき3.8mmはみ出し**、右余白が 8mm→4.2mm へ痩せていた。
「紙からはみ出さない」という保証が床のぶんだけ嘘になっていた形。

`shareMm()` が「床に着いた列を固定して、残りを残りの予算で配り直す」を
落ち着くまで繰り返す。列が多すぎて全部が下限でも入らないときは**下限のほうを
下げる**（紙からはみ出させない、が最後まで優先）。丸め誤差は**いちばん広い列
から引く**（狭い列から引くと下限を割る）。

**`wide` 判定（`table.scrollWidth > table.clientWidth`）は表の中しか見ない**
ので、表そのものが余白へ食い込んでも 0 のまま。器の内寸と突き合わせる網を
別に置く（`tableOver`）。

#### ⑥ バッジは画面の状態をそのまま運ぶ

画面では可否（可/不可）・区分（予定/作業中/設備停止…）・印（計画外/固定/
遅れ）が**色の付いた小さな札**で、そこが一覧の読みやすさの肝になっている。
紙で全部を素の文字にすると、同じ表でも「灰色の升目」に見える。

**状態の判定を紙側でやり直さないこと。** `printRowCells()` が

- `tone`（`SC_FIXED_TONE`＝`WORKABLE_LABEL` / `categoryOf()` /
  `estProvisional` という**既にある1箇所の答えを紙が読める呼び名へ写しただけ**）
- `chips`（`flagList`。`entryCellInfo()` がHTML文字列を組み立てるのをやめ、
  `[{cls,text,title}]` の並びで持つようにした。画面のHTMLも紙のチップも
  **同じ並びから作る**）

を返し、`schedule-print.js` は**紙の意匠へ翻訳するだけ**にする。
行の地の色は**画面と同じ `.sc-rs-*` クラスを `<tr>` に貼る**（色の定義は
行表示マスタの1箇所＝`--rs-fg`/`--rs-bg`/`--rs-line` が持つので、紙のために
もう1つ色表を作らない）。ただし画面側の受けは `.sc-row-line[class*=…]` なので、
**`<tr>` 用の受けを足す**必要がある。

まとまりの帯も画面（`.sc-group-head`）と同じ3点——名前・**どの日付で数えて
いるか（現場歴／太陽暦）**・件数——にする。基準の印は画面と同じく
**日付でまとめているときだけ**出す（区分でまとめているときは日付を数えて
いないので出ない）。

#### ⑦ 「角丸が無い」の半分は紙のせいではなかった（アプリ全体の不具合）

紙の角丸を直しても、区分バッジだけが 0px のままだった。追うと `.sp-badge` の
ルール自体は効いている（`display:inline-block` も `font-weight:800` も出る）のに、
`border-radius:var(--radius-xs)` だけが無効になっていた。

原因は `static/css/00-base.css` の角丸トークンの**すぐ上のコメント**。
A4帳票の例外を説明する文で**ワイルドカードの直後にスラッシュ**を書いており、
そこでコメントが閉じていた。パーサは続きの散文を宣言として読み、
**次のセミコロンまで**——つまり**直後の `--radius-xs` の宣言ごと**捨てる。

ブラウザで実測（`00-base.css` 単体を読ませて `:root` を引く）:

```
現状 : {"xs":"",   "sm":"8px","md":"10px","lg":"14px","pill":"999px","round":"50%"}
修正後: {"xs":"4px","sm":"8px","md":"10px","lg":"14px","pill":"999px","round":"50%"}
```

`--radius-xs` は **12ファイル128箇所**から参照されている。未定義の `var()` は
*invalid at computed-value time* で宣言ごと無効になるため、**アプリ全体の
いちばん小さい角丸が0**だった——画面のスケジュール行（`.sc-row-line`）と
区分バッジ（`.sc-row-cat`）も含む。利用者の「角丸ベースのデザインも失った」
は、紙だけの話ではなかった。

**なぜ誰も気づかなかったか**（＝どんな網を足すべきか）:

- `tests/test_csslint.py` の「トークンが揃っている」は**コメント除去後の文字列に
  `--radius-xs:` があるか**しか見ない。Python の非貪欲な除去も同じ位置で閉じるので、
  宣言は文字としては残り、チェックは通る。
- `tests/test_scale.js` の角丸の許容値に **`0` が入っている**ので、全部0になっても
  落ちない。
- 既存の「コメントに `**` ＋ `/` を書かない」検査は**綴りを1つだけ**見ている。

**綴りを増やして追いかけない。** コメントを潰したあとに残るのはCSSの構文だけの
はずなので、**そこに日本語の約物（`。`『、』「」（）——）が残っていたら、
どこかでコメントが早く閉じている**。クラス名に日本語を使うことはある
（§9.227 の `.op-look-既定`）ので、**文字そのものではなく約物**で見る。
これなら綴りに依らずこの種の事故を全部拾う（実際、この検査は直後に
**この節を説明するために書いたコメント自身**を捕まえた）。

#### 実装

- `static/css/00-base.css`: 角丸トークンの上のコメントを書き直す（＋再発の注記）。
- `tests/test_csslint.py`: 「コメントを外したCSSに散文が残っていない」を追加。
- `static/js/schedule/schedule-view.js`: `entryCellInfo()` の `flags` を `flagList` から
  作るように分解、`SC_FIXED_TONE` を新設、`printRowCells()` が `tone`/`chips` を
  返す、`groupOf()` に `tone`、`groupBasisLabel()` を公開、
  `columnEffWidthPx()` を実測優先（`measuredColumnWidthPx()`／`uiScaleNow()`）、
  `visibleColumnKeys()` の予算を同じ物差しへ、
  `applyTimelineContentColumns()` が `#scTimeline` へ `data-equipment` を刻む。
- `static/js/schedule/schedule-print.js`: `STATE_TONE`、`badgeHtml()`/`kidBadgeHtml()`/
  `kidBadgeKey()`、`cellsOf()` がバッジ・チップ・子の印を組む、
  `buildPages()` が `rowStyle`/`kidCount` を運ぶ、`shareMm()`＋`withMm()`、
  `pageHtml()` が `.sp-table-wrap`／表幅の合計／`--sp-fit`／帯の3点を出す、
  プレビューの facts に「列幅 設定どおり／N%に縮小」。
- `static/css/70-schedule.css`: `.sp-*` を色トークンと `--radius-*` で組み直し、
  `print-color-adjust:exact`、`.sp-table-wrap`、`.sp-badge`/`.sp-chip`/`.sp-kid`/
  `.sp-est-prov`/`.sp-group-*`、`data-borders="off"` を「本当に0」へ。

固定は `tests/test_scprint.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **紙は「画面の一覧の見た目」が正**（§9.237、利用者の指示「画面印刷の時に
  映るスケジュール一覧表の見た目を正にしてその見た目に近づけてほしい」）:
  §9.236で足した3点は**方向は合っていたが効いていなかった**。実機からの
  指摘は4つで、原因はそれぞれ別。
  ①**枠線を外しても薄く残る**——§9.236で「線は一切無くさない」と決めていた
  のを**撤回**した（外したのに残るなら入切が嘘になる）。`data-borders="off"`は
  **格子を本当に0**にし、残すのは線ではなく**面**（見出しの帯・まとまりの帯）と
  **記入欄の下線**だけ（書く場所が分からなくなるため。チェックの説明文にも書く）。
  **太さで見ること**——色で見ると、線が無くても既定の色名が返って素通りする。
  ②**角丸が無くカクカク・帯がグレー**——紙のCSSは`#000/#e8e8e8/#d8d8d8`だけの
  完全なモノクロで、`--radius-*`も色トークンも1つも使っていなかった。

  ブラウザは印刷時に背景色を落とすので、帯もバッジも真っ白で刷られる

  ④**設定した列幅が効かない**——原因が2つあった。
  **(a)`.sp-table{width:100%}`**が残っており、`table-layout:fixed`は
  **余りを各列へ配り直す**ので、colgroupへ設定どおりのmmを入れても

  素通りする**——描画後の実幅で見ること。
  **(b)`columnEffWidthPx()`が保存値しか見ていなかった**。幅を指定していない

  **成り代わり中（`withEquipment`）は測らない**——目の前の設備の幅を別の設備の
