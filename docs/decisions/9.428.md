# §9.428 図の切り替えは「1回で組む・選んだ図を描く」

索引: [決定記録](README.md)

利用者の報告「3D断面図が切り替え直後には出ません」。
追って聞いた症状は **「断面ではなく通常の3Dモデルが出る」「もう一度『断面図』を
押すと出る」**。

## ① 再現しなかった、ということを先に書く

ヘッドレス（1700×1000）で**押す順をひととおり**試したが、**1度も再現しない**。

| 試した順 | 結果 |
| --- | --- |
| まっさらから 断面図（部品の読み込みが走る） | 1枚目から断面図 |
| 模式図 → 断面図 | 1枚目から断面図 |
| 立体図 → 断面図 | 1枚目から断面図 |
| 読み込み中に 立体図→断面図 を連打 | 断面図 |
| 読み込み中に 断面図→立体図 を連打 | 立体図（押した最後のもの） |

**だから「直した」とは言えない。** 言えるのは、**同じ症状を作れる穴が実在し、
それを塞いだ**ということまで（§9.200「再実行で緑になったからで片付けない」の
裏返しで、**再現しないからで片付けない**）。

## ② 見つかった穴（実在・数で確かめた）

画面（`blade-view.js`）の `figMode()` はこう書いてあった:

```js
WL.bladeSolid.sync({ st, M, res: LAST, ringHex: hexOf });   // ← 前の図のまま組む
WL.bladeSolid.setMode(solid, figKind);                       // ← ここで図が変わる
```

`sync()` は「割付が変わった」ときの口で、**`D3.on`なら その場で組んで描く**。
つまり**切り替えのたびに、まず前の図のまま1回組んで1枚描き**、そのあと
`setMode()` が正しい図で**もう1回**組んでいた。実測で **1回の切り替えに 2回**
（網の値: 組んだ回数 `1 → 3`）。

ふつうは同じタスクの中で2回描くので、画面に出るのは後の1枚だけ——**後の1枚が
遅れるか、あいだに描画が挟まると、前の図のまま見える。** 症状と形が合う。

もう2つ、同じ性質の穴があった:

- **部品（three.js）の読み込みを待つあいだに別の図を押せる。** 待ちから戻った
  古い呼び出しが、そのまま組んでしまう。
- **`render()` は切り替え以外の道からも呼ばれる**（掴んで回している最中の毎
  フレーム・器の大きさが変わったとき・台車を回す／引き出すの動き）。
  そのとき場面に在る模型が**どちらの図のものか**を、誰も見ていなかった。

## ③ 直し方

1. **切り替えの口を1つにする。** 割付は `setMode(on, kind, next)` が受け、
   `D3.cut` を決めてから**1回だけ**組む。`figMode()` は `sync()` を呼ばない。
2. **`D3.builtCut`（いま場面に在る模型はどちらの図か）を持つ。**
   `render()` は `builtCut !== cut` なら**描く前に組み直す**——どの道から
   呼ばれても、出る絵は必ず「いま選ばれている図」になる。
3. **切り替えに通し番号（`D3.seq`）。** 読み込み待ちから戻ったとき番号が
   変わっていたら何もしない（押した最後の図が勝つ）。

`view()` に `builds` / `builtCut` / `fixups` を出した。**絵を見ても
「2回組んだ」「前の図のまま描いた」は分からない**ので、網は数で見る。

**欠陥注入で確かめた**: `sync()`→`setMode()` の2段に戻すと、
`test_bladeui` の「組むのは1回だけ」が**2件**落ちる（`1 → 3` / `3 → 5`）。

## ④ まだ言えないこと

**利用者の端末で何が起きていたかは、まだ分かっていない。** ②を塞いでも
同じことが起きるなら、次に見るのは「切り替えの直後に `fixups` が増えているか」
（＝別の道からの `render()` と重なっている）。`WL.bladeSolid.view()` で読める。
