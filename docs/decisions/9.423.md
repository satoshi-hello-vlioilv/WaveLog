# §9.423 網が見る材料を「現場でよくある形」にする（利用者の指示）

索引: [決定記録](README.md)

利用者の指示:

> 検証用フィクスチャのロットは変更して

（§9.418 ⑤ で保留にしていた問い——「見本が 120mm×6条／片耳225mm のままでよいか」
への答え。）

## ① まず、置き場の思い違いを正す

§9.418 に「**検証用フィクスチャのロットは条幅120mm×5条／片耳225mm**」と
書いたが、**2つ間違っていた。**

| 書いたこと | 実際 |
| --- | --- |
| 条数は5 | **6**（`120 × 6 = 720`、`1170 − 720 = 450`、両耳で割って片耳225mm） |
| 検証用フィクスチャのロット | **フィクスチャではない**——`test_bladeui.js` が手順3で打つ値 |

検証用フィクスチャの `仕掛` 表（`db/test_fixture/sikalotnow_test.sqlite3`）は
ロット番号・材質・コースなどしか持たず、**板厚も板幅も条数も無い**。
`bladeLotsFromSource()` は幅が読めなければ条を1本も作らないので（§9.231
0で埋めない）、刃組ガイダンスは `blade-core.js` の `defaultState()`
（元板巾1170mm・279.8mm×4条＝片耳25.4mm）で開く。
そこへ網が手順3で 120mm×6条 を打ち、**以降の節はすべてその形で見ていた。**

**直す前に実物を読む**（CLAUDE.md B）。「フィクスチャを直す」と思って
`make_fixture.py` を開いても、そこには材料の寸法が1つも無い。

## ② 打つ値を「通常の形」にした

利用者の言う通常の形は **50mmくらいの条が22本くらい／片耳15mmくらい**
（片耳は35mm以下、ラインによっては70mm以上もある）。
`50 × 22 = 1100`、`1100 + 15 × 2 = 1130` なので、手順3で打つのは
**元板巾1130mm・条幅50mm・22条**。

**元板巾を先に打つ。** 条の合計（1100mm）が入らない幅のままだと、屑幅が
マイナスになる条数は受け付けない（§9.210）ので、幅→条幅→条数の順で入れる。

## ③ §9.418 の節は「反対の端」へ作り替えた

既定が混んだ形になったので、**差し替えて確かめる節は幅の広い側**にした
（279.8mm×4条／元板巾1170mm＝片耳25.4mm。画面の既定値そのもので、これも
現場にある形）。**片方だけで決めない**（§9.418）という規則はそのままで、
見る端が入れ替わっただけ。

| | 何がここでしか出ないか |
| --- | --- |
| 50mm×22条（既定） | 札どうしの重なり・区間が細かいときの詰めの丸め |
| 279.8mm×4条（差し替え） | 区間が長いときの詰め・札が離れすぎないか |

待ちも向きが逆になる（刃が「増えたこと」→「減ったこと」）。
**数は決め打ちせず、増減で待つ**のは §9.418 のまま——決め打ちすると、
条件が一度も真にならないまま `until` が黙って素通りする。
