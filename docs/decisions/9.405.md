# §9.405 `setup.bat`を`update.bat`へ改名する（利用者の指摘）

## 利用者の言葉

> setup.batファイルはupdate.batファイルに名前を変更出来ませんか？
> **内容的には合うと思うのですが。**

## そのとおりだった

このファイルが実際にしているのは「**次の起動を速くするための下ごしらえを、
起動の前にまとめて済ませる**」こと（部品の確認・バイトコードの事前
コンパイル・旧DBの取り込み・待機画面の写し・刻印）。そして**押さなくても
起動する**——刻印が合わなければ`start_app.py`が同じ`setup_check.run()`へ
自動で落ちる（§9.225）。遅くなるだけで、止まらない。

つまりこれは「**導入の儀式**（setup）」ではない。**版が変わったら1回**の
作業で、押す回数も導入1回に対して更新はこれから何十回もある。
`update.bat`のほうが**いつ押すのかを名前が言っている**。

**入口の名前は「何であるか」ではなく「いつ押すか」を言う。**
`Start.vbs`（毎日）・`stop.bat`（止めたいとき）・`start_app.bat`
（起動しない原因を調べたいとき）はもともとそうなっていて、
`setup.bat`だけが**物の名前**を名乗っていた。

## 引き受けた弱点と、名前以外での埋め方

`update.bat`だけが置いてあると、**初めて導入した人は「まだ更新していない
から自分には関係ない」と読む**。名前が動作を言い当てる代わりに、最初の
1回を取りこぼす形になる。実害は小さい（押さなくても起動する・遅いだけ）
ので、**改名したうえで、取りこぼしを名前以外で埋めた**:

- `update.bat`の成功メッセージに**次に押す時機**を書き足した
  （`次に実行するのは、アプリを新しくしたときです。`）。
  **推測させない**（§CLAUDE 画面の基準・「効くタイミングを書く」）。
- README の表を「**アプリを新しくしたあとの1回**。導入したときも1回だけ」
  に書き換え、**押さなくても起動する**ことも同じ行に書いた。

## 旧名は残さない

`setup.bat`を「`update.bat`を呼ぶだけの薄い入口」として残す手もあったが、
**入口を2つ持たない**（`setup_check.run()`を1箇所にしている理由と同じ
——2つあると「片方では通るのにもう片方では失敗する」が作れる）。
`tests/test_faststart.py`に「旧 setup.bat を入口として残していない」を
足して、機械で止める。

**ただし現場のフォルダーには古い`setup.bat`が残る**（上書きコピーで更新する
運用では消えない）。しかも古いほうは`python setup_app.py`という**§9.404で
移す前の行**を持っているので、押すと失敗する。
`setup_check.sweep_shared_leftovers()`を広げて片付ける案を利用者へ出して
あるが、**現場のフォルダーから物を消す話なので、返事を待つ**。

## 踏んだところ

**改行を2度付けかけた。** CP932のまま中身を書き換えるのに
`read_bytes().decode('cp932')` → 置換 → `replace('\n','\r\n')` と書いたが、
**decodeした時点で`\r\n`はそのまま残っている**ので`\r\r\n`になった
（`file`が `with CRLF, CR line terminators` と言って気づいた）。
**先に`\r\n`→`\n`へそろえてから**書き戻すこと。§9.229が言っている
「改行そのものを見る」は、直すときにも要る。
