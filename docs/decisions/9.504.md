# §9.504 網は本物の置き場へ試しのファイルを書かない——並列の test_eslint が読みかけで落ちた

索引: [決定記録](README.md)

## 経緯

PR #102 の CI（純粋な網・並列8）で`test_eslint`が1回落ちた。同じコミットの push の実行では通っていた。
記録: `ENOENT: no such file or directory, open '…/static/js/core/_print_probe2.js'`（`eslint.config.mjs`の`topLevelNames()`）。

**原因**: `test_printcore.py`が網そのものの確かめのために、**本物の`static/js/core`へ試しのファイルを書いて消していた**
（`_print_probe.js`・`_print_probe2.js`）。`eslint.config.mjs`は同じ置き場を歩いてファイルを読む。純粋な網は並列で回るので、
eslint が一覧に入れたあとで`test_printcore`が消すと、読みに行ったときに無く、eslint ごと落ちる。時間の重なり方しだいで起きる
（フレークではなく、2本の網が同じ置き場を書く・読むことが原因）。前からあった競りで、今回の変更とは関係ない。

## 決めたこと

- 網は**本物の置き場（`static/`・`backend/`など、ほかの網が読む場所）へ試しのファイルを書かない**。試しは一時の置き場へ書き、
  調べる関数に置き場を渡す（`scan(…, root=一時の置き場)`）。
- `test_printcore.py`の網そのものの確かめは、一時の置き場だけを調べても同じことを確かめられる（写しを数えるか・説明文では数えないか）。

| 物差し（`Path.write_text`を数えて`test_printcore.py`を1回回す） | 前 | 後 |
| --- | --- | --- |
| `static/js`の下へ書くファイル | 2 | 0 |
| 網そのものの確かめ（調べる置き場を本物へ戻す欠陥注入） | — | 落ちる（写しを数えない） |
