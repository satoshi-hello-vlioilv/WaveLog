## 経緯（利用者の言葉）

> メインにマージして、P1に進めて

#212（計画と P0）を main へ入れ、P1（純粋な関数）に入った。P1 は量が多いので4つに分けた。

| 区切り | 中身 |
|---|---|
| **P1a（ここ）** | 依存の無い6つ: 字の正規化・真偽の読み方・日時の読み方・正規表現の危険の判定・値の四則演算・判定表の整え方 |
| P1b | 並べ替えと表示の書式（`sort_order`）・絞り込みの SQL（`filter_sql`） |
| P1c | ダッシュボードの式（`dashboard/formula.py`・1,068 行。JS との突き合わせ `test_formulaparity` が既にある） |
| P1d | 連結した CSS・`index.html`・更新履歴の字をデータファイルへ（ルートなので影で比べてから Serve） |

**移したのは関数だけで、ルートは 0本のまま**（答えるのはまだ Python）。Python の関数はそれを呼ぶルートを移すとき（P2 以降）に消す。
それまでの間、同じ関数が2つの言語にある。この間ずれないことは試験表が見張る（下）。

## 決めたこと

- **答えの正は Python**（利用者の端末で動いているのは Python のほう）。問いは `tests/lib/parity_cases.py` に並べる。
  Python に通した答えを `tests/fixtures/parity/<領域>.json` に書き、Rust は `desktop/core/tests/parity.rs` が同じ表を読んで
  同じ答えかを見る。どの問いで何が違ったかを全部並べて落ちる。
- **網 `test_parity.py`**（純粋な網）は表が今の Python の答えと同じかを見る。Python を直して表を作り直さないと、Rust が
  古い答えに合わせたまま「同じ」と言ってしまうため。表が古ければ `--write` で作り直し、`cargo test` で Rust を直す。
- **問いは違いが出やすい所から選ぶ**: Python の `str()`（`True`・`1.0`・`1e-05`）、`strip()` の空白（`\x1c`〜`\x1f`・全角）、
  `\d` が全角やアラビア文字の数字にも当たり `int()` がそれを読むこと、2桁の年・閏日・14 桁の日時・午前／午後
  （`Amazon` の `Am` は午前ではない）、入れ子の繰り返し、0 で割る・負の数の小数の累乗・累乗の行き過ぎ、壊れた条件の行。
- **Python の決まりの写しは `pyish.rs` の1箇所**: `py_str`・`py_float_repr`（最短の桁、10^-5 未満と 10^16 以上は指数）・
  `py_strip`・`digit_value`（Unicode の 10 進数字 68 組。Python 3.13〈Unicode 15.1〉の unicodedata から作った）・`truthy`。
- **字の畳み方**は `unicode-normalization`（NFKC）と `caseless`（casefold。`ΣΑΣ` は `σασ`、Rust の `to_lowercase` だと `σας` になる）。
- **値の四則演算の失敗**は Python で例外になる所と同じにした: 0 で割る・0 の負の累乗・負の数の小数の累乗（Python は複素数）・
  有限の数どうしの累乗が無限になる。掛け算の行き過ぎは Python でも例外ではない（最後に有限でなければ値なし）。
- **午前・午後の見分け**は Python の正規表現（後読み・先読み）を字の比べ方で写した（`regex` クレートは後読みを持たない）。
- **正規表現の意味は JS（画面）にそろえる**（計画書 §6 で P1 に決めると書いた件）。画面が正で、サーバーの式（`formula.py`）は
  すでに JS の意味へ読み替えており、`test_formulaparity` がそれを見張っている。Rust で利用者の正規表現を照合するのは P1c で、
  そこで `fancy-regex`（後読み・後方参照）を使い、同じ読み替えを写す。P1a の `safe_regex` は形を見るだけで照合しない。

## 測った

|---|---|---|
| Rust へ写した純粋な関数 | 0 | 14 |
| Python と突き合わせている問い | 0 | 245（6 領域） |

- `cargo test -p wavelog-core --test parity`: 245/245 が Python と同じ（1回目から）。
- 網が素通りしないことを欠陥で確かめた: 2桁の年に 2000 を足す境目を `y < 100` から `y < 10` にすると、
  3問（`26/09/28 23:48:54`・`99/1/1`・`26/10/02 8:15`）を名指しで落ちた。戻して通る。

**分からないこと**: CI の Python は 3.11（Unicode 14）、手元は 3.13（Unicode 15.1）。表の問いは両方で同じ答えになる字を選んだ
（`test_parity` が CI でも通れば確かめられる）。Unicode の版で畳み方が違う字を問いに足すと、CI と手元で表が食い違う。
