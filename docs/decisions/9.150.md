# §9.150 板幅測定値の視覚表示を作り替える（縦＝条・横＝測定値）

利用者の指示。

> 板幅測定値の視覚表示は、骨子の案をベースに作り替えてほしいです。

骨子（§9.137）の②は「左＝公差と測定値の**縦**グラフ（選択中の丈位置のみ）、
右＝丈位置×条の表」。丈位置の絞り込みは満たしていたが、**図の中身**が
骨子の意図から外れていた。

#### 何が読めなかったか

以前はスウォームプロット（蜂群図）で、**縦＝測定値・横は重なり避けだけ**。

- **横位置に意味が無い。** どの点が何条かは`title`（マウスを当てないと
  読めない）でしか分からず、現場では読めない。
- 40条では点の雲になる。実測すると210×852pxの帯に39点が散らばっていた。
- 重なり回避のために「点の直径以上離す」「クラスタ内は条の順に左右へ」と
  いう仕掛けが要り、`layoutSwarmDots()`は毎回の再描画で実測を伴っていた。

#### 縦を条に取る

**縦＝条（右の測定表の行と1対1）／横＝測定値**へ入れ替えた。

| | 得られるもの |
|---|---|
| 表の行と同じ高さに並ぶ | 外れている条が**目を横に振るだけ**で読める |
| 条の並び＝材料の幅方向（OS→DS） | **片側だけ太いといった傾きが図として見える**——板幅測定で見たいのはこれ |
| 1条1行 | **重なり避けの小細工が要らない**（横位置が値そのもの） |

**数字は図に出さない**——公差の値は測定カード上の帯（§9.146）、測定値は右の
表にある（§9.129）。図が答えるのは「公差のどのへんか」だけ。

#### 行の高さは実際の表を測って合わせる

`alignToleranceChart()`が**見出し1行と本文1行だけ**を測って`--tc-head`/
`--tc-row`へ入れる（40行は測らない。どの行も同じ高さなので2つで足りる）。
トークンから計算すると罫線と表示サイズのぶんでずれる（§9.95の行高と同じ罠）。
実測での最大ずれは**0.5px**。

図と表は**同じ器でいっしょにスクロールする**（`.matrix-body`が唯一の
スクロール器）。片方だけ動くと行の対応が崩れる。図の列は`position:sticky`で
左に留め、丈位置が多くて横へ流れても残す。

#### 基準の札は「画面の距離」で畳む

公差幅に対する割合で見ていたころは、片側公差でなくても（基準1000／下限999／
上限1003のように基準が下限寄りだと）札が13pxしか離れず「下限基準」と重なって
読めなかった。器の**12%（≒25px）**離れていなければ札を出さない。
**線は常に引く**——製造公差は`+3/-1`のような非対称が普通で、線まで消すと
「狙う値がどこか」が図から失われる。

#### 図の持ち主を`filters.js`から取り戻す

`filters.js`（一覧の絞り込みのファイル）が`compactToleranceScale`を**丸ごと
差し替えて**おり、`measure-input.js`の定義は一度も実行されない死んだ
コードだった（CLAUDE.md「同じ関数を2ファイル以上が全置換すると…」）。
作り替えにあたって差し替えを外し、本体を`measure-input.js`へ戻した。
`test_patchlint.py`のALLOWEDからも消した（残っている全置換は2件）。

#### 固定は`tests/test_tolscale.js`

図の作りが変わったので書き直した（26件）。要点は
**「図の行数が測定表の行数と同じ」「図の行が測定表の行と同じ高さに並ぶ」**の
2つで、これがこの図の値打ちそのもの。ほかに、値→横位置の写像が線形か／
基準の線が範囲の中点ではなく基準値を指すか／公差外が端に張り付かないか／
先読みリングが確定後の点と同じ横位置か／**値がほぼ同じ条でも点が重ならないか**
（行が違うので重なりようがない、という新しい約束）。
