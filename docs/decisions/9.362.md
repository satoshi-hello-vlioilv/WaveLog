# §9.362 後片付けは「書いてある」ではなく「消えた」で確かめる

§9.360 で入れた指紋（テストの前後で表ごとの行数を比べ、**汚した本をその場で
名指しする**仕組み）を実際に0件まで下げにいったところ、**後片付けを書いた
つもりで一度も効いていなかった**ものが5種類出てきた。どれも**テストは緑**で、
**書いてあるコードを読んでも間違いに見えない**。共通しているのは
**「消えたことを測っていなかった」**の一点だけだった。

## 見つかった5つ（すべて実測）

### ① 相対パスの後片付けは、黙って空振りする
`run_all.sh` の `resetrecords()`（実績を1本ごとに空へ戻す。§9.356で入れた）は
`pathlib.Path('db/records.sqlite3')` を開いていた。ランナーは `cd tests` して
から走るので、これは `tests/db/records.sqlite3` を指す——**存在しないので
`if p.exists()` が偽になり、例外にもならず、何も起きない。**
入れた日から一度も動いていなかった。

同じ形を `tests/state_fp.py` でも踏んでいる（§9.360 の追補で `__file__` 基準へ
直した）。**ランナーの中で開くDBの道は絶対で書く**——`test_layers.py` に
「相対の道が無いこと」と「実績を空へ戻す口が実在するDBを指していること」を
足した。

これが直った瞬間、`Web測定バックアップ ±1` が出ていた9本のうち**5本は
何も置いていなかった**ことが分かった。`+1`と`-1`が混ざっていたのは、
表が**実行をまたいで生き延びていた**ためで、指紋が見ていたのは
「その本の置き土産」ではなく「前の本との差」だった。

### ② 名前空間に入れた関数を素の名前で呼ぶと、`catch` が握って無音になる
`test_devdigits` の後片付けはこう書いてあった:

```js
try{await deleteBackupRows([id])}catch(e){}
try{await reliableDelete(id)}catch(e){}
```

§9.359 で画面のJSを32本ともIIFEで閉じたので、これらは `WL.records.*` にしか
無い。素の呼び出しは `ReferenceError` になり、**その場の`catch`が握る**。
後片付けは**1行も実行されないまま緑**で、実績が1件ずつ積み上がっていた。

eslintは`tests/`も見るが、**`no-undef`はテストでは切ってある**
（テストはNodeで動き、`require`/`process`を持つため。`eslint.config.mjs`）。
だから素の呼び出しは静的解析でも出ない。`test_waitlint.py` に
「テストが素の名前で画面の関数を呼んでいない」を足した。面（呼ぶと落ちる
名前の一覧）は**実物から作る**（§9.354と同じ作法）——手で並べた一覧は、
面が増えた日から黙って穴になる。注入で素通りしないことも同じ網で見ている。

なお**空の`catch`は`tests/`でも数えられている**（`no-empty`をファイルごとの
上限で固定・§9.326）。後片付けを足すときに`catch(_){}`を並べると、その網が
落ちる——**捨てるときは理由を1行残す**（§9.328）。実際、§9.360の第1弾で
6本ぶん上限を超えたまま気づかず、次の実行まで赤を持ち越した
（**足した網を回していなかった**——変更したファイルから網を選ぶ
`--changed`を通していれば、その場で出ていた）。

### ③ 消す前にモードを戻す
`test_rlmaster` は最後に閲覧モードへ切り替えてから後片付けをしていた。
書き込みは `/api/access-mode` の関所で弾かれ、
`{"error":"現在のモードでは、この操作は実行できません。"}` が返るのに
`catch` が握って**24行が残っていた**。後片付けの順は
**「画面を閉じる → モードを戻す → 消す」**。

### ④ 空のIDで送った操作は、この端末のIDで埋まる
`test_colscopeui` は「IDを名乗れない端末では自分だけの設定を持てない」を
確かめるため `user_id:''` で切り替えを送る。ところが誰の操作かは
`request_user_id()`＝`current_login_id()` の1箇所が答える（§9.276 ③）ので、
**ログインIDを持つ端末では空が`root`で埋まる**——`root`の個人設定として
37行が複製され、そのあと共通へ戻しても**個人の行は消えない**仕様
（§9.259）なので、毎回37行が積み上がっていた。

後片付けは端末のIDを当てにいくのではなく、**印の表（`列レイアウト個人設定
マスタ`）に載っている持ち主を全部拾う**。消してよいのは**この実行で増えた
行だけ**なので、触る前に行のIDを控えておく（無差別に消すと、後片付けを
持つ他の網の前提と食い違う・§9.284）。

### ⑤ 論理削除は行を残す
`test_maint` の「勤務体系を削除できる」は製品のAPIで消しているが、
`shift_pattern_delete()` は `有効=0` にするだけ（設備割当だけ実DELETE）。
**一覧からは消えるが行は残る**ので、勤務体系2行＋勤務区分2行が毎回増える。
論理削除の網は、素の表（`/api/master-table/<表>/delete`）で自分の作った行を
片付けるところまでが1組。

### ⑥ 他の本が残したものを前提にしていた網が、①を直した瞬間に落ちた
`test_eqfeature` の「記録のある設備は帳票から外しても候補に残る」は、
`テスト設備A` に**記録があるつもり**でいた（コメントにも「フィクスチャに
ロットのある設備」と書いてあった）。実際に入っていたのは**前の実行の
置き土産**で、①で実績が本当に空になったとたん `.record-list-row` の待ちが
25秒で timeout した。**材料は自分で注ぎ込む**（§9.351）——置いて、消す。
中身は`codec:'json-full-v32'`＝レコードそのままのJSONで渡すこと
（`'x'`のような当て字だと一覧には出るが、開いた先の帳票が組み立てられない）。
所要は 39秒→**15秒**（待ちが空振りしなくなった）。

## 決めたこと

- **後片付けは「消えたこと」を測るまで、無いのと同じ。** 書いてあること・
  緑であることは根拠にならない（①②③はすべて緑だった）。
  `WAVELOG_FP_DETAIL=1 tests/run_all.sh <本>` で**その本の差分が0になるまで**見る。
- **ランナーが開くDBの道は絶対で書く**（`test_layers.py`）。
- **テストは製品の関数を名前空間で呼ぶ**（`test_waitlint.py`。0件を固定）。
- **後片付けの順は「閉じる → モードを戻す → 消す」。**
- **実績の後片付けは`tests/lib/harness.js`の`clearRecords()`の1箇所**——
  網ごとに書き写すと、書き忘れた本だけが無関係な網を落とす形で現れる。
  土台（`run()`）に乗っている網は書かなくてよい。

| `test_rlmaster` | `列レイアウトマスタ[report:共通] +24` | 0 |
| `test_colscopeui` | `[list:SIKALOTNOW:仕掛] +37` ／ 個人設定 `+2` | 0 |
| `test_cols` | `スケジュール内容表示マスタ[テスト設備A] +2` | 0 |
| `test_mcore`ほか5本 | `Web測定バックアップ ±1` | 0（①で消えた＝置いていなかった） |

| `test_flows`・`test_oppad`・`test_defectlink` | `Web測定バックアップ +1` | 0（`clearRecords()`） |
| `test_maint` | `勤務体系マスタ +2` ／ `勤務区分マスタ +2` | 0（⑤） |
| `test_eqfeature` | `.record-list-row` の待ちが timeout | 0（⑥。39秒→15秒） |

**合計37本**を実測で0件にした（指紋の報告が「うるさい一覧」から
**本物だけを指す警報**になった）。

### ⑦ 「減っている」は「増えている」より悪い
`test_shift` だけは指紋が**マイナス**（`勤務体系設備マスタ -4`）だった。
この網は自分が作る体系と**同じ名前**の体系がフィクスチャにもあるのに、
**名前で引いて消していた**——製品の削除は設備割当を実DELETEするので、
フィクスチャの割当4行が毎回消えていた（§9.284 の「無差別に消すと、
後片付けを持つ網の期待と食い違う」そのもの）。**消えた行は誰も戻さない。**
後片付けは名前ではなく「**触る前に居なかった行**」で決める。
