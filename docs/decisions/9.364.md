# §9.364 仕掛から消えたロットは「実績」で突き合わせる——役割を1つ増やす

利用者の指示:「**作業スケジュール表に組んだロットが、仕掛データから消えた
場合は、作業完了または作業開始したものとして扱いたいです。そこで、「仕掛」
「品質」に続いて「実績」というジャンルを1つ追加します。このデータが設定
ある場合、仕掛データから消えたロットを「実績」から「ロット番号」と「鋳造
番号」と「前工程実績_作業終了_日付」の組み合わせで検索し、対象のロットが
HITした場合、作業完了とし、スケジュールデータにHITした実績データを保存して
実績データが今度更新されてなくなっても保持できるようにしてください。この
キーの組み合わせは後から変更できるようにしてほしいです。**」

## 何が起きていたか

仕掛データは**前工程が終わると行が落ちる**。予定に組んだロットがそこから
消えても、作業スケジュールは「予定」のまま置いていた——現場から見ると
**もう手を付けた（あるいは終わった）ものが、いつまでも次の1本として
並んでいる**。状態を直すには人が1件ずつ触るしかなかった。

## 決めたこと

### ① 役割は4つ目「実績」を足す（`データソースマスタ`の`[役割]`）
`仕掛`／`品質`／**`実績`**／`スケジュール`。判定は今までどおり
`db_access.ACTUAL_DB_KEY`が1箇所で答える——**キーの文字列で比較しない**
（§9.87でそれをやって実機が壊れた）。

### ② 突合キーは「行が持つ」。答えるのは1箇所
既定は利用者の指定どおり **ロット番号／鋳造番号／前工程実績_作業終了_日付**。
保存先は`データソースマスタ`の`[突合キー]`（JSON配列）で、**全体の設定に
しない**——実績のデータソースを差し替えたときに、キーだけ前のまま残る。
答えるのは`db_access.actual_match_keys()`の1箇所。編集場所は
**マスタ管理＞データソースの「実績」行の中**（利用者の選択）——
「どのデータを・どの列で突き合わせるか」が1画面で完結する。

読む側は**JSON配列でも読点区切りでも受ける**。手で直した行を黙って既定へ
倒すと「設定したつもりの列で突合していない」が作れる（§9.328）ので、
読めなかったときは理由を1行残す。

### ③ 「仕掛に在るか」は、**仕掛にも実在する列だけ**で見る
実測では、仕掛は`ロット番号`と`鋳造番号`を持つが
**`前工程実績_作業終了_日付`を持たない**（34列を確認）。突合キーを
そのまま在席判定に使うと、1件も当たらず**全部が「消えた」**になる。

そこで、在席は「突合キーのうち仕掛にも実在する列」で、実績の検索は
**キーの全部**で行う。1つでも仕掛に無ければ判定できないと答える。

### ④ 消えたときの扱い
| 状態 | 扱い |
| --- | --- |
| 仕掛に在る | **予定のまま**（今までどおり） |
| 消えた＋実績にHIT | **完了**。HITした実績の行をそのまま持たせる |
| 消えた＋実績に無い／実績が未設定 | **着手**（消えた＝少なくとも手は付いている） |
| 判定できない（読めない・鍵が足りない） | **1つも動かさない**＋理由を持たせる |

**測定データとの突合（§7.4）が先。** あちらで着手／完了になっている行は
ここで触らない——同じ状態を2つの根拠で決めると、食い違ったときにどちらが
正しいか言えなくなる。計画者が確定した完了／取消も動かさない。
子ロットは親にぶら下がる明細行なので単独では判定しない。

### ⑤ HITした実績は共有スケジュールへ残す
実績データは次の抽出で消えるので、**突合できた事実をあちら任せにしない**。
`作業予定`へ`[実績JSON]`を足し（「無ければ足す」で移行・§9.315）、
**書込役の端末が予定を開いたときに自動で**まとめて1回書く（利用者の選択）。

- 持ち主が別の端末なら書かない（あちらが開いたときに書く）
- 閲覧モードでは書かない（書込ガードと同じ線引き）
- **既に入っている行は上書きしない**——後から読み直して「見つからない」で
  空へ戻すと、保存した意味が無くなる
- **書けなくてもGETは通す**（fail-open）。予定が読めないことのほうが痛い。
  黙って諦めず、理由は`warnings`で画面へ返す

### ⑥ 画面は「なぜその状態か」を字で言う
区分の隣に`実績`／`仕掛落ち`の小さな札を出し、詳しい理由は`title`へ落とす
（§9.234 ①）。**状態を色だけで語らない**（§3）——「完了」という字だけでは、
測定したから完了なのか、仕掛から落ちたから完了なのかが読み取れない。

## 踏んだ罠

網を書くとき、**`plan/add`はスケジュールモードでしか通らない**のに
editモードで呼んでいた。403で1件も入らないのに、**フィクスチャに元から
ある同じロットの予定を拾って通ってしまった**（偽の合格）。IDを控えて
**自分が足した行だけ**を見るよう直した。「材料は自分で用意する」
（§9.351）は、**用意できたことまで確かめて**初めて成り立つ。
