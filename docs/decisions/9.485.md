# §9.485 ロット問い合わせの自動ログインは同梱の Edge 拡張が持つ——WaveLog は ID・パスワードを受け取らない（利用者の指示）

索引: [決定記録](README.md)｜その後: [§9.521](9.521.md) で拡張ごと LotData-Link へ移した（WaveLog は ID・パスワードを受け取らないまま）

## 経緯

利用者の指示「社内環境だと必要がないのですが、ロット検索で、VPN環境だと添付のような入力画面になるので
1クッション必要です。ロット検索用のVPN環境時のID＆PASSを登録しておき、必要に応じて自動入力して自動ログイン
するようにできませんか。ID,PASSはレジストリかどこか比較的安全な場所に保存しておき…初回登録はVPN環境で
ロット問い合わせを使って、登録データがないと判断されたとき、登録修正もどこかから配線…PC単位で管理でき、
他PCからデータが見えない場所に保存する仕組み」。

ロット問い合わせ（`http://nlmfangyweb1a/LotDspWeb/`）は WaveLog とは**別のサイト**で、ブラウザは別のサイトの
入力欄に触らせない（`base.js`の`openLotDsp()`にも同じ断りがある）。入れる役は**そのサイトの中で動ける物**＝
ブラウザの拡張にしか持てない。

## 決めるまでの経過（撤回した案）

1. **WaveLog が資格情報マネージャーに持ち、拡張へ HTTP で渡す案**——置き場は Windows の資格情報マネージャー
   （DPAPI・この PC だけ）で、渡す口は 127.0.0.1 からかつ拡張の ID を名乗る`Origin`だけに絞った。
   **この環境（開発用の Claude Code）の安全確認が、資格情報を返す HTTP の口を作る操作を止めた**
   （新しい攻撃の入口になる）。回避はせず、利用者に選んでもらった。
2. Edge のパスワード保存——既に使っているが自動では入らない。`http://`のページでは Edge／Chrome は
   欄を押して候補を選ぶまで入れない作りと理解している（**推測・実機では確かめていない**）。「ログイン」の
   1手も残る。
3. **採用: 拡張の中に登録する**（利用者の選択「拡張の方式で」）。WaveLog に口を作らない。

## 決めたこと

- 拡張は`program/lotdsp-ext/`（Manifest V3・権限は`storage`だけ）。Edge の「展開して読み込み」で入れる。
- 置き場は拡張の`chrome.storage.local`＝**Edge のこの PC・この Windows ユーザーの領域**。`sync`は使わない。
  **限界を画面にも書く**: Windows のログオンでの暗号化はされない（同じ Windows アカウントでこの PC を使える
  人には読める）。答えは`store.js`の1箇所（ログイン画面も設定画面もここを通す）。
- ロット問い合わせのページでログイン欄（`#input_userId`・`#input_password`・`action.login()`のボタン）が
  **見えたら**（`lotdsp.js`）:
  - 登録済み → 人が打ったのと同じ合図（`input`・`change`）で入れて「ログイン」を**1回だけ**押す。
    8秒で欄が消えなければ失敗とみなし、帯で知らせる（**繰り返さない**＝ロックさせない。開き直しても
    30秒は押さない）。ログイン前に開いていたロット（`linkkey`）から外れたら1度だけ戻す。
  - 未登録 → 押さずに**その場で登録できる帯**（登録するとそのままログイン）。
  - パスワードは画面の文字に出さない（帯には ID だけ入れ直す）。
- 登録・直す・消すは拡張の設定画面（ツールバーの拡張アイコン、または WaveLog から）。
- WaveLog の「使用設備の設定」に**③ロット問い合わせのログイン（VPNのとき）**:
  拡張が入っているか（`wavelog.js`が`<html data-lotdsp-ext>`で名乗る）、入っていなければ入れ方の手順と
  フォルダの場所（`GET /api/lotdsp/ext`＝場所と版だけ）、入っていれば設定を開くボタン（`wl:lotdsp-options`の
  合図を拡張が受けて開く）。**WaveLog は ID・パスワードを受け取りも渡しもしない。**

## 測った（見本ページ・`tests/fixtures/lotdsp_login.html`）

本物のロット問い合わせはこの環境から届かない（VPN が無い）ので、利用者のスクリーンショットと同じ形の見本で測った。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 利用者が手でする操作（欄→ID→欄→パスワード→ログイン） | 5 | 0 |
| 拡張が「ログイン」を押す回数（違うパスワードでも） | — | 1 |
| 開き直したときに続けて押す回数 | — | 0 |
| 画面の文字に出たパスワード | — | 0 |

欠陥注入で確かめた: `input`の合図を外すと5件、「直前に押した」の控えを外すと1件落ちる。

## 分からないこと（利用者の確認が要る）

- 会社の Edge で拡張を読み込めるか（管理の設定で禁じられていることがある）。
- 本物のロット問い合わせで、ログインのあと元のロットの検索まで進むか。
