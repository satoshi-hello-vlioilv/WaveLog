# §9.100 マスタ管理の操作もヘッダーの操作列へ

**残っていた1画面。** 「画面名はヘッダーが持ち、操作ボタンは`#headerViewBar`
へ相乗りさせる」(§9.48・`base.js`の`mountViewToolbar`)は他の画面へ入って
いたが、マスタ管理だけ**操作の置き場が2段**だった。ヘッダーの操作列には
更新者IDしか載っておらず(全幅35pxの行に入力1つ)、絞り込みと再読込は
パネルの中の`.mm-toolbar`に残っていた。

**実測。** 実績カレンダーは既に載っていた(`#calToolbar`が`#headerViewBar`の
中にある)ので、直す対象はマスタ管理だけだった。移設して:

| | 移設前 | 移設後 |
|---|---|---|
| `.mm-toolbar`(パネル内の帯) | 61px | **37px** |
| 一覧の見える高さ | 648px | **671px** |

パネルに残したのは**見出しだけ**(「オペレータマスタ 有効136件」)。
見出しは操作ではないので、操作列へ混ぜない。

**移すと左右の余白が上書きされる。** `85-headerbar.css`の
`.hd-viewbar select,.hd-viewbar input{padding:0 var(--ctl-pad-x-xs)}`が
後から効くため、`.mm-search input`が持っていた「アイコンぶんの左余白30px」が
消え、**虫めがねが文字に重なった**(移してから実測で気づいた)。
アイコン付きの入力をヘッダーへ移すときは、余白を取り戻す指定が要る。
高さと文字も`--ctl-h-sm`/`--fs-sm`へ揃える(操作列に並ぶものは全画面で
30px・1種類、が`tests/test_theme.js`の約束)。

固定は`tests/test_headbar.js`。5画面それぞれについて、操作列が本当に
ヘッダーへ載っていること・パネル側に二重に残っていないこと・高さと文字が
揃っていること・**画面を出たら元の親へ戻る**こと(捨てると次に開いたとき
操作が消える)を見る。アイコンだけのボタン(`‹` `›`)を文字サイズの対象外に
するのは`test_theme.js`と同じ扱い——ここだけ厳しくすると、既存の意図的な
作りが落ちるだけになる。
