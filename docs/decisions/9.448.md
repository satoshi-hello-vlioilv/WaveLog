## ② 点検の報告を1つ訂正する

報告では「**浮くメニューが4流儀ある**」と書いたが、**器の数は4ではなく3**
だった。`.sc-row-menu` は既に `.col-head-menu` の修飾子で、
`.fb-preset-menu`・`.sc-sync-menu`・`.ui-size-menu` など**7つの面が
`.access-mode-menu` を使い回して**いた。つまり「器を使い回す」作法は
すでに在り、**足りなかったのは「使い回す先が2つあった」こと**。

数え直すと、浮いて出る面は**全部で12**（列見出し・予定の行・その入れ子・
測定データ一覧・モード・同期の状態・表の切り替え・再読込・フィルタの
組み合わせ・条件・説明のヒント・見本の情報・「表示」）。
これが `.col-head-menu` / `.access-mode-menu` / `.rec-row-menu` の
**3つの土台**に分かれていた。

## ③ 直し方——土台は`.wl-menu`の1つ、違いは修飾子

```
.wl-menu            器（位置・重なり・幅・余白・枠・角・地・影）
.wl-menu button     項目（高さ36px・字13px・横並び・ホバー・焦点・使えない時）
  └ .col-head-menu   …字がはみ出したら省略記号
  └ .sc-row-menu     …折り返せる（説明の1行を下へ落とす）
  └ .rec-row-menu    …項目は縦積み（字＋その下に理由）
  └ .access-mode-menu…札は縦積み（名前＋その下に一言）
```

寸法は**トークン1箇所**（`00-base.css`）:
`--menu-w` / `--menu-w-max` / `--menu-pad` / `--menu-item-h` / `--menu-shadow`。

**項目の高さは`--ctl-h`（≒36px）へ揃えた。** 左メニューの行き先も普通の
ボタンも36pxなので、**同じアプリの中で押す物の大きさを2種類にしない**。
字も13px（`--fs-base-sm`）に揃えた——**小さいほうへ揃えない**
（12pxは「表内で少し強調したい文字」の寸法で、押す物の字ではない）。

## ④ ふるまいも1箇所（`WL.popMenu`）

`static/js/core/pop-menu.js` が持つのは**器のふるまいだけ**:
置き場所（画面の外へ出さない）・外を押したら閉じる・Escで閉じて開いた本人へ
焦点を返す・**矢印キーで項目を移れる**・`role`を名乗る。

以前はこの配線が**3箇所に書き写されて**いた（`schedule-view.js` /
`records-store.js` / `access-mode.js`、それに `list-view.js`）。写しがあると
**矢印キーのような横断の改良が3箇所の問題**になる——実際、`role`を名乗って
いたのは測定データ一覧の1面だけ、矢印キーで移れる面は**0**だった。

**中身は呼ぶ側のまま。** 項目のHTMLまで取り上げると、面ごとに違う持ちもの
（鍵盤の札・できない理由・色見本・入れ子）のぶんだけ分岐が戻ってくる
（§CLAUDE「その場しのぎの分岐を足さない」）。受け取るのは**組み上がった器**だけ。

入れ子は `adopt()` で**家族**へ足す——子の中を押しても親は閉じない
（§9.398の作法をそのまま保つ）。

## ⑤ 踏んだ罠——土台を修飾子より後に書いていた

最初、`.wl-menu` を `.access-mode-menu` の**後ろ**に置いた。どちらも
詳細度(0,1,0)なので**後に書いた土台が勝ち、修飾子が黙って効かなくなる**。

見つかったのは**欠陥注入**だった（§9.399）。`.access-mode-menu` へ
`min-width:190px` を戻して「網が落ちるか」を見たところ、**落ちなかった**
——製品側が正しくなったのではなく、**その行が最初から効いていなかった**。
土台を修飾子より前へ移したら、注入で U=9 と落ちるようになった。

**両方PASSは証拠にならない**（§9.102）。網を書いたら、必ず**壊して落ちること**
を見る。

このとき `.access-mode-menu{padding:var(--space-2)}` も効いていなかったと
分かったので、**そのまま外した**——札の中に余白（`--pad-card`）があるので、
器の側で足すと2重になる。

## ⑥ ここでやめたこと（次の一手）

`role` と矢印キーを通したのは**本物のメニュー4面**だけ:
列見出し・予定の行（と入れ子）・測定データ一覧・モード。

残りの面は**器の見た目だけ**を共有している。**情報を読ませる浮きパネル**
（同期の状態・説明のヒント・見本の情報・「表示」の設定）に`role=menu`を
名乗らせると、**支援技術に嘘をつく**ことになる——あれは「項目を選ぶ面」
ではない。表の切り替え・再読込・フィルタの組み合わせ／条件の4面は
本物のメニューなので、**次に通す候補**はここ。

## ⑦ 固定した網

- `tests/test_popmenu.js`（新規・9件）: 流儀が7種／項目の高さが36pxを
  下回らない／**浮いて出る面は全部`.wl-menu`を名乗る**（器を作る所を
  ソースで数える——画面を1つずつ開くと、開けない面を数え落とす）／
  列見出しメニューが`role=menu`で項目が全部`menuitem`／↓で焦点が移る／
  Endで最後へ飛ぶ／Escで閉じる／外を押すと閉じる。
- 欠陥注入で確認: `.access-mode-menu`へ`min-width:190px`を戻すと
  「流儀は7種」が U=9 で落ちる。

## ⑧ 追補——網を1本足したら`--pure`も回す

この2本を足したとき、CIの1段目（純粋な網）が `test_waitlint.py` で落ちた:
`waitFor…(...).catch(()=>{})` を3箇所で書いており、**黙って握りつぶす待ち**
（§9.360）を新しく増やしていた。

**見落とした理由は回し方**だった。名前を指定して回すやり方（CLAUDE.md A）は、
**自分が触っていない見張りを選ばない**——`test_waitlint` は `tests/*.js` を
横断で数える網なので、新しい本を足した瞬間から見る対象なのに、
「触ったファイル」からは辿れない。

**網を1本足したら `tests/run_all.sh --pure` も回すこと。** 1段目は52本・
実測20秒で、サーバーも要らない。フルスイート（約39分・指示があるときだけ）
とは別の話。
