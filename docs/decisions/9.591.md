## 経緯（利用者の言葉）

> 仕掛情報や品質情報、作業スケジュールの仕掛一覧や作業スケジュール表に関しても上部メニューの構成の不満やUIサイズの
> バラバラ感が残っており、この点も別リポジトリのLotScopeのメニューなどのUIの内容構成や配置が非常に優秀で参考になると
> 思うので不足している機能は実装し、UI配置やUI関連サイズ、デザインに関しては再構築をお願いします。

足す機能は利用者に選んでもらった: **Excel に出力・一覧の拡大（60〜200%）・表示の設定の書き出し／読み込み**（小さな3つ）と
**スライサー・色付け**。LotScope の「並び・まとめ」と「行カード」は入れない。

## 4. 決めたこと

1. **帯の寸法の置き場は1つ**（`00-base.css`の`--bar-h`／`--bar-fs`／`--bar-px`＝30px・13px・横の余白）。ヘッダーの状態の札・
   ボタン・表の札（`.hd-table-badge`）・画面の操作列（`.hd-viewbar`）・一覧の帯（`--lt-*`の既定）が読む。
   並べた狭い器（作業スケジュールの分割・ポップアップ）だけは`--lt-*`を宣言し直す（26px・11px・§9.505 のまま）。
2. **帯の並び（M1）**: 1段目＝左に絞り込む（一覧を検索 → プリセット → 条件 → 列で絞り込む → スライサー → 色付け）、
   右端に見せ方（表示列 → 表の見せ方 → ファイル ▾）。2段目＝左に状態（件数 → 元データ → スライサー・色付けの札 → 結合など）、
   右に見ている範囲を動かす道具（拡大 → ページめくり）。道具の字は`.lt-tool-t`に入れ、狭い器では印だけにする
   （効いている「列で絞り込む」は字を残す＝状態を色だけで言わない）。
3. **スライサー**（`list/list-slicer.js`）: 列ごとのカードに値と件数の帯。数えるのはサーバー（`GET /api/table/slicer`）——
   一覧と同じ絞り込み（`_table_where`）で、**自分の列の選択だけ外して**数える（選んでいない値の数も見える）。選んだ値は
   問い合わせの`filters`へ「どれかと同じ」（`in`・空の字は空欄）で足し、絞り込みの条件（`S.genericFilters`）には入れない。
   面は一覧のすぐ上（同じ親）で、作業スケジュールが一覧を運ぶとき（`moveGridTo`／`returnGridHome`）一緒に運ぶ。
4. **色付け**（`list/list-marks.js`）: 決まり（条件は かつ・8つまで・条件は6つまで）を問い合わせの`marks`で送り、
   サーバーがページの行に当たりを付ける（絞り込みと同じ SQL を`VALUES`の CTE に当てる＝数の読み方も同じ）。
   件数は絞り込んだ全件で数える。塗る所はセル／行。色は`--look-*`の6色。2段目の札が「何の決まりで何件か」を字で言い、
   押すと塗るのをやめる（決まりは残る）。
5. **一覧の拡大**（`list/list-tools.js`）: 表（`#grid>table`）に`zoom`（60〜200%・10刻み・この窓のあいだ）。仮想行の空行は
   拡大前の高さで作る（`list-view.js`が実際の比を測って割る）。列幅のつまみも比で割る。並べた狭い器では拡大しない。
6. **Excel に出力**: 画面が絞り込んだ全件を集め（5000件ずつ）、`WL.list.exportTable()`＝一覧と同じ見え方（表示列・書式・
   予定に入れたロットを伏せる）で表にして`POST /api/table/export-xlsx`（`xlsx_io.write_sheet`）へ。10万件を超えるときは聞く。
   セルは**書いてある通りに数**（`WL.formula.strictNum`・3桁区切り可・先頭0の番号は字）で15桁までなら数、ほかは見えている字
   （`exportCell()`の1箇所。16桁以上の番号を数にすると桁が落ちる）。`strictNum`は名前空間へ出していなかったので出した
   （型の網が「無い」と言った——出していなければ書き出しが実行時に落ちていた）。
7. **表示の設定のファイル**（`wavelog-list-display`）: 列の設定・スライサーのカード・色付け・絞り込み条件・表示件数・行間。
   **スライサーで選んだ値は持たない**（その場の絞り込みで、人に渡す設定ではない）。
8. 作業スケジュールの帯の字を落とすしきい値（§9.506）は13pxで測り直した: 字を全部出して要る幅 100.0〜109.0em →
   **109.2em**／「追加」の字を落としたあと 84.7〜93.3em → **93.4em**（`em`は器の字の大きさで解けるので、字を変えたら測り直す）。

## 5. 踏んだ罠

- **`:is()`の詳細度は中のいちばん強い物**。帯の束ねた規則の`:is(…, .filter-adhoc-row>button)`が(1,1,1)になり、
  `:is(#genericFilterBar,#listToolbar) .lt-zoom-btn{padding-inline:0}`（1,1,0）が負けて −／＋ の字が器より広くなった
  （`test_typescale`）。拡大のボタンは束ねた規則から外し、自前で高さ・字・余白を書いた。
- `.lt-sums:empty`は効かない（中の器が`display:contents`の空の`span`）。`:not(:has(button))`で伏せる——席が残ると
  幅380pxの2段目が1つ折れる。
- 分割表示の2段目は1px足りずに3段になった（右の群を器に包んで間隔が1つ増えた）。狭い器では2段目の間隔も詰める。
- `test_csslint`の重ねの見張りは`:is(a,b)>i`を`a`・`b`の宣言として数える。印の規則はセレクタを並べて書いた。
