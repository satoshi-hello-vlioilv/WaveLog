# §9.529 刃組のマスタを同じ作りの盤に——刃は設備＋セット＋刃厚・潤滑リングも被り判定へ・刃選択は2つの判定表（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「アプリのマスタ関係の改良をお願いします。マスタのデザインがイマイチなので、すっきり統一感が欲しいです。
認知心理学、情報アーキテクチャに基づいてモダンで美的センスを感じる直感的な考えさせないUIUX設計をお願いします。
１）刃マスタについて ①名称をキーには使わない ②選択する内容、設備、刃の厚さ、セット名(アルファベットから選択)、
というキーは3つで管理してください。③マスタが使いにくい。カテゴリや使用状態がマスタのモーダルから取り扱いできないので
使いやすく再構築してください。
２）ゴムリングマスタについて ①色の被り判定の中に潤滑リングが入っていません。②新規の色を追加する際に色名を付けられません。
③マスタが使いにくい。
３）刃選択マスタについて ①専用刃を使う条件だけになっていますが、刃厚を選ぶテーブルと通常刃か専用刃を選ぶテーブルの2つを
準備し、5㎜刃か10㎜刃かなど、登録している刃厚を選択対象にできるようにしてください。条件テーブルは「保持方式」の選択マスタ
みたいな条件テーブルの作りが好ましいです。自由に条件設定ができ、他マスタで設定した項目(例えば板押さえ)も条件に加えられる
ようにしたいです。条件式の書き方はわかりやすく、サジェスト機能もつけて使いやすく再設計してください。②マスタが使いにくい。」

利用者の選択（3つ）:

- 刃とゴムリングの盤の形 … **一覧＋詳細の2ペイン**（左＝セット／色、右＝選んだ1つ）
- 専用刃に当たったときのセット … **答えでセットも選べる**（専用刃（B）など）
- ゴムリング②の状況 … **色名の欄が見つからない**（手元では名前を付けられたので確かめた）

## 決めたこと

### 共通の作り（「すっきり統一感」）

- 刃・ゴムリング・刃選択・保持方式の専用の盤は**同じ頭・同じ2ペイン・同じ判定表**を使う。
  `board-kit.js`（`WL.bsKit`: 設備の頭・一覧＋詳細・2択の札・保存の段取り）と
  `rule-table.js`（`WL.ruleTable`: 判定表）の2本に集め、盤は中身だけを書く。
- 頭は「設備 ｜ いまの状態 ｜ 操作」の1行＋説明の1行。**タブ名を繰り返す名札をやめた**（同じ字が2箇所）。
  表ごとの状態（登録済み／未登録／保存していない変更）は表の頭が言い、盤の頭では繰り返さない。
- 値はトークンだけ。状態は色だけで言わず札・字を添える（研磨中＝橙の札＋斜線、専用刃＝tealの札）。

### 刃（1）

- 1種類の刃は**設備＋セット＋刃厚**（`blade_upsert()`が同じ3つの2行目を断る）。セット名は `BLADE_SET_NAMES`（A〜Z）の
  1字で、`blade_set_name()`が全角・小文字を読み替える。`名称`の列は読むだけで、呼び名は `blade_label()`（例: A 10mm）。
  刃組ガイダンスの「呼出」は名前でなく id で引く（名前が鍵でなくなったため）。
- 盤は `blade-board.js`（`special:'blade-board'`）。前の「刃セット」タブ（§9.526）はここへ統合し、`blade-sets.js`を消した。
  セットを作る・字を変える・消すは `/api/bladeset/blade-sets` の同じ口（`create`／`rename`／`delete`）。
  字を変えると刃の行・セットの行・刃選択の名指しが同じ字へ。**刃選択が名指ししているセットは消さない**（理由を言う）。
- 新しいセットは空いている字と、**登録済みの刃厚の顔ぶれ**で行を並べて開く（思い出させない）。
- 刃厚ごとの行は欄を離れるとすぐ保存し、描き直しても**焦点は Tab で移った先の欄**（`WL.bsKit.keepFocus()`）。

### ゴムリング（2）

- ① 潤滑リングは色コードが空のまま**画面では紫（`--look-violet`）で見えている**のに、被り判定は空の色コードで比べていた
  ——同じ紫の新しい色が「被っていません」で通った。判定は**見えている色**（`ring_tone()`・`RING_LUBE_HEX`）どうしで
  比べる。`RING_LUBE_HEX`はCSSのトークンと同じ値（網が突き合わせる）。2つ目の潤滑リングも色を変えないと断る。
- ② 色名を**詳細のいちばん上**に見出しの大きさで置き、新しい色を開いたら焦点をそこへ。打った名前は一覧の仮の項目にも映す。
- 新しい色の候補は、標準の色が残っていればそれ、全部使っていれば**登録済みの色からいちばん離れた色**（`_far_hex()`）。
- ③ 盤は刃と同じ2ペイン（左＝色の一覧、右＝色の属性と幅ごとの本数）。

### 刃選択（3）

- 判定表は3つで、**決める順は 保持方式 → 刃のカテゴリ → 刃厚**（`PICK_TABLES`）。後ろの表は前の表の答えを列にできる
  （カテゴリの表は板押さえ方式・フィンガー材質、刃厚の表はさらに刃のカテゴリ）。表ごとに使える項目は
  `pick_fields_for()`の1箇所（群＝ほかのマスタの答え／材料から計算した値／1本目のコイル／仕掛の列）。
- `刃選択マスタ`に `[表]`・`[答え]` の列。カテゴリの答え＝通常刃／専用刃（`[刃の組]`でセットを選べる・空＝使えるどれでも）、
  刃厚の答え＝登録している刃厚（空＝いちばん厚い刃＝今までの選び方）。保存は表ごとに丸ごと（`pick_replace()`）、
  未登録は今までの選び方の種。**旧い「専用刃の決まり」はカテゴリの表の行として読む**（条件の無い旧い行は1度も当たらなかった
  ので読まない）。
- ガイダンスは `bladeChoice()`（2つの表の答え）→ `applyBladePick()`（そのカテゴリ・セットの使用中の刃から、その刃厚）。
  使えなければ黙って落とさず、理由（`missing`）を持って札が言う（「通常刃 A・10mm（専用刃（B）が使えない）」）。
  札の字は `pickWord()` の1箇所。
- 判定表の部品（`rule-table.js`）: セルに入ると**候補**（この列の値＋書き方の見本）が出る。表の下の「読み」が
  触っている行を**文で読む**（「板厚が 1.2 以上 かつ … → 専用刃（セット B）」）。「試す」は同じ画面の表どうしで共有し、
  刃選択の盤の上の帯が「この作業なら → カテゴリ → 刃厚」を1行で言う。
- 入力欄の候補の器は `WL.popMenu.suggest()` の1箇所へ移した（式の欄 `WL.formula.suggest` も同じ器を使う）。

### 踏んだ罠

- **打ち終えた条件が Tab で候補に置き換わった。** 式の欄の作法（最初の候補を選んだ状態・Tab で入れる）をセルにも当てたら、
  `>= 20` と打って Tab で離れると、1つ目の見本（`＜ 20`）に置き換わった（`test_holdpick` が見つけた）。セルの候補は
  **↑↓で選ぶまで何も選ばない**（`pick:false`）。書き終えた条件（記号・範囲・含む）には候補を出さない。
- 72-bladeset.css の `@layer component { … }` の閉じ括弧を、古い規則を消すときに一緒に消した——後ろのCSSが層の中へ
  入り、マスタ管理の画面に一覧の帯が重なって出た。消すときは**ファイルの最後の行が何か**を見る。

## 分からないこと・残したこと

- 現場で「色名を付けられない」と感じた操作の順は確かめられていない（手元では付けられた）。欄を見つけやすくしたが、
  別の操作で起きていたなら分からないまま。
- 判定表の部品はほかのマスタ（表示ルールなど）とは共有していない。式の候補の器だけを共有した。
