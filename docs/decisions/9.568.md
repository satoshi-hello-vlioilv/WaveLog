# §9.568 共有の置き場から使い始める——起動アイコンは行き先で探し、マスタの置き場は共有から渡す

索引: [決定記録](README.md)｜前: [§9.567](9.567.md)｜関係: [§9.559](9.559.md)・[§9.445](9.445.md)・[§9.561](9.561.md)・[§9.563](9.563.md)

## 経緯

利用者の報告:「初回起動後にショートカットを作るという選択肢で実際にショートカットが存在するかどうかを確認していない
ためか、作成済みで2回目に起動したときにも同じ選択肢が出てきて困ります。また初回起動時にマスタをつかみに行って
くれないので、まっさらな状態になってしまいます。マスタの置き場は「\\nlmsrvngy03\工場内共有\検査データ\Masters\master.sqlite3」
としたので、共有置き場のリンクから起動して使い始めるときでも問題なくすぐ使用できるように修正をお願いします。」

## 1. 「作りますか」が2回目にも出る

### 測った（前）

場面7つを作り、`desktop_shortcut.status()`→`offer()`を本物で通した（`.lnk`の代わりに行き先を1行書いた字のファイルを置き、
窓の読み取りだけ差し替え）。**正しく答えたのは 2 / 7**。

| 場面 | 正解 | 前 |
|---|---|---|
| 既定の名前で作った | 聞かない | 聞かない |
| 作ったあと、マスタが替わり別の名前が残っていた | 聞かない | **聞く** |
| デスクトップで名前を変えた | 聞かない | **聞く** |
| みんなのデスクトップに在る | 聞かない | **聞く** |
| 何も無い | 聞く | 聞く |
| 別の名前で作ったあと、名前の控えが空 | 聞かない | **聞く** |
| 同じ名前の別の物（行き先が違う）だけ | 聞く | **聞かない** |

原因は2つ:
- 「在るか」を**名前**で見ていた（`link_path(残した名前).exists()`）。行き先は見ていなかった。
- その名前を**共有のマスタ**（パス設定マスタ・§9.445）に残していた。デスクトップはその PC の物なのに、マスタを切り替えると
  別の名前（別の PC が残した名前・空）を読み、作った物を見失う。報告の形（初回はマスタがまっさら→あとで共有のマスタへ
  切り替え）は2つ目の場面にあたる。どの場面が実際に起きたかは手元では確かめられない（分からない）。7つとも直した。

### 直したこと

- **行き先で探す**: 窓の副コマンドに`list`（フォルダの直下の`.lnk`と行き先）を足し、Python の`find_ours()`が
  その人のデスクトップ・みんなのデスクトップの順に「行き先が入口（または前の`Start.vbs`）の`.lnk`」を探す。
  比べるのは`_same_path()`の1か所（窓は読むだけ）。`status()`は名前の物が自分の物でなければ見つかった物を答える
  （「表示」の盤と「作りますか」が同じ答えを読む）。
- **名前と絵はこの PC の控え**（`runtime_dir()/shortcut.json`・書き手は Python）。控えが無い（前に作った）ときだけ
  前の置き場（パス設定マスタ）を読む。
- 同じ名前の**別の物**だけが在るときは聞き、空いている名前（「測定伝送システム（2）」）で作る（`free_name()`）。
  他人の物を上書きしない・聞いたのに作れない、を起こさない。窓は作る先（`createAt`）をそのまま見せる。

**後: 7 / 7**。

## 2. 初回起動でマスタを掴まない

### 測った（前）

共有の置き場から使い始める場面7つで、使うマスタの置き場を数えた（前＝main の作り。窓の写し方はコードどおりに再現し、
Python は`local.json`だけを読む）。**正しく決まったのは 3 / 7**。

| 場面 | 正解 | 前 |
|---|---|---|
| 新しい PC・置き場に渡す設定あり | 共有 | 共有 |
| 新しい PC・置き場に渡す設定なし（配る人が置き忘れ） | 共有 | **まっさら** |
| 前に入れた PC を共有の入口から | 共有 | **まっさら** |
| `local.json`はあるがマスタの置き場なし | 共有 | **まっさら** |
| その PC で決めた置き場がある | その PC の値 | その PC の値 |
| デスクトップから起動（共有に届く） | 共有 | **まっさら** |
| 開発の作業ツリー（共有から入れていない） | 手元 | 手元 |

原因:
- 渡す設定（`<置き場>\install.json`）は**「この版を配る」を押したときだけ**、しかも押した PC の`local.json`に
  `master_db_path`があるときだけ置かれる。置き場を決めたのが配ったあとなら、新しい PC には何も渡らない。
- 窓が渡す設定を写すのは**新しく入れたときで、`local.json`が無いときだけ**。前に入れた PC・`local.json`が在る PC には届かない。
- しかも`local.json`の書き手が窓と Python の2つだった（§9.563「1つのファイルの書き手は1言語」に反していた）。

### 直したこと

- **窓は渡す設定を`config/install.json`へ写す**（書き手は窓だけ・`local.json`は書かない）。初回のインストール、
  前に入れた PC を共有の入口から起こしたとき（Python の前）、置き場に届いた起動のたび（`update::peek()`）。
  置き場に無ければ`{}`を置く（共有から入れた PC の印）。届かなければ前の写しのまま。
- **決め方は`paths.setting()`の1か所**: その PC で決めた値（`local.json`）→ 共有から渡された値 → 共有から入れた PC なら
  **既定の共有の置き場**（`DEFAULT_MASTER_PATH`＝利用者の指定。更新の置き場の既定と同じ共有の下）。共有から入れていない
  PC（開発・網）は既定へ倒さない。`master_share`の書込サイクルも同じ答えを読む。共通設定の置き場の盤は出どころを言う。
- 配るときの渡す設定（`seed_values()`）も**この PC で効いている値**（同じ`setting()`）から書く。渡す鍵の顔ぶれは`paths.SEED_KEYS`の1か所。
- CI の自己診断の置き場（`make_share.py`）にも本番と同じく渡す設定を置く（工場の共有には届かないので試しの置き場の中のマスタ）。

**後: 7 / 7**。

共有のマスタに届かないとき（初回に共有が落ちている等）は、§9.89 のとおり手元の写しで起動を続け、届いたら取り込む。

## 網

- `test_shortcut.py`: 7つの場面（行き先で探す・空いている名前）・名前と絵はこの PC の控え・窓に`list`がある。
- `test_appupdate.py`: 既定の共有の置き場が利用者の指定どおり・場面ごとの決まり方（渡された値・置き忘れ→既定・
  `local.json`があっても渡された値・その PC の値が先・共有から入れていない PC は手元）・窓は`local.json`を書かない・
  起動のたびと共有の入口で写し直す。
- 窓（cargo test）: 写しは渡す鍵だけ・置き場に無ければ`{}`・届かなければ前の写しのまま・`list`は名前を変えても行き先で見つける。

## 分からないこと

- 報告の PC で、どの場面（名前の食い違い／Public／名前の変更）が起きていたかは確かめられない。7つとも直した。
- 実機の Windows での`list`（COM で`.lnk`を読む）は CI の Windows の網（`make_then_read_gives_same_target`）で確かめる。
