# §9.229 起動スクリプトの改行・選ばせ方の意匠と高さ・組み込み欄の汎用化・異常チップの見切れ（利用者の指示）

利用者からの指摘は4つ。

- ①「setup.batを実行したとき添付のような表示が出るのですが、正常ですか？」
  （`'after' は、内部コマンドまたは外部コマンド…`が延々と並ぶ）
- ②「汎用設定の特にタブは、こんなタブになっているので、変わっている感じが
   わかりません。白背景に白配色で、淵だけ色付きではわかりにくいです。
   標準的な、選ばせ方のサンプルと同じデザインにしてください。他の選ばせ方も
   サンプルの形に合わせてください」
- ③「コイル止めに関して、名前も設定項目も変えられません。汎用設計にしている
   つもりなので、一旦外すなどもできるようにしてほしいです」
- ④「コイル止めに関して、操業データの選択肢の部分のマスタを変えても、連動して
   くれていません。マスタは変わっている？が操業データ項目にあるリストには
   反映されないみたいです」

#### ① 起動スクリプトは CRLF 改行で保存する

**原因は改行コード。** `setup.bat`／`start_app.bat`／`stop.bat`／`Start.vbs`が
**LFだけ**で保存されていた。cmd.exeはバッチファイルを「1行実行しては次の位置へ
シークし直す」形で読み進めるので、CRが無いと**位置が1行につき1バイトずつずれ**、
やがて**行の途中から実行される**。実機の出力がそのまま証拠になっている:

| 出た文字列 | 元の行 |
|---|---|
| `after` | `rem WaveLog setup: run this once after install and after every update.` |
| `les` | `rem It checks Python / packages, pre-compi\|les bytecode…` |
| `tamp` | `rem …writes a readiness s\|tamp so daily startup can skip` |
| `thout` | `rem Start.vbs still works wi\|thout it (just slower).` |
| `9009` | `set RC=%ERRORLEVEL%`（＝`set RC=\|9009`） |
| `が速くなります。` | `echo OK: 次回からの起動\|が速くなります。` |
| `ｫませんでした。…` | `echo NG: 確認で\|ｫませんでした。…` |

最後の1つが決定的で、**2バイト文字の途中で切れている**（`き`の1バイト目が
落ちて`ｫ`に見える）。記号・引用符・CP932の誤読では説明が付かない
——**位置がずれている**としか読めない。

直したこと:
- 4本とも**CRLF**へ変換した。`setup.bat`は**CP932のまま**（既存の約束）。
- `setup.bat`の`if ( ) else ( )`を**gotoラベルへ組み替えた**。括弧の塊は
  cmd.exeが「塊ごと読んでから位置を戻す」経路で、いちばん位置ずれが出やすい。
- `ERRORLEVEL 9009`（＝コマンドが見つからない）を**名指しで言う**
  ——今までは「確認できませんでした。上の内容を確認してください。」しか
  出ておらず、Pythonが入っていないのか、確認処理が失敗したのかが読めなかった
  （§4）。**`py -3`へのフォールバックは足していない**——`Start.vbs`は
  `pythonw.exe`/`python.exe`しか見ないので、setupだけが別の見つけ方で
  成功すると**「セットアップは通るのに起動しない」**を作れる。

固定は`tests/test_faststart.py`（**内容ではなく改行そのもの**を見る。
`LF>0 かつ LF==CRLF`）。**確かめるときは実際にLFへ戻すこと**——
`stop.bat`をLFにして落ちることを確認済み。

#### ② 選ばせ方の実物を「見本と同じ」にする

タイルの中の小さな絵（`.opd-*`）と、実際に測定画面へ出る部品（`.opf-*`）は
**別々に描いている**。絵のほうが先に整っていて、実物だけが取り残されていた。

実測した食い違いは3つ。

1. **未選択の文字が濃すぎた。** 共通の押し味が`color:var(--ink-2)`（#3a565d）
   で、これは本文（`--ink` #173842）とほとんど同じ濃さ。選んだ札をtealにしても
   **選んでいない札のほうが暗い**ので、差として読めない——これが
   「変わっている感じがわかりません」の正体。絵のほうは最初から`--ink-3`で
   描いてあった。**`--muted`へ落とした。**
2. **タブが面を持っていなかった。** 差は下線1本だけで、しかも当たりが
   左右4pxしかなく**下線が文字幅ぶんしか無かった**。§9.220 ①では
   「タブは面を持たない（下に続く欄と一体に読める）」と決めていたが、
   **面が無いと差が読めない**ので撤回する。いまは**淡い面（`--pale`）＋
   濃い文字（`--teal-dark`）＋teal の下線**で、当たりも`--space-3`へ広げた。
   **下線は合図の数に数えない**——丸ぽち（ラジオ）や帯（入切）と同じで、
   「タブという部品の形」そのもの。
3. **セグメントの白い札が地に沈んでいた。** 選んだ札は白、地は`--surface-2`
   ——ほとんど同じ白なので、§9.227 ①で影を落としたときに「1マスだけ少し
   明るい」以上のことを語らなくなっていた（利用者の言う「白背景に白配色」）。
   **1pxの影を戻した。影は3つ目の合図ではなく「面の描き方」**（浮いた札1枚で
   1つ）で、絵のほうは最初からこう描いてある。

あわせてカードとラジオの選択文字も`--teal-dark`へそろえ、**太字は落とした**
（面＋文字色で2つ）。絵の側（`.opd-tabs`）にも面を足して、**絵と実物が
食い違わない**ようにしてある。

固定は`tests/test_oppad.js`。**色そのものは固定しない**（トークンを1つ替える
たびに落ちる）——見るのは「選んだ札と選んでいない札の差」で、
①タブの選んだ札に面があるか ②セグメントの選んだ札に影があるか
③**選んでいない札の文字のほうが薄いか**（相対輝度で+8以上）の3つ。
③は直す前の値（未選択 80.5 / 選択 100.5）で落ちる。

#### ③ 組み込みの欄も普通の項目として設定できる

**名前が変えられなかったのは画面の不具合。** サーバー（`item_upsert`）は最初から
受け付けているのに、`opSaveItem()`が`name:x.builtin?x.name:(d.name||x.name)`と
**送る直前に元の名前へ戻していた**。②の欄は編集できるので、押した本人からは
「保存できているのに反映されない」としか見えない（§9.228 ①で測定画面側の
`renameBuiltinLabel()`は直したが、**保存の口は直っていなかった**）。

**選択肢のまとまりが出なかったのは判定が`[型]`だったから。** コイル止めの
`[型]`は`文字`なので`choiceTypes.includes(x.type)`が偽になり、選択肢・初期値・
手打ち・空欄の札の欄が**丸ごと出なかった**——`[選択肢名]`には`コイル止め`が
ちゃんと結んであるのに、画面からは見ることも変えることもできない状態だった。
判定は**族（`opFamilyOf`）の1箇所**へ寄せる（`opIsChoiceLike()`）。族は
組み込みキーから引くので、組み込みの選択欄も拾う。

いま組み込みの欄で決められるのは、**型以外のすべて**——名前・役割・選択肢の
まとまり・初期値・手打ち・空欄の札・単位・並び・群・幅・必須・出す/出さない・
置き場・選ばせ方・意匠。型だけは画面が持っている部品そのものなので変えられず、
**別の型で記録したいときは新しい項目に同じ役割を持たせる**（§9.223 ①）。

**初期値は組み込みの欄にも入る**が、入るのは**まだ何も選ばれていないとき**
——空欄か`-`のときだけ。「指定なし」のように既定の選択肢が入っている欄には
入らない。仕掛データから値が来る欄（内径・§9.204）は**仕掛の値が勝つ**
——`applyInitials()`は組み込みの欄では控え（`settings.opData`）を書かないので、
`applyInnerDiameterPreset()`から見ると「まだ選んでいない」ままになる。
順番が決まっているので、どちらが勝つか決められないということは無い。

**「一旦外す」は行き止まりにしない。** ②の「この項目」は
`画面の欄は消せません`と書いて終わっていたので、外せないと読まれた。
組み込みの行は消せない（消しても起動のたびに`_seed_builtins()`が作り直す）
のは事実なので、**そう書いたうえで外し方へ連れて行く**——出す/出さないを
持っているのは①の1つだけなので、**入口は増やさずボタンはそこへ移動する**
（§9.207）。いま出ているか外れているかも同じ行に書く。

#### ④ 記録を開き直しても、選択肢マスタの変更が候補に届く

控え（`m.snapshot.context`）には**性質の違う2種類**が同居していた。

- **そのロットの事実**（公差・品質情報・取引先・コース）…測ったときの値なので
  **凍らせるのが正しい**
- **マスタの設定**（オペレータ・機器・内径・スプール・バリ揃え・コイル止め・
  最大条数・設備区分）…**今のマスタが正しい**

`loadMeasurementContext(false)`（＝再開の道）は控えを**丸ごと**当てていたので、
**記録を1件作ったあとは、選択肢マスタを何度直してもその記録では永久に古い
候補のまま**だった。サーバー側は正しく、`/api/measurement/context`は足した値を
すぐ返す（実測で確認）——**画面が控えを見ていた**のが原因。

`applyContextChoices()`として候補だけを切り出し、再開時は控えで開いたあと
**裏で候補だけ取り直す**（`refreshContextChoices()`）。**失敗は黙って捨てる**
——控えを持っている理由は「オフラインでも開ける」なので、そこは崩さない。
**往復のあいだに別の記録へ移っていたら当てない**（`S.measure.id`で見分ける）。

**記録済みの値は候補から落とさないこと。** `optionFill()`は候補に無い現在値を
黙って捨てる（§9.204）ので、取り直した候補にその人・その機器がもう居ないと
**記録が空になる**。取り直しの経路では現在値を候補へ足してから渡す。

固定は`tests/test_oppad.js`。**控えを持っていることを前提として先に固定する**
——控えが無ければ毎回取り直すので、この網は何も確かめないまま通る。

#### ⑤ 条の設計の「異常」まわりが見切れる

利用者の指摘「条の設計の異常関係の表示に見切れがあります」。実機の絵では
`異常 1条／未保存`のチップと`異常の印: 出す`のボタンが**空白のところで折り返し**、
器から溢れていた。

原因は**flexの既定（`flex-shrink:1`）**。この帯（`.split-visual-actions`）には
長い案内文とチップとボタンが並ぶが、**全員が縮む設定**だったので、案内だけでなく
チップとボタンまで一緒に縮む。文字に空白があるものほど先に折り返すので、
**押す前に何のボタンか読めなくなる**。

- **縮む役は案内（と詳細）だけが持つ**（`flex:0 0 auto` ＋ `white-space:nowrap`）。
- **器は折り返せるままにする**——極端に狭い窓では、切り落として見えなくするより
  2行がまし（§9.199）。
- チップの中の`<b>`と`<small>`にも`nowrap`を当てる（器を縮まなくしても、
  中が折り返せると2行になる）。

固定は`tests/test_splitlive.js`。**物差しは「広いときの自分の高さ」**
——トークンから1行ぶんを組み立てると、余白の出どころ（器か中身か）で
食い違って「全部2行」と読み違える。同じ要素の広いときと狭いときを比べれば、
折り返せば必ず背が伸びる。**狭さも決め打ちにしない**——4つが必要とする幅を
測ってそこから確実に足りない幅まで詰める。案内は`min-width:0`で0まで縮むので、
中途半端な幅では縮み代を全部吸ってしまい、**直す前でも通る**（実際に2度通した）。

#### ⑥ 汎用UIの高さをそろえ、セグメントを設定色に乗せる

利用者の指示「汎用UIの高さは揃えたいです。見た目がそろわないです。また、
セグメントは選んだ部分が白なのでわかりにくく、設定色との連携もないので色も
連携でき、カスタム性を損なわないようにUIの作りもしっかり考えてください。」

**高さ**は3か所がずれていた。器（`.opf`／`.selectors>label`）が`--opf-h`を
宣言しているのに、それを読んでいない／内寸を引いていないものがあった。

| 部品 | 直す前 | 原因 |
|---|---|---|
| セグメント | +6px | 器が`padding:2px`＋`border:1px`を持つのに札へ`--opf-h`をそのまま与えていた（トグルは最初から引き算していた） |
| タブ | +1px | 器の下罫線1pxぶん |
| 素の`<input>`/`<select>` | 約33px | `00-base.css`の`padding:7px`のまま。`--opf-h`（30px）を読んでいなかった |

素の欄も器の高さを読むようにしたので、**意匠の「大きさ」の軸がそのまま効く**。
チェックボックスとラジオは形が意味を持つ部品なので触らない（§9.197と同じ）。

**セグメントの選んだ札は設定色で塗る。** §9.229 ②では「白い札＋影」で浮かせたが、
**地（`--surface-2`）も白系なので差が弱く、色の軸も効かなかった**。いまは
塗り＋白文字で、色を選べばそのまま効く（素の指定が`var(--opf-hue,...)`なので、
色の軸の側に書き足す必要は無い——**同じことを2箇所に書かない**）。
**トグルと同じ塗りになるが、形の違いは器が語る**——セグメントは`flex:1 1 0`で
器いっぱいを等分、トグルは中身なりの幅で並ぶ。選ぶ状況も違う（§9.220 ①）。

**役割の一覧にも「いまの名前」を出す。** 利用者の指摘「文字の更新という部分では
プルダウンのリストに載っていないというか、古いままの名称でリンクされています」。
`opRoleHolder()`は**自分を除いて**担当を探すので、**自分が担っている役割の行だけ
添え書きが付かず**、役割の名前（`コイル止め`）だけが残っていた——項目名を変えた
人からは「変えたのに古い名前でつながっている」としか読めない。**役割の名前は
項目名とは別の語彙**（値を何として読むか）なので変えないが、代わりに
`※この欄（<いまの名前>）が担当`を必ず並べる。

固定は`tests/test_oppad.js`。**色は「変えたら変わること」で見る**
（固定色なら白でもtealでも落ちる）。**押した直後に色を読まないこと**——面には
`background-color .15s`の遷移が掛かっており、`getComputedStyle`は遷移の途中を
返すので「押した瞬間はまだ透明」と読める（実際にこれで空振りし、CSSが効いて
いないと誤診断しかけた）。**既定と「主色」を比べないこと**——どちらも同じtealなので、
連携していなくても同じ色になる。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **汎用UIの高さは器の変数がそろえる**（§9.229 ⑥、利用者の指示「汎用UIの高さは
  揃えたいです。見た目がそろわないです」）: `--opf-h`を**器が持つ内寸ぶんだけ
  引いて**札へ渡す——セグメントは`padding:2px`＋`border:1px`で+6px、タブは
  下罫線で+1px 高くなっていた。**素の`<input>`/`<select>`にも器の高さを配る**
  （`00-base.css`の`padding:7px`のままだと約33pxで、部品の30pxと3px違う）。
  意匠の「大きさ」の軸もそれで効く。チェックボックスとラジオは形が意味を
  持つ部品なので触らない。**セグメントの選んだ札は設定色で塗る**（§9.229 ⑥、
  利用者の指示「選んだ部分が白なのでわかりにくく、設定色との連携もない」）
  ——地も白系なので白い札では差にならなかった。素の指定が`var(--opf-hue,…)`
  なので**色の軸の側に書き足さない**（同じことを2箇所に書かない）。
  **役割の一覧には「いまの項目名が担当」と出す**——`opRoleHolder()`は自分を
  除いて探すので、**自分の役割の行だけ添え書きが付かず**、役割の名前だけが
  残って「古い名前でリンクされている」と読まれた。役割の名前は項目名とは
  別の語彙なので変えない。固定は`tests/test_oppad.js`（**色は「変えたら
  変わること」で見る**。**押した直後に読まない**——`background-color .15s`の
  遷移の途中が返り、効いていないように見える）。
- **縮んでよいのは案内だけ**（§9.229 ⑤、利用者の指摘「条の設計の異常関係の
  表示に見切れがあります」）: 案内とチップとボタンが並ぶ帯では、flexの既定
  （`flex-shrink:1`）で**チップとボタンまで一緒に縮み**、空白のところで
  折り返して器から溢れる。**縮む役は案内だけが持つ**（`flex:0 0 auto`＋
  `white-space:nowrap`）。器は折り返せるままにする（狭い窓では2行がまし）。
  固定は`tests/test_splitlive.js`——**物差しは「広いときの自分の高さ」**
  （トークンから1行ぶんを組み立てると余白の出どころで食い違う）、
  **狭さも実測から決める**（案内は`min-width:0`で0まで縮むので、中途半端な
  幅では縮み代を吸い切って**直す前でも通る**。実際に2度通した）。
- **選ばせ方は「選んだ札のほうが濃い」ことで示す**（§9.229 ②、利用者の指示
  「白背景に白配色で、淵だけ色付きではわかりにくいです。標準的な、選ばせ方の
  サンプルと同じデザインにしてください」）: 未選択が`--ink-2`（本文とほぼ同じ
  濃さ）だと、選んだ札に色を付けても**選んでいない札のほうが暗い**ので差に
  ならない——**未選択は`--muted`**。**タブは面を持つ**（§9.220 ①の「面を
  持たない」は撤回。下線1本だけでは差が読めない。下線は合図の数に数えない
  ——丸ぽちや入切の帯と同じで「部品の形」）。**セグメントの白い札には1pxの影**
  （影は3つ目の合図ではなく「面の描き方」。地も白なので、無いと沈む）。
  **見本の絵（`.opd-*`）と実物（`.opf-*`）は別々に描いているので必ず両方直す**
  ——食い違うと設定画面で確かめた意味が無い。固定は`tests/test_oppad.js`
  （**色そのものは固定せず**、選んだ札と選んでいない札の差＝面・影・相対輝度を見る）。
- **組み込みの欄も型以外はすべて設定できる**（§9.229 ③、利用者の指示「名前も
  設定項目も変えられません。汎用設計にしているつもりなので」）: **名前は必ず
  送ること**——`opSaveItem()`が`x.builtin?x.name:…`と送る直前に元へ戻していた
  （欄は編集できるので「保存できているのに反映されない」に見える）。
  **「選択肢を持つか」は族で見る**（`opIsChoiceLike()`＝`opFamilyOf(x)==='choice'`）
  ——`[型]`で見ると、型が`文字`の組み込み選択欄（コイル止め）は選択肢・初期値・
  手打ち・空欄の札の欄が丸ごと出ない。**初期値は組み込みでも入るが、空欄か`-`の
  ときだけ**（「指定なし」のような既定の選択肢が入っている欄には入らない。
  仕掛由来のプリセットが勝つ）。**行は消せない**（`_seed_builtins()`が作り直す）
  ので、**そう書いたうえで①の「測定画面に出す」へ連れて行く**（入口は増やさない）。
- **測定の控えは「ロットの事実」と「マスタの設定」を分ける**（§9.229 ④）:
  `m.snapshot.context`には公差・品質情報（**凍らせるのが正しい**）と、
  オペレータ・機器・内径・スプール・バリ揃え・コイル止め・最大条数・設備区分
  （**今のマスタが正しい**）が同居している。再開（`loadMeasurementContext(false)`）
  で丸ごと当てていたため、**記録を1件作ったあとは選択肢マスタを何度直しても
  古い候補のまま**だった。`applyContextChoices()`で候補だけを切り出し、
  再開時は控えで開いたあと`refreshContextChoices()`が裏で取り直す。
  **失敗は黙って捨てる**（オフラインで開けることが控えの存在理由）、
  **往復のあいだに別の記録へ移っていたら当てない**（`S.measure.id`で見分ける）、
  **記録済みの値は候補へ足してから渡す**（`optionFill()`は候補に無い現在値を
  黙って捨てるので、消えた人・機器だと記録が空になる）。
- **起動スクリプトは CRLF 改行で保存する**（§9.229 ①）: `setup.bat`／
  `start_app.bat`／`stop.bat`／`Start.vbs`。**LFだけだと cmd.exe が行の途中から
  実行する**——バッチは「1行実行しては次の位置へシークし直す」形で読まれるので、
  CRが無いと位置が1行につき1バイトずつずれる。実機では`rem`の行やechoの日本語が
  途中で切れ、`'after' は、内部コマンドまたは…`が延々と並んだ（**2バイト文字の
  途中で切れる**ので、記号や引用符の問題では説明が付かない）。
  `if ( ) else ( )`の**括弧の塊はいちばん位置ずれが出やすい**ので、gotoラベルで
  書く。固定は`tests/test_faststart.py`（内容ではなく改行そのものを見る）。
