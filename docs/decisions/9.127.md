# §9.127 測定画面を寸法の網に載せる（規格はあったのに測定画面だけ外だった）

「規格化したはずなのにバラバラに見える」という指摘を実測で確かめた
（1920×1080、測定画面の1枚の中）。

| | 実測 | トークン |
|---|---|---|
| 文字サイズ | **7種**（9.5 / 11 / 12 / 13 / 14 / 15 / 20px） | 役割ごとに定義済み |
| コントロールの高さ | **13種**（19 / 21 / 25 / 29 / 30 / 33 / 34 / 35 / 36 / 40 / 42 …） | 4種（26 / 30 / 36 / 40） |

#### 原因は「網の巡回に測定画面が入っていなかった」

`tests/test_scale.js`（§9.71）は**実際に画面へ出ている寸法**を数えて
トークンに収まっているかを見る網で、これのおかげで他の画面は揃っていた。
ところが巡回先は仕掛一覧・品質データ・作業スケジュール・ダッシュボード・
実績カレンダー・マスタ管理の6画面で、**測定画面が入っていなかった**。
規格が無かったのではなく、規格を守らせる仕組みの外にあっただけ。

だから直し方は2つで一組になる——**寸法をトークンへ寄せる**ことと、
**測定画面を巡回に加える**こと。片方だけでは同じことが起きる。

| 直したもの | 前 | 後 |
|---|---|---|
| 操作レールのボタン | 42px（直値） | `--ctl-h-lg` |
| 作業時間の入力・ボタン | 34px（直値。**表示サイズに追随しない**） | `--ctl-h` |
| 見出しバーのボタン・判定公差 | 34px（直値） | `--ctl-h` |
| 閉じる・コース警告のボタン | 33 / 35px（成り行き） | `--ctl-h` |
| 段ナビ | `--ctl-h-md`（**存在しないトークン**＝29px） | `--ctl-h-sm` |
| 入力内容のチップ | 25px（成り行き） | `--ctl-h-xs` |
| 基本情報のグループ見出し | `--fs-tiny` 9.5px | `--fs-micro` 11px |
| ヘッダー進捗の分数・レールの件数 | `--fs-base-sm` 13px | `--fs` 14px |

`--ctl-h-md` は**そもそも定義が無い**トークンだった（4種は
xs / sm / 無印 / lg）。存在しない変数を参照した`height`は効かないので、
段ナビだけ中身なりの高さになっていた。

#### 「面」は高さのスケールに乗らない

リストボックス（`size>1`のselect）と複数行入力（textarea）は「1行の的」
ではなく一覧なので、高さは行数が決める。**個別のidで例外にしない**
——増えるたびに一覧へ足すことになり、理由も薄くなる。種類で判定する。

#### 表示サイズ特大で溢れた——直値をトークンにした副作用

直値の`34px`は**表示サイズを変えても大きくならない**。トークンへ寄せると
特大で正しく大きくなり、そのぶん①準備の左ペインが溢れた（実測15px）。
中身を削って帳尻を合わせるのではなく、**その時点で自明な文を消した**:

> 実績板厚・板幅が測定されていないため、過去実績とは比較できません。

これは①準備では**必ず**出る（まだ測っていないのだから）。毎回・全ロットで
同じ文が出るものは読まれないうえ、常設のぶん高さを取る。測ってから出す。
**「使用設備が未登録」のような直せる不備は今までどおり書く**——自明な段階を
言うのと、直せる不備を言うのは別のこと。

固定は`tests/test_scale.js`（測定画面の3段を巡回に追加）。操作レールの
ボタンを42pxへ戻す欠陥を注入し、落ちることを確かめてある。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **新しい画面は`tests/test_scale.js`の巡回に入れる**（§9.127）: 寸法トークンは
  宣言だけでは守られない。**実際に画面へ出ている寸法を数える網**があるから
  他の画面は揃っていたのであって、**測定画面は巡回に入っていなかったため
  1枚の中にコントロールの高さ13種・文字7種**になっていた（規格が無かったの
  ではなく、規格を守らせる仕組みの外にあった）。寸法をトークンへ寄せるのと
  巡回に加えるのは**2つで一組**。`--ctl-h-*`は**xs/sm/無印/lgの4種だけ**
  （`--ctl-h-md`は存在しない。参照しても効かず、中身なりの高さになる）。
  **直値のpxは表示サイズに追随しない**ので、トークンへ寄せると特大で大きく
  なり溢れることがある——中身を削って帳尻を合わせず、**その時点で自明な文を
  消す**（「まだ測っていないから比較できない」は準備では必ずそうなので
  読まれない。「設備が未登録」のような直せる不備は今までどおり書く）。
  リストボックス(`size>1`)とtextareaは「面」で高さのスケールに乗らない
  ——**個別のidで例外にせず種類で判定する**。
