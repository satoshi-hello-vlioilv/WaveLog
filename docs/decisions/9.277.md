# §9.277 表は「ピボット」で組む——軸を抜き出して行／列へ置く（利用者の指示）

> 帳票レイアウトの保存はできるようになったようですが、紙での見え方は表に組んだ
> 後も、何回でも「表に組む」ボタンを押せるので表に組める状態で、実際に帳票を
> 見ると今までの表示と変わらない状態です。子ロット分縦に積む形が今までなので
> 縦に積むが標準で横に積むか表を組むときに、EXCELのピボットテーブルのように
> 自由に組めるように表にしたときには選んだ項目の中に必要な共通軸を抽出して
> それを置く場所を自動もしくはその後ユーザーに修正させる形で作成することで
> 最終形の表の形をしっかり固定できるはずです。**軸の位置と数がわかれば表の
> 形状がわからずに最終形の出力に困らない**のでそのように対応してください。

§9.276 ⑤で直したのは**保存**（`esc()`が属性を引用符で切っていた）で、そこは
本当に直っている。残っていたのは**組み方そのもの**だった。

#### ① 置き場つきの名前では1通りしか作れない

§9.274 では候補が `row`／`col` という**置き場つきの名前**を名乗っていた。

```python
STAT_AXIS = {f'stat.{ik}.{ak}': (il, al) ...}   # (行の名前, 列の名前)
```

これだと「板厚は行・MINは列」という**決め打ちの1通り**しか作れない。行と列を
入れ替えることも、3つ目の軸（対象＝子ロット）を足すこともできない。
**軸は「名前と値」だけを持ち、置き場は盤が決める。**

```python
AXIS_ITEM, AXIS_AGG, AXIS_LOT = '項目', '集計', '対象'
PIVOT_AXES = (AXIS_LOT, AXIS_ITEM, AXIS_AGG)      # ← 既定の置き方はこの並びが決める
STAT_AXES  = {f'stat.{ik}.{ak}': {AXIS_ITEM: il, AXIS_AGG: al} ...}
```

**並び順に意味がある**——1つ目を行・残りを列にするので、繰り返す塊では
「行＝対象／列＝項目・集計」＝**今までの縦積みと同じ絵**が既定になる。
候補の一覧（`field_catalog`）は `axes` を返すだけで、`row`／`col` は返さない
（**置き場を持たないこと**を `tests/test_rbcells.py` が数える）。

#### ② 対象（子ロット）の軸は繰り返しの設定から生える

「対象」は候補の項目ではない——**この塊を子ロットごとに描くか**という塊の
設定なので、盤は `[繰返]` の欄を見る（`fbLotAxisOn`）。

**行にしか置けない。** 子ロットの数は**レコードごとに違う**ので、設計のときに
置けるのは**1つぶんの型**（`lot:true` の印が付いたマス）だけで、数は紙が決める。
行なら型は**連続したひとかたまり**になるので複製できるが、列だと1行ごとに
飛び飛びになって複製できない。**できないことは画面に書く**（§4）ので、
「列」のボタンは押せなくして `title` に理由を出す。

**印は行の中の全部のマスに付ける**（見出しのマスも）。付け忘れると、紙は
印の無いマスだけを先頭へ抜き出してしまい、**行の軸を2本にした瞬間に行が
ばらける**（「全体／板厚」「全体／板幅」の下に、子ロット番号だけが並んで
板厚・板幅の見出しが消える）。

#### ③ 組めないなら押せなくする——「何回でも押せる」の裏返し

利用者の報告「**何回でも「表に組む」ボタンを押せるので表に組める状態**」は、
**押せること自体が「まだ組めていない」という誤った合図**になっていた、と読む。

- `fbTablePlan()` が「組める形」か「組めない理由」を返す1箇所。
- 組めないなら `tableBtn.disabled=true` ＋ `title` に理由（§4）。
- 組めるなら `title` と帯に **`fbPlanText(plan)`** を出す：
  「行＝対象（子ロットぶん）／列＝項目・条件（7列 × 見出し2段＋本体2段）」。
  **軸の位置と数が読めれば最終形が決まる**——利用者の言葉のとおり。

**組んだあとも帯は残る。** 盤が作ったマス（対象の行の見出し＝子ロット番号）は
軸を名乗らないが、それを「軸を名乗らない項目」と数えると、**一度組んだ表は
二度と組み直せなくなる**（帯が消え、ボタンが理由の分からない断りで固まる）。
`fbAxes()` は `lot` の印が付いた足場を読み飛ばす。

**繰り返しを切り替えたら帯を描き直すこと。** `[繰返]` の欄は別の段（③）に
あり、その段を触っても②の盤は組み直されない。拾わないと
**「子ロットごとにしたのに対象の軸がいつまでも出ない」**——利用者から見れば
機能が無いのと同じ。`change` を1つ拾う。

#### ④ 紙は「印の付いたひとかたまり」を子ロットぶんへ広げる

子ロットとの噛み合わせは2通りある（`rpFieldsSection`）。

- **塊ごと繰り返す**（§9.247 ②・今までどおり）——子ロットの数だけ節が出る。
- **1つの表の中で繰り返す**（§9.277）——`lot:true` の並びだけを複製し、**節は1つ**。

**どちらかは印が決める**（`lot:true` のマスが在るか）。設定を2つ持つと
「繰り返すのに表にもする」という決まらない状態が作れる。

**印の無いマスは「全体」**。`lots[0]` を渡すと、**「全体」の欄に1本目の子ロットの
値が出る**（板幅は近い数字なので気づきにくい）。`rpRepeatLots(x,false)[0]` が
ロット全体の統計を持つので、そちらを渡す。

#### ⑤ 縦に積む／横に並べる

> 子ロット分縦に積む形が今までなので縦に積むが標準で横に積むか

`[繰返方向]`（`''`＝縦に積む／`'横'`＝横に並べる）。**既定は縦**——今までの
見え方を黙って変えない。横は `.rp-repeat-row`（`--rp-repeat:N` の格子）で包む。
**繰り返しが1回のときは器を作らない**——1件しかないのに横並びの器で包むと、
幅の計算だけが変わって見え方が微妙にずれる。
**表に「対象」の軸を置いたときは効かない**（1つの表にまとまるため）ので、
そのことを窓の説明に書く。

#### ⑥ 列数の上限を紙とそろえる

`CONTENT_COLS_MAX` を 6→12 にした。紙（`reportSection`）は元から12まで受けるのに
**盤だけが6**で、ピボットに組むと（「1＋項目×集計」で簡単に超える）**黙って6へ
丸められて**いた。`<select>` の候補も 1..12 に広げ、**候補に無い値を代入する前に
`<option>` を足す**——`<select>` は知らない値を代入すると**黙って空になる**ので、
`cols` が 0 として保存され、紙は既定の2列で刷られていた。

#### 網

`tests/test_rbcells.py`（⑥を `axes`／`PIVOT_AXES`／`REPEAT_DIRS`／「置き場を
持たない」へ書き直し）、`tests/test_rbcells.js`（②の約束を書き直し、②-b 軸の
入れ替え・②-c 対象の軸）、`tests/test_rpprint.js`（紙5件）、
`tests/fixtures/report_cells.json`（`lot` の往復。サーバーと画面の突き合わせ）。

**欠陥注入で5件とも落ちることを確認済み**——「全体」に `lots[0]` を渡す／
横並びの器を作らない／見出しのマスに印を付けない／`fbAxes` が足場を
「軸を名乗らない項目」と数える／繰り返しの `change` を拾わない。

**紙になる節そのものを見ること**（§9.244 と同じ）——値を1つ引くだけの網は、
表に組めていなくても通る。**マスの並び順のまま読む**——見出しのマスと値のマスを
別々に集めると、「全体の行の下に子ロットが来る」という**並びそのもの**を
確かめられない。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

  （§9.277、利用者の指示「EXCELのピボットテーブルのように自由に組めるように…
  軸の位置と数がわかれば表の形状がわからずに最終形の出力に困らない」）:
  §9.274では候補が`row`/`col`という**置き場つきの名前**を名乗っており、
  「板厚は行・MINは列」という**決め打ちの1通り**しか作れなかった（行と列を
  入れ替えられず、3つ目の軸も足せない）。いまは`axes`（名前→値）だけを返し、
  語彙と**並び順**は`report_block_repo.PIVOT_AXES=('対象','項目','集計')`の
  1箇所が持つ——**並び順が既定の置き場を決める**（1つ目が行・残りが列）ので、
  繰り返す塊では「行＝対象／列＝項目・集計」＝**今までの縦積みと同じ絵**が既定。
  **候補に置き場を持たせないこと**（`tests/test_rbcells.py`が数える）。
  **「対象」は繰り返しの設定から生える**（候補の項目ではない）。**行だけ**
