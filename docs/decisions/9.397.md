# §9.397 表示位置を動かさない／備考を行へ／設備停止を1枚のマスタへ（利用者の指示）

利用者の指示（原文）:

> **１）作業スケジュール表示位置ずれ不具合**
> 作業スケジュールの更新などデータが更新されるタイミングなどメッセージが
> 長くなったり追加表示のメッセージが出てくるときに添付の画像の部分の行数が
> 増えることで表示位置がガタガタズレるため、対象ロットを選ぼうとしたときなど
> ターゲットがずれるため非常に使いにくいです。**表示位置をころころ変えない
> ということは使いやすさに直結する**ため、守ってほしいです。何かクリック
> したときにメッセージのために1行一時的に増えるとかもそうです。
>
> **２）寸法・外観の入力内容欄の備考が狭すぎる不具合**
> 備考は通常使わないので、行数増やして対応しつつ折りたたんでおくように
> したいです。
>
> **３）**作業スケジュールで停止項目を選ぶときの内訳設定は、内訳は1つしか
> ない場合はそれを既定に。2つ以上あっても既定のものを設定して登録できる
> ようにしてください。
>
> **４）**設備停止分類と内訳と設備停止名の登録を**シームレスにマスタ連携
> できていない**ので、使いやすくなるように改めて「設備停止マスタ」として
> マスタ統合してほしいです。
>
> **５）**作業スケジュールの設備停止の登録用のポップオーバーメニューの
> モーダルについて**小さくてわかりにくく使いづらい、ステップが多い印象**も
> あるので、改良したい。さらに**整列された印象**もほしく、より直感的に、
> 考えなくてもわかるくらいに使いやすくなるように**認知心理学、情報
> アーキテクチャ**に基づいてUIUX設計を見直してください。

## 1. 表示位置ずれ（①）——まず測ってから直した

**直す前に評価関数を書いて、ずれる量を数字にした**（利用者の指示「評価関数を
作成し、検証して問題を明確にしてから対策に取り組んでほしい」）。作業スケジュールを
開き、帯の中で伸び縮みするもの（読込時点のチップ・現場段取りの注記・書込中の印）と、
一覧の上に並ぶ案内6本を**実際に出して**、`main>header`の高さ・`#scTimeline`の
上端・先頭行の `y` を測る。1728×1152（利用者の環境: 2160×1440・125%）で:

| 出したもの | 帯の高さ | 一覧の上端 | 行の位置 |
| --- | --- | --- | --- |
| 素の状態 | 98px | 186px | 226px |
| 読込時点のチップが伸びる | 98px | 186px | 226px |
| ＋ 現場段取りの注記 | **174px**（+76） | 262px | 303px |
| ＋ 書込中の印 | 174px | 262px | 303px |
| ＋ 共有の変更の案内 | 174px | 302px | 342px |
| ＋ 未定の案内 | 174px | 366px | 407px |
| ＋ 選択件数バー | 174px | 421px | **461px**（+235） |

**狙っていたロットが指の下から235px逃げる。** これが「ターゲットがずれる」の
正体で、押し間違いに直結する。

### 直し方は1つの考え方で説明できる——**器の要る場所を、中身の長さから切り離す**

**(a) 帯は1行のまま（`85-headerbar.css`）**

操作列は折り返せるままだった（§9.199 で「極端に狭い窓では切り落とすより
2行のほうがよい」と決めていた）。ところが**文字の長さが器の要る幅を決めて
いた**ので、注記が出た瞬間に3行へ割れた（実測 37px → 114px）。

- `.hd-viewbar .sc-head` と左右の塊を `flex-wrap:nowrap` にする。
- 代わりに**状態の文字だけが縮む**（`flex:0 1 auto` ＋ 省略記号）。
  読込時点のチップは `--w-xl`、段取りの注記は `--w-lg`、書込中の印は `--w-md` で
  頭打ちにし、全文は `title` が持つ。
- **押せる物は縮ませない**（`flex:none`）——切れたボタンは `title` では
  救えない（§9.222）。いちばん重要度の低いものから譲るので、
  面積は「頻度 × 重要度」どおりに配れる（§CLAUDE 1）。

§9.199 の「折り返せるままにしておく」は**この指示で撤回した**。利用者にとって
「2行になっても見えている」より「いつも同じ位置にある」ほうが価値が高い。

**(b) 案内は一覧の「下」へ（`schedule-view.js` / `70-schedule.css`）**

編集権・共有の変更・元データの変更・警告・未定・選択件数の6本は、一覧の**上**に
並んでいた。出るたびに一覧の上端が下がる。

`#scNotices`（知らせの棚）へ束ねて、`.sc-body` / `#scBoard` / `#scBladeBody` の
**後ろ**へ置いた。スクロールする器は中身を上から置くので、**下が減っても行の
y座標は1pxも動かない**。§9.292 ② で下端には既に余白（`#scTailSpace`）を
確保してあるので、ふだんは何も覆わない。

- **中身・id・`hidden` の約束は1文字も変えていない**。変えたのは置き場だけ
  なので、`renderSyncBanner()` など書く側のコードは1行も触っていない。
- 仕切りは `border-bottom` から `border-top` へ（一覧の下に付くので、
  下線では一覧と縁が切れない）。
- 出た瞬間に気づけるよう、**色ではなく動き**で知らせる（0.18秒の淡い出現）。
  動かすのは `opacity` だけ——**場所を動かす動きは付けない**（同じ罠に戻る）。

**overlay（浮かせて重ねる）にしなかった理由**: 行は動かないが、上の数行を
覆う。§9.292 ② の帯（いちばん後ろへ入れる的）とも重なる。下へ置けば
覆うものが無い。

**`.sc-panel` へ `position:relative` を足さなかった理由**: §9.292 ② に
「`sc-panel` へ relative を足すと、既に浮いているもの（`.sc-view-pop` 等）の
基準まで動く」と書いてある。棚は**ふつうの流れの中**に置いた。

固定は `tests/test_scbar.js` §5——**札が並ぶことではなく、帯の高さと行の
y座標が1pxも動かないこと**を見る。棚が一覧より後ろに居ることも見る
（上へ戻すとまたずれるため）。

## 2. 備考は「畳んだ広い行」（②）

`寸法・外観`（旧 丈毎）の表は9列で、備考は**残りを取る列**だった。ところが
他の列（エッジ形状 12.6em・外観 6.2em・長さと肉厚と巻ズレ 7.6em×4…）を
引いた残りは**実測58px**で、2文字も読めない。列を1つ足すたびに細っていく形
そのものが原因である。

**自由記述は器の幅がそのまま使い勝手**なので、列ではなく**行**を与えた
（実測 58px → 693px）。畳めば場所を取らないので、面積は頻度×重要度どおりに
配れる（§CLAUDE 1）。利用者の言葉「行数増やして対応しつつ折りたたんでおく」
そのままの形。

### 畳みは3値にした

以前の `prtFolded` は `Set`（畳んだ丈の集合）で、**既定が必ず「開く」**だった。
備考のように「ふだんは閉じておきたい」ものを表せない。`Map` にして
`true`=畳む／`false`=開く／**無い＝既定に従う**の3値にする（§9.212 ② と
同じ「触っていない」の表し方）。既定を答えるのは `prtFoldDefault()` の1箇所:

| 行の中身 | 既定 | 理由 |
| --- | --- | --- |
| 内訳あり（エッジ形状が異常） | **開く** | 書かないと判定が出ない |
| 備考に文字がある | **開く** | 畳んだままだと書いたことを忘れる（§9.125） |
| どちらも無い | **畳む** | 備考は通常使わない（利用者の指示） |

**段を描くのは「開いているとき」か「畳んだ中身があるとき」だけ。** 何も無い
行では段ごと出さない——9丈ぶんの空の段が並ぶと表の高さが倍になる（§9.126）。

### 主役の列に残したのは「あるか無いか」だけ

58px の器へ本文を写しても読めないうえ、**同じ文が2箇所に出て「違うものかも
しれない」と読み直させる**（§CLAUDE 8）。だから主役の列は `あり` / `—` の
開閉ボタンだけにし、本文は下の段が横いっぱいで持つ（開いていれば欄、
畳んでいれば要約）。全文は `title`。

### 踏んだ罠: 手で畳んだ状態を、異常を選んだあとも持ち越していた

`prtFold` に明示の `true` が残っている行でエッジ形状を「のこぎり状」にすると、
**内訳の欄が畳まれたまま**で、判定だけが「値待ち」で止まる。書けと言われないまま
止まるので、何をすればよいか画面のどこにも出ていない（§CLAUDE 2）。
**書くことが増えたら畳みは手放す**——`had!==has` の分岐で `prtFold.delete(i)`
してから描き直す。`tests/test_msteps.js` の既存の2件が落ちて気づいた。

## 3. 既定の内訳（③）

`[設備停止サブカテゴリマスタ]` に `[既定]` を1列足した。値は `-1`／`0`。

**最初から選ばれる内訳を答えるのは `stop_default_sub()` の1箇所**（§9.163）:

1. **候補が1つならそれ**（利用者の言葉どおり。印の付け忘れでも迷わせない
   ——選択肢が1つしかない場面で「選んでください」と出すのは、できないことを
   聞いているのと同じ）
2. `[既定]` の印がある行
3. 無し（未選択のまま）

画面は**この答えを読むだけ**にした。予定の登録画面（`schedule-view.js`）と
マスタ管理（`master-data.js`）が別々に数えると、「既定」と出ている内訳と
実際に選ばれる内訳が食い違う。API は `defaults`（鍵 `停止理由ID:親サブカテゴリID`）
を1度で返す（`stop_default_sub_map()`）。

**印は兄弟のうち1つだけ。** UNIQUE では守れない（`0` が何行あってもよい）ので、
`stop_sub_upsert()` が立てるときに兄弟を降ろす——守るのはここ1箇所。

**`is_default` を渡さなければ触らない**（`None`＝送っていない・§9.212 ②）。
名前や分を直すたびに既定が落ちると、直した人には何が起きたか分からない。

### 罠: `standard_minutes` は渡さないと消える

`stop_sub_upsert()` は渡した値をそのまま書くので、**省くと `None`（空欄＝親に
任せる）で上書きされる**。網で既定だけを立てようとして分を省いたら、
無関係な「既定の分は4段」の2件が落ちた（実測）。画面（`ssbSave`）は今の値を
必ず載せている。**この作りは変えない**——`null` を「触らない」にすると、
空欄へ戻す道が無くなる。

## 4. 設備停止マスタの統合（④）

§9.389／§9.390 では **3つのタブ**（設備停止分類／設備停止／設備停止の内訳）に
分かれていた。同じ1つの階層を3枚に割っていたので:

- 分類を足す → タブを移る → 停止内容を足す → またタブを移る → 内訳を足す、と
  **タブ往復が2回**要る。
- いま作っている分類がどの停止内容で使われているのか、その停止内容がどんな
  内訳を持つのかが**1画面のどこにも出ていない**。

利用者の「シームレスにマスタ連携できていない」はこの構造そのものを指している。

### 1枚の3ペインにした

```
┌ 分類 ────┬ 停止内容 ──────────┬ 内訳 ─────────────────┐
│ すべて  3 │ [名称・設備・内訳で絞る] │ 刃組待ち  テスト設備A      │
│ 保全    1 │ 刃替え   内訳なし 45分  │ 標準所要分 60分           │
│ 段取り  1 │ 刃組待ち 内訳4件 60分   │ 内訳名  標準所要分 既定    │
│ 待ち    1 │ 定期点検 内訳1件 30分   │ ゴムリング 30  [既定]  ＋下へ│
│ ＋分類    │ ＋ 停止内容を足す       │ └ 交換     20  [既定にする] │
└───────────┴────────────────────────┴────────────────────────────┘
```

- 視覚導線（左→右）が作業導線（大きい区分 → 小さい区分）と同じ向き（§CLAUDE 14）。
- **どの段もその場で足せる**ので、タブを移る手が1度も要らない。
- 幅は中身から決める（§CLAUDE 11）——分類は名前1つなので狭く（`--w-md`〜`--w-lg`）、
  停止内容は名前＋設備＋内訳件数＋分（`--w-lg`〜`--w-2xl`）、内訳は表なので残り。

**停止内容そのものの編集は汎用の編集窓**（`WL.mm.openMaintEditor`）を開いて
使い回す。欄が5つ（対象設備・分類・名称・標準所要分・連携機能）あり、その場の
入力欄では収まらない——**同じマスタの編集の作法を2通り持たない**（§CLAUDE 8）。
「＋ 停止内容を足す」は、いま見ている分類を連れて窓を開く（§CLAUDE 2）。

### 消した定義は残す

`stopCategory` と `stopSub` の `MASTER_DEFS` の行は**消さずに `navHidden:true`**
にした。API の綴りはそのままで、`tests/test_crudroutes.py` が4本の CRUD を
見張る材料でもある——消すとその見張りだけが静かに減る。ナビから伏せるのは
`maintDefVisible()` の1行。

`master_tables.py` の `COVERED_BY` は**実在するタブを指すこと**。
`設備停止分類マスタ`／`設備停止サブカテゴリマスタ` の行き先を `stopReason` へ
付け替えた——伏せたタブを指すと「そのタブが見つからない」行き先になる（§CLAUDE 4）。

### 網の作り替えで分かったこと

- `test_master.js` が持っていた「少項目マスタ（1項目）は窓を開かず上部の
  インラインフォーム」の代表は**設備停止分類だけ**だった。統合で消えるので、
  同じ約束（1項目しかないものに窓を開かせない）を**統合画面の分類ペイン**で
  見るように書き直した。
- `test_mmswitch.js` は「汎用の一覧を持つタブ」として設備停止を使っていた。
  専用画面になると `.op-bar` を持つので「前のタブの盤が残っている」と誤判定する
  ——刃マスタへ替えた。
- `test_stopeq.js` の「一覧では設備名が読める形で並ぶ」は、汎用の一覧
  （`.mm-row`）から統合画面の `.ssb-stop-eq` へ読み替えた。**見るものは同じ。**

## 5. 設備停止の登録UI（⑤）

利用者の言葉は3つに割れる: **小さい／ステップが多い／整列していない**。

### 「ステップが多い」の正体は、1つの作業が2画面に割れていたこと

§9.389 では**同じ器（`#scStopList`）を一覧と手順で入れ替えて**いた。押した
瞬間に画面が丸ごと差し替わるので、何が起きたのかを読み直す必要があり、
戻るには「← 一覧へ」を押すしかない。段は①内訳 →②時間の番号つきで、
**選び終えるまで「あと何手か」が数字で見えている**（＝多く感じる）。

**左＝何を入れるか（停止内容の一覧）／右＝どう入れるか（内訳・時間）を同時に
出す。** 選ぶと右が変わるだけなので画面は動かない（①と同じ趣旨）。左右とも
常に見えているので、選び直しも1手（「戻る」が要らない）。

**番号は外した。** 順に進む手順ではなく、**既に埋まっている設定を見直す画面**に
なったので、番号は「まだやることが3つある」と読ませるだけになる。

### 「小さい」は器の寸法そのもの

窓は 460×560px だった。左右に並べるには足りない（実測: 左は名前＋内訳件数＋
見積で約300px、右は時間の札が7枚並ぶので約400px）。**820×560px** にし、
**保存キーも `scStopModalRectV3` へ変えた**——古い値を覚えている端末に新しい
既定が届かない（§9.105）。

### 「整列された印象」は、左端が1本の線にそろうこと

- 一覧は**1列に積む**。以前は折り返す札の並びで、名前の長さごとに左端が
  ずれていた。1列なら左端がそろい、内訳の件数と見積も同じ位置で読める。
- 右のペインは**ラベル列を固定幅にした2列**（§CLAUDE 9）。以前は段ごとに
  番号・題・状態が横に流れ、選択肢の左端が段ごとにずれていた。

### 「考えなくてもわかる」は、先回りして埋めておくこと

内訳（③）も時間（`stopPickDefaultMinutes`）も**最初から選ばれている**ので、
ふつうは**押すだけ**で入る。進むボタンの字は**いま入るものそのもの**
（`定期点検（日常点検）・15分 を追加`）にした——押す前に読めば取り違えない。

**なぜその分なのかも字で出す**（§CLAUDE 6）。`内訳「日常点検」の標準所要分` /
`この停止内容の標準所要分` / `選択肢の真ん中（標準所要分が未設定）` /
`手で選んだ分` の4通り。同じ「30分」でも当たる見込みが違う。
出どころを答えるのは `stopDefaultMinutesInfo()` の1箇所で、段の順は
サーバーの `stop_default_minutes()` と同じ（画面が別の順で決めると、出ている
数字と入る数字が食い違う）。

**既定の内訳には「既定」の札を出す**——印が無いと「勝手に選ばれた」と読まれる
（§CLAUDE「推測させない」）。

### 実測（`定期点検`＝内訳1件・時間の既定15分）

| | 前 | 後 |
| --- | --- | --- |
| 窓 | 460×560px | 820×560px |
| 押したあとの画面 | 一覧が消えて手順に入れ替わる | 左は一覧のまま、右に設定 |
| 段の番号 | ①② | 無し |
| 内訳の初期値 | 未選択（押せない） | **日常点検（既定）** |
| 進むボタン | `内訳を選んでください`（押せない） | `定期点検（日常点検）・15分 を追加` |
| 追加までの手 | 押す→内訳→時間→追加（4手） | 押す→追加（**2手**） |
