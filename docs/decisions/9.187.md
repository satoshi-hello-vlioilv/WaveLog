# §9.187 列ごとの並べ替え（種類の混在・処理の順番）（利用者の指示）

利用者の指示: 「数字と文字列が混在する場合、null→昇順(数値or日付)→文字列等、
文字種との並びも考慮したい。また、ソート後に文字列変換となっていて固定なのを、
文字列変換→ソートに変更したり、列のカスタム処理フロー変更ができるように」。

- **塊(bucket)で持つ。** 空欄／数値／日付／文字列の4つで、その順番を列ごとに
  決める。既定は「区別しない」＝今までどおりSQLの素の並び。
- **向きは塊の中の値だけを反転する。** 塊の順は利用者が明示的に決めたもの
  なので、向きを変えても動かさない（空欄の行き先が向きで変わると、
  「空欄は最後」と決めた意味が無くなる）。
- **処理の順番を図で出す。** 「変換してから並べる」と言われても、今どちらか
  分からないと選べない。`生の値 → 並べ替え → 読み替え → 書式 → 画面`（既定）と
  `生の値 → 読み替え → 書式 → 並べ替え → 画面`を選べる。
- **8桁の数字は日付として読まない**（製造番号が日付の塊へ移ると、数値の列の
  並びが理由なく変わる）。区切りのある形と、時刻が続く形だけ日付。
- **並べるのはサーバー**（`backend/sort_order.py`）。ページを切り出すのは
  SQL側なので、画面で並べ替えると1ページの中だけが並ぶことになる。
  SQLでは書けないので**2段で引く**——①並べ替えに要る列とROWIDだけ引く
  ②Pythonで並べる ③そのページのROWIDを本体から引き直す。214列×2万行を
  丸ごと運ばずに済む。**素の並びのときはこの経路を通らない**。
- **決まりは画面が送る**（`sorts=[{column,dir,sort,fmt,rule}]`）。サーバーが
  列レイアウトマスタを読む形にすると、対象(target)の組み立て方をサーバーが
  知ることになり、保存前の試し（stage）も効かなくなる。
- **当てられなかったら黙って別の並びで出さない**（`sortNote`を返し、画面が
  そのまま出す）。ROWIDを持たない表では当てられない。
- 保存先は列レイアウトマスタの`[並べ替え]`（1列＝JSON1つ）。
- **判定が2つある**（サーバー＝並べるため／画面＝設定パネルで「この列は
  数値と文字列が混ざっています」と言うため）。食い違わないように
  `tests/fixtures/sort_cases.json`の**同じ例**で両方を突き合わせる
  （`tests/test_sortpipe.py`と`tests/test_sortcustom.js`）。**片方だけ
  直さないこと。**
- **並べ替えを持たない一覧では④の段を出さない**（タイムライン・データ一覧。
  差し替え口の`features.sort:false`）。設定できるのに効かないのが一番悪い。
- **確かめるときは種類の混ざった値を自分で用意すること**——仕掛の
  フィクスチャはどの列も1種類しか持たず、そのまま見ても「混ざったときの順」を
  一度も通らない（実際に素通りした）。
