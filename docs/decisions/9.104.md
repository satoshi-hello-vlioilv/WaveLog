# §9.104 仕掛一覧: 見出しが流れる / 出したあとにもう一度固まる

実機から2つ報告された。**別々の原因だった**——最初は「どちらもメイン
スレッドが止まっているせいだろう」と見立てたが、確かめたら違った。
見立てのまま直すと片方しか直らない。

#### (1) 見出しが流れて消える —— 詳細度の取り違え

```
30-measure.css   #grid th             {position:sticky;top:0}
20-shell.css     #grid th.sortable-col{position:relative}    ← こちらが勝つ
```

`.sortable-col`が付くのは**データ列の見出しだけ**。だから先頭の`#`・
`分割`は固定されたまま、**項目名の並びだけが流れて消える**。報告の
「カラムの項目がスクロールして流れる」はこの見え方そのものだった。

`position:relative`は列幅の取っ手(`.col-resize`)を`position:absolute`で
置くための基準として書かれていた。**`sticky`も位置指定済みの要素**なので
包含ブロックを兼ねられる。relativeは要らないので消す。

**画面の絵で確かめた。** JSから`getBoundingClientRect()`を読むと、
sticky が効いていなくても「器の上端から1px」と出てしまう場面がある
(スクロール直後にレイアウトが追いつく)。器の上端24pxを実際に撮って、
そこに**項目名が写っているか**を見るのが確実だった。

#### (2) 出したあとにもう一度固まる —— 見えない200列を並べていた

実データは**214列**あるが、1600pxの画面に入るのは**16列**。残り約200列は
見えないのに毎回組み立てられ、毎回並べ直されていた。1回の組み直し
(214列×50行)を「作る」と「並べる」に分けて実測すると:

| 作る | 並べる | 合計 | |
|---|---|---|---|
| 44ms | 918ms | 962ms | 全列そのまま(いままで) |
| 91ms | 410ms | 501ms | 全部作って`display:none`で隠す |
| 1ms | 22ms | **23ms** | **16列だけ作る(列の窓)** |

**95%はレイアウト**で、`display:none`で隠しても半分にしかならない
——作ってしまうとレイアウトから外れない。だから**作らない**。
行の窓(§9.95)と同じ考えを横方向へも当てる(`makeColumnWindow`)。

**見出し(thead)とcolgroupは全列のまま置く。** 1行ぶんなので安く、列の
並べ替え・幅の調整・並び替えの当たり判定と、列を数えている既存の作りを
そのまま残せる。畳むのは本文の行だけで、窓の外は`colspan`を持たせた
空セル2つにまとめる。**`table-layout:fixed`ではcolspanで束ねた幅が
colgroupの合計と一致する**ので、表の幅も見出しとの位置も1pxもずれない
(実測: 表の幅21,316pxは畳む前と同じ)。

横に動いたら窓を作り直すが、**余分(overscan)の中に収まっているうちは
作り直さない**(1列ぶん動くたびに組み直すと、それ自体が重い)。

実測(214列×6,009行・表示件数「全件」):

| | 前 | 後 |
|---|---|---|
| 行が出たあとの停止 | 合計4,989ms / 最大1,185ms | 合計515ms / 最大142ms |
| 縦スクロール(大きく25回) | 合計12,505ms / 最大894ms | 合計2,211ms / 最大162ms |

**位置で列を数えないこと。** 本文は窓の中しか作らないので、行の先頭から
数えた位置とデータ列の位置は一致しない。セルには`data-col`を持たせて
あるので、列はそれで引く(テスト側も同じ)。

固定は`tests/test_gridhead.js`(見出しの固定)と`tests/test_listperf.js`
(列の窓。畳んでいること・畳んでも見出しとずれないこと・横へ動かすと
そこの列が出ること)。どちらも**わざと壊して落ちることを確かめてある**。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **一覧は「横に見えている列」しか本文を作らない**（§9.104、`makeColumnWindow`）:
  実データは214列あるが画面に入るのは16列。残り約200列は見えないのに
  並べ直されており、1回の組み直し962msのうち**918msがレイアウト**だった。
  **`display:none`で隠すだけでは501msにしか下がらない**——作ってしまうと
  レイアウトから外れないので、**作らない**。**見出し(thead)とcolgroupは
  全列のまま置く**（1行ぶんなので安く、列の並べ替え・幅調整・並び替えと
  既存の「列を数える」作りをそのまま残せる）。畳むのは本文だけで、窓の外は
  `colspan`の空セル2つ——`table-layout:fixed`では**colspanで束ねた幅が
  colgroupの合計と一致する**ので表の幅も見出しとの位置もずれない。
  **セルは位置で数えないこと**（窓の中しか無い）。`data-col`で引く。
  固定は`tests/test_listperf.js`。
- **`#grid th`の`position:sticky`を詳細度で打ち消さないこと**（§9.104）:
  `#grid th.sortable-col{position:relative}`と書くと`#grid th{position:sticky}`
  に勝ってしまい、**`.sortable-col`が付くデータ列の見出しだけが固定されなく
  なる**（先頭の`#`・`分割`は残るので「項目名だけ流れて消える」という
  見え方になる。実機で報告された）。列幅の取っ手の絶対配置の基準は
  **stickyが兼ねる**のでrelativeは要らない。固定は`tests/test_gridhead.js`。
  **見出しの固定はJSの座標だけで確かめないこと**——スクロール直後は
  効いていなくても「上端から1px」と出る。器の上端を撮って項目名が写って
  いるかを見る。
