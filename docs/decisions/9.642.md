# §9.642 帳票の左の一覧を「日付→（直）→ロット」の木に／バーコードで読んだロットを作業スケジュールの先頭へ（利用者の指摘と指示・2項目）

索引: [決定記録](README.md)｜前: [§9.641](9.641.md)｜関係: [§9.195](9.195.md)（現場歴の日付補正）・[§9.241](9.241.md)（実績の現場日と直）・[§9.179](9.179.md)（入れる位置）・[§9.514](9.514.md)（仕掛から消えたロット）・[§9.637](9.637.md)（設備違いの関門）

## 経緯（利用者の言葉）

> 1) 帳票の表示画面の左側の対象リストが数が増えたときに見えないくらい細く潰れてカード表示されるのでわからないので使えない状態です。ツリービューで日付（太陽歴と現場歴切り替え、現場歴の場合は直の階層も追加）とロット情報を階層構造にして検索しやすい探しやすいリストに変更して下さい。
>
> 2) 作業スケジュールの並び替え機能の発展でバーコードリーダー用のロット番号検索&先頭に配置入れ替える機能を実装して欲しいです。（中略）7桁英数字文字列が打ち込まれたら、スケジュールを探す、あればそれを並び替え、無ければ使用設備（対象設備）の仕掛ロットから探して有れば、ロット組み込む権限がない場合は変更無し。仕掛ロットを組み込む権限が無いことを通知、権限がある場合は、仕掛から強制スケジュールしますとメッセージを出し組み込む。

## 1) 帳票の左の一覧

### 測った（`tests/test_rptree.js`・80件＝10日×1日8件・3直にまたがる）

| 物差し | 前 | 後 |
|---|---|---|
| F1 最も低いロットの行 | **6.6px**（80行すべて） | 26px 以上（2行の行は 40px 前後） |
| F2 中身が切れている行 | **80／80** | 0 |
| F3 日付の節（太陽暦） | 無し（平らな一覧） | 11節（最後の日の夜明け前は暦の翌日）・件数の合計 80 |
| F4 現場歴の直の段 | 無し | 日 → 直（勤務形態マスタの名前）→ ロット |
| F5 夜明け前の記録 | — | 太陽暦では翌日・現場歴では直が始まった日 |
| F6 探して当たったロットへ着くまでに開く回数 | — | 0回（当たった節だけ残して全部開く） |
| F7 節でまとめて一括印刷に選ぶ | 無し | 節のチェック1つ（件数＝節の件数） |

**潰れていた理由**: 縦の flex の器（`.rp-lot-list`）に、`overflow:hidden`の行（カード）を並べていた。`overflow`が`visible`でない
flex の子は最小の高さが 0 になるので、件数が器の高さを超えると全部の行が均等に縮み、80件で1行 6.6px になった。木の行は`flex:none`。

### 作り

- 木の組み立ては`WL.reportTree.build()`の1箇所（純粋な関数）。日付の分け方は`BASES`（太陽暦／現場歴・端末に覚える）。
- **現場歴の日と直はサーバーが答える**（`POST /api/measurement/record-dates`・読むだけ）。直の判定は勤務形態マスタ＝`actuals.date_shift()`
  の1箇所で、実績の一覧（`_with_shift`）も同じ関数を通すように切り出した。記録は端末の保存（IndexedDB）にもあるので時刻は画面が送る。
  代表時刻は作業開始 → 作業終了 → 更新時刻（実績の一覧と同じ順）。引けなかったら暦の日付で並べ、理由を字で言う（描き直しのたびに
  引き直して回り続けないよう、引けなかった記録は控えに「無し」で残し、開き直したら引き直す）。
- 既定で開くのは、いちばん上の日と、その日の先頭の記録（新しい順なら最新）を持つ直。選んだロットの節も開く。探しているあいだは全部開く。
- チェックは節もロットも右端の1列（一括印刷の選びを1本の列で読む）。

### 画面（CLAUDE.md E の手順）

1回目の5案（P1 素の木／P2 1行に詰める／P3 件数を札・時刻の列をそろえる／P4 罫線でゆったり／P5 P3＋木の線と直の帯）は、
別の採点者が 75・67・76・73・78点で80点に届かなかった。指摘（件数のピル札が押せそうに見える・直の帯の青緑の線が「選択中」の印と同じ・
検索で当たった字に印が無い・チェックの列が2本に割れている）を土台に入れて2回目の5案（Q1〜Q5）を作り、**Q4（行を詰めた形）が83点**で
合格した（Q1 82・Q5 81・Q2 79・Q3 77）。採点者の指摘のうち、ロットの行を白い地に（押す物の重み）・状態の札をまっすぐ同じ幅に・
直の見出しも送ると上に残す、の3つを入れた。

## 2) バーコードで読んで先頭へ

### 測った（`tests/test_lotscan.js`）

| 物差し | 前 | 後 |
|---|---|---|
| S1 予定の中ほどのロットを先頭へ動かす手数 | 掴んで先頭まで運ぶ（予定が長いと送りながら） | 読むだけ（ボタン1回＋読む） |
| S2 もう先頭のロット | — | 書かない（改訂番号が動かない）・「もう先頭です」 |
| S4 予定にも仕掛にも無い | — | 予定を変えず「見つかりません → 読み直してください」 |
| S5 予定に無く仕掛にある（組み込める端末） | — | 「仕掛から強制スケジュールします」・予定の先頭の行の前へ |
| S6 予定に無く仕掛にある（組み込めない端末） | — | 予定を変えず「権限がありません → スケジュールモードの端末で」 |
| S9 帯が1行に収まる（1728・1536・2つのモード） | — | はみ出し・重なり・字のはみ出し 0 |

### 作り

- 何をするかは`WL.lotScan.decide()`（予定の中）と`decideWip()`（仕掛を引いたあと）の2つ（純粋な関数）。読んだ字は`normalizedLot()`で
  そろえ（全角・小文字・ハイフン）、7桁の英数字でなければ何もしない。子ロットを読んだら親の行を動かす（子は親にぶら下がって動く）。同じロットが2行あれば
  動かせる予定を先に選ぶ。作業中・完了・開始日時を固定した行は動かさず、そう言う。
- 並べ替えはドラッグと同じ1本（`commitPlanOrder()`へ切り出した・固定した行は据え置き・掴む前の並びも送る＝ほかの端末と食い違えば断る）。
  仕掛から入れるのは仕掛一覧と同じ`addRowToSchedule()`に「入れる位置」を渡す口を足しただけ（動かせる行の先頭の前・無ければ末尾）。
  設備違いの関門（§9.637）もそのまま効く。
- 権限は画面と同じ答え（並べ替え＝`scState.editable`・組み込み＝スケジュールモード）。どちらもできない端末にはボタンを出さない。
- 7桁そろった時点で動く（リーダーが Enter を送らない形でも）。読んだら欄の字を選び直し、次に読んだ字で置き換わる。

### 画面（CLAUDE.md E の手順）

浮く面で始め、4回まわした（どの回も別の採点者・合格は80点）。

| 回 | 案 | 最高点 | 主な指摘 |
|---|---|---|---|
| 1 | V1〜V5（ボタンの下に浮く面・欄の大きさ・頭の色） | 66 | 結論が文に埋もれる・説明と結果で同じ事実を2回言う・面がロット番号の列を覆う・次の一手が無い |
| 2 | W1〜W5（結論＋理由の2段・面を表の右端へ） | 75 | 面が表の右端（実績・「開始」）を覆う・ロット番号が欄と文の2箇所 |
| 3 | X1〜X5（**一覧の下の知らせの棚の1段**＝何も覆わない） | 77 | 「1行目」が表の見た目（完了の行が上にある）とずれる・設備名が帯の札と重複・下の橙の棚と続いて見える |
| 4 | Y1〜Y5（「まだ始めていない予定の先頭」と言う・「行を見る」・棚と罫線で分ける） | **80（Y1）** | 合格。「行を見る」をロット番号入りで大きく・文の中のロット番号を外す、を入れた |

入れた後の確かめ（別の採点者・同じ採点表）で 75点だった（光らせる色が警告の橙と同じ・断りの箱が下の橙の棚と重なって見える・
開いている間ボタンが塗りになり他と形が違う）。光らせる色を青緑に、断り・不明の箱を中立の地＋色の帯と結論の字だけに、ボタンは
塗らない形に直して採り直した: **82点**（合格）。残る指摘（下の橙の棚のほうが結果より目を引く・結果の箱の右が空く）は次の手直しの候補。

**浮く面をやめた理由**: 結果を確かめる先（動かした行）を自分で覆ってしまう。作業スケジュールには「一覧の上端は動かさず、案内は一覧の
下の棚へ」（§9.397）があるので、その棚の1段にした（開いても行のy座標は動かない）。読む欄の位置は結果の長さで動かない（列は固定）。

帳票の木の入れた後の確かめ（同じ採点表）: **前 0点 → 後 85点**。指摘（節のチェックが何を選ぶか・探したときの当たり件数・選んだ行で
状態の札が地に溶ける）は、節のチェックの説明「この N件を一括印刷に選ぶ」・「〜に当たるロット N件」・札の縁取りで入れた。

帯（操作の列）は1728px・スケジュールモードで字つきだと「読込」のチップの字がはみ出した（S9 で測った）。`test_scbar`の約束
（1728px で「追加」の4つは字つき）を守るため、「追加」の塊があるときだけ、幅が足りなければ「読んで先頭へ」を絵だけにし、
意味の重なる「追加」の見出し2文字を先に落とす。

### 網の材料について

フィクスチャの仕掛のロット番号は5桁（L0001…）で7桁が無い。S5 は仕掛の行を1件写してロット番号だけ変えた行を`WL.split.lotRow`の
答えにした。写した行は本物の仕掛に無いので、入ったあとサーバーが「仕掛から消えた＝完了」（§9.514）にする——そのため位置は
**送った位置**（先頭の行の前）で見る（位置の答え方そのものは`test_scinsertpos`が見ている）。
