# §9.196 挿入位置は表を動かさずに示す／追加中の行の位置／列の区切り（利用者の指示）

**① 挿入位置のゴーストで表を動かさない。** §9.179では隙間そのものを行として
流れへ挟んでいたため、カーソルを動かすたびに下の行が1行ぶん上下し、
**鍵の印・詳細・削除のボタンを押そうとすると逃げていった**（利用者の指摘）。
今は器の座標へ**浮かせて**置き、境目の帯と説明の吹き出しだけを出す。
器そのものは`pointer-events:none`で、**帯と吹き出しだけが押せる**
（全面が受けると下の行のボタンが押せなくなる）。

**② 操作の列ではマウスオーバーに反応しない**（利用者の指示）。鍵・詳細・
削除を押そうとしているときに帯や吹き出しが出ると、押す先が隠れる。
吹き出しも**操作の列にかからない**よう、操作列の左端を幅の上限にする。

**③ 「追加中」の行は指定した位置に出す。** 楽観的追加の行はまだ予定時刻を
持たないので、時刻順に並べると必ず末尾へ落ちていた（利用者の指摘「位置を
指定しても一旦一番下に挿入データの処理中の表示が出てしまう」）。
**隣の行の時刻を借りて**その場に留める（配列の並びは`insertEntriesAt`が
入れた位置のまま）。まとめの束も同じ時刻で決めるので、「追加中」だけが
「日付未定」の箱に飛び出すこともない。**借りるのは反映中の行だけ**で、
「展開しきれなかった予定」は今までどおり末尾（あちらは本当に置き場所が
決まっていない。§9.185）。

**④ 列の区切りを引く**（利用者の指摘「列の区切りがわかりにくい」）。
横の罫線しか無かったため、15列が横一列の文字の並びに見えていた。
**borderではなく内側の影で引く**——borderを足すとセルの箱が1px広がり、
列レイアウトマスタで決めた幅と食い違う。取っ手の列と最初のデータ列の左には
引かない（表の外枠になり、まとまりではなく飾りになる）。

固定は`tests/test_scinsert.js`。**「追加中」の位置は応答を遅らせて見ること**
——速いと反映後の並びしか見えず、何も確かめていないのに通る。
