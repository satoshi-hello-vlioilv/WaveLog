# §9.284 赤い網43件の切り分け——「閉じた」の旗が下りない／検証用マスタDBの汚れ（利用者の指示）

利用者の指示は「**切り分けて潰してください。**」。§9.283のあとに回した通しで
**4791/4834 PASS（赤 43）** で、変更前（e9fbbea の内容へ戻して同じ通しを実行）でも
**4818/4864 PASS（赤 46）** ——つまり**§9.283の変更由来ではない先行不具合**だった。
1本ずつ単独で回して分けたところ、原因は4つに分かれた。**うち2つはアプリ本体の
本物の不具合**で、残り2つは検証の土台と古い網だった。

#### A. 「閉じたと告げられた」の旗が一度立つと二度と下りない（本体）

§9.98のとおり「開いているタブが0件」には2つの意味がある——**閉じたと告げられた**
（`POST /api/heartbeat/close`。`CLOSED_GRACE_SEC`=**8秒**）と、**気づいたら0件だった**
（通知が届かなかった。`EMPTY_GRACE_SEC`=**90秒**）。ところが`backend/watchdog.py`の
`_loop()`は、**タブが戻っても`_closed_notice`を下ろしていなかった**。

`pagehide`は**読み直し（F5）でも発火する**ので、この旗はふつうに使っていれば
すぐ立つ。立ったあとは、**次に0件になったときの意味に関わらず8秒で終了**する
——§9.98に「8秒へ揃えるとリロードや別ページへの移動で終了してしまう」と書いた
壊れ方そのものが、**旗の消し忘れという別の道で**起きていた。

  if not empty:
   _empty_since=None
   _closed_notice=False   # ← これが無かった
   continue

現れ方は「重い画面を読み直すとアプリが落ちる」で、回帰テストでは
`test_collayout`／`test_fit`／`test_maint`が**FATAL**（`ERR_CONNECTION_REFUSED`）
になっていた。**起動ログに理由は出ている**（「開いているタブが8秒以上存在しない」）
ので、FATALを見たら**まず`tests/server.log`の終了理由を読むこと**——網の側を
疑って探すと遠回りになる。

#### B. 開いていることは、いちばん先に名乗る（本体）

Aを直しても`test_collayout`は落ちたままだった。読み直しのとき、名乗り直すのが
`base.js`の`WATCHDOG_TAB_ID`＝**アプリのJS（1.4MB）を読み込んで実行し終えてから**
なので、重い画面ではその**8秒**を使い切る。名乗りは`templates/index.html`の
先頭のインラインスクリプトへ移した——HTMLを読んだ直後に走るので数msで届く。

**IDは`index.html`が作って`base.js`へ渡す**（`window.__wlTabId`）。**2つ作らないこと**
——閉じた通知が別のIDへ行き、「開いたまま」の幽霊が残って今度は終了しなくなる。
渡って来なければ`base.js`が今までどおり自分で作る（保険）。
`keepalive:true`で投げ、失敗は握り潰す（名乗れなくても90秒の側で受け止まる）。

#### C. 検証用マスタDBは毎回戻す（`tests/make_fixture.py`の`fix_master()`）

共有スケジュールDBと違い、**マスタDB（`db/master.sqlite3`）はgitが持っていない**
（`.gitignore`で`*.sqlite3`）。テストは全員この1つを共有して書き換えるので、
**片付け損ねた1本が以降ずっと全部を巻き添えにする**（§9.121）。実測では、
通しを何度か回しただけでこうなっていた:

* **データソースの表示順が両方0**になり、左メニューの先頭が「品質データ」に
  なった——`aside [data-db-key]`の先頭を押す網が全部そちらを開き、「分割」も
  「測定」の列も分割ロットも無い一覧を見ていた（`test_coltint`／`test_gridchild`
  ／`test_listperf`／`test_allrows`）。
* **`RNEファイル`が空**になり`rne_scheduler.jobs()`が1件も返さなくなった
  （`test_wkbg`の「手動実行は可能」）。
* **勤務体系「交替勤務(1,2,3直)」が無効**になり、どの設備にも紐づかなくなった
  ——直が引けず、現場日の補正・実績データ表・枠の直の候補が全部落ちた
  （`test_actuals`／`test_opsheet`／`test_sctimecols`／`test_scframe`／`test_shift`）。
  同じ名前の体系が**140本**積まれてもいた。
* **操業データ選択肢の「オペレータ」「スプール」「板厚/板幅測定器」が消えた**
  ——旧マスタは§9.255 ③で作り直さないので、**二度と戻らない**
  （`test_msteps`／`test_recvalues`）。
* **`列レイアウト個人設定マスタ`に1行残っていた**——§9.259で「行が有る＝その人は
  その一覧で個人設定を使う」なので、1行残るだけで以降の全部が「保存したのに
  マスタに入っていない」を見る（`test_collayout` 7件・`test_lcpanel` 8件・
  `test_colmenu` 2件）。
* **`列レイアウトマスタ`の`list:`が残っていた**——ランナーの`resetcontent`は
  `timeline:`／`print:`／`report:`しか戻しておらず、`list:<DB>:<表>`が抜けていた。
  `test_collayout`は毎回「2列目を非表示にする」ので**回すたびに1列ずつ隠れていき**、
  やがて見出しが3つを切って`waitForFunction`が時間切れになる。

`fix_master()`は`main()`の最後にあるので、**ランナーの`reseed`が毎回通る**。
**足りない行を戻し、名前で見分けられる屑（`RT%新設備`・`回帰_%`等）だけ片付ける**
——テストが自分で作った行を無差別に消すと、後片付けを持つ網の期待と食い違う。
**冪等**にすること（何度走っても同じ状態）。**抽出テーブル・既定テーブルは触らない**
——フィクスチャのDBが持つ表の名前はここでは分からず、書き換えると一覧が開けなくなる。

#### D. 古い網は書き直す（§9.200）

**赤いまま残っている網は網ではない**。残り4件は製品ではなく網が古かった。

* `test_master`「勤務形態マスタがmaster.sqlite3に統合された」——**フラットな
  `勤務形態マスタ`は`勤務体系マスタ`＋`勤務区分マスタ`の2枚になった**（移行済みで、
  §9.255 ③により無ければ作らない）。いま在る名前で見る。
* `test_master`「内部データと移行済みは畳んだ状態が既定」——**「移行済み」の群は
  移行済みの表が実在するときだけ出る**ので、`'internal,retired'`と決め打ちにすると
  旧マスタの無い環境では**製品が正しいのに必ず落ちる**。**在る群だけを見る**。
* `test_workable`「未選択は『全設備共通』として扱う」——**材料を自分で用意する**
  （§9.248 ⑥）。設備を選んでいない勤務体系がたまたま在るかどうかに頼っていた。
  作って確かめて消す。
* `test_colscopeui`／`test_filterkeep`の「IDが空のとき」——**誰の操作かは
  `current_login_id()`の1箇所が答える**（§9.276 ③）ので、**画面から空を送っても
  空にはならない**（この端末のIDで受ける）。「空だと断られる」を期待する網は
  ログインIDを持つ端末では必ず落ちる。守りたいのは§9.259の「**空を1つの
  入れ物にしない**」ほうなので、**空の持ち主の行ができないこと**を見る。

* `test_scframe`「枠より前の予定は動かない」——**「いま」から引き直す値を、
  時刻の一致で見ていた**。予定の起点は展開のたびに`now`から引き直す（§9.198）ので、
  2回の`plan()`のあいだに**壁時計のぶんだけ必ず動く**（しかも起点は5分刻みへ
  切り上げるので、境目をまたぐと5分跳ぶ）。分まで（`slice(0,16)`）で比べていたため
  **秒の境目をまたいだ実行だけが落ちて**いた（実測: `23:25:59.294`と`23:26:00.020`
  ＝0.73秒差）。いっぽう枠が誤って押し出したなら行き先は枠の日＝**9日後**なので、
  **1時間の幅で見ればゆらぎ（最大5分）と本物（216時間）を取り違えない**。
  欠陥注入（`position='before:'`を無視して先頭へ挿す）で**ずれ718,320秒**として
  捕まることを確認済み。**再実行で緑になったからといって「フレーク」で片付けない**
  ——落ちる仕組みを言えるまで探すこと（§9.200）。

順番依存で落ちていた3本（`test_scale`／`test_fit`／`test_scperf`）は**単独では
42/42 PASS**で、中身も仕掛一覧のボタン幅・測定画面の起動と帳票に無関係だった
——AとCが直ったので通しでも収まる見込みだが、**「順番のせい」で片付けないこと**
（§9.234 ⑧）。落ちた理由は本物で、たまたま別の経路が塗り直していただけ、が
実際にあった。
