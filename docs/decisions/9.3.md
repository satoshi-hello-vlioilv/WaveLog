# §9.3 スケジュール画面のレイアウト(順次作業表示)

要望にある「順次作業表示とそのスケジュール一覧」は、このタイムライン
そのものを指す。1設備の作業列を上から順に読む縦のカード列とし、各カードに
予定(見積)と実績(わかっている範囲)を並べて出す。

```
┌ 作業スケジュール ─────────────────────────────────────────┐
│ [設備: SL-1 ▾]  起点 09:12(作業中)  稼働: 常昼 8-12,13-17  [再計算] │
├────────────────────────────┬─────────────────────────────┤
│ タイムライン(縦ガント)      │ 追加パネル                   │
│ ┌──────────────────────┐   │  ┌ 仕掛から追加 ───────────┐ │
│ │0 完了  1234500        │   │  │ (仕掛一覧で選択中の行)    │ │
│ │  実績2:22 / 見積2:20   │   │  │ 1234567 缶材 3004-H19    │ │
│ │  (差+2分)              │   │  │ 見積 2時間32分 ±?        │ │
│ └──────────────────────┘   │  │      [この設備の予定へ]  │ │
│ ● 今                       │  └──────────────────────┘ │
│ ┌──────────────────────┐   │  ┌ 設備停止を追加 ────────┐ │
│ │1 着手  1234567 🔒     │   │  │ 保全計画                │ │
│ │  缶材 3004-H19        │   │  │ リール交換      __分    │ │
│ │  0.285×1420 6条       │   │  │ 刃交換          45分    │ │
│ │  経過38分 / 見積2:32   │   │  │ 次工程待ち              │ │
│ │  〜11:44              │   │  │ 材料待ち                │ │
│ └──────────────────────┘   │  │ 人員不足                │ │
│ ┌──────────────────────┐   │  │ 応援対応                │ │
│ │2 予定  刃交換 45分 ⠿  │   │  │ 突発停止(発生時のみ)    │ │
│ │  11:44〜12:29 (2時間後)│   │  └──────────────────────┘ │
│ └──────────────────────┘   │                              │
│ ── 12:00 昼休み ──         │  ┌ 見積の内訳 ─────────────┐ │
│ ┌──────────────────────┐   │  │ 基準 118分              │ │
│ │3 予定  1234599 ⠿      │   │  │ 用途名 缶材   ×1.18 n=96│ │
│ │  板材 5052-H32        │   │  │ 材質  3004    ×1.04 n=210│ │
│ │  3時間12分後 開始      │   │  │ 板厚帯 0.25〜0.31 ×0.93 │ │
│ └──────────────────────┘   │  │ 条数  6       ×1.13 上書き│ │
│                            │  │ 板幅帯 実績なし ×1.00 ⚠  │ │
│ 合計 8件 / 積み残し 2日3時間│  │ = 152分 (98〜237分)      │ │
└────────────────────────────┴─────────────────────────────┘
```

`🔒` は着手中(reorderable=false、動かせない)、`⠿` は未着手(reorderable=true、
ドラッグ可)を表すハンドル。現場段取り権限のみのedit端末では追加パネル・
見積の内訳パネルごと非表示にし、タイムラインとハンドルだけを出す(§9.4.1)。
ヘッダーの `[設備: SL-1 ▾]` は **schedule モードのみ**で、edit モードでは
`▾` を出さず `設備: SL-1(使用設備)` の固定表示になる(§9.6)。

設計上の判断:

- **縦のタイムライン**を採る。横ガントは複数設備の比較には向くが、1設備の
  作業列を上から順に読む用途では縦の方が自然で、既存の一覧・カード群と
  同じ視覚語彙(`.rp-head` / `.db-card` 系)で組める。
- **非稼働帯を線として明示**する(「── 12:00 昼休み ──」)。時間が飛ぶ理由が
  見えないと、計算が間違っているように見える。
- **「◯時間後」は各カードに常時表示**する。これが要望の中心。
  60分未満は「◯分後」、24時間以上は「明日 9:20 (◯時間後)」の併記。
- **見積の不確かさを隠さない**。`±` と `実績なし ⚠` を出す。
  既存の作業時間ベンチマーク(現 `measure-worklog.js`)が σ を出しているのと同じ思想。
- **完了カードにも実績を残す**(カード0)。「見積とどれだけ差があったか」が
  その場で見えることが、§6.9の精度検証を画面上で日常的に感じさせる。
- **設備停止パネルは、選択中の設備に登録されている設備停止マスタの行だけを
  ボタン化**する(§5.3のとおり設備ごとに個別のため、他設備の行は出さない)。
  「突発停止」だけ既定で無効化(グレーアウト)し、ホバーで「発生時は計画
  担当へ連絡してください」と出す(§3.1.1のとおり投入は現場段取りの範囲外
  のため)。
- **ロック保有者はヘッダーに常時表示**する(`GET /api/schedule/lock-status`
  を数秒間隔でポーリング)。誰も保有していなければ何も出さず、保有者が
  いれば「編集中: 田中@NLM-PLAN02」を薄いバッジで出す(自分自身が保有中
  なら「編集中: 自分」)。書込系のボタンを無効化するほどではない
  (§4.2のロックは呼び出し1回分の短命ロックで、通常は一瞬で解放されるため、
  常時グレーアウトすると却って煩わしい)。423が返ってきたときだけ
  トースト通知で知らせる。

> **実装済み(フェーズ10、高密度リスト化)**: 上記モックアップは初期実装
> (カード縦積み、1件あたり数行分の高さ)のものだが、「20行くらいは1画面に
> 入れたい」という要望を受けて再設計した。`.sc-card`(記事要素の縦積み)を
> 廃止し、CSS Gridの`.sc-row-line`(1行≒30px、ヘッダー行`.sc-row-head`を
> 先頭に1回だけ表示し列名の重複表示を省く)へ置き換えている。列は
> ハンドル/状態アイコン/時刻/残り/内容/見積/実績/備考/操作の9列。
> 固定開始日時の編集と見積の内訳(旧・別々のトグルだった)は1つの
> `.sc-row-detail`パネルへ統合し、行末の`▾`/`▴`ボタン1つで開閉する
> (デフォルトは閉、行の縦の専有面積を最小化)。状態は左端の帯色
> (`.sc-row-planned/-active/-done/-cancel`)と状態アイコン
> (`○/▶/✓/✕`、種別=設備停止は`⛔`)の**両方**で表す(色だけに頼らない)。
> 1400×950の画面で22行を表示した検証では20行目の下端が画面内に収まり、
> 目標密度を満たすことを確認済み。キーボード並べ替え(`Alt+↑/↓`)は
> `.sc-row-detail`が行間に挟まると`previousElementSibling`直参照が
> 隣接行を取り違えるため、`.sc-row-line`だけを辿る`adjacentRow()`
> ヘルパーを介するよう修正した。
