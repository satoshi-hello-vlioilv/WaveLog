## 決めたこと

- **写した物**（ルートは 0本のまま・答えるのはまだ Python）:
  - `sort_order.rs` … 塊（空欄・数値・日付・文字列）と塊の中の並び、安定な並べ替えを後ろの鍵から重ねる `order_rows`、
    設定の正し方（`normalize_spec`・`spec_json`・`describe`）、書式（数・日時・字）、表示ルール（条件・「かつ／または」・かっこの組）、
    画面に出す字（`display_text`）。
  - `filter_sql.rs` … 一覧の条件 → SQL の WHERE と値の並び（字・数・値の並び・日付・組・検索）、効いていない条件の名乗り。
- **Python の決まりの写しを `pyish.rs` に足した**: `py_g`（`'%g'`）・`py_float`（`float()`。数字のあいだの `_`・全角の数字・inf／nan）・
  `py_dumps`（`json.dumps` の `", "` の区切りと小数の書き方。SQL の値の並びがこの字になる）・暦の日（`Date`・通し日・曜日）。
- **固定の小数の丸めは Rust の書き方のままでよい**ことを先に確かめた（`2.5`→`2`・`3.5`→`4`・`2.675`→`2.67`・`1234567.25`→`.2`。
  どちらも2進の値を正確に丸めるので同じ答え）。
- **利用者の正規表現**（表示ルールの「正規表現」）は `fancy-regex`（0.20）で照合する。入れ子の繰り返しは先に `safe_regex::risk()` で断り、
  書けない式は「当たらない」（Python と同じ）。`(?i)` などのフラグも同じ答えになることを試験表で確かめた。

## Python と違うまま残した所（試験表に入れていない）

どれも Python では**例外で止まる**所で、Rust は例外の代わりに「整形しない」「0」を返す。今の画面からは届かない値なので、
呼ぶ側（ルート）を移すときに、そのルートが例外をどう返していたかに合わせて決める。

- 書式の曜日（`ddd`）で暦に無い日（2026/02/31）: Python は `ValueError`、Rust は生の値のまま返す。
- 「今日から N 日以内」の N が無限大（`inf`）: Python は `OverflowError`、Rust は 0 として読む。
- 値の並び（`in`）の要素が並びや辞書: Python の `str()` は `[1, 2]`、Rust は JSON の字 `[1,2]`。
