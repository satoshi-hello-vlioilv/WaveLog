# §9.629 脆弱性の直し——版の目録の道・色の字の注入・窓の外へ開く道・照合が止まらなくなる正規表現（利用者の指示）

## 経緯（利用者の言葉）

> このアプリに脆弱性がないか確認して
>
> 2.(対象2、4、5)のコードで直せる部分を直したい。

確かめた結果のうち、2（版の目録の確かめ）・4（画面へ字を差し込む道と`file:`）・5（正規表現で固まる）を直した。
1（版の署名）・3（中継の HMAC）は配る仕組みそのものの話なので、この節では扱わない。

## 2. 版の目録（manifest.json）の道を確かめる

窓の更新（`desktop/src/update.rs`の`stage()`）は、共有の置き場の`manifest.json`の`payload`と`files[].path`を信じて写していた。
共有の置き場に書ける1人が目録を書き換えると、`..\`・`C:\…`・`db`・`config`へ写せた（Windows では`\`も区切り・名前の大小を見ない）。

- **物差し**: 悪い目録 10 通り（`..`・絶対の道・`\`区切り・ドライブ・先頭の点・空の名・`db`／`DB`／`config`を payload に・payload に無い頭）を
  `stage()`へ渡し、受け付けた数を数える網（`stage_refuses_every_bad_manifest`）。**直す前 8/10 を受け付けた → 直したあと 0/10**。
- 名前の決まりは`plain_name()`の1箇所（空でない・`.`で始まらない・`/` `\` `:`を含まない）。payload は`KEEP`（`db`・`config`）を大小を問わず断る。
  サーバーの`app_update._payload_name()`も同じ決まりにそろえた（版を置く側が先に断る）。

## 4. 画面へ字を差し込む道

| 道 | 直す前 | 直したあと |
| --- | --- | --- |
| ゴムリングの色コード（SVG の`fill="${hex}"`） | 何でも保存でき、`"/><image …>`で画面に要素を差し込めた | 保存は`#rrggbb`だけ（`ring_upsert()`が断る）・画面も形の違う値を捨てる（`blade-core.js`） |
| 行表示マスタの`colorKey`（`class`属性の字） | 何でも保存でき、属性を閉じて差し込めた | 保存は英小文字・数字・`-`の名前だけ（`ROW_COLOR_KEY`）・画面は`rowStyleClassOf()`の1箇所で形を見る |
| 窓の外へ開く道（`open_outside`） | `file:`も開いた（共有の置き場の実行ファイルを開かせられた） | `http`・`https`・`mailto`だけ（`outside_ok()`） |

**物差し**: 注入の見本 3 つ（色コード 2・colorKey 1）が保存されるか。**直す前 3/3 通った → 直したあと 0**（`test_bladeset`・`test_scrowstyle`）。
`file:`は`outside_refuses_file_and_odd_schemes`（cargo test）が見る。

## 5. 照合が止まらなくなる正規表現（ReDoS）

表示ルール・ダッシュボードの式・設備グループの決まり・判定表の条件は、利用者が書いた正規表現を共有のマスタに置く。
Python の`re`にも画面の`RegExp`にも時間の上限は無く、`(a+)+$`のような**入れ子の繰り返し**は当たらない字が1文字増えるたびに時間がおよそ倍になる。
1人が書いた式で全員の端末が固まる。

- **物差し**: 危ない見本 6 つを 25 文字の字に当てて時間を測った。**直す前 5/6 が 0.6〜2.3 秒**（1文字ごとにほぼ倍）。
  直すのを戻した欠陥注入では網（`test_saferegex`・30 文字）が 600 秒の上限まで返らなかった。**直したあと 1 本 50ms 未満**で「当たらない／断る」。
- 見分け方は「中に繰り返しを持つかっこを、さらに 2 回以上くり返す」（`(a+)+`・`(a*)*`・`(\w+\s?)+`・`(.*a){12}`）。
  `(a?)+`・`(ab)+`・`[(a+)]+`・`\(a+\)+`のような安全な形は通す（網は危ない 12・ふつう 18 の見本）。
- 答えは**サーバー`backend/safe_regex.py`と画面`WL.formula.regexRisk()`／`safeRegExp()`の2つで同じ決まり**。網が同じ見本を node の中で
  list-formula.js に当てて突き合わせ、断る理由の字も同じであることを見る。依存は足さない（§9.268）。
- 使う所: `sort_order.rule_test`（表示ルール）・`dashboard/formula.js_regex`・`dashboard/pivot.compile_rules`・`equip_groups.clean_rules`（保存の前に断る）・
  base.js の表示ルール・rule-cells.js の判定表（書いている最中に理由を出す）。

**撤回した案**: 時間で打ち切る（別スレッド・`signal`）——`re`は途中で止められず、Windows には`signal.alarm`が無い。形で先に断るほうが速く、理由も言える。
**踏んだ罠**: 画面の判定を最初 base.js に置いたが、突き合わせの網は list-formula.js だけを読むので届かなかった。式の部品（`WL.formula`）へ移した。

## 回したもの

関係する網（test_appupdate 89・test_bladeset 186・test_scrowstyle 29・test_saferegex 9・test_formulaparity・test_colrule・test_bladeui・
test_holdpick・test_stoprules ほか）と`--pure`、窓は`cargo fmt --check`・`cargo clippy --all-targets -- -D warnings`・`cargo test`（32）。
**フルスイートは回していない**（利用者の指示があるときだけ）。
`test_dashapi`の「作業日の段」など 3 件は、この変更を外した main でも同じ時刻（UTC 0:05）に落ちた。**原因は網の「いま」**: 記録を 07:00〜10:30 に置き、「いま」を壁時計にしていたため、0時〜現場日の始まりに回すと記録が「まだ来ない時刻」・前の作業日に入る。「いま」をきょうの 12:00 に止めて直した（2.521.1・「いま」を 01:25 に止めると 3 件落ち、12:00 で 0 件）。
