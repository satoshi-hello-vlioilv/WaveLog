# §9.117 読み替えルール: 作った本人が確かめられない画面を直す

表示ルール（§9.88 段4）の編集画面は、判定そのものは正しく動いていたが、
**書いた人が「これで合っているか」を確かめる手立てが無い**状態だった。
どれも「動かない」わけではないので、使ってみるまで気づけない類の欠けで、
まとめて直した（`static/js/list/list-rules.js`）。

| 直したこと | 直す前に起きていたこと |
|---|---|
| 行を▲▼で並べ替えられる | 「上から順に最初に当たったもの」が決まりなのに順番を変えられず、直すには消して作り直すしかなかった |
| 「どれにも当てはまらないとき」を作れる | 評価側は「条件が空の行＝既定」で動いていたが、条件を1つ未満にできず**画面からは決して作れなかった** |
| 行ごとに当たり件数を出す | 当たらないことに一覧を見て気づくのでは遅い |
| 既定より下の行を「決して来ない」と言う | 死んだ行が普通の行と同じ見た目で並んでいた |
| どの列で使っているかを出す | 使い回す前提の仕組みなのに、直すと他の列にも効くことが画面のどこにも無かった |
| 「試してみる」に何行目が当たったか出す | 結果だけでは、思ったのと違うときにどこを直すか分からない |
| `prompt()`/`confirm()`をやめる | 素のダイアログは浮きウィンドウの裏に出ることがあり、見た目も他の確認と揃わない |

#### 使っている列はサーバーが返す

参照はルール側でなく**列レイアウトマスタ側**（`[読み替えルール]`）にあるので、
画面だけでは全対象ぶんを知りようがない。`display_rule_usage_all()`を足して
`GET /api/display-rule-master`の`usage`で一緒に返す（ルールごとに引くと
ルールの数だけ問い合わせが増える）。**読めなかったとき(null)は黙る**
——空配列と同じに扱うと「どこにも使われていません」と言い切ってしまい、
消してよいと読まれる。

#### 入力中は組み直さない

値の入力（`.lr-val`/`.lr-text`）で`render()`を呼ぶと入力欄が作り替わり、
**1文字ごとにカーソルが飛ぶ**。`refreshCounts()`が当たり件数と
「試してみる」だけを差し替える。

固定は`tests/test_colrule.js`（57件）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **読み替えルールの編集は「書いた本人が確かめられる」ことが要件**
  （§9.117、`static/js/list/list-rules.js`）: 行の▲▼で評価順を変えられること・
  **条件を全部消せる**こと（条件0＝「どれにも当てはまらないとき」という
  評価側の約束。以前は最後の1つを消せず、既定の行を画面から作る手立てが
  無かった）・行ごとの当たり件数・既定より下の「決して来ない行」の明示・
  **どの列で使っているか**（`display_rule_usage_all()`が
  `GET /api/display-rule-master`の`usage`で返す。**読めなかった(null)を
  「使っていない」と同じに扱わないこと**）。**値の入力中に`render()`を
  呼ばないこと**——入力欄が作り替わって1文字ごとにカーソルが飛ぶ
  （`refreshCounts()`が件数と「試してみる」だけ差し替える）。
  固定は`tests/test_colrule.js`。
