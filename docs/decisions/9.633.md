# §9.633 Python→Rust の移行 P0——ルートの表・影の比較・HTTP の入口・書き手の対応表（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.632](9.632.md)｜計画: [`docs/RUST_MIGRATION_PLAN.md`](../RUST_MIGRATION_PLAN.md) §3〜§5｜関係: [§9.544](9.544.md)・[§9.546](9.546.md)・[§9.563](9.563.md)

## 経緯（利用者の言葉）

> P0から進めてください

P0 は「土台と物差し。移したルートは 0本」（計画 §4）。業務の答えは1つも変えていない。

## 決めたこと

- **業務のクレート `wavelog-core`（`desktop/core`）**。`desktop/` をワークスペースにし、窓（Tauri）と分けた。
  業務は Tauri も Windows も知らない（Linux で `cargo test --workspace` が全部回る）。
  答えと問い合わせの形（`Ask`・`Reply`）、Python へ回す口（`Backend`）、静的ファイル（`statics`）はここへ移し、窓が使う。
- **答えを決めるのは `Core::answer()` の1箇所**。ルートの表（`routes::ROUTES`）で
  - `Serve` … Rust が答える（Python の側は消す）
  - `Shadow` … Python が答え、Rust も答えて違いを記録する（読むだけの GET に限る。`routes::check()` が断る）
  - 表に無い … Python
  窓（`router.rs`）も HTTP の入口も同じ関数を通る。答えの見出し `X-WaveLog-By` は `shell`／`rust`／`python`。
- **移行の状態は `GET /__rust/status`**（表の顔ぶれ・Serve の数・影の数・`OWNS`）。Rust が答える。
- **影の比べ方は `shadow::compare()` の1箇所**: 状態コード → Content-Type → 本文。両方 JSON なら値で比べ（鍵の順は見ない）、
  数は字で比べる（`1` と `1.0` を同じにしない。Python は `1.0` と書く）。違いだけを `logs/shadow.jsonl` へ1行ずつ
  （窓は作業場所の logs、HTTP の入口は `--log-dir`）。5MB を越えたら数えるだけにする。
- **Rust の答えの途中で止まっても窓ごと落とさない**: `routes::run()` が `catch_unwind` で受けて 500（`kind: rust_panic`）で返す。
  そのため release の `panic` を `abort` から `unwind` に変えた（abort だと受けられずに窓が消える）。
- **開発と網の HTTP の入口 `wavelog-serve`**（`desktop/core/src/bin/serve.rs`・機能 `serve`・窓の exe には入れない）。
  `/static/` はディスクから、残りは `Core::answer()`、表に無い物は内側の Python へそのまま渡す。
  内側の Python は `program/app.py` を `WAVELOG_HTTP_PORT=5030` で立てる（`backend/launcher/server.py` の `http_port()`。
  変わるのはこの入口のポートだけで、書込役の LAN の受け口 `PORT+1` と画面が読む `PORT` は変えない）。
- **網のランナー**: `WAVELOG_SERVE=rust tests/run_all.sh …` で外側 5029 を Rust、内側 5030 を Python にして回す。
  既定は今までどおり Python だけ。
- **物差し `tests/lib/rust_progress.py`**（読むだけ）と **網 `test_rustplan.py`**（純粋な網・`ALWAYS`）:
  - Serve のルートが Python に残っていない／影のルートが Python にある
  - `OWNS`（Rust が書き手の事実）を Python が書いていない
  - 書き手の対応表 `docs/RUST_WRITERS.md` が今のコードから作った物と同じ（`--write` で作り直す・手で書かない）
  - 欠陥の注入4つ（記憶の中だけ）でそれぞれ落ちる

## 測った（P0 の基準値）

| 数 | 値 |
|---|---|
| Python が答えるルート（道×メソッド・画面と CSS も含む） | 273 |
| Rust が答える／影 | 0／0 |
| 業務の Python の行数（更新履歴の字を除く） | 48,264 |
| Python が書く表 | 51（表の名前が式で決まる書き手 25。汎用の表の口・`TableDef`・端末の控えなど） |
| 製品の Python を直に読む網 | 83 |
| 煙テスト `--smoke` | Python だけ 184/184（73秒）・Rust の入口を通す 184/184（87秒） |

Rust の入口を通したことは見出しで確かめた: `/static/…` は `shell`、`/`・`/api/access-mode` は `python`、`/__rust/status` は `rust`。

**測っていないこと**:
- JS の網 236本を通しで Rust の入口に通す比較——通しは利用者の指示で回す（CLAUDE.md の A）。
- Windows の実機の起動の秒・メモリ・exe の大きさ——ここでは測れない（CI の自己診断の記録と実機で見る）。

### 数え直した数（§9.632 の誤り）

§9.632 と計画書に「Python の網 112本のうち 91本が `backend` を直に読み込む」と書いた。これは誤りだった。
`from backend|sys.path` を grep した本数で、`sys.path` に触るだけの網まで数えていた。
物差しの定義（`^\s*(from|import) (backend|app)` か `import_module(`）で数え直すと **83本**。
ルートも「270本」はデコレータの数で、物差しは道×メソッドで数えるので **273**。計画書は直した。

### 踏んだ罠

1回目の `WAVELOG_SERVE=rust` の煙テストは、Rust の入口が「Address already in use」で立たなかった。
前の実行が残した Python のサーバーが 5029 を掴んでいて、止める側が新しい形（内側の 5030）しか見ていなかった。
いまの `stop_server` は、どちらの形で立てたかに依らず**両方のポートが空くまで**待つ（`any_up()`）。
