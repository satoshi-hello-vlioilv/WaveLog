# §9.109 作り直せるファイルは自動で手元へ置く（利用者に設定させない）

§9.108の続き。「`db_dir`を実ローカルへ移してください」という**案内では不十分**
だった。実機のアプリは`C:\boxdrive\Box\...\WaveLog_v1\`に置かれており、
`db/cache/`（共有DBの写し）も`schedule_cache.sqlite3`（共有スケジュールの
作業コピー）も**Box Driveの中**にある。設定を頼むのではなく、
**アプリが置き場を決める**。

#### 判定と行き先

`backend/paths.py`の`work_dir()`が決める。判定材料は2つ——
クラウド同期フォルダーの名前（`cloud_sync_hint()`）と、UNC／ネットワーク
ドライブ（`is_network_path()`）。

| `db_dir` | 作り直せるファイルの置き場 |
|----|----|
| 手元のふつうのフォルダー | **そのまま`db_dir`**（今までどおり。健全な端末の挙動は変えない） |
| Box/OneDrive等の中 | `%LOCALAPPDATA%\WaveLog\work\<識別子>` |
| UNC・ネットワークドライブ | 同上 |

識別子は`db_dir`のハッシュ8桁。1台に複数インストールしても写しが混ざらない。

**UNCの判定は`resolve()`の前に、渡された文字列そのもので行う。**
`resolve()`は共有が落ちていると失敗し得るうえ、Linuxでは`\\server\share`が
ただのファイル名に、`//server/share`が`/server/share`へ潰れて、**判定その
ものが消える**（この分岐をテストで踏めなくなる）。`resolve()`が失敗した
場合は「手元ではない」に倒す——**確かめられないものを手元とみなすと、
まさに壊れる場所へ写しに行く**。

#### 何を移し、何を移さないか

**移すのは「消えても取り直せるもの」だけ。**

| | 置き場 | 理由 |
|----|----|----|
| 共有DBの写し（`cache/`） | `work_dir()` | 共有から作り直せる |
| スケジュールの作業コピー | `work_dir()` | 共有から取り直せる |
| **マスタDB**（`master.sqlite3`） | **`db_dir`のまま** | **本物のデータ** |
| **測定データDB**（`records.sqlite3`） | **`db_dir`のまま** | **本物のデータ** |

本物のデータを黙って別の場所へ移すと、**クラウドで同期されているつもりの
データが同期対象から外れる**。動かしてよい種類ではない。

#### 判定は1回だけ

`work_dir()`は結果を覚える。`is_network_path()`は`resolve()`を伴うので、
リクエストのたびに呼ぶと**共有が不調なときにその1行が唯一の失敗原因になる**
（CLAUDE.mdの「共有DBを開く前に`Path.exists()`/`stat()`を置かないこと」と
同じ罠）。

#### 前の置き場の後始末

逃がした場合、前の置き場に残った**自分の生成物だけ**を消す
（`<キー>.g*.sqlite3` / `*.sqlite3.tmp` / `_mirror.json`）。写しは作り直せる
ので運ぶ必要が無い——運ぶほうが遅く、しかも運び先が掴まれていれば失敗する。
**消せなくてよい**（共有・クラウドの上では普通に失敗する。実害は置きっぱなし
だけ）。**利用者のファイルには触らない。**

#### 案内は「こうしてください」ではなく「こうしました」

設定を求めないので、起動ログは警告ではなく記録にする。どこを使ったかと
その理由は`GET /api/db-mirror`（`cacheRelocated`/`cacheRelocatedReason`）と
パス設定画面（`work_dir`/`work_dir_reason`）に出すが、**読むだけで設定は
不要**。

固定は`tests/test_localwork.py`（手元ならそのまま・クラウド／ネットワーク
なら逃がす・**本物のデータは動かさない**・判定は1回だけ・後始末は自分の
生成物だけで失敗しても落ちない）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **作り直せるファイルの置き場は`paths.work_dir()`が決める**（§9.109）:
  `db_dir`がクラウド同期フォルダー（Box/OneDrive等）やUNC・ネットワーク
  ドライブの上なら、**利用者に設定を求めず**`%LOCALAPPDATA%\WaveLog\work\
  <識別子>`へ自動で逃がす。手元なら`db_dir`のまま（**健全な端末の挙動を
  変えない**）。**移してよいのは「消えても取り直せるもの」だけ**——写し
  （`cache/`）とスケジュールの作業コピーはwork_dir側、**マスタDB・測定
  データDBは`db_dir`のまま**（本物のデータを黙って移すと、同期されている
  つもりのデータが同期対象から外れる）。**判定は1回だけ**行って覚える
  （`resolve()`を伴うので、リクエストのたびに呼ぶと共有不調時にそれ自体が
  失敗原因になる）。UNCの判定は**`resolve()`の前に生の文字列で**行うこと
  ——Linuxでは`\\server\share`も`//server/share`も潰れて判定が消える。
  固定は`tests/test_localwork.py`。
