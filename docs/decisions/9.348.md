# §9.348 公差の答えは登録表が出す。「描いたあとに足す」は登録で

`docs/REVIEW_2026-09.md` §6.3 3-16「装飾チェーンを『登録表』へ」。
フェーズA（§9.96）が「消すには定義を1箇所にして分岐を登録表で持つ形へ移す
必要がある」と書いたまま残っていたもの。

## 何が起きていたか

`toleranceDetail`（判定公差の答え）を**3つのファイルが読み込み順に
「退避して被せて」いた**: `measure-input`（根） → `measure-tolerance`（指示型）
→ `lot-split`（分割ロットの条ごと） → `measure-worklog`（**指示型をもう一度**）。

- 被せの1つが第3引数（`typeName`）を落とすと根まで届かず、完了前の確認が
  全項目に「いま選ばれている項目の公差」を当てた（実際に起きた。§9.125）。
- 読み込み順がそのまま答えの順になる。順番の意味（分割→指示型→製造）は
  `JS_FILES` の並びにしか無い。
- 同じ分岐（指示型）が2度書かれ、**内側（tolerance）の指示型分岐は
  一度も走らない**——外側（worklog）が先に取るから。フェーズAで
  `compactToleranceScale` に起きたのと同じ形。

`renderMeasurement`／`updateMeasurementHeading` も同じで、4つ＋2つのファイルが
「描いたあとに足す」を被せで書いていた。

## 決めたこと

1. **`WL.tolerance`（登録表）**を根の `measure-input.js` に置く。提供者は
   `{name, priority, detail(kind,index,type)}`。`resolve` が priority の
   大きい順に当て、**引数は resolve が運ぶ**——「1つ落とすと根まで届かない」は
   構造として作れない。最後は既定（製造／オーダー公差）。
2. **返し方は3通りで、区別に意味がある**: `detail`＝答え／`null`＝「公差なし」
   （次へ行かない）／`undefined`＝自分の答えではない（次へ）。
   以前の被せは `null` を「表示しない」の意味で返しており、これを「次へ」に
   読み替えると**非寸法の項目に製造公差が当たる**。
3. 提供者は3つ: 分割ロット（30）→ 指示型・`指示_項目`の値（20）→
   指示型・単一（10）。分割は寸法系だけ、指示型は非寸法だけに答えるので
   互いに交わらず、**今と同じ答え**になる。順番は `priority` で言い、
   読み込み順に戻さない。
4. **`WL.measureHooks.afterRender／afterHeading`**（`WL.listHooks` §9.93 と
   同じ形・fail-open）。核は `…Core` で、**早期 return でもフックは走る**。
   6つの被せを登録に置き換えた。順番は登録順＝読み込み順（今までと同じ）。

## 結果

| | 前 | 後 |
| --- | --- | --- |
| `toleranceDetail` の定義 | 4 | **1**（＋提供者3） |
| 描画の被せ（render／heading） | 6 | **0** |
| 退避して被せる形（全体） | 30 | **21** |

公差まわりの網10本 665/665。**振る舞いは変えていない**（同じ順・同じ null）。

## 網

- `tests/test_patchlint.py`（純粋）: 定義が1つ／被せが無い／提供者が3以上。
- `tests/test_tolscale.js`: 画面で `WL.tolerance.providers()` の顔ぶれと
  priority の順、`WL.measureHooks.count()` を固定。**1つ登録し忘れると
  その分の公差が黙って製造公差に化ける**ので、顔ぶれを数える。
- A/B: 分割ロットの提供者を外すと `test_tolscale` が6件落ちる（提供者の顔ぶれ＋
  異幅分割の判定・帯・点の位置）。`test_splitlive` は落ちない——あちらは条の図の
  網で、判定公差そのものは見ていない。**顔ぶれを数える網が要る**のはこのため。

## 残り（3-16 の続き）

まだ被せの形で残る21件: `renderMeasureGrid`／`renderMeasureGridVertical`／
`compactToleranceFacts`／`processDeviceInput`／`collect`／`ensureMeasureShape`／
`markDirty`／`saveLocal`／`openMeasurement`／`resumeStoredMeasure`／`focusCurrent`
（測定）、`openMeasurement`／`resumeRecordFromList`／`openRecords`（access-mode の
関門）、`renderTabs`（filters）、`optionFill`（dashboard）。「あとに足す」は
フックへ、「前で断る」は関門の登録へ、と形が分かれる。
`test_patchlint` の ALLOWED 2件（`compactToleranceData`・`updateWorkTimePanel`）
は「元を呼ばずに丸ごと差し替える」ので、登録表ではなく引数で分岐する形へ。
