# §9.539 在庫の「下限」を項目ごと外す——刃・スペーサー・ゴムリング・フィンガー（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

マスタの視覚化の候補 E「在庫の棒」の案（E-1〜E-5）は、どれも「保有が下限を割っているか」を主役に描いていた。それを見て:

> 「そもそも下限という管理項目が不要なので、項目から削除したいです。そのうえで再度案を組み立てて、有効な視覚化内容と方法を検討してほしいです。」

範囲は確かめた——**刃・スペーサー・ゴムリング・フィンガーの4つ全部**（刃の「下限割れ」の札と、刃組ガイダンスの在庫の注意も一緒に消える）。

## 測った（評価関数）

物差しはスクラッチの `eval_minq.js`: テスト設備Aで、4つの部品の一覧 API が返す `minQty` の数と、4つの盤に出ている下限の欄（`data-f="minQty"`）・「下限」の字を数える。

| 物差し | 前（VER2.425.0） | 後 |
| --- | --- | --- |
| API の `minQty`（刃・刃セット・スペーサー・ゴムリング・フィンガー） | 6・6・26・51・14（103） | 0 |
| 盤の下限の欄（刃・スペーサー・ゴムリング・フィンガー） | 2・26・5・14（47） | 0 |
| 盤の「下限」の字 | 1・2・1・1（5） | 0 |
| 刃組ガイダンスの在庫の注意（`warnings()`の`kind:'stock'`） | 5種（刃・ゴムリング・スペーサー・フィンガー・潤滑リング） | 0 |

## 決めたこと

- **下限は読まない・書かない・見せない。** 画面の欄・列・札（「下限割れ」「下限を下回っています」）、頭の字（「下限割れ N」）、
  刃の径ゲージの `bladeWear().low`、刃組ガイダンスの在庫の注意、サーバーの行（`minQty`）・保存の受け口（`min_qty`）・初期セットの0を外した。
- **DB の列（`下限枚数`／`下限本数`）は残す。** 古い版の画面やサーバーが同じ共有マスタを開いても壊れないため（列を消すと古い版の SELECT が落ちる）。
  新しい版はこの列に触らない（`_only()`が値の無い鍵を書かないので、残っている値もそのまま）。
- 古い画面が `minQty` を送ってきても断らない（`body()`は既定で知らない鍵を捨てる）——保存されないだけ。

## 網

- `test_bladeset.py`: 送られた `minQty` は捨て、行は `minQty` を持たない／4つの `*_upsert` が `min_qty` を名前に持たない。
- `test_bladeboard.js` ⑥: タイルにも詳細カードにも「下限」の字・欄が無い（前は「下限割れ」が出ることを見ていた）。
- `test_partboards.js` ④: スペーサーの表に下限の欄・列・字が無い（前は「下限を割った行は橙の札」）。

## そのあと

E の視覚化は下限なしで組み直す（在る量そのもの——台車に載っているぶんと空き、寸法の分布、作れる幅、軸を埋める長さ など）。
