# §9.536 刃マスタの径ゲージ——刃厚 → セット → 選んだセットの3階層、タイル（既定）と刃厚ごとの一覧を切り替え（利用者の選択 B-9／B-10）

索引: [決定記録](README.md)

## 利用者の言葉と選んだ経緯

マスタの視覚化の候補（A〜H）の B「刃の径ゲージ」を、案を見ながら2回に分けて詰めた。

1. B-1〜B-5（径の棒・同心円・全セットの表・研磨の暦・枚数の帯）→
   「情報の階層が混ざっているのがダメです。そういう意味で正しいのはB-2ですが、分かりにくい。B-3かB-5かなと思ってますが、表示階層を合わせて欲しいです。」
   「刃厚が違うものもセット名が同じものを同じグループとして扱うのは実際の運用では違ったので、このように同一グループとして扱う機能は維持しつつ、サンプルは刃厚違いも別グループとして扱うように」
   ——B-3・B-5 は設備全体の情報（刃厚ごとの枚数）を、選んだセットの詳細カードの中に置いていた（誤り）。
2. B-6〜B-10（一覧に棒・上に設備全体の帯・一覧を表に・刃厚 → セットの木・タイルとドーナツ）→
   **「B-9とB-10を切り替え表示できるような形式で実装お願いします。デフォルトはB-10」**

案の画像はスクラッチの `mockB.js`／`mockB2.js`（製品のコードではない）。

## 決めたこと

- **情報は3つの階層を混ぜない。** L1 設備全体（刃厚ごとの今すぐ選べる枚数）＝刃厚のまとまりの見出し／
  L2 セット（使用限界径までの残り・枚数と下限・研磨の予定）＝一覧の1項目／L3 選んだセット（カテゴリ・使用状態・刃厚の行の直す欄）＝詳細カードだけ。
  詳細カードの「下限を下回っています」は外した（一覧の札が言う・同じ事実を2度出さない）。
- **一覧の1項目は セット×刃厚**。1つのセットが刃厚を2つ持てば両方の刃厚のまとまりに出る（同じセットとして扱う機能は残す・選ぶとどちらも光る）。
- 見せ方は2つ。**タイル（B-10・既定）**＝輪の長さが残り、直す欄は下に開く（押すとそこまで見せる）。
  **刃厚ごとの一覧（B-9）**＝2ペインの木。まとまりの見出しに、刃厚ぶんの枚数をセットごとに積んだ帯（塗り＝ふつうに選ばれる・斜線＝研磨中・枠だけ＝専用刃。押すとそのセット）。
  切り替えは頭の「見せ方」。**この端末に覚える**（`localStorage`・覚えられない端末は既定のまま）。顔ぶれと既定は `VIEWS`／`VIEW_DEFAULT` の1箇所。
- 計算は `blade-core.js` の `bladeWear()`（1行の残り・段・研磨の予定・下限割れ）と `bladeStock()`（刃厚のまとまり）の1箇所。字は `wearDue()`。
  2つの見せ方はどちらもこれを読むだけ。
- **物差しはサーバーが答える**（`/api/bladeset/blade-sets` の `wear`・`blade_wear_scale()`）: 使用限界径・研磨周期は刃組基準値、
  満タンは**刃組基準値の新しい欄「刃 新品径」**。空欄なら**その設備でいちばん大きい現状径**を満タンにし、凡例がどちらで描いたかを字で言う
  （新品の径は聞いていないので勝手な数で埋めない・§9.231）。新品径が使用限界径以下なら使わない。
- 段: 残りが幅の **25% 未満**（`WEAR_NEAR`）で「残りわずか」（橙）、使用限界径以下で「使用限界」（濃い橙）。色だけにせず札でも言い、凡例が同じ数を言う。
- 研磨の予定＝研磨日＋研磨周期。過ぎたら「研磨の予定を N日過ぎ」（太字の橙）、まだなら「次の研磨 月/日」、研磨日が無ければ「研磨日の記録なし」。
  研磨中のセットは札が言うので予定の字を持たない。
- 「今すぐ選べる」＝通常刃・使用中・有効な行の枚数の合計（専用刃は判定表に当たったときだけ選ばれるので数えない）。

## 分からないこと・残したこと

- 1回の研磨で削れる量はマスタに無いので、「あと何回研磨できるか」は出していない。
- 「残りわずか」の 25% は画面の決めで、現場の目安は聞いていない（変えるなら `WEAR_NEAR` の1箇所）。
- セット数が多い設備（1刃厚に十数セット以上）でのタイルの見え方は確かめていない。
