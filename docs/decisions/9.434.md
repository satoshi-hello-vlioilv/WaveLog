# §9.434 製品幅をクリアランスで痩せさせない／広げた側が小径／刃が作る寸法を画面へ

索引: [決定記録](README.md)

利用者の指摘（4通・順に）:

> 計算ロジックのミスを発見しました。ゴムリングの使い方が逆です。

> 板幅が50㎜でクリアランスが0.1㎜の場合、
> 上刃：刃の内々寸法 ＝ 製品幅＋クリアランス×2 ＝50.2
> 下刃：刃の外々寸法 ＝ 製品幅 ＝50
> 板幅は確保して組みます。ここにクリアランスでマイナス公差側には寄せません。

> ゴムリング刃組の場合、
> 下バリ→上刃を広く→上刃側にクリアランス分を追加、上側が小径ゴムリング
> 上バリ→下刃を広く→下刃側にクリアランス分を追加、下側が小径ゴムリング

> ゴムリングの色だけでなく、ゴムリング径もガイダンス上でわかるようにしてください。
> 今は純粋な板幅しか表示がないので、クリアランス分の計算が入った寸法で
> 上下正確に刃の幅を示すラベルも必要かもしれません。

**別々の誤りが2つあった。** 片方（大小が逆）は絵で見えるが、もう片方
（幅がクリアランスぶん痩せる）は**0.1mmなので図では1pxも出ない**——
絵を見ても分からないところに入っていた。

---

## ① 製品幅がクリアランスぶん痩せていた

### 何が起きていたか

§9.419 までは、上下の刃を**公称の切断位置の中心に振り分けて**いた:

```
U[i]  = origin + c_i + sign[i] × (刃厚＋クリアランス)/2
Lo[i] = origin + c_i − sign[i] × (刃厚＋クリアランス)/2
```

このとき条の幅は、条の端を作る2枚の刃（＝**その条の側を向いていない面**）
から出る:

```
幅 = 中心の差 + 刃厚 = (条幅 − (刃厚＋クリアランス)) + 刃厚 = 条幅 − クリアランス
```

**符号の並びに関わらず、どの条も一律に「条幅 − クリアランス」**になっていた
（実測: 板幅50・クリアランス0.1 で全条 49.9）。注文幅に対してマイナス公差側
そのもので、現場の組み方と逆だった。

当時の説明文には「面は公称の切断位置をはさんでクリアランスの半分ずつ——
条幅の出方は以前と同じ」と書いてあった。**「半分ずつ」に寄せた時点で
幅が痩せている**ことに気づいていなかった。

### どう直したか

**刃が作る境目**（`edge`）を起点に置く。境目は条幅ではなく
**条幅＋クリアランス**ずつ進む——1つの切断が作る2つの端は、上下の刃の面が
クリアランスぶん離れているぶんだけ食い違うため。

```
edge[i] = origin + c_i + (i − 1) × クリアランス
U[i]    = edge[i] − 刃厚/2 + d × (sign[i] + 1) / 2      （d ＝ 刃厚＋クリアランス）
Lo[i]   = edge[i] − 刃厚/2 + d × (1 − sign[i]) / 2
```

条の端は「その条の側を向いていない刃の面」で、答えるのは
`cutFace()` の1箇所（図・網・検算がここを通る）。

### 検算（板幅50・クリアランス0.1・刃厚10）

| | 上軸 内々 | 上軸 外々 | 下軸 内々 | 下軸 外々 | 実寸 |
| --- | --- | --- | --- | --- | --- |
| 下バリの条 | **50.2** | 70.2 | 30.0 | **50.0** | **50.0000** |
| 上バリの条 | 30.0 | **50.0** | **50.2** | 70.2 | **50.0000** |

利用者の示した数（50.2 と 50）と一致し、**どの条も指示幅ちょうど**になる。

### 起点の取り方（OS側で合わせる）

`edge[0] = origin − クリアランス` に取ると、**1条目の左端がちょうど`origin`**
（材料の並びの1条目の左端）になるので、図の材料と刃が OS 側でぴたりと合う。
DS 側へ向かって最大 (条数−1)×クリアランス（22条・0.1で2.1mm）だけ、材料の
並びと境目が食い違う——材料は連続した1枚なのに、端の測り方が条ごとに上下
入れ替わることから来る差で、**耳が吸う**。

**変わるのはスペーサー寸法と部材の員数**なので、既に記録済みの刃組の内容とは
数字が変わる。

## ② ゴムリングの大小が逆だった

```
下バリ → 上刃を広く → 上刃側にクリアランス分を追加 → 上側が小径
上バリ → 下刃を広く → 下刃側にクリアランス分を追加 → 下側が小径
```

つまり **広げた側（内々）が小径／製品幅を作る側（外々）が大径**。
従来の `ringType()` は逆（内々の側に大径）を当てていた。

理屈: **外々の対＝製品幅を作る刃は、製品の面のすぐ裏に身がある**。大径リングは
刃先より外まで張り出しているので、板をその刃から浮かせて傷の混入を防ぐ。
広げた側の刃は製品から逃げているので、そちらは小径でラップを稼ぐ。

**なおこの件は、利用者の最初の説明文（「内々寸法の方に大径」）と3通目
（「上側が小径」）で逆のことが書かれていた。** 実装は3通目（操作として
書かれているほう）に合わせ、報告でその食い違いを明示して確認を求めた。
**分からないところは推測で埋めない**（§9.426）。

## ③ 見えていなかったこと（画面）

②の報告を受けて調べたところ、**画面の表示自体はどこも食い違っていなかった**
——図の「大／小」の字・帯の色・断面図のリングの太さ・拡大図の1行・所要の
チップは、すべて `ringType()` が決めた1つの `{ringT, od}` を読んでいた。
**独立したラベルは無い**ので、「ラベルだけ逆」は起こり得ない。

足りなかったのは**読み取れる量**のほうだった:

- **径が図に無い。** 色は外径そのもの（§9.377）だが、**どの色が何ミリかは
  覚えていないと引けない**（§CLAUDE「思い出させない」）。
- **刃が作る寸法が図に無い。** 出ていたのは条幅（注文の幅）だけで、
  クリアランスが入った実際の寸法はどこにも無かった。①の誤りが
  何か月も見つからなかったのは、これが理由でもある。

### 足したもの

| 場所 | 何を出すか |
| --- | --- |
| 図のリングの帯 | `大Φ319` / `小Φ316`（狭い区間では `大`/`小` へ落とす） |
| 図の上の帯 | `板押さえ：ゴムリング 大 緑Φ319／小 橙Φ316`（色・径・大小を1箇所で言い切る） |
| 図の区間（記号の下） | `内260.10` / `外259.80`（その軸の刃が作る寸法） |
| 刃組表 | `刃の間隔` の列（`内＝刃の内々／外＝刃の外々`） |
| 拡大図の1行 | `刃の間隔 内260.10（条幅 259.80）` |

**図の字は狭い区間では入らない**（50mm×22条では1つも入らない）ので、
**落ちない置き場を1つ持つ**——刃組表の列。黙って消えるものだけにしない
（§CLAUDE 4）。

内／外のどちらを出すかは `bladeSpan()` の1箇所が**幅から**決める
（バリ方向の規則を図や表へ写すと、規則を直したときにそこだけ古いことを言う）。

## ④ 固定した網（`test_bladeui.js`）

絵では読めない（0.1mmは1pxも出ない）ので、**割付の値そのもの**を見る:

- どの条も指示幅ちょうどに出る（`cutFace()` で測る）
- 下バリ：上刃の内々＝幅＋クリアランス×2／下刃の外々＝幅
- 広げた側（内々）が小径・製品幅を作る側（外々）が大径
- 刃が作る寸法（内／外）が刃組表で読める
- ゴムリングの径と色と大小を上の帯が言い切る
