# §9.181 設備停止を入れる／その場で登録する（利用者の指示）

利用者の指摘は「設備停止モーダルが使いにくいです。使いやすく修正してください。
見栄えも改善してください」「スケジュールモードのスケジュール作成時の設備停止入力の
部分からも設備停止の登録ができるようにしてください（メンテナンスしながら登録
しやすい形）」。

直したのは次の5点。**置き場は`#scStopButtons`の1つ**で、モーダルと側パネルは
それを移し替えて使う（描画とイベント配線を2つ持たない。§9.13の作法をそのまま）。

1. **どこへ入るのかを先に書く。** 以前は設備名も入る位置も画面に無く、押してから
   結果を見て確かめるしかなかった。差し込む位置（§9.179）を決めているときは
   その行も書く（同じ位置を隙間と帯の両方が言う）。
2. **分類は分類マスタの名前で出す。** 以前は固定の5つ（保全/段取り/待ち/突発/
   その他）しか知らず、**マスタへ登録した分類は黙って「その他」へ落ちていた**
   ——登録した名前が画面から消える。並びは「分類マスタ → 昔からの固定分類 →
   実データにあるだけの分類 → 分類なし」で、**どこにも属さない分類を消さない**。
3. **押せるのに何も起きないボタンを置かない**（§4）。突発停止は「予定には
   入れられません」として**理由を文字で**分けて出す（以前は無効なボタンと
   ツールチップだけで、なぜ押せないのか読めなかった）。判定は`STOP_LOCKED`の
   1箇所で、一覧とドラッグの両方が見る。
4. **絞り込みを付ける。** 数が増えると目で探すことになる。**入力中は一覧だけを
   描き直す**——入力欄を作り直すと1文字ごとにカーソルが飛ぶ（§9.117で読み替え
   ルールの編集が踏んだ罠）。当たらないときは「N件のうち0件」と書く。
5. **その場で登録できる。** メンテナンス中に「この停止理由がまだ無い」と気づく
   場面が本番なので、マスタ管理へ行き直させない。登録したものは**印を付けて
   その場に出す**（探し直させない）。登録先（設備名）も書く。

固定は`tests/test_scstop.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **設備停止の入口は`#scStopButtons`の1つ**（§9.181）: モーダルと側パネルは同じ器を
  **移し替えて**使う（描画とイベント配線を2つ持たない。§9.13）。**分類は分類マスタの
  名前で出す**——固定の5つへ丸めていたため、登録した分類が黙って「その他」へ落ちて
  いた。並びは「分類マスタ→固定分類→実データにあるだけ→分類なし」で、どこにも
  属さない分類を消さない。**追加できないもの（突発停止）は理由を文字で分けて出す**
  （§4。無効なボタンとツールチップでは理由が読めない。判定は`STOP_LOCKED`の1箇所）。
  絞り込みは**入力中に一覧だけを描き直す**（入力欄を作り直すとカーソルが飛ぶ。§9.117）。
  **その場で登録できる**ようにし、登録したものは印を付けてその場に出す。
  固定は`tests/test_scstop.js`。
