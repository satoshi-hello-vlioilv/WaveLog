# §9.506 作業スケジュールの帯と面も「1面1サイズ」に——表の見せ方の要約を帯から外し「追加」に字を（利用者の選択「案A」）

索引: [決定記録](README.md)

## 利用者の言葉

> 作業スケジュール一覧もお願い

§9.505（一覧の上部メニューを「1面1サイズ」に）の**段2**。案を見せて選んでもらった点が1つ:

> A

——「追加」の4つ（仕掛一覧・設備停止・コメント・枠）は**アイコンだけ**で、字は説明（`title`）の中にしか無かった。
字を添えると1728px（利用者の常用）でも帯に入らない。案A＝表の見せ方の**いまの設定の要約**
（「まとめなし・いまから過去8時間」＝約190px）を帯から外し、空いた幅で字を添える。案B＝今のまま。

## 測った（評価関数・§9.505 と同じ数え方）

帯（`#scHead`）の中の**字**の大きさ・**押す物**の高さ・角丸の種類。数えないもの: 開く印「▾」と絵（字ではない）、
切り替えの**中の札**（外側の枠が高さを持つ）。1728×1030・スケジュールのモード・テスト設備A・個別。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 帯の字の大きさ | **2種**（12・10px——「追加」の見出しと表の見せ方の要約が10px） | **1種**（12px） |
| 帯の押す物の高さ | **2種**（30px・段の切り替え32px）。全体の画面は**3種**（24／48時間が28px） | **1種**（30px） |
| 「追加」の4つ | アイコンだけ（字は説明の中） | **字つき** |
| 表の見せ方の面の字 | **5種**（10・11・12・13・14px） | **1種**（12px） |
| 同期の面（読込のチップ）の字 | 3種（11・12・13px） | 1種（12px） |
| 行の右クリックの字 | 2種（11・12px） | 1種（12px・§9.505 で列見出しと一緒に動いた） |
| 字を全部出して帯に要る幅 | 約126em | **91.8〜111.1em** |
| 「追加」が字つきになる組み合わせ（5つの画面幅×表示サイズ3段） | 3／15 | **6／15**（1728px・中を含む）。ほかの字を失った組み合わせ 0 |

## 直したこと

- **表の見せ方の要約を帯から外した**（案A）。捨てずに**説明（`title`）の1行目**「いまの設定: …」と
  `data-state`へ移した——乗せれば読め、開けばパネルの中に全部ある。
- **「追加」の4つに字**。字を落とすしきい値（`@container`）は**字を全部出して要る幅を測り直して**決めた:
  1728／1920／1600／1440／1366px × 表示サイズ 小・中・大で **91.8〜111.1em** → 130em を **111.5em** へ。
  「追加」の字を落としたあとに要る幅は **84.4〜96.6em** → 全部の字を落とす段を 91em から **96.7em** へ
  （1366px・中＝90.8em は前から字なし・1440px・中＝97.0em は字が残る）。1728px・中は器が121emで字が出る。
  15通りすべてで帯は器からはみ出さない（はみ出し0px・切れた字0件）ことを測って確かめた。
  1728px・大（110.0em）と1600px・中（110.3em）は、字を出しても入る（要る幅 103.8／107.7em）が、
  表示サイズ「小」の要る幅（111.1em）に合わせたしきい値のため字を落とす——`em`1つのしきい値では、
  表示サイズごとの要る幅の違い（絵と余白はほぼ固定の大きさ）を吸収しきれない。前（130em）も落ちていた。
- **段（全体／個別／刃組／履歴）と24／48時間を、ダッシュボードの切り替えと同じ1つの部品に**。縁取りをやめて
  地の色でまとまりを言い、中の札26px（`--ctl-h-xs`）＋余白2px×2で外側30px（前は縁取り1pxのぶん32px、
  24／48時間だけ別の顔で28px）。**踏んだ**: はじめ縁取りを残して中の札を24pxにしたら、「高さは寸法の刻み
  （19/26/30/36/40px）から」の網3本（`test_scale`・`test_theme`・`test_headbar`）に落ちた。刻みに無い寸法を
  作らないために縁取りのほうを外した。
- **読込のチップを「読込 23:14」**（「名前 値」）へ。一覧の「元データ 9/17 10:14」と同じ読み方で、
  押せる物なので押す物の顔（枠・地）にした。「たった今／N分前」は説明と面の中が持つ。
- **絵の取り違えを無くした**: 読込のチップの ↺（`fa-clock-rotate-left`）は段「履歴」と同じ絵だった（外した）。
  「再計算」の ⟳（`fa-arrows-rotate`）は一覧の「元データ」の再読込と同じ絵だった（電卓 `fa-calculator` へ）。
- **言葉**: 表の見せ方の面の見出し「表示」→**表の見せ方**（押したボタンと同じ名前。ヘッダーの「表示」とも分ける）、
  「広く」→**広く使う**（形容だけでは何をするか言わない。押して戻したときに字を書き直す処理にも同じ字を入れた——
  片方だけ直すと、1回押して戻すと「広く」に戻る）、帯の見出し「追加」は10px→12px（名前の書き方＝細く薄く）。
- 面の字は1種（12px）: 表の見せ方の面の見出し・行の名前・説明・畳む段、さかのぼりの札（11→12px）と起点（10→12px）、
  同期の面の名前・補足・項目とその説明。

## 動いた値（キャプチャに写らない面も含めて・§9.449 の教訓）

`test_popmenu.js` の控え（13面×17項目）では **2件**: 同期の状態 の項目の字 13→12px・項目の高さ 34→32px
（余白は変えていない。高さは中身なり）。§9.505 の8件と合わせて **10件／5面**。

控えが見ていない所: 表の見せ方の面（見出し 13→12px・説明と畳む段の説明 11→12px・段の印 13→12px・畳む段の
ボタン自体 14→12px・さかのぼりの札 11→12px・起点 10→12px。**小計の設定の札（`.sc-subtotal-opt`）も同じ規則なので
11→12px**）、同期の面（名前・補足・項目の説明 11→12px）、帯（「追加」の見出し 10→12px・段の切り替え 32→30px
で縁取り無し・24／48時間 28→30px で段と同じ顔・読込のチップの地 薄灰→白・枠 淡→濃）。

## 分からないこと

- 「読込 23:14」から「たった今／N分前」を外したことで、**古さに気づくのが遅れる**かは現場で使ってみないと分からない。
  遅いとき（`is-slow`）と同期エラーは今までどおりチップに字で出る。

## 固定する網

- `test_scbar.js` … 帯の字・押す物の高さ・角丸が各1種／「追加」の4つは字つき（1700px＝118.7em）／
  要約は帯に書かず説明の1行目／「いつのデータか」に答えるのは読込のチップ1つ
- `test_scsubtotal.js` … 小計の設定が入口の要約（`data-state`）に出る
- `test_popmenu.js` … 控えを書き直した（同期の状態 2件）
