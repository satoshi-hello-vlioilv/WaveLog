# §9.183 データソースの名称も再起動待ちであることを言う（利用者の指示）

利用者の指示: 「一覧を見るのところに出るデータの名称もマスタから変更できる
ようになっていますが、こちらも再起動後に反映されるのでその旨わかるように
表示追加をお願いします」。

**接続先も表示名も、起動時に1回だけ決まる**（`db_access.DBS`はプロセス
起動時の写し）。読み込み先については既にマスタ管理画面が「再起動待ち」を
出していたが、**名称の変更は誰も何も言わなかった**。左のボタンが古い名前の
まま残っているのを見て、利用者からは「マスタで直したのに反映されない」と
しか見えない。

- **突き合わせるのはサーバー**（`/api/catalog`の`restartPending`）。
  保存値と`DBS`の中身を比べ、種別を`'label'`（名称だけ）/`'path'`（読み込み先）
  /`'new'`（登録したばかり）/`'gone'`（無効にした）で返す。画面で推測しない。
- **気づく場所と打つ手を同じ場所に置く。** 案内は左メニューの「一覧を見る」
  グループの中に出し、押すと「データ接続」のタブが開く（`openMasterMaint('dataSource')`）。
- **待ちが無いときは出さない**（常設すると読み流される）。何が待っているか
  （名称／読み込み先）と、いまの名前も文字で添える。
- マスタ管理側のカードにも「再起動待ち（名称）」と出し、「いまの名称」の行を
  足す。判定は`dsPendingKinds()`の1箇所。
- **読むだけ・失敗しても空で返す**（左メニューが出なくなるのが一番困る）。

固定は`tests/test_dsrestart.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **データソースは「名称」も再起動待ち**（§9.183）: 接続先と同じく表示名も
  起動時に1回だけ決まる（`DBS`はプロセス起動時の写し）。以前は読み込み先しか
  「再起動待ち」を出しておらず、**名称の変更は誰も何も言わなかった**ため、
  左のボタンが古い名前のまま残っているのを見て「直したのに反映されない」と
  受け取られた。突き合わせは**サーバー**（`/api/catalog`の`restartPending`）で、
  画面で推測しない。案内は左メニューの中に出し、押すとデータ接続の設定が開く
  （気づく場所と打つ手を同じ場所に置く）。固定は`tests/test_dsrestart.js`。
