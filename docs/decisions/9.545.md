# §9.545 端末の控え——ブラウザ版とデスクトップ版のあいだで、端末の測定データと設定を揃える（利用者の指示・移行 P3）

索引: [決定記録](README.md)｜設計: [`docs/DESKTOP_MIGRATION_DESIGN.md`](../DESKTOP_MIGRATION_DESIGN.md) §8｜前: [§9.544](9.544.md)

## 利用者の言葉

「他、最も重大な問題（端末内測定データがブラウザの置き場に依存している点）についてはどう対応できますか？
一時置き場にファイルを生成しますか？」→ 設計書 §8 の方針（一時置き場ではなく端末の作業場所の控えへ、保存のたびに
写し続ける）を示し、**「1も2も進めてください」**。

## 決めたこと

- **控えは Python が持つ**（`backend/terminal_store.py`）。置き場は`paths.local_root()/terminal/terminal.sqlite3`。
  `%TEMP%`（ディスクの整理が消す）にも`db/`（Box の上・他の PC へ同期される）にも置かない。掃除の対象にもしない
  （作り直せない）。読み書きは Python だけで、デスクトップ版の窓は Start.vbs と同じ Python を使う（Store 版でも同じ写しを見る）。
- **記録**: 画面は端末へ保存するのと同じときに控えへも書く（`reliablePutCore`・待たない）。消すときは「消した印」
  （消した時刻）を残す。開いたときに1回、記録IDごとに突き合わせて**`updatedAt`の新しいほう**を採る
  （`records-store.js`の`reconcileTerminal()`）。一覧・1件の読み出しはこれが済むまで待つ（4秒で見切る）。
  消した印より古い記録は控えも画面も受け付けない。突き合わせで消すときは**共有のバックアップを消さない**
  （消した側の窓が済ませている）。
- **見出しと中身を分ける**: 開くたびの突き合わせは見出し（ID・時刻）だけを運び、中身は要る記録だけを取る
  （記録は1件で数十KB。全件を毎回運ぶと開くたびに数MB）。
- **設定**（localStorage）: サーバーが控えを画面の HTML へ埋め、`core/terminal-sync.js`（**JS_FILES のいちばん先**・
  base.js より前）が画面のJSより先に当てる。印（`WaveLogTerminalSyncV1`）に「最後に揃えた番号」と**値の指紋**を覚え、
  控えの値を当てるのは**手元の値が最後に揃えてから変わっていない名前だけ**。手元で変えてまだ送れていない値は手元が勝つ。
  初めて揃える画面では手元に在る名前がすべて正（前の版から使い込んだ設定を消さない）。変わった名前だけを5秒ごと・
  閉じるときに送る（丸ごと送らない）。送らない名前は理由の書けるものだけ（印そのもの・記録の写し・一覧の取り置き）。
- **控えの口はどのモードでも・切断中でも書ける**（`_LOCAL_ONLY_BLUEPRINTS`）。共有ではなく端末の手元にしか無いので、
  塞ぐと共有へ送れないときにこそ要る控えが取れなくなる。
- **名前**: 画面の名前空間は`WL.terminalStore`。`WL.terminal`は既に「この端末の名札」（ログインID・PC名）が使っていた
  （最初に同じ名前で書いて上書きし、網で気づいた）。
- **製品に消す口は作らない**。網は`tests/reset_terminal.py`でファイルを直に消す（ランナーは1本ごと、土台は始めと終わり）。

## 撤回した案・踏んだ罠

- **一時置き場（`%TEMP%`）へ引き継ぎファイルを作る**——ディスクの整理が消す。共有へ送れていない記録はそこにしか無くなる。
- **1回きりの引き継ぎ**——移行のあいだは同じ PC で両方を行き来する（併存）。WebView2 と Edge は保存領域そのものが
  別なので、アドレスを揃えても解けない。両方から届くのは Python だけ。
- **「最後に見た番号より後に変わった名前は控えが勝つ」**（最初の形）——**読み直しの往復と行き違った手元の変更が戻った**。
  画面が自分で送った古い値も「番号より後」に入るので、送る前（5秒の間）に読み直すと、控えの古い値で手元の新しい値を
  上書きした。`test_lotcopy`が「全部消したら消えたまま（再読込で復活しない）」など4件で捕まえた。**値の指紋**で
  「手元が最後に揃えてから変わっていないか」を見る形に直した。
- **画面のJSより後で当てる**——画面が古い設定で組み上がってから変わる。HTML に埋めて最初に当てる。
- 説明のコメントに`</script>`の字をそのまま書いて、頭の`<script>`が途中で閉じた（`Invalid or unexpected token`）。

## 測った（評価関数 E6・設計書 §8）

物差しは`test_terminal.js`。**同じサーバーを2つのオリジン**（`127.0.0.1:5029`と`localhost:5029`）で開き、2つの窓に見立てる
（オリジンが違えば保存領域が分かれる——本物の2つの窓と同じ「互いに見えない」形）。

| 物差し | 結果 |
| --- | --- |
| ① 共有へ送っていない記録が、もう一方の窓で開ける（件数・顔ぶれ・中身の指紋） | 一致（1件 / 1件・指紋一致） |
| ② 新しいほうが勝つ（両方向）・控えは古い版を受け付けない | 両方向とも届く・古い版を拒む |
| ③ 消した記録は戻らない（両方の窓）・消した後の古い記録を控えが受け付けない | 戻らない・`refused 1` |
| ④ 設定が両方向に届く・消した名前も届く・送らない名前は控えへ入らない | すべて満たす |
| ⑤ 初めて揃える窓では手元が正（手元の値が控えへ送られる） | 満たす |
| ⑥ 控えの値に`</script>`が入っても画面は壊れない | 壊れない・値はそのまま届く |
| ⑦ 送る前に読み直した変更は手元が勝つ | 戻らない・開いた直後に控えへ送られる |

`test_terminal.js` **23/23**、`test_terminalstore.py` **21/21**（置き場・新しいほうだけ・消した印・見出しと中身・設定の番号・
閲覧モードと切断中でも書ける・HTML に埋めている）。

欠陥注入（1件ずつ入れて、その場で戻した）:

- 控えのほうが新しい記録を取り込まない → ① が3件落ちる
- 控えが消した印を見ない → ③ が落ちる（`refused 0 / stored 1`）
- 指紋を見ずに控えの値を当てる → ⑤ と ⑦ が落ちる

## 網に与えた影響（前提が変わった網）

- `test_share.js`は2つ目のブラウザの文脈を「別のPC」に見立てていた。**同じサーバーに開く2つ目の文脈は、いまは
  「同じ端末の別の窓」**（控えで揃う）なので、PC2 を開く前に控えを白紙へ戻す（本物の別の PC は控えも別）。3件落ち→16/16。
- 網どうしの置き土産を防ぐため、ランナーは1本ごとに、土台は始めと終わりに控えを白紙へ戻す（`resetrecords`と同じ扱い）。
