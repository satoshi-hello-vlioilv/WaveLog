# §9.116 予定から外す受け皿（掴んでいる間だけ出る）

タイムラインの行を掴んで下端の帯（`#scDropRemove`）へ落とすと外せる。

**掴んでいる間だけ出す。** 常設すると「消す場所」が画面に居座り、
並べ替えのたびに押し間違いの的になる。**外せない行（実施中・完了・計画外・
権限なし）ではそもそも出さない**——出しておいて落としたら断る、では
掴んだ手間が無駄になる。

確認は `deleteEntry()` が持っているものをそのまま通す（確認の文言と
取り消しの作法を2つに増やさない）。受け皿へ落としたときは
`commitDragOrder()` を呼ばない——外すのが目的なので、帯へ来るまでに
通り過ぎた位置を保存する意味が無い。

**idは持ち主の型で渡すこと。** 掴んだidは`dataset`由来の**文字列**だが、
`deleteEntry()`は`e.id===id`で探すので、文字列のまま渡すと見つからず
**確認だけ出て何も消えない**（実際にそうなっていた。回帰テストが見つけた）。
`removableEntry()`が引き当てた行の`id`をそのまま渡す。

帯は掴んだ行より**上**に出す（§9.112のゴーストと同じ罠）。DOMに在るかを
見るテストでは捕まらないので、`elementFromPoint()`でその場所の一番手前が
帯であることを確かめる。固定は`tests/test_scdrop.js`（10件）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **予定から外す受け皿は掴んでいる間だけ出す**（§9.116、`#scDropRemove`）:
  常設すると押し間違いの的になり、**外せない行では最初から出さない**
  （出しておいて断るのでは掴んだ手間が無駄）。落としたら
  `commitDragOrder()`を呼ばない（外すのが目的なので途中の位置は保存しない）。
  **idは持ち主の型で渡すこと**——掴んだidは`dataset`由来の文字列だが
  `deleteEntry()`は`e.id===id`で探すため、そのまま渡すと**確認だけ出て
  何も消えない**。`removableEntry()`が引き当てた行の`id`を渡す。
  帯は掴んだ器より上（§9.112のゴーストと同じ罠。`elementFromPoint()`で
  確かめる）。**幅いっぱいにしないこと**（§9.238 ①、利用者の指示
  「ロットの並び替えや入れ替えなどをやりたい時にその先がドロップゾーンに
  あると干渉して目的の操作ができなくなる」）——以前は`left`〜`right`で下端を
  横断しており、**一覧の末尾へ行を運ぶ動線をそのまま覆っていた**（並べ替えの
  つもりが外す確認になる。意図と反対のことが起きるので押し間違いより悪い）。
  器は中身の長さから決めて右下へ寄せ、説明は`title`へ落とす（§9.234 ①）。
  **幅の数字だけを見る網では捕まらない**ので、「受け皿と同じ高さでも器の
  左寄りでは受け皿が手前に居ない」ことまで見る。固定は`tests/test_scdrop.js`。
