# §9.111 列の設定: 右クリック・名前付き保存・式で作る列

実機からの要望3点（§9.105の7点のうち残っていたもの）。

#### ④ 見出しの右クリック

列を1つ隠すためだけに設定パネルを開かせない。押した列がそこにあるので
「この列を隠す」は迷いようがない。**戻す操作も同じメニューに置く**——
隠した本人が次に探すのはそこなので、別の場所を覚えさせない。

`thead th`すべてに`data-col`を付けた（セルと同じで、位置で数えずキーで
引く。§9.104）。番号・ボタンの列にも効く。**最後の1列は隠せない**——
見出しが1つも無い表は、右クリックして戻すこともできなくなる。

#### ⑤ 名前を付けて覚える（列プリセットマスタ）

**マスタへ置くのが要点**で、そうすると他のPCからも同じ形を呼び出せる
（要望の主目的）。中身は列レイアウトマスタと同じ構造をJSONで丸ごと持つ
——プリセットは出し入れが丸ごとなので、列ごとに行へ展開しない（展開すると
行数が列数×プリセット数になる）。ファイルへの書き出し/読み込みも同じ中身
を扱い、**対象(target)も一緒に書く**（別の一覧のファイルを読み込んだ
ときに気づけるように）。読み込みは**保存せずに当てる**（§9.90と同じ）。

パネルの高さを820→880へ、保存キーをV5へ（帯を1段増やしたぶん、同じ
高さだと足元の「保存」が画面の外へ出る。実測で切れていた）。

#### ⑦ 式で作る列

要望は「計算式で条件を追加できるが、**元の列が無いと使えない**」。
データ側に無い列を、既にある列から作って並べたい。

**列レイアウトマスタの1行として持つ**（`[計算式]`列を追加）ので、並び・
幅・書式・読み替え・出す/出さないはデータ列とまったく同じ仕組みに乗る。

**`eval`を使わない。** 式は利用者が書き、マスタに保存され、他のPCでも
動く。文字列をJSとして実行する作りにすると、保存した式がそのPCで何でも
できてしまう。`static/js/list/list-formula.js`が字句解析→構文解析→評価を自前で
行い、**書ける物を最初から限る**。

比較には落とし穴がひとつある。**緩く数として読むと `[コード] = 10` が
`'010'` に当たる**——先頭ゼロのコードは実データに普通にあるので、照合が
黙って壊れる。比較のときだけ「元の文字へ戻して一致するなら数」という
厳しい判定を使う（計算では `'010' * 2 = 20` のままでよい）。

**壊れた式は書いている時点で断る**（知らない関数・引数の数まで）。
評価時まで待つと、実データの行が全部空になってから気づくことになる。
式が通らない行は**その行だけ空**にして列は残す（直せる場所へ辿れる）。

**この列は表示だけ**で、並べ替え・絞り込みはサーバーがデータ側の列に
対して行うので対象にならない。**できないことは画面にそう書く**
（できるように見せて効かないのが一番わかりにくい）。

固定は`tests/test_colmenu.js`（④）・`tests/test_colpreset.js`（⑤⑦の
画面側）・`tests/test_formula.js`（⑦の式の意味。ブラウザ不要で56件）。

## 守ること（`CLAUDE.md` から移した規則の本文）

  式は利用者が書き、マスタに保存され、**他のPCでも動く**。文字列をJSとして
  実行する作りにすると、保存した式がそのPCで何でもできてしまう。字句解析→
  構文解析→評価を自前で持ち、書ける物を限る。**比較では緩く数として
  読まないこと**——`[コード] = 10`が`'010'`に当たり、先頭ゼロのコードの
  照合が黙って壊れる（計算では`'010' * 2 = 20`でよい）。**壊れた式は
  書いている時点で断る**（知らない関数・引数の数まで。評価時まで待つと、

  仕組みに乗る。**表示だけの列**で並べ替え・絞り込みの対象にはならない
  ——そのことを画面にも書く。固定は`tests/test_formula.js`。
