# §9.365 完了突合を「クエリ結合マスタの1行」にする——用途で使いみちを分ける（利用者の指示）

**背景。** §9.364で作った実績突合は、`データソースマスタ`の`[突合キー]`という
**別の仕組み**だった。列名の並びを1つ持つだけなので、

- **左右で同じ列名しか使えない**（仕掛が`ロット番号`、実績が`材料ロット`だと
  当てられない）
- **持ち帰る列を選べない**（相手の行を丸ごと保存する）
- **完了した時刻が分からない**（だから作業スケジュールの「さかのぼり」で
  隠せない。§9.366）
- **保存する前に確かめられない**（クエリ結合には下見があるのに）

一方で`クエリ結合マスタ`は、左右別々の突合キー・取り込む列・接頭辞・
実データの見本つき列選択・保存する前の下見を**すでに全部持っていた**。
利用者の言葉:「クエリ結合のようなスタイルでデータをキーで突合せする汎用
スタイルにしてほしい。…実装済みの機能が使えるなら、実装済み機能をベースに
汎用性を拡張する方向でもよいです。」

**① 1行が「何のための結合か」を名乗る。** `クエリ結合マスタ`へ`[用途]`を
足した——`''`＝一覧に列を足す（今までどおり）／`'完了突合'`＝仕掛から消えた
ロットを相手のデータで探し、当たれば完了にする。**同じ突合の仕組みに、違う
使いみちを乗せる**ので、キーの組・取り込む列・接頭辞・下見は1つの作りのまま。
**既定を`''`から動かさないこと**——保存済みの行は用途を持たないので、既定を
変えると設定を触っていない現場の結合が別のものとして動き出す。

**② 完了突合の左は「仕掛」。** 予定が持っている明細（`detail`）は投入した
時点の仕掛行の写しなので、左のキーはその列名で引ける。右は任意のデータソース
（役割「実績」に限らない）。**左の値を取ってから右の並びへ直す**のが
この段の値打ちで、`_find_right()`が`{左の列名: 右の列名}`の対応表で戻す。
**ここを取り違えると、左の名前で相手を引くことになって必ず外れる**
（欠陥注入で確かめてある）。

**③ 持ち帰るものは3つ。** `columns`（空＝相手の全列）＋`prefix`が
「結合後にどのデータを使えるようにするか」で、`take_columns()`の1箇所が答える。
`[完了日時列]`が完了時刻で、`finish_time_of()`が読む。**書式は決め打ちにしない**
——現場のデータはISO・`2026/09/01`・`2026-09-01 13:45`・DATETIME型が混ざるので、
読めた形だけ使い、**読めなければ空**を返す。推測で日時を作ると、さかのぼりが
実際の作業と違う日で切れる。

**④ 読めなくても完了にする**（利用者の選択）。完了日時が空・読めない行は
**完了にはするが、さかのぼりでは常に出す**。隠す側へ倒すと「完了にしたはずの
行がどこにも無い」になる。画面はその理由を印の説明に書く（推測させない）。

**⑤ 既定の1件は残す。** `データソースマスタ[突合キー]`の設定は、
`builtin_finish_def()`が**保存されていない1件の定義**として同じエンジンへ
乗せる（既定の品質データ結合と同じ作法）。設定していない現場は今までどおり
動き、画面にも出るので「登録していないのに完了になる」を探さずに済む。
**利用者が1件でも登録したら既定は当てない**——同じロットを2つの定義で探すと、
当たった順で完了時刻が変わる。既定の完了日時は、利用者が名指しした
`前工程実績_作業終了_日付`が**突合キーに入っているときだけ**使う
（入っていないものを勝手に探しに行かない）。

**⑥ スケジュールで使う結合を選べる**（利用者の指示「作業スケジュールに
使用可能とするデータも選べるように」）。以前は登録済みの結合が**全部**
スケジュール表へ当たり、外す手立てが無かった。`[スケジュール除外]`を足し、
**保存値は「使わない」側**にする（§9.132の作法）——設定を触っていない行は
今までどおり効く。判定はサーバー（`definitions_for(for_schedule=True)`）で、
画面は`for=schedule`を付けて聞くだけ。**画面で結合の顔ぶれを組み立て直さない。**

**⑦ 下見は用途で見る場所が変わる。** 完了突合が探すのは「仕掛から**消えた**」
ロットなので、いま仕掛にある行へ当ててみても0件にしかならず、設定が正しいか
どうかを何も言えない。`probe_finish()`は**相手の側**を見て、
①相手に何行あって突合キーが揃っている行はいくつか ②完了日時の列を実際に
いくつの行で読めたか ③当たったとき何が持ち帰られるか（列の名前と実例）
を答える。

**⑧ 層。** 「定義の持ちもの」（`parse_finish_time`・`take_columns`・
`finish_time_of`）は**定義を持つ側**（`query_join.py`）に置く。
`actual_match.py`が持つと、下の層（`query_join`）が上の層を関数の中で
`import`することになる（`test_importlint.py`が数える）。`actual_match`からは
同じ名前で再公開してあるので、呼び方は変えなくてよい。

**画面。** 用途は編集窓の**いちばん上**（決める順のとおり——ここで決めた
使いみちで下の節の意味が変わる）。完了突合では③が「当たったらどうなるか」に
替わり、**結合の仕方の6枚は出さない**（「当たったら完了」の1通りしかないので、
押せるのに効かない設定を残さない・§4）。④は「何を持ち帰るか」になり、
「完了時刻にする列」が出る。一覧には`用途`の列が増え、既定の完了突合も
1行として並ぶ。

固定は`tests/test_finishjoin.py`（21件）・`tests/test_qjoinui.js`・
`tests/test_actualmatch.py`。**欠陥注入で確かめてある**——`for_schedule`の
絞り込みを外すと「一覧には出るがスケジュール表には出ない」が落ち、
左右の対応表を外すと突合そのものが4件落ちる。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **突合の定義は`クエリ結合マスタ`の1行。用途で使いみちを分ける**（§9.365）:
  `[用途]`は`''`（一覧に列を足す）と`'完了突合'`の2つで、**既定を`''`から
  動かさないこと**（保存済みの行は用途を持たない）。完了突合の左は役割「仕掛」で、
  **予定の値は左の列名で取り、右の並びへ直してから**相手を引く（左の名前で
  相手を引くと必ず外れる）。持ち帰るのは`columns`＋`prefix`＝`take_columns()`、
  完了時刻は`[完了日時列]`＝`finish_time_of()`の1箇所。**日時の書式は決め打ち
  にせず、読めなければ空**を返す（推測で日時を作らない）。**読めなくても完了に
  するが、さかのぼりでは常に出す**（隠すと「完了にしたはずの行が無い」になる）。
  `データソースマスタ[突合キー]`は`builtin_finish_def()`が**保存されない既定の
  1件**として同じエンジンへ乗せ、**登録が1件でもあれば当てない**（同じロットを
  2つで探すと当たった順で完了時刻が変わる）。**「定義の持ちもの」は定義を持つ側
  （`query_join.py`）に置く**——`actual_match`に置くと下の層が上の層を関数の中で
  `import`することになる。下見は用途で見る場所が変わる（完了突合は**相手の側**を
  見る。仕掛にある行へ当てても0件にしかならない）。固定は
  `tests/test_finishjoin.py`・`tests/test_qjoinui.js`。
- **スケジュール表で使う結合は選べる。保存値は「使わない」側**（§9.365、
  利用者の指示）: 以前は登録済みの結合が**全部**スケジュール表へ当たり、外す
  手立てが無かった。`[スケジュール除外]`が1の行だけが外れるので、**設定を
  触っていない行の見え方は変わらない**（§9.132の作法）。判定はサーバーの
  `definitions_for(for_schedule=True)`で、画面は`for=schedule`を付けて聞くだけ
  ——**画面で結合の顔ぶれを組み立て直さない**（無効にした結合が選択肢に残る）。
  完了突合の行は一覧の結合として当たらない（列を足すためのものではない）。
