# §9.563 言語の住み分け——どの処理をどの言語に持たせるか（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.562](9.562.md)｜関係: [§9.544](9.544.md)・[§9.546](9.546.md)・[§9.552](9.552.md)・[§9.270](9.270.md)・[§9.561](9.561.md)

## 経緯

利用者の指示:「体感が変わらないという理由で書きなおす直さないを決めるのではなく、最もメリットがある言語でその処理を行わせるという
設計思想で必要箇所を洗ってほしいです。Pythonが役に立つ場面がほとんどないという全体感がもしあれば方針としては依存関係のあるものを
排除するという形で進めてもよいです。将来的に拡張したときにPythonを残すメリットがあるか。ある部分は着手しない。着手すべき部分があれば、
着手する。とくにバグの出にくさや将来的な拡張性でどの言語を使用すべきかしっかりすみわけを行ってほしいです。」

速さ（体感）では決めず、**バグの出にくさ**と**拡張のしやすさ**、それに**配る・動かすときの痛み**の3つで決める。
根拠は「実際に起きた不具合」に置いた。

## 測った（いまの作り）

| 層 | 言語 | 行数 | 持っているもの |
|---|---|---|---|
| 窓・起動・更新・初回の写し・ショートカット | Rust（`desktop/`） | 約2.6千 | 起動画面・Python の監督・版をそろえる・`.lnk`・`/static/`を返す |
| 業務・保存・共有 | Python（`backend/`） | 約4.5万（うち更新履歴の字 7千） | 241 のルート・SQLite・共有DBの写しと錠・予定の展開・帳票の材料・Excel |
| 画面 | JS（`static/js/`） | 約8万 | 全画面・図・式・一覧 |
| 網 | Python 2.1万・JS 6.1万 | | JS の網はほぼ全部 HTTP 越し（どの言語で答えても使える） |

Python の外の部品は flask だけ（`program/requirements.txt`）。

### 実際に起きた不具合 209件の分類（決定記録 524枚のうち、原因の節を持つ 178枚を読んだ）

数え漏れはある（全部は通読していない）。層と分類は読み手の判定。

| 層 | 型・形 | 実行環境・配布 | 並行・錠・共有 | 論理・仕様 | 見た目 | 文字コード・パス | その他 | 計 |
|---|---|---|---|---|---|---|---|---|
| Python（業務） | 7 | 0 | 12 | 9 | 0 | 5 | 1 | 34 |
| Python の実行環境・配布 | 1 | 11 | 3 | 0 | 0 | 5 | 0 | 20 |
| JS | 17 | 0 | 6 | 53 | 1 | 0 | 9 | 86 |
| CSS | 0 | 0 | 0 | 0 | 20 | 0 | 6 | 26 |
| 境界（JS↔Py／Py↔Rust） | 3 | 0 | 2 | 3 | 0 | 0 | 1 | 9 |
| Rust | 0 | 0 | 0 | 1 | 0 | 1 | 0 | 2 |
| 網・道具・文書 | 0 | 1 | 0 | 1 | 0 | 2 | 28 | 32 |

読み取れること:

1. **「実行環境・配布」の不具合は全部、Python 本体ではなく「Python を動かす周り」**（Store 版の仮想化 §9.318・§9.496、
   python と pythonw §9.415、pip と flask §9.268、置き場で import が変わる §9.404、.bat・.vbs の改行と文字コード §9.229・§9.547）。
   このうち多くは、窓（Rust）へ移したことで**すでに消えた**（§9.546〜§9.559）。
2. **業務の Python の不具合は大半が「論理・仕様」と「共有ファイル・錠」**。前者はどの言語でも起きる。後者は Windows と SMB の
   置き換えの決まり・ネットワークの不安定さが原因で、Rust でも同じ OS の呼び出しになる（§9.108・§9.268・§9.384）。
   言語を替えて減ると言える根拠は、記録の中に見つからなかった。
3. **例外が1つ**: §9.270「`with connect(...)`は接続を閉じない」。Rust なら所有権（Drop）で閉じるので起きない種類。
   ただし Python の側でも、**接続を返す1か所**で塞げる（下の 2）。
4. **件数でいちばん多いのは JS の型・形（17件）**。関数の取り違え・`undefined`・`null`の扱い・名前の綴り違いで、
   型検査（TypeScript の検査）があれば半分以上（17件中 9件）を書いた時点で止められた。
5. **言語の境界で壊れている**（9件）: 同じ設定ファイルを Python と Rust の両方が書いた（§9.561 追補）、応答の形を片側だけが
   選り分けた（§9.205・§9.381）。言語の選び方より「1つの事実・1つのファイルの書き手は1言語」が効く。

## 決めたこと（言語ごとの受け持ち）

| 受け持ち | 言語 | 理由（バグの出にくさ・拡張性・配る痛み） |
|---|---|---|
| 窓・起動画面・プロセスの監督・終わり方 | **Rust** | OS と直に話す所。所有権で開いた物を必ず閉じる。1つの exe で配れる（§9.546） |
| 版をそろえる・初回の写し・ショートカット・ファイルのバイト単位の書き出し | **Rust** | Python が動く前に要る。.bat・.vbs・WSH の文字コードと改行の罠が無い（§9.552・§9.555・§9.559） |
| **Python そのものを用意すること**（どの Python を使うか・部品の導入） | **各 PC の Python のまま**（探すのは窓・`locate::python()`）——【追補で撤回】同梱しない | 同梱は配る版を十数 MB 太らせ、「Python は各 PC のもの・配る物は小さく」という作りの意図に反する（利用者の判断・下の追補） |
| 業務（予定の展開・突合・換算係数・帳票の材料・マスタ） | **Python のまま** | 不具合の大半は論理・仕様で言語では減らない。4.5万行と 2.1万行の網を書き直す危険のほうが大きい。式・集計・表を足す拡張は Python が最も速く安全に書ける |
| SQLite・共有DBの写し・錠 | **Python のまま** | 壊れ方は OS とネットワークの決まり。§9.552 でも共有DBは Python に残すと決めている。接続の閉じ忘れは 2 で塞ぐ |
| Excel の読み書き・Navigator の DLL | **Python のまま** | 外の形式・外の部品とつなぐ所で、足すときの手間が最も小さい |
| 画面 | **JS のまま＋型の検査**——段を分けて着手 | ブラウザで動くのは JS だけ。書き換えではなく、**検査だけ**足す（ビルドの段は足さない） |
| 1つの設定ファイル・1つの事実 | **書き手は1言語** | 境界の不具合の原因。読み手が何言語でもよいが、書くのは1つ |

**Python の依存は外さない**。「Python が役に立つ場面がほとんどない」状態ではない——業務の 4.5万行がまさに役に立っていて、
拡張（新しい集計・表・取り込み）もここが受ける。外すべきなのは Python ではなく、**Python を各 PC に用意してもらう形**のほう。

## この記録で着手したもの

### 2. 接続は `with` を抜けたら閉じる（§9.270 を根から塞ぐ）

`sqlite_io.connect()` が返す接続の型を、`with` を抜けたら**確定（コミット／ロールバック）してから閉じる**型にした
（`sqlite3.connect(factory=…)`）。107 か所の `with connect(...)` は書き換えない——答えは接続を作る1か所。

- 前に確かめたこと: 107 か所のどれも、カーソルや接続を `with` の外へ持ち出していない（構文木で見た。持ち出していれば閉じた後に読めなくなる）。
  `with c:` を取引の区切りに使う書き方も 0 か所。
- §9.270 の回り道（写しの中身を上書きする・置き換える側は `_opened()`）は残す。害は無く、外すと元に戻ったときに再び壊れる。

## 追補（利用者の判断・同梱の Python を撤回）

利用者の判断:「Python を窓が持つ：もともとの意図と反するためやらない。Pythonの同梱はしない。配布が巨大化する。
Flaskは排除してポート依存を取り除いた対象なのでこれもやらない。」

- **誤っていた前提**: 「配る・動かすときの痛み」を PC ごとの Python の違い（PATH・Store 版・pip）だけで量り、
  **配る版の大きさ**と、作りの意図（Python は各 PC のもの・配る物は小さく保つ・§9.555 の版は`PAYLOAD`だけ）を軽く見た。
- **直したあと**: Python も flask も同梱しない。各 PC の Python を窓が探す今の形（§9.546）のまま。
  Store 版・PATH の順で起きた不具合は、これまでどおり窓の探し方（`locate::python()`）と`paths.browser_dir()`（§9.496）で受ける。
- **flask について**: §9.544 で外したのは**ポートと HTTP のサーバー**。flask はいまも窓口（`program/sidecar.py`）の中で
  WSGI としてルートの振り分けに使っている（ポートは開かない）。これも触らない。
- 次の段は 2（画面の JS に型の検査・§9.566）と 3（境界の約束を1つの定義に）。
