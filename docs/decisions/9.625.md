# §9.625 紙の字送りは画素にそろえない——画面で測った割り付けが、刷るときに字の幅の違いで切れるのを直す（利用者の報告）

索引: [決定記録](README.md)｜前: [§9.624](9.624.md)｜関係: [§9.622](9.622.md)・[§9.242](9.242.md)・[§9.332](9.332.md)

## 経緯（利用者の言葉）

> アプリ内のプレビューはOKでしたが、印刷のプレビューで同様の現象が発生しています。

§9.624 で、帳票の画面（アプリ内のプレビュー）では切れなくなった。Latitude 3550（1920×1080・100%）の印刷のプレビューでは、まだ切れていた。切れたのは、寸法の「製造」の行・運転条件の3段目・測定データの33〜40条。

## 原因

刷る紙は、画面で測り終えた割り付けを写して作る（`rpPageHtmlFor()`）。写すのは、塊の行の割り当てと縮める倍率で、刷る側では測り直さない（§9.242「刷るときもプレビューと同じ箱」）。だから、画面と刷る側で字の幅が同じであることが前提になる。

画面の字送りは、PC の字の描き方の設定で変わる。字を画素へそろえる（ヒンティング）と、同じ字の幅が変わる。この設定は、100%の画面で効く。この環境で fontconfig の hinting=hintfull を当てると、帳票の紙の字の幅は次のようになった。
- 162 要素のうち 48 要素で変わった。
- 変わり方は最大 ×1.089。

刷る側の字の幅が画面と違えば、刷った紙で字が折り返し、画面で測った器から切れる。3550 の Windows で、画面と刷る側のどちらがどれだけ違ったのかは**分からない**（この環境では Windows の描き方を再現できない）。

## 直したこと

`static/css/00-base.css` の base 層に、`.rp-page,.os-page,.sp-page{text-rendering:geometricPrecision}` を足した。
- この指定の字は、画素へそろえず字の形どおりの幅で並ぶので、PC の描き方の設定に関係なく同じ幅で組まれる。
- 刷る書類も同じ CSS を読むので、紙の中でも同じ指定が効く。
- 字の大きさ・割り付けの決め方は変えない。

100%の画面では、紙の小さな字の輪郭が少し柔らかく見えることがある（画素にそろえないため）。

## 物差し（`tests/test_rpmetric.js`・1920×1080）

同じロットの帳票を2つの環境で開き、紙の中を比べる。
- 字送りを画素にそろえない環境（既定）
- 字送りを画素にそろえる環境（fontconfig hinting=hintfull）

| 項目 | 直す前 | 直した後 |
| --- | --- | --- |
| M1 字を持つ要素の幅が同じ（差 0.5% 以内） | 114/162（最大 ×1.089） | 162/162 |
| M2 塊の行の割り当て・縮める倍率が同じ | 同じ（この見本のロットは中身が短く、余白が吸った） | 同じ |

Windows の印刷で直ったかは、利用者の 3550 で確かめてもらう。
