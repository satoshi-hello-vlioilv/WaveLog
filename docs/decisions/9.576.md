# §9.576 共有マスタへ書き出せなかった変更を、次の書込の「取り直す」で消さない——写しに残して送り直し、画面へ言う（利用者の不具合報告）

索引: [決定記録](README.md)｜前: [§9.575](9.575.md)｜関係: [§9.263](9.263.md)・[§9.384](9.384.md)・[§9.188](9.188.md)・[§9.372](9.372.md)

## 経緯（利用者の報告）

> 不具合修正をお願いします。マスタをいじってからスケジュールに追加できなくなったようです。

報告（VER2.467.0・LS4・スケジュールモード）: 設備停止を予定へ追加すると **HTTP 400「指定のサブカテゴリが見つかりません」**。
同じ数分のあいだに、共有の置き場への書込が `[WinError 59] 予期しないネットワーク エラー`・`[WinError 5] アクセスが拒否されました`
で落ちていた。追加できる停止とできない停止があった。

## 1. 原因（コードで追い、試しの共有で再現した）

マスタを共有に置くと（§9.263）、読みは手元の写し、書きは「ロック → 取り直す（共有 → 写し・force）→ 当てる → 改訂番号 → 共有へ丸ごと置換」。

1. 設備停止マスタで内訳を足す → 写しに入る → **共有への書き出し（`_push`）がネットワークの失敗で落ちる**。
2. 書き出しは teardown で行っていたため、失敗は**記録に警告が1行残るだけ**。画面は 200（保存できた）を受け取る。
3. 画面は写しから一覧を読み直すので、**足した内訳は見えている**。
4. 予定へ追加する（`schedule` の段も共有マスタの書込サイクルを通る）→ 頭の「取り直す」が**写しを共有の古い中身で上書き**
   → 足した内訳が写しからも消える → 画面が送った内訳の番号が見つからず 400。
5. 内訳を触った停止だけが落ちる（＝「できるものとできないもの」がある）。

起動のときの取り込み（`configure()`）も同じく force で写しを上書きしていたので、再起動でも消えていた。

## 2. 物差しと前後（試しの共有で、書き出しを10回わざと落とす）

| 物差し | 前 | 後 |
| --- | --- | --- |
| 画面に見えた変更が次の書込で消える | **10 / 10** | **0 / 10** |
| 届くようになっても共有へ出ない | 10 / 10 | 0 / 10 |
| 書き出せなかったことを画面が知る | 0（200 だけ） | 応答の頭で知らせ（同じ字は30秒に1回） |

## 3. 決めたこと

- **書き出せなかった変更は写しに残し、印を写しの外に置く**（`master.local.sqlite3.unpushed.json`＝積んだ共有の改訂番号・時刻・理由）。
  印を写しの中（共有メタ）へ置くと、送り直したときに印ごと共有へ出て、取り込んだ他の端末まで「書き出せていない」と読む。
- **取り直す前に送り直す**（`_settle_pending()`の1箇所。書込サイクルの頭と起動が呼ぶ）。
  - 共有の改訂番号が印の番号のまま（＝誰も書いていない）なら、写しをそのまま共有へ出す。取り直しは要らない。
  - 共有が先に進んでいたら（他の端末が書いた）、**写しを控えのファイル（`master.unpushed.<時刻>.sqlite3`）へ写してから**
    共有を取り込み、控えの場所まで言う。丸ごと置換なので混ぜられない——どちらかを黙って捨てない。
  - 共有へ届かなければ写しも印も触らず、書込を理由つきで断る（503・「書き出せていない変更はこの端末に残っています」）。
    起動では写しのまま立ち上がる。
  - 共有の改訂番号を読めないことを「0番」と取り違えない（`_read_revision(strict=True)`）。
- **書込サイクルは応答を返す前に閉じる**（after_request）。知らせは応答の頭 `X-WL-Master-Notice`（URL 符号化）で、
  画面は `api()` の1箇所が拾って知らせる。状態コードは変えない——変更は写しに残って送り直されるので、押し直させると二重になる。
  ハンドラが投げたときの保険に teardown でも閉じる（ロックを返すため）。
- 予定の追加が断られたら、画面は**設備停止の一覧を読み直す**（同じ番号を送り続けない）。断りの字は番号と次の一手まで言う
  （`stop_sub_missing()`）。

## 網（見張り）

- `test_mastershare.py` 9節: 書き出しの失敗で写しと印が残る・ロックは返す／次の書込で送り直し、写しを消さない／
  共有が先に進んでいたら控えへ逃がして取り込み、場所を言う／届かないまま起動しても写しを消さず、届いた起動で送り直す／
  実物の Flask で応答の頭に知らせが乗る（失敗・送り直し）
- 欠陥注入（1件ずつ）: 送り直しを外す → 10件落ちる／閉じるのを teardown へ戻す → 2件落ちる

## 残したもの

- 同時刻の `schedule.lock.json` の WinError 5／59 は作業予定の錠（`schedule_sync`）の側で、表示はベストエフォート。
  今回の 400 とは別の道なので触っていない。共有の置き場そのものの不調（ネットワーク・権限）の原因は**分からない**。
