# §9.126 測定画面の再設計 第4段: 面積を配り直す（器が中身より大きい）

3段構成が一巡したので、**実際に測って**空きを洗い出した（1920×1080）。

| 場所 | 空き |
|---|---|
| ①準備 中央ペイン | オペレータ一覧の隣の下に **237px**、下端に221px |
| ②測定 板幅ブロック | 右に **430px**、表の下に **340px** |

どれも「中身を減らしたのに器がそのまま」という同じ形をしていた。

#### 器も条数ぶんだけにする

§9.124で**行のDOM**は条数ぶんに減らしたが、CSSは
`grid-template-columns:repeat(2,minmax(0,1fr))` と
`grid-template-rows:20px repeat(20,minmax(0,1fr))` のままだった。
つまり**1列しか作らなくても器は2列ぶん、8行しか作らなくても器は20行ぶん**
場所を取り続けていた。②を全幅にしたことで、それがそのまま空きになった。

列数はJSが決める（`stripColumnCount()`の1箇所）。行は`grid-auto-rows`で
中身ぶんだけ作り、**高さの上限は`--strip-rows`（JSが条数から入れる）で
器の側が持つ**——器いっぱいに伸ばすと1条のロットで1行が700pxになり、
20行に固定すると8条で12行ぶんの白が残る。

**DOMの数だけを見る網では捕まらない。** 最初に書いた検証は
「`.strip-column`が1つ」を見ていたので、CSSが2列ぶん取ったままでも
素通りした（列の幅は半分になっているのに）。**実際の寸法**（列の幅・
最後の行の下端と器の下端）で見るように書き直した。

#### 空いた幅を「関係の遠いもの」へ回さない

最初は空いた430pxを公差側へ回した。ところが**公差数直線は縦向き**なので
幅を渡しても使われず、空きが「右端」から**「数直線と入力表のあいだ」**へ
移っただけだった（実測900px）。**一緒に読むものを引き離しては意味がない。**
公差と入力表を隣り合わせにし、余りは右端へ寄せる形に直した。幅は2列の
ときの見え方（公差568px / 表416px）に合わせてある。

#### px指定のリストは行の途中で切れる

①のオペレータ一覧は`height:273px`だった。1行31pxなので**約8.8行**——
最後の名前が半分で切れており、しかも1行のコントロール2つと同じ行に並ぶ
ため隣の下に237pxの穴を作っていた。

最初は168px（5行ぶんのつもり）へ詰めたが、これも**5.35行**で切れた。
**pxで行数に合わせ込むのは無理**——表示サイズを変えれば1行の高さも変わる。
`size`（行数）に任せる形にした。

**ただし行数は減らさない。** 検証データのオペレータは171人おり、見える行を
減らすほど探すのが大変になる。`size="7"`どおりの219pxにするだけで、
切れは無くなり穴も54px減る。**「空きを詰める」ことが目的化すると、
使いにくくする方向へ簡単に倒れる。**

固定は`tests/test_msteps.js`（75件）。3つの欠陥（列数のCSSを2列固定へ戻す／
行数を20行固定へ戻す／リストの高さをpxへ戻す）を注入し、それぞれ落ちる
ことを確かめてある。

## 守ること（`CLAUDE.md` から移した規則の本文）
