# §9.524 保持方式マスタ——フィンガー／ゴムリングを判定表で決める（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「刃組ガイダンスで、フィンガーとゴムリングを選ぶ条件を今は板厚だけでフィンガーの登録のみに持たせていましたが条件が複雑になるので、所得済みデータを列に持つ条件テーブルを組めるようにマスタを追加してください。」

選んでもらったこと（3つ）:

- 条件の列 … **計算値＋仕掛の列**（板厚・元コイル幅・条数・条幅の最小/最大と、仕掛データの列を列名で）
- 表の形 … **列＝データの判定表**（行＝決まり・右端＝保持方式・空欄のセル＝問わない・試す行）
- どれにも当たらないとき … **表の最後の既定の行**で決める

## 測った（評価関数）

| | 前 | 後 |
| --- | --- | --- |
| 方式を決められる条件 | 板厚だけ（刃組基準値のフィンガー切替板厚） | 計算値5つ＋仕掛の列（任意の列） |
| 未登録の設備で、板厚 0.1〜2.0（39通り）の方式が今までと同じ | 39/39 | 39/39 |
| 条数・仕掛の列・板厚の範囲で決める5場面 | 表現できない | 5/5（当たった行も一致） |
| 刃選択マスタの「材質」条件が当たる | 当たらない | 当たる |
| フィンガーマスタの「適用板厚 上限」 | 説明は「この板厚未満で使う」なのに、どこも読んでいない（効かない欄） | 欄を外した（列の値は残す） |

## 見つけた不具合

- **刃選択マスタの「材質」「ロット番号」は1度も当たっていなかった。** 条件の値を作る`pickCtx()`は
  `st.material`／`st.lotNo`を読むが、刃組ガイダンスはどこでもそれを入れていなかった。
  1本目のコイルの仕掛の行（`st.src`）から引くようにした（材質＝製造材質→オーダー材質）。
- **フィンガーマスタの「適用板厚 上限」は効かない欄だった。** 説明文は「空欄なら切替板厚に従う」と
  言っていたが、判定は刃組基準値の切替板厚だけを見ていた。方式は保持方式マスタが決めるので欄を外した。

## 決めたこと

- `保持方式マスタ`（設備ごと）。1行＝1つの決まり（条件JSON＋保持方式＋備考）。**上から順に見て最初に
  当たった行**、**条件の無い行＝既定の行**で最後に1つ（`_hold_tidy()`が整える・消せない）。
  保存は表を丸ごと置き換える（`hold_replace()`）。
- **登録が無い設備は、今までの決め方をそのまま表にした「種」**（`hold_seed()`）を返す。
  触っていない設備の動きは変わらない。「未登録に戻す」は行を消す（種を保存しない）。
- 条件の語彙は**刃選択マスタと同じ**（`field/op/value/value2`・比べ方8つ）。仕掛の列は
  `source.<列名>`（帳票ブロックの道と同じ綴り）。判定は`blade-core.js`の`firstRule()`の1本で、
  刃選択（`pickGroup`）・保持方式（`holdPick`）・盤の試す行が同じ1本を通る。
  仕掛の列は型を持たないので、比べ方で読み方を決める（大小・範囲は数、＝／≠は両方が数なら数、含むは字）。
- 条件が読む仕掛の行は、刃組ガイダンスでは1本目のコイルの**完全な生データ**を開くたびに取り直す
  （§9.388と同じ口）。刃組スケジュール一覧の見込みは**予定の写し**（一覧に出している列だけ）を渡す
  ——写しに無い列の条件は当たらない（§9.231 引けない値を当てない）。
- 刃組ガイダンスの説明は**何行目のどの条件で決まったか**を言う（`holdReason()`・出どころを書く）。
- 盤は`bladeset/hold-pick.js`（`special:'hold-pick'`）。セルの書き方は`< 0.6`・`0.6〜1.0`・`>= 20`・
  `SUS`・`!= X`・`*SUS*`。**読めない字は理由を出して直すまで残し、保存させない**。試す行は
  **見えている列の値だけ**を読む（消した列の値が裏で効いていた）。
- 網: `test_holdpick.js`（判定・盤・ガイダンス）と`test_bladeset.py`（保存・種・戻す・語彙）。
