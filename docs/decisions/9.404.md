# §9.404 直接実行するものを`program/`へまとめる（リポジトリ直下の整理）

## 何をしたか

リポジトリ直下に平置きになっていた**直接実行されるPythonと、その道連れの
資材**を `program/` へ移した。

| 移したもの | いままで | いま |
| --- | --- | --- |
| Flask本体の組み立て | `app.py` | `program/app.py` |
| 起動開始点 | `start_app.py` | `program/start_app.py` |
| 起動前の確認 | `setup_app.py` | `program/setup_app.py` |
| 停止 | `process_manager.py` | `program/process_manager.py` |
| 起動待機画面 | `loading.html` | `program/loading.html` |
| 必要な部品 | `requirements.txt` | `program/requirements.txt` |
| 開発用の道具 | `requirements-dev.txt` | `program/requirements-dev.txt` |

**移さなかったものが2つある。どちらも「そこに在ること」が役目だから。**

- **`_pycache_bootstrap.py`** — `tests/test_faststart.py`・`test_ddllint.py`・
  `test_bootopen.py`・`test_boot.py` の4本が **素のモジュール名**で
  `import _pycache_bootstrap` している。これは横着ではなく、
  「`sys.pycache_prefix` を**最初のimportより前に**立てる部品が、探索先の
  通っている場所に在る」ことを確かめている——`program/`へ入れると、
  確かめている内容そのものが変わる。
- **`eslint.config.mjs`** — ESLint v9 の flat config は `files:` の glob を
  **設定ファイルのあるフォルダ基準**で解決し、`..` で始まるパターンを
  **拒否する**。`program/`へ移すと `static/js/**/*.js`・`tests/**/*.js` が
  1件も当たらなくなり、**lintが「0件で緑」になる**（緩む側に壊れる）。

## なぜ`program/`か（名前）

利用者と2つ確かめた——**何を隔離するか**（実行ファイルだけか、開発用の
ファイルも含めるか）と**フォルダ名**。答えは「実行ファイル＋開発ファイル」
「`program/`」。`bin/`（実行形式の置き場という含み）・`app/`（`backend/`を
`app/`にできない理由と同じ衝突を招く）は採らなかった。

## 踏んだところ

### ① `import _approot` を足さないと、移した瞬間に何も読めない

`python program/start_app.py` と打つと、`sys.path[0]` は **`program/`** に
なる。リポジトリ直下は通っていないので `import backend...` も
`import _pycache_bootstrap` も落ちる。

そこで探索先の答えを**1箇所**に置いた（`program/_approot.py`）。
4本はこれを**いちばん最初に**通し、その次に `_pycache_bootstrap` を読む。

```python
# program/_approot.py
import os
import sys
_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
if _ROOT not in sys.path:
    sys.path.insert(0, _ROOT)
```

**4本それぞれに2行ずつ書かない。** 置き場が変わったとき、直す場所が4つに
増える（この移動そのものが、まさにそれを1つにしておけばよかった例）。

### ② `APP_ROOT` は動いていない（現場のDBはそのまま）

`backend/paths.py` の `APP_ROOT` は **`backend/paths.py` の位置**から
2つ上を指す。`backend/` を動かしていないので、`db/`・`config/local.json`
の解決は**1バイトも変わらない**。移したファイルを指していた2箇所
（`requirements.txt` の指紋・`loading.html` の写し元）だけを、
新しく足した `PROGRAM_DIR`（＝`APP_ROOT/'program'`）へ向けた。

### ③ `.bat`/`.vbs` は CRLF・CP932 のまま触る

`start_app.bat`・`setup.bat`（§9.405で`update.bat`へ改名）・`stop.bat`・`Start.vbs` の起動行を
`program\…` へ書き換えた。**改行と文字コードを変えないこと**（§9.229）。
CRLF の行末に `\r` が残っているので、`sed 's/…$/…/'` は当たらない
（`$` を外したパターンで置換した）。置換後は `file` で
「Non-ISO extended-ASCII text, with CRLF line terminators」を確かめる。

### ④ 見張りを一緒に動かさないと、移動そのものが監視を外す

移すだけで、**機械の見張りが静かに外れる**場所が5つあった。どれも
「落ちる」のではなく「見なくなる」——緩む側に壊れるので、通ったことが
証拠にならない。

| 見張り | 外れ方 | 直し方 |
| --- | --- | --- |
| `tests/test_pick.py` | `ROOT.glob('*.py')` が`program/`を見ない | `(ROOT/'program').glob('*.py')` を足す |
| `tests/pick_tests.py` | `('app.py',[ALL])` 等が当たらない | 規則の道を`program/…`へ。受け皿`('program/', g('起動'))` は**名指しの下**に置く（`hit`は当たった規則を全部足すので、`program/app.py`は`[ALL]`のまま） |
| `tests/test_pyflakes.py` | `TARGETS` が旧い道 | `program/…` へ |
| `tests/test_quietlint.py` | 3本を旧い道で探し、**無ければ黙って飛ばす** | `program/…` へ |
| `.github/workflows/nets.yml` | `pip install -r requirements.txt` が無いファイルを指す | `program/requirements.txt` へ |

### ⑤ 通しで出た赤4件——`backend`の中の素の`from app import app`

1段目（純粋な網）は51本すべて緑、通しでも`test_scowner`の**4件だけ**が
落ちた。中身は**書き込みが500**（`{'error': "No module named 'app'"}`）。

`backend/launcher/server.py`と`backend/schedule_owner.py`が、その場で
`from app import app`と書いていた。`program/start_app.py`から起動する限り
`program/`が`sys.path[0]`なので読める——**入口の隣に在ることに頼っていた**。
テストは`backend`だけを読み込んで中継の受け口を叩くので、その経路では
読めない。**呼ばれ方で答えが変わる**のが原因で、移動そのものは二次的。

答えを`backend/app_module.py`の`flask_app()`1箇所へ置いた。置き場は
`paths.PROGRAM_DIR`が答え、探索先に無ければ自分で足す。読むのは
**呼ばれたときだけ**——`app`は`backend`を読むので、モジュールの読み込み時に
読むと§9.329で0にした輪が戻る（`# 遅延:`の印を付けて`test_importlint`の
数から外してある）。

## 網

`tests/test_faststart.py` に「直接実行する4本は `program/` にある」と
「`_pycache_bootstrap.py` はリポジトリ直下のまま」を足した。
`tests/run_all.sh` と `tests/visual/run.sh` の起動行も `program/` へ。
