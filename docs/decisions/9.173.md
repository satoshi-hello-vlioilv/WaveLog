# §9.173 測定データのまとめ／分解と、紙のマス数（利用者の指示）

利用者の指示は「今までの縦方向に幅情報、横方向に検査した項目を並べて表示する
方式も残してほしい／使用するグリッドサイズを標準で設定したうえで、各帳票ブロックの
使用グリッドサイズの変更＆組合せができるように／特に測定項目は組み合わせて表示した
方が効率的に面積を利用できるので通常は今までどおり軸を共通にして組み合わせた形、
分解したときに個別内容になるように／グリッド変更時データが入りきらない場合は
選択できるがデータを絞るように絞れる内容を提示する」。

#### 紙の1列＝1つの部品にする

測定データの表を「列の集まり」（`RP_MEAS_GROUPS`）として持ち直した。こうすると
3つが同じ仕組みで書ける。

- **まとめ**（既定・今までの紙）… 条番号を共通の軸にして、選ばれた列を横に並べる
- **分解** … 項目ごとの小さい表になり、1枚ずつ場所と幅を決められる
- **絞り込み** … 「入りきらない」ときに**落とせる単位**が列そのものになる

保存先は増やしていない。列を落とすのも群を分解するのも**同じ`hidden`**で表せる
（列レイアウトマスタの order/hidden/widths だけで足りる）。キーは
`測定列:<群>:<列>`（まとめの中の1列）と`測定データ・<群>`（分解したときの1枚）。

- **まとめに載るか単独で置くかは、単独ブロックが出ているかどうかの1点で決まる**
  ——同じ内容を2箇所に出さない（§9.129）。
- **既定は「まとめだけ」**（`rpInitialHidden`）。列レイアウトマスタのhiddenは空なので、
  そのまま使うと分解した1枚ずつが全部紙に出て、同じ測定値が2箇所に並ぶ（§9.162で
  データ一覧が踏んだ罠と同じ）。
- **触った時点で既定を書き下ろす**（`rpStage`）。`rpHiddenSet()`は「まだ一度も並びを
  保存していない＝既定」で判断するので、orderが空のままhiddenだけ書くと次に読むとき
  また既定へ戻り、**押しても何も起きない**（分解が効かない、で実際に踏んだ）。
- **まとめも分解も同じ関数が書く**（`measTableHtml`）。別々に持つと、片方だけ直した
  状態が作れる。

#### 紙のマス数

`12 / 8 / 6 / 4`。**粗いほど左端がそろう**（§9.135）ので4つだけにしてある。保存先は
列レイアウトマスタの`widths[__グリッド__]`で、幅と同じく`×RP_SPAN_UNIT`して入れる
（40〜900へ丸められるため。§9.169と同じ約束）。

- **各ブロックの幅は12マス基準で保存する。** マス数を変えても意味が変わらないよう、
  読むときに今のマス数へ割り付け直す。
- **幅の選択肢はマス数から作る**（1/4・1/3・1/2・2/3・全幅）。割り切れない刻みは
  近いマスへ寄せ、同じ幅が2つ並ばないようまとめる。

#### 入りきらないときは「何を落とせるか」を出す

**幅は選べるままにする**（利用者の指示「選択できるが」）。その代わり、その場に
落とせる列を並べる（`rp-block-cols`）。

- **判定は描いたあとの実寸で行う**（`rpMarkOverflow`）。列の数や文字数から見積もると、
  表示サイズ・紙の向き・ロットごとの列数で必ずずれる。
- **表だけを見る。** 節そのものを測ると、枠線や余白の丸めで1〜2pxはみ出した扱いに
  なり、入っている塊にまで案内が出る（実際に出た）。
- 案内も落とせる列も**組み換え中しか組み立てない**——CSSで隠すやり方だと、隠し忘れが
  そのまま紙に出る（§9.169と同じ）。

固定は`tests/test_rpblocks.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **測定データの表は「列の集まり」で持つ**（§9.173、利用者の指示）:
  帳票の測定データは**縦＝条番号／横＝項目×丈位置**の1枚（今までの紙）が既定で、
  **項目ごとに分解**もできる。紙の1列を1つの部品（`測定列:<群>:<列>`）にしてある
  ので、①まとめ ②分解（`測定データ・<群>`）③入りきらないときの絞り込み、の3つが
  **同じ`hidden`**で書ける（保存先を増やさない）。**まとめに載るか単独で置くかは
  「単独ブロックが出ているか」の1点で決まる**（同じ内容を2箇所に出さない）。
  **既定は「まとめだけ」**（`rpInitialHidden`）——hiddenが空のまま使うと分解した
  1枚ずつが全部紙に出て、同じ測定値が2箇所に並ぶ。**触った時点で既定を書き下ろす
  こと**（`rpStage`がorderを埋める）——orderが空のままhiddenだけ書くと、次に読む
  ときまた既定へ戻り**押しても何も起きない**（分解が効かない、で実際に踏んだ）。
  **まとめも分解も`measTableHtml()`の1本が書く**（別々に持つと片方だけ直した状態が
  できる）。紙のマス数は`12/8/6/4`で`widths[__グリッド__]`へ（幅と同じく
  `×RP_SPAN_UNIT`。§9.169）。**各ブロックの幅は12マス基準で保存し、読むときに
  今のマス数へ割り付け直す**（マス数を変えても意味が変わらないように）。
  入りきらない判定は**描いたあとの実寸**で、**表だけを見る**——節そのものを測ると
  枠線や余白の丸めで1〜2pxはみ出した扱いになり、入っている塊にまで案内が出る。
  固定は`tests/test_rpblocks.js`。
