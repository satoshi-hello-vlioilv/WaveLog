# §9.230 操業データの盤: 挿入位置・群ごと移動・1マス幅・空きの設定窓（利用者の指示）

「操業データ — 測定画面に出す入力欄と並び」の盤（`op-board`）について4つ。

- ①「ドラッグアンドドロップ操作で位置変更をする際に、群の位置も意識した挿入位置の
   表示をしてほしいです。マウスオーバーの位置がまずどの群の上にいるか、対象となる群に
   挿入位置を表示させてください。」
- ②「右クリックで幅変更のボタンが中途半端で、1/12(1マス)がない。1/12も使いたいので
   追加してください。」
- ③「空きのカードを追加しても、ダブルクリックで編集がでないので、右クリックのメニューが
   最終手段となっており、通常の方法では幅変更や削除などできない。」
- ④「郡単位で移動できるようにしたいです。」

#### ① 落とし先は「カーソルの真下の物」で決め、群を塗って見せる

`opDropAt()`は**段（同じ上端の集まり）に丸めてから**いちばん近い境目を探していた。
群は横にも並べられる（§9.226 ③）ので、**同じ段に隣の群の札が居ると、そちらの境目が
選ばれる**——狙った群に入らない。真下に物があるときは**その物の群の中で**決める
（左半分＝手前／右半分＝次）。段の探索は、札と札のあいだ・盤の余白へ落としたときの
受け皿として残す。

**落とし先の群は塗って見せる**（`.is-drop-group`）。線（`.op-drop-mark`）だけだと、
帯のすぐ上と下のどちらへ入るのかが読めない——**面と文字の2つ**で示す
（吹き出しは今までどおり「置き場／群 へ」）。掴むのをやめたら塗りも消す。

#### ② 幅に1マス（1/12）を足す

設定窓の幅の帯（`opSpanPickerHtml`）は最初から1マスから選べたので、**右クリックだけが
刻みを削っていた**。`OP_TILE_SPANS`へ`1/12`を足す（サーバーの`SPANS`は1〜12なので
保存はそのまま通る）。

#### ③ 空きのカードも同じ設定窓を開く

「空きは決めることが幅だけだから窓を開かない」としていた（§9.228 ②）が、そのぶん
**右クリックが唯一の手段**になっていた。いまは他のカードと同じくクリックで開く。
**決めることが無い段は出さない**（`opTabsFor()`が①どこに出すか・④メモだけを返す）
——押しても何も無い段を並べないという元の判断は、窓ごと閉ざすのではなく段を絞る形で
満たす（§4）。①に「この空き」の行を置き、**削除**と**ふつうの項目へ戻す**をそこから。
切り替えは`opSetPad()`の1箇所を通す——部分的なJSONを送ると`item_upsert`は全列を書くので
**送らなかった設定が消える**（§9.113／§9.212 ②と同じ形）。

#### ④ 帯を掴むと群ごと動く

`.op-band`を`draggable`にし、**帯とその下の札（＝1つの群の塊）**をまとめて挿す。
読み方は`opCollectLayout()`と同じ「帯より下がその群」で、`opGroupBlock()`の1箇所が
答える。道具（幅・名前・畳む）からは掴ませない（`draggable="false"`）——押そうとしたら
群が動く、では押せない。**止まるのは帯の単位だけ**（`opGroupDropAt()`）——群の中の
1枚の前へ群を挿すことはできないので、いま乗っている群の塊の上半分なら前、下半分なら
次の群の前。**カードと群は別の控え**（`opState.drag`／`opState.dragGroup`）で持つ
——1つにまとめると「いま何を運んでいるか」が読めなくなる。

固定は`tests/test_oppad.js`。ヘッドレスではHTML5のD&Dの座標を作れないので、
`WL.opBoard`の口（`dropAt`/`groupAt`/`groupDropAt`/`groupBlock`/`moveGroup`）を
直に呼ぶ（§9.218 ④と同じ）。**「群が横に並んでいるとき」の網は張れていない**
——検証用データでは群幅を6にしても中身の量で段が分かれ、同じ段に2つ並ぶ形を
作れなかった。代わりに「**真下の札の境目に付く**」（左半分＝その札の手前／
右半分＝次）を見る。**素通りを疑うこと**——最初に書いた「その群が落とし先になる」は、
全部が横いっぱいの盤では段の探索でも同じ答えになり、`hit`の枝を潰しても通った。

**並びを崩す網は、APIで控えてAPIで戻すこと**（§9.121）。`opSaveLayout()`は
画面のDOM順をそのままマスタへ書くので、動かしたあと**画面越しに戻すと保存の
往復と描き直しが噛み合わず、中途半端な並びが残る**。実際に「誰が測るか」
「測定表の形」が消えて`その他`になり、群の`[群折りたたみ]`まで落ちて、
**関係の無い`test_msteps`・`test_opui`が落ちた**——`db/master.sqlite3`は実行を
またいで生き延びるので、崩したまま終わると次の実行が引き継ぐ。控えは
`GET /api/operation-item-master`の行と並びごと持ち、後片付けは
`POST /api/operation-item-master/layout`で戻す。
