# §9.289 帳票ブロックの「内訳の列数」が効かない——選択肢12・CSSの規則2（利用者の報告）

利用者の報告:

> 帳票ブロックマスタで調整する列数が全く聞いておらず、5列にしようとしたところ、
> プレビューは2列、紙レイアウトの方のプレビューも2列になってしまいました。

#### ① 何が起きていたか

`帳票ブロックマスタ`の`[内訳の列数]`は**空欄と1〜12**から選ばせる（§9.277で
`CONTENT_COLS_MAX`＝12へそろえた）。ところが**実際に効いていたのは1・2・4だけ**で、
`3`と`5`〜`12`はどれを選んでも既定の2列で並んでいた。

| 選んだ数 | 出ていた列数 |
| --- | --- |
| 空欄 | 2（既定。正しい） |
| 1 | 1 |
| 2 | 2 |
| 3 | **2** |
| 4 | 4 |
| 5〜12 | **2** |

#### ② 原因——列数を「クラスへ焼き込んで」いた

`reportSection()`は列数の運び方を2通り持っていた:

```js
const cls=matrix?'rp-grid rp-grid-m':('rp-grid'+(cols?' rp-grid-'+cols:''));
const st=matrix?` style="--rp-cols:${n}"`:'';
```

- **表として組んだ塊**（マス数・空きマス・見出しを持つ）… `--rp-cols`で渡す（正しく効く）
- **ふつうの「ラベル＝値」の並び** … `rp-grid-5`のような**クラス名**へ数を焼き込む

そして`60-report.css`が持っていた規則は**2本だけ**だった:

```css
.rp-grid{display:grid;grid-template-columns:repeat(2,minmax(0,1fr));gap:0 8px}
.rp-grid-4{grid-template-columns:repeat(4,minmax(0,1fr))}
.rp-grid-1{grid-template-columns:minmax(0,1fr)}
```

`.rp-grid-3`／`.rp-grid-5`〜`.rp-grid-12`は**どこにも無い**ので、クラスは付くが
何も起きず、基底の`.rp-grid`＝2列で並ぶ。**§9.233 ③とまったく同じ形**
——「器の名前で書き分けると、書き足し忘れた側だけが静かに壊れる」。
選択肢が4つだった頃に書いた規則が、選択肢を12へ増やしたときに置き去りになっていた。

**盤の見本も紙も`reportSection()`の同じ1本を通る**（§9.279）ので、
食い違うのではなく**両方そろって2列**になる——だから利用者からは
「設定が**全く**効いていない」としか見えない。

#### ③ 直し方——数を運ぶのは`--rp-cols`の1本だけ

列数を答えるのは`reportSection()`の`n`の1箇所なので、**その1つの数をいつも
`--rp-cols`で渡す**。CSSは変数を読む規則を1本持つだけでよい。

```js
/* 表として組んだ印（§9.282）と列数を分ける。クラスへ数を焼き込まない。 */
const cls=matrix?'rp-grid rp-grid-m':'rp-grid';
const st=` style="--rp-cols:${n}"`;
```

```css
.rp-grid{display:grid;grid-template-columns:repeat(var(--rp-cols,2),minmax(0,1fr));gap:0 8px}
```

**あわせて片付けたもの**:

- `.rp-grid-1`／`.rp-grid-4` … 変数が同じ値を出すので不要（`n`が1なら1列、4なら4列）
- `.rp-grid-m`の`grid-template-columns` … `.rp-grid`と**必ず同時に付く**ので二重宣言だった。
  この印が担うのは「表として組んだ」ことと`dense`だけにする（§9.282の判定に使う印でもある）
- `.rp-block.rp-flow-col`（中の並べ方＝`縦`）の`column-count` … ここも`2`固定＋
  `-1`／`-4`の書き分けで、**5列にしても2段しか作らなかった**。`var(--rp-cols,2)`にする
- `master-maint.js`の`colsEff` … 頭打ちが`Math.min(4,…)`のままだった（規則が1〜4しか
  無かった頃の名残り）。欄の選択肢と同じ12へ

**既に登録してある塊の見え方は1マスも変わらない**——効いていた3通り（空欄＝2・1・4）は
変数でも同じ数を出すし、`3`と`5`〜`12`は**そもそも一度も効いたことがない**。

#### ④ 網が素通りしていた理由——宣言だけを見ていた

§9.279・§9.280でこの欄の周りに網を6本置いていたが、**1本もこの欄を守れていなかった**。
どれも読んでいたのが`--rp-cols`という**宣言**か`className`だったからで、
**CSSに規則が在るか**は一度も通っていない:

```js
const cols=h=>{const d=document.createElement('div');d.innerHTML=h;
  const g=d.querySelector('.rp-grid');
  return g?(g.style.getPropertyValue('--rp-cols')||g.className):'(格子なし)'};
```

`document.createElement('div')`へ入れているので**画面にも付いていない**
——`getComputedStyle`が解けないため、そもそも実際の列数を測れない形だった。

§9.237 ④aの「**宣言値（`<col style>`）だけを見る網は素通りする——描画後の実幅で
見ること**」の再発。新しい網（`tests/test_rpprint.js`の§9.289）は

1. `.rp-page > .rp-block`の中へ**実際に付けてから**
2. `getComputedStyle(g).gridTemplateColumns`の**トラック数を数える**
3. 1〜12を**全部**通す（1つずつ書くと、次に選択肢を増やしたとき同じ穴が空く）
4. `縦`（段組）は`display`がgridでないので`column-count`で数える

欠陥を戻すと`合わない列数: [3,5,6,7,8,9,10,11,12]`で落ちることを確認した。
**「表に組んだ塊」の側は欠陥を戻しても通る**（あちらは元から`--rp-cols`）ので、
どちらの道が壊れたのかも網の出力から読める。

#### ⑤ 教訓

**選択肢の数だけ規則を書く作りにしない。** 語彙が増える側（欄の選択肢）と
規則を書く側（CSS）が別のファイルにあると、増やしたときに片方だけが取り残される。
運ぶのが「数」なら**変数1本**にすれば、選択肢をいくつ増やしてもCSSは触らなくてよい。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **紙の余白は「紙の軸 × 塊の段」の掛け算。フォールバックで代用させない**（§9.313、
  利用者の報告「縦横の余白変更ボタンは別々に機能させたいのに、どちらを押しても両方
  反応して別々に機能してくれません」）: §9.311 Cで`--rp-dense-x`／`--rp-dense-y`に
  分けたのに、CSSは`var(--rp-dense-x,var(--rp-dense,1))`と**フォールバックで**読み、
  塊ごとの自動の詰め（`rpFitBlockBodies`）は`--rp-dense`という**1つの値**だった。
  そのため**紙の軸が「ふつう」＝未設定のとき、塊の段がその軸の値そのものに化ける**
  ——横は触っていないのに、縦を押すと左右の余白が動く（実測: 欄の左右が
  2→1.1→0.5→2）。逆に紙の軸を決めると**段を置き換えてしまう**ので、
  「横＝詰める」を押したのに左右が**緩む**（実測 1.1→1.2）。
  いまは**別の変数**（`--rp-pack`）にして、CSSが`軸 × 段`と掛ける——
  ①紙の軸は軸ごとにそのまま効く ②段は**さらに詰める方向にしか動けない**
  （`Math.min`で気を付ける必要も無くなる）。
  **詰めた結果その塊が紙に入れば段は解ける**（＝もう詰める必要が無い）ので、
  そのときだけ余白は「紙の軸 × 既定」へ戻る——**軸が混ざったのとは別のこと**として
  網も見分ける。**測るのは刷り上がりの寸法**（`--rp-dense-x`が空かどうかを見る網は、
  フォールバックで両軸が1つの値に落ちていても素通りする・§9.289。実際に素通りしていた）。
  **材料は自分で注ぎ込むこと**——中身なりの高さで全部が収まっている紙では
  塊の段が1つも掛からず、**直す前でも3×3すべて分離して見える**（実測）。
  固定は`tests/test_rppack.js`。
- **節の列数は`--rp-cols`が1本で運ぶ。クラスへ数を焼き込まない**（§9.289、利用者の
  報告「帳票ブロックマスタで調整する列数が全く聞いておらず…5列にしようとしたところ、
  プレビューは2列、紙レイアウトの方のプレビューも2列」）: `reportSection()`は
  **表として組んだ塊だけ**`--rp-cols`で渡し、ふつうの「ラベル＝値」の並びは
  `rp-grid-5`のような**クラス名へ数を焼き込んで**いた。ところがCSSに在る規則は
  `.rp-grid`（2列）・`.rp-grid-1`・`.rp-grid-4`の**3本だけ**で、欄が選ばせる
  `3`と`5`〜`12`は**規則がどこにも無く既定の2列**で並んでいた（**§9.233 ③と同じ形**
  ——器や値の名前で書き分けると、書き足し忘れた側だけが静かに壊れる）。
  **盤の見本も紙も同じ1本を通る**（§9.279）ので食い違わず、**両方そろって2列**＝
  「設定が全く効かない」としか見えない。いまは列数を答える`n`の1つを**いつも**
  `--rp-cols`で渡し、CSSは変数を読む規則を1本持つだけ——`.rp-grid-N`は廃した。
  `.rp-grid-m`は**表として組んだ印**（§9.282の判定に使う）と`dense`だけを持ち、
  列数は持たない（`.rp-grid`と必ず同時に付くので二重宣言になる）。
  **「中の並べ方＝縦」（段組）の`column-count`も同じ変数から**——ここも2固定で、
  5列にしても2段しか作らなかった。**選択肢の数だけ規則を書く作りに戻さないこと**
  （語彙が増える側とCSSが別ファイルだと、増やしたときに片方が取り残される）。
  **網は宣言を見ないこと**——§9.279・§9.280の6本は`--rp-cols`の**宣言値**か
  `className`しか見ておらず、しかも`createElement('div')`の中で測っていた（画面に
  付いていないので`getComputedStyle`が解けない）ため、**1本もこの欄を守れていなかった**
  （§9.237 ④aの再発）。実際に`.rp-page`の中へ付けてから
  `gridTemplateColumns`のトラック数を数え、**1〜12を全部通す**（1つずつ書くと、
  次に選択肢を増やしたとき同じ穴が空く）。固定は`tests/test_rpprint.js`の§9.289
  （欠陥を戻すと`合わない列数: [3,5,6,7,8,9,10,11,12]`で落ちることを確認済み）。
