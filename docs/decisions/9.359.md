# §9.359 画面のJSを全部閉じた。土台は「短い名前のまま、明示的に公開する」

REVIEW 3-17 の残り4本（`measure-input`／`measure-view`／`records-store`／
`base`）を一度に閉じた。利用者の指示:「**3-17はある意味のリスクなので
一気に実施をお願いします。**」——**半分だけ閉じた状態がいちばん危うい**。
規約が2つ混在し、`typeof` のガードが残ったままになる。

結果、**画面のJS 32本すべてが閉じた**（開いたままのファイル 0）。
`no-undef` は各段で 25／64／74／144 出て、いずれも 0 まで直した。

## 外へ出す面

| ファイル | 面 | 個数 |
| --- | --- | --- |
| `measure-input.js` | `WL.measureInput` | 15 |
| `measure-view.js` | `WL.measureView` | 31 |
| `records-store.js` | `WL.records` | 49 |
| `base.js` | 短い名前18個（`window.X=X`）＋ `WL.base` 35 | 53 |

`base.js` だけ扱いを変えた。`$` は**1,031箇所**・`esc` は**1,464箇所**あり、
`WL.base.$()` へ移すと読みにくくなるだけで、得るものが無い——**衝突は
起きようがない**（このファイルだけが名乗っている）。**短い名前のまま、
どれを公開しているかを1箇所で宣言する**のが、この土台の正しい閉じ方。
使う場所が少ないもの（35個）は「土台ではない」ので `WL.base` へ。
残る約80個は、ファイルの中だけのものになった。

`test_globallint` の `window.*` 上限は 63→79。**増えたぶんは意図した公開**で、
上げてよいのは「閉じた結果として公開を宣言した」ときだけ、と網に書いた。

## 閉じたから見つかったもの

- **死んだコードが2つ**。`measure-input` の `stat()`（§9.214 で表を解体した
  ときに呼び出しが消えていた）と、`measure-view` の `qualityGradeFields`
  （12行の配列）。後者は**コード中のコメントに既に「読まれていない死んだ
  配列」と書いてあった**——グローバルのあいだは「外の誰かが読んでいるかも
  しれない」と言い切れず、断り書きを添えるしかなかった。閉じると証明できる。
- **公差の提供者が1つ、丸ごと登録されなくなっていた**。`measure-tolerance.js`
  が `typeof compactToleranceFacts!=='function'` で早期 return しており、
  閉じた瞬間に「指示型（単一の指示値）」が消えて3つが2つになった。
  **`no-undef` は `typeof` を報告しない**ので、eslint が0件でも壊れている
  （§9.355 と同じ形。1本目は列の設定パネルが黙って開かなくなった）。
- **網が3つ、関数を被せていた**（§9.352 が禁じている形）。`activeRequiredControls`
  ・`reliablePut`・`reliableAll`。閉じると外から差し替えられないので、
  `WL.measureHooks.own` の口を通す形へ直した。あわせて登録表に足りない物を
  2つ入れた: **①返上**（`own(name,null)`。返上できない登録表は後始末ができず
  次の網へ漏れる・§9.121）、**②核の公開**（`reliableAllCore`等。`own` は
  丸ごと持つので、元へ委譲する口が無いと「数える」「遅らせる」が作れない）。

## 手順として残すこと

1. **同名のローカル宣言を持つファイルは書き換えない。** 3件見つけた
   （`filters.js`・`measure-opdata.js`・`test_scale.js` がいずれも自前の
   `collect()` を持つ）。**確認は必ず書き換える前の内容に対して**——
   書き換えた後に調べると宣言そのものが書き換わっていて検出できない
   （実際に取りこぼし、構文エラーで気づいた。`git show HEAD:<file>` で見る）。
2. **`let` の入れ物は getter で載せる。** 値で載せると古い物が固定される
   （`equipmentMasterState` は丸ごと差し替える箇所がある）。**外から書く
   ものは setter も要る**（`measureDirty` は `records-store` が false に倒す）。
3. **書き換えは「`name(`」と「`typeof name`」だけでは足りない。**
   状態オブジェクト・定数・関数参照渡し（`.map(ensureMeasureShape)`）が残る。
   書き換え → `no-undef` → 残りを直す、を繰り返す。
4. **eslint は `tests/` を見ない。** トップレベル名を取り出して tests/ 側と
   突き合わせる手順が別に要る（`processDeviceInput` 等をこれで見つけた）。

## 分かったこと（先に誤って説明した）

`base.js` の `esc=v=>…` を「宣言の無い代入」だと読み、strict モードでは
例外になるはずなのに動くのはなぜか、を長く追った。**誤りだった**——21行上の
`const api=async(u,o)=>{…},` から続く**宣言リストの一部**で、`esc` は
ふつうの `const` である。`window.esc` が無いのに `typeof esc` が `function`
だったのも、**トップレベルの `const` はスクリプトスコープの束縛で `window`
には載らない**からで、すべて筋が通る。`node --check` の構文エラーが教えた。
**「動くはずがないのに動く」と思ったら、まず自分の読み方を疑うこと。**
