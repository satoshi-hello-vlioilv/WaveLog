# §9.497 update.bat は版を最初に言い、作り直せる古いデータを片付けてから確かめる（利用者の指示）

索引: [決定記録](README.md)

## 経緯

利用者の指示:
- 「古いデータ(一時ファイルたち)をアップデートで一旦消して、作り直した方が良い気がしています。」
- 「update.batでアップデートの版の表示追加と、古いデータの処理など、そのあたりの処理はできませんか？」

## 見立て

今回の2件（§9.495 共有の元に届かない・§9.496 ショートカットが作れない）は、**古いファイルが残っていたせいではない**
（どちらも作りの誤り。片付けても直らなかった）。それでも、更新の区切りで作り直せる物を一度消すことには値打ちがある:
消し忘れた古い世代・書きかけ・前の版の部品が溜まらない／「古い物を見ているのでは」を疑う手間が減る。
§9.249 の掃除（`file_cleanup`）が既に「消えても取り直せる物だけ」を種別ごとに持っているので、**新しい規則は作らず**
その1箇所を使う。

## 決めたこと

1. update.bat（`setup_app.py`）の画面の頭に**アプリの版**を出す（`ready.version_note()`の1箇所）。比べる相手は前回の刻印:
   「VER2.384.0（前回の確認は 2.381.0 → 今回 更新しました）」／「（前回の確認と同じ版です）」／「（この端末で初めての確認です）」。
2. 確かめる前に**作り直せる古いデータを片付ける**（`file_cleanup.run_for_update()`＝全種別）。自動では消さない種別
   （バイトコード・使われていない作業フォルダ・起動の部品）も含める。バイトコードは直後の事前コンパイルが、待機画面の
   写しは直後の写し直しが作り直す。画面には1行（件数・容量）、種別ごとの内訳は記録（launcher.log）へ。
3. 種別「起動の部品」（`runtime`）を足した: 補助スクリプト・次の起動用の待機画面・起動の進捗・書きかけ。置き場は
   `runtime_dir()`と`browser_dir()`（§9.496）。**残す物**: 起動前確認の刻印・起動中の印・いまの待機画面・
   **ショートカットの絵**（デスクトップのショートカットが指していて、作り直すのは作るときだけ——消すと白紙になる。
   網を先に書いて気づいた）。
4. 本物のデータ（マスタ・測定データ・共有スケジュール・設定・ログのいま書いている分）は`file_cleanup`から見えない
   場所にあり、触らない（§9.249 の線引きのまま）。
5. 更新の片付けは**ログへ書かない**（`run(log=False)`）。update.bat の画面は結果だけ（§9.431）——アプリのログの行が
   画面へ混ざっていた。

## 測った（`tests/test_cleanup.py`）

| 物差し | 前 | 後 |
| --- | --- | --- |
| 作り直せる起動の部品を数える | 種別が無い | 8件（2つの置き場×4） |
| 更新の片付けで残る物 | 片付けが無い | 刻印・起動中の印・待機画面・絵だけ |
| 更新の片付けでバイトコード | 消えない（自動では消さない種別） | 消える |
| 版の1行 | 出ない | 前回の版と今回の版を言い分ける |

## 網の誤り（直した）

足した節を置き場の差し替え（`patch()`）の外に置いていたため、最初の実行でこの作業環境の本物の置き場
（作り直せる物）を片付けた。節を差し替えの中へ入れ、アプリの置き場（`__pycache__`を拾う）も一時の置き場へ向けた。

## 追補（2026-09-25）: update.bat は`db_access`を読み込まない

**追補1（`4d23e11`）・追補2（`5bd6df5`）の経緯**: CIのまっさらな取得で、update.bat の画面に
「データソースマスタに役割「仕掛」の行がありません…」という時刻つきの警告が1行混ざった。追補1で片付けの
`_db_dir()`が`db_access`を読み込む道を塞いだが、同じ警告はまだ出た。追補2では道を1つずつ塞ぐのをやめ、
ロガーの側で画面へ出すのを止めた（`logging_setup.console_off()`）。ここまでの決定記録は無く、コミットのメッセージだけにあった。

**追補3（見直しで見つけた）**: 追補2は**画面に出る症状を隠しただけ**だった。片付けは決まり（残す日数・世代）を
`_cfg()`→`db_access.path_config_value()`で読んでおり、`db_access`は読み込んだだけで`master_share.configure()`を呼ぶ。
マスタを共有に置いた現場では、update.bat のたびに**共有のマスタを丸ごと写しへ取り込み直していた**（`_pull(force=True)`）。
update.bat は起動中のアプリを確かめないので、そのとき写しへ錠なしで上書きし、アプリの書込と競り得た（起きる時間の幅は狭い）。
あわせて、update.bat のたびに共有との往復が1回入っていた。

**決めたこと**: アプリの外から設定を読む道を、**読み込んでも何も起きない**ところへ置く。
- 設定どおりのマスタの置き場は`paths.master_db_file()`の1箇所（`db_access`もこれを使う）。`resolve_db_file`・
  `resolve_local_db`も`paths`へ移した（`db_access`は再公開するだけ）。
- 共有なら手元の写しを開く、という見立ては`master_share.local_path_of()`（取り込まない・状態を書き換えない）。
  `configure()`も同じ見立て（`_mirror_of()`）を通る。
- パス設定マスタの表の読み方は`path_config`の1箇所（`rows()`／`read()`／`value()`）。`db_access`の`path_config_rows`・
  `PATH_CONFIG_TABLE`・`_master_path_config()`はここを呼ぶ。接続は必ず閉じる（前は`with connect()`で閉じていなかった・§9.270）。
- 片付けの`_cfg()`は`path_config.value()`を読む。

| 物差し（`test_cleanup.py` の 10・新しいプロセスで片付けを回す） | 前 | 後 |
| --- | --- | --- |
| `db_access`を読み込む（共有・手元） | する・する | しない・しない |
| 共有のマスタを取り込みに行く回数（共有に置いた形） | 1 | 0 |
| 掃除の決まり（残す日数）をパス設定マスタから読む | 読む（14＝この環境の値） | 読む（9＝網が置いた値） |

`console_off()`（追補2）は残す——update.bat の画面は「結果」と「次にすること」だけ（§9.431）という約束はそのままで、
ほかの道から記録が混ざることへの守りになる。

**あわせて直した（同じ見直し）**:
- 「使用中の N件は次の掃除で消えます」は、定期の掃除で消さない種別（作業フォルダ・起動の部品・バイトコード）を含むときは正しくなかった。
  1文は`file_cleanup.failed_note()`の1箇所（update.bat の画面と掃除の画面の`lastError`が同じ1文）。含むときは
  「次の update.bat か、不要ファイルの掃除の「選んだものを掃除する」で消えます」。
- 版の1行（`ready.version_note()`）は版が**下がった**ときも「更新しました」と言っていた。下がったときは「前の版に戻っています」、
  上がったときは「更新されています」（ファイルの事実。確認の結果より前に出る1行なので「しました」と言い切らない）。
