# §9.514 仕掛から消えたロットは完了側へ・実際の時刻は人に入れてもらう（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「作業スケジュールのデータの中で仕掛からなくなったものは基本的に作業完了しているので、このアプリで完了させて
いなくても、基本的に完了側にデータを移行するようにしてください。仕掛にないロットや時間的に完了したであろう
設備停止は、色を変え、ユーザーに登録を促し開始時間だけ(この場合は登録済みの時間を適用する)もしくは開始時間と
終了時間を入力(ワンクリックでも入れられるような入力補助をいれ、分単位でできるだけ簡単に入力できる仕組みを
入れること)させるようにしてください。(過去の履歴から修正も可能にしてください)」

「操作のところに完了フラグや登録を促すボタンを入れたいです。もっと良い方法やバランス的により良い配置があれば
遠慮なく提案してください。」

案を3つ出し、利用者の選択は: 配置「札＋ボタン1つ」／設備停止の判定「後ろの作業が始まったら」／履歴「時刻の修正だけ可」。

## 測った（評価関数・直す前）

`test_actualmatch.py` の 5)・8) を**先に書いて**直す前に回した（直す前 26/38・12件未達）。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 仕掛から消え、突合先にも無いロットの状態 | **着手**（「〜継続中」のまま居座る・いつまでも完了にならない） | **完了**（時刻未登録と名乗る） |
| 時刻が分からない済んだ行が「時刻未登録」と名乗るか | 0（灰色の「仕掛落ち」だけ） | 名乗る（時刻の列に橙の字「時刻未登録」・行の地と左の帯） |
| 時刻未登録の行の並び | 末尾（予定の後ろ・完了なのに予定より下） | 完了側の最後（これから並ぶ行の直前） |
| 後ろの作業が始まった設備停止 | **予定のまま**（毎回「いまから」並び直す） | 完了（時刻未登録） |
| 実際の時刻を入れる口 | **無い**（400） | 開始だけ（見積で終わる）／開始と終了 |
| 登録した行が段「履歴」に出るか | **出ない**（予定のままの行は履歴に入らない） | 完了・設備停止として時刻つきで出る |
| 履歴から直せるか | **できない**（見るだけ） | 手で入れた時刻だけ直せる |
| 押す回数（候補で良いとき） | — | **2回**（時刻を入れる→登録する） |

## 決めたこと
- **§9.364・§9.462の「着手（作業中として扱う）」を撤回**。仕掛から消えた＝作業は終わっている、として完了にする
  （`_apply_actual_source()`）。開始時刻の無い作業中の行が居座り、後ろの予定を押し続けていた。
- **設備停止**: 後ろの作業が始まった（着手・完了）なら、その前の停止は終わっている。開始を固定した停止は、
  固定した開始＋見積が過ぎたら終わっている（`_settle_passed_stops()`・並びの後ろから1回で数える）。
- 人が確かめる前に完了とみなした行（`autoDone`）で時刻が1つも無ければ`timesNeeded`。理由の本文は`doneReason`、
  入力の手がかりは`timesHint`（開始の候補と出どころ＝前の行の終わり／完了突合の完了日時−見積／固定した開始・見積の分）。
  答えは`_times_prompts()`の1箇所。
- **保存は予定の行の1列**（`[手入力実績JSON]`・開始・終了・終わりの出どころ・誰が）。**測定データの実績とは別の欄**。
  登録で**状態も完了にする**（人が確かめた完了を、仕掛に戻っても黙って予定へ戻さない）。
  「開始だけ」は**登録した時点の見積**で終わりを決めて残す（`endFrom=見積`）。検めるのは`manual_payload()`の1箇所
  （分に丸める・終わりが始まりより前・未来の開始を断り、直し方を言う）。口は`plan/update`（ルートは増やさない）。
- 画面（利用者の選択「札＋ボタン1つ」）:
  - **時刻の列が橙の字で「時刻未登録」**（色だけにしない）、行は完了の薄さを打ち消して淡い橙の地と左の帯。
    並びは**完了側の最後**（これから並ぶ行の最初の時刻の直前を借りる・日付でまとめても「日付未定」の箱を作らない）。
  - 操作の列に**「時刻を入れる」1つ**（入れられる端末だけ・§CLAUDE 4）。行のダブルクリック・右クリック「進める」でも開く。
  - 知らせの棚に「N件の実際の時刻が未登録です」と**「順に入れる」**（やめたら止まる）。
  - 窓（`WL.scheduleTimes`の1つ・予定の画面と履歴が共有）: 開始の候補が入り、終わりは「見積で終わる」が選ばれている
    ＝**押すだけで登録**。−5分／＋5分／今・開始＋見積、所要と見積との差をその場で出す。欄は分まで。
  - 登録後は時刻の列に時刻と**鉛筆の印（手入力・出どころ）**。直すのは右クリック「実際の時刻を直す」・段「履歴」の「時刻を直す」。
- **完了の印（チェック）を押させる案は採らなかった**: 完了は自動で移るので押す物が要らず、押す物を2つ並べると
  次の1手が2つになる（§CLAUDE 2）。

## 踏んだ罠
- 最初は区分の列に札（「時刻未登録」「手入力」）を足したが、**「完了」と並ぶと幅に入らず切れた**（1728pxで実測・
  「時刻…」「手入…」）。時刻が無いこと・時刻の出どころは**時刻の列**が言う形に移した。
- 時刻の無い行は並べると**末尾へ落ちる**（予定の後ろに「完了」が並ぶ）。完了側の最後へ置く時刻を借りる。
- `WL.scheduleView`へ`entries()`を足したら、同じ働きの口が既にあった（`test_eslint`の重複キー）。既存の口を使う。

  開始だけ（見積で終わる）／開始と終了／前後逆は断る／履歴に時刻つきで出る・直せる
