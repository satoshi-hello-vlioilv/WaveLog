# §9.408 刃組スケジュール一覧から刃組ガイダンスへ入れる／標準の計算値を出す（利用者の指示）

## 利用者の言葉

> 刃組スケジュール一覧からも刃組ガイダンスに行けるようにしてください。
> **刃組メインのスケジュールなのに刃組ガイダンスに行けないのは微妙です。**
> 刃組の標準の計算値で**使用スペーサなど一覧内に関連情報が出る**ように
> してほしいです。

## ① 行き先が無かった

刃組スケジュール一覧（§9.383）は**同じ予定を段取りの側から見る**段で、行は
「刃組の停止」1つずつ。ところが**そこから刃組ガイダンスへ入る的が無く**、
入るにはいったん個別のタイムラインへ戻って行のチップを押す必要があった
（段取りを見ている人が、段取りの道具へ最短で入れない）。

行き先の的は**題名の横に別に立てる**（§9.377 と同じ作法）。押すのは
タイムラインのチップと**同じ `openRowLink()`**——開けない理由の言い方を
2つ持たない。

## ② 「未記録」しか出ない表だった

記録（`刃組履歴マスタ`）が無い段取りの部材欄は、全部「未記録」と書いていた
（空欄＝0に見せない・§9.231）。**嘘は無いが、読む人の役に立たない**——
これから組む段取りこそ「何を何本用意するか」が知りたい。

**標準どおり組んだときの値は計算できる。** 刃組ガイダンスが画面を開いたときに
出しているのと同じ計算（`solve()`＋`snapshot()`）を、画面を組み立てずに通せば
よい。実際に出た値（検証用フィクスチャ・条4×280mm／板厚1.6）:

| 欄 | 見込み |
| --- | --- |
| スペーサー | **14種 68本** |
| 板押さえ | ゴムリング |
| クリアランス | 0.16（板厚の10%・§9.378） |
| 刃径 | Φ318.2 |
| 条数 | 4 |

## 計算の既定を1箇所へ寄せた（`blade-core.js`）

計算を借りるには「**標準の条件**」が要る。これは今まで**画面だけが持って**
いた:

| 今までの置き場（`blade-view.js`） | 移した先（`blade-core.js`） |
| --- | --- |
| `const st = {…}` の既定値リテラル | `defaultState()` |
| `applyStandards()`（基準値→既定値） | `applyStandards(st, M)` |
| `applyBladePick()`（刃の選び方） | `applyBladePick(st, M)` |
| `clearanceRate()` / `clearanceFor()` | `clearanceRate(M)` / `clearanceFor(M, t)` |
| （無かった） | `standardState(seed, M)` |

画面は**それを呼ぶ薄い口**になった。書き写して2箇所に置けば、一覧の
「使用スペーサー」と刃組ガイダンスの刃組表が**静かに食い違う**。

### ついでに直った順序の食い違い

刃の選び方（`刃選択マスタ`・§9.379）の条件は**板厚・条数・幅**なのに、画面は
**材料を当てる前**に1度だけ選んでいた（`loadContext()`の中で、既定の
板厚1.3・見本のロットのまま）。予定から開いても、当たる行は既定の材料で
決まっていたことになる。`standardState()` は**材料を当ててから選ぶ**ので、
画面側も予定を当てた直後に `applyBladePick()` を呼ぶ順へそろえた。

## 出どころを必ず書く

同じ表に**記録（組んだ事実）と見込み（これから）**が並ぶので、取り違えると
「もう組んだ」と読める。3つを字で書き分ける:

| 状態 | 状態の欄 | 部材の欄 |
| --- | --- | --- |
| 記録済み | `記録済み` ＋ 時刻 | 記録の値（本文の濃さ） |
| これから（計算できた） | `これから` ＋ **標準の計算値** | 見込みの値（一段薄い字・`title`に出どころ） |
| これから（計算できない） | `これから` ＋ `計算できず`（`title`に理由） | `未記録` |

**台車と刃セットは見込みを出さない**——計算で決まる値ではなく、組むときに
人が選ぶもの。これを混ぜると「計算した値」と「まだ決めていない値」が同じ顔で
並ぶ。字は `未定`（`title`に「刃組ガイダンスで選び、確定保存すると記録されます」）。

**計算できないときは既定の見本で埋めない**（§9.231）。条が1本も読めない
（次に切る材料が予定から読めない）ときは `null` を返し、理由を字で出す。
既定のロット（LOT1×4）で計算すると、**予定と何の関係も無い数字**が
「使用スペーサー」として並ぶ。

## 取りに行く回数

- **刃組マスタは設備ごとに1回**（部材の登録を直すのは稀）。段を開くときに
  記録と**同時に**取りに行く（直列にすると段の切り替えが遅い）。
- 「再計算」を押したときは**両方とも取り直す**——押した人が期待しているのは
  「いま分かることを全部見直す」こと（§9.200）。
- 予定が差し替わったら刃組の表も描き直す（`applyPlanResult`）。でないと、
  行を足しても並べ替えても**刃組の表だけ古いまま**残る。
