# §9.395 帳票を1)〜6)に連動させる（利用者の指示）

利用者の指示（原文）:

> **７）１）〜６）の対応により帳票の連動が必要な部分はフレキシブルに対応し
> 連動して正しく表示・非表示するように改修してください。**

§9.389〜§9.394 でした改良のうち、**紙に響くところ**をここでまとめる。
指示の1件目〜6件目の中で紙へ届いたものは各記録にも書いてあるので、ここは
**「紙の側の決まり」**だけを持つ。

## 1. 紙で守る決まりは1つ: **「無いものは出さない。あるものは消さない」**

| もと | 紙はどうするか |
| --- | --- |
| §9.390 内訳の2段目 | 予定表の札は「1段目 / 2段目」の1枚（`nonWorkSubText()`が画面と紙の共通の1本） |
| §9.391 母材／丈毎 | **丈別データは今までどおり出す**（下の §3） |
| §9.392 設備ごとの入力内容 | **外した項目は紙からも落とす。ただし値があれば出す**（下の §2） |
| §9.393 外観・巻ズレ | **書いた列だけ出す**（§9.393 §5） |
| §9.394 手入力の基準 | **道（`calc.manualLimit`）を足す**（下の §4） |

**「あるものは消さない」が効く理由**は§9.107と同じ。設備の設定を変えたあとに
古いロットを刷ると、**測った値が紙から消えてしまう**——紙は手元に残り、
あとから根拠を確かめる相手が居る。

## 2. 設備で外した入力内容は紙からも落ちる（値が無ければ）

判定は `rpItemOff(x,name)` の**1箇所**——「設備マスタで外してあり
（`settings.measureItemsOff`）、かつこの記録に値が1つも無い」。節ごとに
書くと、片方だけ消える紙ができる。

当てる先は4つ:

- まとめの測定データ（`widthMeasurementSection`）… 群を落とす
- 1枚ずつの測定データ（`measSoloSection`）… 節ごと出さない
- 板厚の測定データ（`rpIsDimensional`）
- 母材実績／カード指示

## 3. 丈別データは「面が分かれても」今までどおり出す

§9.391 で `rpShowProduct()` を `isMaterial` → `isPiece` にしたが、**戻した**。

**「最大」で刷る白紙の控え欄が出せなくなる**（§9.132／§9.309。丈の表を
空欄のまま刷って手で書く現場がある）。`isPiece` だけにすると、母材を選んだまま
完了したロットで枠ごと消える。**触っていない現場の紙を勝手に変えない**ほうを
採る。

`tests/test_rpmaster.js` がこれを捕まえた——丈を書いていない記録で
「丈別データ」が紙から消え、**4件が赤**になった。

## 4. 踏んだ罠: **コードへ行を足しても紙は変わらない**

手入力の基準（§9.394）を `測定条件` の塊へ足そうとして、コード側の行に
書き足した。**紙は1行も変わらなかった。**

理由は §9.278 の決まり——**マスの並びがあれば、それが紙の正**。`測定条件` は
帳票ブロックマスタに種（`登録設備=calc.equipment` …）を持つ塊なので、
紙はマスタの並びを出す。コードの行はそこで捨てられる。

**足す先は「道」**（`calc.*`）:

- `calc.manualLimit` … 手入力の基準（`ラテラルボー 0〜2.5（手入力）`）。
  **出どころを添える**（§CLAUDE 6）——同じ「0〜2.5」でも、仕掛から引いた
  基準と人が打った基準では当たる見込みが違う。
- `calc.measureType` … 入力内容を**今の名前**で（旧名`母材/丈毎`→`母材`）。

道の一覧（`CALC_CATALOG`）と見本（`SAMPLE_VALUES`）は**サーバーが持つ**
（§9.163）。`測定条件` の種にも「手入力の基準」を1行足したので、**新しく
作った現場では最初から紙に出る**——既にある現場は盤から置ける（それが
利用者の言う「フレキシブルに」）。

**紙のどこへ置くかは現場が決める**ので、網が見るのは「**道が答えるか**」
（`WL.reportBlocks.calcFor()`）。紙のマスの位置を網で固定すると、
盤で組み替えた現場で落ちる。

## 5. 固定した網（`tests/test_rpblocks.js`）

1. 設備で外した入力内容（バリ）は紙の測定データから落ちる
2. **外してあっても値が入っていれば出す**（記録を消さない）
3. 手入力の基準は道が出どころつきで答える
4. 入力内容の道は今の名前で答える

**欠陥注入で確かめた2件**:

1. `rpItemOff` から値の確認を外す（常に伏せる）→ 2 が赤。
2. まとめの測定データから群の絞り込みを外す → 1 が赤。
