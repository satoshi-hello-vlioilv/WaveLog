# §9.107 データ一覧: 「無い」と「見せてもらえていない」を言い分ける

実機からの報告: **「編集中データ一覧をスケジュールモードで開くとデータが
あるのに見えない形になります。データはあるけど見えないではなく、権限が
ないので見えないという正しい事実を理解できるような表示表現にしてほしい。」**

#### 何が起きていたか

edit以外のモード(閲覧・スケジュール)では、データ一覧が読むのは
**共有された閲覧用データ**(`records_backup_export_path`へ複製した
`records.sqlite3`、§3.5)だけで、この端末のIndexedDBにある編集中データは
読まない。その端末では測定データを書かない前提だからで、これ自体は設計
どおり。

問題は**そのことが画面のどこにも書いていなかった**こと。0件になると
一覧は`renderRecordListRows()`の既定文言

```
表示できるデータがありません。
```

だけを出す。手元に編集中データがある人がこれを読めば、**保存したものが
消えた**と受け取る。実際そう報告された。文言が「無い」と断言している以上、
利用者の読みのほうが正しい。

#### 直し方: 事実を数えて、そう書く

表示の責任を2つに分ける。

- **一覧の描画は`records-store.js`が1箇所で持ち続ける**(関数の定義は1箇所)
- **理由の文言は開いた側(`access-mode.js`)が渡す** ——
  モードの判定・編集権限の有無・端末内の件数を知っているのはあちらだけ

受け渡しは`recordListState`の3つの欄で、`openRecords()`(編集モードの
経路)が**開くたびに必ず消す**。消し忘れると編集モードに戻ったあとも
「このモードでは開けません」と出続ける。

| 欄 | 何を入れるか |
|----|----|
| `notice` | 一覧の先頭に置く帯。出どころと、切り替えの導線 |
| `emptyHtml` | 0件のときの本文(絞り込みで0件のときは従来どおり) |
| `sourceNote` | ヘッダーの副題。「共有された閲覧用データ（読み取り専用）」 |

**端末内の件数は`reliableAll()`で数える。** 「編集中2件・完了1件が
保存されていますが、このモードでは開けません」と書けて初めて、
「無い」ではなく「見せてもらえていない」が伝わる。数えられなかったときは
件数の文を落とす(0件と言い切らない)。

**0件の理由は3つに分ける。** 打つ手が違うため一緒にしない。

| 理由 | 何が起きたか | 打つ手 |
|----|----|----|
| `unconfigured` | 閲覧用データの置き場が未設定 | パス設定マスタを設定する |
| `error` | 置き場はあるが読めなかった | 共有・接続を見る |
| （空） | 読めたが該当が無い | 本当に0件 |

判定は**文言ではなく印**で行う——`loadViewModeRecords()`が投げる例外へ
`err.code='unconfigured'`を付ける。文言で判定すると、文言を直した瞬間に
黙って壊れる。

#### 切り替えの導線は「押せば変わる」ときだけ出す

帯の中の「編集モードへ切り替えて表示する」は`accessMode.canEdit`が真の
ときだけ描く。**偽のときはボタンを出さず、代わりにログインID・PC名を添えて
「この端末には編集権限がありません」と書く**——押しても何も変わらない
ボタンほど分かりにくいものはない。ボタンは一覧を描き直すたびに作り直される
(絞り込み・並べ替えのたび)ので、配線は**委譲で1本**にする。

**同じボタンを2つ出さない。** 帯と0件の本文の両方に置くと、1画面に同じ
ボタンが並ぶ。導線は帯が持ち、0件の本文は理由だけを書く。

固定は`tests/test_recperm.js`（案内の有無・件数・理由の3分岐・導線を
押したら編集モードへ戻って手元のデータが出ること・**編集モードの0件は
従来どおりの素直な文言のまま**であること）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **データ一覧の「0件」は「無い」とは限らない**（§9.107）: edit以外のモードでは
  一覧が読むのは**共有された閲覧用データだけ**で、端末内の編集中データは
  読まない。以前は0件のとき「表示できるデータがありません」とだけ出しており、
  **手元にあるのに消えたと受け取られた**（実機で報告）。**描画は
  `records-store.js`が1箇所で持ち、理由の文言は開いた側（`access-mode.js`）が
  `recordListState`の`notice`/`emptyHtml`/`sourceNote`へ渡す**——モード・
  編集権限・端末内の件数を知っているのはあちらだけ。件数は`reliableAll()`で
  数え、**数えられなければ件数の文を落とす**（0件と言い切らない）。0件の理由は
  「置き場が未設定」「読めなかった」「該当が無い」の3つに分け、**判定は文言でなく
  `err.code`**（文言で判定すると文言を直した瞬間に黙って壊れる）。
  切り替えボタンは`accessMode.canEdit`のときだけ出し、無いときは
  ログインID・PC名を添えて権限が足りないと書く。**同じボタンを帯と0件本文の
  両方に置かないこと。** `openRecords()`は開くたびに3欄を消す（消し忘れると
  編集モードでも案内が出続ける）。固定は`tests/test_recperm.js`。
