# §9.88 一覧の見せ方(列の並び・幅・表示名・書式)

設計の全体像は **`docs/COLUMN_PRESENTATION_DESIGN.md`** にある(要望7件を
「列の見せ方」と「一覧全体の見せ方」の2つの器へ畳んだ経緯、画面案、作業順)。
ここには実装で決めたことだけを残す。

**マスタは2つ。** `列レイアウトマスタ`(1行=1対象の1列: 表示名・表示順・幅・
表示・書式)と`一覧表示設定マスタ`(1行=1対象: 行間)。対象(target)は
`list:<DBキー>:<テーブル>` / `timeline:<設備名>` のスコープ文字列。
**行が1件も無い対象＝未設定＝既定の見せ方**(他マスタと同じ互換ポリシー)。

**同一性はデータ側の実カラム名。** 表示名を変えても設定は追随する。
記録に無い列は末尾へ回し、記録にあってデータ側に無い列は黙って捨てるので、
**データ側の項目が増減しても設定は壊れない**(`WL.columnLayout.apply()`)。

**保存は全置換。** 対象ごとに行を消して入れ直す。したがって
**触っていない設定も一緒に送らないと消える**。見出しのD&Dで並びだけを
送っていたため、並べ替えると表示名が消える不具合が実際に出た
(`bindColumnHeaderTools`の`persist()`)。サーバー側も、並び(order)に載って
いない列でも幅・表示名・書式・非表示のどれかが指定されていれば行を残す
(`set_column_layout`。片方だけ拾う実装だと、その設定だけが黙って消える)。

**整形は画面側だけで行う(段3)。** サーバーは生の値を返し、`WL.cellFormat`が
表示直前に整える。並べ替え・絞り込みを生の値で効かせたままにするため。
- 数値: 小数桁で丸め → 3桁区切り → 単位を前後に添える
- 日付時刻: `yyyy/MM/dd HH:mm` 形式のパターン。日=`d` 月=`M` 時=`H` 分=`m` と
  大文字小文字で区別する(Excelの「文脈で月か分か決まる」は説明できないので
  採らない)。`'リテラル'`で囲んだ文字はそのまま出る
- **整形に失敗したら生の値を出す。** 空欄になるより値が見えるほうがよい
  (現場で「データが消えた」と判断されるのが最悪)。数値として読めない値、
  日付として読めない値、**日付を持たない値に`yyyy`を要求した場合**が該当する
- 空欄は空欄のまま(単位や`0.00`だけが並ぶ列にしない)

**列の設定パネルは共通のフローティングウィンドウで出す**(`WL.makeFloatingWindow`、
§9.16)。位置と大きさを与えられないと、パネルは中身(プレビューの列数)の分だけ
横に伸びて画面外に開き、実質操作できなくなる(実際に起きた。公開漏れで
`typeof makeFloatingWindow==='function'`が常に偽になっていた)。

**読み替え(段4)は書式より先**。読み替えは生の値を見て判断するので、
'00'を'0'へ整形してから読み替えると当たらない。1つのセルが表示されるまでは
`生の値 → 読み替えが当たればその言葉で確定 → 当たらなければ書式 →
整形できなければ生の値` の順で固定してある(`WL.cellFormat.cell()`)。

**読み替えのルールは列に属さない**(`表示ルールマスタ`)。ルール名でまとめて
登録し、列側は名前で参照する——列に紐づけると「00→なし」を列の数だけ
書かせることになる。1行=1つの読み替えで、**表示順の上から見て最初に
当たったものを採用**する(Excelの条件付き書式と同じ。この1文以上の説明が
要らないことが大事)。行の中の条件はAND、**行同士がOR**と決めてある
(「ORもANDも1画面で」は組み合わせが爆発して、作った本人にも読めなくなる)。
条件が空の行は「どれにも当てはまらなかったとき」の既定。
左辺には他の列を選べるので「区分が3のときだけ○○と出す」が書ける。

壊れた入力への方針も書式と揃える: **壊れた条件は1件だけ落とす**
(1つの入力ミスでルール全体が消えると「保存したのに戻っている」としか
見えない)。**壊れた正規表現は「当たらない」で済ませる**(一覧を落とさない)。
**ルールを消しても列側の参照は残す**——無いルール名は読み替えなしとして
扱えばよく、参照を消して回るより一覧が出ることを優先する。

**並び順(段5)は複数キー**。見出しのクリックは1キーへの置き換え、
Shift+クリックはキーの追加(最大4)。既定を置き換えにしてあるのは、日々の
操作のほとんどが「この列で並べたい」だから。**2つ以上あるときは順番を出す**
——矢印だけでは先後が分からず、結果を読み違える。順番は**矢印の後ろへ
丸数字**で置く(列名の直後に素の数字を置くと「製造材質2」のように列名の
一部に見える)。組み合わせは`ソートプリセットマスタ`へ名前を付けて保存し、
フィルタの登録条件と同じ構成(状態を見せる→選ぶ→保存する)で出す。

**一覧の問い合わせは`WL.listQuery()`で組み立てる**。`filters.js`が`load()`を
丸ごと差し替えるため、両方に同じ組み立てを書くと片方だけ直した状態になる
(品質データ結合とキャッシュで実際に2度起きた)。`filters.js`側が足すのは
絞り込み条件だけ。

**タイムラインの内容欄は項目ごとの独立した列(段6)**。以前は選んだ項目を
「 / 」で繋いだ1つの文字列だったが、**1セル1値**にすると上の仕組みが
そのまま効く(対象`timeline:<設備名>`)ので、タイムライン専用の設定画面を
作らずに済む。実装で外せない点:
- **見出し(`.sc-row-head`)と行(`.sc-row-line`)は同じグリッド定義を共有する**。
  内容の1トラックを`var(--sc-content-cols)`へ差し替え、JSが項目数と幅から
  `applyTimelineContentColumns()`で組み立てる(行の最小幅`--sc-row-min`も同時)。
  片方だけ別の組み立てにすると左端がずれ、表として読めなくなる。
- 見出しの文字は**表示名 → 内容項目の日本語ラベル → キー**の順に落とす。
  生のキー(`mfgTemper`等)が見出しに出てはいけない。
- 並べ替えD&Dと幅つまみは`bindTimelineHeadTools()`が付け、保存は一覧と
  同じ`/api/column-layout-master`(全置換なので触っていない設定も送る)。
- **どの項目を出すか**は従来どおりスケジュール内容表示マスタで、
  **モードによらず読む**（§9.246 ②）。以前は`scState.fullControl`で
  塞いでおり、編集モードだけ既定の4項目へ落ちて**同じ表が2通りの姿**を
  持っていた（モードを一往復すると直る、という形で実機から報告された）。
- 親子(分割)の折りたたみつまみは**最初の内容セルの中**へ入れる。素の兄弟に
  すると1列ぶんずれて以降の桁が全部合わなくなる。
- CSSのコメントに`**/`を書かないこと。そこでコメントが閉じてグリッド定義が
  壊れ、内容が1列に潰れる(実際に起きた)。

固定は`tests/test_collayout.js`(並び・幅・表示)、`tests/test_colformat.js`
(書式・パネル)、`tests/test_colrule.js`(読み替えの判定・編集画面)、
`tests/test_displayrule.py`(保存の仕方)、`tests/test_colsort.js`(並び順)、
`tests/test_sccols.js`(タイムラインの内容列: 桁合わせ・行高・列数)。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **一覧の見せ方（`列レイアウトマスタ`／`一覧表示設定マスタ`）は全置換**:
  対象(`list:<DB>:<表>` / `timeline:<設備>`)ごとに行を消して入れ直す。
  **触っていない設定も一緒に送らないと消える**——見出しのD&Dで並びだけを
  送っていたため、並べ替えると表示名が消える不具合が実際に出た。
  サーバー側(`set_column_layout`)も、並びに載っていない列を幅・表示名・
  書式・非表示のどれかが指定されていれば残す（片方だけ拾う実装だと、
  その設定だけが黙って消える）。値の整形は**画面側だけ**で行う
  （`WL.cellFormat`。並べ替え・絞り込みを生の値で効かせたままにするため）。
  **整形に失敗したら生の値を出す**のが原則で、空欄にしない。
  **読み替え（`表示ルールマスタ`）は書式より先**に効く（生の値を見て判断する
  ため。'00'を'0'へ整形してから読み替えると当たらない）。ルールは列に属さず
  名前で参照し、**表示順の上から見て最初に当たった行を採用**する
  （行の中の条件はAND・行同士がOR、条件が空の行は既定）。壊れた条件は
  **1件だけ**落とし、壊れた正規表現は「当たらない」で済ませ、ルールを消しても
  列側の参照は残す（無いルール名＝読み替えなし）。詳細は
  `docs/COLUMN_PRESENTATION_DESIGN.md`と`docs/SCHEDULE_MODE_DESIGN.md`§9.88。
  **一覧の問い合わせは`WL.listQuery()`で組み立てる**——両方に書くと片方だけ
  直した状態になる（品質データ結合とキャッシュで実際に2度起きた）。
  **`load()`を丸ごと置き換えないこと**（§9.93）。以前は`filters.js`が
  `load=async function(){...}`で全置換しており、元の定義をgrepで辿っても
  最終的な実装に行き着かなかった。拡張したい側は**`WL.listHooks`へ登録する**
  （`onQuery(fn)`=問い合わせへ条件を足す／`onAfter(fn)`=描き終えた後）。
  `filters.js`が足すのは絞り込み条件だけ。
  固定は`tests/test_collayout.js`・`tests/test_colformat.js`・
  `tests/test_colrule.js`・`tests/test_colsort.js`・`tests/test_displayrule.py`。
