# §9.622 帳票の紙は PC の環境の設定で字の大きさ・中身を変えない——紙の中はトークンを表示サイズ「中」で計算し直す（利用者の指摘）

索引: [決定記録](README.md)｜前: [§9.621](9.621.md)｜関係: [§9.132](9.132.md)・[§9.433](9.433.md)・[§9.237](9.237.md)・[§9.332](9.332.md)

## 経緯（利用者の言葉）

> 帳票の印刷機能で、PCによってはプレビューにした時に見切れてしまうこともあります。環境設定によらず、文字サイズがユーザーの意図に反し変化することなく同じ表示内容で見切れなく正しく印刷出来るようにしたいです。そもそもそういう可能性が原理的にあるかどうかも含めてコードを調査し、必要に応じて修正をお願いします。

## 原理として、紙が PC ごとに変わり得る道（調べた結果）

| 道 | 紙が変わるか | 根拠 |
| --- | --- | --- |
| この端末の表示サイズ（小・中・大・`--ui-scale`） | **変わっていた → 直した** | トークン（`--fs-badge`など）は`:root`で一度計算されて受け継がれる。紙の中の部品がそれを使うと、その PC の表示サイズで字が変わる（実測: 状態の札 10px → 小 9.2px／大 11px）。§9.237 は紙の字を px で書いて避けていたが、トークンを使う部品が紙に入ると漏れる |
| Windows の拡大率（125% など・画面の倍率） | 変わらない | 実測。CSS の px と mm は倍率に関係なく同じ長さで組まれる |
| ブラウザの既定の字の大きさ（「大」など） | 変わらない | 実測。紙の字は px で書いてあり、`rem`／`em` の根を既定の字に持たない |
| 画面（窓）の大きさ | 紙そのものは変わらない | 実測（1536×864・1280×720）。プレビューは紙ごと縮めて器へ入れる（`--rp-scale`）。字の計算値・割り付けは同じ |
| ブラウザの「最小の字の大きさ」（Edge の設定） | **変わる（利用者が選んだ設定どおり）** | 12px にすると、紙の字 162 要素のうち 159 が 12px へ持ち上がる。紙は割り付けを測り直すので**見切れは0**。デスクトップ版（WebView2）には利用者がこの設定を変える口が無い（開発の入口をブラウザで開いたときだけ効く） |
| 書体（Segoe UI・Yu Gothic UI は同梱しない） | **分からない** | Windows 10／11 には両方入っている。入っていない PC では代わりの書体の幅で割り付けが変わり得るが、ここでは確かめられない |
| Windows の「テキストのサイズ」（アクセシビリティ） | **分からない** | WebView2 の中の字に効くかを、この環境では確かめられない |

プレビューと刷る書類は同じ CSS・同じ割り付け（測って縮める`rpFitBlockBodies`・紙の枚数）から出る。だから同じ PC の中では、プレビューで切れていなければ刷っても切れない（網の P1〜P3 を両方で数える）。

## 直したこと

`static/css/00-base.css` のトークンの塊のセレクタを `:root` から `:root,.rp-page,.os-page,.sp-page` にした。この塊は`--ui-scale:1`を宣言しているので、紙の根（帳票・操業データ表・作業予定表）でもう一度当たると、紙の中のトークンが表示サイズ「中」の値で計算し直される。値の写しを持たず、答えは1箇所のまま。

最小の字の大きさは直さない。利用者が「小さい字を読めるように大きくする」と自分で選んだ設定で、それを打ち消すのは「利用者の意図に反して変える」側になるため。代わりに、その設定でも見切れないことを網で守る。

## 物差し（`tests/test_rppaper.js`）

同じロットの帳票を8つの場面で開き、プレビューと刷る書類（`@media print`）の両方で紙の中を数える。
- P1 字の大きさが基準と同じ要素の割合
- P2 縮める倍率と紙の枚数が基準と同じ
- P3 切れている要素が0（`overflow`で隠れる・紙の外へはみ出す・塊の下が切れる・入りきらない塊）
- P4 紙の横がプレビューの器の中で読める

物差しが切れを見つけられることは注入で確かめた（`WAVELOG_RPPAPER_INJECT=24` で紙の字を 24px にすると P3 が4件見つける）。

| 場面 | P1 直す前 | P1 直した後 | P3 |
| --- | --- | --- | --- |
| 表示サイズ 小 | 161/162（状態の札 10→9.2px） | 162/162 | 0 |
| 表示サイズ 大 | 161/162（状態の札 10→11px） | 162/162 | 0 |
| 既定の字 20px | 162/162 | 162/162 | 0 |
| 画面の倍率 125% | 162/162 | 162/162 | 0 |
| 画面 1536×864・1280×720 | 162/162 | 162/162 | 0 |
| 最小の字 12px | 3/162（数えるだけ・利用者の設定） | 3/162 | 0 |

この網のロット（検証用フィクスチャ）では、直す前も P3 は0だった。現場で見切れた帳票の中身（塊の組み合わせ・長い字）は分からないので、表示サイズの漏れが見切れの元だったとは言い切れない。直したのは「字の大きさが PC の表示サイズで変わる」道で、見切れについては P3 を8場面で守る網を置いた。
