# §9.577 操業データ表の段組は横96マス・幅は中身から——値が切れない幅を先に取り、入らなければ段を足す（利用者の選択 C）

索引: [決定記録](README.md)｜前: [§9.576](9.576.md)｜関係: [§9.553](9.553.md)・[§9.575](9.575.md)・[§9.294](9.294.md)

## 経緯（利用者の指示）

> 今のLS4の構成は7ロット入るのですが、上下余白が大きく、無駄も多いので10ロットくらい詰め込んでもよい…項目数だけで言うと約40項目です。
> データ量優先で表示が欠けないような作りで改良をお願いします。
> 幅は項目ごとにフレキシブルにできないと到底収まりません。
> 段数は任意のはずなので、変更が効くことは変えず、文字の大きさは同じでCをベースにした考え方でお願いします。

案は1回目6案（F 88.5・C 84・D 84…）、2回目で H3 88.5 と C 85 が僅差になり、利用者に確かめて **C**（96マス・中身の幅・段は利用者が決める・字は今の大きさ）に決まった。

## 1. いまを測る（LS4 の見本 42項目・1直30ロット・A4横・高密度 8.5px）

24マスの盤に1段21項目を置くと、ほぼ1マスずつになり、中身の幅を配れなかった（幅は画面の列幅の比）。

| 物差し | 前（2.470.0） | 後 |
| --- | --- | --- |
| 値が切れたセル | **58** / 955（5項目） | **0** / 623 |
| 段の数 | 2 | 3（どの段も紙の幅に入る最小の数） |
| 1枚のロット数 | 23 | **15**（目標「10ロットくらい」を超える） |
| 字の大きさ | 8.5px | 8.5px（変えない） |
| 表が紙の高さに占める割合 | 86% | 82% |

ロット数が減ったのは、切れていた値に必要な幅を取ったため（2段では入らない）。見本（`o4` の案 C）の予測（15ロット・3段・切れ0）とちょうど一致した。

## 2. 決めたこと

- **盤は横96マス**（`UNITS`・サーバーの`PLACE_UNITS`）。1マスはA4横で約2.9mm。
- **幅は中身から**: 紙と同じCSSで描いた写しで、その紙に出る値の最長と見出し（2行まで折り返すので「全体の半分か最長の語」）を測る
  （`measureContent()`・同じ材料なら測り直さない）。`canvas`の見積もりは使わない（§9.294 ④で足りなくなった）。
- **マスへ切り上げてから余りを比で配る**（`spansFromWidths(ws,units,unitPx)`）。比だけで配ると、広い1項目が中身より痩せる
  （網: 900px の項目が 882px になる）。盤より多ければ広い項目から1マスずつ返す。
- **段の数は「どの段も紙の幅に入る最小の数」**（下限2・上限4）。**段の数は利用者が変えられる**——盤の「段を足す」は
  自動の位置にも効き（固める前）、固めたあとは空いた段として出る。置いた位置・幅は利用者のまま。
- 中身より狭く置いた項目は `tight` で名指し、盤の下と紙の説明で「値が切れうる N項目」と言う。
- **古い配置は読み替える**: 配置は何マスの盤で置いたか（`u`）を名乗り、名乗らない配置は24マスの頃の物として4倍にする
  （画面の`onBoard()`とサーバーの`normalize_place()`が同じ決まり）。
- 盤と一覧の段組の格子は `--rcl-units` の1つ（CSSに24を書かない）。盤の目盛りは4マスごと（96本引くと地が潰れる）。

## 網（見張り）

- `test_recordlayout.js`: 中身の幅以上をマスで取る／広い項目も比で痩せない／紙に入るまで段を足す／狭く置いた項目は tight／
  古い配置は4倍へ・u を名乗る配置はそのまま（画面とサーバー）／紙は96本のトラック・値が切れない
- 欠陥注入（1件ずつ）: 切り上げを外す → 1件落ちる／サーバーの読み替えを外す → 2件落ちる

## 残したもの

- 盤の札の名前は、狭い項目（例: 「スリット 大径リング色」）で3つが2行に入りきらず「…」になる（`title`で読める）。
  札の幅は紙の幅の比なので、札だけ広げると盤と紙がずれる。
