# §9.394 基準が引けないときは手で入れる（利用者の指示）

利用者の指示（原文）:

> **６）ラテラルボーおよびバリの項目について、基準が取得できない場合、
> 基準なしと出るだけでなく、手動で入力できるように、そのバッジをボタン化する
> などして入力モーダルを出して入力したら手動で基準を表示させる機能を
> 追加してください。**

確認して決めたこと（`AskUserQuestion`）:

| 迷い | 決めたこと |
| --- | --- |
| 手で入れた基準をどこに持つか | **そのロットだけ**（測定データの中に持ち、出どころは「手入力」と明記する） |

## 1. マスタへ書かない

1本のロットのための例外をマスタへ書くと、**次のロットへ黙って効く**。
置き場は測定データの `settings.manualLimits`（項目名 → `{value, by, at}`）で、
**誰がいつ入れたか**も一緒に持つ（§9.180 と同じ作法）。

**出どころは必ず「手入力」と書く**（§CLAUDE 6）——同じ「0〜2.5」でも、
仕掛から引いた基準と人が打った基準では当たる見込みが違う。札は
「手入力基準 0.00〜2.50（直す）」と読める。

**手で入れた基準は判定にも効く。** 基準がある＝判定できる、という筋を
項目ごとに変えない。どちらの根拠で赤が出ているかは札が言い続ける。

## 2. 踏んだ罠（本題）: ラテラルボーは**何も言っていなかった**

利用者の言う「基準なしと出る」を実物で確かめたら、**バリとラテラルボーで
出ている場所が違った**。

- **バリ** … 上の札（`#toleranceSummary` のピル）が「基準なし」と出す。
- **ラテラルボー** … `measure-worklog.js` の `suppressSummaryForInstruction()`
  が、指示型の項目では**その札ごと伏せて**いた。代わりに「指示値」カードを
  出す約束だったが、**そのカードは画面のどこにも出ていなかった。**

カードが出ていなかった理由は2つ重なっている:

1. `WL.tolerance.register()` が **`detail` を持たない提供者を黙って捨てて**
   いた（`if(typeof p.detail!=='function')return`）。カードは `facts`／`scale`
   だけを持つ提供者なので、**一度も走らない**。`WL.tolerance.providers()`にも
   現れないので、誰も気づけない（`tests/test_tolscale.js`が「提供者は3つ」と
   数えていたのがその証拠）。
2. 仮に走っても、`WL.measureTolerance.parts()` は図（`.accurate-numberline`）
   だけを取り出して測定表の隣へ渡す作りで、**カードの側（`facts`）は
   捨てられる**。

結果、ラテラルボーでは基準について**画面が何も言わない**状態だった。

直したのは2つ:

- **登録で捨てない**（§9.328「黙って捨てない」）。`detail`／`facts`／`scale`の
  どれか1つでも持てば受け、どれも無ければ**理由を1行残して**断る。
  答えを出すのは `detail` を持つ提供者だけなので、`resolveTolerance()`は
  そこを飛ばす。
- **抑止は「代わりに出す物があるときだけ」**。`suppressSummaryForInstruction()`は
  **指示値が読めるときだけ**札を伏せる。読めないときは札を残す——
  そこが利用者の言う「基準なし」で、そのまま手入力の入口になる。

## 3. 入口は札の1つ

`WL.measureHooks.on('afterHeading')` で、**見えている札**を `<button>` に
差し替える（描いたあとに足すのは登録表から・§9.352。被せない）。

- **伏せてある札はボタンにしない**（押せないボタンを残さない・§CLAUDE 4）。
- 字は「基準なし／手入力」「手入力基準 0.00〜2.50（直す）」——
  **押すと何が起きるかを字で書く**（色と枠だけにしない・§CLAUDE 3）。
- 押せる物には**押せる形**（枠と指のカーソル）を与える（§9.385 の裏）。
- 押す口は `data-tol-manual` への**委譲が1つ**。札は見出しを描き直すたびに
  作り直されるので、直に `onclick` を張ると張り忘れる面ができる。

窓は `promptModal`（§9.342 の3つのうちの1つ）。窓は
**「このロットだけ・マスタには残しません」**と書き、空欄で決定すれば取り消し、
数にならない値は**理由を書いて断る**（黙って0にしない・§9.231）。

## 4. 提供者の優先度は25

`detail` の提供者として `priority:25` で登録する（指示型の20より上）。

- **人がこのロットのために打った値**なので、あとから届いた指示値で黙って
  上書きしない。
- **同じ数にしない**——同数だと順番が読み込み順で決まり、§9.348 が畳んだ
  依存が戻る。

手入力が無ければ `undefined`（＝次の提供者へ）を返すので、**入れていない
ロットの挙動は1文字も変わらない**。

## 5. 足せる項目は1箇所

`MANUAL_LIMIT_TYPES`（ラテラルボー・バリ）。利用者が挙げた2つで、
増やすときはここ1行。**寸法系（板厚・板幅）には出さない**——公差の出どころが
別に在るので、手入力の道を混ぜない。

## 6. 固定した網（`tests/test_tolscale.js`・11件）

1. 基準が引けないラテラルボーでも**札が出て**、それが入口になる
2. 押すと何が起きるかを字で書く／押せる形（指のカーソル）を与える
3. 窓が「このロットだけ・マスタに残さない」と書いている
4. 入れた基準が札に出て、**出どころは「手入力」**
5. **判定にも使う**（範囲0〜2.5・`source==='manual'`）／いつ入れたかも残る
6. **バリにも同じ道がある**／**板幅には出さない**
7. 空欄で決定すると取り消す／数にならない値は理由を書いて断り、0を入れない

**欠陥注入で確かめた2件**:

1. `suppressSummaryForInstruction()` を元どおり「常に伏せる」へ戻す → 1・2が赤。
2. 手入力の提供者を `undefined` 固定にする → 4・5が赤。

**書き換えた既存の網**（§9.389 §10 と同じ理由——**顔ぶれや字を丸ごと固定
しない**）:

- `test_tolscale.js` … 提供者を文字列で並べる検査 → **要る提供者が居るか＋
  priority の降順**で見る（`facts`だけの提供者は`detail`の相棒なので同数を許す）。
  フックの件数も**下限**で見る。
- `test_ngcard.js` … 札の字の完全一致 → **「基準」と言い「公差」と言わない**で見る。

## 7. 踏んだ罠（網の側）: 前の節が開けた窓が後ろを全部覆う

`page.click` が30秒待って落ちた。測ると**札は115×22pxで見えていて、
上に `#appConfirmModal` が居た**——前の節が手動入力へ切り替えており、
その警告（`alertModal`「手動入力は例外操作です」）が開いたままだった。

**窓は1枚しかない**（§9.342）ので、開いていると後ろの操作がすべて覆われる。
節の頭で閉じてから始める。**「押せない」で終わらせず、何に覆われているかを
出す**こと（`elementFromPoint`）——30秒待って落ちるだけでは理由が残らない。
