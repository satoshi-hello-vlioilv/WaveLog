# §9.554 毎日の入口を exe 自身にする——版を比べて写し、印を外し、ショートカットは入口の exe へ（利用者の選んだ案 C）

## 経緯

利用者の報告と問い:
「vbsから起動すると、実行前のダイアログが2回出てくる形ですが、正常でしょうか？どちらも次回から開かないのチェックボックスを
入れると次は1発でデスクトップ版を開くようになりました。…exeから実行するのかvbsから実行するのか起動として一般的に推奨される
スタート方法はどういう方法でしょうか。個人的にはデスクトップ版としてはexeから起動を想定していました。」

4案（A 今のまま Start.vbs／B 共有の exe を直に／C exe 自身を入口に／D 正式なインストーラ）を比べて示し、利用者が選んだ:
「Cで進めてください。」

### 2回出ていた理由（推定。ダイアログの種類は画面を見ていないので断定していない）

ZIP をブラウザで落として展開すると、中のファイルすべてに「インターネットから来た」印（Mark of the Web・NTFS の別の流れ
`Zone.Identifier`）が付く。印の付いたファイルをエクスプローラー・WSH の道で起こすと「ファイルを開く – セキュリティの警告」が出る。

1. 1回目: 印の付いた`Start.vbs`。
2. 2回目: `Start.vbs`が`CopyFile`で写した exe。`CopyFile`は**印ごと写す**。版ごとに新しいフォルダへ写すので、更新のたびに新しい
   ファイル＝印つき。

チェックを外すとそのファイルから印が消えるので2回目以降は出ないが、**更新の ZIP で付き直す**（毎回2回）。

## 決めたこと

1. **入口は exe 自身**。ショートカットの行き先は、この PC の決まった場所の
   `%LOCALAPPDATA%\WaveLog\desktop\WaveLog.exe`（入口）に`--program "<program フォルダ>"`を付けたもの。
2. exe は起動のはじめに（窓を作る前に）、**どこから起こされたか**で決める——`launch::plan()`の1箇所:
   - 共有の`program\WaveLog.exe`・入口から起こされた: 配った exe の版（大きさ＋更新時刻）の写し
     `desktop\<版>\WaveLog.exe`へ渡す（無ければ写す）。渡したら自分は終わる。
   - 版ごとの写しそのもの: そのまま窓として動く。
   - それ以外（作る途中の`desktop/target/`・手で置いた exe）: 入口の役目を持たない（開発の道を変えない）。
   - 写せない・起こせないときは**そのまま動く**（窓が出ないより、共有から動くほうがまし）。理由は`desktop.log`。
3. **写した物から印を外す**（`launch::install()`＝途中のファイルへ写す→印を外す→名前を変えて入れ替える）。外すのは
   **自分で写した、出どころの分かっている物だけ**。配った`program\WaveLog.exe`の印は触らない。
4. 入口は、窓として動き出した版が自分と同じ中身に置き直す（`refresh_entry()`）。入口は起こされるとすぐ終わるが、
   当たったら少し待ってやり直す。
5. program フォルダの答えは`locate::program_dir()`の1箇所: `--program`→`WAVELOG_PROGRAM_DIR`→exe の上へたどる→
   **最後に使った控え**（`desktop\program.txt`）。引数の無い入口（タスクバーに留めた等）でも中身を探せる。
6. ショートカットは Python が決める（§9.552 のまま）。行き先は窓が渡す`WAVELOG_SHELL_ENTRY`（Store 版の Python は
   `AppData\Local`を自分だけの写しに見せるので、場所を組み立てずに窓の答えを使う）。前の行き先`Start.vbs`も
   **自分のもの**と見て、窓の中で起動したときに入口へ付け替える（`migrate()`・残した名前の物で、行き先が`Start.vbs`の物だけ）。
7. `Start.vbs`は**移行期間のために残し、exe を起こすだけ**（入口があれば入口、無ければ`program\WaveLog.exe`）。写さない。
   片付けは移行が済んでから（`setup_check.RETIRED`の道）。

## 撤回した案

- **A（今のまま）**: 更新のたびに警告2回。VBScript は Microsoft が廃止予定と公表している（将来の Windows では既定で使えない見込み）。
- **B（共有の exe を直に）**: 動いている間 exe を掴むので、1台でも開いていると更新で上書きできない（§9.546）。
- **D（MSIX 等＋署名）**: 正統だが、コード署名の証明書と社内の配布ルールが要る。将来の選択肢として残す。

## 網

- Rust（`cargo test`）: `plan()`が起こされた場所ごとに正しく決める（配った exe・入口→写す／写してあれば渡す／写しそのもの→
  そのまま／作る途中→そのまま／配った exe が無い→そのまま）・入れ替えで半端なファイルを残さない・**Windows では写した物の
  印が外れ、元の印は残る**（Windows の CI でだけ回る）。
- 自己診断（Windows の CI・本物の WebView2）を**2回**たどる: ①印を付けた共有の exe を直に起こす（最初の道）→版ごとの写しと
  入口ができ、どちらにも印が無く、配った exe の印は残っていること ②`Start.vbs`から（入口が在る＝毎日の道）。どちらも
  「窓は版ごとの写しで動いている」「ショートカットの行き先が入口の exe」を確かめる。
- `test_shortcut.py`: 行き先・引数・前の行き先も自分のもの・付け替えの5通り（付け替える／もう入口／別の物／窓の外／無い）。
- `test_faststart.py`: Start.vbs は写さず exe を起こすだけ・`--program`を渡す。

## 踏んだ罠

- 評価関数で「前」を測るとき、`git stash`のあとを測っていた——作業中の変更はコミット済みだったので、`stash`しても main には
  戻らない。main を別の作業ツリーに出して測り直した（`git worktree add`）。
- 物差しが`TARGET_NAME='Start.vbs'`の字を探していたので、新しく足した`LEGACY_TARGET_NAME='Start.vbs'`にも当たった。行頭に限った。

## 分からないこと・実機で確かめること

- 利用者の画面で出ていたダイアログが「セキュリティの警告」（印による）か「Windows によって PC が保護されました」
  （SmartScreen）かは確かめていない。後者なら、印を外すことで出なくなる見込みだが、署名の無い exe を最初に共有から起こす
  1回目は出ることがある。
- 実行中の窓をタスクバーに「ピン留め」すると、留まるのは版ごとの写しの道になり、更新で古い版のフォルダが片付くと
  留めた先が無くなる。デスクトップの起動アイコンを右クリックして留めれば入口が留まる。窓そのものの留め先を入口へ
  向ける作り（AppUserModelID と再起動の指定）は入れていない。
- Box Drive の「オンラインのみ」の`program\WaveLog.exe`を版の比較で読むとき（大きさと更新時刻だけを見るので中身は取り寄せない
  見込み）、写すときに取り寄せが起きる。実機では確かめていない。
