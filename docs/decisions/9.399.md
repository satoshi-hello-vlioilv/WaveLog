# §9.399 右クリックメニューを群で束ね、複製とDeleteキーを足す（利用者の指示）

利用者の指示（原文）:

> **右クリックメニューを改良し、最新の内容に合わせてより分かりやすく、
> 見やすく表示内容・機能を再構成してください。追加の機能として、
> 停止内容の複製追加といった複製機能を実装してください。**
>
> **DELETEキーで作業スケジュールの選択対象を削除する機能も実装してほしいです。**

## 1. 何が読みにくかったのか

行の右クリックは §9.207 で足し始めてから**項目が13へ増え**、区切りは2本だけ
——実質**平らな1本の並び**だった。「開始」と「予定から外す」と「表示列の設定」が
同じ顔で並ぶので、**何がどこにあるのかを毎回読み直す**ことになる。

**解き方**: 並びは「この行で何をするか」＝**作業導線そのもの**（§CLAUDE 14）。

```
進める → この行を直す → 増やす・写す → 選ぶ・並べる → 画面 → 外す
```

- 群は**1つ5件以下**（一度に見渡せる粒度）。
- **中身の無い群は出さない**（`pruneMenuGroups()`）——行によって出る項目が
  変わるので、見出しだけ残ると「この下に何かあるはず」と探させる（§CLAUDE 4）。
  区切りが連続したときも1本へ畳む。**並べ替えはしない**（並びは呼ぶ側が決める）。
- **危ない操作はいちばん下の群へ離す**（§CLAUDE 5）。
- **鍵盤でできることはその場に書く**（`<kbd class="chm-key">Delete</kbd>`）
  ——メニューを開いた人が、その道を知らないままにしない（§CLAUDE 2）。

### 踏んだ罠: 見出しを`button`にしない

`10-roles.css`の`.col-head-menu button`が**行き先の寸法を配る**ので、
見出しまで押せる行き先と同じ顔になる（§9.264と同じ罠）。見出しは
**押せない字**なので`div.chm-group`で組む。

## 2. 複製できるのは「もう1件あり得る」ものだけ

| 種類 | 出すか | なぜ |
| --- | --- | --- |
| 設備停止 | **出す** | 同じ停止をもう1回（午前と午後の点検、2台ぶんの刃替え）は普通に起きる |
| 申し送り | **出す** | 同じ文をもう1行、も普通にある |
| 作業 | **出さない** | 同じロットを2回流すという**実体が無い** |
| 枠 | **出さない** | 同じ日・同じ直の枠が2つあっても**何も変わらない** |

**内訳・見積・備考ごと、その行のすぐ下へ**入れる（探させない・§CLAUDE 2）。
「その行の次」は**「次の行の前」**——`position`は`before:<id>`と`end`しか
無いので、次の行が無ければ末尾（`nextEntryIdOf()`）。

**名前を直してある行は、直した名前のまま複製する。** `plan_add`は設備停止の
`[予定名称]`をマスタから写すので、その場ではマスタの名前になる——**違うときだけ**
続けて名前を戻す。いつも送ると、同じ名前を書き戻す更新が毎回飛ぶ。

設備停止の複製には**停止理由のID**が要る（`plan_add`が名称をマスタから写すため）。
予定の行はIDを持たないので、**いま読み込んである選択肢から名前で引く**
（`stopReasonIdOfEntry()`）。引けない＝マスタから消された停止なので複製できない
——**理由を書いて残す**（§CLAUDE 4）。断りは`duplicateBlockReason()`の1箇所が
答える（メニューの断り書きと押したときのトーストを同じ言葉にする・§9.372）。

## 3. Deleteキーは「1本の道」を通す

**通るのは`removeEntries()`の1本だけ。** 確認の文言も、外したロットを仕掛一覧へ
戻す知らせも、選択バーの「選んだN件を予定から外す」と**同じになる**
（§CLAUDE 8。同じ操作を2通りの顔で持たない）。

**打っている最中は取らない**（鍵盤の事故を作らない）:

- 欄（`input`/`textarea`/`select`/`contentEditable`）に居るとき
- **日本語を変換している最中**（`isComposing`／`keyCode===229`）
- 窓・浮き窓・印刷プレビューが開いているとき
- 作業スケジュールの画面に居ないとき／1件も選んでいないとき

**Backspaceは取らない**——利用者の指示はDeleteで、Backspaceは「1つ前へ戻る」と
結び付いている鍵盤が多い。

選んではいるが**外せない**（日時を固定した予定）ときは、**理由を言う**
——押しても何も起きない鍵にしない（§CLAUDE 4）。

## 4. 踏んだ罠: 欠陥注入を戻す前にコンテナが落ちた

網が噛むかを確かめるため**3件の欠陥を注入**した直後にコンテナが再起動し、
**復元されないまま作業ツリーに残った**:

| 混入 | 死んでいたもの |
| --- | --- |
| `if(it.group)return '';` | 群の見出しが1つも描かれない |
| `if(ev.key!=='Delete'\|\|1)return;` | Deleteハンドラが常に return |
| `if(1)return;`（`duplicateEntry`） | 複製が何もしない |

**見分けられたのは、3件ともコメント・CSS・網の期待と矛盾していたから**
——`.chm-group`の意匠が在るのに空文字を返す、`Delete`と書いた札を出しながら
ハンドラが即 return する、という形で**自分自身と食い違う**。

**教訓**: 欠陥注入は**必ず1件ずつ入れて、その場で戻す**。3件をまとめて入れると、
途中で落ちたときに**何を入れたのかを外から読めない**（今回は矛盾から復元できたが、
矛盾の無い注入だったら気づけない）。CLAUDE.md の「走っている最中に触らない」と
同じ事故の別の形。
