# §9.559 新しい PC へはアドレスだけ渡す——初めての起動でこの PC へ写し、起動アイコンは聞いて作る／Start.vbs・update.bat を外す（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.558](9.558.md)｜関係: [§9.554](9.554.md)・[§9.555](9.555.md)・[§9.557](9.557.md)・[§9.548](9.548.md)・[§9.318](9.318.md)・[§9.225](9.225.md)

## 経緯

利用者の指示:
「ファイルをサーバーからＰＣのローカルに移して起動してという流れではありますが、アップデートの仕組みが構築できたことで、
ローカルにいったん移すという手間も省きたいです。…初回に配布する際に、ショットカット(アドレス)だけ渡すという形にできないか
検討してほしいです。必要なものはそこから初回起動でコピーされ、アプリのショートカットがデスクトップになければ、許可を求め
つくられる。…デスクトップ版への移行も進んできているので、vbsをはじめ、不要なファイルの整理もお願いします。」

検討の結果（今ある仕組みで作れる）を示し、利用者が選んだ:
1. 写す先は **`%USERPROFILE%\WaveLog`**
2. 新しい PC の`config/local.json`の最初の値は **配る版を決めた PC の`master_db_path`を共有へ控えて写す**
3. Start.vbs・update.bat（＋setup_app.py）は **今回すぐ外す**

## 決めたこと

1. **配る入口**: 「この版を配る」（`app_update.set_release()`）で、その版の exe を置き場の直下（`<置き場>\WaveLog.exe`）へ
   写す（`place_entry()`）。新しい PC にはこの exe のアドレスだけを渡す。画面「アプリの更新」の「新しい PC へ」に
   アドレスとコピーのボタン、初回に写る共有のマスタの置き場を出す。
2. **渡す設定**: 同じときに`<置き場>\install.json`へ、配る版を決めた PC の`config/local.json`の`master_db_path`・
   `master_share_mode`を書く（`place_seed()`・`SEED_KEYS`）。`db_dir`・`records_db_path`はその PC の物なので渡さない。
   決めた PC が`master_db_path`を持たないときは**書かずに理由を言う**（ほかの PC が控えた値を空で消さない）。
3. **初めての起動**（Rust・`desktop/src/install.rs`）:
   - 共有の入口から起こされた exe（同じフォルダに`release.json`と`versions`）は、自分をこの PC の版ごとの写しへ写して
     `--install-from <置き場>`で渡し、すぐ終わる（共有の exe を掴み続けない・§9.554 と同じ理由）。
   - 写しの窓は、前に使った program フォルダが在ればそれを使う。無ければ`%USERPROFILE%\WaveLog`へ、**更新と同じ道**
     （`update::check_and_apply()`＝写して sha256 を全部確かめ、項目ごとに置き、途中で失敗したら戻す）で配る版を写す。
     その前に`install.json`を`config/local.json`へ（在れば触らない）、置き場が既定でなければ置き場の控え`config/update.json`も書く。
   - 進み具合は起動画面の段「版をそろえる」に「初めての起動: 写しています n/N」で出す。
4. **起動アイコンは聞いて作る**: 画面が起動したあと、`desktop_shortcut.offer()`が真なら「デスクトップに起動アイコンを
   作りますか？」（作る／作らない）。真になるのは、窓の中・作れる端末・残した名前のアイコンがデスクトップに無い・
   この PC で断っていない、のすべて。断ったら`runtime_dir()`に控えて次から聞かない（「表示」から作れる）。
   自己診断の窓（`WAVELOG_SELFTEST`）は人が居ないので聞かない。
5. **写す先を AppData の外にする**: Microsoft Store 版の Python は`AppData`への書込をその Python だけの写しへ回す（§9.318）。
   アプリのフォルダの`config/update.json`は Python が書いて窓（Rust）が読むので、`AppData`の下だと窓から見えない。
6. **Start.vbs・update.bat・setup_app.py を外した**。毎日の入口は exe（§9.554）、起動前の確認は起動のたびに窓口
   （`sidecar._prepare()`）が刻印が食い違ったときだけ行う（§9.225）ので、手で押す入口は要らない。版（`PAYLOAD`）から
   Start.vbs を外し、前の版が残した物は`setup_check.RETIRED_DESKTOP`で片付ける。合図は「**窓の中で動いている**」
   （その PC はもう exe から起動している）。`.git`のある作業ツリーは触らない（`update.rs`と同じ線引き）。
   update.bat だけが使っていた`ready.version_note()`・`file_cleanup.run_for_update()`も外した。
7. 前に Start.vbs へ作ったショートカットは、窓の中で起動したときに入口へ付け替わる（`migrate()`・§9.554 のまま）。
   Start.vbs の実物が無くても行き先の字で見分けるので付け替わる。

## 撤回した案

- **写す先を`%LOCALAPPDATA%\WaveLog\app`にする**: 利用者の目に触れないが、Store 版の Python の書いた物が窓から見えない（5）。
- **新しい PC で共有のマスタの置き場を画面で聞く**: PC ごとに打つ手間と打ち間違いが出る。配る版を決めた PC の値を写す形を選んでもらった。
- **共有に`local.json`を手で置く**: 置き忘れると新しい PC が共有の DB を見ない。
- **Start.vbs を1版残す**: §9.554 で起動のたびに付け替わる作りなので、残す理由が無い（利用者の選択）。

## 踏んだ罠

- 評価関数が「初回に写す」を`launch.rs`の字で探していたので、`install.rs`に作っても 0 のままだった（物差しの誤り・§9.555 と同じ形）。
  配線の実物（`main.rs`が`install::handoff_from_share(`を呼び、`install.rs`に`run(`がある）で測るよう直した。
- `git stash`で「前」を測るとき、新しく足したファイル（追跡外）は stash に入らない。前の値は main.rs の配線が無いことで 0 になると確かめた。

## 分からないこと・実機で確かめること

- 共有の置き場の exe を初めてダブルクリックしたときに Windows の警告（「発行元を確認できません」）が出るかは、共有のサーバーが
  イントラネットとして扱われているかに依るので分からない。出ても1回だけ（写した物からは印を外す・§9.554）。
- 実機（Windows）で、共有から写す時間（数百ファイル・十数MB）は確かめていない。CI の3回目は同じ PC のフォルダから写す。
- Python のインストールは残る（中身が Python のため）。同梱すればこの手間もなくせるが、配る量が増えるので別の機会に検討する。
