# §9.337 テストの層分けとCI（REVIEW 3-13）

## 何が問題だったか

通しは **39分**（直列・1,600件超）。直したいものと関係のない網まで毎回待つので、
実際には「引数なしで通す」のは指示があったときだけになり（CLAUDE.md A）、
**その間ずっと何も機械が見ていない**状態だった。

## 決めたこと——3層

| 層 | 何を | 実測 | いつ回る |
| --- | --- | --- | --- |
| 1. 純粋な網 | サーバーを立てずに回る48本 | **20秒**（並列8。直列56秒） | pushごと（CI）＋手元 |
| 2. 煙テスト | 起動・一覧・スケジュール・測定 各1本 | **93秒**（173件） | pushごと（CI） |
| 3. 全件 | 通し | 約39分 | **人が指示したときだけ** |

```
tests/run_all.sh --pure     # 1段目（並列。パス設定の差し替えも見せ方の戻しもしない）
tests/run_all.sh --smoke    # 2段目
tests/run_all.sh            # 全件
```

**全件は並列化しない**（過去の非目標のまま）。ランナーは1台のサーバーと
共有フィクスチャを順に使う作りで、並べると互いの書込を踏む。**分けたのは
サーバーの状態を持たない層だけ。**

## 1段目に載せてよいものの決め方

「**まっさらな取得（DBも設定もサーバーも無い）でそのまま通る**」ものだけ。
判定は目でも注意書きでもなく、`git archive HEAD | tar -x` した写しで
1本ずつ回して決めた（64本の候補のうち47本が通り、17本はサーバーを要った）。

そして**そのあとを見張るのはCIそのもの**——`.github/workflows/nets.yml` の
1段目はまっさらな取得で回るので、サーバーを要る網を `PURE_TESTS` へ載せれば
そこが落ちる。注意書きではなく仕組みで止める。

互いの状態を触らないことが「純粋」の定義なので、**並列にしてよい**。

## 踏んだ罠——「合計 0/0 PASS」で緑になった

`grep -c` は**0件でも数を出して終了コード1を返す**。`|| echo 0` を添えると
`"0\n0"` になり、`$(( ))` が構文エラーで止まる。そのとき

```
  合計 0/0 PASS  (FAIL/FATAL: 0)  所要 9秒     ← 終了コード 0
```

と出た。**1本も回っていないのに緑。** §9.200 の「赤いまま残っている網は網では
ないが、緑に見えている壊れた網はもっと悪い」をそのまま踏んだ。いまは
**回った本数を数え、宣言の本数と食い違えば落とす**（`RAN` / `N`）。

## 見つかった素通り2件（§9.334 の続き）

領域フォルダにしたときに `glob('*.js')` → `rglob` へ直したのは4本だったが、
**まだ2本残っていた**——`test_csslint`（インラインの見た目の直書きを数える）と
`test_pick`（規則に当たらないソースを数える）。どちらも 3-9 以降
**0本のJSしか見ずに通っていた**。直しても違反は0件だったので実害は無かったが、
**数え落としは緩む側に壊れるので、通ったこと自体が証拠にならない**（§9.335）。

## 網（`tests/test_layers.py`、`ALWAYS`、18 PASS）

名前が実在する・**一覧の宣言は1箇所だけ**・1段目に画面のテストを混ぜていない・
1段目の網は通しの一覧にも載っている（層が別の宇宙へ分かれない）・
`--pure` がパス設定の差し替えより前でサーバーを触らない・**0本でも緑に
ならない見張りが残っている**・CIが1段目と2段目を回し全件は回さない。

**一覧の宣言を1箇所に縛るのは A/B で分かった**——最初の網は
`PURE_TESTS="$PURE_TESTS test_scbar"` と書き足す欠陥を**素通りさせた**
（宣言を1つ読むだけだったので、2つ目が見えない）。

**`.py` の同名で画面のテストを見分けないこと**——`test_savechip` のように、
同じ主題をサーバー側と画面側の2本で見ている網が実際に在る。

## CI

`.github/workflows/nets.yml`（push / pull_request）。1段目は
`requirements-dev.txt`（pyflakes）と `npm i -g eslint`、2段目は playwright の
chromium を入れて `WAVELOG_NODE` / `NODE_PATH` / `WAVELOG_PLAYWRIGHT` /
`WAVELOG_CHROMIUM` を渡す（ランナーの既定はこの開発サンドボックスの置き場なので、
CIでは実際の置き場を渡す）。**このワークフローはここからは実行して確かめて
いない**（GitHub 上でしか動かない）。
