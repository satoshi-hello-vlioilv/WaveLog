# §9.189 申し送り（コメント）と、紙に画面のまとめを入れる（利用者の指示）

利用者の指示: 「①まとめ方法も反映して印刷できるようにしてください。
②コメント用の欄、コメントもできるものを設備停止のように追加できるように
してください」。

**① 画面の「まとめ」を紙にも。**
 - まとまりの判定は**画面の1箇所**（`groupBucketOf`）を通す
   （`WL.scheduleView.groupOf/groupMode`）。紙だけ別に組み立てると、画面と
   紙でまとまりが食い違う。
 - 紙では**まとまりの見出し行**を表の中へ入れる。紙を切り分けた続きの枚にも
   出す（見出し無しで始まると、どのまとまりの続きか読めない）。
 - **日付ごとにページを分けていて、まとめも日付**のときは見出しを出さない
   ——紙の頭と同じ文字になる（§9.129 同じものを2箇所に出さない）。
 - **見出し行を「行」として数えないこと**。枚数は実測で切る（§9.115）ので、
   見出しを行と数えると**そのぶん予定が紙から抜け落ちる**。`data-row`の
   付いた行だけを数える。
 - 画面が「まとめない」のときは設定を出さず、そう書く（押しても何も
   起きないチェックを置かない）。

**② 申し送り（コメント）。**
 - 予定の列へ挟む1行。入口は設備停止のとなり、差し込む位置の決まりも同じ
   （§9.179のカーソル位置）。
 - **時間を取らない**のが設備停止との違い。`kind='コメント'`は見積0分で、
   `expand_plan`は**カーソルを進めない**——申し送りを1行入れるたびに後ろの
   予定が押されるのでは、書く気が失せる。
 - 紙では**横いっぱいの1行**（列に押し込むと読めない幅になる）。
 - あわせて、紙の下に**手書きの申し送り欄**を付けられるようにした。
   **枚数を測るときにこの欄の高さを引くこと**——引き忘れると行で紙を埋めた
   あとに欄が押し出し、A4から溢れる（実測1188px > 1123px。`test_scprint`が
   捕まえた）。

固定は`tests/test_sccomment.js`と`tests/test_scprint.js`（13節）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **申し送り（コメント）は時間を取らない**（§9.189）: 予定の列へ挟む1行で、
  入口も差し込む位置の決まりも設備停止と同じ。違うのは`kind='コメント'`が
  **見積0分で`expand_plan`のカーソルを進めない**こと——1行入れるたびに後ろの
  予定が押されるのでは書く気が失せる。紙では**横いっぱいの1行**にする
  （列に押し込むと読めない）。**画面の「まとめ」は紙にも入れる**が、判定は
  `groupBucketOf`の1箇所を通し、日付ごとにページを分けているときの日付見出しは
  出さない（紙の頭と同じ文字になる。§9.129）。**見出し行を「行」として
  数えないこと**——枚数は実測で切るので、数えるとそのぶん予定が紙から抜ける。
  紙の下の申し送り欄も**高さを引いてから**行を詰めること（引き忘れるとA4から
  溢れる。実測1188px>1123px）。固定は`tests/test_sccomment.js`。
