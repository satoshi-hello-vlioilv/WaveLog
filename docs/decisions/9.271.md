# §9.271 `config/local.json` を読めなかったことを黙らない／置き場はフォルダで書ける（利用者の報告）

利用者の報告は「`\\nlmsrvngy03\工場内共有\検査データ\Records` を共有のメインに
したい。`master_db_path` にそこの `master.sqlite3` を書いたが**正しく読み込んで
いないようだ**」。

#### ① 読めなかったことを黙っていた

```python
def load_local_config():
 try:
  data=json.loads(path.read_text(encoding='utf-8'))
  return data if isinstance(data,dict) else {}
 except Exception:
  return {}          # ← 理由を捨てる
```

**このファイルは現場が手で書く。** そして Windows のエディタは、こちらが
想定していない形で保存する。実測した3つとも、上の書き方では
**「1つも書かれていない」のとまったく同じ**になっていた。

| 保存のされ方 | 何が起きるか |
|---|---|
| UTF-8（BOM付き） | `Unexpected UTF-8 BOM` → `{}` |
| ANSI／CP932（日本語コメント入り） | `UnicodeDecodeError` → `{}` |
| カンマを1つ多く打った | `JSONDecodeError` → `{}` |

`{}` は「上書き無し」なので、本体は既定の `db\master.sqlite3` を黙って読む。
**画面にもログにも何も出ない。** 利用者から見えるのは「書いたのに読まない」
だけで、打つ手がまったく無い。

直し方は2つで、**片方だけでは足りない**。

- **受ける** … `utf-8-sig`（BOM有無どちらも読める）→ 駄目なら `cp932`。
  現場が手で書くファイルなので、読めるものは読む。
- **黙らない** … 読めなかった理由を `paths.local_config_error()` に残し、
  **起動ログ**（`db_access` が値を使う場所）と**共通設定の段「置き場」**の
  両方に出す。文面は「**このファイルに書いた設定は1つも効いていません**」まで
  言い切る（§4。「読めません」だけでは何が起きているのか伝わらない）。

**「無い」と「読めない」は別のこと。** 無いのはふつうの状態（既定で動く）だが、
読めないのは事故で、打つ手も違う。`local_config_error()` は前者では `None`。

#### ② 置き場をフォルダで書けるのは作業予定だけだった

利用者は「**このフォルダに master.sqlite3 と schedule.sqlite3 を置く**」と
考える。ところが綴りの約束は揃っておらず、フォルダを書けるのは
作業予定（§9.262 `resolve_schedule_share`）**だけ**で、マスタと測定データは
ファイル名まで要求していた。同じ画面の同じ「置き場」なのに、行ごとに
書き方が違うことになる。

`db_access.resolve_db_file(raw, filename)` の**1箇所**が答え、
`resolve_schedule_share()` もそこへ委譲する。判定は §9.262 と同じく
**綴りだけ**（`.sqlite3`／`.db`／`.sqlite` で終わらなければフォルダ扱い）——
共有越しでは `is_dir()` が失敗することがあり、**存在確認そのものが唯一の
失敗原因になる**のを避ける。

#### ③ 環境変数で書くと「無いので作る」が押せなかった

§9.268 ④ で `paths.expand_path()` を入れたが、**§9.267 で足した2箇所を
通していなかった**。

- `storage_layout._planned_of()` … 「これから効く値」に `%LOCALAPPDATA%\WaveLog`
  が生で出る＝**どこへ置かれるのか画面から読めない**
- `storage_layout.prepare_path()` … 展開前は相対パスに見えるので
  **`絶対パスで指定してください` と断られる**。書いてあるのに否定する文言で、
  §9.267 が掲げた「設定さえ書いてあれば作る」が、変数で書いた端末では
  一度も効かない

どちらも**展開してから**扱う。**保存は生のまま**（§9.268 ④。展開して保存すると
端末ごとに違う文字列になり、同じ `local.json` を全端末へ配れなくなる）。

#### 固定

`tests/test_storage.py` の9〜11節。

- BOM付き・CP932は**読める**／壊れたJSONは**理由を返す**（`{}` を返すだけにしない）
- 理由が `layout()` の答えに入る（**作っても渡し忘れれば黙るのと同じ**）
- フォルダ指定がマスタ・測定データ・作業予定の**3つとも同じ関数で解ける**
- **本体が実際にそこを開く**こと——別プロセスで `db_access` を読み直して
  `_MASTER_PATH_CONFIGURED` を見る。「答えられる」だけを見る網は、
  **本体がその答えを使っていなくても通る**（§9.268で踏んだ形）
- 「これから効く値」も「作る先」も展開後であること

5つの欠陥（握り潰す形へ戻す／本体が `resolve_db_file` を通らない／
`prepare_path` が展開しない／`layout()` へ渡し忘れる／フォルダ規則を外す）で
それぞれ落ちることを確認済み。**例外で止めず報告すること**——
`prepare_path` を素で呼ぶ網は、断られた瞬間に以降の確認が1つも走らずに
終わっていた（§9.269と同じ罠）。

## 守ること（`CLAUDE.md` から移した規則の本文）
