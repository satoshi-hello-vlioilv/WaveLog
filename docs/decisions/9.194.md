# §9.194 結合の仕方を6通りから選ぶ／既定の品質データ結合を解除できる（利用者の指示）

**① 結合の仕方は6通り。** §9.193の結合は「この一覧は全部残し、当たった行に
列を足す」（左外部結合）の1通りしか無かった。利用者の指示は「6つの結合の
タイプ別に説明と共に視覚的にわかりやすい簡単な表サンプルや図などを組み合わせて
結合する方法を選ばせ」——SQLのJOINと同じ6通り（左外部／内部／右外部／完全外部／
この一覧にしかない行／相手にしかない行）を選べるようにした。

**② 6通りは3つの真偽値で表す**（`query_join.JOIN_KINDS`）。「一致した行」
「左にしかない行」「右にしかない行」のどれを残すか——この3つが決まれば
結合は決まる。**エンジンもこの3つで動き、画面のサンプル表もこの3つから
組み立てる**ので、「説明はこう書いてあるのに実際は違う」が原理的に起きない。
**判定を画面へ写さないこと**（§9.163と同じ理由）。既定は`left`で、
**動かさないこと**——保存済みの行は結合方法を持たないので、既定が変わると
設定を触っていない現場の一覧が黙って変わる。

**③ 「相手にしかない行」は一覧の全体と突き合わせる。** 表示中のページだけで
決めると、2ページ目に居る行を「相手にしかない」と数えてしまい、ページを繰る
たびに結果が変わる。`_left_key_set()`が**キーの列だけ**を読む（1行200列の
実データを丸ごと運ばない。§9.94）。読めなければページと突き合わせ、
**そのことを但し書きで言う**。相手を丸ごと読むのはこの3通りのときだけ
（それ以外は表示中の行のキーで絞る。共有越しに全件を運ぶと数十秒止まる）。

**④ 行が増減したことは必ず伝える。** 列が足されるだけだった頃と違い、
結合の仕方によっては一覧から行が消える／相手の行が増える。黙って変えると
「絞り込んでいないのに件数が合わない」としか見えないので、一覧の帯は
`-60行 +12行`のように出し、下見は`200 → 140行`と言う。

**⑤ 列を足さない結合では「何を足すか」を出さない。** 「この一覧にしかない
行」は当たっていない行だけを残すので、相手の値がそもそも無い。押せるのに
効かない欄を残さない（§4）。

**⑥ 突合キーは「実データの見本」つきで選ぶ。** `/api/table-columns?samples=1`
が先頭20行から3件だけ返す——`L0001`と`A-1`が突き合わないことは、値を見れば
分かる（推測させない）。同じ名前の列は候補として出し、まとめて足せる。
**名前のゆれを吸収する規則は画面へ書かない**——サーバーが返した正規化済みの
名前どうしを比べるだけにする。

**⑦ 既定の品質データ結合は解除できる**（利用者の指示）。パス設定マスタの
1行（`builtin_quality_join='off'`）で切る。**既定はon**——今まで何も設定せずに
品質列が出ていた現場の見え方を変えない。**解除してもエラーにしない**
（利用者の指示「該当する列データがないときには品質情報のデータが検索・表示
されないというだけでエラーなく使えるように」）: 列が足されなくなるだけで、
その列を見ていた設定（列レイアウト・フィルタ）は「無い列」として静かに落ちる。
**解除しても定義そのものは画面に出す**——「どうつないでいるのか」を見て
真似できることが値打ちなので、解除＝見えなくする、にはしない。
「複製して編集」でその設定を下敷きにした結合を作れる。

固定は`tests/test_qjoin.py`・`tests/test_qjoinui.js`。**図は「あること」
だけを見ないこと**——6枚が同じ絵でも「図が6つある」は通る。塗り分けの
種類を数える。

## 守ること（`CLAUDE.md` から移した規則の本文）

- **結合の仕方は「3つの真偽値」で持つ**（§9.194、`query_join.JOIN_KINDS`）:

  **「一致した行」「左にしかない行」「右にしかない行」のどれを残すか**で決まる。
  エンジンもこの3つで動き、**画面のサンプル表も同じ3つから組み立てる**ので、
  説明と実際の動きが食い違わない。**既定は`left`から動かさないこと**——保存済みの
  行は結合方法を持たないので、既定を変えると設定を触っていない現場の一覧が黙って
