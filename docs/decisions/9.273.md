# §9.273 遅い書き込みに「保存しています…」を出す（利用者の指示）

> 共有へ保存しているときに、少しタイムラグがあるので保存していますという
> メッセージが欲しいです。保存しましたというメッセージが出るまで6秒くらい
> 待たされます。

マスタを共有に置くと、保存は書込サイクル（ロック→取り直し→当てる→改訂番号→
押し出し・§9.263）を通る。実機で数秒。そのあいだ画面は無反応で、押した手応えが
何も無い——**もう一度押される**（そして順番待ちで409が返る）。

#### 出す場所は既にあった

`WL.saveState`（§9.212 ④）はタイトル帯の`#saveState`に「保存中…／保存しました／
保存できませんでした」を出す。ただし**使っていたのは列レイアウトの保存だけ**で、
マスタ管理の保存はトーストで「保存しました」と言うだけだった。だから利用者には
「終わったこと」しか伝わっていなかった。

#### 1箇所で出す——`api()`

保存の呼び出しは十数箇所に散っているので、**そこへ足さない**（足し忘れた画面
だけが無反応のまま残る）。**全部が通る`api()`**が出す。

  ・**非GET**なら500ms後に「保存しています…」
  ・返ってきたら「保存しました」／「保存できませんでした」
  ・`WL.saveState.run()`で包まれている保存には**手を出さない**
    （同じ場所に2つ書くと後から書いたほうが勝ち、文言が入れ替わる）

**500ms待つ**のは、手元にマスタを置いている端末では保存が一瞬で終わるため。
待たずに出すと**光って消えるだけの帯**になる（`tests/test_savechip.js`が
「速い保存では出さない」で固定）。

**やり直しのボタンは自動側では出さない。** `run()`は`fn`を持っているので
押し直せるが、`api()`は同じPOSTをもう一度投げることになり、**二重に書きうる**。
理由は呼んだ側のトーストが言うので、帯は状態だけを持つ（§8）。

#### 読むだけのPOSTには出さない

POSTでも書かないものがある（`access_mode._READ_ONLY_POST_ENDPOINTS`。RNEの抽出・
写しの取り直し・接続の下見・クエリ結合の解決・共有の取り込み・選択肢の使用回数）。
そこで「保存しています」と出すのは嘘。

**画面に同じ一覧を持たない**（必ず腐る）。**呼ぶ側が`quiet:true`の印を付ける**
——読みか書きかを知っているのは呼ぶ側で、それが1箇所に集まっている必要は無い。

**付け忘れ・付けすぎは`tests/test_savechip.py`が機械で数える**：Flaskの
`url_map`から「読むだけのPOST」のURLを引き、画面の`api()`の呼び出しと
突き合わせる。**付けすぎのほうも見る**——本物の保存に印を付けると、
利用者が欲しがっているまさにその場面で出なくなる。

#### 固定

`tests/test_savechip.py`（7件・印の付け忘れ/付けすぎ）と
`tests/test_savechip.js`（9件・実際の見え方）。後者は`page.route`で応答を
差し替えるので、**サーバーへは1件も届かない**（検証で本物のマスタを書き換えない）。

4つの欠陥（帯を出さない／待たずに出す／`quiet`を無視する／失敗にやり直しの
ボタンを出す）でそれぞれ落ちることを確認済み。
