# §9.407 刃組ガイダンスの「戻る」は来た道を戻る（利用者の指摘）

## 利用者の言葉

> 刃組ガイダンスへ遷移した後、戻るボタンから戻ったときに、作業スケジュール
> 一覧に戻れず、全体のスケジュール一覧に戻ってしまうので、**来た道を戻る形に
> 配線し直してください**。

## 何が起きていたか

戻るボタン（`#bsFrom`・§9.378）は**入口を2つにしない**ために、左メニューと
同じ口（`WL.scheduleView.open()`＝`openScheduleView()`）を呼んでいた。
ところが `openScheduleView()` は**開いたときの段を毎回決め直す**:

```js
scState.boardMode = scState.pickerEnabled ? 'board' : 'single';   // 直す前
```

設備を選べる端末（スケジュール／閲覧モード）では既定が**俯瞰ボード**なので、
どの段から送り出しても戻り先は俯瞰になる。**押した人から見れば「戻っていない」**
——しかも設備の選択まで見かけ上ふりだしに戻る。

これは「入口を1つにする」こと自体が悪いのではなく、**入口に『どこへ開くか』を
渡す口が無かった**のが原因。同じ関数を呼びながら、段だけを引き継げればよい。

## 直した形

- `openScheduleView(opts)` が `opts.mode`（`board`／`single`／`blade`）を受ける。
  決めるのは `boardModeOnOpen()` の1箇所——**渡されなければ今までの既定**、
  渡されたらその段。ただし `board` は設備を選べる端末しか持たない段なので、
  自設備固定の端末では `single` へ落とす（押せるのに何も起きない段へ戻さない）。
- 送り出す側（`SC_LINK_TARGETS.bladeset.open`）が `back:{mode:scState.boardMode}`
  を渡す。**刃組ガイダンスは段の名前を知らない**——鍵だけを預かり、
  呼び名は `WL.scheduleView.modeName()` が答える。
- 戻るボタンの字を**行き先の名前**にした。

  | 直す前 | 直した後 |
  | --- | --- |
  | `この予定から BS刃組み（テスト設備A）` | `作業スケジュール一覧へ戻る` ＋ `BS刃組み（テスト設備A）` |
  | `刃組スケジュール一覧`から来ても同じ | `刃組スケジュール一覧へ戻る` |

  押す前に**どこへ出るか**が読める（利用者に思い出させない）。

- 刃組の段（`blade`）へ戻るときは `switchToBlade()` をそのまま通す。予定に加えて
  **刃組の記録も要る**ので、一覧だけ描くと「未記録」しか出ない段になる。

## 呼び名は1つの表が持つ

段の鍵と**外向きの名前**は `SC_MODES` の1箇所:

| 鍵 | 札の字 | 外向きの名前 |
| --- | --- | --- |
| `board` | 全体 | スケジュール全体（俯瞰） |
| `single` | 個別 | **作業スケジュール一覧** |
| `blade` | 刃組 | **刃組スケジュール一覧** |

段を足すときは**ここにも1行足すこと**——足し忘れると、その段から送り出した
画面の戻り先が名無し（総称の「作業スケジュール」）になる。

### 撤回した案: 札のHTMLもこの表から作る

いちど3つのボタンを `SC_MODES.map()` で組み立てたが、**`tests/test_docindex.py`
が落ちた**——撮る道具（`tests/visual/capture.js`）が `#scModeBoard` を押すのに、
`id="scModeBoard"` という字がソースのどこにも無くなるため。`id` を文字列から
組み立てると、**押す側と押される側をつなぐ字が消える**。札のHTMLは素のまま
残し、表が持つのは鍵と外向きの名前だけにした。
