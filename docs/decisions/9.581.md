# §9.581 数の読み方は2つだけ（数として読めるか／書いてある通りに数か）——字の全体で読み、3桁区切りは正しい位置のときだけ・空欄は大小に当たらない

索引: [決定記録](README.md)｜前: [§9.580](9.580.md)｜関係: [§9.477](9.477.md)・[§9.111](9.111.md)・[§9.187](9.187.md)

## 経緯（利用者の指摘）

> 式（列の作り方）の部分で、3桁区切りの数値（例：1,200）が数として比較されていない可能性はありますか？
> 直してください。他にも計算式や表示ルールと絡めて不具合が発生しそうな部分がないかチェックをお願いします。

## 1. 測った（前）

数の読み方が**5箇所でばらばら**だった: 式の比較演算子（`strictNum`）・式の計算（`parseFloat`＝先頭だけ読む）・
表示ルールの比べ方（`looseNum`＝カンマをどこでも外す）・サーバーの並べ替え（`num_of`・同）・一覧の絞り込みの大小
（`Val()`＝先頭の数字だけ・読めなければ0）。物差しは入力→正しい答えの表（式42件・サーバー19件）と、
ルール↔変換した式（1400件）・画面↔サーバーの表示ルール（1152件）の突き合わせ。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 式の表（比較・連結・計算・丸め・誤差・空欄） | **23/42 誤り** | 0/42 |
| サーバーの表（読み方・絞り込み・式のルール） | **12/18 誤り** | 0/19 |
| 表示ルール ↔ 変換した式 | 0/1400 | 0/1400 |
| 表示ルール 画面 ↔ サーバー | — | 0/1152 |
| 空欄が「5より小さい」に当たる（表示ルール・式） | 当たる（「-5より大きい」には当たらない） | 当たらない |

前の誤りの中身:
- **比較演算子**: `'1,200' > 1000`・`'12.50' > 9`・`'+5' = 5` が字の比較になっていた（数にして字へ戻すと一致しない＝数ではない、と判定していた）。
- **`+`**: `'12A' + '3'` が 15、`'010' + '3'` が 13（説明は「片方が文字なら連結」）。
- **計算と num()**: `'2026-10-11' * 1` が 2026、`'12A' * 2` が 24（先頭だけ読む）。
- **誤差と丸め**: `0.1 + 0.2` が 0.30000000000000004（`= 0.3` が偽）、`round(1.005,2)` が 1、`round(-2.5,0)` が -2。
- **崩れた3桁区切り**: `'1,2'` が 12、`'12,00'` が 1200（表示ルール・サーバーの並べ替え・書式）。
- **一覧の絞り込み（以上・以下）**: `'1,200'` が 1（1000より大きいに当たらない）、空欄・`'abc'` が 0（5より小さいに当たる）、`'12A'` が 12。
- **サーバーの「表示の値で並べる」**: 式を使う表示ルール（条件の式・「式が真なら」・`=`で始まる表示）を字として扱い、画面の表示と並びが食い違っていた。

## 2. 決めたこと

- **読み方は2つだけ**（`static/js/list/list-formula.js`の1箇所。`WL.formula.looseNum`を書式・並べ替えの分類も呼ぶ）:
  - `looseNum` … **数として読めるか**。字の全体が数のときだけ（前後の空白・正しい位置の3桁区切り・先頭のゼロ・`+`・末尾のゼロ・`.5`）。
  - `strictNum` … **書いてある通りに数か**。looseNum に加えて整数の部分が0で始まらない（`010`・`007` はコード＝字）。
- **使い分け**: 比較演算子と`+`は strictNum（数か字かを決める所）、計算（`- * / %`・関数）と`cmp()`（表示ルールの比べ方）は looseNum。
- サーバーは`sort_order.num_of()`が同じ決まり（正規表現を写す・網が同じ例で見張る）。一覧の絞り込みは`NumOf()`（接続が登録）で読み、読めない値は NULL＝当たらない。打った境の値が読めなければ何にも当たらない。
- **計算の結果は15桁へ丸める**（`tidy`）。**四捨五入は10進でずらし、0から遠い側へ**（Excel の ROUND と同じ）。
- **大小は空欄を比べない**（`WL.formula.ordered()`・式の`<`等・表示ルールの大小と範囲・サーバーの`rule_test`）。`=`／`<>`は空欄どうしの一致を見たいので対象外。空欄を当てたいときは「空欄」の比べ方。ルールを式へ変換するときは`trim(x) <> ''`を添えて同じ答えにする。
- **式を使う表示ルールはサーバーで表示の値を作らない**（`sort_order.rules_need_formula()`）。式を解くのは画面の`WL.formula`の1箇所——サーバーへ写しを作らず、並べ替えは「表示の値では並べ替えられません」と言ってふだんの並びへ倒す。

## 3. 残したこと（分からない・別の作業）

- **日付の大小**: `'2026/9/30'`と`'2026/10/1'`は字で比べる（0埋めの無い日付は順が逆になる）。式に日付の型を足す話で、今回は触っていない。
- **小計の数の読み方**（`subtotalNum`・単位つき）と**マスタ管理の欄の数**（`master-maint.js`）は、単位を読む／打った値を整えるという別の役目なので今回は統一していない。
