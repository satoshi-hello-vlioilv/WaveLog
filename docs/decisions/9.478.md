# §9.478 表示ルールの「表示の値」の速さを測った——描き直しへの影響は揺れの中（利用者の指示）

索引: [決定記録](README.md)

## 経緯

振り返りの評価で挙げた「表示の値の速さを測っていない」（§9.474 は Proxy で見ている列だけを引く作りに
したが、実測していなかった）。利用者の指示「1から4まで順番に進めてください」の2。

## 測った（1728×1030・仕掛一覧 1000行・読み替えを持つ列3つ・`scratchpad/test_zprobeperf.js`）

| 条件の見方 | 一覧の描き直し（中央値） | セル1つあたりの読み替え |
| --- | --- | --- |
| 読み替えなし | 176ms | 0.23µs |
| 元のデータ | 165ms | 0.79µs |
| 表示の値（他の列2つを見る・書式つき） | 159ms | 1.07µs |
| 表示の値で**読み替え付きの式の列**を見る | 164ms | 2.58µs |

- 表示の値の上乗せは**セル1つあたり 0.3〜1.8µs**。1000行×3列を全部通しても 1〜8ms。
- 一覧の描き直しは画面に出す行（88行）しか作らない（§9.94・§9.104）ので、差は約160msの揺れの中に埋もれる。
- 最初の測り方では式の列を**セルのたびに解き直して**いて 5.86µs と出た——製品（`list-view.js`の`colCalc`）は
  列ごとに1回だけ解くので、測る側を同じにして測り直した（測る側の作りで数字を盛らない）。

## 決めたこと

- 作りは変えない（重くないので、Proxy で見ている列だけを引く作りのまま）。
- **重くなる作り直しだけを捕まえる網**を置く: 読み替え付きの式の列を表示の値で見ても、セル1つあたり
  30µs 未満（実測の約10倍の余白・時間の網は余白を大きく取る・§9.426）。

## 網

`test_colrule.js`: 1000行×3回で、表示の値・読み替え付きの式の列を見るルールのセル1つあたりが 30µs 未満。
