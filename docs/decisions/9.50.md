# §9.50 RNE抽出の状態表示と手動実行

仕掛/品質データのローカル運用(`sikalot_source=local`)の抽出は、
`rne_scheduler` が起動時に1回＋`rne_extract_interval_sec`ごとに背景で回す
だけだった。**成否はアプリログにしか出ず、画面からは動いているのかも
分からず、今すぐ取り直す手段も無かった**(「実際に起動させる方法が分からない」
という指摘)。マスタ管理 > パス設定の下部へ状態パネルを置く。

- `GET /api/rne-extract/status` … 有効/停止・実行中か・直近の成否と行数・
  抽出先ファイルの最終更新・**資材(RNE/symnavim.conf)が配置されているか**・
  次回間隔。`sikalot_source`が`network`のときは「停止中」と、有効化の手順
  (localにして保存 → **サーバー再起動**)を画面へ出す。
- `POST /api/rne-extract/run` … 「今すぐ抽出」。抽出は数十秒かかり得るので
  背景スレッドで走らせて即座に返し、画面は`/status`を2秒間隔で追う
  (実行中のあいだだけ。終わったら止める)。
- 二重実行は `_run_lock`(非ブロッキング)で止める。定期実行と手動実行が
  重なったら定期側がその周回を飛ばす(次の周回で追いつく)。

**抽出は取得元(`sikalot_source`)と独立して実行できる。** 「抽出の成果物を
仕掛一覧が読むか」と「抽出を回すか」は別の関心事で、共有から読みつつ
ローカルの複製を作っておきたい/配置と接続を試したい、という運用があるため。

| | 決め方 |
|---|---|
| 定期実行 | パス設定マスタの `rne_extract_enabled`。`auto`(既定)=`sikalot_source=='local'`のときだけ / `on`=取得元に関わらず回す / `off`=回さない |
| 手動実行 | 上の設定にも取得元にも依らない。資材(RNE・`symnavim.conf`)が揃っていればいつでも実行できる |

- `start()`は**常にスレッドを立てる**。可否は`_loop()`が毎周回`schedule_enabled()`で
  読み直すので、`on`へ変えれば再起動なしで回り始める。
- `extract_possible()`(資材の有無)と`schedule_enabled()`(定期実行の可否)を
  分けて`/status`へ返す(`canRun`/`enabled`)。画面はボタンの活殺を`canRun`で、
  「定期実行 有効/停止中」の表示を`enabled`で出す。
- `run` は**データを書き換えず抽出元から読み直すだけ**なので、
  `_READ_ONLY_POST_ENDPOINTS` で書込ガードの対象外にしてある
  (閲覧モードの端末からも取り直せる)。
