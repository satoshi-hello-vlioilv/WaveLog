# §9.608 公差の図の行を表の行へそろえ続ける・測定データ分析の数をはみ出させない（利用者の指摘）

索引: [決定記録](README.md)｜前: [§9.607](9.607.md)｜関係: [§9.150](9.150.md)・[§9.214](9.214.md)・[§9.415](9.415.md)

## 経緯（利用者の言葉）

> チェック用の左の表の行と板厚の幅位置や板幅用の条の行位置が合っていないのでその部分をそろえてください。わかりにくいです。
>
> 数値がはみ出ているので修正してください。（測定データ分析の「100.0001000.000」）

## 1. 公差の図の行（`test_dimboth` D7）

図の行の高さ（`--tc-head`／`--tc-row`）は `alignToleranceChart()` が表を測って入れる。測るのは**描いたその場の1回だけ**だったので、
そのあと表だけが動くと図がずれた。窓を伏せたまま描く（保存した測定を開き直す `resumeStoredMeasure` は描いてから窓を出す）と、
高さ0を読んで測らずに飛ばしていた。

| 場面（板厚の表／板幅の表のずれ・最大 px） | 前 | 後 |
| --- | --- | --- |
| 開いたまま・条を減らす・手で打つ・窓の大きさ・丈の往復 | 0.5／0.5 | 0.5／0.5 |
| 表示サイズ「大」 | 10.1／7.1 | 0.5／0.5 |
| 窓を伏せて描いてから出す（開き直し） | 34.2／21.9 | 0.5／0.5 |

- 表の大きさが変わるたびに測り直す。見張りは表ごとの `ResizeObserver` の1つ（`mxAlignWatch`・描き直しで付け替える）。
  図の変数は図にしか効かないので、測り直しが表を動かして回り続けることは無い。

## 2. 測定データ分析の数（`test_dimboth` D8）

MIN と MAX を2つに割った枠（`grid 1fr 1fr`）へ押し込んでいたので、桁の多い値（1000.000）が隣へ食い込み、カードの縁を越えた
（1728px で 20px・1536px で 32px）。数の幅のまま横に並べ、入らなければ MAX を下の段へ折り返す（`flex-wrap`）。前後 1件→0件（両方の大きさ）。
