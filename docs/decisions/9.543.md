# §9.543 換算係数——見積と実績の散布図・1ロットの積み上げ・係数の効き目と上書き（利用者の選択 H-1＋H-5＋H-2）

索引: [決定記録](README.md)

## 利用者の言葉と選んだ経緯

マスタの視覚化の候補 H「換算係数」。H-1〜H-5（スクラッチの `mockH.js`・見本の実績120件は画面の中だけ）を見て
**「H-1とH-5とH-2の組み合わせでお願いします。」**

- H-1: 見積×実績の散布図（主役）。
- H-5: 1ロットの見積の積み上げ（基準時間×係数）。散布図の点から開く。
- H-2: 係数の効き目（フォレスト図）と、その場での上書き。今の係数の表を置き換える。

並べ方: 上＝要約の数（当たっているか）／左＝散布図と、その下に押した点の積み上げ／右＝係数の図と、その下に上書きの欄。
「当たっているか → このロットはなぜこの分数か → どの係数をどう直すか」を左上から右下への1本の流れで読む（基準14）。
積み上げの段を押すと右の図でその係数が選ばれる（H-5 → H-2）。

## 調べて分かったこと（案の前提）

- サーバーは**設備ごとのモデルの要約しか返していなかった**（基準時間T0・σ・件数・係数）。1件ごとの実績と見積を返す口は無かった。
- 精度の口（`GET /api/schedule/accuracy`）は、見積を**基準時間T0だけで代用**した粗い指標だった（因子を当てていない）。
- 画面は因子の名前を**英字のキーのまま**（`purposeName`・`mfgThickness`…）出し、ばらつきを対数の数（σ）のまま出していた。

## 測った（評価関数）

物差しはスクラッチの `eval_lf.js`。検証用の設備Aに**完了実績48件を本物の保存の口**（`POST /api/measurement/backup`）から入れて測り、
終わったら消す（`backup/delete`・再計算でモデルが無い状態へ戻ることを確かめる）。**正解は画面と独立に**作る:
実績は入れた分数、見積はサーバーが公開する係数・区切り・上書きを網で当てはめた値、外れ値は中央値±3×1.4826×MAD（対数）。

| 物差し | 前（VER2.429.0） | 後 |
| --- | --- | --- |
| ロットごとの実績と見積が正しい値で出ている | 0/48 | 48/48 |
| 要約の数（±20%に入った割合・実績÷見積の中央値・外れ値の件数） | 1/3（外れ値の件数だけ字で出ていた） | 3/3 |
| 英字のキーのまま出ている因子名 | 18 | 0 |
| 1ロットの積み上げが見積に一致する | 0/1 | 1/1 |
| 保存の前に「効くロットと見積の変わり方」を正しく言う | 0/1 | 1/1 |
| 上書きの保存と解除 | できる（1回押す） | できる（1回押す） |

測り方の直し（2つ・正直に書く）:
- ②は最初、画面の印（data属性）だけを見ていた。前の画面は外れ値の件数を**字で**出していたので、字も数えるように直してから「前」を取り直した（0/3 → 1/3）。
- ④の許容は「後」を測る前に 0.15分 → **0.3分**へ緩めた。係数が小数3桁に丸めて返るので、6つ掛けると最大0.3分ずれる（純粋な網と同じ許容）。

網: `test_lfpoints.py`（10件・サーバー不要）と `test_lfui.js`（14件）。欠陥を入れて確かめた:
- 点の見積で手動上書きを無視する → 両方の網が落ちる。
- 保存の前の「見積の変わり方」を、今の係数で割らずに数える → `test_lfui.js` ④が落ちる。

## 決めたこと

- **1件ごとの実績と見積・外れ値・要約はサーバーの1箇所**（`load_factor.points()`）。見積は**予定と同じ `estimate_work()`**
  （手動上書きも効いた値・因子ごとの内訳つき）を完了実績の明細へ当てたもの——上書きを保存し直せば点も動く。
  応答は既存の `GET /api/schedule/load-factors` に載せた（`points`・`accuracy`・`factorLabels`）。新しいルートは足さない
  （`schedule.py`はルート数が上限）。
- **外れ値の判定は `outlier_flags()` の1箇所**（推定の `_fit` と点が同じ答えを読む）。
- `GET /api/schedule/accuracy` と `load_factor.accuracy()` は**消した**（使い手は今の画面だけで、中身は T0 だけの代用だった）。
- **因子の呼び名は `FACTOR_LABELS` の1箇所**（用途・材質・調質・板厚・板幅・板丈・条数・丈割数・作業人数と単位）。画面へ英字のキーを出さない。
- 帯は真ん中の80%（±1.2816σ）。「±20%に入った割合」と「帯に入った数」は別の物差しとして両方出す（前者は現場の言葉、後者はモデルの言葉）。
- 点は新しい順に1000件まで（`POINTS_MAX`）。要約は全件で数える。数が切れたら凡例が「新しいN件を表示（全M件）」と言う。
- 係数の図の水準の並び: 数の水準は小さい順、字の水準は件数の多い順。10件未満の水準は白抜き（×1寄りに縮めてある）。
- 打った値の◆は**物差しの外なら端で止め**、値は字で添える（打っている途中に物差しが動くと読めない）。
- 換算係数の画面は `master-data.js` から `master-loadfactor.js` へ移した（`registerSpecial('load-factor')` の名乗りも移す）。

## 分からないこと

- 現場の実績でこのモデルがどのくらい当たっているかは、この環境には完了実績が無いので分からない。
- 全設備をまとめたモデル（basis='pooled'）のとき、点の外れ値はこの設備の実績だけで判定する（推定は全設備で判定している）。
  数え方が違うので、件数が推定の「除外」と食い違うことがある。実害があるかは使ってみないと分からない。
