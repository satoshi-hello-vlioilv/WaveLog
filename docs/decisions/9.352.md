# §9.352 拡張は登録表へ。被せ（退避して差し替え）も全置換も作らない

`docs/REVIEW_2026-09.md` §6.3 3-16「装飾チェーンを『登録表』へ」の第2弾（第1弾は §9.348）。
振る舞いは変えない。

## 何が起きていたか

第1弾のあとも、`const base=fn; fn=function(){…base()…}` の**被せが21件**、元を呼ばずに
丸ごと差し替える**全置換が2件**（`test_patchlint` の `ALLOWED`）残っていた。
被せは読み込み順が答えの順になり（`JS_FILES` の並びにしか順番の意味が無い）、
引数を1つ落とすと根まで届かない（§9.125 で実際に起きた）。網の正規表現が
行頭の `fn=function` しか見ていなかったので、`{const old=selectTable;selectTable=async
function…}` のような**行の途中の被せ3件は数にも入っていなかった**（quality-analysis.js）。

## 決めたこと

1. **登録表は土台（`base.js` の `WL.measureHooks`）に置く。** 測定画面のファイルより先に
   読まれ、`markDirty` のように土台の関数からも呼べる。口は3つ:
   - `on(name,fn)` … **あとに足す**。登録順に走り、1つが転んでも残りは走る（fail-open）
   - `gate(name,fn,{priority})` … **前で断る／引数を差し替える**。`false`＝呼び出しは何もしない、
     配列＝次の引数、`undefined`＝次へ。priority の大きい順（被せの「外側が先」を保つ）
   - `own(name,fn)` … **丸ごと持つ**（1つだけ）。核は持ち主が居ればそれを呼ぶ
   名前は**呼ぶ側（核）が決め、核の1箇所にだけ書く**。一覧側は `WL.listHooks`（§9.93）に
   `onTabs`／`onGrid`／`onBeforeSelectTable`／`onSelect` を足した。
2. 移した先（21＋2＋3件 → **0**）:
   - あとに足す: `afterGrid`・`afterGridVertical`・`afterFocus`・`afterDirty`・`afterSave`・
     `afterValidation`・`afterBindInputs`・`afterOptionFill`・`afterOpenMeasurement`・
     `afterResumeStoredMeasure`・`collect`／`shape`（回収した値・持ち物へ足す）・
     `beforeDeviceInput`／`afterDeviceInput`、一覧の `tabs`・`grid`・`select`
   - 前で断る: `openMeasurement`（lot-split＝子ロットなら親へ読み替え・priority 20 →
     access-mode＝編集モードか・10）、`resumeRecordFromList`・`openRecords`（access-mode）、
     `persistAndTransition`（完了前の確認）、一覧の `beforeSelectTable`（フィルタの文脈）
   - 丸ごと持つ: `workTimePanel`（作業時間パネルは worklog が持ち主）
   - 公差の登録表（`WL.tolerance`）に `facts(kind)`／`scale(kind,values,count)` の口を足し、
     指示型のカードと数直線を提供者へ。`compactToleranceData` は lot-split の全置換の中身
     （index 省略時は今の入力位置・基準値は提供者の値を優先）を核へ移した。
3. `test_patchlint` は「被せが**0**」「全置換が0（`ALLOWED` は空）」を固め、行の途中の
   被せも拾う。注いだ3件（行頭・途中・全置換）を数える自己検査つき。

## 触っていない／変えたこと

- 核の `compactToleranceData` の基準値の既定は `TOL_DIMENSIONS[kind].baseKey`
  （板丈なら `mfgLength`）。lot-split の全置換は板厚以外を `mfgWidth` にしていたが、
  提供者が基準値を返さない板丈のときだけ違う値になる（そちらが正しい）。
- `window.updateValidationVisuals`／`window.persistAndTransition` の再公開は要らなくなった
  （核の関数そのものが残るので）。

## 罠

- 被せの `finally` は**早期 return でも走る**（lot-split の openMeasurement）。核へ移すときは
  関門→`try{核}finally{あとのフック}` の形にして同じにする。関門で断ったときは
  あとのフックも走らない（元も `return` が try の外だった）。
- 網は「行頭の代入」だけ見ていた。**見張っている形と実際の形が違うと、0件の網は緑のまま**。
  自己検査には実際の形（行の途中）も注ぐ。

## 追補: 通しで1回だけ落ちた `test_choicelinkui`

第2弾のあとの通し（6,117件）で、`test_choicelinkui` の「掴んで親の箱へ落とす」だけが
**帯の字待ちの15秒で切れて FATAL**（6113/6117）。単独では 14/14、3-16 前の JS でも 14/14、
通しで直前に回る7本と続けても 230/230 で**再現しない**。網は直前の「④-c」で既に出ている
「結びました」と同じ字を待っていたので、落とし込みが捨てられても素通りする作りだった
（落ちたのは字が**別のもの**——「保存しています…」のままか断りの文——だったことを意味する）。
**掴む前の字を控えて「変わって『結びました』になる」を30秒待ち、切れたら帯の字をそのまま
記録に出す**形へ直した。次に落ちたときは仕組みが読める。製品側の `clConnect` は保存中の
落とし込みを黙って捨てる（`if(clState.busy)return`）——「できないことは、できないと書く」の
候補として残す。
