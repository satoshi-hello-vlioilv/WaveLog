# §9.200 変更が元へ戻る／保存できない（404）／行の色とアイコンのUI（利用者の報告）

利用者の報告は2件。①「行の見せ方のUIをもう少しわかりやすく使いやすくしてほしい。
不具合もあり、実際に変更ができない不具合があります」（画面には
「行の見せ方を保存できませんでした / `<!doctype html> … 404 Not Found`」という
トーストが出ていた）②「スケジュールを入れ替えたり変更して位置が変わっても、
画面を切り替えて戻ってくると位置が元に戻ってしまっています。保存のタイミングが
ないまま新規を読み込んでいるような挙動」。

**① 取得中の応答は「いつの分か」で捨てる（＝並べ替えが元へ戻る真因）。**
予定を変えると`invalidatePlanCache()`でキャッシュを捨てるが、**そのとき既に
飛んでいるGETは止められない**。返ってくるのは変更前の内容なので、素直に
`scPlanCache`へ入れて画面へ当てると、
`並べ替える → 画面は新しい順 → 少し遅れて古い応答が届く → 元の順に戻る`
となる。しかも古い内容がキャッシュに残るので、**画面を切り替えて戻ると
その古い順が出る**——利用者の言う「保存のタイミングがないまま新規を
読み込んでいるような挙動」そのもの。

直し方は世代（`scPlanGen`）を1つ持ち、**取りに行った時点と戻ってきた時点で
世代が違えば捨てる**。捨てる場所は、予定を取りうる3箇所すべて
（`planApply` / `warmPlan` の先読み / `prefetchSchedule` の起動時先読み）。
あわせて書込のあとの取り直しを`loadPlan()`から**`loadPlan(true)`**へ変えた
——キャッシュ可のままだと、古い応答が先にキャッシュへ入っていた場合に
それをそのまま画面へ戻していた。
**件数や設備名で見分けようとしないこと**：並べ替えは件数も設備も変わらない。

再現は`tests/test_scsave.js`。**1本目のGETだけ「先に取ってから、届けるのを
3秒遅らせる」**——`route.continue()`の前に待つとサーバーへ届くのが3秒後に
なり、返ってくるのは並べ替え**後**の内容なので競合そのものが起きない
（直す前でも通ってしまう。実際に2度通した）。世代の判定を無効化すると
「遅れて届いた変更前の応答で画面を巻き戻さない」が落ちることを確認済み。

**② 応答がJSONでないときは、状態コードから言い直す。**
`api()`は本文をJSONとして読めないとき`{error:本文}`にしていたため、Flaskの
404ページ（HTML）がそのまま`Error.message`になり、**トーストにHTMLが丸ごと
出ていた**。読む側に要るのは「何が起きたか」と「次に何をすればよいか」なので、
404/405/403/409/423/5xxを日本語へ言い直す。生の本文は`err.body`（先頭500字）
に残す。**JSONで`error`が返っているときは今までどおりその文言を使う**
——サーバーが理由を書いているのに、こちらで上書きしてはいけない。

**③ 「更新は届いたが、まだ再起動していない」をサーバーが答える。**
404の真因はこれだった。**JS/CSSはリクエストのたびにディスクから配られるが、
Pythonはプロセス起動時に読み込んだきり**なので、更新後に再起動を忘れると
**新しい画面が古いサーバーへ話しかける**。画面からは「保存できない」としか
見えない。`GET /api/build`が`restartNeeded`（起動より後に更新された`.py`が
あるか。True/False/**None＝確かめられなかった**）を返し、左メニューの版数の
すぐ下に理由と打つ手を出す（`#restartNeeded`。気づく場所と打つ手を同じ場所に
置く・§9.183と同じ作法）。**Noneを「要再起動」と同じに扱わない**——`stat()`は
共有越しで落ちうる。**この判定で`/api/build`を失敗させないこと**
（`guard.probe()`の生存確認が読んでいる）。

**④ 行の色とアイコンのUIを作り直す。**
- **アイコンは絵を見たまま選ぶ。** 以前は名前だけの選択欄で、選ぶ前に
  どんな絵か分からず、しかも名前に「(絵文字)」が付いていて器から**見切れて
  いた**（実機で「工具(絵文…」）。いまはボタンに**いまの絵と呼び名**を出し、
  押すと絵の一覧（決めない／絵文字／記号／線画）が開く。名前から
  「(絵文字)」を外し、種類は一覧の見出しが言う。
- **「既定」の枠には、その区分の元の絵を出す。** 名前と同じ字を絵の場所へ
  置くと「既定／既定」と2度読ませることになる。元の絵は
  `rowStyleBaseIcon()`の1箇所が答え、見本・入口のボタン・選ぶ盤の3つが
  同じものを見る。
- **色の目安を1行だけ先に書く**（灰=目立たせない…紫=臨時・特別）。
  行ごとの`title`に隠すと、8色が何を表すのかを覚えていないと選べない。
- 段の見出しと同じ「行の色とアイコン」を中でもう一度出さない（§8）。
- 行の右端は「⟲ 戻す」。押せないときは**理由を`title`に書く**
  （「この区分はまだ設定していません」）。

**⑤ 並べ替えを中止したときは画面に出す。** `commitDragOrder()`は画面と状態の
件数が食い違うと順序を壊さないために中止するが、`console.warn`だけだったので
**「動かしたのに元へ戻った」としか見えなかった**。件数と打つ手（再計算で
読み直す）を文字で出す。

**⑥ ついでに、赤いまま残っていた3件を直した。** 通しで常に落ちる網は
「落ちても気にしない」ことを教えるだけで、本物の退行を隠す。3件とも
**製品ではなくテスト側が古かった**:
- `test_scbatch`「まとめても全件がサーバーへ保存される」…数えていたのが
  `state==='予定'`だけだった。**追加したロットに実績があると、その行は
  突合で「完了」として返る**（落ちたのではない。実測で12件投入→予定+10・
  完了+2）。全件で数えるように直した。
- `test_wkfast`「『再計算』では情報源を取り直す」…`include_hidden=1`が
  付いた問い合わせを数えていたが、**§9.165でその引数ごと廃止**したので
  1件も数えていなかった。あわせて製品側も直した——作業可否の見張りは
  「まだ可でない行があるとき」しか動かないため、全部が可になっていると
  **押しても材料が古いまま**だった。押したときだけ材料を捨てて裏で
  取り直す（`refreshCurrentMode(force)`）。
- `test_msteps`「オペレータの選択肢を減らしていない」…`>=100`と実データ
  (171人)の数を直に書いていたため、検証用フィクスチャ(29人)では
  **必ず落ちた**。マスタの件数と選択肢の件数を突き合わせる形へ直した。
