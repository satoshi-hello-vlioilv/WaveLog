# §9.125 測定画面の再設計 第3段: ①準備の整理と③完了前の確認表

第1段で器を、第2段で②の中身を作った。残っていたのが**①準備**と**③確認**で、
どちらも「今までのペインをそのまま置いただけ」だった。

#### ①準備: 18個の設定を役割でまとめ、その他は畳む

選択項目は18個が意味のない順に並んでいた。役割で分け、見出しを付ける。

| 見出し | 中身 |
|---|---|
| 誰が測るか | オペレータ・検査員・作業人数 |
| 測定表の形 | 縦割数・横割数 |
| 使う機材 | 内径・スプール・板厚測定器・板幅測定器 |
| その他の設定（既定で畳む） | 巻出方向・条入力順・方向・バリ揃え・コイル止め |

**畳む5つを決めた根拠は憶測ではない。** 既存コードに2つの証拠がある——
`report-dashboard.js`の`SOFT_CHOICE_IDS`（未選択なら色で促す6項目＝畳んでは
いけないもの）と、`30-measure.css`のコメント「条入力順・方向はプリセット値の
ままで問題ないことが多い」。

**畳んだままでも値は読める。** 要約に5つの現在値を並べ、既定と違うものは
印を付けて「N件が既定と違います」と数で言う。隠したものが何かを書かずに
隠すと、設定がそこにあること自体が忘れられる。コイル止めの既定は**ロット
由来**（`innerTape`）なので定数で持たない——内巻両面テープのロットで常に
「既定と違う」と出てしまう。

**「入力内容」「丈位置」は①から外して②へ移した。** どちらも測りながら
何度も切り替えるもので、1回決める設定と同じ場所に並べるものではない。
副産物として、**②に丈位置が出るようになった**——`PageUp/PageDown`で
動かせるのに、それまでどの段にも出ておらず「いま何丈目か」は`#stepStatus`の
文でしか分からなかった。高さは`size`（選択肢の数）に合わせる。CSSでは
リストボックスの高さを中身に合わせられない。

**並べ替えは`order`だけで行い、DOMは動かさない**（受信欄の制約と、②の
`.selectors>*`の規則を壊さないため。§9.122）。

#### ③確認: 完了前の確認表

未測定も公差外も、それまでは**完了を押した後**の確認ダイアログでしか
分からなかった。押す前に見えれば直しに戻れる。

| 行 | 出すもの |
|---|---|
| 測定 | `済/対象` と未測定の項目名・充足数 |
| 公差外 | 件数・項目・**どの丈位置か**・判定していない項目 |
| 作業時間 | 開始/終了の記録状態 |
| 対象外 | 意図して外した項目（あるときだけ） |

**保存状態はここに出さない**（ヘッダーに常時ある）。**完了ボタンも置かない**
（操作レールに常時ある）。同じものが2箇所にあること自体が認知コスト。
各行の「直す」は**直せる場所まで連れて行く**——②へ移り、該当項目と該当
丈位置を選ぶ。番号を言うだけでは探させることになる。

#### 公差外は画面ではなくデータから数える

`updateValidationVisuals()`が見るのは**いま描かれているグリッドだけ**なので、
別の丈位置・別の項目にある公差外は完了まで誰も気づけない（進捗を全項目から
数えているのと同じ理由。`measure-progress.js`の存在理由そのもの）。

##### 3つのラッパーが引数を落としていた

`toleranceDetail(kind,index)`は**3つのファイルが順に包んでいる**。

| ファイル | 何をするか |
|---|---|
| `lot-split.js` | 分割ロットなら子ロットごとの公差を返す |
| `measure-worklog.js` | 指示型（ラテラルボー等）なら`[0,指示値]` |
| `measure-tolerance.js` | 寸法型なら根の関数、それ以外は指示公差 |

どれも**`#measureType`（画面の選択）を見て**分岐し、余分な引数を捨てる。
根の関数に「項目名」の引数を足しても届かない。実際、最初の実装では
**全項目に「いま選ばれている項目の公差」が当たり**、公差の無いラテラルボーが
板幅の公差で判定されて偽の1件が出た。3つすべてに第3引数を通して直した。

**この壊れ方は、注入検証をしていなければ気づかなかった。** 検証用
フィクスチャには公差が1件も入っていないため、公差の材料ごと注ぎ込まない
限り「0件」しか出ず、**壊れていても同じ結果**になる。

##### 公差が無い項目を「合格」に混ぜない

バリ・テレスコープ・巻ずれはマスタに公差が無く、画面でも判定していない。
これを合格と同じに見せると、確認したつもりで何も確認していないことになる。
**項目名で言う**（値の件数で言うと、測るたびに増えて読まれなくなる）。

固定は`tests/test_msteps.js`（68件）。2つの欠陥（ラッパーが引数を落とす／
描かれている丈位置しか見ない）を注入し、それぞれ落ちることを確かめてある。

## 守ること（`CLAUDE.md` から移した規則の本文）
