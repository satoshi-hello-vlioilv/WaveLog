# §9.26 分割バーが他画面へ残る不具合(§9.10・§9.17の修正)

scheduleモードでサイドバーの「仕掛（現在）」を押したとき、
`selectDb`ラッパーが「scheduleモードかつ設備選択済みなら`exitScheduleView()`
しない」という特例を持っていたため、**利用者は一覧へ移動したつもりでも
スケジュールパネルと幅調整の分割バーが残ったまま**になっていた
(「スケジュールの幅位置調整スライダーが他の画面へ侵食する」として報告)。
これはサイドバーが画面の切替であるという§9.1・ARCHITECTURE.md
「画面の開き方・閉じ方の約束」に反する。

判定を「**呼び出し元が内部かどうか**」(`scInternalDbSwitch`)へ変更した。
分割表示を組み立てるために`showSplitList()`が自分で呼ぶ`selectDb`だけが
画面を閉じない扱いになり、利用者のサイドバー操作では必ずスケジュール画面から
出る。分割表示は今までどおり`refreshAll()`→`showSplitList()`で自動的に出る。
