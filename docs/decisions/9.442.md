# §9.442 拡大図は押した軸の半断面／記号は軸で色を分ける／上下刃の中心間は出さない

索引: [決定記録](README.md)

利用者の指示:

> ガイダンスの拡大図で、**上軸は上の図、下軸は下の図を選ぶ**ようにしてほしいです。
> **アルファベットも少し色がわかっていると違いが出て**わかりやすいです。
> また、**上下刃の中心線は、拡大図に不要**です。表示が重ならないように注意して
> 表示をお願いします。

---

## ① 下軸を押しても上軸の図が出ていた

### 何が起きていたか

拡大図は `zoomFigure(res, r)` が組むが、どの区間から組むかは

```js
const z0 = (r.zones || [])[0];            // ← 先に来たほう
const P = res.zp.zones[z0.i][z0.upper ? 'up' : 'lo'];
```

だった。**同じ記号（A・B…）は上下軸の両方に出る**——記号は「同じ組み方」を
束ねた印で、軸はその置き場所だから。千鳥では `A` が上軸の奇数番目と下軸の
偶数番目に並ぶので、**下軸の A を押しても `r.zones[0]`（上軸のほう）で開いて
いた。**

### 欠陥注入で確かめた

押した軸を無視する作り（直す前）へ戻すと、網が**利用者の報告そのもの**を出す:

```
{"up":{"asked":"up","got":"up","zone":"1"},
 "lo":{"asked":"lo","got":"up","zone":"1"}}   ← 下軸を押したのに上軸の図
```

### 直し方

**的が「どちらの軸か」を名乗る**（`data-axis`）。模式図の `.bs-bhit`（区間
ぜんたい）と、断面図・立体図の記号の札（`.bs-t3b`）の両方が持つ。
`openZoneZoom(badge, hit, axis)` がそれを受け、`zoomFigure()` が
**その軸の区間**を選ぶ。その軸に無ければ今までどおり先頭へ倒す。

描き直し（`syncZoneZoom`）でも**同じ軸のまま**開き直す（`zoomAxis`）——
軸が飛ぶと、見ていたのと違う図が出る。

### 網は絵ではなく「どの区間から組んだか」で見る

**上下で寸法が同じ材料では、絵が同じでも取り違えは起きている。**
器（`#bsZoomFig`）が `data-axis` と `data-zone` を名乗り、網は
**押した軸と組んだ軸が一致すること**と**上下で区間が違うこと**を見る。

## ② 記号は軸で色を分ける

押した記号の軸で拡大図が変わるようになったので、**押す前にどちらの図が出るかが
読める**ようにする。`--bs-fig-badge-up`（藍）／`--bs-fig-badge-lo`（青緑）。

- **字は同じまま。** 記号が指すのは「同じ組み方」で、軸はその置き場所。
  字まで変えると、別の組み方に見える。
- **色だけで語ってはいない**（§CLAUDE 3）——軸は**位置**（図の上下）と
  **刃組表の列**（上軸／下軸）がすでに言っている。色はその念押し。
- 色リテラルを増やさない（§9.350）——既存の族（`--rs-indigo` ／ `--rs-cyan`）から選ぶ。
- **刃組表の記号（`.bs-bdg`）は1行に1つ**で、その行は上下の両方を持つので
  色は分けない（分けると「この行はどちらか一方」と読める）。

## ③ 「上下刃の中心間」は拡大図から外す

この字は **貼る相手が無い寸法**（2枚の刃の位置の差）なので、§9.432 では
「名前も添えて必ず引き出す」と決めていた。引き出すということは
**席を1つ余計に食う**ということで、他の寸法を押し出していた。

**値は刃組図の見出し（`#bsDVal`）が持っている**ので、拡大図から落としても
読めなくなるものは無い（§CLAUDE 8 同じ情報を2箇所に出さない）。

消したのは**字だけ**。**反対側の軸の刃の破線は残す**——クリアランスの向き
（どちらへずれているか）は**絵でしか読めない**（§9.413）。足元の一言も
そのまま「破線は反対側の軸の刃（面と面のあいだがクリアランス …）」と言う。

落ちる字の数は `seq.filter(kind==='knife')` の数ぶん＝**本体の区間で2件、
端部の区間で1件**（区間の左右の刃それぞれに付いていた）。

## ④ 網（`test_bladeui.js` 293 → 296件）

- 模式図の区間が `data-axis` を名乗る（`lo` と `up` の両方が在る）
- **押した軸と組んだ軸が一致し、上下で区間が違う**（器の `data-axis`／`data-zone`）
- 記号の色が上軸と下軸で違う
- 「上下刃の中心間」の字が**0件**／破線は残っている

**欠陥注入で確かめた**（§9.399・1件だけ）——押した軸を無視する作りへ戻すと
「上軸を押せば上軸…」が落ち、戻すと 296/296 PASS。

### 網を書くときに踏んだこと

この節は**区間を押して回る**ので、終わったあと閉じっぱなし・別の区間で開き
っぱなしのまま進むと、次の「もう一度押すと閉じる」が成り立たない（実際に
2件落ちた）。**次の節が見る形へ戻してから渡す**（§9.394 と同じ作法）。

---

**【§9.455 で撤回】記号の色を軸で分けるのはやめた。** このときの指示「アルファベットも少し色が
わかっていると違いが出てわかりやすい」は**文字ごとの色**の意味で、軸で分けたのは読み違い
だった（同じ A が上軸・下軸・刃組表で3色になり、縞の模様に見えていた）。

**【§9.457 で撤回】拡大図の「破線の刃は残す」もやめた**（利用者の指示「拡大図の刃の横の点線は
消してください」）。クリアランスの値は足元の説明が言う。
