# §9.244 空欄の札を族で判定・落ちたテストを緑と数えない・帳票は「帳票だけの1枚もの」を刷る・測定値の統計を子ロットごとに（利用者の指示）

#### ① 「空欄の札を出さない」が組み込みの入力欄で効かない

> 操業データ項目マスタで空欄の札を出さないに設定しても、自動の項目の場合、
> それが有効になりません。

§9.229 ③で「選択肢を持つかは族で見る」と決めたが、**直したのは画面だけ**で
`_row_to_item`は`[型]`のままだった。組み込みの選択欄はどれも`[型]='文字'`で、
選択肢は`[選択肢名]`のほうで結んでいる:

| 項目 | 型 | 族 | autoFill |
|---|---|---|---|
| オペレータ | 文字 | choice | |
| 内径 | 文字 | choice | preset（＝利用者の言う「自動の項目」） |
| コイル止め | 文字 | choice | |
| 縦割数 | 文字 | number | preset |
| 元幅（実績） | 文字 | output | computed |

画面（`opIsChoiceLike()`）は族で見ており書き込みも通っていたので、
**書けるのに読むと必ずFalse**という形で出ていた——設定画面のボタンは効いて
見えるので、保存し直しても直らないことしか分からない。判定は
`widget_family()`の1箇所へ寄せた。数（number）と自動で入る値（output）では
今までどおり倒す（選ぶ札そのものが無い）。

**確かめるのは組み込みの欄で。** `[型]='選択'`の項目だけを見る網は直す前でも
通る（実際、最初に書いた網がそうだった）。

#### ② 落ちたPythonテストを「全部PASS」と数えていた

`tests/run_all.sh`は出力の`^PASS`／`^FAIL`／`FATAL`の字を数えるだけだったので、
Pythonのテストが例外で止まると**そこまでのPASSだけが残り「59 PASS / 0 FAIL」**
と表示された（①の調査中に実際に踏んだ——`NameError`で止まったまま緑だった）。
終了コードで見るようにした。

**赤いまま残っている網は網ではないが（§9.200）、緑に見えている壊れた網は
もっと悪い。**

#### ③ 帳票の印刷が用紙の8割に縮む（VER2.117.0でも再現）

> 用紙を最大活かせておらず、用紙に対して80％くらいの比率と共に表示内容の
> クオリティも下がっているように見えます。
> …このままうまくいかないようであれば、印刷ボタンの挙動を変更し、印刷を
> WINDOWS介さず…独自モーダルから出力する方法でもよいです。

§9.243で`@page`の余白を1つにそろえてもなお縮んだ。**こちらの割り付けは
正しい**ことを先に確かめた:

```
page.pdf({preferCSSPageSize:true})
  → /Type/Page 1件・MediaBox [0 0 594.96 841.92] （＝210×297mm）
```

残る差は**アプリの画面ごと刷っている**ことから来る。刷っている書類はSPA全体
（`.layout`／`main`／`.rp-scroll`…）で、帳票以外は`display:none`で伏せている
だけ——伏せた要素も器の幅・`min-width`・`--ui-scale`・スクロール器として
版面の組み立てに関わり得るし、`@media print`の規則が1つ増えるたびに
「刷るときだけ効く」経路が増える。

利用者の許可を受けて、**紙に出したいものだけの書類を作ってそれを刷る**形に
した（`rpPrintPages`）。同じ生成元の`<iframe>`へ、帳票のCSSと**測り終わった
`.rp-page`のDOM**をそのまま書き出す。

- 倍率（`--rp-fit`）はインラインで付いているので**プレビューが1対1で出る**
- **`--rp-scale`（画面の拡大縮小）は等倍へ戻す**——紙には関係が無い倍率
- **表示サイズ（`data-ui-size`）はプレビューと同じものを持ち込む**
  ——`--rp-fit`はその状態で測った値なので、片方だけ変えると食い違う
- **窓（`window.open`）ではなく`<iframe>`**——ポップアップのブロックに掛からず、
  閉じ忘れも起きない
- 器は**`display:none`にしない**（寸法が0になり中身が測れない）。画面の外へ逃がす
- **一括印刷も同じ道**（片方だけ残すと「1枚なら合うのに一括だけ縮む」になる）
- 組み立てに失敗したら`window.print()`へ落とし、理由をトーストで言う（§4）

ダイアログの用紙・倍率はこちらからは決められないので、**確かめる場所を
ボタンの説明に書いた**（用紙をA4・倍率を100%）。

**確かめ方**——`print()`をすり替えて**刷ろうとした書類そのもの**を測る。
「窓が出たか」を見る網は、書類が空でも通る。

#### ④ 測定値の統計を異幅分割の子ロットごとに

> 異幅分割の複数ロットが混在するパターンにおいてもロットごとに統計データが
> 出てくるように対応をお願いします。

`測定値の統計`という塊を新設した。**行＝対象（全体＋子ロット）・列＝項目×集計**。

**統計は「条に紐づくか」で2種類に分かれる**（§9.214で一度書いたとおり）:

| 測り方 | 項目 | 子ロットごとに出せるか |
|---|---|---|
| 条ごと | 板幅・ラテラルボー・バリ・テレスコープ・巻ずれ | 出せる |
| 丈ごと | 板厚（丈位置ごとに3点）・板丈・肉厚 | **出せない** |

子ロットは**条の範囲**で決まる（`settings.splitGroups`の`count`を先頭から積む。
`widthRowContext`と同じ材料を使うこと——別の数え方をすると、紙の中で条番号と
ロット№の対応が2通りになる）ので、丈ごとの項目はどの子ロットのものとも
言えない。**言えないことは言わない**（§4）——「—」で出し、理由も紙に書く。

まとめもロットごとも`rpStatOf()`の1箇所が作る。出す項目・集計は塊の設定で
選べ、印は`|`で並べるので他の見せ方を消さない。**既定では出さない**
（今まで無かった塊なので、置いていない現場の紙を勝手に増やさない）。

固定は `tests/test_rpprint.js`。**分割と測定値を注ぎ込んで、値が実際に
分かれることまで**見る（範囲を無視する欠陥を注入すると2件落ちる）。
