# §9.519 転写計算アプリへの進度情報の取込も同梱の拡張が持つ——WaveLog の道とは頼みの有無で分ける（利用者の指示）

索引: [決定記録](README.md)

## 経緯

利用者の指示「別リポジトリのWaveLogではロット検索をVPN接続環境からもアクセスできるようにしています。この方式を
移植し、ロット検索したときに得られるHTMLのデータ『進度情報』の設備実績情報を取得して、必要な設備毎のロットの
寸法や重量、オフの長さなどのデータ等を転写計算アプリに取り込む方法を検討してください」。
検討（転写計算アプリ側 `docs/LOTDSP_IMPORT_DESIGN.md`）のあと、利用者の答え:

- 拡張の置き方は「**WaveLog拡張に追加して1つで管理したいが、WaveLog上での挙動とは分けて使えるようにしたい**」
- 「鋳造番号が空の場合、ロット番号のところにロット番号を入れて、HTML上の検索を押さなければいけません」
- 「設備BOX数は最大25までの可変なので気を付ける必要があります」
- 「会社のEdgeで拡張は使えました」（§9.485 の「分からないこと」の1つ目が解けた）

表を読めるのは**LotDsp のページの中で動ける物**だけ（§9.485 と同じ理由: LotDsp は別サイト・表は AngularJS が
ブラウザの中で描く・VPN のログイン済みの状態は Edge の中にしかない）。

## 決めたこと

- 拡張（`program/lotdsp-ext/`）に**別のファイルとして**足す。WaveLog の道（`lotdsp.js`・`wavelog.js`）は1行も変えない。
  - `tpa.js` … 転写計算アプリの画面の受け口。**ポート 57821 かつ `<meta name="application-name" content="TransferPitchAnalyzer">`**
    のページでだけ名乗る（`<html data-tpa-lotdsp-ext>`）。WaveLog の画面（5029）では何もしない。
  - `tpa-lotdsp.js` … LotDsp のページで、**頼み（job）があるタブでだけ**動く。頼みは`background.js`が
    「転写計算アプリが開かせたタブ」の番号ごとに`chrome.storage.session`へ持つ。人が開いた LotDsp・WaveLog から
    開いた LotDsp では頼みを尋ねて空なので何もしない＝**分け方は「頼みの有無」**。
  - `background.js` … 頼みを受けて LotDsp を開き、読めた画面をアプリへ返す。送り手は URL で確かめる
    （頼みはループバックの画面から・画面は LotDsp のページから）。
- **ログインはしない。** VPN のログインは`lotdsp.js`のまま（同じ欄を2つの物が押しに行かない）。
  `tpa-lotdsp.js`はログイン欄が消えるのを待つだけ。
- **検索は人と同じ道**: ロット番号の欄（`#common_searchLtno`。最初の画面では`#input_searchLtno`——[§9.520](9.520.md)）へ`input`・`change`の合図で入れて
  `action.search()`を押す。linkkey は鋳造番号が要るので使わない。検索のあと出るタブは相手が決めるので、
  「進度情報」でなければ押す。
- **何を読むかは決めない。** 渡すのは描き終わった画面の HTML そのもの（`document.documentElement.outerHTML`）。
  列の意味づけ（見出しの文字で探す・設計と実績を№で結ぶ・設備マスタで絞る）は転写計算アプリの
  `lotdsp_progress.py`の1箇所。拡張は「頼まれたロット番号で、実績の表の行数が落ち着いた（250ms×3回同じ）」
  ことだけを確かめる——BOX は最大25の可変で、`ng-repeat`が描き終わるまで行数が動く。
- 新しい権限は足さない（`tabs.create`／`update`／`remove`／`sendMessage`は`tabs`権限なしで使える）。
  権限は`storage`だけのまま。
- 頼みを置く順: **空のタブを作って頼みを置いてから LotDsp へ進める**。LotDsp でいきなり開くと、読み手が
  頼みを尋ねる方が置くより先になることがある。
- 読めたら LotDsp のタブは閉じてアプリのタブへ戻す。読めなかったら残す（何が出ているかを人が見られる）。
  失敗は理由（「検索結果 0件・相手の文言」等）を付けてアプリへ返し、LotDsp の下の帯でも言う。
  読み終わる前にタブが閉じられたらその旨を返す（アプリを3分待たせない）。

## 撤回した案

- **拡張から転写計算アプリへ HTTP で直接送る**——127.0.0.1 の口を外に向けて開くことになる（§9.485 で止まった
  「口を増やす」と同じ形）。タブ間のメッセージで画面へ渡し、画面が同じオリジンの API を呼ぶ形にした。
- **拡張の中で列を読んで JSON にする**——列の意味は転写計算アプリの計算が決めるので、答えが2箇所になる。
  実物の class は列とずれている箇所もある（「前ｵﾌ」の見出しが`prog-label-jbfo`、値の td が`prog-jbbo`）。
- **転写計算アプリ用に別の拡張を作る**——ログインを2つが押しに行く（利用者の選択で撤回）。

## 測った（見本ページ・`tests/fixtures/lotdsp_progress.html`）

本物のロット問い合わせはこの環境から届かないので、利用者が保存した実物（L7150C0）と同じ形の見本で測った。
実物そのもの（転写計算アプリ側の`tests/fixtures/lotdsp_progress_L7150C0.html`）にも`tpa-lotdsp.js`を入れ、
渡した HTML を転写計算アプリの取込 API へ通して10工程が読めることを確かめた（保存した静的なページは
「検索」がフォームを送ってしまうので、その確かめだけ送信を止めた）。

| 物差し | 結果 |
| --- | --- |
| 頼みの無い LotDsp のタブで押した回数（検索・タブ） | 0 |
| 頼まれたときの検索の回数／タブを押した回数 | 1／1 |
| 渡した BOX の行数（見本 25・3） | 25・3（行を2回に分けて描いても全部） |
| ログイン画面で押した回数（ログイン・検索） | 0（ログインが済んでから検索） |
| 該当なしのとき | 理由付きで返す・帯で言う |
| 権限 | `storage`のみ（変わらず） |

欠陥注入で確かめた: 頼みの確かめを外すと「頼みの無いタブでは押さない」が落ち、行数が落ち着くのを待たずに
渡すと「25 BOX すべて」が落ちる（13行で渡った）。

## 分からないこと（利用者の確認が要る）

- 本物の LotDsp で、検索のあとに出るタブ・「検索結果」の出方が見本と同じか。
- ロット番号の検索で複数件（「前」「次」）になるロットがあるか（あれば、いま出ている1件目のロット番号が
  頼んだ番号と同じときだけ読む）。
