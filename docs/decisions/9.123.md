# §9.123 測定画面の再設計 第1段: 文脈バーと段の枠

1枚に全部を出す作りをやめ、「準備 → 測定 → 確認」の3段に分けた。この段で
入れたのは器だけで、中身は今のペインをそのまま使う（②測定＝右ペイン、
①準備＝左＋中、③確認＝左）。

#### なぜ段に分けるか（数字）

実測（1920×1080）で、測定画面には**入力欄28・ボタン32・タブ13個**が同時に
見えていた。しかも面積の配分が作業の実態と逆で、**1回決めるだけの「選択項目」が
画面の1/3**を占め、**作業時間の9割を使う測定も1/3**しかなかった。
②で本体を1枚にしたことで、測定パネルは **635px → 1747px** になった。

#### 段は関門ではなくタブ（利用者の指示）

順番は強制しない。①が途中でも②③へ行ける。ただし**進めない理由は書く**——
既定の入力内容は母材＝手動入力の項目なので、②では「母材は手動入力の項目です。
測定器から受けるには入力内容を切り替えてください」と出し、項目を変えると消す。
押せるのに何も起きないのが、いちばん悪い。

状態は**色だけで伝えない**。段の見出しに必ず文字を付ける
（`開始 未` / `0/8 項目` / `残り 8項目`）。

#### 文脈バーは重ねない

ロット・製品・測定表の形（条×丈）・判定公差を段の上に固定する。
**進捗と保存状態はヘッダーに常時出ているので、ここには入れない**——
同じものが2箇所にあること自体が認知コストで、しかも片方だけ古くなる。

**開いた時点で埋まっていること**が要件。最初の実装は`WL.onReady`で1回描くだけ
だったため、段を移動するまで `—` のままだった。空欄は「取れていない」のか
「まだ描いていない」のか区別が付かない。中身が変わる経路（進捗の更新・
測定画面の開閉・入力内容や条数の変更）をすべて拾う。

#### 縦は測定表のもの——枠は最小限しか取らない

最初は文脈バーと段ナビを**2行**に分けた。結果、本体がそのぶん縮み、
**表示サイズ特大で左ペインが22pxはみ出した**（通しテストの`test_maint`が
検出）。段・理由・文脈を**1行**に収めて 22px→0px。
同時に`test_tolscale`が5件落ちた——公差数直線は測定パネルの中にあるので、
既定の①準備では**高さ0のまま測っていた**（隠れている要素を測って
「上限が下限より上にない」と読み違える）。②へ移ってから測るよう直した。

**この2件は、第0段で安全網を先に用意していなければ、実機で表示サイズを
大きくしている端末だけが壊れて気づけなかった。**

#### 受信欄は作り直さない（§9.122）

段の切り替えは**CSSの表示/非表示だけ**で行い、DOMの親を変えない。
隠れているあいだフォーカスは外れるので、②へ入ったときに戻す（作り直しとは
別物）。固定は`tests/test_msteps.js`（23件）で、2つの欠陥を注入して確かめた——
②で面積を渡さない／段の切替で受信欄を作り直す（後者は`test_mcore`が
**転送0件**で落ちる。実機で起きる壊れ方そのもの）。

#### 危ない操作を主要動線から外す

「このデータを削除」は「測定を完了」の真下にあり、押し間違いの的だった。
③確認でだけ出す。

**コメントに閉じ記号を含めない。** 実装中、コメント内のワイルドカード付きの
例示が`*/`となってコメントを途中で閉じ、**ファイル全体が構文エラー**になった
（CSSで既知の罠と同じものをJSでやった）。段が一切動かない状態になる。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **測定画面は「準備→測定→確認」の3段**（§9.123、`static/js/measure/measure-steps.js`）:
  段は**関門ではなくタブ**で、順番を強制しない（いつでも行き来できる）。
  ただし**進めない理由は書く**（母材・丈は手入力なので転送を受けられない等）。
  状態は色だけで伝えず、見出しに必ず文字を付ける（`開始 未`／`0/8 項目`）。
  **切り替えはCSSの表示/非表示だけ**で行い、ペインを別の器へ移し替えない
  （移すと受信欄の親が変わりフォーカスが落ちる。下記§9.122）。
  **枠は1行に収めること**——段と文脈を2行に分けたら本体がそのぶん縮み、
  表示サイズ特大で左ペインが**22pxはみ出した**（`test_maint`が検出）。
  縦は測定表のもの。**測定パネルの中を測るテストは②へ移ってから測る**
  （公差数直線は①では高さ0で、隠れた要素を測ると読み違える）。
  文脈バー（ロット・製品・条×丈・公差）は**開いた時点で埋まっていること**で、
  進捗・保存状態は**ヘッダーに常時出ているので重ねない**（同じものが2箇所に
  あること自体が認知コスト）。固定は`tests/test_msteps.js`。
