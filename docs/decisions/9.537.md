# §9.537 ロールマスタの表に「1周の長さ」と「見分けにくい相手」——異常位置判定と同じ計算で、計算の列を登録表から足す（利用者の選択 C-4）

索引: [決定記録](README.md)

## 利用者の言葉と選んだ経緯

マスタの視覚化の候補 C「ロール径と1周」の案 C-1〜C-5（1周の長さの数直線・ラインを横から見た図・見分けにくい組の行列・
表に列を足す・ピッチを試す）を見て **「C-4でお願いします。」**。図を別に置かず、いまの表の右に
**1周の長さ（数）・1周の帯（全行で同じ目盛り）・見分けにくい相手（札）**の3列を足す。

案の画像はスクラッチの `mockC.js`（製品のコードではない）。案の画像では面長・本数・材質・基準番号の列を省いて描いていたが、
**実装ではこの4列を残した**（一覧から情報を減らす判断は案の画像に含めていなかった）。代わりに列の幅（`grow`）を中身の長さから配り直した。

## 測った（評価関数）

前は VER2.423.0。物差しはスクラッチの `eval_roll.js`: テスト設備A に見本のロール8本（入側→出側）を入れ、
**正解は総当たり**（各ロールの1周の帯の上を0.5mmずつ・測りの許容±2%・2倍と半分）で作り、表の各行と突き合わせる。終わったら消す。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 1周の長さが表に出ている | 0/8 | 8/8 |
| 見分けにくい相手を名指し（正解は16の向きつきの組） | 0/16 | 16/16 |
| 印（＝・×2・÷2）も正しい | 0/16 | 16/16 |
| 余計な名指し | 0 | 0 |

総当たりは、案を描いたときに気づいていなかった組（リールスリーブ Φ508 の1周の半分がピンチロール3本と重なる）も見つけ、表も同じ6組を出した。

網: `test_roll.js` ⑦（判定と同じ計算・1周の長さと帯・札の名指しと色）。`rollConfusions()`を倍数まで見ないように壊すと ⑦ が落ちることを確かめた。

## 決めたこと

- **見分けにくい相手は、測定画面の異常位置判定と同じ計算**（`defect-locator.js` の `rollConfusions()`）。
  「このロールが付けた欠陥（1周の帯のどこか＋測りの許容 ±2%＝`ROLL_TOL_DEFAULT`）を `rollMatches()` にかけたら、ほかに当たるロール」。
  倍数は2まで（2回に1回だけ数えた・1周に2箇所）。探すのは**同じ設備の中だけ**（1ロール1設備・§9.239）。
- 印: **＝** 1周が重なる（見分けられない・橙の札）／**×2** 相手の1周が2倍／**÷2** 相手の1周が半分（灰の札）。
  相手の呼び名は「ロール名（入出位置・接触面）」（同じ名前のロールを見分ける）。
- 1周の帯は**全行で同じ目盛り**（200mm 刻みに丸めた最小〜最大・見出しが目盛りを言う）。色は当たる面（上＝青・下＝琥珀・上下＝紫）、字は接触面の列。
  径MINが無いロールは1点（小さな丸）。
- **汎用の表に「計算の列」の登録表**（`WL.mm.registerCell(種類,{prep,text,html,label})`・`cols`の1列が`cell:'種類'`を名乗る）。
  盤は種類を知らない。`prep`は表の全行で1回（同じ`prep`を名乗る種類は1回だけ数える）。並べ替えは`text`で効く。
  ロールの3種類は `master/master-roll.js` が名乗る。
- 一覧の1行は `maintRowEl()` へ切り出した（`renderMaintList` を長くしないため）。

## 一緒に直したこと

- `test_mmswitch.js` の「切り替えた先の一覧が出ている（追加が押せる）」は、§9.529 で刃マスタが専用の盤（「追加」を持たない）になって以来**必ず落ちていた**
  （VER2.422.0・VER2.423.0 でも同じ落ち方を確かめた）。汎用の一覧を持つタブとしてロールマスタを使うように直した。

## 分からないこと・残したこと

- 許容 ±2% は測定画面の既定値（`ROLL_TOL_DEFAULT`）。現場が判定のときに別の許容を打つと、見分けにくさも変わる（表は既定値で言う）。
- 接触面が違う組（入側ピンチロールの上と下）も ＝ と出す。欠陥の出た面が分かれば判定では見分けられるが、表は面で絞らない（札の呼び名が面を言う）。
- 実設備のロールの本数・径の散らばりでの見え方は確かめていない。
