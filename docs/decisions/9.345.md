# §9.345 条件を足す入口はボタン。検索欄の顔をした器を2つ並べない

`docs/REVIEW_2026-09.md` 4-1 ③ の指摘:「仕掛一覧に検索欄が2つ（ヘッダー
『一覧を検索』と絞り込みバー『検索して条件を追加』）。同じ形で意味が違う」。

## 機能は重複していない。顔だけが同じだった

| | 何をするか | 幅（実測） |
| --- | --- | --- |
| ヘッダー `#search` | **行**の全文検索 | 245px |
| 絞り込みバー `#filterTokenSearch` | **条件のカタログ**を検索して足す | **1071px** |

やっていることは別。**消してはいけない**——後者は §9.287 で「よく使う条件」
の行と `⋯` の入口を吸収した、今の主動線そのもの。

問題は**顔が同じ**ことと、**器が中身より大きい**ことだった。丸みも枠も同じ
入力欄が2つ並び、しかも条件側は `flex:1 1 auto` でバーいっぱい（1071px）へ
伸び、teal の枠で**画面でいちばん目立つ**。足す条件の名前は短いので、この幅に
根拠が無い（画面基準11「器がグリッドの1マスぶんに自動で伸びるのを放置しない」）。

## 決めたこと

**常時開いた入力欄をやめ、`＋ 条件を追加` のボタンにする。** 押したときだけ
欄を出し、幅は候補の名前に足りるぶん（`--w-xl`）にする。余った場所は
**空白のまま**（画面基準13「列を増やして詰めない」）。

これは §9.287 が既に決めている言語と同じ——「効いている条件はアイコン＋件数の
1バッジ、中身はポップオーバー」。**入口はボタン、中身は浮き**で揃える。

**畳むときは打ちかけの字も捨てる。** 条件はまだ1つも足っていないので残す
値打ちが無く、残すと次に開いたとき前の字が出ていて「何か効いている」と読める。

作法は落としていない: Esc で畳む、外を押しても畳む、開いたら焦点が乗って
そのまま打てる、候補は今までどおり出る。

## 網

`tests/test_filter.js` に5件。**③の本体は「検索欄の顔をした器は、同時に
ひとつだけ」**——これが崩れない限り、幅や文言を直しても指摘は戻らない。
あわせて、押すと開く／焦点が乗る／中身なりの幅（バーの半分未満）／打つと
候補が出る／Escで畳んで字も残らない、を見る。

**ここで自分が踏んだ罠**: 候補の箱は `position:fixed` なので
**`offsetParent` が必ず `null`**。「見えているか」をそれで測ったため、
出ているのに「見えない」と読めて**網自身が1件落ちた**。固定配置の要素は
`hidden` と中身の有無で見る。
