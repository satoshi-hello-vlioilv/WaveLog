# §9.411 起動モーダルで「更新を当てているか」を言い分ける（利用者の指示）

## 利用者の言葉

> start.vbsから起動したときに、起動モーダルが出ますが、**アップデートなども
> 実施してくれると思うので、実施しているときとしていないときの違いも分かる
> ように**、改良してほしいです。**デザインも新たにゼロから一新したいので
> モーダルのデザイン案を5案出してください。**

## 起きていること（利用者の読みは当たっている）

毎日の起動は**刻印**（`ready.json`・§9.225）を見て、合っていれば確認を飛ばす。
合わなければ `update.bat` と**同じ処理**（`setup_check.run()`）をその起動で
まとめて行う——部品の導入・**バイトコードの作り直し**・旧DBの取り込み・
待機画面の写し・刻印の書き直し。バイトコードの有無は実測で
**app読み込み 1,168ms ⇔ 211ms（5.5倍）**なので、当たっている起動は目に見えて
長い。

ところが待機画面に出ていたのは段の名前だけで、しかも言い方が逆だった:

| そのときの実際 | 出ていた字 |
| --- | --- |
| 更新を当てている（数秒かかる） | 「必要な部品が揃っているか確認しています」 |
| 何もしない（飛ばす） | 「確認済みです（update.batで確認しました）」 |

**どちらも「確認」としか言っていない。** 待たされている人には、遅いのが更新の
せいなのか、共有が遅いのか、固まったのかが読めない。

## 直した形

進捗（`boot_status`）に**3つしかない状態**を足した。分からないうちは空——
**推測して「していない」と言わない**。

| 値 | 意味 |
| --- | --- |
| `''` | まだ分からない／その段は更新と関係ない |
| `skip` | 前回の確認のままで済んだ（飛ばした） |
| `update` | いま確認・導入・作り直しをしている |

`update` のときは**何が変わったから確認するのか**も一緒に渡す。材料は
`ready.mismatch()` が既に人の言葉で持っていた（「アプリの版（2.305.0 →
2.306.0）」「Pythonの場所（… → …）」）ので、**書き足さずにそのまま運ぶ**。

さらに、確認の途中経過（`setup_check.run()` の `say()`）を**ログと同じ言葉で**
画面へも流す。ここは何秒もかかる段なので、黙っていると止まって見える。

待機画面は**同じ場所で言い分ける**（出たり消えたりする帯を2つ持つと、
どちらが今の話か分からない）:

| 状態 | 帯 |
| --- | --- |
| `update` | **更新を反映中**（琥珀）／`変わったもの: アプリの版（2.305.0 → 2.306.0）` |
| `skip` | **更新なし**（中立）／`前回の確認（update.bat）のまま起動します` |

色だけで伝えず、**字にも分類名を書く**（§CLAUDE 3）。

## デザイン5案

作り替えの案は [`docs/mockups/boot-modal-5.html`](../mockups/boot-modal-5.html)
に**実物と同じ配色・同じ10段階**で描いた（見本なので製品には載らない）。
上の切り替えで **更新なし／更新を反映中／起動できなかった** を全案いっぺんに
見比べられる。

| 案 | 骨格 | 向いている場面 |
| --- | --- | --- |
| 1 | ステータスカード（今の作りの正統進化） | 見え方を大きく変えたくない |
| 2 | タイムライン（**済んだ段は1行に畳む**・更新は節として挿し込む） | どこで待たされているかを最短で読ませたい |
| 3 | 2ペイン（左＝アプリの顔／右＝進み具合） | 起動が数秒かかる端末 |
| 4 | ミニマル（既定は1行・「詳しく」で開く・更新時は自分から開く） | 起動が1〜2秒で終わる端末 |
| 5 | ダッシュボード（版・更新・経過・ポート＋**所要秒つきの表**） | 起動の遅さを追いかけたい |

どの案も次の3つを必ず満たす形で描いてある（採用案の実装もこれを守る）:

1. 10段階の進み具合（サーバー6＋ブラウザ4）が読める
2. **更新を当てているか／当てていないか**が同じ場所で読み分けられる
3. 失敗したときに「次に何をすればよいか」がその場に出る

**採用が決まるまで、いまの意匠のまま①の機能だけ載せてある**——選ぶのを
待つあいだ「どちらか分からない」状態を続けないため。

## 採用した意匠（利用者が選んだ形・VER2.307.0）

5案→複合→A〜E→P1〜P5→Q1〜Q5と振ったが、**利用者は途中で「少し前へ戻る」と
判断した**（`docs/mockups/boot-modal-5.html` の案2 タイムラインを指して）。
そこから**横の流れ**へ作り替え、最終的に決まったのは次の3つ:

| 決めたこと | 何を選んだか |
| --- | --- |
| 骨格 | **S4 流れる帯**（`boot-modal-v6.html`） |
| 動き | **M1改 W2**（ヘッダーの波紋・中／`boot-modal-v8.html`） |
| アイコン | **J4**（予定表＋測定線＋測った点／寸法ごとの描き分けはしない） |

### なぜ明るくしたか

利用者の言葉は「**明るい感じにしたいけど、アプリのイメージとあまりズレすぎない
ように**」で、一見すると両立しない。実ファイルを測ると**両立どころか同じこと**
だった——本体（`static/css/00-base.css`）は地`#eef2f4`・ティール`#087c89`の
**明るい画面**なのに、起動画面だけが暗く、しかも**別のティール**（`#2ec9c0`）を
使っていた。つまり「明るくする」＝「本体へ寄せる」。
v6以降の見本は**本体のトークンをそのまま写し、新しい色を1つも作っていない**。

`html.app-booting` の地も暗い色＋`color-scheme:dark`をやめ、`--bg`にした
（待機画面が明るくなったので、暗いままだと引き渡しで色が飛ぶ）。

### 進み具合に答えるのは1本だけ

最初の案では「10段の目盛り」と「進捗バー」を両方置いたが、**同じ進み具合が
画面に2つ出る**（§CLAUDE 8）。帯が段を担うので、**バーは1本・%もその脇の
1箇所だけ**にした。いまの段の名前も帯が出すので、見出しの欄は持たない
（`#bootStage`は廃止）。

### 波紋（利用者の指示）

> M1の波紋は、**だんだん薄く遠くまで**、かつ**ヘッダーバーの部分のみ**で
> 文字や白いモーダル背景部分には干渉しないように

| 要件 | 作り |
| --- | --- |
| ヘッダーの中だけ | 器（`.head`／`.boot-head`）を`overflow:hidden`で切る |
| 文字に干渉しない | 文字・版・マークは`z-index:2`、輪は`0`（輪は必ず文字の下） |
| だんだん薄く遠くまで | 不透明度 4%で.32 → 30%で.15 → 消える。周期4.6秒・輪3本 |

**作りで2つ踏んだ**（どちらもやらないと狙いの逆になる）:

- **`transform:scale()`を使わない**。線まで一緒に拡大されるので、
  **遠くへ行くほど輪が太くなる**。幅と高さを動かせば線は1.5pxのまま。
- **広がりは`linear`**。加速する曲線だと、不透明度が上がりきる前に輪が遠くへ
  行ってしまい、**マークから立ち上がる瞬間が見えない**。

**「本文へ漏れていない」は画素で数え、欠陥注入で網が効くことを確かめた**:

| 測ったもの | 本文の差（波紋の位相を変えて撮り比べ） |
| --- | --- |
| いまの作り | **5画素・最上段のみ**（撮影の境界の丸め） |
| `.head{overflow:visible}`を注入 | **1,153画素・全280行**に拡散 |

測り方でも2つ踏んだ。**別カード同士のハッシュ比較は無効**（カードごとに縦位置の
端数が違い、文字のアンチエイリアスが変わるので永遠に一致しない。同じ器の
位相差で見る）。**`*`は疑似要素に当たらない**（`*,*::before,*::after`が要る。
止め忘れたバーの光が、波紋と無関係な差として出ていた）。
静止画を撮るときの**遅延は必ず負**にすること——無限アニメの正の遅延は
初回しか効かず、定常状態が写らない。

### アイコン（`backend/app_icon.py`）

16pxでは中の線3本（綴じ2本＋折れ線）が潰れるため**寸法ごとに描き分ける**案も
出したが、**利用者は「J4のまま」を選んだ**ので1つの絵で通す。

`MARK`は「描く順に並べた組（`rrect`／`line`／`curve`／`dot`）」へ作り替えた。
**SVGの`stroke`は線の中心に太さの半分ずつ乗る**ので、枠線は「太い角丸を塗って
内側を白で抜く」形で作る。`ICON_VERSION`は2（**上げないと古い絵が残る**）。

角丸のSDFに**内側を負にする項**（`min(max(qx,qy),0)`）が無く、
**角丸半径0の四角が半分の濃さでしか塗れていなかった**（見出しの帯で踏んだ）。
半径14の四角しか無いうちは`-r`が効いて気づけない。
