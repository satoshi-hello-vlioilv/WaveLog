# §9.438 応答が届かなかった追加を、再送で二重に入れない

索引: [決定記録](README.md)

利用者の報告:

> スケジュール作成時、同じロットが2つ表示されてしまう不具合が発生しています。
> 同期し直しても直りません。

---

## ① 原因は「再送」——どちらも本物の行だった

予定の書込キューは、失敗した操作を**最大3回まで投げ直す**。通信不良や503の
ような「待てば通るかもしれない」失敗のためで、再送そのものは正しい。

ところが **HTTPは「サーバーが書いたか」を答えない。** 書けたのに応答だけ
落ちたとき、画面には**失敗としか見えない**ので、同じ `add` をもう一度投げる。
`plan_add()` は素の INSERT なので、そのたびに1行増える。

**どちらも本物の行**なので、共有DBを取り込み直しても消えない——
利用者の「同期し直しても直りません」はここから来ている。

## ② 測った（評価関数）

**1操作あたり、共有DBに増える行数。理想は1。**

| 場面 | 直す前 | 直したあと |
| --- | --- | --- |
| 単発の追加（`/plan/add`）で応答が落ちる | **3行** | **1行** |
| まとめ追加（`/plan/batch`）で応答が落ちる | **6行**（1ロットあたり） | **1行** |
| 通信が正常なとき | 1行 | 1行 |

「3」「6」は再送の回数そのもの。まとめ追加は、まとめ書込が落ちると個別経路へ
落ちてもう一度投げ直すので、回数が倍になる。

## ③ 直し方——再送を止めず、「何度届いても結果は1つ」にする

**至上1回の配送はネットワーク越しには作れない。** 作れるのは
「何度届いても結果は1つ」のほう。

**操作に身元（`操作ID`）を持たせ、同じ身元は2回適用しない。**
2回目は、1回目に作った行のIDを**そのまま返す**——画面から見れば「成功した」と
同じで、行は1つのまま。

```
画面 : 積むときに1回だけ身元を作る（投げ直しでは作り直さない）
API  : opId を通す（単発の /plan/add も、まとめの /plan/batch も）
DB   : 同じ身元の行が在れば、その予定IDを返して INSERT しない
```

### 決めたこと

- **身元は行そのものが持つ**（別表にしない）。予定と同じ寿命で、共有DBを
  写しても一緒に付いていき、消える予定と一緒に消える。
- **入れるのは行と同じ INSERT で。** あとから別の UPDATE で書くと、その
  あいだに届いた再送が身元を見つけられず、結局2行になる。
- **有効・無効は見ない。** 消された予定も「その操作は適用済み」なので、
  再送で作り直してはいけない（外したはずの行が数秒後に戻る）。
- **足すのは追加だけ。** 更新・削除・並べ替えは同じ結果を2回書いても行は
  増えない（べき等）。増えるものにだけ身元を足す。
- **身元は積むときに1回だけ作る。** 投げ直すたびに作り直すと別の操作として
  受けられ、何も変わらない。
- **時刻から作らない**（[§9.400](9.400.md)）——同じミリ秒に2件積むことがある。
  `crypto.randomUUID()`、無ければ乱数を3つつなぐ。
- **列が無い写しでも今までどおり動く。** 古い版が作った共有DBには `操作ID` 列が
  無い。`ensure_plan_table()` が「無ければ足す」で移行するが、足せなかった
  端末では身元を載せずに INSERT する（二重は防げないが、**動かなくなるよりよい**）。

## ④ 網（`test_plandup.js`）

**「書けたのに届かなかった」を、実際の経路でそのまま作る**——
`route.fetch()` でサーバーへは本当に届け、`route.abort()` で応答だけ落とす。
モックではないので、`plan_add()` は本当に走る。

固定するのは3つ:

1. 単発の追加で応答が落ちても、予定は1行だけ
2. まとめ追加で応答が落ちても、予定は1行ずつ
3. **通信が正常なら、追加はこれまでどおり1行入る**（塞ぎすぎていない）

**欠陥注入で確かめた**（§9.399・1件だけ入れてその場で戻す）——身元の
突き合わせを殺すと、1と2が落ちる（3行／6行）。3は落ちない（正常系は無傷）。

**待ちは黙らせない**（[§9.360](9.360.md)）。書込キューが片付くのを待つところを
`.catch(()=>{})` で握り潰していたので、`wait.js` の `until()` へ移した
——片付かないまま先へ進むと、行が1つなのは「まだ書いていないから」かも
しれず、数えたことにならない。
