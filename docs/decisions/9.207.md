# §9.207 表示列の非表示が保存されない／操作列の固定をやめて右クリックへ／表示列をメニューへ／計算式の列（利用者の指示）

> 「表示非表示で、非表示にしても表示に切り替わってしまう列がいくつか
>  あります。」「表示列の設定で保存ボタンを押したら、モーダルを閉じて
>  ほしいです。」「操作ボタンの列固定は不要です。…代わりに右クリック
>  メニューに操作と同等の機能を実装し…充実させてください。」
> 「よく使う表示列のカスタム機能だけはメニュー部分に出してほしいです。」
> 「計算式などを組むために空の列(名前は必須)を追加できるようにしたいです。」

### ① 非表示が保存されない（真因）

列の設定パネルの`initialHidden`に

```js
keys.filter(k=>!chosen.has(k)&&(!scIsFixedCol(k)||SC_COL_OFF_BY_DEFAULT.includes(k)))
```

と**「固定列は既定で出す（監査4列を除く）」という条件が重ねてあった**ため、
利用者が固定列を消しても**次に開くとチェックが戻り、保存し直すと出てきた**。
効かない列は`SC_COL_OFF_BY_DEFAULT`に載っていない固定列すべて——区分・作業・
日付(現場歴)・時刻・勤務・残り・見積・実績・備考・操作で、利用者の
「計算している関係のものが多い印象だが全部とも言い難い」と一致する。

**既定かどうかは`timelineColumnKeys()`（＝`timelineHiddenSet()`）が既に
見ている。同じ判定を2箇所に置かない**——片方だけが古くなる。

あわせて、**保存したらパネルを閉じる**（保存＝この作業は終わり）。
**失敗したら閉じない**——直す場所が消えてしまう。

### ② 操作列の固定をやめ、右クリックへ

操作の列は`position:sticky;right:0`で右端へ貼り付けていたが、§9.176で
移動も表示/非表示もできるようになったので、**真ん中へ動かした列を右端に
貼り付ける**という辻褄の合わない状態が作れてしまう。貼り付けをやめ、
**行の右クリック**が同じことを全部できるようにした（開始／再開／帳票／
固定／詳細／申し送りの編集／選ぶ／予定から外す／実績の削除／表示列）。

- **並べるのは「いまできること」だけ**（§4）。
- **危ない操作は下へ離す**（§5）。色でも分かるようにするが、文字も出す（§3）。
- **見た目は見出しの右クリックと同じ器を使い回す**（2つの流儀を覚えさせない）。
- 詳細（固定開始・見積の内訳）は**操作の列を隠していても開ける**
  ——以前はボタンが無ければ器ごと作らなかったので、列を隠すと辿り着けなかった。

### ③ 表示列だけメニューへ出す

§9.199で見え方を1枚のパネルへ集めたが、**表示列は触る回数が桁違いに多く**、
「開く→探す→押す」の3手が毎回かかっていた。**入口は1つのまま場所だけ
動かす**（idを変えずにバー直下へ）。**同じ入口を2箇所に置かない**（§8）。

### ④ 計算式の列

**一覧とまったく同じ仕組み**（`WL.formula`＝列レイアウトマスタの`[計算式]`）に
乗せる。式の書き方もヘルプも1つで、**`eval`は使わない**（§9.111）。

- 材料は**画面に出ている列と同じ**なので、`[ロット番号]`のように**見出しの
  言葉で書ける**——`__date__`のような内側のキーを覚えさせない
  （`timelineKeyByName()`が 表示名→見出し→キー の順に当てる）。
- **表示だけの列**で、並べ替え・絞り込みの対象にはしない。
- 式は**列ごとに1回だけ解く**。行を描くのは別の関数なので、
  **式が変わったときだけ解き直す控え**として持つ（引数で配って回すと、
  渡し忘れた経路だけが黙って空になる）。
- **式が空の列も並びに数える**（一覧の`listColumnKeys()`と同じ）。作った
  直後は式が空なので、落とすと足した列がその場で消える。
- **計算で作った列を内容表示マスタへ混ぜない**——混ぜると「内容欄の項目」
  として扱われ、式を消した瞬間に空の列が残る。
- 設定パネルの見本は**口が組み立てた行**を式へ渡す（`formulaRowOf`）。
  予定の行は`{列名:値}`ではないので、素通しにすると見本だけ全部「（空）」になる。

固定は`tests/test_sctimecols.js`・`tests/test_scbar.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **スケジュール表の列の既定は1箇所でだけ判断する**（§9.207）: 列の設定
  パネルの`initialHidden`に「固定列は既定で出す」を重ねていたため、
  **利用者が日付・時刻・残りなどを消しても開き直すとチェックが戻り、保存し直すと
  復活していた**。既定かどうかは`timelineColumnKeys()`（＝`timelineHiddenSet()`）が
  既に見ている——**同じ判定を2箇所に置かない**。**列の設定は保存したら閉じる**
  （失敗したら閉じない。直す場所が消える）。**操作の列は普通の列**——
  `position:sticky;right:0`をやめた（移動できる列を右端に貼り付けると辻褄が
  合わない）。代わりに**行の右クリック**が同じことを全部できる（開始・再開・
  帳票・固定・詳細・申し送り・選ぶ・外す・実績削除・表示列）。**並べるのは
  いまできることだけ／危ない操作は下へ離す**。詳細の器は**操作列を隠していても
  作る**（隠すと辿り着けなくなっていた）。**表示列だけはメニューバーに直接出す**
  （§9.199でパネルへ畳んだが、触る回数が桁違いに多い。**入口は1つのまま場所だけ
  動かす**＝idを変えない）。**計算式の列は一覧と同じ`WL.formula`に乗せる**
  ——材料は画面に出ている列と同じなので`[ロット番号]`のように**見出しの言葉で
  書ける**（`timelineKeyByName()`）。式は列ごとに1回だけ解き、行を描くのは別の
  関数なので**式が変わったときだけ解き直す控え**で持つ。**式が空の列も並びに
  数える**（落とすと足した列がその場で消える）。**計算で作った列を内容表示
  マスタへ混ぜない**。設定パネルの見本は`formulaRowOf`で行を組み立て直す
  （素通しにすると見本だけ全部「（空）」になる）。固定は
  `tests/test_sctimecols.js`・`tests/test_scbar.js`。
