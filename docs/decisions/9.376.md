# §9.376 作業日・直を直す道を行から辿れるようにする／`waitForFunction`の述語がPromiseを返すと何も見ない

2つの話が入っている。前半は利用者の指摘⑥への手当て、後半はそれを
確かめようとして見つけた**網の素通り**で、後半のほうが影響が大きい。

---

## 1. 「作業日の変更はどのようにしたら出来ますか」（利用者の指摘⑥）

利用者の言葉:

> 作業日の変更はどのようにしたら出来ますか。例）9/12 １直で3SCAという材料を
> ６ロット作業するように 9/12 ２直分のロットを１直へ移動しました。
> 9/12 ２直が空白になったため、9/12 ３直分のロットを入れたいのですが、
> 移動できません。この場合どうすれば良いのですか？
> **自動で作業日と作業直が入りますが日付修正する機能も必要です。**

### 2つの別々のことが1つの文に入っていた

- **「移動できません」** … §9.374 の自動スクロールが無かったこと。掴んで
  いる間は`dragover`しか起きずホイールも効かないので、**動かせるのは
  いま見えている行だけ**だった。1画面に収まらない移動（別の直へ運ぶ）は
  物理的にできなかった。**これは直っている。**
- **「日付修正する機能も必要です」** … こちらが本項。

### 機能は前からあった。入口が無かった

予定の作業日・直は**計算値**（起点＋見積の積み上げ）で、行が自分で持って
いる値ではない。だから「この行の日付を打ち替える」という形は取れず、
日付・直を決めるのは**枠**の行（§9.238 ②）——「ここから先を、その日・
その直の頭から並べる」——である。

**その枠を入れる道が、上の道具列のアイコン1つしか無かった。** しかも
そのアイコンから入ると末尾へ足すか、掴んで落とす必要がある。
利用者の頭の中の言葉は「**この行を別の日へ**」なので、
**その言葉からは一度も辿れなかった。**

直したのは3つ。**機能は1つも足していない。**

1. **行の右クリックに「ここから下を、別の日・直から並べる…」**を足した。
   押すと今までと同じ窓（`openFramePicker`）が、**その行の直前**を指して
   開く。入口を増やしただけで、窓も保存の道も1本のまま（§9.207）。
2. **窓が「どこへ入るか」を先に言う**（§2 推測させない）——
   「〈ロット番号〉のすぐ上に入れます。ここから下ぜんぶが、選んだ日・直の
   頭から並び直します」。下にある「枠とは何か」の説明と同じ顔だと読み
   飛ばされるので、面を持たせて先頭に立たせた（色帯は面とセット・§9.344）。
3. **時刻まで決めたいときの行き先を書いた**（§4）——「いまの日時で固定する」
   （§9.38）が既にあるので、窓の説明からそこへ案内する。

**出すのはこれから並ぶ行だけ**（`kind!=='枠' && state==='予定'`）。
済んだ行・作業中の行の上へ枠を挟んでも起点は動かない
（§9.238 ②「進めるのは前へだけ」）ので、押せても何も起きない項目になる。
枠そのものの行にも出さない——すぐ上の「枠の日付・直を変える」と同じことになる。

判定は`frameInsertable()`の1箇所（§9.163）。道具列のボタンと行のメニューで
別々に判定すると、**片方だけが押せる**状態を作る。

## 2. `waitForFunction`の述語がPromiseを返すと、待たずに抜ける

上の手当てを網で固定しようとして、**「サーバーに入ったか」を待つ判定が
一度も待っていなかった**ことが分かった。

```js
// これは「何も見ていない」
await page.waitForFunction(a=>fetch('/api/…').then(r=>r.json()).then(j=>…),
  arg,{timeout:25000,polling:400}).then(()=>true,()=>false);
```

Playwright の`waitForFunction`は、**述語が返したPromiseを待たない。**
Promiseそのものが真なので、条件が成立していなくても**その場で抜ける**。

`tests/`で実測した（3秒後にだけ真になる述語を置いた）:

```
経過ms= 82  値= false
```

**82msで、値`false`のまま「成立した」ことになった。**

### なぜ気づけなかったか

この形を`test_srcsync.js`（§9.375）で2箇所使っており、**どちらも常に真**を
返していた。欠陥注入で確かめたときも、落ちたのは**別の**判定
（`planOf()`でサーバーに聞き直す形のもの）で、この2つは落ちなかった——
**落ちなかったことが手掛かりだった**のに、他が落ちたので通り過ぎた。

CLAUDE.md の「速くしたら**同じものを見ていることを確かめる**」
「**両方PASSは証拠にならない**」（§9.102）はまさにこれで、
**規則は書いてあったのに、当てる先を間違えた。**

### 直し方

サーバーへ聞き直す待ちは、**Node側で回す**`tests/lib/wait.js`の`poll()`で置く。

```js
const found=await W.poll(async()=>(await plan()).find(e=>…), f=>!!f, 25000, 400);
```

`page.waitForFunction`に渡してよいのは**画面のDOMだけを見る同期の述語**。

### 機械で見張る

`tests/test_waitlint.py`に`ASYNC_PRED`を足した。**0件**で固定する
——上限で許すと、素通りする判定がそのぶん残る。落ちるのではなく
**黙って緑になる**形なので、増分では見張れない。
網そのものが素通りしないことも、わざと1つ書いて数えて確かめる。

リポジトリ全体（166本）でこの形は**この2箇所だけ**だった。

## 固定する網

- `tests/test_scframe.js`（30→37件）… 行から辿れる／枠の行には出さない／
  窓が「どこへ入るか」を先に言う／**言ったとおりその行のすぐ上に入る**。
  後片付けも「消えた」で確かめる（§9.362）。
- `tests/test_waitlint.py`（8→10件）… Promiseを返す述語が0件であること。
- `tests/test_srcsync.js`（§9.375）… 2箇所を`W.poll`へ直した。**欠陥注入
  （取り込みを止める）で4件が落ちる**ことを確かめ直した——直す前は
  この4件のうち2件が落ちなかった。
