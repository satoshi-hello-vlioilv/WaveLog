# §9.356 通しで落ちた本はその場で単独へ回して切り分ける。実績も1本ごとに戻す

利用者の指示:「複数回発生している不具合は再発防止策もしっかり検討し、仕組みに
組み込んでください。フルスイートを複数回回すのは非効率すぎます。」

## 何が起きていたか

通し（6,100件・32分）を回すたびに **4〜7本が落ち、顔ぶれが毎回違った**:

| 回 | 落ちた本 |
| --- | --- |
| 1回目 | opunit 2件・screorder・choicelinkui |
| 2回目 | recdel・choicelinkui・nav・opblanktint・screorder・wkfast・scsave |
| 3回目 | ngdone・opunit・screorder・wkfast |
| 4回目 | wkfast |

**単独では緑**のものが多く、切り分けるには**通しをもう一度回す**しかなかった（32分）。
しかも「単独で緑だから揺れ」と片付けると、本物を見逃す（§9.200）。

## 決めたこと

### 1. 落ちた本は、通しの最後にその場で単独へ回す

`tests/run_all.sh` が落ちた本を控え、**最後に1本ずつ単独で回し直す**（状態を白紙へ
戻してから）。結果を2つに分けて出す:

```
-- 落ちた本を単独で回し直す（順番・状態への依存かを切り分ける） --
   test_wkfast.js           単独でも落ちる（本物）
   test_nav.js              単独では緑（順番・状態への依存）
```

**直し方がまるで違う**——前者は製品かその網の期待そのもの、後者は網かランナー。
落ちた本だけなら数十秒で済むので、**通しを2回回す理由が無くなる**。
`WAVELOG_NO_RETRY=1` で止められる。

### 2. 測定の実績も1本ごとに空へ戻す

**実行をまたいで生き延びる置き場は、これで3つ目**:

| 置き場 | 戻す仕掛け | 入った時期 |
| --- | --- | --- |
| 作業予定（共有スケジュールDB） | `reseed`（`make_fixture.py`） | 以前から |
| 見せ方（列レイアウト・内容欄） | `resetcontent` | §9.121 |
| **測定の実績（`records.sqlite3`）** | **`resetrecords`** | **ここ** |

残った実績は**計画外実績として予定表に現れ**（§9.33）、行数・作業可否・「作業中」の
有無を変える。実測で **6件**残っていた（`RPPROD-G3`・`stc-done`・設備名の空いた行…）。
後片付けを忘れた1本が、**無関係な網を落とす**。壊れ方が遠いので、落ちた側を見ても
原因に辿り着けない。

実績を前提にする網は**自分で置いて自分で消す**（§9.351）。ランナーが1本ごとに空へ
戻すので、置き土産に頼る網は**その場で落ちる**——遠くの1本ではなく、自分が落ちる。

## 見つけた本物（`test_wkfast`）

「保存値だけで判定した時点では仕掛を読んでいない」（`pages===0`）は、**種データと
矛盾していた**。種は「可」と「不可」の両方を持つ（不可10件。`make_fixture.py` が
意図してそうしている）。製品は `state!=='ok'` の行を取り直しに行く（§9.67）ので、
**不可が1件でもあれば必ず読む**。

以前この判定が通っていたのは、**前の実行が残した実績で予定の状態が変わり、
たまたま不可が0になった回**だけ。つまり**置き土産に依存して緑になっていた**——
「緑に見えている壊れた網はもっと悪い」（§9.200）の実例。

判定を実態に合わせた: 「最初の描画に『?』が無い」＋「読みに行くのは『可』でない行が
あるときだけ」。

## 効いた（通しで確かめた）

仕組みを入れて通しを回すと、**落ちた本が 4〜7本 → 1本**になった（6130/6131）。
残った1本は切り分けが「単独でも落ちる（本物）」と言い、実際に本物だった:

`test_opunit` の「見本の単位は1つだけ」は、置き場を押したあと **450ms の固定待ち**で
測っていた。通しのときだけ間に合わず、**前の置き場のまま**測って落ちていた
（実測: 「内部」を押したのに `位置:"外下左"`）。見本の `data-opunit` が押した先に
なるまで待つ形へ直した（§9.102）。

**切り分けの前にサーバーは再起動しない。** 「通しの直後の状態」を保ったまま回すから
こそ、この本は再現した——再起動すると、通しでだけ出る問題を取り逃がす。

## 踏んだ罠

- 落ちた本を控える1行を `run()` へ入れ忘れ、**切り分けが一度も走らなかった**
  （`RETRY` は空のまま）。**わざと落として確かめる**まで気づけない——
  仕組みを入れたら、その仕組みが働くことを注入で見る。
