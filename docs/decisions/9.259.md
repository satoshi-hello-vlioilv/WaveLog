# §9.259 列の見せ方を「みんなと同じ／自分だけ」で選ぶ（利用者の指示）

> 列の表示の部分については、こだわりが強い人もいるので、表示する一覧表毎に
> 共通のものを使うか、個別ID単位のものを使うか選べるようにしたいです。

列レイアウトマスタは今まで全員で1つだった。こだわりのある人が並びを直すと
**全員の見え方が変わる**ので、直したい人も遠慮して直せない。かといって全部を
個人のものにすると、決めた並びを配れなくなる。**一覧ごと・人ごとに選べる**のが
答えで、これはフィルタを「個人のもの／共有のもの」に分けた§9.172と同じ形。

**入れ物は2つ。** 列レイアウトマスタの`[所有者ID]`（**空欄＝みんなのもの**。
既存の行はそのまま共通の設定として効き続ける）と、切り替えの記憶を持つ
`列レイアウト個人設定マスタ`（**行が有る＝その人はその一覧で個人設定を使う**。
フィルタ個人設定マスタの「行が無い＝印なし」と同じ約束）。

**誰の行を読み書きするかは`column_layout_owner()`の1箇所が答える。** 読む側
（GET）と書く側（POST）と切り替える側が全部ここを通ることで、「画面には個人の
並びが出ているのに保存は共通へ行く」が構造として作れない。

**画面は今までどおり対象(target)だけを送る。** 所有者の解決はサーバーが持つので、
`list:<DB>:<表>`のような文字列の組み立て方をサーバーへ持ち込まずに済む
（§9.187で「targetの組み立て方をサーバーが知ることになる」を避けたのと同じ理由）。
おかげで`WL.columnLayout`を呼ぶ約30箇所は1つも変わらない。

**鍵は(対象,列名)から(対象,列名,所有者ID)へ張り直す。** 張り直さないと、
同じ列の個人設定を1つも作れない（`UNIQUE constraint failed`で落ちる）。
**所有者IDをNULLにしないこと**——SQLiteの一意索引はNULL同士を「違う」と見るので、
同じ列の行が何本でもできてしまう。`NOT NULL DEFAULT ''`で必ず値を持たせ、
古い行は`''`へ揃えてから張り直す。

**個人にするときは、いま見えている共通の設定を写してから切り替える。** 白紙から
始めると、こだわって作った並びが押した瞬間に消えたように見える。
**共通へ戻しても個人の行は消さない**（また個人へ戻せば続きから使える）。
消したいときは列の設定パネルの「まっさらに戻す」を使う。

**差分保存(§9.212 ②)で残す値は、同じ所有者の行から取る。** 共通から取ると、
個人設定を1項目だけ触った瞬間に残りが共通の値で塗り替わる。

**利用者IDが空なら必ず共通。** 空を1つの入れ物として扱うと、IDを名乗れない端末
どうしが同じ「個人設定」を共有してしまい、共通と区別が付かなくなる（フィルタの
§9.172は空を受け皿にしてよいが、あれは印であってレイアウトそのものではない）。
画面では**押せなくして理由を書く**（§4）。

**持ち出し(§9.178)は共通ぶんだけ。** 持ち出しは「みんなの設定」を配るための
ものなので、誰かの個人設定が混ざると受け取った側の全員にその人の好みが当たる。

**画面はいまどちらかを必ず文字で出す**（§3）——黙って個人の並びを出すと、
自分にだけ違って見える理由が画面のどこにも無くなる。**利用者IDは`/api/whoami`から
後から届く**ので、`load()`は**どの利用者IDで読んだかを覚え、変わったら読み直す**
（§9.184と同じ罠。覚えないと、その人の個人設定は永久に載って来ない）。
パネルが一覧より先に開いたときは、読んでから描き直す（「読む前だから分からない」を
「みんなと同じ」と言い切らない）。

**紙の割り付けは対象外**（`opsheet-print.js`が`personalScope:false`）——同じ名前の
紙を2人が刷って中身が違う、が起きる。利用者の指示も「表示する**一覧表**毎に」。

**確かめるときの落とし穴**: 差分保存の網は、個人と共通で**触っていない項目の値を
わざと違えてから**部分保存すること。同じ値のままだと、残す値をどちらから取っても
同じ答えになり、**共通から取る欠陥を素通りさせる**（実際に一度素通りした）。
固定は`tests/test_colscope.py`（4つの欠陥で落ちることを確認済み）・
`tests/test_colscopeui.js`。
