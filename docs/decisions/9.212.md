# §9.212 設定の保存を「送った項目だけ・下書きは別・状態を出す」へ（利用者の指示）

利用者の言葉:

> 「操作した内容が、スムーズに反映され、待たされず、**修正した内容が
> 戻されたりしない**ために、より良い方法があれば提案していただきたいです。」
> 「書き込み方向指示はマストではなく、目的を達成するための手段として
> どうかという提案です。」

§9.211 ①で列幅の不具合を3つ直したが、**どれも「全置換の保存」と
「1枚しかない写し」という土台から生えていた**。同じ形の事故が今後も
起きるので、土台のほうを次の1本の決まりへ組み直す。

> **画面が正。保存は追いかける。読み直しは初回・手動・自分が変えた直後だけ。**

内訳は5つで、①⑤は§9.197・§9.211 ①で入っている。ここで②③④を入れる。

| | 内容 | どこ |
|---|---|---|
| ① | 操作している間は裏の読み直しに表を作り直させない | `WL.columnResize.busy()/defer()`（§9.211 ①） |
| ② | 保存を「送った項目だけ更新」にする | `POST /api/column-layout-master` |
| ③ | 下書き（設定パネル）と保存済みを分ける | `WL.columnLayout`（3枚の重ね） |
| ④ | 保存の状態を画面に出す | `WL.saveState`／`#saveState` |
| ⑤ | 読み直しの合図を絞る | `load()`のキャッシュ・`canAutoReload()` |

#### ② 保存は「送った項目だけ書く」

以前は対象(`target`)の行を全部消してから入れ直す**全置換**で、
docstringにも「幅だけを変えたいときも並び全体を送ること」と書いてあった。
その通りに書けなかった呼び出しが**実際に3回**壊した:

- 見出しを1回ドラッグしただけで計算式の列が全部消える（§9.113、`formulas`）
- 列幅を保存すると列ごとの並べ替えが消える（§9.211 ①、`sorts`）
- 幅固定が解ける（§9.119、`locks`）

呼ぶ側は十数箇所に散っており、「9個のキーを毎回全部渡す」を各所で守らせるのは
無理筋。**入口で安全側へ倒す**——JSONにキーがあるものだけを書き換え、
無いものは今の値を残す（`set_column_layout(..., fields=…)`）。
パス設定マスタが§9.192で同じ理由で同じ形にしてある。

**並び(`order`)だけは全体を送る。** 部分的な並べ替えは「どちらが正か」が
決まらない（A→BとC→Dが別々に走ると結果が定まらない）。

**空と省略は別のこと。** `hidden:[]`は「隠す列は無い」、`hidden`が無いのは
「触っていない」。そのうえで**まっさらに戻す口**として`clear:true`を足した
——差分更新にすると「全部消す」が9個のキーを空で並べる作業になり、
**1つ書き漏らすとその設定だけ生き延びる**（検証の後片付けで実際に困った）。

固定は`tests/test_colsave.py`。**「clearを付けなければ残る」ことも見る**
——片方だけでは、全置換に戻しても半分は通ってしまう。

#### ③ 下書き・掴んでいる最中・保存済みを別の重ねにする

`WL.columnLayout`は写しを1枚しか持っておらず、`stage()`（保存せずに画面へ
当てる）が**保存済みと同じ入れ物**を書き換えていた。列の設定パネルは
モーダルではない浮きウィンドウなので開いたまま見出しを触れてしまい、

- 見出しからの保存が**パネルの未保存の編集ごと**マスタへ書き込む
- 逆にパネルを保存せずに閉じると**保存済みの幅まで巻き戻る**

の両方が起きていた（§9.211 ①で`noteSaved()`という継ぎ足しを入れたが、
控えを2箇所に持つのが元の無理）。3枚に分ける:

- **saved** … サーバーにある形。`load()`/`save()`/`patch()`だけが書く。
- **draft** … 設定パネルの未保存の編集。`stage()`で置き、`discard()`で捨てる。
- **live** … 掴んでいる最中の見え方。`hold()`で置き、`release()`で捨てる。
  **保存には行かない**（離した時点の値だけを`patch()`が送る）。

画面に出るのは3枚を畳んだ値で、**上の重ねが勝つ**。

**重ねは「触っている項目だけ」を持つこと。** 最初`hold()`を
`{...get(target), ...body}`（まるごとの写し）で書いたところ、
`widths`しか触っていない重ねが`hidden`まで抱えてしまい、
**その裏で保存された`hidden`が見えなくなった**——列を1つ動かした直後の
描き直しで「畳んでいたはずの5列」が出て、見出しのセル数(19)と
`--sc-cols`のトラック数(16)が食い違い、**表が1列ずつずれた**
（`tests/test_sctimecols.js`が3件で捕まえた）。畳んだ結果は覚えて、
どれかの重ねが変わったときだけ捨てる（1列ごとに引く場面があるので、
毎回作り直すと重い）。

保存を組み立てる側は**必ず`WL.columnLayout.saved(target)`から材料を取る**
——`get()`は下書きを含む。

#### ④ 保存の状態を1箇所に出す

設定の保存はこれまで**黙って投げていた**ので、失敗しても画面には何も出ず、
**次に読み直したときに元の値が出てくるだけ**だった——本人からは
「勝手に戻った」としか見えない。

置き場は**画面名の右（タイトル帯 `.hd-context`）の1箇所**。どの画面の
どの設定を保存していても同じ場所に出るので探さなくてよい。
**状態は色だけで伝えない**ので必ず文字を出し（保存中…／保存しました／
保存できませんでした）、**失敗は消さずに残して「再試行」を同じ場所に置く**。
成功は2秒で引っ込める。**失敗は呼び出し側へも投げ直す**——黙って
「保存できた」ことにしない。

固定は`tests/test_lcpanel.js`（下書きと保存済みが混ざらないこと・
保存せずに閉じても外から保存した幅が残ること・状態が文字で出ること）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **列設定の保存は「送った項目だけ書く」**（§9.212 ②）: `POST /api/column-layout-master`は
  JSONにキーがあるものだけを書き換え、**無いものは今の値を残す**。以前は常に全置換で、
  呼ぶ側が1項目でも渡し忘れるとその設定だけが黙って消えた（計算式§9.113・並べ替え
  §9.211 ①・幅固定§9.119の3回）。呼ぶ側は十数箇所に散っているので**入口で安全側へ
  倒す**（パス設定マスタ§9.192と同じ作法）。**並び(`order`)だけは全体を送る**
  ——部分的な並べ替えはどちらが正か決まらない。**空と省略は別のこと**で、
  `hidden:[]`は「隠す列は無い」、`hidden`が無いのは「触っていない」。
  **まっさらに戻すときは`clear:true`**——付け忘れると送っていない設定だけが
  生き延びる（検証の後片付けが実際に困った）。固定は`tests/test_colsave.py`
  （**「clearを付けなければ残る」ことも見る**。片方だけでは全置換に戻しても半分通る）。
- **`WL.columnLayout`は3枚の重ね**（§9.212 ③）: **saved**（サーバーにある形。
  `load`/`save`/`patch`だけが書く）／**draft**（設定パネルの未保存。`stage`で置き
  `discard`で捨てる）／**live**（掴んでいる最中。`hold`で置き`release`で捨てる。
  **保存には行かない**）。画面に出るのは3枚を畳んだ値で上が勝つ。
  **保存を組み立てる材料は必ず`WL.columnLayout.saved(target)`から取る**
  ——`get()`は下書きを含むので、そこから作ると**パネルで触っただけの内容まで
  マスタへ入る**。**重ねは「触っている項目だけ」を持つこと**——`{...get()}`で
  まるごと写すと、`widths`しか触っていない重ねが`hidden`まで抱え、
  **その裏で保存された`hidden`が見えなくなる**（見出しのセル数と`--sc-cols`の
  トラック数が食い違い、表が1列ずつずれた。`tests/test_sctimecols.js`が検出）。
  畳んだ結果は覚え、重ねが変わったときだけ捨てる（1列ごとに引く場面がある）。
- **設定の保存の状態は`WL.saveState`が1箇所に出す**（§9.212 ④）: 置き場は
  タイトル帯の`#saveState`。**黙って投げないこと**——失敗しても画面に何も出ないと、
  次の読み直しで元の値が出るだけで「勝手に戻った」としか見えない。
  保存中／保存しました／保存できませんでした＋**再試行**を文字で出し、
  **失敗は消さずに残し、呼び出し側へも投げ直す**。成功は2秒で引っ込める。
