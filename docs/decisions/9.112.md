# §9.112 行の中の高さ: 器の外寸から作ると必ずはみ出す

実機から2点。「作業スケジュールの操作ボタンUIと文字が見切れている（規格化の
漏れかもしれない）」と「列レイアウトの並べ替えでゴーストが出ない」。
**どちらも当たっていた。** 前者は規格化の漏れそのもので、後者は
「作ってはいたが一度も見えていなかった」。

#### 見切れの原因: `--row-ctl-h` が行の**外寸**から作られていた

行の高さの決まりは §9.90 でこう書かれている——

```
--row-h = --fs × --lh + --row-pad-y × 2 + 1px(罫線)
```

`--row-h` は行という器の**外寸**で、上下の余白と罫線を**含む**。ところが
行の中のボタンの高さは

```
--row-ctl-h = min(--ctl-h-xs, --row-h - 2px)     ← 誤り
```

と、その外寸から2pxだけ引いた値になっていた。行の中に実際に入れる高さは

```
--row-inner-h = --row-h - --row-pad-y × 2 - 1px  (= --fs × --lh)
```

なので、**ボタンは必ず器より「余白2つ＋罫線 − 2px」ぶん高い**。実測すると
表示サイズ 極小 +6px / 小 +7px / 中 +7px / 大 +8px / 特大 +9px で、
**大きくするほど差が開く**（利用者から見ると「拡大しても直らない」）。
セル（`.sc-row-line>*`）は `overflow:hidden` なので、はみ出したぶんは
そのまま切り落とされる。同じ計算違いが仕掛一覧のロット番号リンク
(`.lot-dsp-link`)にもあり、こちらは `line-height` に `--row-ctl-h` を
そのまま入れていて（罫線1px×2を引いていない）5段階すべてで2px切れていた。

**直し方は「行を高くする」ではなく「行に入る大きさにする」。** §9.90 が
「行の下限を決めるのは行の中の**文字**であって `--ctl-h-xs` ではない」と
決めているので、ボタンの側が縮む。`--row-inner-h` をトークンとして置き、
`--row-ctl-h` はそこから作る。**`--row-ctl-h` を定義し直している3箇所
（`:root` / `#grid` / `.sc-row-line`）すべてで揃えること**——1つ直しても、
定義し直した場所ではそちらが勝つので直らない（実際、`:root` だけ戻して
再現を試みたときに何も起きず、原因を見失いかけた）。

副次の2つも同時に直る形にした。

- **記号だけのボタンは正方形にする。** 幅の下限が `--ctl-h-xs`（行の外の
  ボタンの高さ）だったため、縮んだ高さとの差がそのまま横長の歪みになる。
  `min-width` も `--row-ctl-h` にする。
- **タイムラインの `--row-pad-y` から差分3pxを外す。** 「一覧の行の高さへ
  寄せるため」に足していたものだが、当時一覧の行が高かったのは上の計算違いで
  行内ボタンが7px膨らんでいたからで、**寄せる先そのものが狂っていた**。
  残すとタイムラインのほうが一覧より背が高くなり、「一覧より少しだけ密」
  （§9.36）の逆になる。

#### ゴーストの原因: 重なり順が直値で、器の裏に回っていた

列の設定パネルの並べ替えは、掴んだ行の写し（`.lc-ghost`）を `body` 直下へ
作って指に付いてこさせる作りになっていた。しかし `z-index:60` の直値で、
パネル自身は浮きウィンドウ（`--z-popover` = 1600）。**写しは常にパネルの裏**
にあり、DOMには居るのに一度も見えていなかった。掴む場所が浮きウィンドウの
中である以上、ゴーストは**掴んだ元の器より上**に出す必要がある。
トークン `--z-drag`(1650) を足し、傾き・影で「持ち上げている」ことを形でも
示す。**存在するかどうかだけを見るテストでは捕まらない**（DOMには居る）ので、
**掴んだ元の器と重なり順を比べる**こと。

#### 安全網が2px見逃していた

`tests/test_fit.js` はこの種の見切れを見るための網なのに、両方とも素通り
させていた。理由は2つ。

1. **許容が2px**だった（字形の丸めを見込んだ値）。ロット番号リンクの
   はみ出しは**ちょうど+2px**で、境界の内側に収まっていた。→ 1pxへ。
2. **先祖にスクロールできる器があれば見逃す**作りだった。「器ごと動かせば
   読める」という理屈は正しいが、**その要素自身が `overflow:hidden` で
   切り落としている**場合には当てはまらない。仕掛一覧の中身は `#grid`
   (`overflow:auto`)の子なので、**セルの中で切れているものが全部見逃されて
   いた**。→ 自分自身が切り落とす軸では、先祖のスクロールを言い訳にしない。

`tests/test_typescale.js` の「行内のボタンは行に合わせて縮む」も書き換えた。
直した後は**行間を変えても入れる高さは変わらない**（変わるのは余白のほう）
ので、「縮むこと」は不変条件ではない。守るべきは「**どの行間でもセルに
収まっていること**」。同じ理由で「最密の行は既定より明確に低い」の閾値も
px差から割合へ変えた——px差の6という数字は、行内ボタンが行を膨らませて
いた頃の値だった。

固定は`tests/test_fit.js`（5段階×8画面で溢れ0。`--row-ctl-h` を元の式へ
戻すと5サイズすべてで `.sc-row-actions` を名指しで落とす）と
`tests/test_lcpanel.js`（ゴーストが出る・掴んだ元より上・離すと消える。
`z-index:60` へ戻すと「上に出る」だけが落ちる）。
**どちらも、直す前の実装に戻して落ちることを確かめてある。**

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **重なり順は`--z-*`のトークンから選ぶ**（§9.112）: `--z-overlay`1100 /
  `--z-modal`1500 / `--z-popover`1600 / **`--z-drag`1650**（掴んでいる最中の
  写し）/ `--z-settings`5000 / `--z-confirm`5200 / `--z-toast`5300 /
  `--z-boot`9000 / `--z-alert`9999。**直値を書かないこと**——ゴースト
  (`.lc-ghost`)が`z-index:60`だったため浮きウィンドウ(1600)の裏に回り、
  DOMには居るのに**一度も見えていなかった**（実機で「ゴーストが出ません」と
  報告された）。**ゴーストは掴んだ元の器より上**に出す。DOMに在るかどうかを
  見るテストでは捕まらないので、**元の器と重なり順を比べる**こと。
