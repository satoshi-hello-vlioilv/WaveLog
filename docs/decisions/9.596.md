# §9.596 完了突合の編集窓を「完了突合の作り」にする——決める順の4節＋右に「いまの設定」の文と「いまの予定で試す」・「2件以上は空にする」を完了の判定にも効かせる（7案→組合せ→3回目の M・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.595](9.595.md)｜関係: [§9.365](9.365.md)・[§9.367](9.367.md)・[§9.514](9.514.md)・[§9.595](9.595.md)

## 経緯（利用者の言葉）

> 完了突合せの場合、クエリ結合の今の入力方式ベースだと少し違和感が残る作り（おそらく想定外）の状態になっているので
> 使いやすさの改良も含めて修正をお願いします。

## 1. 物差しと前後の値

完了突合（`purpose='完了突合'`）の編集窓を 1728×1152 と 1536×864 で撮り、次の5つを数えた（同じフィクスチャ・同じ定義）:

| | 一覧の結合の言葉（用途の札を除く） | 効かない／誤解させる欄 | 画面と動きの食い違い | 開いた時点で②「いつ完了」が見える（1536） | いまの予定で試せる |
| --- | --- | --- | --- | --- | --- |
| 前（main 728a172） | **12** | **2** | **1** | いいえ | いいえ |
| 後 | **0** | **0** | **0** | はい | はい |

- 一覧の結合の言葉: 「足す先」「足す列」「列を足します」「一覧の帯」「一覧を開き直す」「この一覧」「『結合』欄」など。
  完了突合は列を足さないのに、窓の字の半分は一覧の結合の説明のままだった（用途で字を変える所が無かった）。
- 効かない欄: ②の左の「この一覧（足す先）」のデータと表の選択。完了突合は**仕掛の役割のデータで決まる**
  （`finish_definitions()`が`left == 仕掛`の行しか拾わない）ので、選び直すと**黙って効かない定義**になった。
- 食い違い: ④「相手が2件以上あったら」＝「空にする」を選んでも、完了の判定（`actual_match._find_right`）は
  **先に見つけた1行で完了にしていた**。下見（⑤）は「2件以上あったキー」と数えるのに、予定は完了になる。
- 窓の中身の高さ（1728）: 1413 → 1403px。

## 2. 決めたこと

1. **用途で変わる字は`QJ_WORDS`の1箇所**（`qjWord(k)`が用途を見て引く）。窓の節の見出し・説明・足元の1行・
   並べ替えの札・「全部持ち帰る」の札まで、完了突合では完了突合の言葉で言う。一覧の結合の字は今までどおり。
2. **左（予定のロット）は選ばせない**。札と「役割『仕掛』のデータで決まります（選び直せません）」の1行だけ。
   開いた時点で`left`を仕掛のデータへそろえる（古い定義で別のデータを指していても、保存すれば直る）。
3. **「2件以上は空にする」は完了の判定にも効く**。相手に同じキーの行が2件以上あれば、先頭の行を印（`_DUP`）つきで
   控え、`multi='blank'`の定義では**完了にしない**（理由「どれか決められません」・`code='ambiguous'`）。
   既定（`first`）は今までどおり先頭の行で完了。
4. **`lookup()`は理由の種類（`code`）と足りない鍵（`lacking`）を返す**（hit／inWork／gone／keys／nofile／ambiguous／read）。
   仕掛に残っているロットでも、直すべき理由（鍵が揃わない・ファイルが無い・決められない）があればそれを言う。
5. **いまの予定で試すのは`actual_match.trial()`の1箇所**。材料は`schedule_calc.trial_plans()`（まだ完了していない
   作業の親の行のうち、実績を保存していないもの）。内訳の名前・色の段・意味はサーバーの`TRIAL_KINDS`が持ち、
   画面は読むだけ。下見の口（`/api/query-join-master/probe`）が`trial`を一緒に返す。

## 3. 画面（E の手順・1728×1152 と 1536×864 で撮って採点）

基準と重みは採点の前に決めたが、**その控えが残っていない**（作業の途中で会話を畳んだときに失った。値は**分からない**）。下の点は採点したときの値。

撮って見えた今の悪い所: 1536 では開いた窓に「いつ完了にするか」が出ず（③が画面の下）、決める順（いつ完了→何で探す）と
並び（何で探す→いつ完了）が逆。左の欄が選べるのに効かない。保存する前に「いまの予定がどうなるか」が分からない
（⑤の下見は相手の表の数しか言わない）。

| 回 | 案と点 |
| --- | --- |
| 1回目（A〜G） | C 80・E 77・D 76・G 75・F 73・B 72・A 69 → 1位と2位の差が3点（僅差） |
| 2回目（組合せ H〜K＋上位3） | K 87・H 83・I 82・C 80・E 77・D 76・J 76 → 90未満 |
| 3回目（組合せ L〜O＋上位3） | **M 93**・O 92・L 91・N 91・K 87・H 83・I 82 |

**M** を入れた（3回目の最高点）:

- 主の列は決める順の4節: ① これは何か → **② いつ完了にするか**（札2枚・作業時間にする列・いまの予定で当たった
  1件の見本）→ ③ 実績のデータと突合キー（左は固定の札）→ ④ 何を持ち帰るか（持ち帰る値の見本つき）。⑤は持たない。
- 右の列（窓の中で止まる）: **「いまの設定」を1つの文で言う**（予定のロットを〈実績のデータ〉の〈鍵〉で探し、
  〈当たったら〉完了にして、〈開始〉〜〈終了〉を作業時間にする）。札を押すとその欄へ移って光る（図と入力を結ぶ）。
  その下に**いまの予定で試す**: まだ完了していない作業 N件の内訳を帯と行で（完了にする・予定のまま・完了・時刻なし・
  鍵が揃わない・ファイルが無い・決められない・読めない）、足りない鍵の名前と件数、例のロット。
- 案の要（他の案から抜き出した物）: C の「右にいつも見える答え」、D の「文として読める組み立て」、
  K の「いつ完了を先に」、G の「直す節へ飛べる」。
