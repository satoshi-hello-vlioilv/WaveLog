# §9.186 印刷はプレビューを先に出す（利用者の指示）

利用者の指示: 「プレビューを出す前にいろいろ聞きすぎるので、一旦今の条件で
プレビューを出して、必要なら設定変更するような形で修正内容をリアルタイムで
プレビューで見せる形にしてください」。

以前は「印刷しますか？」＋チェック4つの確認から始まり、**紙を見る前に
決めさせていた**。日付ごとに分けるか・実績欄を付けるか・完了も載せるかは、
どれも刷り上がりを見れば分かることなので、聞く順番が逆だった。

- 押したら**すぐ今の条件の紙**が出る（設定は端末に覚えてある）。
- 左に決めること、右に刷り上がり。並びは実際にする順（①何を載せるか →
  ②紙の列 → ③刷り上がり → 印刷）。
- **設定を触るとその場で変わる。** 枚数もその場で出る。紙の列
  （§9.118のレイアウト）を保存したときも描き直す。
- **組み立ては`buildPages`/`splitToSheets`/`pageHtml`の既存の1本**を通す。
  プレビュー用の別の組み立てを作らないこと——見たものと刷るものが違ったら
  プレビューの意味が無い。「印刷する」は**見えている紙をそのまま**出す。
- 紙は実寸(mm)のまま組み、`transform:scale()`で縮めて見せる。倍率は
  **幅と高さの両方**へ合わせる——幅だけだと1枚が縦に切れ、「A4に収まって
  いるか」というプレビューの一番の用が果たせない。

固定は`tests/test_scprint.js`（12節）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **印刷はプレビューを先に出す**（§9.186、`static/js/schedule/schedule-print.js`）:
  以前は確認ダイアログでチェック4つを聞いてから刷っており、**紙を見る前に
  決めさせていた**。押したらすぐ今の条件の紙を出し、設定を触るとその場で
  刷り上がりが変わる形にする。**組み立ては既存の1本**（`buildPages`/
  `splitToSheets`/`pageHtml`）を通し、プレビュー用の別の組み立てを作らない
  （見たものと刷るものが違ったら意味が無い）。倍率は**幅と高さの両方**へ
  合わせる（幅だけだと1枚が縦に切れ、A4に収まるかが分からない）。
