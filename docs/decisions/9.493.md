# §9.493 作業スケジュールの小計——まとめとは別の軸で、区切りごとに作業ロット数と選んだ列の合計を出す（利用者の指示）

索引: [決定記録](README.md)

## 経緯

利用者の指示:
「作業スケジュール一覧で、日単位または直単位でまとめ機能はありますが、それと同じように、でも独立して集計を
まとめて小計として指定した単位ごとに行またはラベルとして出すようにしたいです。作業ロット数、指定した項目列の
合計値（例えば重量）など、ある程度汎用性を高く想定して作成してください。ONOFFの機能も実装お願いします。」

## 決めたこと

1. **まとめとは別の軸**。まとめ＝行を箱に分けて頭に見出しを付ける／小計＝区切りの**お尻**で数える。
   どちらを変えても他方は動かない。区切りの語彙と日付の数え方は**`bucketOf(e,mode,col)`の1本**を共有する
   （`groupBucketOf()`はその薄い呼び名になった）。語彙を2つ持つと、片方だけ直した日に「見出しは8/18なのに
   小計は8/19」が起きる。
2. 区切りは まとめ の6つ（日付〈現場歴／太陽暦〉・勤務・日付＋勤務〈2つ〉・区分）＋**「列の値が変わるごと」**
   （材質・調質・計算列など、表に出している列を1つ選ぶ）。区切りは**続いている間は同じ**（まとめと同じ作法）。
3. **数えるのは作業ロットだけ**（`subtotalCounted()`の1箇所）。取消・設備停止・申し送り・枠は数えず合計にも
   入れない。子ロットは親の1本（値は親の行が持つ——子を足すと同じ重量を2度数える）。
4. 合計は**数として読めた値だけ**を足す。桁区切りの`,`は読み、数の後ろの字（kg など）は単位として控え、単位の
   違う値は足さない。読めなかった値は**0として足さず**、合計に`*`を付けて`title`で件数を言う（黙って足すと、
   小計が小さく出ても気づけない）。1件も読めなければ「—」。
5. 値の出どころは**表のセルと同じ**`timelineRuleView().raw()`（固定列の字・式の列・内容の値）。時間の列
   （見積・実績）だけは字ではなく**分**を足す（`SC_SUBTOTAL_AMOUNT`）——字の書き方は「表示」で変わる（§9.341）。
   足せない列（区分・日付・時刻・印・人・操作）は候補に出さない（押せても何も起きない物を置かない）。
6. 出し方は2つ:
   - **行** … 表と同じグリッド（`--sc-cols`・`--row-h`）に載る1行。合計は**足した列の真下**。名前は最初に足す列より
     左の列をまたいで置き、切れたら`title`で全文。最初の列から足すときは右端の余り（`1fr`）へ回す。
   - **ラベル** … 1行の帯。列にはそろえないので、どの列の合計かを字で添える。
7. 設定は**この端末・設備ごと**（`localStorage`の`ScheduleSubtotalV1`。列の顔ぶれが設備ごとに違うため）。既定は切。
   入口は「表示」パネルの1段（まとめの下）。切のあいだは「出さない／出す」の札だけ——出し方と列は出すと決めてから
   選ぶ。列の札には**いまの予定で数として読める件数**（`2/43`）を添え、1件も読めない列は押せなくして理由を書く。
   畳んだ入口にも「小計:〜」と出す（思い出させない）。
8. 並べ替え（`wireDrag`／`commitDragOrder`）は`.sc-row-line`だけを数えるので、小計の器は並びに入らない。

## しなかったこと・分からないこと

- **紙（印刷）には出していない**。紙の割り付け（`schedule-print.js`）は別の組み立てで、まとめの見出しは`groupOf`で
  運んでいる。小計も載せるなら同じ口（`WL.scheduleView`）から区切りを渡すのが筋だが、今回は画面だけにした。
- 設備停止の時間の合計（「この直で止めた時間」）は数えていない（作業ロットだけ）。要るなら数える行の決まりを
  `subtotalCounted()`の1箇所で広げる。
- 「表示」パネルは Esc で閉じない（前からの振る舞い。今回は触っていない）。
- 近くの網を回したとき、`test_sctimecols`が2件落ちた（「前提: 当たる行と当たらない行の両方がある」— 40行のうち
  完了の行が0）。**この変更を外しても同じに落ちる**（同じ顔ぶれで確かめた）ので小計のせいではない。
  `test_scpick`の直後に回すと必ず再現し、`test_colsrcfx`・`test_scprint`の直後では再現しない。ランナーの単独の
  回し直しは1回目が落ち2回目が通る（サーバーに一時的な何かが残る形）。`test_scpick`が片付けで取ったままにする
  編集セッションを返しても変わらなかった。**原因は分かっていない**（フレークとは呼ばない・§9.426）。
