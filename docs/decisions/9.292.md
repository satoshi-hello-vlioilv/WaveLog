### ① 印刷範囲（`static/js/schedule/schedule-print.js`）

`RANGE_MODES` は `all`（既定＝今までどおり全部）／`date`（現場歴の日付で
from〜to）／`picked`（一覧のチェックで選んだ予定だけ）の3つ。当てるのは
`applyRange()` の1箇所で、`collectPages()` が**設備ごとに**通す。

- **日付は `workDayKey()` で数える**——紙のページ分けと同じ関数。別に数えると
  「範囲は18日までなのに、18日の紙に19日の行が混じる」が起きる（§9.115・§9.197）。
- **親を絞り、残った親の子だけを残す**——子だけ落とすと内訳が消え、子だけ残すと
  親の無い行が紙に出る。
- **日付は打たせず、実際にある日から選ぶ**（`<select>`）。打つ形は①1文字ごとに
  欄が作り直されてカーソルが飛び（§9.117）②予定の無い日や逆さまの範囲を作れる。
- **日付の決まっていない予定は範囲に入れられない**（比べる値が無い）。落とすのは
  正しいが**黙って落とさない**（何件はじいたかを書く・§4）。
- **「選んだ予定だけ」はこの端末が開いている設備の選択**なので、他の設備には
  当てられない（そのことを画面に書く）。選んでいなければ押せなくして理由を書く。
- 何件中何件を刷るのかを必ず文字で出す（§3）。

固定は `tests/test_scprint.js` §9.292 ①——**札が並ぶことではなく、紙になる行が
実際に減ること**を見る（札だけを見る網は1件も絞らない実装でも通る）。

### ② 一覧の下の余白（`static/js/schedule/schedule-view.js`）

`#scTailSpace` を `renderTimeline()` の末尾に置き、高さは `fitTailSpace()` が
**測って**入れる（狙いは「最後の行の上端が器の上端まで上がれる」ことなので、
要るのは `器の高さ −（最後の行の上端から中身の下端まで）`）。

- **器の高さより大きくしない**（それ以上あっても押し上がる量は増えない）。
- **収まっている一覧は帯だけ**（`TAIL_MIN_ROWS`=2行ぶん）——押し上げる必要が
  無いのに1画面ぶん空けると、2件しかない設備で画面のほとんどが空になる。
- **空けた場所には役目を持たせる**——この帯は「ここへ落とすと、いちばん後ろに
  入る」の的で、そう書いてある。的として働かせているのは `insertSlotAt()` の
  1箇所で、**行と行のあいだの当たり判定（§9.199 の±8px）は広げない**。
- 器の大きさが変わったら測り直す（`ResizeObserver`）。`.sc-timeline` へ
  `scrollbar-gutter:stable` を置く（バーの出入りで測り直しが振動する・§9.227 ②）。

### ③ 同期のタイミング（`renderSyncChip` / `openSyncMenu`）

仕組みは §9.188 で既にあり `/api/schedule/sync-status` が全部答えている——
足りなかったのは**届く範囲**。チップに出ていたのは「12秒前に取込」だけで、
**次はいつか・見張りは動いているか・間隔はいくつか**は `title` の中にしか
無かった（触る画面では読めない・§4）。

押すと開く浮きメニューへ「見張り／次の確認／最後に取り込んだ／最後に確かめた／
共有が最後に変わった／改訂番号／書込役」を**時刻と経過の両方**で並べ、いちばん下に
「いま取り込む」を置く。**一覧の鮮度チップと同じ言語**にそろえてある（§9.286 ④）。

- **秒読みはしない**——巡回は10秒ごとなので1秒刻みの数字は必ずずれる。
  「およそ◯秒後」と幅で言う（§3）。
- **見張りが動いているときだけ「次の確認」を答える**——止まっているのに
  「30秒後」と書くと、待てば来ると読まれる（来ない）。
- 器の外へ `position:fixed` で出し（§9.201）、**開いた器を控える**（§9.222 ①）。

### ④ 列の設定パネルが開かない（`static/js/list/list-columns.js`）

**真因は差し替え口の契約違反**。`initialHidden` は「まだ一度も保存していない
ときの既定」を答える口で、**保存済みなら `null`** を返す約束
（`actuals-view.js` / `records-store.js` にそう書いてある）。ところがパネルは
戻りをそのまま `.filter` していたので、**一度でも列の設定を保存した一覧では
`Cannot read properties of null` で組み立てが止まっていた**。

さらに、**窓を最後に出していた**ので、組み立てが転ぶと窓はいつまでも出ない
（例外は `console` にしか出ない＝押しても何も起きないボタン）。いまは
**先に窓を出してから中身を組み立てる**。転んでも ①窓は出ている ②何が起きたのかを
窓の中に書く ③閉じられる、の3つが残る。**出すたびに画面の中へ引き戻す**
（`makeFloatingWindow` が返す `applyRect()`）——前より小さい画面で開くと
画面の外に出うる。

`wl-window.js` の引き戻しは **`rect` そのものを書き換えない**（`rect`＝利用者が
決めた形／引き戻し＝いまの画面へどう出すか。書き換えると、窓を小さくして開いた
あと元の大きさへ戻しても縮んだままになる）。

固定は `tests/test_actuals.js` §9.292 ④——**保存済みの状態で開く**こと（保存前に
開くだけの網は直す前でも通る）。

### ⑤ 帳票ブロックのラベルを上下に（`report_block_repo` / `master-maint.js` / `report-dashboard.js`）

マスの持ちものに `stack` を1つ足しただけ。**紙だけの設定（列レイアウトの
`formats`）にしない**——盤の見本には原理的に当たらず「見本は正しいのに紙だけ
別物」が作れる（§9.282）。ラベルを出さないマス・見出し・空きでは意味を持たないので
**サーバーと画面で同じ落とし方**をする。保存の形は §9.274 と同じで、
`stack` を使っている塊だけ JSON へ切り替わる（触っていない塊は1バイトも変わらない）。

盤には**マスごとの「並べ方」**と、**全部へ同じ値を書く操作**「ラベルを上下に」を
置く（設定は1つ・操作が2つ。§9.207 の「入口を2つにしない」に反しない）。

### ⑥ 紙の文字とセルの余白（`schedule-print.js` / `70-schedule.css`）

§9.236 の「収まるならそのまま使う」は**撤回した**——列の少ない設備では紙の右に
何十mmも余り、そのぶん文字が小さいままだった。いまは**余っているぶんだけ幅も
文字も一緒に大きくする**（縮めるときと同じ比率で向きが逆になっただけ）。
**幅と文字は必ず同じ比率で動かすこと**——片方だけ動かすと「画面で決めた
この列に何文字入るか」が紙で変わる（§9.237）。

- 地の大きさをひと回り上げた（見出し 9→10.5px／本文 11→12.5px）。
- `FONT_SCALES`（自動＝枠いっぱい／小・標準・大・特大）と `CELL_PADS`
  （詰める・標準・広め）を prefs へ。既定は `auto` / `1`。
- 上限 `MAX_FIT`=1.35（1列しか出さない紙で文字だけ巨大にならない）、下限は
  今までどおり `MIN_FIT`=0.62。**幅は必ず紙に収める**（`shareMm`）。
- **床に着いたら打つ手を書く**（§4）——「縮めています」だけでは、大きさを
  選び直しても変わらない理由と次にすることが読めない。列の範囲を狭める／
  用紙をA3・横向きにする、と名指しする。
- **効いている倍率は `withMm()` に聞く**（§9.163。画面で別に計算しない）。

### ⑦ 一覧を広く使う（`body.sc-wide`）

畳むのは**上の帯**（アプリのヘッダー＝画面名・状態・全体操作・操作列と、
スケジュールの道具列）で、実測でこの2つが縦に約110px使っている。
**左メニューは触らない**——あちらは自分の畳み（§9.58）を持っており、同じことを
する入口を2つ置かない（§9.207）。

- 印は `body.sc-wide` の1つ（§9.288 ⑥と同じ作法。画面ごとの書き分けを増やさない）。
- **戻る道は必ず1つ見えている**（§4）——器の右上の札と Esc。
  Escは**浮き窓・モーダルが開いていないときだけ**取る（窓を閉じたつもりで
  帯まで戻さない）、変換中は取らない（§9.221 ①）。
- 札は `.sc-body` の中へ置く——位置の基準になる `position:relative` を持って
  いるのはここで、`.sc-panel` へ relative を足すと `.sc-view-pop` など既に
  浮いているものの基準まで動く。
- 画面を出るときは印を外す（設定は残す）——外へ持ち出すと、他の画面で
  ヘッダーが消えたまま戻せなくなる。

固定は `tests/test_scbar.js` §9.292 ②③⑦、`tests/test_scprint.js` §9.292 ①⑥、
`tests/test_actuals.js` §9.292 ④、`tests/test_rbcells.py` / `tests/test_rbcells.js` ⑤。

  （§CLAUDE 8。似た数字が並ぶと、読む側は違うものかもしれないと数え直す）。
  いまはチップ1つで、文字は**この画面が読んだ時刻**だけ。共有の取り込み・書込役・
  改訂番号・読み込みの内訳は**押すと開く浮きメニュー**が持つ——§9.292 ③でメニューは
  既に全部答えていたので、足りなかったのは畳むことだけだった。**打つ手は足元に2つ**
  （「読み直す」＝この画面／「いま取り込む」＝共有。読む場所と打つ手を同じところに
  置く・§4）。**異常だけは文字にも出す**（§3）。
  **現場段取りの注記は一致しているときは出さない**——ヘッダーのバッジ
  （`#fieldReorderBadge`）が「並べ替え可」「設定要」の両方を既に言い分けており、
  操作列にも出すと同じ文が2つ並ぶ。**画面名の説明は畳んで`title`へ**（§9.234 ①。
  `setHeaderContext()`が入れているので読む手立ては残る）。
  **モードのチップは「モード ＋ 短い呼び名」**——`MODE_LABELS`のままだと
  「モード スケジュールモード」と1つのチップに同じ語が2回出る（文章の中は今まで
  どおり`MODE_LABELS`。「スケジュールへ切り替えますか？」では読めない）。
  固定は`tests/test_scbar.js`——**「チップが在ること」だけを見ないこと**（2つ
  並んでいても通る）。操作列の中で「時点／取込」を名乗る**見えている要素の数**を数える。
