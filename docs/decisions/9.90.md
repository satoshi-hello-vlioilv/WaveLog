# §9.90 寸法を文字サイズから決める / 列の設定パネルの作り直し

**きっかけ。** トークン化(§9.71)は済んでいたのに「文字サイズの統一感が
足りない」という指摘が続いた。実測すると原因は**トークン同士の関係が
決まっていないこと**で、2つに分かれた。

- **1つの表の中で文字サイズが3種類**。仕掛一覧はセル14px・行内ボタン12px・
  分割フラグ12px・バッジ10px(600箇所)。タイムラインは内容14px・日付12px・
  時刻13px・作業可否10px。同じ距離で同時に読むものの大きさが違う。
- **高さ÷文字サイズが7種類**(1.31/1.38/1.86/2.17/2.50/2.57/2.77)。同じ
  「ボタン」でも小さいものほど詰まって見える。

**決めたこと。**

1. **高さは文字から作る。** `--ctl-h-* = 文字(--fs*) × --lh + 上下余白×2`。
   役割の違いを持つのは**上下余白だけ**(5/7/8.5/10.5px)で、今の
   26/30/36/40px をほぼそのまま再現しつつ、文字を変えれば箱が必ず追随し、
   **文字が入らない高さになりようがない**。px の直値へ戻さないこと。
2. **表ごとにセルの文字サイズを1つ決める**(`--tbl-fs` / 印は `--tbl-fs-mark`)。
   器(`#grid` / `.sc-row-*`)が宣言し、中のセル・行内ボタン・印はそれを見る。
   一覧は`--fs`、15列並ぶタイムラインは`--fs-sm`。**行内のボタンはセルの値と
   同じ大きさ**で、1段下げるのは印(フラグ・バッジ)だけ。
3. **行の下限は行の中の文字**。`--row-h = --fs × --lh + 行の余白×2 + 罫線`。
   以前は`--ctl-h-xs(26px固定)`が下限を決めていて、行間を最密にしても
   31pxより詰まらなかった(「小さくする方向に調整できない」の原因)。
   行内ボタンは`--row-ctl-h = min(--ctl-h-xs, --row-h - 2px)`で**行に
   合わせて縮む**ので、ボタンが行を押し広げることもない。
   段階も詰める側へ寄せた(2/3/4/6/9px → 1/2/4/7/11px、最密で約22px)。
   **`--row-h`/`--row-ctl-h`は`#grid`側でも定義し直すこと**——カスタム
   プロパティは定義した場所で解決されるため、`:root`のままだと行間つまみ
   (JSが`#grid`へ`--row-pad-y`を差す)が効かない(`--row-pad-y`と同じ罠)。
4. **列の見出しは折り返さない。** 中途半端に2行になると行の高さが変わって
   表として読めない。入り切らないときは**まず左右の余白を削り**
   (`--row-pad-x-head`)、それでも足りなければ省略記号。
5. **数字は表全体で等幅**(`font-variant-numeric:tabular-nums`)。以前は書式を
   当てた列だけで、同じ表の中で桁の揃う数字と揃わない数字が混ざっていた。

**列の設定パネルは作り直した。** 下段の横長プレビュー表をやめ、**列のリスト
の中に「この列の見え方(実データ1件)」を入れた**。横長の表は37列あると端が
見えず、並べ替えの操作(縦のリスト)と結果(横の表)が別の場所に出るため視線が
往復する。1行=1列で「名前・出す/出さない・見え方」が同じ行に並べば、その行
だけを見て判断できる。既定の大きさも 880×620 → 1180×760 へ広げた
(37列ある一覧で11列しか見えなかった)。

- 触った結果は**保存せずに後ろの一覧へ即反映**する(`WL.columnLayout.stage()`)。
  設定画面の中の見本で想像させるより、本物の一覧が変わるほうが速く確実。
  **保存せずに閉じたら開いた時点の形へ戻す**(戻さないと「保存」の意味が消える)。
- **チェックは`click`で受ける。** `change`は`click`の後に飛ぶため、行の
  クリックで一覧を作り直す実装だと反映されない(外しても一覧に残る、という
  不具合として実際に出ていた)。
- **並べ替えは行のどこを掴んでもよい。** 押しただけなら列を選ぶ、少しでも
  動かしたら並べ替え、と**しきい値(4px)で分ける**。つまみの中だけを
  ドラッグ元にすると「掴めない＝並べ替えられない」と受け取られる。
- 書式・読み替え・表示名を変えたら**リストの例も描き直す**
  (`renderPreview()`が`renderList()`も呼ぶ)。ここを忘れると行の例が古い
  ままになり、「効いていない」と見える。

**浮きウィンドウは端ならどこでも掴んでリサイズできる**(四辺+四隅の8方向)。
つまみはJSが差し込む——浮きウィンドウは4箇所で作られており、HTMLに8個ずつ
書かせると書き漏らした窓だけ端を掴めなくなる。上・左へ伸ばすときは反対側の
辺を固定する(left/topも一緒に動かす)。

**一覧のツールバーは3つの群にまとめた**(見せ方 / 並び / 状態)。近接と囲みで
群を作り(共通領域)、状態(品質データ結合)は操作ではないので右端へ寄せる。
「いつも使う並び」は**選択+保存+削除の3つを1つのメニューへ畳んだ**——常に
見えている必要があるのは「今どれを使っているか」だけ。固定幅のselectを
やめたので、長い名前が途中で切れることも無くなった(実機で見切れていた)。

**読み込みの内訳を出す**(§9.90)。「一覧が出るまで時間がかかる」という報告に
対して、共有が遅いのか・量が多くて転送に時間がかかっているのか・描画なのかが
分からないと打ち手が決まらない。`/api/table`が`timing`(開く/列/件数/取り出し/
結合/読んだ場所)を返し、画面側が転送・整形・描画を実測して、待機表示と一覧の
脇のチップ(押すと内訳)へ出す。**描画時間は`renderGrid()`の中で測る**
——`filters.js`が`load()`を丸ごと置き換えるため、`load()`側に置くと絞り込みを
使ったときだけ測れなくなる(§9.88と同じ落とし穴)。

固定は`tests/test_typescale.js`(表の中の文字・見出しの折り返し・高さと文字の
関係・行間の下限・見切れ)と`tests/test_lcpanel.js`(パネルの大きさ・8方向の
リサイズ・チェック・並べ替え・即反映と取り消し)。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **寸法は文字サイズから作る**（§9.90）: `--ctl-h-*`は
  「文字(`--fs*`)×`--lh`＋上下余白×2」の式で、役割の違いを持つのは
  **上下余白だけ**。**pxの直値へ戻さないこと**——以前は26/30/36/40pxの直値で、
  高さ÷文字サイズが7種類に散り「同じボタンでも小さいものほど詰まって見える」
  状態だった。**1つの表の中のセル・行内ボタンは同じ大きさ**にする
  （器が`--tbl-fs`／印だけ`--tbl-fs-mark`を宣言し、中はそれを見る。一覧は
  `--fs`、15列並ぶタイムラインは`--fs-sm`）。行の高さは
  `--row-h = --fs × --lh + 行の余白×2 + 罫線`で、**下限を決めるのは行の中の
  文字**（`--ctl-h-xs`に依存させると行間を詰められなくなる。行内ボタンは
  `--row-ctl-h`で行に合わせて縮む）。**`--row-h`/`--row-inner-h`/`--row-ctl-h`は
  `#grid`側でも定義し直す**——カスタムプロパティは定義した場所で解決されるため、
  `:root`のままでは行間つまみが効かない（`--row-pad-y`と同じ罠）。
  **行の中に置くものの高さは`--row-inner-h`から作る**（§9.112）:
  `--row-h`は行の**外寸**で上下の余白と罫線を含むので、そこから作ると
  **必ず器よりはみ出す**。以前`--row-ctl-h`が`--row-h - 2px`だったため、
  行内ボタンが器より6〜9px高く、セルの`overflow:hidden`に切り落とされていた
  （実機で「操作ボタンと文字が見切れる」。**表示サイズを上げるほど差が開く**
  ので拡大しても直らない）。`box-sizing:border-box`なので、罫線のある部品へ
  `--row-ctl-h`を`line-height`として渡すときも**上下1pxずつを引く**
  （`.lot-dsp-link`がこれで2px切れていた）。**直すときは定義し直している
  3箇所すべてを揃えること**——1つだけ戻しても定義し直した側が勝つので、
  再現の確認そのものが失敗する。
  **列の見出しは折り返さない**（足りなければ余白を削り、次に省略記号）。
  固定は`tests/test_typescale.js`と`tests/test_fit.js`。
  **`tests/test_fit.js`の許容は1px、かつ「自分が`overflow:hidden`なら
  先祖のスクロールを言い訳にしない」**——2px許容＋先祖スクロールで
  見逃していたため、上記2件はどちらもこの網を素通りした。緩めないこと。
- **列の設定パネルは触った結果をそのまま一覧へ出す**（§9.90、
  `WL.columnLayout.stage()`で保存せずに当てる）。**保存せずに閉じたら開いた
  時点の形へ戻す**——戻さないと何が保存済みか分からなくなる。
  パネルの中の一覧は**1行=1列**で「名前・出す/出さない・見え方（実データ1件）」
  を同じ行に並べる（下段の横長プレビュー表は廃止）。**書式・読み替え・表示名を
  変えたらリストの例も描き直す**（`renderPreview()`が`renderList()`も呼ぶ。
  忘れると行の例が古いままで「効いていない」ように見える）。
  **チェックは`click`で受ける**——`change`は`click`の後に飛ぶため、行の
  クリックで作り直す作りだと反映されない（実際に「外しても一覧に残る」不具合に
  なった）。並べ替えは行のどこを掴んでもよく、**押しただけなら選ぶ・少しでも
  動かしたら並べ替え**としきい値で分ける。固定は`tests/test_lcpanel.js`。
