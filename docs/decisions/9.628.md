# §9.628 ダッシュボードを LotScope のグリッドのパネルへ移植する——前の3つの表示は組み込みのダッシュボードに（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.627](9.627.md)｜関係: [§9.64](9.64.md)・[§9.285](9.285.md)・[§9.341](9.341.md)・[§9.597](9.597.md)・[§9.609](9.609.md)

## 経緯（利用者の言葉）

> 別リポジトリのLotScopeのダッシュボードがとても優秀なので、その多機能なダッシュボードを移植してください。

## 前の形と、移植で決めたこと

前の「生産管理ダッシュボード」（`report-dashboard.js` の 600 行）は、**決まった3つの表示**（稼働状況・自設備・自由集計）だけで、
利用者がパネルを足す・組み替えることはできなかった。LotScope のダッシュボードは、グリッドにパネル（数字・グラフ 28 種・
合わせた表・稼働のガント・ABC 分析・スライサー）を自由に置き、ダッシュボードの組とセットを保存できる。

**物差し（14c）**: LotScope の語彙 25 種（図の種類・集計・見せ方・期間・枠・凡例・色の組・数字の形・合わせるデータの役割…）を
WaveLog の定義と突き合わせた。**25 種すべてがそろった**（図の種類 33/33＝`CHARTS` 28＋`EXTRA_VISUALS` 5・集計 19/19・期間 7/7 ほか）。

| 層 | 置き場 | 中身 |
| --- | --- | --- |
| 集計 | `backend/dashboard/`（pivot・answer・aggregate・formula・layout・ops・sources・store・equip_groups） | 数・分け方・合わせた表・稼働・ABC。計算列は WaveLog の`list-formula.js`と同じ答え（parity の網） |
| 元 | `sources.py` | 測定データ（`rec`＝写しの sqlite）・作業予定（`plan`＝予定の展開）・データソース（`src:<名>`）・役割（`role:<役割>`） |
| 保存 | `ダッシュボードマスタ`・`設備グループマスタ`（master.sqlite3） | 置き場は 共通デフォルト＝開発者・共通＝マスタを書ける端末・自分だけ＝本人（`store.Who.gate()`） |
| API | `routes/masters/dashboard.py` | 組み・セット・外した組み込み・設備グループ（マスタ管理の約束 §9.82 の4本）・数・列の札 |
| 画面 | `static/js/dash/`（13本）・`63-dashboard.css` | グリッド・組む所・スライサー・右クリック・画面の印刷。元の意味は`WL.dashKit.src`の1箇所、問い合わせは`WL.dashKit.fetch`の1本 |

前の3つの表示は**組み込みのダッシュボード**（稼働状況〈既定・§9.64〉・自設備・作業時間の分析）＋ LotScope の「標準」（仕掛と完了）の4つ。
自設備の設備は「この端末の使用設備」（`@mine`）で、画面が問い合わせる直前に`WL.equipment`の設備へ置き換える（§9.285）。
前の画面にあって移植で落ちかけた物（自設備の「全設備との差」・時間の書き方`WL.duration`）は合わせるデータの役割「基準」と
`unit:min`で戻した。設備グループはマスタ管理の「設備」の群（汎用の表・名前の決まりは1行に1つの字）。

### 決めたこと（規則の表に載せた物）

1. **添え書きは項目に分けて持つ**（元・設備・期間・条件・日付の数え方。`dashboard.js`の`metaParts()`の1箇所）。
   多くのパネル（半分以上・2枚以上）で同じ物は**道具の行の「このダッシュボードの前提」に1回**、パネルには違う物だけ。共通にある期間・条件を
   パネルが持たなければ「期間 すべて」「条件 なし」と**言い切る**（書いていない＝共通と同じ、を常に正しくする）。
   合わせた表の条件はまとまりの見出しの中。
2. **色相は設備だけ**（`EQUIP_COLORS`・同じ設備はどのパネルでも同じ色＝設備の木の順・`equipColor()`の1箇所）。
   量の棒・1つの値は紺、ガントの作業の棒は灰青（隣の量の棒と同じ紺にしない）、設備でない系列・内訳（人数・用途名のドーナツ）は
   灰青の濃淡（`SERIES_SHADES`）。データの種類の色（前は作業実績＝青緑）と、項目ごとの色相の組（`CAT`）はやめた。
   前は系列の何番目かで色を決め、時系列は1つずれて始まるので**同じ設備が橙と青緑に分かれた**（網で直す前に落ちることを確かめた）。
3. **同じ数を2か所に出さない**: 合わせた表の見出しの「計」は、上の数字のパネルが言うなら出さない（`noTotal`）。
   数字のパネルの題に単位の括弧を書かない（単位は数の横）。自設備のオペレータごとの実績は棒つきの合わせた表（計なし・この端末の設備だけ）。
4. **数える物は空でも 0**（サーバーの総計・合わせた表のセル）。前は1行も当たらないと総計のマスが無く「–」（分からない）と出た。
5. 時の軸は**期間の始まり〜終わり**（数の無い日・月も並ぶ）。字は終わりの日から間引く。年をまたぐ期間は年も書く。年月は「2026/10」。
6. 1つの値だけの棒は1色（前は 8 項目までだと項目ごとの色＝項目の数で色の意味が変わった）。0〜4 の整数の軸は整数の目盛りだけ。
7. ガントの「この期間の作業はありません」は「いま」の線を避ける。凡例は出ている物だけ（勤務の外・直の境目・作業日の境目）。
8. スライサーは、絞っていないとき「パネルの設定」（期間と設備で同じ言葉。7 回目に「組んだまま」は推測させると言われた）。
   月は暦の名前（10月・9月・◀ 8月）で、相対の「今月・先月」と混ぜない。
9. **合わせた表の行は数えた設備ぜんぶ**（答えの`parts`＝スライサー・表の設備で絞った後。数の無い設備も 0 の行・単位つきの「0分」）。
   並びは決めた列 → 同じなら隣の列 → 名前で、並べている列の見出しに ▼／▲。どのまとまりも同じ条件なら見出しに書かない。
10. 数の書き方: 所要時間は 3 桁区切り（`WL.duration`の1箇所・ダッシュボードの外も）。数の席の幅はその列でいちばん大きい数の字を測る
    （決め打ちの 3.6em に「4,800分」が入らずはみ出した）。時間は小数 2 桁まで（0.75 を 0.8 と書くと隣の 3.1% と合わない）。
11. ガント: 棒の無いわけの字は縦の線（作業日・直の境目・いま）の間の入る区間に置き、入らなければ「作業なし」。稼働／勤務の時間は
    稼働率の下の 2 行目（どの幅でも）。現場歴で暦の 0 時が作業日の途中にあれば「10/24 0:00」の札。
12. 棒の中の数の字は、白と濃い字のうち地との明るさの比が大きいほう（`inCls()`）。0 でない値の縦棒は 3px から。
