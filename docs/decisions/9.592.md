# §9.592 運用モード（通常／厳密）を作業スケジュールの「運用」の札から切り替える・厳密モードで押せない「開始」を鍵つきの灰で残す（7案→組合せ7案から B3・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.591](9.591.md)｜関係: [§9.588](9.588.md)・[§9.518](9.518.md)・[§9.570](9.570.md)・[§9.338](9.338.md)

## 経緯（利用者の言葉）

> 通常・厳密モードの切り替えはスケジュールから設備作業者権限でもできるようにしてください。
> また、開始ボタンが見えなくなると入替対象、つまり入れ替えて先頭にすべきロットがわからなくなるのでグレーアウトのような
> 見えるけど使えない状態を適切に表現するような形をとってほしいです。

切り替えられる端末の範囲は利用者に選んでもらった: **並べ替えできる端末**（スケジュールモードの端末と、編集可能モードで
「現場段取り（並べ替え）」がその設備に付いている端末・設備作業者を含む）。厳密モードは並びの決まりなので、並びを決める権限に揃える。

## 4. 決めたこと

1. **開始の状態は`startStateOf()`の1箇所**（`schedule-view.js`）——`'go'`＝押せる／`'locked'`＝厳密モードでいまは押せない／
   `''`＝出さない（可でない・作業でない・開始できない端末）。表を描く・可否を差し替える（`applyWorkableFlags`）・右クリックの
   メニュー（`canStart`＝`'go'`）が同じ答えを読む。HTML は`startBtnHtml(e,state)`の1箇所、押したときの配線は`bindStartBtn()`。
2. 押せない開始は`aria-disabled="true"`（`disabled`にしない——乗せると理由が読め、押すと「まだ開始できません」と理由を言う）。
   理由は`lockedStartReason()`: 一番上でない行は「一番上のロット（L0001）だけ・この行を一番上へ並べ替えて」、一番上の行でも
   始められないときはサーバーの`strictTop.reason`。
3. ヘッダーの「運用」の札（`#runModeBadge`）は**作業スケジュールの1設備の段でいつも出す**（通常でも厳密でも・全体の俯瞰では伏せる）。
   押すと`WL.popMenu`の面（`#runModeMenu`）: 先頭に「いま開始できる」（厳密のとき）、通常／厳密（語彙はサーバーの`runModes`・
   `menuitemradio`）、足元に「◯◯の全端末に効きます」と切り替えられる端末。できない端末では選べない形にして理由を書く。
   厳密の札は青緑の面（モードの1つで「設定要」の橙ではない・§9.338）。
4. 口は`POST /api/schedule/run-mode`（`routes/schedule_start.py`・厳密モードの段）。書くのは`master_repo.write_equipment_run_mode()`
   （設備マスタの窓と同じ列・同じ正規化・知らない設備と語彙に無い字は400）。段は編集モードだけの段なので、
   `access_mode._ENDPOINT_EXTRA_MODES`でスケジュールモードへも開け、ハンドラが`line_ops_allowed()`で二重に絞る。
5. **切り替えてよい端末は`line_ops_allowed()`の1箇所**（`routes/schedule.py`・前の名前は`_times_allowed()`）——スケジュール
   モード／編集モードで「スケジュール可否」が可／その設備の「現場段取り」を持つ。§9.518 の実際の時刻と同じ答えで、予定の応答が
   `canEnterTimes`・`canSetRunMode`の2つの鍵で運ぶ（権限の答えは1つ・鍵は用途ごと）。

## 5. 踏んだ罠

- **土台の`button[aria-disabled="true"]`は半透明（`--op-disabled`＝.5）**。灰の面に重なると、字と地が実効 2.17:1・面と行が 1.1:1 まで
  落ち、「入れ替える相手を探す目印」にならなかった（撮った絵で薄すぎた）。この部品だけ半透明を外し（`opacity:1`）、押せないことは
  灰の面・鍵・カーソル・`aria-disabled`・理由で言う（字は`--ink-2`＝6.51:1）。§9.570 の「薄さは1つ」は、薄くして**よい**物の決まりで、
  読ませる目印には当てない。
- Playwright は`aria-disabled="true"`のボタンを「押せない」と見て`page.click`を30秒待つ。押せない開始を押す網は、覆われていないことを
  `elementFromPoint`で確かめてから`page.mouse.click`で押す。
- 網の途中で落ちた手元の試し（素の`node`で回した）が設備マスタの運用モードを厳密のまま残し、次の通しの最初の確かめが落ちた
  （材料はランナーの外では揃わない）。網は`run_all.sh`から回す。
- `test_sctimes`／`test_sctimesedit`は「テスト設備A に有効な停止内容が1つ以上ある」ことを自分で作らずに当てにしていた。その停止内容は
  私の撮影の台本（§9.590 の作業中）が作り、同じ台本の後片付けが論理削除していた——置き土産が無くなった日から「材料を足せた」で
  落ち続けた（変更前の main でも同じ値で落ちる）。両方とも**停止内容を自分で作って自分で消す**ように直した（testing.md「物が無いなら前提を作る」）。
