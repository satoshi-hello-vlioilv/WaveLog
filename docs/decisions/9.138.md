# §9.138 入力内容の「板厚/板幅」を板厚と板幅へ分ける

§9.137の骨子の実装2/5。**枠の数がまるで違うものを1つの項目にまとめない。**

| | 板厚 | 板幅 |
|---|---|---|
| 数え方 | **丈ごとに3点**（エッジOS・中央CL・エッジDS） | **条ごと**（最大40条） |
| 保存先 | `measurements.thickness[丈位置][0..2]` | `measurements.width[丈位置][0..条数-1]` |
| 進む先 | `settings.tStep`（3点の巡回） | `settings.wStep`（条入力順） |
| 測定器 | マイクロメータ | ノギス／コンベックス |

分ける理由は**進捗が読めなかったこと**。1項目のままだと「3＋条数」の合算に
なり、`0/43`と出ても板厚が終わっているのか板幅が終わっているのか分からない。
枠の数が違うので画面の作りも二重で、`renderMeasureGridVertical()`は
「板厚/板幅のときだけ」専用の2枚組ワークスペースを持ち、同じ
`stripColumnsHtml`/`lengthCompareHtml`をもう一度並べていた。

#### 判定は1箇所（`WL.measureItem`、`measure-view.js`）

`type==='板厚/板幅'`という**文字列比較が6ファイル・十数箇所**に散っていた
（公差の出どころ・幅分割公差・自動転送の固定・帳票の節・入力欄の数）。
2つへ分けるだけで**片方だけ直った状態**が簡単にできてしまい、そこだけ黙って
別の項目の公差で判定する——§9.125で`toleranceDetail`の第3引数を3ファイルへ
通し忘れて偽の公差外を出したのと同じ壊れ方なので、判定を関数へ集約した。

- `KEYS` … 項目名→保存先キー。`activeMeasureKey()`はこれを引くだけ。
- `isDimensional(type)` … 製造/オーダー公差を選べる寸法系か。
- `kindOf(type)` … 公差をthickness/widthどちらで引くか。
- `slotCount/slotLabels/slotHead` … **枠の数と呼び名**。ここが答えるので、
  測定表・丈位置くらべ・読み上げ名に項目ごとの分岐を書かない。

**新しく`type==='板厚'`のような比較を散らさないこと。**

#### 落とすと黙って壊れるもの

- **保存済みレコードの旧名。** `settings.measureType`は`'板厚/板幅'`のまま
  保存されている。選択肢から消えた値を`select.value`へ入れると**空文字**に
  なり、どの項目でもない状態で開く。`ensureMeasureShape()`が読み込む時点で
  `板幅`へ寄せる（coilStopと同じ方針）。**帳票は`ensureMeasureShape`を
  通さない生のレコードも読む**ので、`report-dashboard.js`と
  `measure-tolerance.js`の`DIMENSIONAL`は**旧名も受ける**。
- **横長の公差バー（`#toleranceSummary`）。** 板厚/板幅では隠していた
  （数直線の隣の公差カードが基準値・公差±・判定範囲を既に持つ＝§9.129の
  「同じ数字を画面に2つ出さない」）。分けた後の**両方**へ引き継ぐこと。
  引き継ぎ忘れると②の枠が7→9に増え、`test_msteps`の枠数の網が落ちる。
- **測定器の振り分け。** 以前は1項目の中で機種を見て板厚／板幅へ自動で
  振り分けていた。分けた後は**項目が決める**——板幅のままマイクロメータを
  送っても入らず、案内を出す（バリ・テレスコープと同じ形）。項目の行き来は
  `← →`1つなので、現場の手数は1つ増えるだけ。
- **`advanceSlot()`/`retreatSlot()`。** 「次の枠へ」を`advanceWidth()`のまま
  にすると、板厚で`↓`やEnterを押したときに条入力順で動いてしまう
  （枠は3つしかないので当たらない位置へ行く）。

固定は`tests/test_mcore.js`（板厚の3点・受け取れない測定器・板幅を汚さない）
と`tests/test_msteps.js`（9項目・枠数）。**検証用フィクスチャは公差を持たない**
ので、公差がらみを確かめるときは§9.125と同じく材料ごと注ぎ込むこと。
