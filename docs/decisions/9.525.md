# §9.525 刃組ガイダンスを見た目のままA4横1枚へ印刷する（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「刃組ガイダンスの表示画面を左のメニューを除いた見た目そのままを印刷できる機能を実装してください。A4横のレイアウトが良いです。」

## 測った（評価関数）

同じ材料（50mm×22条・元板巾1130）で刃組ガイダンスを開き、刷った紙をPDFで確かめた（画面は1728×1152＝利用者の常用環境）。

| | 前（ヘッダーの「画面を印刷」＝ブラウザの印刷そのまま） | 後 |
| --- | --- | --- |
| 用紙 | A4**縦** | A4**横**（`@page{size:297mm 210mm;margin:8mm}`） |
| 左メニュー | 刷れる | 刷らない |
| 並び | **組み直る**——紙の幅（約1062px）が「窓の幅」になり、狭い窓の決まりで右の「刃組の内訳」が図の下へ回る | 画面と同じ（器を画面の幅のまま組み、比を保って縮める・倍率0.636） |
| 断面図（WebGL） | **白い**（描いた絵を持ち続けない作り） | 刷る直前に描き直して絵にする |
| 枚数 | 1 | 1 |
| 刷り終わったあと | — | 印・倍率・絵・用紙の指定が残らない |

## 決めたこと

- **入口は増やさない**（§9.300 ①「印刷は画面ごとに1つ」）。ヘッダーの「画面を印刷」の中身を
  **画面が名乗れる**ようにした（`registerView({print, printHint})`→`WL.printCurrentView()`）。
  名乗らない画面は今までどおりブラウザの印刷——ほかの画面の動きは変えない。ボタンの説明
  （`title`）も画面が名乗り、刃組ガイダンスでは「左のメニューを除いた…A4横1枚に縮めて」と言う。
- **紙を組み立て直さない**。いま見えている器（`.layout > main`）をそのまま刷る
  （`WL.printCore.printScreen()`）。器は画面で測った幅・高さに止め（`--print-w/--print-h`）、
  刷れる範囲÷器の大きさで縮める（`--print-zoom`・大きくはしない）。余った向きの余白は左右に分ける。
- **幅の条件（`max-width`）は画面にだけ効かせる**（`@media screen and …`）。刷るときは紙の幅が
  窓の幅になるので、狭い窓の決まり（刃組の`1200px`・ヘッダーの`1180px`）が紙の上でだけ効いて
  並びが変わっていた。
- **WebGLの図は刷る直前に絵へ差し替える**（`beforeSnap`で描き直させ、その場で`toDataURL`）。
  後片付けで元へ戻す。
- 刷る段取り（印・題・後片付け・2回待って開く）は`runPrint()`の1箇所。紙を組み立てる印刷
  （`printOnPage`）も同じ段取りを通す。
- 題（PDFに保存したときのファイル名）は「刃組ガイダンス_設備_日時」。
- 網: `test_screenprint.js`。**並びは紙の幅で測る**——画面の幅のまま測ると、紙の上でだけ効く
  幅の条件を見逃す（直す前の`max-width`を戻しても網が通ってしまい、測り方を直した）。
