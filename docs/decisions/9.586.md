# §9.586 寸法・外観の判定をエッジ形状の右隣へ——見出しの上段で「判定に効かない列」と「揃いで判定する列」を分ける（7案→組合せ7案から H4・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.585](9.585.md)｜関係: [§9.204](9.204.md)・[§9.393](9.393.md)・[§9.396](9.396.md)・[§9.397](9.397.md)

## 経緯（利用者の言葉）

> メイン測定画面の寸法外観の判定をエッジ形状の横に移動させて、何に対しての判定なのかわかりやすくしてください。

測定画面 ②測定 →「寸法・外観」の丈の表。列は「丈｜長さ｜肉厚｜**判定**｜外観｜巻ズレ OS｜巻ズレ DS｜エッジ形状｜備考」で、
判定（揃いの合否・§9.204）が**長さ・肉厚の隣**にあった。判定の根拠はエッジ形状と値(mm)だけなので、長さ・肉厚の判定に読める。

## 1. 物差しと、直す前の値

1丈目の判定とエッジ形状を測った（1728×1152・切断面3級・3丈）。

| 測るもの | 直す前 | 直した後 |
| --- | --- | --- |
| 判定とエッジ形状の列の間 | 4 | 1（右隣） |
| 判定とエッジ形状の距離 | 274px | 17px |
| 判定と根拠のあいだに挟まる関係ない欄 | 3（外観・巻ズレ OS/DS） | 0 |
| 判定の真上の見出しが何の判定かを言うか | 「判定」のみ | 「揃い（切断面 3級）で判定」 |
| 根拠（入力）の後ろに結果が来るか（左→右） | いいえ | はい |
| 表のはみ出し（1728） | 無し | 無し |

## 2. 7案を撮って2回採点した

基準と重み（撮る前に決めた）: 何の判定か読める30・判定と根拠の近さと作業の順25・見渡し20・既存との一貫と作りの汎用性15・幅と崩れ10。

1位 E と2位 B が3点差（5点未満）なので2回目へ。

## 3. 作り

- 見出しは2段（`templates/index.html`）。上段＝群（判定に効かない5列／判定に効く2列）、下段＝項目。丈と備考は上下にまたがる。
- 判定に効く群は縁（`--teal`の2px）と字（`--teal-ink`）で言う。色だけにしない（字でも「揃い…で判定」と言う）。
- 級は材料ごとに変わるので、上段の字は基準の帯と同じ答え（`cutFaceGrade()`／`cutFaceLimits()`）から`judgeGroupText()`が描く。
  基準が引けないときは「揃い（基準なし・判定しません）」——判定すると書いたまま判定しない表にしない（§CLAUDE 4）。
- 行の並びは`productRowHtml()`の1箇所（エッジ形状→判定）。保存・必須の判定は`data-product-field`で引くので並びに依らない。

網: `test_msteps.js`（見出しの並び・判定がエッジ形状の右隣・上段が判定の群の真上で「揃い…判定」と言う・判定に効かない群がある）。

## 4. 見つけたが直していないこと

フル HD・125%（1536×864）では、**直す前から**丈の表が器より約90px広く、備考の列と「全丈 OK一括入力」が切れている
（列の幅の合計 56.4em が器の約 640px を超える）。今回の並び替えでは幅は変わらない。別の依頼として扱う。
