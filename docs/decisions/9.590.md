# §9.590 設備停止マスタを「分類 → 停止内容の木＋段（基本・内訳・挿入の条件）」に作り直し、挿入の条件は「組み立てる｜式を書く」で入れる（7案→組合せ7案から H1・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.589](9.589.md)｜関係: [§9.588](9.588.md)・[§9.397](9.397.md)・[§9.389](9.389.md)・[§9.474](9.474.md)・[§9.489](9.489.md)

## 経緯（利用者の言葉）

> 設備停止マスタを作り変えて適切に階層化してください。設備停止挿入条件が作りにくく使いにくいです。一覧表にある表示列の
> 「この列の作り方」のような条件入力ができるとやりやすい。別リポジトリのLotScopeの表示列のUIの配置などを参考に
> もっときれいに使いやすく作り替えてください。

入れ方は利用者に選んでもらった（「組み立てる＋式を書く」＝LotScope の「この列の作り方」と同じ2つの札）。

## 4. 作り

- **画面**: 左＝分類 → 停止内容の木（分類の行は畳む・開く、右の「＋」でその分類に停止内容を足す・「×」で分類を消す）。
  右＝選んだ停止内容の段（基本・内訳・挿入の条件）。段の札はいまの値（「30分」「2件」「条件 2・自動1」）を言う。
  基本は読むだけの値で、直すのは汎用の編集窓1枚（§9.397 のまま）。
- **挿入の条件**（`master/master-stoprule.js`）: 決まりの札は「もし 製造材質 が変わる なら → 1本・45分・自動で入れる」と文で読む。
  押した札がその場で開き、**組み立てる｜式を書く**と答えの欄（本数・1本ずつの分・入れ方・覚え書き）。右に**いまの予定の境目で試した
  結果**（当たる札・本数・足りない／入っている）。保存の前に、使えない式は札を開いて理由を言い、止める。
- **組み立ての部品**（`core/formula-builder.js`・`WL.formulaBuilder`）: 節（列・見方・値・比べ方）を「かつ／または」でつなぐ文。式の字へ
  変えるだけで、式の決まりは増やさない（計算と確かめは`WL.formula`の1本）。**見方の語彙は呼ぶ側**（設備停止は`WL.stopRules.HOWS`:
  が変わる／が同じ／の差（後ろ−前）が／（前のロット）が／（後ろのロット）が）。
- **式**: 一覧の式と同じ書き方。名前は `[前.列]`（前のロット）・`[後.列]`（後ろのロット）。それ以外の名前は「使えない」と字で言う。
- **判定**: どの行に当たるかは`WL.stopRules.ruleHit()`の1箇所（予定の黄色の帯と、マスタの「試した結果」が同じ答え）。
  式のある行は式で、前の版のセルの条件の行は`firstRule()`で。
- **前の版の表**: 開くと`fromCells()`が同じ意味の式へ直す（組み立てられる形なら組み立ても）。セルの中の「または」・否定・正規表現は
  式だけ（「式を書く」で開く）。意味が同じことは網が同じ境目で確かめる（`test_stoprules.js` 1b）。
- **サーバー**: `設備停止挿入条件マスタ`に`[式]`と`[組立JSON]`を足した（無ければ足す・読み取り専用の接続では空として読む）。
  式のある行はセルの条件を持たない。長さは一覧の式と同じ 2000字まで。

## 5. 撤回・外したこと

- §9.588 の「3つのペインの下に全幅の判定表」（M3）を撤回。表は2次元（列×行）で、1つの決まりを作るのに列を先に足す必要があった。
- 判定表の部品（`bladeset/rule-table.js`）に §9.588 で足した口（`sourceSets`・`answerCols`・`savedWord`）は使う人がいなくなったので外した。
- 分類の「すべて」で絞る札はやめた（木で全部が見える。絞るのは検索欄）。

## 6. 作業の途中で見つけた脆さ（`test_stopcat.js`が時々落ちる）

`test_stopcat.js`の「パス欄に『参照…』ボタンが付く」ほか3件が、この版で8回中2回、変更前の main でも3回中1回落ちた
（パス欄 0件・一覧は「読み込んでいます…」）。「フレーク」で片付けずに測ると、仕組みはこうだった:

1. 「マスタ管理」を押すと、開いていたタブ（設備停止）の読み込みが走る。
2. その途中で共通設定のタブへ移る（網も人も同じ）。共通設定は取って描き終える。
3. 後から着いた設備停止の読み込みが**負けた側**として今のタブを描き直す（§9.331）——このとき`force`付きで描き直すので、
   描き終えた共通設定が**もう1度「読み込んでいます…」に戻って取り直す**。網はその隙に数えていた。

直したこと: 負けた側の描き直しは**取り直さない**（`loadMaintInner(false)`）。今のタブは勝った側がもう取ってあるので、控えから
描けば足りる（共通設定は同じ回のうちに描き直され、「読み込んでいます…」の隙が無くなる）。直したあと 18回続けて通った。
