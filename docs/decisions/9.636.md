## 決めたこと

- **`formula.rs`**（`backend/dashboard/formula.py` の写し）: 字句・構文（式の木）・関数 51 個・`check`・`sql_value`・`clean_calc`・
  計算列（`CalcColumns`）。答えの正は Python（Python は画面の JavaScript と `test_formulaparity` で突き合わせてある）。
- **字は UTF-16 の単位（`Vec<u16>`）で持つ**。長さ・位置・切り出し・大小・`lenb` を JavaScript と同じ単位で数える。Python は
  `surrogatepass` で、絵文字を半分で切った字（割れたサロゲート）も持つ。試験表ではそういう答えを `{"$u16": [単位…]}` で書く
  （UTF-8 に書けないため）。正規表現・大文字小文字・NFKC へ渡すときだけ字へ戻す（割れた所は U+FFFD）。
- **15 桁の丸め（`tidy`）**は Python の `Decimal(n).quantize(…, ROUND_HALF_UP)` と同じ: 31 桁で丸めた形から決め、ちょうど半分に
  見えるときだけ正確な 10 進の桁（`{:.1100e}`）で決める。
- **正規表現は JavaScript の書き方を `fancy-regex` の書き方へ読み替える（`translate`）**。意味は Python の読み替え（`re.ASCII`）と同じ:
  `\d`・`\w`・`\b` は ASCII（`\b` は前後を見る形で書く）、`\s` は JavaScript の空白 25 字、`.` は改行 4 字以外、`$` は字の終わり（`\z`）、
  `[^]` は何でも、`[]` は当たらない、`\k<名>` はそのまま、`\xHH`・`\uHHHH` は `\x{…}`。
  - `fancy-regex` は `\<` `\>` を語の境目と読む。JavaScript と Python は `<` `>` の字そのものなので、字として書く。
  - 類（`[…]`）の中の `[` `&` `~` `--` は Rust では特別（入れ子・交わり・差）なので字として逃がす。
- **空の照合の続け方は Python の `re.sub`・`finditer` と同じにした（`matches`）**。`fancy-regex` の `find_iter` は `x*` を `abxd` に当てると
  `x` の直後の空を拾わない（`[0..0, 1..1, 2..3, 4..4]`）が、Python と JavaScript は拾う（`-a-b--d-`）。空の照合の直後だけ同じ位置で
  空にならないよう1字進める。
- `register`（計算列を SQLite の関数として接続に登録する）は、接続を Rust が持つ P3 で写す。

## Python と違うまま残した所

- **基準日を省いた `kamadate`**: Python は端末の地方時の今日、Rust は UTC の今日（地方時を読む部品がまだ無い）。日本の端末では
  0 時〜9 時に1日ずれうる。試験表は基準日つきだけ。ルートを移すときに地方時を読む部品を足す。
- **割れたサロゲートを含む字を、さらに正規表現・大文字小文字・NFKC へ渡したとき**: Python は割れたまま扱い、Rust は U+FFFD に置き換える。
- **入れ子の深い式**: Python は再帰の上限（`RecursionError`）で例外、Rust はスタックの限りまで計算する（式は 2,000 字まで）。
