## 経緯（利用者の言葉）

> メインにマージして、ステップ2へ進んでください。

ステップ1（[§9.598](9.598.md)）で決めた型（頭の行・一覧＋右の詳細・部品）の上に、**汎用の表で描くマスタ**（ロール・帳票ブロック・
内部データの表・移行済み・テーブル生データ）を載せる。主役は一覧（表）。依頼の元は §9.598 と同じ
（「もったりした印象」「統一感や一貫性」「ビジュアル化も採点要素に」）。

## 1. 物差しと前の値（1728×1152・汎用の表の27画面）

撮る道具の中で、表の1画面ごとに**読めなくなっている所**と**同じ役目が画面ごとに違う所**を数えた
（細い列は 1536×864 も。数え方は画面の上で直に測る——切れたセル＝`scrollWidth`が器より広い、数の列＝8割以上のセルが数）。

| 物差し | 前（main febe21f・27画面） | 後（18画面） |
| --- | --- | --- |
| 切れたセル | 245 | 0 |
| 切れた見出し | 10 | 0 |
| 48px未満の列（1728／1536） | 12／15 | 0／0 |
| JSON の生の字 | 2 | 0 |
| 左寄せの数の列 | 22/22 | 1/10（帳票ブロックの幅＝帯にそろえた列・2-4） |
| 色見本の無い色コード | 50 | 0 |
| 件数の置き場（題の横／タブ） | 24／2 | 0／18 |
| 左の一覧に同じ呼び名 | 7組 | 0 |
| 中身の無い定型の用途の1行 | 11 | 0 |
| 字だけの空の表示 | 17 | 0 |
| テーブル生データの古い帯／表の要素 | 1／1 | 0／1 |

- 画面が27→18なのは、刃組の盤と設備停止が持つ9表を内部データから外したため（左の一覧の同名が0になった・2-1）。数の列が
  22→10なのは、外した4表（ゴムリング・スペーサー・フィンガー・刃）の11列と、字になった列（帳票ブロックの高さ＝「中身なり」・
  台車の有効＝「有効」）の2列が抜け、稼働カレンダーで1列増えたため（画面ごとに数えた。稼働カレンダーが前に0列と数えられた理由は確かめていない）。
- テーブル生データの「表の要素」は`<table>`のまま（行40px・縞なし・同じ札の行へ寸法をそろえた）。物差しは要素を数えるので1のまま。
- 入れたあとに測り直して、設備の最大条数・標準時間（「40（既定）」「未設定」まじり）が数の列と見なされず左寄せのまま残っていたのを
  見つけた。数かどうかは既定の印を外して見、「未設定」は空欄と同じに数えないようにした（`mmIsNumText`）。
- 帳票ブロックは内容の列（並べた項目の JSON）が中身の幅をそのまま比にしたため、ほかの10列を **2〜48px** まで潰していた
  （264セルのうち245が切れる）。§9.598 1d の「中身を測った比」が、長い字の列が1つあると効かなかった。
- 左の一覧の同名7組は、刃組の盤（ゴムリング・スペーサー・フィンガー・刃・刃選択・刃組基準値・保持方式）が持つ表が
  「内部データ」にも同じ呼び名で出ていたもの（`COVERED_BY`の書き漏れ）。
- 用途の1行の11画面は「ここでは行をそのまま足す・直す・消せます。」の定型（何の表か・ふだんどこで直すかを言っていない）。

## 2. 採点（§9.597 の手順・採点表は先に決めた）

## 3. 決めたこと

### 2-1 サーバーの対応表（`backend/routes/master_tables.py`）
- 刃組の盤が持つ8表（ゴムリング・スペーサー・フィンガー・刃・刃セット・刃選択・刃組基準値・保持方式）と設備停止挿入条件を
  `COVERED_BY`へ（専用の画面を指す・内部データに出さない）。左の一覧の同名は0になる。
- 条設計・刃組履歴は`EDITED_FROM`（刃組ガイダンスの「条の設計」「確定保存」が書く）。台車の`NOTES`は「ここで足す・直すと、
  刃組ガイダンスの台車の札が変わります」。
- **内部データの列の見せ方はサーバーの語彙**（`COLUMN_VIEWS`・対応表の`views`）。稼働カレンダーは「いつ」＝区分で読む列が変わる
  曜日と日付を1列に（`毎週 土曜`／`日付 2026-10-25`・曜日は DB の 日=0〜土=6）、稼働は「稼働／休み」。画面へ表の知識を写さない。
  編集の欄（`fields`）は列そのまま。

### 2-2 件数はタブ、探す欄はタブの行の右（`listBar()`）
- **どの一覧も札の行を1つ持つ**（`.mm-lbar`）: 左にタブ（1つなら「一覧 N件」・絞ったら「n / N件」）、右に探す欄・群の開閉
  （すべて開く／すべて畳む）・段の凡例。題の横の件数（「有効 N件」）はやめた。テーブル生データは「中身 N件」（先頭だけなら
  「先頭 N / 全 N件」）。
- 群の開閉は**札の行の中**（器は一覧ごと）。前は操作列に1つ置いた`#masterMaintFold`がロール→テーブル生データへ移っても残っていた
  （製品の不具合・物差しの撮影で見つけた）。
- 探す欄は**行のある一覧だけ**（0件の表には出さない）。

### 2-3 探す（その場で絞る）
- 打つたびに、表に出しているすべての列の字（見分けにくい相手の札の中も）で絞る（`filteredMaintItems()`・全角半角と大小は
  区別しない`mmFold`）。当たった字に印（`mark.mm-hit`）、タブは「n / N件」。打っている欄の焦点は描き直しで切れない
  （`WL.base.onTyped()`）。群の見出しの件数と要約も**絞った行で数え直す**。0件なら「「…」に当たる行はありません」と「探す欄を空にする」の1つ。
- **欄の字はいつも、いま効いている言葉そのもの**。別のマスタへ移ると言葉を外す（札の行を作り直す回＝`barKept()`が偽の回に、
  **絞る前に**外す）。テーブル生データで表を替えた回も同じ。

### 2-4 列の幅（`fitMaintColumns()`）
- 中身なり（見出し〜**320px**）。**器に入るなら px で置き、行の罫線も表の幅で止める**（`is-fitw`・余りは「まとまりの外」・§9.209）。
- 入らなければ比で分け、短い中身の列は潰さない（最小＝見出しの幅か中身の120pxまで）。それでも入らないときだけ`optional`の列を
  右から畳み、札の行の右に「ほか N列（…）は行を開いた詳細」と書く（基準12: 余白があるうちは隠さない）。
- 数の列は右寄せ（`is-num`・桁がそろう）。図が主役の列（帳票ブロックの幅＝12マスの帯）は`align:'figure'`で帯にそろえて左
  （見出しが帯の上に来る・入れたあとの採点の気づき）。単位は**見出しの名前の外**（`.mm-th-unit`・名前は「径MAX」のまま。網と並べ替えが名前で引く）。

### 2-5 全行で同じ列は1行へ（`mmListPlan()`／`mmSameLine()`）
- **5行以上**で全行が同じ値の列は、表から外して「全行で同じ」の1行に並べる（列を2つは残す）。**畳むのは`fold`を名乗る列だけ**
  ——設備の「使える機能」のように**行どうしを比べるための列**は、たまたま全行同じでも畳まない（最初は全部の列を畳み、
  `test_eqfeature`・`test_measitems`の設備の列を隠した。私の設計の誤り）。
- 「既定」の列は持たない。既定の行は名前の後ろの薄い札「既定」（`tag`）、**全部が既定なら**札を出さず「種類 すべて既定（アプリが持つ塊）」の1行。

### 2-6 値は印で（`MM_VALUE_TEXT`／`MM_VALUE_HTML`）
- 字（`cellText`）は title・並べ替え・探すが使い、セルの中身だけを印にする（§9.598 1d と同じ作り）。足した書式:
  `itemList`（内容＝「N項目」＋札3つ＋「+N」）・`paperSpan`（幅＝12マスの帯＋「n/12」）・`rowsAuto`（高さの空と0＝「中身なり」）・
  `zeroBlank`（ロールの径MIN の 0＝「—」）・`enabledFlag`（有効を「有効／無効」の字）・`words`／`weekWhen`（サーバーの語彙）・
  `#rrggbb`は色見本＋コード。
- 群（設備）の見出しは**選択中と違う中立の形**（地なし・左の帯なし・下の線）＋件数＋要約。要約は登録表
  （`WL.mm.registerGroupSum(種類,fn)`・定義が`groupSum`で名乗る）。ロールは「径 a〜b mm・見分けにくい組 N」（`master-roll.js`）。

### 2-7 空の表示（`mmEmptyHtml()`）
- 0件は絵＋「まだ1行もありません」＋足す道1つ（右上の「＋ 〜を追加」）。絞って0件は「「…」に当たる行はありません」＋「探す欄を空にする」。内部データ（ふだんは別の画面で直す表）は「ふだんの画面で設定すると、ここに行が増えます」も添える。

### 2-8 内部データの用途の1行
- 「何の表か（`NOTES`）＋ふだんはどこで直すか（`EDITED_FROM`）」（例: 「設備ごとの稼働日・非稼働日。ふだんは実績カレンダー画面の
  稼働日設定で直します。」）。無い表は「アプリの内部の表を行のまま足す・直す・消す画面です」。定型の「ここでは行をそのまま…」はやめた。

### 2-9 テーブル生データ
- 表を選ぶ欄と「再読込」は**頭の右**（`setHeadActs`）。一覧は同じ札の行（「中身 N件」・探す欄）・同じ表の寸法（行40px・縞なし）。
- 日時（`Tue, 13 Oct 2026 … GMT`）は「YYYY-MM-DD hh:mm」、有効は字、色コードは色見本、数は右寄せ。器より広い表は右端を
  淡くぼかし「横にあと N列 →」（押すと送る）。題の横に「読むだけ」の札（枠なし・`.mm-mode-chip.is-ro`）。

## 5. 実装で見つけたこと

- **5-1 探す欄の字と絞り込みが食い違っていた**（入れたあとの1回目の採点で見つかった）。札の行を作り直す回（別のマスタから
  戻った回）に、前の言葉で行を絞り終えてから言葉を消していたので、その1回だけ絞った行が空の欄の下に並び、当たった字の印も
  出なかった（撮影の道具は 1728 で打ったあと別の画面を経て 1536 を撮るので、この道を通った）。言葉の寿命を札の行の答え
  （`barKept()`）にし、作り直す回は絞る前に外す・欄の字と印はいま効いている言葉から作る、にした。テーブル生データで表を替えた回も
  同じ不具合だった。網は2つ（4. に書いた）。

- **全行で同じ列を自動で畳むと、比べるための列が消える**（2-5）。畳む列は定義が名乗る（`fold`）。
- 単位を見出しの`<b>`の中に入れると、見出しの名前で列を引く網（`test_roll`）と並べ替えの読み取りが「径MAXmm」を見る。名前の外へ。
- 0件の一覧が前の画面の`is-fitw`を持ち越していた（空と段の画面の道でも外す）。
- テーブル生データの縞は測定画面の全体の規則（`tbody tr:nth-child(even)`）から来ていた（打ち消しを1行）。
- 札の中の字（11px）が`test_smalltext`に当たった（読ませる字は`--fs-sm`＝12px 以上・§9.560）。
- 案の撮影の仕掛けの罠（製品ではない・記録だけ）: 体に付けた印の名前が製品の`.v-num`と当たり全部が右寄せになった／案の CSS を
  画面で限定しないと文書全体が送られた／隠した列が`0px`の格子の列になった。
