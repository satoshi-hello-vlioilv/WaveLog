# §9.355 1本目（list-view.js）を閉じた。`typeof` のガードは `no-undef` が見逃す

`docs/REVIEW_2026-09.md` §6.3 3-17「旧5本のグローバル関数を名前空間へ」の**1本目**。
土台（globals を実物から作る・§9.354）を入れたので、閉じた漏れは機械が教える。

## なぜ list-view から

REVIEW は「records-store（ほかから呼ばれる面が最小）」から始めると書いていたが、
§9.354 の網で**測ったら順が違った**:

| 閉じるファイル | 外からの呼び出し |
| --- | --- |
| `list/list-view.js` | **20** |
| `measure/measure-input.js` | 25 |
| `measure/measure-view.js` | 64 |
| `measure/records-store.js` | 74 |
| `core/base.js` | 4,681 |

**推測ではなく実測で順を決める。**

## やったこと

1. `list-view.js` を IIFE で閉じ、**外へ出す面は末尾の `WL.list`（17個）**にまとめた。
   `init`／`load`／`renderGrid`／`renderGridInner`／`renderTabs`／`renderDbNav`／`selectDb`／
   `listLayoutTarget`／`listColumnKeys`／`fmtStamp`／`applyTableData`／`estimateColumnWidth`／
   `tableCacheGet`／`tableCacheSet`／`checkParentLookupRows`／
   `checkSplitRowsForMissingChildren`／`setSplitCellText`。
2. 呼び出しを直した: 画面のJS **20箇所**（`no-undef` が行と列まで教えるので機械で置換）、
   検証 **110箇所**（21本）。グローバルに出ている関数は **459→353**。
3. `tableCacheSet(key,data,at)` に「いつ取ったことにするか」を足した。
   網が内部の `tableCache`（Map）を直に触って `at` を書き換えており、閉じた瞬間に
   触れなくなったため。**内部を晒すより、意味のある引数で受ける。**

## `typeof` のガードは `no-undef` が見逃す（この回の罠）

`no-undef` を 0 件にしても、**画面は静かに壊れていた**。列の設定パネルが開かない。
例外は1件も出ていない。原因:

```js
target:()=>typeof listLayoutTarget==='function' ? WL.list.listLayoutTarget() : '',
```

呼び出し側は直したが、**`typeof` の判定が古い名前のまま**。閉じたので
`typeof listLayoutTarget` は `'undefined'` になり、三項演算子が黙って `''` を返す。

`typeof x` は**未定義でも例外にならない**のが言語の仕様で、`no-undef` もそこは報告しない。
だから**閉じるときは `typeof <名前>` も一緒に探す**（実測15箇所・7本。うち製品10・検証5）。
§9.354 で「`typeof x==='function'` のガードは、名前を間違えても黙る」と書いた翌日に、
同じ形で自分が踏んだ。

## 残り

`measure-input`（25）→ `measure-view`（64）→ `records-store`（74）→ `base`（4,681）。
`base` は `esc`／`$`／`S`／`showToast`／`api` が大半で、**閉じるより先に「1文字の名前を
名前空間へ」を決める**必要がある（`$` と `esc` だけで 2,884 箇所）。
