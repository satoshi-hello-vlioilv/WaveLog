# §9.555 アプリの更新——共有の置き場に版を残し、「配る版」へ各PCが起動時にそろう（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.554](9.554.md)｜関係: [§9.546](9.546.md)・[§9.548](9.548.md)・[§9.552](9.552.md)・[§9.513](9.513.md)・[§9.405](9.405.md)

## 経緯

利用者の指示:
「更新の仕組みを作りたいです。ファイルの置き場は「\\nlmsrvngy03\工場内共有\検査データ\Records\アプリメンテナンス\WaveLog」に
して、バージョンごとのデータをこの場所に保存し、アップデートを行う機能を組み込みたいです。」

選んでもらったこと（4つの問い）:
1. 各PCは **手元へ写して動かす**（共有の版フォルダから直に動かさない）
2. 共有へは **ZIP を選んで置く**（工場のネットワークがインターネットへ出られなくても使える）
3. 各PCへは **配る版を指定 → 起動時に自動**（前の版へ戻すのも指定し直すだけ）
4. 今の運用: 各PCはアプリのフォルダを自分の PC へ写して使っている。共有が要るデータは
   `\\nlmsrvngy03\工場内共有\検査データ\Records\master.sqlite3`・`schedule.sqlite3`。設定はアプリのフォルダか LOCALAPPDATA。

それまでの更新は、端末ごとに「main の ZIP を落とす → 上書き → update.bat」の手作業だった。

## 決めたこと

1. **置き場**は `update_dir()`（既定は利用者の指定した共有・`config/local.json` の `update_dir` で変えられる。
   窓と Python が同じ鍵・同じ既定を読む——網が字を突き合わせる）。
   - `versions\<版>\` … 版ごとの中身（`PAYLOAD`＝`backend`・`static`・`templates`・`program`・`Start.vbs`・`README.md`）と
     `manifest.json`（全ファイルの道・大きさ・sha256・入れ替える項目）
   - `release.json` … **配る版**（決めた人・日時・前の版）
2. **データは版に入れない**。`db`・`config`（と `tests`・`docs`・`desktop` の開発の物）は ZIP に入っていても置かない。
   各PCのアプリのフォルダの `db`・`config` は入れ替えで1度も触らない。
3. **版を置く**のは Python（`app_update.publish_zip()`・共通設定の段「アプリの更新」）: ZIP の頭（`WaveLog-main/`）を外し、
   版の字（`APP_VERSION`）を読み、欠かせない物（`changelog_data.py`・`sidecar.py`・`WaveLog.exe`）を確かめ、
   途中のフォルダへ書いてから名前を変える。断る: ZIP でない・アプリの物でない・欠かせない物が無い・危ない道（`..`）・
   **同じ版の置き直し**（もうその版を写した PC と中身が食い違う）。
4. **配る版を決める**のも Python（`set_release()`）。置いてある版だけ選べる。前の版を控える。
5. **各PCをそろえるのは窓**（Rust・`desktop/src/update.rs` の `check_and_apply()`）。起動画面の段「版をそろえる」で、
   **中身（Python）を起こす前に**（動いている Python のファイルを入れ替えない）:
   - `release.json` を読む。**3秒で打ち切る**（届かない UNC は OS が数十秒待たせる。届かなければいまの版で起動）
   - 手元の版（`backend\changelog_data.py` の `APP_VERSION`）と同じなら何もしない
   - 違えば `<アプリ>\.update\<版>.stage\` へ写し、**全ファイルの大きさと sha256 を目録と照らす**（合わなければ1つも入れ替えない）
   - 目録の項目ごとに入れ替える（今の物は `.update\<前の版>.old\` へ・直前の1つだけ残す）。**途中で失敗したら全部戻す**
   - exe も変わったら、新しい exe の写しへ渡して開き直す。新しい窓は前の窓が終わるのを待つ（`--after-pid`。
     先に開くと「1つだけ起動」の仕組みが前の窓へ回して、新しい窓が閉じてしまう）
   - 開発の作業ツリー（`.git` が在る）は入れ替えない
6. **権限**: 置く・配るのは開発者・メンテナンス者（`role_can('app:release')`）。できない端末には押す物を出さず理由を書く。
   モードは編集可能モード（core の書込の既定）。

## 撤回した案

- **共有の版フォルダから直に動かす**: 利用者が「手元へ写す」を選んだ。共有が遅い・切れると開けない、更新中に掴む。
- **アプリが GitHub から取りに行く**: 工場のネットワークと非公開リポジトリの鍵の管理が要る。ZIP を選ぶ形にした。
- **起動時に常に最新へ**: 戻すときに版を消す・置き直す必要がある。配る版を指定する形にした。
- **入れ替えを Python で行う**: 動いている Python 自身のファイルを入れ替えることになる。窓（Python を起こす前）の役目にした。
- **exe が変わったかを「大きさ＋更新時刻」で見る**: 同じ大きさの exe が同じ秒に置かれると見落とした（網が落ちた）。中身（sha256）で見る。

## 測った（評価関数・前→後）

コードの事実から数える（`eval_u.py`。前は main 6a42a4e を別の作業ツリーに出して測った）。

| 物差し | 前 | 後 |
| --- | --- | --- |
| U1 更新1回で端末ごとにする手作業 | 3 × N | 0 × N |
| U2 更新1回でメンテナンス者がする手作業 | 0（各PCで3つ） | 2（版を置く・配る版を選ぶ） |
| U3 共有に版を残す（戻せる元がある） | 0 | 1 |
| U4 前の版へ戻す手作業 | 3 × N | 1（配る版を選び直す） |
| U5 写した中身を確かめる（sha256） | 0 | 1 |
| U6 更新が db・config に触らないことを網で固定 | 0 | 1 |
| U7 共有に届かなくても起動を待たせない | 0 | 1 |

## 網

- `tests/test_appupdate.py`（25項目・1段目）: 置くのは PAYLOAD だけ（db・config・tests・docs・`__pycache__` は入らない）・
  危ない道は外へ書かない・断るもの5つ・目録の sha256 が中身と合う・配る版は置いた版だけ／前の版を控える／選び直しで戻る・
  窓と同じ置き場・鍵・版の読み方・権限は開発者とメンテナンス者だけ。
- Rust（`cargo test`）: 版と置き場の読み方・配る版へそろえてデータを触らない／前の版は控えに残る／選び直しで戻る・
  壊れた版（sha256 が合わない）は1つも入れ替えない・届かない／決めていない／開発の作業ツリーは飛ばす・待ちは打ち切る・
  入れ替えの途中で失敗したら全部戻す。

## 踏んだ罠

- 評価関数が `fn apply` という名前を探していたので、`check_and_apply()` を作っても「端末の手作業 3 × N」のまま出た
  （物差しの誤り）。窓が起動時に `update::check_and_apply(` を呼んでいるか、の配線の実物で測るよう直した。

## 分からないこと・実機で確かめること

- **この仕組みが入る前の版の PC は、自分ではそろわない**（そろえる窓の役目が古い exe に無い）。今回だけ今までどおり ZIP で
  上書きしてもらう必要がある。その後は自動。
- 実際の共有（`\\nlmsrvngy03`）での写す速さ・書込の権限・ウイルス対策ソフトの影響は確かめていない（網は一時フォルダ）。
- 開いたまま何日も使っている PC は、閉じて開き直すまでそろわない（起動時にだけ見る）。接続状況の版の列で見分けられる。
- 古い版へ戻したとき、新しい版が足した DB の列は残る（列の追加は「無ければ足す」だけなので古い版でも読める見込みだが、
  版ごとには確かめていない）。
