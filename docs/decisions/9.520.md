# §9.520 取込でロット番号が入らない——最初の画面の欄は `#input_searchLtno`（利用者から届いた不具合報告）

索引: [決定記録](README.md)｜前: [§9.519](9.519.md)｜その後: [§9.521](9.521.md) で拡張ごと LotData-Link へ移した

## 経緯

利用者の報告「拡張あり: LotDsp を別タブで開いて自動で取り込みます、という機能で、取り込みができるはずが、
この画面で止まってしまい、ロットナンバーを打ち込んでくれません」「このロット検索を手動ですると、結果が出た
瞬間に残りの動作はしっかり行われるので、繋ぎこみがうまくいっていません」。画面写し（`#/lotdsp`・
「ロット問合せ ★検索条件を入力して下さい」）と開発者ツールの要素が添えてあった。

- 最初の画面のロット番号の欄: `<input id="input_searchLtno" name="searchLtno" ng-model="input.searchLtno">`
  （`table#form1:gridPanel_Menu2` の `td.menu-body-input`）
- 「検索」: `<button class="btn btn-default btnCustom lotdspBtnCustom" ng-click="action.search()">`
  （`table#form1:gridPanel_Menu3` の `<td ng-if="showLtno">` の中）

§9.519 の見本は、利用者が保存した**検索のあとの画面**（上の検索欄 `#common_searchLtno`）から作っていた。
拡張が開くのは `#/lotdsp`＝**最初の画面**で、そこには `#common_searchLtno` が見えていない。`tpa-lotdsp.js` は
「`#common_searchLtno` が見えるまで待つ」の1段目で待ち続け、欄にも入れず「検索」も押さなかった。
手で検索すると上の検索欄が現れ、そこから先（タブ・行数の落ち着き・渡す）は §9.519 のとおり動いた——報告の
「手動ですると残りは行われる」と合う。

## 決めたこと

- ロット番号の欄は **`#input_searchLtno`（最初の画面）と `#common_searchLtno`（検索のあと）の見えている方**。
  検査番号の欄は同じ組（`…Ltno` → `…Knno`）。
- 「検索」は**その欄から外へ囲みをたどって最初に見つかる、見えている `action.search()`**。
  2つの画面の「検索」を取り違えない（欄とボタンが別の表にあっても、共通の囲みで結ばれる）。
- 最初の画面の「検索」は `ng-if` の中で**欄より遅れて現れる**ので、見えるまで待つ（最大15秒・全体の残り時間の内）。
  値を入れるのはボタンが見えてから（入れたあとに画面が描き直されて値が消えるのを避ける）。
- 拡張の版を 1.1.1 に上げる。
- 転写計算アプリ側は同じ回で「検索」ボタン1つに統合し、拡張の段階が 25 秒進まなければ「LotDsp のタブで
  貼り付けて検索を押せば続きは自動」と案内する（ロット番号はクリップボードへ写す）——拡張が画面の変化に
  追いつけなかったときの逃げ道。

## 撤回した案

- **`#common_searchLtno` を `#input_searchLtno` に置き換えるだけ**——検索のあとの画面（上の検索欄）から始まる
  タブ（例: 既に検索済みの画面が開いている）で動かなくなる。見えている方を選ぶ形にした。
- **最初に見つかった `action.search()` を押す**——最初の画面では上の検索欄の「検索」が隠れたまま先に並ぶことがあり、
  隠れたボタンの `click()` は AngularJS の側で何も起きないことがある。欄に近い見えているボタンにした。

## 測った（見本ページ・`tests/fixtures/lotdsp_progress.html`）

見本に実物どおりの最初の画面（`#input_searchLtno`・600ms 遅れて現れる「検索」・上の検索欄は隠れている）を足し、
既定をこの画面から始まる形にした（`?header=1` で検索のあとの画面から始まる）。

| 物差し | 直す前 | 直した後 |
| --- | --- | --- |
| 最初の画面で押した「検索」の回数 | 0（1段目で待ち続ける） | 1 |
| 相手の model に届いたロット番号 | 空 | L7150C0 |
| 渡した BOX の行数（25・3） | 渡さない | 25・3 |
| 検索のあとの画面から始めたとき | 動く | 動く（上の検索欄の「検索」を1回） |
| `test_tpaext.js` | 16/21 | 21/21 |

欠陥注入で確かめた: 「検索」が見えるまで待たずに探す形へ戻すと、最初の画面の4件と該当なしの1件が落ちる
（「『検索』ボタンが見つかりません」）。

## 分からないこと（利用者の確認が要る）

  違っても空にしないだけで、検索には影響しない）。
- 本物で、最初の画面から検索したあとに出る画面・タブが見本と同じか（§9.519 から持ち越し）。
