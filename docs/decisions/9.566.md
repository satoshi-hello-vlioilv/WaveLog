# §9.566 画面の JS に型の検査——公開の型は名乗っている式から起こす

索引: [決定記録](README.md)｜前: [§9.565](9.565.md)｜関係: [§9.563](9.563.md)・[§9.326](9.326.md)・[§9.354](9.354.md)・[§9.359](9.359.md)

## 経緯

§9.563（言語の住み分け）の「次の段」2。利用者の判断「２．画面の JS に型の検査：実施」。
実際に起きた不具合 209件のうち、件数でいちばん多いのは **JS の型・形（17件）**——無い物を呼ぶ・綴り違い・
引数の数や形の取り違え。ブラウザで動くのは JS だけなので、書き換えずに**検査だけ**足す（ビルドの段は足さない）。

## 測った（前）

物差しは2つ。

1. **TypeScript の検査器が出す件数**（`tsc --checkJs`・57本）: **9,666件**。うち 9,072件は「名前が無い」「その型に無い」——
   画面の JS は IIFE で閉じて`WL.<名前> = …`／`window.<名前> = …`で公開する（§9.359）ので、検査器は公開を読めない。
   残りも大半は DOM（`querySelector`の戻りの`.value`）と、空の字面（`o = {}`）からの推し量り。**このままでは使えない**。
2. **過去の不具合を注いで止まるか**（評価関数・下の表）: 過去に実際に起きた形 10件を今のコードへ1件ずつ注ぎ
   （本物の置き場へは書かず、中身の差し替えで渡す）、**今の網（eslint）は 1件**しか止めない。
   `typeof toast`（無い名前）は eslint の`no-undef`の外（`typeof`は除かれる）。

## 決めたこと

### 公開の型は「名乗っている式」から起こす（宣言の写しを持たない）

`tests/lib/js_types.js` の1本が2周で調べる:

1. 第1周: `WL`・土台の名前を any にして全ファイルを読み、`WL.x = 式`・`WL.x.y = 式`・`Object.assign(WL.x, {...})`・
   `Object.assign(WL, {...})`・`window.x = 式` の**式の型**を検査器に聞く。
2. 集めた型から宣言（`interface WLShape`・`declare var`）を**記憶の中で**書く。ファイルには残さない——
   手で書いた宣言は実装と食い違う写しになる（答えは実装の1箇所）。
3. 第2周: 宣言を添えて検査する。

宣言の書き方の決まり（どれも実測で決めた）:

- **TS 6 は strict が既定で真**（入れると 15,167件）。`strict: false` を明示する。止めたいのは無い物・綴り・引数の形で、
  `null` の扱いまで今の書き方を全部変えると、検査より先に書き換えの危険が来る。
- 名前空間の項目は**省略可**（`?:`）: `window.WL = window.WL || {}` で空から育て、何本ものファイルが少しずつ足すので、
  必須にすると育てる途中の代入が全部食い違いになる。strict ではないので、読む側には省略可は無いのと同じ。
- 関数の引数は**全部省略可**で書く: JS の関数は引数を省いて呼べる（検査器も JS の中ではそう読む）が、型を字へ起こすと
  既定値の無い引数が必須になり、`toleranceDetail(kind)` のような正しい呼び出しが数の誤りに見えた。**多すぎる引数は止まる**。
- `window` に**抜け道を作らない**（`[k: string]: any` を置かない）。置くと「window に載っていない名前を window から読む」
  （§9.215）が素通りする。外から置かれる名前だけ宣言する: 画面の HTML の`<script>`が置く物（`__wlTerminal`）と、
  押したときだけ読む第三者の部品（`THREE`）。
- 宣言の中で解けない型（IIFE の中の型名を指す等）は**その項目だけ any に倒して数える**。いまは 0。倒れたら網が落ちる
  （黙って見張りが外れるのを止める）。

### 数えないもの（取り違えではないもの）

- DOM の型の上の「その型に無い」（`Element` の`.value` など・692件）: ブラウザは実行時に許し、注記で黙らせる手間になるだけ。
- 空の字面から推し量った型（`{}`・`never`）の上の「無い」（555件）: 検査器が中身を知らないだけ。
- `Window` の上の「無い」は**数える**（上の §9.215 のため）。

### 土台の関数に引数の型を書く（JSDoc）

呼ばれる回数の多い土台の名前（`api`・`esc`・`showToast`・`confirmModal`・`alertModal`・`promptModal`・`ttlCache`・`pick`・
`setState`・`fmtDim`・`fixedToleranceValue`）と`presetName`に`@param`／`@type`を書いた。書いても**新しい指摘は 0件**
（今の呼び出しはどれも形どおり）。`api` と `esc` は1つの`const`に並んでいて、`@type` が両方に掛かったので2つの宣言に分けた。

## 分からないこと・残したこと

- 144件のうち、本物の取り違えがあるかは1件ずつ見ていない（見た約80件は推し量りの狭さか、害の無い物だった——
  例: `datumOf(M)` は引数を読まない関数に渡しているだけ・§9.470 で基準面は DS に固定）。件数は減らす方向にだけ動かす。
- `null`・`undefined` の扱い（strict）は入れない。入れるなら1ファイルずつ（`// @ts-check`と strict の組）で、別の段にする。
