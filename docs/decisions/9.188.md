# §9.188 共有スケジュールの見張り（変わったときだけ取り込む）（利用者の指示）

利用者の指示: 「スケジュールデータは共有場所(BOX)にあります。読んで使うときに
ローカルにコピーしてから使わないと競合すると思うのでその機能を実装してほしい。
更新チェックをバックグラウンドで行い、更新を検知したら更新する。しかし頻繁に
更新がかかるときにそれをやると負荷が大きいので、1度更新したら休止し、30秒後
再度更新チェックを再開する形でループ処理したい」。

読む先は元から手元の作業コピー（`fetch_snapshot()`が`backup()`で写す）
だったが、**GETのたびに写していた**。1画面を開くだけで共有ファイル全体の
コピーが何度も走り、共有越しでは1回が数百ms、しかもそのあいだ共有を掴む
ので他の端末の書込とぶつかる。

- **改訂番号だけを見る。** メタテーブルの1行を読むだけなので、全体の
  `backup()`より桁違いに軽い。変わっていなければ写さない。
- **写した直後は休む**（既定30秒）。更新が続いているときに毎回写すと、
  こちらが共有を掴み続けて全員が遅くなる。
- **見かけ（更新時刻・バイト数）も見る。** アプリの外から差し替えられる
  ことがある（検証用の種入れ・別ツール）ので、見かけが変わっていたら間隔の
  内側でも写し直す。**statは確認のためだけに使い、失敗は「分からない」**
  として扱う（共有越しではstatだけ失敗することがある。CLAUDE.md）。
- **書込は必ず取り直す**（`fetch_snapshot(force=True)`）。見張りの間隔を
  信用して書くと、間隔の内側に他端末が書いた変更を踏み潰す。反映後は
  手元が正なので`mark_verified()`で記録する。
- **見張りが止まっていても読めること**が最優先。写しの新しさは
  「最後に確かめた時刻＋間隔」で判断するので、スレッドが死んでも
  最大で間隔ぶん古い写しを返したあと自分で写し直す（従来の動きへ落ちる）。
- 間隔・休み・入切はパス設定マスタ（`schedule_watch_*`）。**再起動は要らない**。
- **画面にも出す。** ヘッダーの「共有: ◯秒前に取り込み」を押すとその場で
  取り込む。他のPCの変更に気づいたら読み直すが、**触っている最中は
  勝手に読み直さない**（掴んで動かしている途中に行が入れ替わると、何を
  していたか分からなくなる）——そのときは帯で知らせて、押されたら読み直す。

固定は`tests/test_scwatch.py`（サーバー）と`tests/test_scwatchui.js`（画面）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **共有スケジュールは「変わったときだけ」取り込む**（§9.188、
  `backend/schedule_watch.py`）: 以前は**GETのたび**に共有ファイル全体を
  写しており、共有越しでは1回数百ms・そのあいだ共有を掴んで他端末の書込と
  ぶつかっていた。改訂番号（メタの1行）だけを見て、変わったときだけ写す。
  **写した直後は休む**（既定30秒。更新が続くときに掴み続けない）。
  **見かけ（stat）は確認のためだけに使い、失敗は「分からない」として扱う**
  （共有越しではstatだけ失敗する。`Path.exists()`で読みを止めない約束と同じ）。
  **書込は必ず`fetch_snapshot(force=True)`**——間隔を信用して書くと、間隔の
  内側に他端末が書いた変更を踏み潰す。**見張りが止まっていても読めること**が
  最優先で、写しの新しさは「最後に確かめた時刻＋間隔」で判断する。間隔・休み・
  入切はパス設定マスタ（`schedule_watch_*`、再起動不要）。画面では
  **触っている最中は勝手に読み直さない**（`canAutoReload()`）。固定は
  `tests/test_scwatch.py`・`tests/test_scwatchui.js`。
