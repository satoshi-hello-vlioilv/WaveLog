# §9.162 データ一覧の表示列を仕掛一覧と同じパネルで決める

**要望**: 「データ一覧も他の一覧と同様に、表示列の編集ができるようにしてください。
全く同じ機能で統合し流用する形でお願いします。」

**流用の形**: 列の設定パネルは§9.120で差し替え口(`WL.listColumns.open(source)`)を
持っている。データ一覧はその3つ目の口（既定＝仕掛一覧、作業スケジュールの内容欄、
そしてこれ）で、**パネルそのものには手を入れていない**。設定画面を新しく作らない
のがここでの要点で、2つあると覚えることが2倍になり、片方にしか無い機能ができる。

**対象は`records:list`**。保存先は列レイアウトマスタで、並び・出す/出さない・幅・
表示名・書式・読み替え・計算式のすべてが仕掛一覧と同じ仕組みに乗る。

**列の鍵は日本語の項目名**にした（仕掛一覧と同じ作法）。英字キーにすると計算式が
`[lotNo]`のようになって書いた本人以外に読めない。**同じ名前を2つ作らない**
（§9.113。列は名前で引く）ため、`recordAllColumnKeys()`が入口で1回だけ落とす。

**既定は今までの15列**。候補は44列あるが、`initialHidden`が「一度も保存していない
うちは既定の15列だけをチェック済みにする」を答える——列レイアウトマスタのhiddenは
空なので、そのまま使うと**保存した瞬間に見覚えの無い29列が並ぶ**（§9.120で内容欄が
踏んだのと同じ罠）。一覧側の`recordVisibleColumnKeys()`も同じ判定を持つ。

**幅と並びはJSが`--rec-cols`へ入れる**。列は設定で増減するので、CSSに書いておける
形ではない。CSSに残してあるのは**設定を読む前の1瞬だけ使う既定**で、既定の15列と
同じ幅にしてある（違う幅を書くと、読み込んだ瞬間に列がずれて見える）。

**日付時刻は地方時の`yyyy-MM-dd HH:mm:ss`にしてから書式へ渡す**。保存値はISO
（末尾Z＝協定世界時）なので、生のまま渡すと時差のぶんずれた時刻が出る
（`WL.cellFormat`のパターンは文字列の数字をそのまま読むため）。

**差し替え口へ足した3つ**（いずれも任意。答えない口は今までどおり）:
`originOf(k)`＝分類を口が答える（測定データの一覧では、値を持つ列でも
「計算・操作」が正しいものがある）／`noteOf(k)`＝その列の作り方の一言／
`currentWidthOf(k)`＝幅を「手で決める/固定」へ切り替えたときの初期値。
**3つ目は既存の不具合の修正でもある**——以前は`#grid`の見出しだけを見ており、
仕掛一覧以外の対象では必ず120pxになっていた。

**閲覧モードではボタンごと出さない**。列レイアウトマスタの保存はedit/scheduleに
しか開いていないので、閲覧モードでは「保存」だけが403で弾かれる。押せるのに
何も起きないボタンは、無い機能より質が悪い（§9.120）。

**操作の列は消せる**。消しても行のダブルクリック・Enterでは開けるが、**削除は
できなくなる**ので、パネルの「この列について」にそう書いてある。

固定は`tests/test_reccols.js`。
