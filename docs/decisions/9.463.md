# §9.463 ゴムリングの空きの既定2〜5mm／刃組基準値の編集窓／仕掛の写しを確実に最新へ／断面図の拡大縮小／区分はロット番号／帯の2列／OS・DSの連動／向きは「基準原点を左・右」（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

> １）ゴムリングの空きの適正範囲は2㎜～5㎜を規定値に変更してください。（今設定している10倍）
>
> ２）刃組基準値マスタは、モーダルサイズがころころ変わり安定せず、入力項目の配置も整列して
> いないのでバラバラ統一感もないのできれいにわかりやすく使いやすいUIUX設計に再構築して
> ください、モーダルのタイトル名も変です。
>
> ３）仕掛情報一覧のところで最新の情報になっていないときに、一覧を再読み込み押しても任意に
> 取りに行った感じがなく最新版化されません。行ったのであれば動き(反応)が欲しいし、実際の
> データ更新がされていない感じもあるので正しく元データのところをコピーして、手元のところの
> 版を最新にしてデータを更新したものを見るように修正してください。少なくとも起動時は確実に
> 最新のファイルに更新し、古い手元のファイルを見ているような状態にならないようにしてください。
> 意図的に更新停止していない限りは、版が相違ある場合直ちに更新すべきです。通常は自動で行う
> はずですが、手動モードなどありましたか？なければ更新機能の手動自動を実装したうえで、
> デフォルトは今まで通り自動にしてください。
>
> ガイダンスの断面図は拡大縮小もできるようにしてください。
>
> 刃組ガイダンスの区分のロットの表示は「LOT1」ではなくロット番号を表示してください。
> クリアランス、ラップなどの表示のバッジの余白が目立つことと、配置が左に偏っていてスペース
> 有効活用できていないことが気になります。
> OS,DSのエリアにマウスオーバーでフォーカスしたときに右側の一覧表が強調されるようにして
> ください。刃の部分は強調が効いてわかりやすくなりましたがOS,DSの部分は無かったので同様の
> 機能を実装したいです。
> 向き変更ボタンについて、段取り向きとか図面向きというのをやめて、基準原点を左、基準原点を右
> といった形で迷いの少ない呼び方に変更するようにします。既定は基準原点を右側に表示して、
> 呼び方もマスタから変更できるようにしておいてください。

## ① ゴムリングの空きの既定

`STANDARD_DEFAULTS`の`ringGapMin/Max`を 0.2／0.5 → **2.0／5.0**。

**マスタに値を保存してある設備では、保存値のほうが効く**（既定はコード・上書きだけがDB・§9.377）。
その設備は②の窓で欄を空にすれば既定へ戻る。

## ② 刃組基準値の編集窓

**原因（調べた結果）**

- 窓の高さは**いま開いている段の中身なり**で、窓は画面の中央に置くので、段を切り替えるたびに
  上下の端が跳ねた。
- 欄は折り返す横並びで、幅がラベルと説明の長さで決まるので列ができない。
- 題は「一覧の先頭の列の値」＋「を編集」で、先頭が有効長だったので「1599.6 を編集」。
- 空欄の数の欄は既定値に従うのに、**その既定値が窓に出ない**。
- 選ぶ欄（基準面・中抜き）は「（既定）」の札が無く、**触らずに保存しただけで値が固定された**。

**直したこと**（どれも汎用の編集窓に足した口で、マスタが名乗って使う）

- `formLayout:'rows'` … 1欄1行（ラベル｜入力｜説明の3列・ラベルは固定幅で右揃え）。
- `mmHoldTabHeight()` … いちばん高い段の高さを器に与える（段を切り替えても大きさが変わらない）。
- `editTitle(e)` … 題を組み立てる口。刃組基準値は「設備名 の刃組基準値」。
- `defaultsKey:'standardDefaults'` … サーバーの既定値を読み、数・文字の欄は**薄字で「既定 ○」**、
  選ぶ欄は先頭に**「（既定）○」**（登録の無い値はそれが選ばれている）。＋／−も既定値から動かす。
- 踏んだ罠: `.mm-field input`の`min-width:200px`が行の入力欄の幅を押し広げ、説明に重なった
  （物差しが入力の器の右端しか見ておらず見逃した→＋ボタン・単位まで見るよう物差しを直した）。

| 物差し（1728×1030） | 前 | 後 |
| --- | --- | --- |
| 段を切り替えたときの窓の高さの揺れ | 499px（428〜927） | 0 |
| 窓の上端の揺れ | 249px | 0 |
| 入力の左端がそろっていない段 | 5／6 | 0／6 |
| 入力が説明に重なる段 | — | 0 |
| 題 | 1599.6 を編集 | テスト設備A の刃組基準値 |

## ③ 仕掛の写しを確実に最新へ

**原因（調べた結果）**

- 「再読込」は写し直しを頼んでいたが、**写しているあいだ画面に何も出さず、結果（写した／
  変わっていない／写せなかった）を捨てていた**。どれでも同じに見えた。
- 写し直すかどうかを元ファイルの時刻と大きさだけで決めており、`force`を送っていなかった。
- **写し直しに錠が無く**、背景の周回と「再読込」が重なると同じ世代名・同じ`.tmp`へ2本が書いた。
- 起動直後は**前回の起動の写し**をそのまま出し、背景の最初の周回は3秒後だった。
- 写しが新しくなっても画面は知らず、画面の控え（3分）のあいだ前の行を出し続けた。
- 「手動」の設定は無かった（`db_mirror_enabled`は「写して読むか」で、別の軸）。

**直したこと**

- `_refresh_lock` … 写し直しは1本ずつ。
- `_first` … 起動して最初の周回が済むまで`read_path()`が待つ（最大30秒）。最初の周回は待たずに回す。
- `update_mode()`（`db_mirror_update`: auto＝既定／manual）… 手動では写さず`check_one()`で
  「新しい版があるか」だけ確かめ、`source_info().newer`で画面へ渡す。共通設定 > どこから読む か に欄。
- 再読込は`force`で写し直し、**押した直後に「元データを取り込み直しています」**、終われば結果を字で
  （取り込み直した／最新だった／取り込めなかった＋理由）。2度押しは1回にまとめる。
- 画面は20秒ごとに`/api/db-mirror/source`（共有を見に行かない軽い口）で素性を聞き、取り込んだ時刻が
  変わっていれば読み直す。手動のときは鮮度チップに「新しい版あり」（橙）。

| 物差し（`eval_mirror.py`） | 前 | 後 |
| --- | --- | --- |
| 起動後に古い写しを読んだ時間 | 3.0秒 | 0.0秒 |
| 2本重ねた写し直しの失敗・古いまま（20回） | 5〜13 | 0 |
| 手動のとき「新しい版あり」を言える | × | ○ |
| 自動／手動の切り替え | 無し | 有り（既定 自動） |

**手動の決め方**: 手動は「意図して更新を止める」なので、**起動時も写さない**（新しい版があることは言う）。

## ④ 断面図の拡大縮小（§9.413「寄る・引くは持たない」を撤回）

ホイールで寄る・引く（**マウスの下の点を動かさない**）。拡大中は右ドラッグ／Shift＋ドラッグで平行移動。
倍率は「視点を戻す」の横に出し、「視点を戻す」で×1。平行投影のままなので、画面の中の寸法どうしは
同じ縮尺で比べられる。拡大しているあいだは×1のときの縮尺と中心を使う——帯の字が倍率で変わると
全体の縮尺が動き、寄るたびにマウスの下の点がずれた（実測 11〜22mm）。器の外へ出た札は出さない。

## ⑤ 区分はロット番号

予定の写しに条の幅が無いと`lots`が空で届き、画面の初期値（`LOT1`）の名前が残っていた。
1本目のコイルの番号（`headLot`）を仮の名前の代わりに使う。手で足した条（`LOT2`…）はそのまま。

## ⑥ 断面図の左上の帯

- 設定のバッジは**高さ中身なり・字は真ん中**（高さを部品寸法で決めて baseline 揃えにしていたので
  字の下にだけ空き）。
- 帯は**入るなら2列**（`hudCols()`が測る）: 左に読み方・突き合わせ、右に設定のバッジを縦に。
  入らない器では折り返す横並び。

| 物差し（1728×1030・断面図） | 前 | 後 |
| --- | --- | --- |
| 帯の高さ | 87px | 66px |
| 帯の右の空き | 313px | 37px |
| バッジの字の上／下の空き | 1／10px | 2／2px |
| 図の縦の大きさ | 429px | 448px |

## ⑦ OS・DS の連動

刃の区間と同じ`[data-badge]`の道に載せた。右の端部の表（`#bsOsSide`／`#bsDsSide`）が`OS`／`DS`を
名乗り、模式図は端の区間（`bs-ehit`・押しても拡大図は開かない）、断面図は OS・DS の札が重ねる的
（区間の面は光るだけ・§9.417）。

## ⑧ 向きは「基準原点を左／右」

- 1つの札の字が押すたびに入れ替わる形をやめ、**2つの札を並べていまの側を濃くする**。
- 状態は「基準原点を左か右か」。図の左右（`flip`＝DSを左）は基準面との組み合わせで`flipOf()`が答える。
- 既定の側と呼び方は刃組基準値（`viewDatumPos`＝右／`viewLabelLeft`／`viewLabelRight`）。
