# §9.92 起動の継ぎ目をなくす

**症状。** 「起動時の挙動がスムーズでなく、モーダルが一回消えてまた出現
してから起動する。初回は画面が準備しきれていないのに表示し、レイアウトが
崩れた状態から数秒待って構築される。」

**一度消えてまた出る。** 起動待機画面(`loading.html`、`file://`)は
`location.replace`でアプリのURLへ移る。**新しい文書が最初の1枚を描くまで、
ブラウザは既定の白を塗る。** 待機画面もアプリの覆い(`#appBoot`)も深い紺の
ため、その白い1枚だけが光って「覆いが消えてまた出た」ように見える。
→ `templates/index.html`の`<html>`へ**背景を属性で直接**持たせた
(`style="background:#0d2029"`)。CSSの到着を待たずに効かせる必要があるので
属性で持つ。値は`loading.html`の背景の起点と同じ。**アプリのCSSへ新しい
16進を足さない約束の例外はここだけ**で、理由も上のとおり。
併せて、引き渡し前の250msの待ちをやめた——進捗はその直前に描き終えて
おり、待ちは画面が止まって見える時間を延ばすだけだった。

**崩れた状態が数秒見える。** 覆いを外す条件が`permission`と`list`だけで、
`assets`(全JSの読み込み)を見ていなかった。読み込みの遅い端末では最後のJSが
走る前に本体が見え、そのぶんの組み替えが目に入る。
→ **`assets`も揃ってから外す**。

**時間切れのときに中身の無い枠を見せない。** 8秒の保険で覆いを外す方針は
変えない(画面が出ないまま固まるのは、崩れて見えるより悪い。§9.86)。ただし
時間切れの原因はほぼ「一覧がまだ来ていない」で、そのまま外すと**枠だけの
画面**が数秒見えて「崩れてから組み上がる」と受け取られる。
→ 外す直前に、`#grid`が空なら「一覧を読み込んでいます…」の置き換えを
入れる。**操作できる画面を出す**という原則はそのままに、見えるものが
「読み込み中」だと分かるようにする。

固定は`tests/test_bootflash.js`(背景が生のHTMLの属性にあること・実際に
塗られていること・覆いの解除条件に`assets`が入っていること・時間切れの
置き換えがあること)。
