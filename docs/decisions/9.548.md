# §9.548 exe 起動への一本化——main へ入ったら CI が exe を置き、ブラウザ版の起動の道とポートの仕組みを外す（利用者の指示）

索引: [決定記録](README.md)｜設計: [`docs/DESKTOP_MIGRATION_DESIGN.md`](../DESKTOP_MIGRATION_DESIGN.md)｜前: [§9.547](9.547.md)｜次: [§9.549](9.549.md)

## 利用者の言葉

「mainに入れたときに自動でexeを作る形にしてください。一本化を進めて」
問いへの答え: 届け方＝**ZIP を落として上書き**／一本化の範囲＝**段3まで**（ブラウザ版の起動の道とポートの仕組みも外す。
exe が動かない端末は起動できなくなることを承知のうえ）。

## 決めたこと

### exe を main へ置く（CI）

- **exe と Python は同じ届け方で一緒に届く**ようにする——枠の約束の版（`protocol`）が違えば窓は起動しない（§9.546）。
  現場は main の ZIP で上書きするので、**CI が main へ`program/WaveLog.exe`をコミット**する（Release に置くと別に取りに行くことになり、組がずれうる）。
- `desktop.yml`の`publish`段（main への push のときだけ・`contents: write`はこの段だけ）: windows 段が作って自己診断を通した exe を
  `program/WaveLog.exe`へ、作った元の指紋（`desktop/`の木と`backend/app_icon.py`）・版・自己診断の数を`program/WaveLog.build.json`へ。
  **窓の元が前に置いた物と同じなら置き直さない**（リポジトリを膨らませない）。**作っているあいだに元が変わったら置かない**（古い exe で上書きしない・後の版が置く）。
  `concurrency`で1本ずつ。コミットは`[skip ci]`。
- 置き場は`program/`（§9.406: 直下は Start.vbs だけ）。`.gitignore`から exe の除外を外した。手で作った exe は足さない。

### 段3: ブラウザ版の起動の道を外す

- **Start.vbs は exe を手元へ写して起こすだけ**。exe が無い・写せない・起こせないときは**理由と次の一手**（ZIP で上書き・空き容量・書き込み権限）を出す——黙ってブラウザ版へ逃げない。
- 外した物: `program/start_app.py`・`start_app.bat`・`stop.bat`・`process_manager.py`・`loading.html`、`backend/launcher/guard.py`、
  `/api/ready.js`、`boot_status`の書き手（顔ぶれ`STEPS`/`BROWSER_STEPS`は`#appBoot`のために残す）、`setup_check`の待機画面の写し、
  `paths.instance_file()`、`config`のタブの猶予と`app_url()`、`watchdog`のタブの見張り（`_active_tabs`・`_loop`・`start()`・`/api/heartbeat/close`・`quit-check`の`tabs`）、
  画面の早いハートビートとタブID・タブを閉じにいく仕掛け、§9.547 の「起動のしかた」の切り替え一式（選ぶものが無くなった）。
- **残した物**: `/api/heartbeat`（在席と版の知らせ）・`/api/app/quit`・`/api/shutdown`・`teardown()`／`_exit()`（窓口と終了ボタンが通る）、
  `HOST`/`PORT`（開発と網の入口・書込役の受け口`PORT+1`）、`paths.browser_dir()`（ショートカットの補助スクリプトと絵）、端末の控え（§9.545。WebView2 の保存領域が消えたときの戻り先）。
- **開発と網（テスト）の HTTP の入口**は`backend/launcher/server.py`（`python3 program/app.py`）。背景処理は窓口と同じ`services.start()`、タブの見張りは持たない。
  止めるのは`/api/shutdown`。網のランナー（`run_all.sh`・`with_fixture.sh`）もこれで起こす。
- **上書きコピーで残る物を片付ける**: `setup_check.RETIRED`（外したファイル。旧い直下の置き場の物も）——合図は**新しい Start.vbs が届いていること**
  （もう`start_app.py`を起こさない）。`MOVED_AWAY`の「新しいほうが在るとき」は移した先が無いので使えない。届く途中の混ざった配置では1バイトも触らない。
  端末の手元の待機画面の写し・進捗・起動中の印は`RETIRED_LOCAL`。update.bat と窓口の起動前の確認が通る。
- 開き直し方の字は`WL.RESTART_HOW`の1箇所（「stop.bat で止めてから」を3箇所に書いていた）。

## 撤回した案

- **exe を Release に置く**——ZIP とは別に取りに行くので、exe と Python の組がずれうる（窓が起きない）。
- **exe が無ければブラウザ版で起動する**——段3の意味が無くなる（利用者は「exe が動かない端末は起動できない」を選んだ）。代わりに理由と次の一手を出す。
- **開発と網のためにも Playwright を WebView 越しに回す**——網の全部（274本）を作り直すことになる。HTTP の入口を開発と網だけに残すほうが小さく安全。
- **`#appBoot`の段の名前（「Webサーバーを起動」）を直す**——画面の見た目が変わるので、利用者に確かめてから（CLAUDE.md の E）。今回は残した。【§9.549で直した】利用者の指示「言い換えてください」。

## 踏んだ罠

- **網が製品の一覧をそのまま材料にすると、一覧から抜けた物を見逃す**。欠陥注入（`RETIRED_LOCAL`から`instance.json`を抜く）を
  網が拾わなかった——網が`setup_check.RETIRED_LOCAL`の名前でファイルを作り、その名前で消えたかを見ていたので、抜けた名前は作られも
  確かめられもしなかった。**期待する名前は網の側に書く**ように直し、注入し直して拾うことを確かめた（外した物の一覧も同じ形に直した）。
  欠陥注入は5件（ブラウザ版へ逃げる・合図を見ずに消す・手元の印を残す〈直したあと〉・進捗の書き手を戻す・外した物を一覧に載せない）。

## 分からないこと

- `publish`段が main へ書けるか（main に保護の決まりがあると push が断られる）。main へ入ったときにしか動かないので、**取り込んだ後に確かめる**。
- 本物の Windows 端末（Store 版の Python・Box Drive）で、`RETIRED`の片付けが Box の同期とどう噛み合うか。
