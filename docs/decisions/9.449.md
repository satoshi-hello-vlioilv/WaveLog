# §9.449 浮きメニューの寸法を揃えるのは撤回——揃えるのは値ではなく値の置き場

索引: [決定記録](README.md)

利用者の判断:

> 今回修正案のキャプチャの範囲の文字の変更と行の高さの変更はあまり有益な
> 変更ではないですね。却下。

> 当然不具合の修正はOKです。

---

## ① 何が誤っていたか

§9.448 で「浮きメニューの流儀を 18種 → 7種」を良いことだと置いた。
**その物差しが誤っていた。**

「同じ役目の物を2つ作らない」（CLAUDE.md）は**作りの話**であって、
**見た目の値まで同じにしろとは言っていない**。面ごとに寸法が違うのは、
面ごとに中身が違うからで——列見出しのメニューは18項目が並ぶ短い字の列、
モードの札は「名前＋その下に一言」の2行——**揃えること自体に用は無い**。

利用者が名指ししたのは2つ（文字 12→13px・行の高さ 24→36px）だが、
**実測すると私が動かしていたのは13面・58箇所**だった:

| 面 | 私が動かしていたもの |
| --- | --- |
| 列見出し・予定の行・入れ子 | 最大幅 320→340px／影の色／項目 24→36px／字 12→13px |
| 測定データ一覧 | 最小幅 240→210px／高さの上限 なし→70vh／影／項目 32→36px／字 |
| モード・再読込 | 最小幅 190→210px／最大幅 なし→340px／高さの上限／内余白 8→4px／影／項目 34→36px |
| 同期・表の切り替え・組み合わせ・条件・見本・「表示」 | 内余白 8→4px／影／項目 34→36px |
| **説明のヒント** | **最大幅 なし→340px**／高さの上限 なし→70vh／内余白／影／項目 |

**説明のヒントは実害が出る**——最大幅が無かったのは、説明文が折り返し
すぎないようにするためで、340pxで切ると読みづらくなる。
「揃える」の一言で、**見ていない面まで一緒に動かしていた。**

## ② 直し方——名前は1組、値は面ごと

器（`.wl-menu`）とふるまい（`WL.popMenu`）は1つのまま、**値だけ**を
§9.448より前へ戻した。戻し方は「元のCSSへ書き戻す」ではなく、
**トークンの既定値と、面ごとの宣言**にしてある:

```
.wl-menu{ --menu-w:210px; --menu-w-max:320px; --menu-max-h:70vh; … }  ← 既定（列見出し）
.rec-row-menu{ --menu-w:calc(240px*scale); --menu-max-h:none; … }      ← 面ごとの値
.access-mode-menu{ --menu-w:190px; --menu-w-max:none; --menu-pad:…; }  ← 面ごとの値
```

こうすると**その面の値がその面のブロック1箇所で読める**。
「答えは1箇所に持つ」は満たしたまま、**値を1つにはしない。**

## ③ 測った

| 物差し | §9.448（却下） | 直したあと |
| --- | --- | --- |
| §9.448より前と違う項目（13面・17項目ずつ） | **58** | **0** |
| 器の名前 | 1（`.wl-menu`） | **1**（そのまま） |
| 置き場所・外クリック・Esc・矢印キー・`role`の配線 | 1箇所 | **1箇所**（そのまま） |

**残したもの**（見た目を変えないもの）:

- 器が`.wl-menu`の1つであること、ふるまいが`WL.popMenu`の1箇所であること
- `role=menu`／`menuitem`と**矢印キーで項目を移れる**こと（↑↓・Home・End）
- **不具合の修正**: `.rec-row-menu`のホバーが全項目を危険色にしていた
  （2項目目を足した瞬間に無関係な項目が赤く光る）。利用者の
  「当然不具合の修正はOK」に当たる。

## ④ 網を「揃っていること」から「勝手に動かしていないこと」へ

`tests/test_popmenu.js` の物差しを入れ替えた。以前は
**U＝流儀の総数が7種であること**を見ていた——これは「揃えるほど良い」を
網に焼き付けたもので、**却下された価値観そのもの**だった。

いまは `tests/fixtures/menu_look.json`（13面 × 17項目）と突き合わせて
**1つも違わないこと**を見る。意図して変えるときは控えを書き直す
——黙っては通らない。欠陥注入で確認: 字を13pxへ戻すと
`列見出し.itemFs 12px→13px` ほかで落ちる。

## ⑤ 教訓

**見た目を動かす前に「読む人に何が良くなるか」を言えること。**
言えないなら、それは整頓であって改良ではない。数が揃うことは、
それ自体では利用者の得にならない。

キャプチャを先に見せる手順は正しかった（§CLAUDE E）。
足りなかったのは**キャプチャに写らない面まで数えて見せること**で、
今回は58箇所のうち2箇所しか見えていなかった。
**動かした値は、見せた範囲の外も含めて全部数えて出す。**
