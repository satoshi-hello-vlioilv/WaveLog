# §9.110 列の並び: 幅を引いただけで番号・ボタンが右端へ飛ぶ

実機からの報告: **「列の移動や表示非表示で正しく反映されない部分がありました、
実態は表示非表示ができないだけかもしれません」**。

#### 実際は逆で、壊れていたのは並びのほう

再現すると、**表示/非表示は正しく効いていた**（隠した列は消え、保存され、
再読込後も隠れたまま）。壊れていたのは並びで、しかも引き金は列の設定
パネルではなく**見出し側の操作**だった。

| | 先頭 | 末尾 |
|----|----|----|
| 操作前 | `# / 分割 / ロット番号 …` | `… 測定` |
| **列幅を引いた後・再読込** | `ロット番号 / 鋳造番号 …` | `… # / 分割 / 測定` |

原因は`bindColumnHeaderTools()`の`fullOrder()`が、保存する並びを
`allColumns`（**データ列だけ**）から組み立てていたこと。§9.106で
「並びは`listColumnKeys()`の1本」に統一したのに、この呼び出し側だけが
更新されていなかった。番号・ボタンの列が保存する並びから丸ごと落ち、
次に開いたとき`apply()`が「知らない列」として**末尾へ回す**。

**列幅を引く操作は日常的に使う**ので、実質「触るたびに飛ぶ」状態だった。
見出しのD&D・幅のダブルクリックも同じ経路。

#### 直しただけでは足りない

**実機には既に壊れた形で保存された設定がある。** こちらが直さないと、
利用者が`#`・`分割`・`測定`を手で引きずり戻すことになる。読むときに直す:
`healedColumnOrder()`が「番号・ボタンの列が1つも入っていない並び」を
データ列だけの並びとみなし、**データ列の順は覚えているまま、番号・ボタンの
列だけを本来の位置へ戻す**。パネル側も同じ関数を通す——直し方が違うと、
§9.106で1本にした並びが表示だけ2本に戻る。

固定は`tests/test_collayout.js`（幅を引いても並びから消えないこと・右端へ
飛ばないこと・古い並びが直ること・その直しでデータ列の順を崩さないこと）。
**4件とも、直す前の実装に戻すと落ちることを確かめてある。**

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **見出し側の操作も`WL.listColumnKeys()`の1本の並びで保存する**（§9.110）:
  `bindColumnHeaderTools`の`fullOrder()`が**データ列だけ**から並びを作って
  いたため、**列幅を少し引いただけで`#`・`分割`・`測定`が右端へ飛んだ**
  （並びから落ちる→次に開くと「知らない列」として末尾へ回る。実機で
  「列の移動が反映されない」と報告された。**表示/非表示は正常だった**）。
  番号・ボタンの列を含まない並びを新しく保存しないこと。**読むときの
  自己修復も外さない**——実機には既に壊れた形の設定が保存されており、
  `healedColumnOrder()`がデータ列の順を保ったまま番号・ボタンの列だけを
  本来の位置へ戻す。パネルも同じ関数を通す（直し方が違うと並びが2本に
  戻る）。固定は`tests/test_collayout.js`。
