# §9.632 業務の Python を Rust へ移す——計画と、§9.563 の住み分けを改める（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.631](9.631.md)｜計画: [`docs/RUST_MIGRATION_PLAN.md`](../RUST_MIGRATION_PLAN.md)｜関係: [§9.563](9.563.md)・[§9.544](9.544.md)・[§9.546](9.546.md)・[§9.554](9.554.md)

## 経緯（利用者の言葉）

> PythonをRustに置き換える計画を立ててください。

計画の案と4つの問いを示し、利用者が答えた:

> 1は製品だけ、2は提案どおり、3は64bit、4は進めてください

1. Python を消す範囲 → **製品が動く部分だけ**（網・道具は Python のまま）。
2. 移行中の新しい機能 → **移した領域は Rust・まだの領域は Python・移している最中の単位には足さない**。
3. Navigator の DLL → **64bit**。
4. 計画を文書と決定記録に残して push する。

## §9.563 から改めたこと

§9.563 は「業務・SQLite・共有DB・Excel は Python のまま」と決めた。理由は、業務の不具合の大半が論理・仕様で言語では減らず、
書き直す危険のほうが大きいこと。

その追補で利用者は「Python を同梱しない（配る物が巨大化する）」と決めた。§9.563 自身が「外すべきなのは Python ではなく、
Python を各 PC に用意してもらう形のほう」と書いており、同梱を外した後に残る道は **業務を Rust の exe へ移す**ことだけになる。
今回の指示はこの目的に沿うものとして受けた。

- **変わらない事実**: 論理・仕様の不具合は言語で減らない。だから書き直しには **影の比較**（同じ問い合わせを両方へ送り、
  不一致が 0件になってから切り替える）を必ず通す。
- **変わらない決まり**: 1つのファイル・1つの事実の書き手は1言語（`data.md`）。移行の途中でもこれを守るため、
  **移す単位はルートではなく書き手**で切る。

## 決めたこと

- 窓の振り分け（`router.rs`）に「Rust が答えるルートの表」を置き、表に無いものだけ Python へ回す（画面と JS の網は変えない）。
- 段は P0（土台・物差し）→ P1（純粋な関数）→ P2（読むだけのルート）→ P3（保存と共有）→ P4（マスタ）→ P5（予定）→
  P6（残り・RNE）→ P7（Python の撤去）。中身と物差しは計画書の §4・§5。
- **P2 を終えた時点で実測し、続けるかを決め直す**。
- 開発と網のための HTTP の入口も Rust に持たせる（窓の枠と同じハンドラ）。
- 業務のクレートは窓と分け、Tauri も Windows も知らない（Linux で `cargo test` が回る）。

## 測ったこと（基準値）

- 業務の Python 約4.7万行（このほか更新履歴の字 7.4千行）・ルート 270本・背景のスレッド 15か所・外の部品は flask だけ。
- 網: JS 236本（HTTP 越し）・Python 112本（うち 91本が `backend` を直に読み込む）。
- 起動の秒・メモリ・exe の大きさは **未計測**（Windows の実機で P0 に測る）。
