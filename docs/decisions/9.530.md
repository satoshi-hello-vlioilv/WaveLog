# §9.530 判定表の行と列を後から並べ替える——掴む札・キー・列の並びを保存（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「条件テーブルの部分は行や列の並び替えが後からできるようにしてほしいです。」

対象は判定表の部品（`rule-table.js`）——保持方式・刃のカテゴリ・刃厚の3つの表が同じ部品を使うので、1箇所で3つとも変わる。

## 測った（評価関数）

同じ表（列＝板厚・条数、決まり4行。1行目は条数だけ・2行目以降は板厚だけ）で測った。前は VER2.416.0。

| | 前 | 後 |
| --- | --- | --- |
| 列を並べ替える手段 | **0**（無い） | 列ごとに掴む札（ドラッグ／←→キー） |
| 最後の決まりを先頭へ動かす手数 | 3（▲を1段ずつ） | 1（ドラッグ） |
| 保存→開き直しで列の並び（板厚/条数）が残る | **残らない**（条数/板厚へ入れ替わる） | 残る |

網: `test_holdpick.js` ⑥（7件）、`test_bladeset.py`（3件）。確定を `drop` だけにする欠陥を入れると ⑥ が3件落ちる。

## 見つけた不具合

- **列の並びが保存されていなかった。** 画面は列を「上の行・左の条件から順に」起こしていたので、1行目に無い列は後ろへ回る
  ——並べた順と開き直した順が違っていた（実測: 板厚/条数 → 条数/板厚）。条件の無い列（足しただけの列）も保存で消えていた。

## 決めたこと

- **列の並びは表の設定**として保存する。`保持方式マスタ`・`刃選択マスタ`に `[列JSON]`（どの行にも同じ値・読むときは最初の行）。
  答えは `table_cols()` の1箇所: 保存した並びを先に、条件にあるのに並びに無い列（前の版で保存した表）を後ろへ。
  表で使えない列（前の表の答えの順を越えるもの）は `normalize_cols()` が落とす。
- 並べ替えの手段は**掴む札（⠿）の1つ**: 行は番号の横、列は見出しの名前の前。ドラッグでもキー（行＝↑↓・列＝←→）でも動き、
  焦点は動いた札についていく。行の ▲▼ ボタンは外した（同じ役目を2つ持たない）。
- 確定は `dragend`（§9.201——最後の `dragover` が断った場所で離すと `drop` は起きない）。動いていなければ何もしない。
- **既定の行はいつも最後**（札を持たない・運んでも最後より後ろへは入らない）。列を動かしたら各行の条件も列の並びへそろえる
  （`sortConds()`）——保存しても読み直しても同じ並び。
- 運んでいる行・列は薄く、入る先は teal の線（行＝上下・列＝左右）で言う。札は枠を持たない（押す物に見せない）。

## 分からないこと・残したこと

- 刃選択の盤の2つの表のあいだで行を運ぶことはできない（表が違えば答えの意味が違うので、運べないのが正しいと判断した）。
