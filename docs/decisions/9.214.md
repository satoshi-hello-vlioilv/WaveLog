# §9.214 ③測定データ分析は表を解体してロットのMIN/MAXにする（利用者の指示）

> 「『確認して完了』の測定データ分析の欄は、**今カード内に出ている表は解体**。
> 中身のデータは**表示は必要なものに絞り**、表示内容や削ったそのエリアも
> 使って、**ロット単位で、板厚のMIN,MAX、板幅のMIN,MAX**を表示できるように
> してください。」

以前は6項目（板厚・板幅・バリ・ラテラルボー・巻きずれ・テレスコープ）×
MIN/AVE/MAX/3σ/N数の**30マスの表**だった。**このロットがどの範囲に
収まったか**を読むのに5つの数字は要らない——AVEと3σは合否にも次の行動にも
効かず、読む側は毎回MINとMAXだけを拾っていた（§1「面積は頻度×重要度で
配る」）。

いまの中身は3段:

1. **板厚・板幅のMIN/MAX**（主役。数字を大きく、単位とN数を添える）
2. **そのほか**——**値のある項目だけ**1行ずつ（MIN〜MAX とN数）。
   測っていない項目の行は出さない（空の行は「測り忘れ」と区別が付かない）
3. **子ロットごとの板幅**（分割ありのときだけ）

**公差の合否はここで言わない。** 公差外の件数は③の確認表が数えており、
効いている公差はすぐ上の`#toleranceList3`が出している——同じことを3箇所で
言うと、読む側は「違うものかもしれない」と数え直す（§8）。ここが言うのは
**測った値の範囲**だけ。

**N数は必ず添える**（§6）。1点しか測っていないMIN/MAXと80点のMIN/MAXでは
当たる見込みが違う。

**子ロットごとに出せるのは板幅だけ。** 条は子ロットに属する
（`splitSequence`が条→ロットを持つ）ので板幅は割り振れるが、**板厚は丈位置
ごとに3点**で測るため条に紐づかない。出せないものを黙って空欄にせず、
**そう書く**（§4）。子ロットが1つしか無いときは節ごと出さない
（同じ数字が上の主役と2箇所に並ぶ）。

固定は`tests/test_msteps.js`。**値は自分で注ぎ込んでから見ること**——
検証用データに測定値は入っておらず、そのままでは「まだ測っていません」しか
出ずMIN/MAXの道を一度も通らない。**注ぐ前に空にすること**も要る
——そこまでのテストが打ち込んだ値が残っており、実際にMINが49.50へ
引きずられた。
