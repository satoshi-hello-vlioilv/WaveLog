# §9.346 `offsetParent` は「見えているか」の物差しではない

同じ日に**3回**踏んだので規則にする。`offsetParent` が `null` になるのは
「伏せてある」ときだけではない。

| `offsetParent===null` になる場面 | よくある誤読 |
| --- | --- |
| `position:fixed` の要素（**常に** `null`） | 「出ているのに見えないと読む」 |
| まだ組み上がっていない／`display:none` の親の中 | 「まだなのに出来上がったと読む」 |
| `<body>` そのもの | — |

## 今日の3件

1. **`tests/test_filter.js`（§9.345）**: 候補の箱 `.filter-suggest` は
   `position:fixed`。`offsetParent` で「見えているか」を測ったので、
   **出ているのに「見えない」**と読み、**網自身が1件落ちた**。
   → `hidden` と中身の有無で見る。
2. **`tests/test_stopcat.js`**: 一覧の器が `offsetParent===null` なら
   「畳んである画面だから待ち終わり」と扱っていた。ところがこれは
   **「まだ組み上がっていない」でも真**になる。**通しの1本目**（サーバー
   再起動直後で、マスタDBの移行がその場で走る）だけ、**まだ空の一覧を
   「出来上がった」と読んで**素通りし、`.mm-row` が0件のまま
   「既定の分類が入っていない」と報告していた。
   → 畳んであるかは**器の印**（`#masterMaintForm.mm-form-page`）で見る。
3. （同じ形）`waitForSelector` の既定 `state` は `'visible'` なので、
   `'#appConfirmModal[hidden]'` を待つと**永久に一致しない**（§9.342）。

## 決めたこと

**「見えているか」を測るときは、何が理由で見えないのかを分けて書く。**

- **伏せてあるか** … `hidden` 属性／`display`／**器の印**（クラス）
- **画面に出ているか** … `getBoundingClientRect()` の幅と高さ
- **中身があるか** … `childElementCount`

`offsetParent` を使ってよいのは「**この要素は静的配置の祖先を持つか**」を
知りたいときだけで、それは普通この網が知りたいことではない。

## 直したが、証拠は次の通しで取る

2 の失敗は**通しの1本目でしか起きない**（サーバー再起動＋移行が同時に走る
タイミング）。**欠陥を戻しても単体では再現しなかった**ので、
「この穴が原因だった」とは**まだ言い切れない**。穴そのものは誤りなので
塞いだうえで、**次の通しで緑になることを証拠にする**（§9.200「再実行で
緑になったからといってフレークで片付けない」の裏返しで、**直したから
緑になったとも、まだ言えない**）。

## ついでに見つけた置き土産

`設備停止分類マスタ` に **43行**あり、うち **39行が試験の屑**
（`分類128369`・`検査52323` 等、論理削除で `有効=0` のまま残ったもの）。
削除は論理削除なので**行は永久に残り、通すたびに増える**。
`tests/make_fixture.py` の `fix_master()` はこの表を見ていない（§9.284 の
「名前で見分けられる屑だけ片付ける」が未適用）。
**今回の失敗の原因ではない**ので、別の変更として片付ける。
