# §9.551 デスクトップ版の印刷・保存を本物の WebView2 で確かめる——保存は`saveBlob`／`saveFrom`の1箇所（利用者の選んだ候補 1-B）

索引: [決定記録](README.md)｜設計: [`docs/DESKTOP_MIGRATION_DESIGN.md`](../DESKTOP_MIGRATION_DESIGN.md) §4-5｜前: [§9.550](9.550.md)

## 経緯

起動は exe の窓（WebView2）だけになった（§9.548）。設計書 §4-5 で「印刷・保存は WebView2 でも動く見込みだが、Windows の実機では
確かめていない」と書いたまま、手を付けていなかった（P4）。利用者の言葉: 「メインにマージして、1-Bを進めてください。既定のブラウザはedgeです。」

## 洗い出し（アプリの印刷・保存の道）

| 種類 | 使う所 |
| --- | --- |
| 印刷（画面そのもの・`window.print()`） | `print-core.js`・`base.js`（画面を印刷）・品質一覧・作業予定表 |
| 印刷（見えない iframe・`contentWindow.print()`） | 帳票（`report-dashboard.js`の`rpPrintFrame`） |
| 保存（画面で作った Blob＋`a[download]`） | 接続の記録の CSV・フィルタ・列の設定・ログの書き出し |
| 保存（中身が添付で返す・ページを移す） | Excel の書き出し（`location.href`）・ログの「保存」（`<a href>`） |
| 読み込み（`<input type=file>`） | マスタの取り込み・フィルタ・列の設定 |
| クリップボード | 自己診断で確認済み（§9.546） |

## 確かめ方

- 窓（`desktop/src/main.rs`）は**自己診断のときだけ**保存を記録する（`on_download`→`record_download()`：保存先・大きさ・先頭4バイト）。
  `/__desktop/downloads`で画面の自己診断へ渡す。**利用者の起動では受け手を付けない**——付けると WebView2 の既定の保存の案内
  （右上の小窓）が出なくなる（wry が`DownloadStarting`の`Handled`を立てる）。
- 自己診断（`desktop/src/selftest.js`）に3項目: 画面で作ったファイル／中身が添付で返す Excel（日本語の名前）／帳票の印刷の書類
  （見えない iframe が画面と同じ CSS で組み上がり`print`を呼べる）。
- 印刷の窓とファイルを選ぶ窓は**人が操作する窓**なので CI では開かない（下の「実機で確かめること」）。

## 分かったこと（1回目の自己診断・`ac11f6f`）

- Blob の保存は通る: `C:\Users\runneradmin\Downloads\wl-selftest-保存.txt`・3200バイト・名前どおり（日本語の名前も）。
- 帳票の印刷の書類は組み上がる: CSS 5/5 本・`--teal`が効く・`print`を呼べる。
- **中身が添付で返すファイルへページを移しても、保存が始まらない**。窓の記録に保存の始まり（`DownloadStarting`）が1度も来ず、
  ページも移らない。つまり**窓の中では Excel の書き出しとログの「保存」が何も起きなかった**（Excel の書き出しは0.9秒後に
  「書き出しました」と言うので、利用者は保存されたと思う）。WebView2 の中のどこで止まるか（窓の宛先＝自前の仕組みで返した応答
  だからか）は**分からない**。

## 決めたこと

- **保存は`WL.base.saveBlob(blob, 名前)`／`WL.base.saveFrom(url)`の1箇所**。`saveFrom`は`fetch`で受け取って Blob にし、
  `saveBlob`で落とす（窓で通ると確かめた道）。名前は`Content-Disposition`の`filename*`（日本語はここにだけ入る）を先に読む。
  断られたら理由を言う Error を投げる（ページを移さない・`apiErrorMessage`で状態コードから言い直す）。保存の6か所をこの2つへ寄せた。
- Excel の書き出しは、成否を待たずに0.9秒後「書き出しました（ブラウザの保存先を確認してください）」と言っていた
  → **保存できた名前**（「ダウンロード」フォルダ）か、**できなかった理由**を言う。
- 自己診断は画面の`saveBlob`／`saveFrom`そのものを試す。
- 既定のブラウザは Edge（利用者の答え）→ §9.550 の「LotDsp を Edge で名指しして開く」は入れない。

## 撤回した案

- **窓が保存の受け手を常に付け、保存先を決めて字で知らせる**——WebView2 の既定の案内が消え、画面の見た目が変わる。
  既定の案内で足りる（保存先は「ダウンロード」フォルダ・右上に出る）。
- **窓（Rust）が添付の応答を見つけて自分でファイルへ書く**——Python の応答を Rust が読み分けることになり、役割の分け方（§9.544）が崩れる。
  画面の`fetch`→Blob で足りる。

## 網

- `test_saveio.js`（新・5項目）: Excel が日本語の名前・中身（PK）のまま**Blob から**落ち、ページを移さない／ログの「保存」も Blob から／
  断られたら理由／保存を自前で書いている所が無い。欠陥注入3件（ログの保存を元の形へ・`filename*`を読まない・Excel をページ移動へ）を全部拾う。
  **落とす元が`blob:`であることまで見る**——添付へページを移す形はブラウザでは落ちるので、それだけでは窓で動かない形を見分けられない。
- 窓の自己診断（CI の Windows）: 上の3項目。

## 踏んだ罠

- **網の環境（POSIX）では Chromium が日本語の保存名を「download」へ倒す**。ASCII の名前は通り、日本語の名前は Blob の種類・`fetch`の有無に
  関係なく全部「download」になった（切り分けた）。`LANG=C.UTF-8`で通る。網の土台（`harness.js`）がブラウザへ`LC_CTYPE=C.UTF-8`を渡す
  （現場の Windows では日本語のまま保存される・自己診断で実測）。
- **`--pure`で`test_dbmirror`が1回落ちた**（「待って取り直さない」を 0.3秒で切っていて、並列8本の重さで 0.70秒）。単独では3回とも通る。
  欠陥（待って取り直す）なら必ず待ちの合計 2.5秒以上かかるので、境目をその半分（1.25秒・製品の定数から）にした。欠陥注入で 2.50秒・落ちる。
- **確かめる前にコミットした**（`--pure`の結果を見ずに、同じコマンドでコミットと push まで進めた）。落ちたのは上の時間の判定で、変更とは
  別だったが、順番の誤り。結果を見てからコミットする。
- `with_fixture.sh`が、自分で起こしたサーバーの終わりを待ったまま止まることがある（今日2回）。後片付けは済んでいた。仕組みは**分からない**。
  調べる台本は`run_all.sh`の網の中で`WAVELOG_SHOT`のときだけ動く形にして回した。

## 実機で確かめること（利用者へ）

1. 帳票の「印刷」を押す → 印刷の窓が出て、プレビューが紙1枚ずつ（A4）になっている。やめても2回目が出ない。
2. 作業予定表・一覧の「画面を印刷」→ 印刷の窓が出る。
3. マスタ管理のロールマスタで Excel を書き出す → 「書き出しました: ロールマスタ_….xlsx」と出て、「ダウンロード」フォルダに入る。
4. マスタ管理の取り込み・フィルタの取り込み・列の設定の取り込みで、ファイルを選ぶ窓が開き、選んだファイルが読める。
