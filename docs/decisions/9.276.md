# §9.276 設定画面の6件——属性の逃がし・説明の量・更新者ID・説明の階層・見本の再現（利用者の指示）

> 1) 帳票ブロックは上部ではなく左サイドバーに変更し、説明文はポップオーバーなど
>    場所を取らない方法にしてください。
> 2) マスタを確認しているときに説明文の長さを切り替えると、マスタ表示内容が
>    消えます。…このボタンは3つもエリアを使っているが…隣の文字サイズ切り替え
>    UIのように、ポップオーバーメニューなど場所を使わない方法で。
> 3) ユーザーIDを表示する上部のメニュー部分は、IDを書き換えられないように…
>    ボタン化して接続状況確認と配線してください。
> 4) アクセス権限マスタの説明文(モーダルも含む)が`<b>`タグが見えていて正しく
>    エンコードされていない…説明文長すぎて…タブやアコーディオンなど使って…
> 5) 帳票ブロックのカスタムで表で組み替えて保存したらその瞬間はきれいに保存
>    されますが、再度読み込むと「表に組む」というボタンが押せなくなっていたり、
>    帳票プレビューでは見た目は全く変わっていない状態でした。
> 6) 操業データ項目のモーダル左半分のプレビュー機能が再現度が中途半端です。

#### ⑤ 本体は`esc()`——属性へ埋めると引用符で切れる

いちばん深いのはこれで、**帳票とは関係ない**。`base.js`の`esc()`は

```js
esc = v => { const d=document.createElement('div'); d.textContent=v??''; return d.innerHTML };
```

だった。ブラウザのこの直列化は**`&` `<` `>`しか逃がさない**——文字節点では
引用符に意味が無いからで、仕様どおりの動きである。ところが**この関数の
使い道の大半は属性**（`value="${esc(v)}"` / `title="${esc(v)}"`）で、値に`"`が
1つでもあると**そこで属性が閉じ、残りが黙って消える**。

§9.274で足したセルの保存形は`[{"kind": "blank"}, …]`というJSONなので、
編集窓の隠し欄（`<input type="hidden" data-field="content" value="…">`）が
**`[{`まで切り詰められて**いた。症状はこう出る:

  * 開き直すと`fbParse('[{')`が行の形として読み、**マスの並びが1件の屑になる**
  * その1件は軸を持たないので**「表に組む」が押せない**
  * 窓の右の見本の紙も**中身なしのまま**
  * **そのまま保存すると、マスタの中身まで壊れる**（`[{`が保存される）

実データに`"`が入る場面は今まで無かったので、**この穴は長いあいだ誰も
踏まなかった**。直しは**置換方式へ変える1箇所**だけ:

```js
esc = v => String(v??'').replace(/[&<>"']/g, c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));
```

**中身に使ったときの見え方は1文字も変わらない**（`&quot;`は`"`として出る）ので、
70箇所を超える呼び出しは触らずに済む。**インラインのイベント属性の中でJSの
文字列を組み立てている箇所が無いこと**を先に確かめてある（`'`を逃がすと壊れる
のはその形だけ）。

**紙の側は最初から正しかった**——サーバーの`parse_content`／`dump_content`は
JSONを往復できており、子ロットごとの繰り返し（§9.247 ②）も表として出ていた。
**保存の口だけを見る網では捕まらない**ので、`tests/test_rbcells.js`は
①`esc()`そのものを属性へ往復させ、②-b**窓を開き直して盤の中身**を見る
（欠陥を戻すと両方落ちることを確認済み）。

#### ② 説明の量——専用の画面を潰していた

`renderMaintList()`は`def.cols`から見出しを組んだ**汎用の一覧**を
`#masterMaintList`へ無条件に書く。専用の画面（`special:*`——接続状況・共通設定・
操業データ項目…）は同じ器へ自前の中身を描いているので、そこへ空の表を
書き込むと**丸ごと消える**。

描き直しの入口を`refreshMaintScreen()`の1つにし、`def.special`があるときは
**`loadMaintInner()`へ戻す**（専用の画面の唯一の受け口。2つ目の対応表を作らない）。

帯（3つのボタン）は`#mmHintBadge`＋浮きメニューへ。**隣の`#uiSizeBadge`と同じ
言語**にすることで、押す前にどちらの形か思い出さずに済む。**いまどれかは
ボタンに文字で出す**——畳んだだけで現在値が読めなくなるのでは、場所を空けた
意味が無い（§CLAUDE 3）。

**網は専用の画面で試すこと**——ふつうのマスタ（設備）で切り替える網は、
直す前でも通る（あちらは汎用の一覧そのものなので、描き直せば戻る）。

#### ③ 更新者IDは名乗るだけ

`#masterUserId`は打ち込める`<input>`だった。ここは**この端末のログインID**で、
アクセス権限マスタの照合・監査列・フィルタの持ち主が見ている値——打てると
**他人の名前で更新できてしまい、記録の意味が無くなる**。`<button>`にして、
押したら**接続状況**（§9.272）へ行く。

読み取り専用にすると「IDが取れない端末では何も保存できない」が生まれるので、
**出どころを増やした**（§9.208 ⑧のPC名と同じ作法）——`os.getlogin()`は端末に
つながっていないプロセスで`OSError`を投げるので、`getpass.getuser()`を足す。
**答えるのは`access_mode.current_login_id()`の1箇所**にし、`/api/whoami`は
そこを通す（以前は同じ判定を2箇所に書いており、画面が名乗る値と権限の照合に
使う値が食い違いうる状態だった）。

**設定で名乗り直せるようにはしない**——PC名と違い、ここは権限の照合に使うので、
自己申告できると区分（§9.272）を名乗れてしまう。

#### ④ 説明文の生タグと、階層

`hintHtml()`は**エスケープしてから**`**強調**`だけを`<b>`へ変える（§9.222 ⑧。
マスタへ入れた文字列の中のHTMLがそのまま効かないようにするため）。だから
説明文へ生の`<b>`を書くと、**画面に`<b>`という字がそのまま出る**。
2つの`hint`と1つの`more`がそうなっていた。

**書き間違いは目で数えない**——`tests/test_hintlint.py`が`hint:`/`hintShort:`/
`more:`の文字列リテラル（**継続行の`+'…'`まで**）を読んで`<...>`を数える。
`ALWAYS`に入れてあるので、新しいマスタを足した瞬間から対象になる
——画面を開いて回る網では、開き忘れた1つが永久に残る。

アクセス権限の説明は900字ちかい1段落だった。常時出すのは**1文だけ**にし、
残りは「何を知りたいか」で3つに割って`<details>`へ畳む（`hintMore`）。
**編集窓では節を出さない**（§CLAUDE 8「窓の説明は一覧の説明と同じにしない」）
——窓に要るのは「いま決めることの一言」で、細かい話は各欄の`?`が持つ。

#### ⑥ 見本は「いま触っている1つ」だけを、同じ手順で

設定窓の左半分は`<label>`と中の欄を**自前で組み立て**、そのあとで
`previewWidget()`・`presentation()`を呼んでいた。組み立てが2箇所に分かれて
いる以上、測定画面の`layout()`が足す1手でも欠ければ見本だけが違う形になる
——実際、`placeholder`に`0 mm`を入れていたので、**単位を「内部」にすると
欄の中に`mm`が2つ**見えた（実物の`fieldEl()`は`placeholder`を持たない）。

`WL.opData.buildPreviewField(def)`を1本置き、`fieldEl()`→`opf-host`→
`applyPresentation`→`buildWidget`/`stripWidget`→`opout`→`placeUnit`→
`applyLook`と、`layout()`が1つの欄にする手順をそのままの順番でなぞる。

**`def.preview`を立てて呼ぶこと**——`values()`／`apply()`／`collect()`／
`paintAuto()`は**画面全体**から`[data-op]`・`[data-opauto]`を拾う（測定画面には
欄が1組しか無い前提）ので、印を持つと**開いているロットの記録へ見本の値が
混ざる**。`fieldEl()`が印を付けるかどうかだけを分ける。

隣の欄（§9.250 ⑤のゴースト）は**やめた**。利用者の言うとおり
「変更中の対象項目だけの再現で十分」で、しかもあれはマスタの行から自前で
組み立てていたので**本物と揃わない絵で幅を判断させて**いた。

#### ① 置き場は左サイドバーへ

§9.255 ①で上の帯へ1行に畳んでいたが、塊が増えるほど横スクロールになり
名前が省略記号で切れ、しかも**紙の高さをそのぶん削って**いた（紙が主役の
画面で面積の配り方が逆・§CLAUDE 1）。`.rp-nav`の中へ移して**縦に積む**と
名前がそのまま読め、削るのはロット一覧の高さだけで済む。

**畳まない**——掴んで紙へ落とす道具そのもの。畳んだのは**説明のほう**で、
`?`の浮き出しへ落とした（**消さない**——「押すだけでも出せる」は札の形からは
読めず、掴めない環境の唯一の道・§9.234 ①）。

**組み換えへ入るときだけロット一覧を開く**——畳んだままだと置き場ごと
消えてしまう。**覚え（localStorage）は触らない**で、抜けるときに元へ戻す。

#### 固定

`tests/test_hintlint.py`（6件・`ALWAYS`）／`tests/test_rbcells.js`（①②-b⑥⑦を追加）／
`tests/test_rplayout.js`（置き場の場所・縦積み・浮き出し）／`tests/test_opunit.js`
（⑥ 見本の単位）／`tests/test_oppad.js`（見本は1つ・記録に混ざらない）。
更新者IDを`localStorage`で渡す形へ、テスト27本を機械的に書き換えてある。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **`esc()`は「属性にも使う」ので引用符まで逃がす**（§9.276 ⑤、利用者の報告
  「表で組み替えて保存したら…再度読み込むと『表に組む』が押せなくなっていたり」）:
  以前は`textContent`→`innerHTML`任せで、**ブラウザのその直列化は`&` `<` `>`しか
  逃がさない**（文字節点では引用符に意味が無いので仕様どおり）。ところが
  **使い道の大半は`value="${esc(v)}"`／`title="${esc(v)}"`＝属性**なので、値に`"`が
  1つでもあると**そこで属性が閉じ、残りが黙って消える**。帳票ブロックのセル
  （§9.274）は`[{"kind": …}]`というJSONなので**`[{`まで切り詰められ**、開き直すと
  盤が屑1件になり「表に組む」が押せず、**そのまま保存するとマスタの中身まで壊れた**。
  置換方式（`&amp; &lt; &gt; &quot; &#39;`）に直したので、**中身に使ったときの
  見え方は1文字も変わらない**（`&quot;`は`"`として出る）。**インラインの
  イベント属性の中でJSの文字列を組み立てない**こと（`'`を逃がすと壊れるのは
  その形だけ）。**保存の口だけを見る網では捕まらない**——サーバーは正しかった。
  **窓を開き直して盤の中身**まで見る（`tests/test_rbcells.js` ①②-b）。
- **専用の画面（`special:*`）を汎用の描き直しで潰さない**（§9.276 ②、利用者の
  報告「説明文の長さを切り替えると、マスタ表示内容が消えます」）:
  `renderMaintList()`は`def.cols`から**汎用の一覧**を`#masterMaintList`へ無条件に
  書くので、そこへ自前の中身を描いている専用の画面は**丸ごと消える**。
  描き直しの入口は`refreshMaintScreen()`の1つで、`def.special`があるときは
  **`loadMaintInner()`へ戻す**（専用の画面の唯一の受け口。2つ目の対応表を作らない）。
  **網はふつうのマスタで試さないこと**——汎用の一覧そのものなので描き直せば戻り、
  直す前でも通る。説明の量は`#mmHintBadge`＋浮きメニュー（隣の`#uiSizeBadge`と
  同じ言語）で、**いまどれかはボタンに文字で出す**（畳んで現在値が読めなくなる
  のでは場所を空けた意味が無い・§3）。
- **更新者IDは名乗るだけ。答えるのは`current_login_id()`の1箇所**（§9.276 ③、
  利用者の指示「IDを書き換えられないように…ボタン化して接続状況確認と配線」）:
  ここは**この端末のログインID**で、アクセス権限マスタの照合・監査列・フィルタの
  持ち主が見ている値——打ち込めると**他人の名前で更新できて記録の意味が無くなる**。
  `<button>`にして押すと接続状況（§9.272）へ行く。読み取り専用にするぶん
  **出どころを増やす**（`os.getlogin()`は端末につながっていないプロセスで
  `OSError`。`getpass.getuser()`を足す。§9.208 ⑧のPC名と同じ作法）。
  `/api/whoami`も**同じ1箇所を通す**——2つ書くと、画面が名乗る値と権限の照合に
  使う値が食い違いうる。**設定で名乗り直せるようにはしない**（PC名と違い権限の
  照合に使うので、自己申告できると区分を名乗れてしまう）。
- **説明文に生のHTMLタグを書かない。長い説明は畳んで階層にする**（§9.276 ④、
  利用者の報告「`<b>`タグが見えていて正しくエンコードされていない」）:
  `hintHtml()`は**エスケープしてから**`**強調**`だけを`<b>`へ変える（§9.222 ⑧。
  マスタへ入れた文字列のHTMLがそのまま効かないための順番なので変えない）ので、
  生のタグは**字のまま画面に出る**。**目で数えないこと**——`tests/test_hintlint.py`が
  `hint:`/`hintShort:`/`more:`の文字列（**継続行の`+'…'`まで**）を読んで数え、
  `ALWAYS`に入れてあるので新しいマスタも自動で対象になる（画面を開いて回る網では
  開き忘れた1つが永久に残る）。900字の1段落は**リード文1文＋`hintMore`の節**
  （`<details>`）へ。**編集窓では節を出さない**（§8「窓の説明は一覧の説明と
  同じにしない」）——窓に要るのは「いま決めることの一言」で、細かい話は各欄の`?`。
- **設定窓の見本は`WL.opData.buildPreviewField()`の1本で作る**（§9.276 ⑥、利用者の
  指示「変更中の対象項目だけの再現で十分なので再現度をしっかり上げてほしい」）:
  以前は`<label>`と中の欄を**設定窓が自前で組み立て**ており、`placeholder`に単位を
  入れていたため**「内部」にすると単位が二重に出て**いた（実物の`fieldEl()`は
  `placeholder`を持たない）。組み立てが2箇所にあるかぎり、測定画面の`layout()`へ
  1手足すたびに見本だけが古い形になる。口は`fieldEl()`→`opf-host`→
  `applyPresentation`→`buildWidget`/`stripWidget`→`opout`→`placeUnit`→`applyLook`と、
  `layout()`の手順をそのままなぞる。**`def.preview`を立てて呼ぶこと**——
  `values()`／`apply()`／`collect()`／`paintAuto()`は**画面全体**から`[data-op]`・
  `[data-opauto]`を拾うので、印を持つと**開いているロットの記録へ見本の値が混ざる**。
  隣の欄（§9.250 ⑤のゴースト）は**やめた**（本物と揃わない絵で幅を判断させない）。
- **帳票の「出していない塊」は左サイドバー（`.rp-nav`）に縦で置く**（§9.276 ①、
  利用者の指示）: §9.255 ①で上の帯へ1行に畳んでいたが、塊が増えるほど横スクロールに
  なり名前が省略記号で切れ、**紙の高さをそのぶん削って**いた（紙が主役の画面で
  面積の配り方が逆・§1）。**畳まないこと**——掴んで紙へ落とす道具そのもの。
  畳むのは**説明のほう**で`?`の浮き出しへ落とす（**消さない**——「押すだけでも
  出せる」は札の形からは読めず、掴めない環境の唯一の道・§9.234 ①）。
  **組み換えへ入るときだけロット一覧を開く**（畳んだままだと置き場ごと消える）が、
  **覚え（localStorage）は触らず**抜けるときに戻す。
