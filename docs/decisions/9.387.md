# §9.387 刃組は「1本目に切るコイル」で組む／条の設計を必須にする（利用者の不具合報告）

利用者の報告:

> 刃組ガイダンスの不具合です。刃組間に処理する**すべてのロットを同時に
> カットするような組み方**になっています。やり方が違います。
> 刃組ガイダンスは、**1本目に切るものの情報で組んで**ください、1本目が分割
> ありのものだけ子ロットの情報を使って、今の条設計でやっているのと同じで、
> **かつ条設計が必須の流れ**で、その内容で刃組をしてください。
> **条設計済みの場合はそのまま開いて**、かつ再設計ができる配線もお願いします。

## 1. 何が壊れていたか

`bladeSeedLots()` は、**その停止の次から、次の刃組までの作業行を端から集めて**
条にしていた:

```js
for(const x of all.slice(from)){
  if(x.kind==='設備停止'&&stopLinkRowOf(x))break;   // 次の刃組まで
  ...
  if(originalWidth&&total+w*cnt>originalWidth+0.001)break;   // 元幅に載るまで
  lots.push({...});
  if(lots.length>=9)break;
}
```

つまり **別々に切るはずのコイルが、1本の元板に同居**していた。元幅に載るあいだ
（または9ロットまで）詰め込むので、2本目・3本目のコイルの条が1本目の元板に
並んでしまう。スリッターが1回の通しで切るのは**コイル1本**で、条はその1本を
割ったものなので、集める単位が最初から違っていた。

## 2. 直し方——組む単位と数える単位は違う

**関数を2つに分けてある意味を、片方が守っていなかった。**

| 関数 | 答える問い | 単位 |
| --- | --- | --- |
| `bladeSeedLots` | **何を組むか** | 次に切る**コイル1本** |
| `bladeRunPlan` | **何本流すか**（予定本数・1本目の材料） | 次の刃組までの**コイルの本数** |

`bladeRunPlan`（§9.382）は最初から「コイル1本ずつ」で数えていた（子は数えない）。
`bladeSeedLots` だけが「次の刃組まで全部」のままだった。

新しい `bladeSeedLots` は、停止の次から**最初の作業行（子でない行）1つ**を
`head` として取り、そこで止める:

- `head` に子がぶら下がっている → **その子ロットが条**（切断巾×条数）
- 子が無く分割ありと読める → 条にしない。`skipped` に数えて画面へ出す
  （親の幅は元コイル幅なので、条幅に使うと1本で元幅を使い切る）
- 分割なし → そのコイル1件（切断巾 × 内訳の本数。§9.209 分割が無くても図に出す）

板厚・元コイル幅も `head` の行から読む。`headLot`（1本目の親ロット）を
新たに返す——条の設計はこの1件で引く（§9.378 条の設計は親ロットで持つ）。

## 3. 条の設計を必須にする——止めるのは確定保存の1箇所

利用者と相談して**確定保存で止める**ことにした（図・刃組表・所要は見られる
ままにする）。刃組はこの並びで組むものなので、記録が無いまま確定すると
**測定は既定の並びで始まり、組んだ形と食い違う**。

止めるのは `saveCarriage()` の入口1箇所だけ。`designState()` が
「ロットが無い／未記録／記録と違う」のどれかを返したら、**理由と次の一手を
字で出して**断り、記録のボタンへ焦点を移す（§CLAUDE 4）。

**見ながら決める動線は壊さない**——先に図を出さない作りにすると、様子を
見て条を決めることができなくなる。断るのは「決めた形を残す」手前だけ。

## 4. 条の設計が済んでいれば、その並びで開く

`applySeed()` の最後で `applyDesign(headLot)` を呼ぶ。記録があればそちらを
正とする——予定の写しから組み直すと、**現場が決めた並びを黙って上書き**する
ことになる。記録のほうが新しい決定である。

## 5. 再設計（やり直し）の配線

- 記録と違うとき、記録のボタンの字を **「記録し直す」** に変える
  （「記録する」と同じ字では、上書きだと分からない）
- **「記録した並びに戻す」** を、記録と違うときだけ出す（§CLAUDE 4）。
  押しても**記録は消さない**——画面を記録の側へ合わせるだけなので、
  押し間違えても失うものが無い（§CLAUDE 5 取り消せない操作を主要動線に置かない）

## 6. 網（`test_bladeui` 106→109件）

**既存の網は古い挙動を固定していた**——`[C1, C2, N1]` を期待しており、
N1（2本目のコイル）が混ざることを「正しい」と書いていた。書き直した。

| 見るもの | 欠陥注入で戻したときの値 |
| --- | --- |
| 1本目のコイルだけで組む | `P2`（最後の行が1本目になる） |
| 1本目が分割ありなら子が条 | `[{"name":"P2","w":900,...}]` |
| 1本目（親ロット）を名乗る | `P2` |
| 記録と違うときは確定させない | `台車 A の刃組を記録します`（＝素通り） |

網を書くときに踏んだこと:

- **完了のボタンは右レールの「台車差分」の段の中**に居る（既定は「端部」）。
  段を開かずに押すと的が伏せられたままで、`page.click` が30秒で落ちる。
- **刃セットが未選択だと別の断りが先に出る。** 最初「〜でないこと」で判定して
  いたため、刃セットの断りでも素通りして**緑に見えていた**
  ——否定形の判定は、別の理由で止まったときに気づけない。**出た窓の題で
  見分ける**ように直した。
- 窓の器は `#appConfirmModal`（`#appConfirm` ではない）。
  閉じるのは **`#closeAppConfirm`**——`alertModal` は「やめる」を伏せるので、
  `#appConfirmCancel` を押しに行くと固まる。
- 控え（`st.lots`）を直に書き換えず、**本数の欄を打って**変える。直に書くと
  描き直しの配線を通らず、画面と控えが食い違ったまま測ることになる。
