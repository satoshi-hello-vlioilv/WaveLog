# §9.319 公差外は完了を止めない。止めるのは「誰が測ったか」だけ

設計書（`SCHEDULE_MODE_DESIGN.md`）に節が書かれないまま、`CLAUDE.md` の
規則としてだけ残っていた回。本文は下の「守ること」。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **公差外は完了を止めない。止めるのは「誰が測ったか」だけ**（§9.319-A、利用者の
  指示「測定値のエラーでNGがあっても測定は完了できるようにしてください」）:
  以前は`persistAndTransition('完了')`が`result.ng.length`で入口から引き返して
  いた。**公差外は「測った事実」**であって入力の誤りとは限らない——外れたまま
  完了して次の工程へ渡す判断は現場のもので、アプリが握ってはいけない（§4の
  「できないと書く」は**本当にできないとき**の話。ここは「してよいか」）。
  **止める代わりに、黙って通さない**——確認は**1つの窓にまとめる**
  （`measure-progress.js`のラッパーが未測定と一緒に出す。2回聞くと2回とも
  読まれなくなる。§5は確認を増やせという意味ではない）。**見出しは事実に
  合わせる**（公差外があるのに「測定していない項目があります」だけ出さない）。
  **通した完了は記録に残す**——`settings.completedWithNg`（件数と項目）。
  中身は`WL.measureReview.outOfTolerance()`の1箇所から作り（§9.163）、
  **直したら消す**（外れていた印が残ると、直した完了まで疑わせる）。
  **読める場所も一緒に作る**——押した瞬間のトーストは消えるので、データ一覧の
  列（`完了時の公差外`）に出す。**読める場所の無い印は、残していないのと同じ**
  （§4）。**既定では出さない**（§9.132。いま見ている一覧を勝手に1列増やさない）。
  **オペレータ／検査員の未選択は今までどおり止める**（誰が測ったか分からない
  記録は、あとから意味を持てない）。**文言も直すこと**——完了ボタンの`title`と
  `showValidationMessage()`が「完了できません」のままだと、止めていない理由を
  止めた理由として書くことになる（§CLAUDE 6）。固定は`tests/test_ngdone.js`。
- **異常位置判定は、ピッチだけでも保存できる**（§9.319-B、利用者の指示）:
  幅方向（`settings.defectLocation`）と長手方向（`settings.defectRoll`）は
  **別の鍵**で、紙も`defectSection()`が「長手だけでも出す」ように組んである。
  ところが**足元のボタンだけが幅方向しか見ておらず**、ピッチだけ入れた人には
  「判定できていないため保存できません」「この判定は帳票に出ません」と出て
  いた——**記録には入っているのに画面が嘘をつく**（§CLAUDE 6）。判定は
  `rollReady()`の1箇所（開いていれば入力欄、まだ書き戻されていなければ記録）。
  **何を保存したかを言う**（片方だけのとき「保存しました」だけだと、もう片方も
  保存できたと読める）。**「帳票から外す」は幅方向だけ**と`title`に書く（§4）。
  **②を触ったら足元も塗り直す**（`refreshRoll()`の尾）——押せるようになった
  ことに気づけない。固定は`tests/test_defectlink.js`。
- **紙の「異常位置判定」と「ピッチ判定」は別の塊**（§9.319-C、利用者の報告
  「印刷レイアウトでピッチ測定の場合、見切れが生じる…文字の大きさも小さすぎて
  見えない…異常位置判定とピッチ判定のブロックを分けてほしい…条の分割の図を
  最大化したい…異常位置判定（参考）となっていますが、異常位置判定に変更」）:
  1つの塊にピッチを差し込んでいたため、**器の高さは幅方向の図に合わせて決まり**、
  ピッチだけのロットでは背丈が違って`overflow:hidden`に切り落とされていた。
  塊を分ければ高さはそれぞれの中身から決まる（`rpFitRows()`が測る）。
  **文字は`.rp-field`（本文8.5px／ラベル8px）へそろえる**——判定の欄だけ
  6.5〜8pxで、同じ紙の中に読める大きさが2通りあった。
  **図は全幅、欄は下へ横に流す**（毎回読むのは図のほう・§CLAUDE 1。以前は右へ
  54mm＝紙の28%の欄を立てていた）。**候補の表は`table-layout:fixed`＋colgroup**
  ——ロール名は現場が決める文字なので、割りを決めないと長い1本で他の列が潰れる。
  **入切は塊の「紙に出す」に一本化**（`長手:`の印は廃した。塊を分けた以上、
  同じことをする入口が2つになる・§9.207）。**ただし旧い印は1度だけ読み替える**
  （§9.132）——読む人が居なくなると、**わざわざ「出さない」を選んだ紙が版を
  上げただけで黙って1枚増える**。`rpHiddenSet()`が`長手:なし`を「ピッチ判定を
  隠す」と読み、`rpShowBlock()`が**押されたその場で印を捨てる**。
  **捨てないと「出す」を押しても次に読むとまた隠れる**（§4。§9.274でここへ
  集約した「押しても何も起きないボタン」を別の道で作ることになる）。固定は`tests/test_rpdefect.js`
  ——**材料は自分で注ぎ込むこと**（候補の表はロールが1本も無いと出ない。条番号の
  札は条が広いときだけ出るので、本物の器の中へ1つ置いて測る）。
  **許容を広く取らないこと**——「同じくらい」で見ると0.5px違う実装が通る
  （実際に通った）。
