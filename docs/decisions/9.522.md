## 決めたこと

### 長い関数を増やさない網（`tests/test_funclen.py`）
- ファイルごとに「本数」「超過行数」の2つを `tests/fixtures/funclen_baseline.json` に固定し、
  **下げる方向だけ**動かせる（`--update`・`test_importlint`／`test_eslint` と同じ作法）。
- **関数の名前・行番号では固定しない**——切り出して名前が変わったり、上に1行足して位置が
  ずれたりしただけで落ちる網は、直す人を止めるだけになる。
- 網そのものが素通りしないことは**ファイルへ書かずに**確かめる（eslint は `--stdin`・§9.504）。
- 1段目（`--pure`）に入れた。eslint の探し方は `test_eslint.eslint_cmd()` の1箇所を使う。

### 切り出し方: 段の順番は副作用の順番そのもの
3本とも「1つの関数が多くの局所変数を共有しながら、いくつもの役目を順に行う」形だった。
段ごとの関数へ分け、**段のあいだで渡す物は文脈の1つ**にまとめた。

| 元 | 文脈 | 段 |
| --- | --- | --- |
| `renderGridInner` | 描画の文脈 `g`（`gridScope()` が作り、②③④が書き足す） | ①`gridScope` ②`gridColumnView` ③`gridColumnWidths` ④`buildGridTable` ⑤`makeGridRowBuilder`（`gridRowCells`・`gridSplitCell`・`gridDataCell`・`bindGridRowActions`・`bindGridRowPlan`・`bindGridChildFold`・`gridChildRow`） ⑥`mountGrid` ⑦`feedRemainingRows` |
| `bindFieldBuilders` | 盤1つぶんの文脈 `fb`（`fbContext()`） | `fbDrawCols`・`fbDrawChosen`（`fbChosenCellHtml`）・`fbDrawList`・`fbDrawInsp`（`fbInspHtml`）・`fbDrawTableBtn`（`fbAxesHtml`・`fbBindAxes`）・`fbDrawStack`・`fbDrawSeed`・`fbWireTools` |
| `_expand_plan_with` | 置く係 `_Placer`（`cursor` と `truncated` を持ち回る） | `_plan_entries`・`_finish_join_missing_note`・`_plan_anchor`・`_Placer.place`（`_frame`／`_comment`／`_ongoing`／`_timed`）・`_assign_work_dates`・`_copy_parent_times`・`_finalize_actuals` |

- **副作用の順番は1つも入れ替えない**（例: 列の窓は見出しを作ったあと・行を作る前、
  追い判定の世代は器へ載せたあとに読む／設備停止を終わらせる判定は計画外の実績を混ぜる**前**）。
  各本体の頭の説明にこの順番を書いた。
- 帳票ブロックの盤は、描き直しどうしが `fb.drawX()` 越しに呼び合うので、以前の
  「`const` の巻き上げが効かないので入れ物越しに呼ぶ」（`drawSeedRef`・`drawStackRef`）が要らなくなった。
- 本文は**範囲で移しただけ**（字下げだけ変えた）。閉包から取り出す名前は各関数の頭で `fb` から
  取り出す。取り出し忘れが同じファイルの別の変数へ黙って当たらないことも確かめた（同名の変数は0）。
- 説明の注釈（判断の根拠・§番号）は1つも落とさず、段の関数の側へ運んだ。

### 予定の展開は「出力が1バイトも違わない」で確かめた
画面と違ってサーバーの展開は出力そのものを比べられる。一時DBに全種類の行——作業・設備停止・
枠（届いた／未到達／直の名前違い）・申し送り・子ロット・固定開始（未来／過去で遅れ）・取消・
手入力の時刻・仕掛から消えた（突合あり／なし）・計画外の実績・稼働帯が尽きる行——を置き、
**時刻を固定した36通り（780行・警告132件）の展開結果を前後で比べて完全に一致**した。
環境に依らないよう、仕掛の在席の問い合わせ（`actual_match.lookup`）と負荷率の控えは固定の答えに
差し替えた。**欠陥を1つ注ぐと267行の差が出る**ことも確かめた（物差しが素通りしない）。
注ぐときは `.pyc` の置き場を毎回新しくした（同じ秒・同じ大きさの書き戻しで古いコードが動く罠・testing.md）。

## 見つけた不具合: 稼働帯が尽きたあとの枠・作業で展開全体が止まる

切り出しのために1行ずつ読んでいて見つけた。**元のコードで再現した**（切り出しで入ったものではない）。

- 置ける稼働帯が上限（5年・1830日）まで見つからないと、次に置ける時刻（`cursor`）が `None` になる。
  申し送りだけは `None` を考慮していたが、**枠は `target > cursor`、作業は `snap_to_working(None)` の
  `s <= cursor` で例外**になり、**その設備の予定の展開全体が止まる**——作業スケジュールが開けない。
- 起きる形は2つ: **固定開始の打ち間違い**（2040年など）と、**全曜日を休みにした稼働カレンダー**の
  後ろに枠がある場合。

直し方: `_Placer.place()` の入口の1箇所で「`cursor` が空なら置けない行」とし、置けない行を書く形を
`_unplaced()` の1箇所にまとめた。作業・設備停止はいままでの打ち切りと**同じ出力**、枠は開始が空・
空きは数でない（画面の `frameDetailHtml()` は「—」と書く）。どれも「〜日先までに置ける稼働帯が
ありません」の理由が1行付く。

### 決めたこと
- **骨組みの置き場は `templates/index.html` の `<template id="tpl-名前">`**、複製は `WL.template(名前)` の
  1箇所（`base.js`）。無ければ名前を言って止まる。**index.html は Jinja が描く**ので、骨組みの説明に
  Jinja の構文の字（波かっこ2つ・波かっことパーセント・波かっことシャープ）を書くと**起動画面ごと
  出なくなる**——移す途中で私が実際にやった（注釈に「その字を書かないこと」と、その字そのものを書いた）。
  `test_loadorder.py` §6 が「Jinja が読めること」「呼ぶ骨組みが在ること／置いた骨組みを誰かが呼ぶこと」を見張る。
- **マスタの1欄は型→組み立て関数の表**（`MM_FIELD_BUILDERS`）。型を足すときは表へ1行。**表は自分が
  持つ鍵だけで引く**（`Object.hasOwn`）——`constructor` のような継承の鍵を型と取り違えない。
  分岐の中の複数行の文字列は**字下げも HTML の中身**なので、字下げは元のまま移した。
- 予定の1行は、ボタン・右クリック・ダブルクリックが**同じ `caps`（この行でできること）**を読む。
  右クリックの群は作業導線の順（§9.399）のまま、群ごとの関数にした。
