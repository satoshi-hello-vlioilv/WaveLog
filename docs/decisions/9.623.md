# §9.623 帳票は同じ記録IDの新しい版（手元・共有）で描く——一覧が「完了」なのに帳票が「編集中」になるのを直す（利用者の指摘）

索引: [決定記録](README.md)｜前: [§9.622](9.622.md)｜関係: [§9.616](9.616.md)・[§9.621](9.621.md)

## 経緯（利用者の言葉）

> 測定実績のリスト上のフラグが「完了」状態のものを読み出して帳票表示させているのですが、帳票上のフラグ表示が「完了」と右上に表示される正しいときと「編集中」と表示される時があります。

## 原因

- 一覧（データ一覧・測定実績）は、手元と共有の新しいほうの状態を見せる（§9.616・`mergedRecords()`）。
- 帳票（`openReportView()`）は、編集モードではこの端末の保存（`reliableAll()`）をそのまま描いていた。

この端末に古い「編集中」の版が残っていて、共有に別の PC が完了した新しい版があると、次の食い違いが起きる。
- 一覧は「完了」と出す。
- 帳票は手元の版を描くので、札が「編集中」になる。紙の中身（測定値・オペレータ）も古い版のまま。

この端末に古い版が無い記録は、帳票が共有から取り込んで描く（`fetchRecordFromBackup()`）。だから正しく「完了」と出る記録と、「編集中」と出る記録があった。

## 直したこと

- 「記録IDの新しい版」を `WL.records.latestRecordById()` の1箇所にした（`records-store.js`）。
  - 手元と共有の1件を `remoteIsNewer()` で比べる。
  - 共有が新しければ、この端末へ取り込んで返す。
  - 測定画面を開く `latestRecordFor()` もこれを通る（答えは1箇所）。
- 帳票の `rpFreshen()` が、これを読む。
  - 一覧から開くとき（`openReportForRecord`）は描く前に確かめる。最初の1枚から新しい版になる。
  - 帳票の左の一覧で選ぶときは、描いてから確かめる。新しい版に替わったら描き直す（選ぶたびに待たせない）。
  - 閲覧・スケジュールモードは、もともと共有を読んでいるので通らない。

## 物差し（`tests/test_rpfresh.js`）

この端末に古い「編集中」の版を置き、共有に新しい「完了」の版を置いて帳票を開く。

| 項目 | 直す前 | 直した後 |
| --- | --- | --- |
| F1 右上の札が「完了」 | 「編集中」 | 「完了」 |
| F2 紙の中身も新しい版 | 手元の古い版 | 共有の版 |
| F3 帳票の一覧で選び直しても「完了」 | 「編集中」 | 「完了」 |
| F4 手元が新しいときは手元の版のまま | 手元の版 | 手元の版 |
