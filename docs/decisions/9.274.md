# §9.274 帳票ブロックを「セル」で組む——マトリクス・書式・紙からマスタへ（利用者の指示）

利用者の指示（5件）:

> 1. 帳票ブロックマスタをいじっても、帳票の紙レイアウトのところで見えている
>    データ、プレビューのデータは変わりません反映されていない感じです。
> 2. 帳票の紙レイアウトからブロックをダブルクリックしたら、帳票ブロックマスタに
>    移行するように配線してください。今のモーダルでできることは少ないので
>    マスタに繋いできちんと修正できるようにしたいです。
> 3. 帳票ブロックマスタに配置したデータの並べ方自由度が足りず困っています。
>    例えば板厚MIN、板厚MAX、板幅MIN、板幅MAX、板丈MIN、板丈MAXをブロックに
>    設定して表示させると、すべて横方向に、2段のカラムで並べられます。縦にも
>    項目を並べて、横も共通軸で並べたりすることでマトリクスも整形できるように
>    したいです。
> 4. 帳票ブロックマスタに配置したデータの書式変更もできるようにしてください。
>    数値の桁数、日付の書式、文字列を寄せる方向など。
> 5. 帳票ブロックマスタに説明書きみたいなものが出ているものがありますが、
>    ON/OFF、ONも短め、通常など調整できるようにしてほしいです。

#### ① 「反映されない」の本体は、並びに載せずに「出す」を押せたこと

再現して確かめたところ、**マスタの保存も、紙への伝わり方も、写しの捨て方も
動いていた**。壊れていたのは1点で、**あとから足した塊は「出す」にできなかった**。

  * `rpHiddenSet()` は「**並び（`order`）に載っていない自作の塊は必ず隠す**」
    （§9.217。マスタへ足した瞬間に全員の紙が1枚増えるのを防ぐため。判断は正しい）
  * `rpStage()` が並びを書き下ろすのは「**`order` が空のときだけ**」

この2つが噛み合うと、**一度でも配置を保存した紙**（`order` が埋まっている）では
あとから足した塊が永久に隠れる。「出す」を押すと `hidden` からは消えるが、
次に読むとき `rpHiddenSet()` が並びに載っていないことを理由に**また隠す**。
押しても何も起きないボタン（§4）そのもので、しかも黙って戻るので
「マスタをいじっても紙が変わらない」としか見えない。

**出すときは並びにも載せる**——「並びに載るまで出さない」の裏返しをそのまま
書く。出す・出さないの経路は3つ（塊の編集窓・組み換えの札・帳票レイアウト
マスタ）あるので、**判定も書き込みも `rpShowBlock()` の1箇所**を通す（§9.163）。
載せるのは**末尾**（§9.248 ③と同じ作法。前へ挿すと利用者が並べた順が押し出される）。

あわせて塞いだ写しの取りこぼしが3つ:

  * **`WL.reportBlocks.keys` が二重定義だった**——同じオブジェクトに同じ名前を
    2度書くと後の方だけが残るので、`rpBlockKeys()` は**一度も呼ばれない死んだ
    コード**だった。網が `keys()` で「自作の塊が候補に並ぶ」を見ていたので、
    **見ていたのはコードの既定の塊だけ**。役が違うので名前も分けた
    （`keys()`＝コードの既定／`allKeys()`＝既定＋自作）。
  * **候補の一覧（`fbCatalog`）を誰も捨てていなかった**——操業データの項目を
    足しても、盤の候補には次の再読込まで出ない。
  * **「紙全体で見る」の顔ぶれ（`rbState.blocks`）も捨てていなかった**——
    しかも**マスタの行を表示順に流していただけ**なので、出していない塊まで並び、
    設備ごとに変えた幅も効かない、刷り上がりとは別物の絵だった。
    いまは**本物の紙**（`WL.reportLayout.info(設備)`）を読んで組む
    （読めなければ今までどおり。fail-open）。

捨てるのは **`forgetReportCaches()` の1箇所**（§9.163）——別々に捨てると必ず
捨て漏れる（実際、3つのうち2つは一度も捨てていなかった）。保存だけでなく
**削除のあとも捨てる**（持ったままだと「消したのに紙に残っている」）。

さらに、**どの紙に効くのかを編集窓に書く**（`#rbWhere`）。
「◯◯の紙に出しています（幅 12/24 マス・高さ 中身なり）」／「まだ置かれて
いません。保存したあと帳票レイアウトで『出す』にすると紙に出ます」。
ここで幅を決めても紙が変わらない理由（＝紙の側が上書きしている）が読めないと、
利用者からは壊れているようにしか見えない（§CLAUDE 6）。

#### ② 紙の塊のダブルクリックは帳票ブロックマスタへ

塊そのもの（名前・載せる項目・書式・既定の幅と高さ）を直せるのはマスタだけ
なので、**ダブルクリックはそちらへ移る**（利用者の指示どおり）。開き方は
`rlyEditBlock()` の1本を通す——帳票レイアウトマスタからの行き来と同じ道で、
2つ持つと「紙からは開けるのにレイアウトからは開けない」が作れる。

**この紙だけの見え方**（この設備での幅・高さ・列幅・行列入れ替え・項目ごとに
分ける・落とした列）はマスタが持てないので、**入口は消さない**（§4）。
塊の**左上**に小さな「紙」ボタンを置いて今までの窓を開く——縁の掴み（右・下・
右下）と重ならない位置なので、§9.226 ③で浮き帯を外した理由（掴む的が消える）
には当たらない。窓の側にも「帳票ブロックマスタで直す」を置き、
**どちらで直すのかを毎回思い出させない**（§2）。

#### ③④ 1つのマス（セル）が持つものを増やす

利用者の例（板厚MIN／MAX・板幅MIN／MAX・板丈MIN／MAX）は、**共通の軸を持つ表**
にしたい、という話。今まで1マスが持てたのは「ラベル・出どころ・横×縦のマス数」
だけで、**軸の見出し**——値を持たず文字だけ出すマス——が無いので表が組めない。
共通の軸で並べるとラベルが見出しと二重になるので、**ラベルを出さない**も要る。

    種別  value ＝ ラベルと値／head ＝ 見出し（文字だけ）／blank ＝ 空き
    ほかに showLabel（ラベルを出すか）・align（寄せ）・format（書式）

**書式は `WL.cellFormat`（`base.js`）を通す**——一覧・実績データ・作業予定表と
同じ道具。帳票だけ2つ目の整形器を持つと、同じ「小数2桁」が画面によって違う
結果になる（§9.163）。**整形に失敗したら生の値**（`value()` がそう作ってある）。
寄せは `@layer utility` の `.al-*`（§9.239 ④）——一覧と同じ1組を使う。

**保存の形は今までの行の形のまま**（§9.226 ⑥）で、新しい持ちものを1つでも
使う塊だけ**JSONの配列**へ切り替える。読む側は `[` で始まるかどうかだけで
見分ける。こうすると**触っていない塊の保存値は1バイトも変わらない**
（`|1` も `x1` も足さない）。壊れたJSONは行の形として読み直す（黙って空にしない）。

盤（`field-builder`）は3つ足した:

  * **見出し**ボタン（値を持たないマスを1つ足す。足したら書ける状態にする）
  * **選んだマスの設定**（種別・ラベル・寄せ・書式）——器は常に置いて中身だけ
    入れ替える（選んでも盤が1pxも動かない・§9.227 ②）。**横／縦のマス数は
    ここに出さない**（盤のマスが既に持っており、同じ数を2箇所に置くと片方だけ
    直した状態が作れる・§CLAUDE 8）
  * **表に組む**——**軸は候補が名乗る**（`field_catalog` の `row`/`col`）。
    ラベルを空白で割って推測すると、名前に空白を含む項目で必ず崩れる。
    軸を名乗らない候補は表に組めない、と**画面が言える**のもこの印があるから
    （§4）。作るのはふつうのマスの並び（見出し＋ラベルを出さない値）だけなので、
    **組んだあとは手で直せる**——魔法の状態を作らない。

#### ⑤ 説明の量は3段（通常／短め／出さない）

`hintHtml()` の**1箇所**（§9.163）——説明を出す場所は十数箇所あるので、そこへ
足すと足し忘れた欄だけが長いまま残る。置き場は**この端末**（読み方の好みなので
PCごとに違ってよい・§9.199／§9.242 ⑥）、**既定は今までどおり通常**。

**「短め」は最初の1文だけ**（`。` まで）——文の途中で切ると意味が反転しうる
（「〜しないでください」の前半だけが残る）。**`?`（くわしい説明）は消さない**
——押したときだけ開く、場所を取らない入口なので、消すと短くした人が全文へ
辿り着けなくなる（§9.234 ①）。専用の画面（`special:*`）は描き直さないと
変わらないので、**「出さない」だけはCSS（`html[data-hint]`）でも効かせる**。

#### 固定

`tests/test_rbcells.py`（19件・保存の形と語彙）と `tests/test_rbcells.js`
（18件・盤と紙と配線）。**同じ例**（`tests/fixtures/report_cells.json`）を
サーバー（`parse_content`/`dump_content`）と画面（`WL.reportCells`）の両方へ
通す——読み方が2通りあると、盤で組んだ形と紙が食い違う（§9.245）。

**盤のDOM越しに見ないこと**——盤は隠し欄を wiring 時にしか読まないので、
そこだけを見る網は**盤が読み直さない形でも「0件」で通る**（実際にそうなった）。
`WL.reportCells` を公開して口で確かめる。

4つの欠陥（並びに載せない／見出しのマスを値として描く／いつもJSONで書く／
説明の量を効かせない）でそれぞれ落ちることを確認済み。
