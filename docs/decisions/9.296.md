# §9.296 紙の列幅を測るときは「作業以外の行も束ねない形で」測る

設計書（`SCHEDULE_MODE_DESIGN.md`）に節が書かれないまま、`CLAUDE.md` の
規則としてだけ残っていた回。本文は下の「守ること」。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **紙の列幅を測るときは「作業以外の行も束ねない形で」測る**（§9.296、
  §9.294 ④の追補）: 束ねた題名は列の幅を決めないが、**固定列（区分・日付・
  時刻…）は実際に刷られる**ので、行ごと測定から外すとその列が痩せる
  （実測: 「設備停止」の札が「予定」より2文字長く、1セル切れた）。
  題名だけ外して残りはふつうの行として測る。
  **見切れは「中身が器の外へ出ているか」で見ること**——`td.scrollWidth`は
  `table-layout:fixed`のセルで**max-contentの幅**を返すことがあり、中の札が
  収まっていても溢れたと報告する（実測: 29.9px＋余白4.7pxで器35pxに収まって
  いるのに`scrollWidth`は44）。子要素があるときはその右端と内容boxを
  突き合わせる。
- **マスの持ちものを紙へ運ぶ口は`rpCellTuple()`の1つ。1つも落とさない**
  （§9.296 ③、利用者の報告「帳票ブロックマスタで、ラベルを上下に変更しようと
  してボタンを押しても、変化が全くなく、プレビューも横のまま変わらないです」）:
  §9.292 ⑤で足した`stack`は、保存・盤の札・サーバーの往復まで全部動いて
  いたのに、**`rpCellTuple()`が`cell()`へ渡すオブジェクトに入れ忘れて**いた
  ——**設定は効いているのに見本も紙も1pxも変わらない**（いちばん気づきにくい
  壊れ方。§9.113／§9.212 ②と同じ形で5度目）。マスに持ちものを足したら、
  **ここと`fbCell`／`fbText`／`parse_content`／`_rich()`を必ず揃える**。
  **網は`reportSectionHtml()`へ手で組んだタプルを渡さないこと**——あの口は
  タプルをそのまま受けるので、**運ぶ側が落としていても通る**（実際に通って
  いた）。`WL.reportStat.sectionHtml()`（マスの配列を受ける1本）を通す。
- **一覧の文字は`--tbl-fs`。画面ごとに散らさない**（§9.296 ①、利用者の指摘
  「実績データの表も、仕掛一覧と同じ文字サイズを使用してください。少し小さい
  ような感じがします」）: `.ac-list`だけ`--fs-sm`(12px)で、同じ「一覧」なのに
  2px小さかった。**行の高さは行の中の文字から作る**（§9.90）ので、
  `--tbl-fs`へ変えれば`--row-h`も一緒に動く。印は`--tbl-fs-mark`、行内ボタンは
  `--row-inner-h`（§9.112。`--row-h`は外寸なのでそこから作るとはみ出す）。
- **常時載っているカードは「頻度 × 重要度」で面積を配る**（§9.296 ②、利用者の
  指示「品質データ分析のカードは文字や表示エリアが広く大きいので周りのサイズや
  余白感に合わせて調整してほしい。また、折りたためるように」）: グラフを作るのは
  時々で、下の一覧は常に見る（§CLAUDE 画面基準 1）。題は`--fs-title`（画面その
  ものの題）から`--fs-base-sm`（準見出し）の役へ移し、余白は`--pad-dialog`から
  `--pad-card`へ。**畳んだら帯だけ残す**——入口が消えないので、いつでも開き直せる。
  **いまどちらかはボタンの文字が言う**（§3）。置き場はこの端末（読み方の好み・§9.199）。
