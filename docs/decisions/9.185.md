# §9.185 時刻未定の案内と、追加後の時刻の取り直し（利用者の指示）

利用者の指示: 「スケジュール追加時に正しく時間などの計算も反映されて
ほしい。もしうまくいかなくて未定が残ってしまった場合、未定が出たら再計算を
押すことをアナウンスしてほしい」。

- **書込のあとは時刻を取り直す。** 予定を1本足す・外す・並べ替えると、
  **その後ろの予定の時刻が全部動く**。楽観的更新で作った行は
  `plannedStart`を持たないので、取り直さないと足した行は「未定」のまま、
  後続は古い時刻のまま残る。`runWriteQueue()`が「時刻の動く操作
  （add/delete/reorder/update）」を通したかを覚えていて、キューが空に
  なったところで`loadPlan()`する。覆いは出さない（行は既に出ている）。
- **未定が残っていたら言う。** `#scUndecided`が件数・ロット番号・打つ手を
  文字で出す。行にも「未定」と出るが、行は下へ流れるので上でまとめて言う。
- **理由で分ける。** ①サーバーへ反映中（待てば決まる＝案内しない）
  ②稼働カレンダーに置けない（⚠に理由が出ているのでそちらを読ませる。
  「再計算」では直らないのでボタンを出さない）③それ以外（「再計算」で直る）。
- ボタンはヘッダーの「再計算」と同じ処理を呼ぶ（同じことをする道を2つ作らない）。

固定は`tests/test_scundecided.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **書込のあとは予定の時刻を取り直す**（§9.185）: 予定を1本足す・外す・
  並べ替えると**その後ろの時刻が全部動く**。楽観的更新の行は`plannedStart`を
  持たないので、取り直さないと足した行は「未定」のまま・後続は古い時刻のまま
  残る（実機で「追加しても時間が計算されない」）。**未定が残ったら件数と
  ロット番号と打つ手を文字で出す**（`#scUndecided`）。理由で分け、
  **反映待ちは案内しない**（待てば決まる）、**カレンダーに置けないときは
  「再計算」を出さない**（押しても直らない）。固定は`tests/test_scundecided.js`。
