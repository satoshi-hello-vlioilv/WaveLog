# §9.57 作業可否フラグを予定ロット全件へ行き渡らせる

§9.51で入れた作業可否フラグが、予定の一部で「?」(判定できない)のまま
残っていた。原因は**索引の作り方**にある。

**根本原因**: 索引は`/api/table`に`page_size=5000`を渡して仕掛を一度に
読み切るつもりだったが、`backend/routes/tables.py`の

```python
size=min(500,max(50,int(request.args.get('page_size',200))))
```

が**上限500件に切り詰める**。エラーにはならず黙って500件だけ返るため、
仕掛が2000件あっても索引には先頭500件しか入らず、それ以降のロットは
どうやっても引き当てられなかった。「スケジュールへ入れたロットは仕掛一覧の
表示からは除外される」仕様(§9.44)と重なって、画面上の一覧を見ても
確かめようがない形になっていた。

**対処**: 索引作りをページ送りにする(`loadWorkableIndex`)。

- `WORKABLE_PAGE_SIZE=500`(サーバー上限に合わせる)、
  `WORKABLE_MAX_PAGES=40`(20000件ぶんの歯止め)。
- 先に`plannedLotKeys()`で**予定に載っているロット番号の集合**を作り、
  ページを1枚読むたびに見つかったものを集合から消す。空になった時点で
  打ち切るので、実際の往復は「予定ロットが出そろうまで」で済む。
  最終ページ(`rows.length<PAGE_SIZE`)または`scanned>=total`でも止める。
- それでも残ったロットは`fillMissingLots()`が絞り込み検索(`filters`の
  `eq`、同時3本)で1件ずつ確定させる。ここで見つからなければ
  **仕掛に無いことが確定した**という意味で空文字を入れ、「?」ではなく
  「不可」として扱う。上限は`WORKABLE_FILL_LIMIT=60`件。

索引作りは§9.51のとおりバックグラウンド(`scheduleWorkableWatch`)で走り、
結果は`applyWorkableFlags()`がセルだけ書き換える。`renderTimeline()`は
呼ばないので、操作中に行が作り直されることはない。

`window.scheduleWorkableState()`は`{watching,indexSize,fetchedAt,equipment,
pages,scanned,total}`を返し、何ページ辿って何件走査したかを検証から
確かめられる。

**実測**(仕掛2007件・予定312件): 「?」0件(可211/不可101)、索引2007件、
4ページ+個別補完で`/api/table`10回、バックグラウンド3.1秒。修正前は
索引500件で「?」が残っていた。
