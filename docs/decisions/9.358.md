# §9.358 網の言い切りは「幅」と「自分が作った行」で見る。最初の描画は1回で測る

利用者の指示:「**最終確認のフルスイートを先に実施して完全に穴をふさぐことが
できていることを確認してください。**」

結果は **6131/6133 PASS（落ち2件）**、所要2030秒。§9.356で入れた自動の切り分けが
働き、2本とも「**単独では緑（順番・状態への依存）**」と分類された。ここでは
「フレークだった」で片付けず（§9.200）、**落ちる仕組みを2本とも言えるところまで**
辿った。どちらも**製品側は正しく、網の言い切りが強すぎた**。

## ① test_scsplit ——「伸び125分 / 親の見積120分」

予定の起点は**展開のたびに`now`から引き直し、5分刻みへ切り上げる**
（§9.198、`backend/schedule_calc.py` の `ANCHOR_ROUND_MIN=5`）。網は

- `beforeEnd` = 追加前の最後の予定終了時刻
- `afterEnd`  = 追加後の最後の予定終了時刻

を**別々の問い合わせ**で取り、その差が親の見積と**等しい**ことを見ていた
（`Math.abs(grew-est)<1`）。ところが2回の問い合わせのあいだに刻みの境目を
またぐと、**起点が5分進み、ぶら下がる予定の終了時刻がそろって5分後ろへ動く**。
＝ 伸びは「親の見積 **+0〜5分**」になる。切り上げなので**後ろへだけ**動く。

§9.284（`test_scframe`）とまったく同じ形で、あちらは分まで（`slice(0,16)`）で
比べていた。**「いま」から引き直す値を、時刻の一致で見ない。**

直し: `grew>=est && grew-est<=5`。**幅の根拠を網に書いた**——本物の失敗
（子の数だけ伸びる）は子2件ぶんで**+240分**なので、ゆらぎの5分とは桁で離れており、
あいだの値で取り違えることがない。

## ② test_wkfast ——「最初の描画に『?』が無い」

`{"is-unknown":1,"is-ok":33,"is-ng":11}` で落ちた。§9.67が保証しているのは
**「仕掛一覧から投入した行は、投入時に保存した残仕掛設備ｺｰｽだけで確定する」**
ことであって、**予定に載っている全部に「?」が無い**ことではない。保存を持たない
古い予定（他の網がAPIで直に作った行など）は最初の描画で「?」になり、
**そのすぐ下の「保存が無い古い予定も裏の取り直しで解消される」がまさにそれを
見ている**——2つの言い切りは同時には成り立たない。単独では保存の無い行が
たまたま0件だったので通っていた。

**この直前の`pages===0`と同じ言い過ぎが、1つ隣に残っていた**（§9.356で
`pages===0`は直したが、同じ段落のもう1行を見落とした）。**同じ理由で誤っている
言い切りは、たいてい隣にもある。**

直し: **この実行で投入した行**（`data-id`で引く）だけを見る。保存を持つ行が
「?」になれば、残りが何件あっても落ちる。

## 測る場所が違うと、注入しても素通りする

直した網を**欠陥注入で確かめた**（`storedCourseOf()`が保存値を読まないようにする）。
——**素通りした。** 45行すべてが「?」なのに、投入した行だけは「?」でなかった。

原因は**測っている時点**。`firstPaint`（内訳）と、投入した行の状態とを
**別の`page.evaluate()`**で取っていたため、そのあいだの数ミリ秒で**裏の取り直しが
終わって**しまい、「最初の描画」ではなく「取り直したあと」を見ていた。

直し: **1回の評価で両方を持ち帰る**。以後は注入で投入3件すべてが「?」になり、
正しく落ちる。**「最初の」を測る網は、2回に分けて取らない。**

なお注入そのものも一度空振りした——**起動中のサーバーは、その起動のあいだ
渡すファイルを差し替えない**（§9.255）。JSへ欠陥を入れたら**サーバーを起こし直す**
まで反映されない。配信されている中身を`curl`で確かめてから測ること。

## 決めたこと

- **「いま」から引き直す値は幅で見る。幅の根拠（何分の刻みか）を網に書く。**
- **網の言い切りは「自分が作った行」に限る。** 他の網が残した行まで巻き込む
  言い切りは、通しでだけ落ちる。
- **「最初の描画」は1回の評価で測る。** 分けて取ると、裏の取り直しが先に終わる。
- **注入で確かめる前に、注入した中身が配信されているかを確かめる。**
