# §9.139 ②の測定表を「丈位置×条」の1つの表にする（実装）

§9.136で決めた形の実装（骨子の3/5）。

以前は**2枚**あった——「いま選んでいる丈位置の条を縦に並べた帯」
（`stripColumnsHtml`）と「他の丈位置を見るための丈位置くらべ」
（`lengthCompareHtml`）。同じ値が2箇所にあり（§9.129に反する）、しかも
**動き方が違った**——丈を切り替えると帯は中身が入れ替わるのに、くらべは
列の色だけが動く。どちらを見ているのかを、その都度組み立て直す必要があった。

1つの表にすると、切り替えは「どの列がアクティブか」だけになり、
**表そのものは動かない**。

- **横＝丈位置、縦＝条。** 丈は最大10列（縦割9＋尾）なので横は足りる。
- **条は1列で40行まで。2段に折らない**（横は丈位置が使う）。
- 列見出しが丈位置の選択を兼ねる。**セルを押しても、その列がいま測る列になる**
  ——押した先が別の列なのに前の列へ値が入ると、入れた本人にも気づけない。
- 判定の印（OK/NG）は**いま測っている列だけ**。全列に出すと最大400個並んで
  印そのものが背景になる。公差外の色は`judgeInput`が全列へ付けるので、
  外れていることはどの列でも分かる。

#### `#lengthPos`は残す

見えている一覧は②から降ろしたが、**`select`そのものは残す**。丈位置を
持っているのはこの`select`で、`PageUp/PageDown`・完了前の確認の「直す」・
帳票まで全部がこれを見る。**見えている一覧を消すことと、状態の置き場を
消すことは別**（§9.124の`#measureType`とチップの関係と同じ）。

#### 列の幅で2回踏んだ

- `width:100%` … 丈位置4つで**1セル222px**。`1234.56`（実測63px）の3倍以上。
- `width:auto` … 今度は`input`の**既定の見た目幅（約20文字）**がmax-contentを
  決めてしまい、190px級に広がる。`table-layout:fixed`と併せると逆に器より
  狭く縮み、**1セル41px**まで潰れた。

決着は「`fixed`＋`width:100%`＋**列数から上限**」。列数はロットで変わるので
JSが`--mx-cols`で渡す。余りは右に空ける——器いっぱいに引き伸ばすのは
「中身から決める」（§9.130）の逆。

固定は`tests/test_msteps.js`（行数・列数・丈位置の列・セルの幅の下限）と
`tests/test_mcore.js`（板厚が3行）。
