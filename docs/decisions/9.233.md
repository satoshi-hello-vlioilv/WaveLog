# §9.233 条の設計の重なり・自動で入る値の見せ方・単位の置き場・添え書き・上部帯・フラットネスの見出し（利用者の指示）

利用者の指示（4群）:

> １）条の設計の表示に関して 異常位置判定を行うと、異常位置の図の表示のラベルと、
> 「異常の印・出す」のバッジが別の表示と重なってしまいきれいに収まっていません。

> ２）操業データ項目マスタについて ①自動で入る値についても、選んで設定できるように

> 多いです。不具合修正してください。③追加したばかりの「母材」のところだけ、単位を内部に
> 入れ込んで設定したときにデータ入力を右寄せにすると単位と被ってしまいます。④単位を
> 設定するときに位置を選べますが、選択したUIによっては、単位の位置のずれや単位が出ない

> ４）入力内容のフラットネスを選んだときの右側のフラットネス入力欄の上部の表示やボタン類が

#### ① 条の設計: 印は流れの中へ置き、操作の行は縮ませない

重なりの原因は**2つ**あり、片方だけ直しても絵は変わらない。

1. **印を条の帯に重ねていた。** `.split-visual-block.is-defect`の中で
   `.svb-defect`が絶対配置に近い置き方をしており、条の番号・幅のラベルの上に
   乗っていた。**印は流れの中へ置く**（`flex-direction:column`＋`gap`）
   ——重ねてよいのは「その場所そのものを指す物」だけで、分類名の札は違う。
2. **縦のflexで操作の行が縮んでいた。** `.split-visual-actions`が既定の
   `flex-shrink:1`のままだったので、カードが低いと**箱だけが中身より短くなり**、
   `overflow`を持たないぶん中身が下の行の上へ描かれていた。
   `flex:0 0 auto`＋`min-height:var(--ctl-h-sm)`で縮ませない。
   器の側（`#splitCard>.split-visual`）は`flex:1 0 auto;min-height:0`。

**同じセレクタが2箇所にある**ことに注意（§9.129と同じ罠）——
`.split-visual`は`35-split.css:84`と`#splitCard>.split-visual`の2つがあり、
**詳細度の高い後者が勝つ**。前者だけを直しても実測値は1pxも動かない。

固定は`tests/test_splitlive.js`。**数や有無を見る網では捕まらない**
（どちらも要素は在る）ので、器と中身の実寸（`scrollHeight`と`clientHeight`）と、
印とラベルの矩形の重なりで見る。**印は自分で付けること**——検証用データに
異常の印がある保証は無く、「無ければ素通り」の書き方だと直す前でも通る。

#### ② 自動で入る値も「選んで設定できる」

母材の参考値3つ（元幅（実績）・屑幅（両耳合計）・計算全長（参考））は
`<output>`で、値は画面が入れる（§9.232）。**打ち込む部品は要らないが、
どう見せるかは選べる**——`WIDGET_FAMILIES['output']`に
`プルダウン`（＝枠つき・今までどおり）／`文字だけ`／`強調`の3つを置いた。
値を持たない欄なので**器（`.opf-widget`）は被せない**——被せると押せる部品に
なり、押しても何も起きない（§4）。印（`data-opout`）を器へ置いてCSSが読む。

**効かなかったのは`valueEl()`が`<output>`を見ていなかったから。**
`valueEl()`は「**書ける**欄」を返す口（`setValue()`／`syncWidget()`が書き込む
先）なので、ここへ`<output>`を混ぜてはいけない。代わりに口を2つ足した:

- `outputEl(host)` … 値は持たないが画面に出ている欄
- `displayEl(host)` … いま**見えている**操作面（器があれば器、素のプルダウン
  `.opf-plain`なら`<select>`、それも無ければ`<output>`）

単位の置き場・逃げ場の幅・見せ方は**すべて`displayEl()`を基準にする**。
別々に引くと「セグメントだけ単位が出ない」のような穴が残る。

寄せも`<output>`では効かない形だった——`display:flex`の器なので
`text-align`は動かない。`justify-content`で当てる。

#### ③ 逃げ場の幅は「器の変数」で配る

単位を欄の中へ重ねる（`内部`）ときの`padding-right`は、以前
`.measure-shell .selectors>label[data-opunit="内部"]>input{…}` と
`.op-prev-field .opf[…]` の**2つの器を名指し**していた。母材は器の名前が違う
（`.material-grid`）ので1つも当たらず、**右寄せにした値が単位の上に乗っていた**。
**器を1つ足すたびにCSSを書き足す作りだと、足し忘れた器だけが静かに壊れる。**

いまは`applyPresentation()`が`--opf-pad-r`を器へ渡し、「素の欄も器の高さを
読む」1本の規則がそれを使う。▼の場所（実測16px）が要るかどうかは
**いま見えている操作面**でしか分からないので、幅の判断はJSが持つ。

同じ考え方で、マスタが差配している欄には**`opf-host`という1つの印**を付ける
（`layout()`・`fieldEl()`・設定窓の見本の3箇所）。高さ（`--opf-h`）・角丸・
文字も`opf-host`が配るので、母材でも意匠の「大きさ」の軸がそのまま効く
（以前は`.material-grid`が`--ctl-h`固定で、大きさを変えても何も起きなかった）。

**`[data-opunit="内部"]>select,>input`に`>output`を足すのを忘れないこと**
——挙げ忘れると自動配置が次の段へ回し、**単位だけが1段上に浮く**。

#### ④ 単位は「見えている操作面」のとなりへ置く

以前は**2箇所で別々に組み立てて**いた——自由項目は`fieldEl()`が`<label>`の
innerHTMLへ、組み込みの欄は`syncBuiltinUnit()`が末尾へ。どちらも
**器（`.opf-widget`）が後から末尾に足される**ことを知らないので、

- 「外下」… 単位が器の**上**に出る（欄と単位のあいだにボタンが挟まる）
- 「内部」… 1pxの裏方の`<select>`に重なり、**一度も見えない**

という形で出ていた。置くのは`placeUnit()`の**1箇所**で、基準は`displayEl()`。
**同じ形なら触らない**（`layout()`は畳み・条件で何度も走るので、毎回
入れ替えると読んでいる最中に単位が瞬く）。

**手打ちを許したプルダウンも「内部」に重ねられない**——`<select>`は器の裏へ
回って1pxになり、見えているのはコンボボックスの入力欄だから。判定は
サーバーの`unit_in_ok(widget, free_text)`の1箇所で、画面は
`unitInBlocked`／`unitInFreeTextBlocked`の一覧を引くだけ（§9.163）。
**保存値は残す**ので、手打ちを外せば「内部」が復活する。

#### ⑤ 出どころの添え書きは、置き場を選べる1行

内径は仕掛データの`ｺｲﾙ_内径目標`から初期値を選ぶ（§9.204）。その添え書き
（`.prep-from`）が`white-space:normal;overflow-wrap:anywhere`で、①準備の1列
（実測124px）に対して2行になり、そのぶん欄が下へずれて隣と高さが揃わなかった。

- **折り返さない**（入らなければ省略記号。全文は`title`）
- **コンパクトに**（`仕掛から 508` → `仕掛 508`）
- **置き場を選べる**（`欄の下`／`名前の横`／`出さない`）

置き場は操業データ項目マスタの`[出どころ表示]`。**既定は`欄の下`**＝今までの
見え方（既定を変えると、設定を触っていない現場の画面が黙って変わる）。
**添え書きを持つ項目にだけ欄を出す**——`SOURCE_NOTE_KEYS`をサーバーが答える
（どの欄が仕掛から値を引くかは、引いている側しか知らない）。

「名前の横」のために、組み込みの欄の名前も`<span class="opf-name">`で包む
（`renameBuiltinLabel()`）。自由項目は`fieldEl()`が最初からそう作っており、
**組み込みの欄だけが素のテキスト節点**だった。包むのは1度だけで、書き換えるのは
先頭のテキスト節点だけ（中に添え書きが入るので`textContent`ごと差し替えない）。
横並びの印（`is-with-note`）は**移した側（JS）が付ける**——`:has()`で拾うと、
当たらなかったときに誰も気づけない。素の`.opf-name`には当てないので、母材の
「屑幅（両耳合計）」のような長い名前は今までどおり折り返せる。

`WL.opData.sourceNotePlace(builtinKey)`が置き場を答え、`layout()`のあとに
`WL.innerDiameter.refresh()`を呼んで当て直す（マスタを直しても画面が変わら
ないと「効いていない」としか見えない）。**読めないうちは既定**を返す
——空を返すと、マスタが届く前の1瞬だけ添え書きが消える。

#### ③（3群）「母材・丈は手入力です」は入れる場所のすぐ上

上部帯（`#mstepNote`）へ出していたため、母材のときだけロット・製品・
測定表の形・判定公差が押されて**33〜70px切れていた**（実測1366px）。
母材の題（`.mat-block-title`）の中の`#materialManualNote`へ移す。
文言は`measure-steps.js`の1箇所（`MATERIAL_NOTE`）が書き、
`paintMaterialNote()`が`paint()`と`applyRightLayout()`の両方から呼ばれる
（入力内容の切り替えは段の描き直しを伴わない経路がある）。

#### ④（4群）フラットネスの見出しも1行

「全条を〇/△/×にする」の3つのボタンと凡例で`.editor-head`が2行になり、
そのぶん測定表が縮んでいた。記号そのものを札にした1つの群
（`.flat-pick-group`）へまとめ、ラベルは`title`と`aria-label`が持つ
——**測定表の縦は条数ぶんの入力面に使う**（利用者の指示）。

固定は`tests/test_opunit.js`（②③④⑤）・`tests/test_msteps.js`（3群・4群）・
`tests/test_splitlive.js`（1群）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **「印刷」は画面ごとに1つ。判定は画面が登録で名乗る**（§9.300 ①）:
  ヘッダーの「画面を印刷」（`#printCurrentView`。品質データ分析が作って
  `.global-actions`へ置いたまま残る汎用の操作）を隠す規則が
  `body.rp-mode,body.qa-mode`と**画面の名前を並べた形**だったため、あとから専用の
  印刷を持った作業スケジュールだけが静かに二重になっていた（上の行に「画面を印刷」・
  操作列に「印刷」。§9.233 ③と同じ形）。いまは`WL.registerView({ownPrint:true})`で
  **画面が名乗り**、`enterView()`が`body.view-own-print`を立て、CSSはその1本だけを
  見る。**画面の名前をCSSへ並べないこと**（品質データ分析だけは画面の登録簿に
  載っていない＝一覧の中の状態なので名指しのまま）。**網は「無いから通った」を
  作らないこと**——その端末で品質データ分析を開いていなければボタン自体が無いので、
  無ければテストが作ってから測る。
- **単位を置くのは`placeUnit()`の1箇所、基準は「見えている操作面」**
  （§9.233 ④、利用者の指摘「選択したUIによっては、単位の位置のずれや単位が
  出ないということがある」）: 以前は**2箇所で別々に組み立てて**いた
  ——自由項目は`fieldEl()`が`<label>`のinnerHTMLへ、組み込みの欄は
  `syncBuiltinUnit()`が末尾へ。どちらも**器（`.opf-widget`）が後から末尾に
  足される**ことを知らないので、「外下」は器の**上**に出て、「内部」は1pxの

  （器があれば器／素のプルダウン`.opf-plain`なら`<select>`／それも無ければ
  `<output>`）。**同じ形なら触らない**（`layout()`は何度も走る）。
  **手打ちを許したプルダウンも「内部」に重ねられない**——判定はサーバーの
  `unit_in_ok(widget,free_text)`の1箇所で、画面は`unitInBlocked`／
  `unitInFreeTextBlocked`の一覧を引くだけ（§9.163）。**保存値は残す**
  （手打ちを外せば復活する）。固定は`tests/test_opunit.js`。
- **`valueEl()`は「書ける欄」。画面に出ている欄は`outputEl()`／`displayEl()`**
  （§9.233 ②、利用者の指摘「自動で入る値の場合、単位設定や外観変更などしても
  変更が効かないものが多い」）: 母材の参考値3つは`<output>`で、`valueEl()`が
  拾わないため単位も寄せも意匠も**黙って落ちていた**。**`valueEl()`へ混ぜない
  こと**——`setValue()`／`syncWidget()`が書き込む先なので、混ぜると読み取り
  専用の欄へ値を書きに行く。寄せは`display:flex`の器なので`text-align`では
  動かない（`justify-content`で当てる）。自動で入る値の選ばせ方は

  **器は被せない**（押せる部品にすると押しても何も起きない・§4）——印

- **マスタが差配している欄の印は`opf-host`の1つ**（§9.233 ③、利用者の指摘
