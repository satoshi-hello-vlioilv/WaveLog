# §9.132 表示サイズを5段階から3段階へ縮める

> 「文字サイズの5段階を3段階に縮め、影響範囲を小さくして調整しやすく
> しましょう。2段階分削除してください。」（利用者からの依頼）

#### 何を消したか

| | 以前（5段） | いま（3段） |
|---|---|---|
| 極小 `xs` | .84 | — |
| 小 `sm` | .92 | .92 |
| 中 `md` | 1（既定） | 1（既定） |
| 大 `lg` | 1.1 | 1.1 |
| 特大 `xl` | 1.22 | — |

倍率の幅は **.84〜1.22（1.45倍の開き）→ .92〜1.10（1.20倍の開き）**。
既定（中）は動かしていないので、**いま使っている見え方は変わらない**。

#### なぜ効くのか

このアプリの寸法は「文字サイズ × 行送り ＋ 余白」で組み上がっており
（§9.90）、器の高さも幅も`--ui-scale`に連動する。つまり**段が増えるほど、
1つの器を直すたびに確かめる組み合わせが増える**。実際、これまで手当てして
きた溢れは特大でのものが大半だった——

- 測定画面の左ペインが特大で22pxはみ出す（§9.126）
- 母材パネルが「大」「特大」で枠から溢れる（VER1.87.0）
- 選択欄の幅が特大で12px溢れる（§9.130。幅は「測ったときの文字サイズ」の
  結果なので、文字だけが1.4倍になると器から出る）
- 通しテストで最後まで残った2件も、どちらも**xlでだけ**落ちていた
  （`test_maint`の左ペイン+12px、`test_fit`の`#operator` 横+14px）

両端の2段は「効果は大きいが、そのぶん破綻もそこでだけ起きる」段だった。
落とすと、`test_fit`の巡回は5段×8画面→**3段×8画面**になり、実装側も
「特大でどうなるか」を毎回考えなくてよくなる。

#### 消した段を選んでいた端末をどうするか

`localStorage`（`MeasurementUiSizeV1`）には`xs`/`xl`が既に保存されている
端末がある。**無効な値として既定（中）へ落とすと、わざわざ選んでいた人ほど
設定が黙って戻る**ので、`UI_SIZE_ALIASES`で残った段のいちばん近いものへ
寄せる（`xs`→`sm`、`xl`→`lg`）。`applyUiSize()`も同じ表を通すので、
古いキーで呼ばれても既定へ落ちない。

#### 触る場所

段は3箇所に散らばっているので、増減させるときは必ず揃える。

| 場所 | 何を持っているか |
|---|---|
| `static/css/00-base.css` | `:root[data-ui-size="…"]{--ui-scale:…}`（倍率そのもの） |
| `static/js/core/base.js` | `UI_SIZES`（選択肢と呼び名）・`UI_SIZE_ALIASES`（古い保存値の行き先） |
| `static/css/20-shell.css` | `.ui-size-swatch[data-swatch="…"]`（選ぶ前に大きさが分かる見本） |

固定は`tests/test_uisize.js`（選択肢が3つであること・小＜中＜大・保存の
持ち越し・**廃止した段の保存値が近い段へ寄ること**）。溢れの巡回
（`test_fit.js`）と、寸法の巡回（`test_scale.js`/`test_typescale.js`/
`test_uisize.js`（旧`test_calscale.js`）/`test_scbalance.js`/`test_course.js`/`test_maint.js`）も
3段で回るように揃えてある。

#### ついでに見つかった「置き土産」——実績に暗黙に頼っているテスト

この作業の通しで`test_screport`の「作業中の行をダブルクリックすると測定画面が
開く」だけが落ち、単体では通った。**画面は正しく開いていた**（`modal:true`／
ロット`ZZ9T4813`）。落ちたのは、テストが行のロット番号を`/L\d{4}|M\d{4}/`
という**番号の形の決め打ち**で拾っていたため、実データ由来の`ZZ9T4813`に
当たらず空になったから。そしてその行が先頭の作業中になったのは、
**異常終了した実行が残した実績**が`db/records.sqlite3`に居座っていたため
（§9.121そのもの）。テスト側は内容セル（`data-content-col="lotNo"`）から
読むようにして、番号の形を仮定しないようにした。

**ここで「実績もランナーが起動時に白紙へ戻す」を入れかけたが、取り消した。**
入れた途端に`test_wkbg`（判定材料が揃う前は「?」）と`test_theme`（実績のある
行に削除ボタンが出る）が落ちるようになり、**コードを1行も変えていない
`366836e`でも同じ2本が落ちる**ことを確かめた——つまりコードではなく状態。
この2本は**測定バックアップに実績が1件以上あることに暗黙に頼っており**、
実績を作るのは`test_screport`/`test_startwork`/`test_share`/`test_orphan`と
いずれも**後**に走るテストなので、効いていたのは前回の実行の残骸だった
（空で4件FAIL → 実績を入れ直すと52/52 PASS）。`tests/README.md`が既に
「前提は他のテストの残骸に頼らず自分で作る」と書いている型が、まだ2本
残っていたことになる。**掃除する前に、掃除して困る側を直す。**
`tests/reset_records.py`は手で使う道具として残してある。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **行・列を「最大」で出せる。既定は「その塊の今までの出し方」**（§9.309、利用者の
  指示「データが最大に入ったときの行や列の表示になるような設定を追加してほしい…
  板幅表示が40条まで常時表示しているのと同じ形」）: 帳票ブロックマスタの
  `[最大表示]`（`''`＝ふつう／`最大`／`データなり`）。紙の高さがロットごとに変わると
  置き場所を決め直すことになるので、**入れ物を最大に固定して足りないぶんは空欄**で
  出す——測定データの表は元からそう組んである（40条ぶんを常に出す）ので、足したのは
  **切り替えられること**と、丈のように今までデータなりだった塊への適用。
  **3値にすること**——`最大`／`データなり`の2択にすると、既定をどちらにしても
  **片方の塊の見え方が黙って変わる**（測定データは40条が既定、丈別データは記録された
  丈だけが既定・§9.132）。答えるのは`rpFullCount()`の1箇所（§9.163。呼ぶ側で
  `Math.min`を書かない）。**語彙はサーバー（`FULL_LABELS`）が持つ**。
  **注記も言い直すこと**（§3）——控え欄を出していないのに「空欄にしています」と
  書いてあると紙が嘘をつく。**設定は`rpMergeBuiltin()`と`rpUserBlockDef()`の両方へ
  運ぶ**（§9.113。片方だけだと既定の塊か自作の塊のどちらかで効かない）。
  **網は見本のロットで数えないこと**——見本は40条・9丈まで埋めてある（§9.254 ④）ので
  「最大」と「データなり」が同じ数になり、何も確かめられない。行数は実データの
  ロット（`tests/test_rpblocks.js`）、注記は見本（`tests/test_rbsample.js`）で見る。
- **帳票の表は「縮める前に余白を詰める」**（§9.298、利用者の指示「帳票ブロック
  マスタの『丈別データ(長さ、肉厚、揃い)』に関して、横方向の幅を小さくしたときに
  他の表と同じように余白を詰めてデータの文字サイズを極力キープするような変化を
  するように」）: `rpFitBlockBodies()`はいきなり`--rp-fit`で**丸ごと縮めて**おり、
  丈別データを6/24マスにすると0.55倍＝本文7.5pxが**4.1px**になっていた（実測）。
  余白（2px/1px）は縮まないので、詰めれば入る余地があるのに使っていない。
  段は`RP_DENSE_STEPS=[1,.55,.25]`の3つで、**1段目は「詰めない」**——入っている
  塊の見え方は1pxも変わらない（§9.132）。段の中身（セルの上下・左右の余白、
  行送り、見出しと注記の余白、札と内訳のあいだの隙間）は`60-report.css`が持ち、
  JSが決めるのは**どの段まで進むか**だけ（§9.163）。**文字サイズには掛けないこと**
  ——文字を保つのがこの仕組みの目的で、掛けると`--rp-fit`と同じことをするだけになる。
  **段ごとにまとめて測る**（塊ごとに試すとグリッド全体が毎回組み直される・
  `rpFitRows()`と同じ理由）。**測る前に`--rp-fit`と`--rp-dense`を両方外すこと**
  ——片方だけだと一度詰まった塊が二度と戻らない（§9.210 ④・§9.217の罠）。
  **表のセルだけを詰めても足りない**——1丈しか無いロットでは塊の高さの半分以上を
  見出しと注記が占めている（実測: 表32px）。**行送りに数を入れるのは既に数が
  書いてある規則だけ**（`.rp-note`の既定は`normal`なので、数を入れると詰めていない
  状態の見え方まで変わる）。固定は`tests/test_rpblocks.js`の§9.298——**A/Bで見る**
  （inlineの`--rp-dense`を`!important`で打ち消して測り直し、「詰めないと縮む倍率が
  下がる」ことまで確かめる。「狭いと詰まる」だけを見る網は、詰めが縮める側に1pxも
  届いていない実装でも通る）。
- **紙は「余白 → 余力のある列 → 折り返し → 文字サイズ」の順で詰める**（§9.303 ①、
  利用者の指示「列内の全体余白の調整→個別に余力のあるもの余白調整→改行による
  文字表示エリア確保(高さ方向への逃げ)→文字サイズ調整による表示用量アップ」）:
  §9.298は「余白（3段）→丸ごと縮める」の2手だったが、**折り返しが制御できて
  いなかった**——幅が足りなくなると表のセルはその場で折り返すので、**1行で収まる
  はずのものが2行になり**、増えた高さで余白詰めと文字縮小が起きていた。
  段は5つで、`RP_PACK_STEPS`の1箇所が持つ（①そのまま ②1行に戻す ③列内の全体余白
  ④余力のある列を詰まった列へ回す ⑤折り返す）。そのあとに`--rp-fit`。
  **1段目は「今までどおり」**——入る塊の見え方は1pxも変えない（§9.132）。
  **判定は縦と横の両方を見る**——1行に揃える段では横へ溢れるので、高さだけを見ると
  「入った」と誤って判断してそこで止まる。
  ④は`table-layout:fixed`の**等分をやめて`auto`へ**切り替える——中身の短い列が
  幅を余らせたまま長い列だけが溢れるのを、要るところへ配り直す（これが利用者の言う
  「他の列の余白が残っている場合はそこを先に詰める」）。
  **段の中身はCSSが持ち、JSが決めるのはどの段まで進むかだけ**（§9.163）。
  **1行に揃えるのは器や値の名前で書き分けない**（§9.233 ③）——`*:not(.rp-info-box)`で
  塊の中をまとめて揃える（自由記述だけは外す。1行にすると横へ延々と伸びるだけで
  畳める高さが無い）。固定は`tests/test_rpblocks.js`の§9.303 ①——**A/Bで見る**
  （段を`!important`で止めて測り直し、「段を止めるとそのぶん文字を縮めることに
  なる」ことまで確かめる。印が付いたことだけを見る網は素通りする）。
- **設備の有効・無効は「機能ごと」。保存値は「使わない機能」**（§9.302、利用者の指示
  「設備マスタの有効・無効機能を実装してください。有効無効の範囲については機能別に
  分けて変更できるようにしたいです」）: 設備マスタの`[無効機能]`に、使わない機能を
  カンマ区切りで持つ。**裏返しなのは「空欄＝すべて使える」を既定にするため**——
  「使う機能」で持つと、**あとで機能を1つ足したときに触っていない設備が黙って
  無効になる**（§9.132）。語彙は`master_repo.EQUIPMENT_FEATURES`の1箇所
  （`measure`＝測定画面の使用設備／`schedule`＝作業スケジュールの設備／
  `report`＝帳票の配置を編集する設備）で、**画面へ綴りを書き写さない**（§9.163。
  一覧はサーバーが解いた`features`の真偽値を読むだけ）。判定は`equipment_allows()`
  の1箇所で、**機能を指定しない問い合わせは常に真**（設備マスタの編集・改名の追跡・
  綴り寄せは「使えるかどうか」とは別の話で、ここで絞ると無効にした設備のロールや
  過去の設定が引けなくなる）。**知らない綴りは捨てる**（保存値が語彙から外れると、
  画面のチェックに現れないまま効き続ける＝押しても外せない設定になる）。
  **絞るのは「これから設備を選ぶ場所」だけ**——実績データ・データ一覧のように
  **記録から出てくる一覧は絞らない**（履歴なので、外した瞬間に読めなくなるのは
  行き過ぎ・§9.15）。帳票も**ロットが1件も無い設備だけ**落とす。
  **いま選んでいる／いま開いている設備は落とさない**（落とすと直す手立てまで
  画面から消える）。**伏せた件数と直す場所は必ず文字で出す**（§4。使用設備の窓は
  助けの行、スケジュールは選択欄の`title`、一覧は「使える機能」の列が
  `すべて`／残る機能名／`なし（どこにも出ません）`と言う）。
  **設備マスタの側から設備を選ぶ欄（ロール・設備停止・勤務形態など）は絞らない。**
  画面の欄は`check-set`（**札は「使う機能」・隠し欄は「使わない機能」**で、裏返す
  場所はこの型の描画と入切の2箇所だけ）。固定は`tests/test_eqfeature.js`
  ——**候補が減ること・減らないことの両方を見る**（片側だけの網は、絞りすぎる実装も
  絞らない実装も素通しする）。
- **表示サイズは3段階（`sm` .92 ／ `md` 1 ／ `lg` 1.1）。段を増やさない**
  （§9.132）: 寸法は「文字×行送り＋余白」で組み上がるので、**段が増えるほど
  1つの器を直すたびに確かめる組み合わせが増える**。以前は5段（極小.84〜
  特大1.22）あり、手当てしてきた溢れは**特大でだけ起きるもの**が大半だった
  （左ペイン22px・母材パネル・選択欄12px…）。両端を落として.92〜1.10へ
  狭めてある。段は**3箇所**が持つので増減させるときは必ず揃えること——
  `00-base.css`の`:root[data-ui-size=…]`（倍率）・`base.js`の`UI_SIZES`
  （選択肢）・`20-shell.css`の`.ui-size-swatch`（見本）。**廃止した段の
  保存値は`UI_SIZE_ALIASES`で近い段へ寄せる**（`xs`→`sm`／`xl`→`lg`）
  ——無効値として既定へ落とすと、わざわざ選んでいた人ほど設定が黙って戻る。
  固定は`tests/test_uisize.js`、溢れの巡回は`tests/test_fit.js`（3段×8画面）。
