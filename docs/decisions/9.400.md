# §9.400 ICASコピーの既定ルール／停止内容の複製／設備停止の追加を1本の帯へ（利用者の報告と指示）

利用者の報告・指示（原文）:

> **１）作業スケジュール表のICASのコピー機能不具合**
> デフォルト登録済みになっていて、設定変更しようとしたら、その内容は追加扱いに
> なりました。かといって、条件をすべて削除すると、ルールがないと言われますが、
> 内部的にルールがある状態なので、デフォルトのルールでも使えないといった形です。
> したがって、デフォルトのルールをしっかり設定の部分の表(おもて)に出してもらって
> 変更が効くように修正してください。ルールなしの場合コピーはロットナンバーだけの
> 連結コピーになるなど、ルールがないとしてコピーができないではじくみたいなことの
> ないようにしてください。
>
> **２）作業スケジュール表の設備停止内容複製機能の追加**
> 右クリックメニューにないので追加してください。
>
> **３）作業スケジュール表の設備停止の追加ポップオーバーメニューの改修**
> もっとすっきり使いやすいデザインでUIUX検討してくださいデザイン案をいくつか
> 提示してほしいです。

（②の対象について、確認への回答）

> 予定の行は複製したら重複するのでダメですね。
> **停止内容(マスタから引っ張ってくるもの)を複製したい**です。

## 1. ICASコピー — 「登録済みに見えるのに実体が無い」の正体

推測ではなく**実機で状態を取り出して**確かめた（`WL.lotCopy.rules()` と
`localStorage` を並べて出す使い捨ての網）。欠陥は**3つが重なっていた**。

| 見えていた症状 | 実測 | 原因 |
| --- | --- | --- |
| 「デフォルト登録済み」なのに実体がない | `localStorage` は `null` のまま | `rules()` が `seed()` を**保存していなかった** |
| 設定変更が「追加扱い」になる | 例の `id` が `'r'+Date.now()` で**読むたびに変わる** | 窓を2枚開くと互いの `id` を知らず、直した行が別行として増える／「最後に使ったルール」も毎回忘れる |
| 全部消すと「ルールがない」と言うのに内部にはある | `[]` を保存 → **再読込で例が復活** | `[]`（＝利用者が空にした）を「まだ作っていない」と同じに読んでいた |
| ルールが無いとコピーできない | `copyLots()` が `if(!use)` で**はじいていた** | ルール不在を断る理由に使っていた |

### 直した形

```js
function rules(){
 if(cache)return cache;
 let raw=null,had=false;
 try{const s=localStorage.getItem(KEY); had=(s!==null); raw=JSON.parse(s||'null')}catch(e){…}
 if(had&&Array.isArray(raw)){cache=raw.map(normRule);return cache}
 cache=seed().map(normRule);
 save();                       // **例も本物の行にする**（直せる・消せる）
 return cache;
}
```

- **鍵そのものが無いときだけ**例を書き、**その場で保存する**。以後はただの1行。
- `id` は決め打ち（`r_icas_space` / `r_icas_space_nl10`）。**時刻から作らない**
  ——保存しないまま時刻でIDを作ると、同じ物が読み込みのたびに別物になる。
- **`[]` はそのまま尊重**する。「まだ作っていない」と「利用者が空にした」は別。

### ルールが1本も無くてもコピーできる

```js
const PLAIN={id:'',name:'ルールなし（半角スペースでつなぐ）',
             seps:[{kind:'space',text:'',count:1,every:1}]};
function currentRule(){
 const list=rules();
 return list.find(r=>r.id===currentId())||list[0]||PLAIN;   // **必ず1つ返す**
}
```

**呼ぶ側に「無いときの扱い」を書かせない**——書かせると、はじく分岐がそこで増える。

**区切りは半角スペース1つにした。** 指示は「ロットナンバーだけの連結コピーに
なる**など**」だったが、区切り無しの棒つなぎ（`A1A2A3`）は貼り先（ICAS）で
使えない。**はじかないという目的は同じに満たしつつ、出てくる物が使える**ほうを
採った。**名前が状態をそのまま言う**ので、何が起きるかは推測させない
（メニューにも見本の出どころにも `ルールなし（半角スペースでつなぐ）` と出る）。
`PLAIN` は**一覧には出さない**——出すと §9.367 で撤回した「触れない既定」に戻る。

## 2. 複製するのは「予定の行」ではなく「停止内容そのもの」

§9.399 で「停止内容の複製」を**予定の行の複製**と読んで実装したが、利用者の
意図は**マスタの1行**だった（「予定の行は複製したら重複するのでダメですね」）。

- サーバー: `schedule_repo.stop_reason_duplicate()` ＋
  `POST /api/schedule/stop-reason-master/duplicate`（`routes/masters/stop_detail.py`。
  `schedule.py` は41ルートで上限・§9.389）。
- **登録とは別のルートにする。** 登録は `(対象設備,名称)` の自然キーで既存行の
  更新に倒れるので、「同じ内容をもう1行作る」をそこへ載せると**直したのか
  増やしたのか呼ぶ側から読めない**（1. で踏んだのと同じ形）。
- **写すのは「その停止内容が持っているもの全部」**——分類・標準所要分・色キー・
  連携機能と、**内訳の木（2段とも・既定の印つき）**。内訳を置いていくと
  「同じ名前なのに選べる内訳が無い」中途半端な行ができる。
- **名前だけは必ず変える**（`名称（写し）`、埋まっていれば `（写し2）`…）。
  数えるのは**サーバーの1箇所**（`stop_reason_copy_name()`）——画面でも数えると、
  UNIQUEで弾かれる名前を画面が自信満々に出すことになる（§9.163）。
- 入口は**設備停止の一覧の右クリック1つ**。使っているその場で増やせる
  （マスタ管理を開き直させない・§CLAUDE 2）。
- `access_mode._ENDPOINT_EXTRA_MODES` へ `masters.stop_reason_duplicate_route:{'schedule'}`
  を載せる。**載せ忘れると押しても403で黙って弾かれる**（§9.389と同じ罠）。

## 3. 設備停止の追加は「上＝一覧の2列／下＝決める帯」（案B）

案を3つ描いて実寸（820×560px）で見てもらい、**案B**を選んでもらった。

### なぜ左右2ペインをやめたか — 面積の配り方が逆だった

§9.397 の形を実測すると、**右ペインの半分を「時間」の札10枚（4段）が
占めて**いた。スライダーと出どころの1行はスクロールの外。ところが決めることは
**内訳と時間の2つだけ**で、しかも**どちらも最初から入っている**——
**いちばん広い場所を、いちばん触らないものに配っていた**（§CLAUDE 1）。

```
いままで  [ 一覧 45% ][ 内訳 / 時間の札10枚 / スライダー / 追加 55% ]
これから  [ 一覧（2列・窓いっぱい）                               ]
          [ 名前 › 内訳 › 内訳 · 時間 ………… 選び直す            ]
          [ ◯◯（内訳）・30分 を いちばん後ろ へ追加              ]
          [ 入る先・時間の出どころ・−＋の意味                     ]
```

決めた点:

1. **一覧は2列。** §9.397 で1列にして左端をそろえたが、左右の分割をやめて
   窓いっぱいになったので、1列のままだと**6文字の名前に1600pxの器**を
   与えることになる（§CLAUDE 11）。2列でも左端は2本にそろう。
2. **時間は「− 数 ＋」の1組**（§9.247。数で決まる設定に札を並べない）。
   `−`／`＋` は**時間マスタの選択肢を送る**ので、顔ぶれを決めるのは今までどおり
   マスタ（§9.389）。選択肢に無い分は**数字を打てば入る**——スライダーより
   正確に合い、3段ぶんの高さが消える。
3. **内訳は `<select>`。** ふつうは既定が入ったままなので開く手すら要らない。
   添える印は**2つまで・短く**（`既定`・`＋N`）——実測で
   `下刃（既定）（さらに2件）　30分` が器から溢れ、**名前のほうが切れていた**。
4. **「どこへ入るか」の専用の帯は消した。** 入る先は**追加ボタンの字そのもの**に
   入っている（§CLAUDE 8「同じ情報を2箇所に出さない」）。
5. **追加は必ず自分の1行**（`flex:1 0 100%`）。入る先まで字に入るので長さが
   行ごとに変わり、同じ行へ置くと「決める物」の並びが名前の長さで動く
   ——実測で「選び直す」が全幅ボタンの右へ弾き出された。
6. **「選び直す」は1行目の右端**（`margin-left:auto`）。やめる操作なので
   主要動線（追加）と同じ行に並べない（§CLAUDE 5）。
7. **分類はチップで絞る。** 分類が1種類しか無い設備では**出さない**
   （押しても何も変わらない物を置かない・§CLAUDE 4）。絞り込みは
   **打った字 → 分類チップ**の順——この順でないと件数と中身が食い違う。
