# §9.558 データ一覧（測定データ）の操作を下の帯へ——行を選ぶ→選んだ1件の操作が出る（利用者の選んだ案 C）

索引: [決定記録](README.md)｜前: [§9.557](9.557.md)｜関係: [§9.222](9.222.md)・[§9.507](9.507.md)・[§9.105](9.105.md)・[§9.553](9.553.md)

## 経緯

利用者の指摘（§9.557 の依頼の２）:
「測定データ一覧のスクロールバーがリストの直下に来るので圧迫感がある。再開や帳票のボタンも小さく使いづらい、
文字サイズバランスは行のサイズ感の統一感を損ないたくないので十分に配慮は必要だがわかりにくく使いにくい状態は
改善したい案を5案程度出して検討させてください。」

5案（A 操作列を左へ固定／B 行に乗せたときだけ出す／C 選んで下の帯／D 右の詳細の窓／E 操作を1つの「⋯」へ）の
画像を出し、利用者が選んだ:
「スクロールバーは表示列の多さで出るので出てもよいですが「測定実績」の表示方法と合わせて一番下に持っていって
ほしいです。変更内容はCが良いです。1つずつしか選ばない工程でもあり、選ぶ→操作したい内容が表示という流れで
特に迷うことはないので。」

## 決めたこと

1. **操作の列（`__actions__`）をなくす**。行の中の「再開・帳票・⋯」（34×19px・12px）は、§9.222 ① で下限を
   持たせてまで切れないようにしていたが、ボタンとして小さく、列の幅（161〜193px）が横のはみ出しの一因だった。
2. **行を押すと選ぶ（1件だけ）**。選んだ行は`.is-selected`（地の色＋左の太線・字だけでなく`aria-selected`も）。
   焦点が来ても選ぶので、↑↓で選び直せる。Enter は再開、ダブルクリックは帳票（今までどおり）。
3. **選んだ1件の操作は一覧の下の帯`#recordActionBar`**（`renderRecordActionBar()`の1箇所）。左に「何を選んでいるか」
   （ロット番号＋状態・使用設備・更新日時——字は一覧の行と同じ`recordCellText()`で作る）、右に「再開する／開く」
   「帳票」「⋯ その他」を標準の大きさ（`--ctl-h`・本文の字）で出す。選ぶ前は帯に「行を押して選ぶと…」と言う。
   **帯の高さは選ぶ前後で同じ**（場所を動かさない・§9.397）。
4. **一覧の器が残りの高さを全部使う**（`#recordList{flex:1;min-height:0}`）。横のスクロールバーは一覧の器の一番下
   ＝帯の真上に来る（測定実績の一覧と同じ置き方）。行の高さは変えない（28px のまま）。
5. 保存済みの並びに残っている`__actions__`は候補に無いので読み飛ばす（`recordAllColumnKeys()`の`known`）。
   列の設定パネルから「操作」の列は消えた。

## 撤回した案

- **A 操作列を左へ固定**: ボタンは行の中のままで小さい。行の高さを上げずに大きくできない。
- **B 乗せたときだけ出す**: 何ができるかが乗せるまで見えない（探させる）。
- **D 右の詳細の窓**: 一覧の横幅を削る（列が多い一覧で、さらにはみ出す）。
- **E ⋯の1つへ**: 一番よく使う「再開」が2手になる。

## 測った（評価関数・前→後）

物差しは測定データ一覧を開いて測る（1728×1152＝利用者の常用環境・15列の既定・記録2件）。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 横のはみ出し（既定の列で） | 59px | 0 |
| 横のスクロールバーの下の空き（一覧の器の外） | 711px | 0（器が下まで伸びる・帯までの隙間 0） |
| 操作のボタンの大きさ・字 | 34×19px・12px | 98×36px・14px（「再開する」） |
| 操作のボタンが切れる | 3つとも省略記号になり得た（§9.222） | 0（帯の中・字を全部出す） |
| 行の高さ | 28px | 28px（変えない） |
| 選んだ行 | — | 1件だけ・帯が同じロット番号を言う |
| 帯の高さ（選ぶ前→後） | — | 53px → 53px |

## 網

- `tests/test_reccols.js`: 既定の列は14（操作の列が無い）・押すと1件だけ選び、帯が同じロットを言う・帯のボタンは
  高さ30px以上・字13px以上・一覧と帯のあいだは0・↓で次の行を選び直す。
- `tests/test_recdel.js`: 削除は帯の「⋯ その他」から（3つの表示サイズで帯のボタンが切れない）。

## 踏んだ罠

- 帯の高さが選ぶ前（説明の1行）と後（ボタン）で 52→53px に動いた。最小の高さを罫線の1pxまで含めて決めた。
- 網で「1行目の検査番号のセル」を`:first-of-type`で押そうとして待ち切れなかった（`:first-of-type`は要素の種類で数えるので、同じ`div`の見出しの行`.record-list-head`が1番目になり、どの行にも当たらない）。
  本物のマウスで1行目のロット番号以外のセルを押す形にした。

## 分からないこと

- Windows の実機（2160×1440・125%）でのスクロールバーの見え方は確かめていない（網のブラウザはスクロールバーを
  描かない）。器の一番下に来ることは器の寸法で確かめた。

## 追補: 直し忘れた網（§9.562 の作業中に見つけた）

行の中のボタン（`.record-list-row .report`）をなくしたのに、帳票を開く網5本（`test_eqfeature`・`test_rpblocks`・`test_rplayout`・
`test_rpmaster`・`test_rpprint`、計11か所）が古い選択子のままだった。main で `test_eqfeature` が「`page.click` の時間切れ」で落ちて見つかった
（変更を退避した main の状態でも同じに落ちることを確かめた＝§9.562 の変更が原因ではない）。
§9.558 のときになぜ回さなかったかは**分からない**（`pick_tests.py` は `records-store.js` に `test_eqfeature` を結び付けている）。

直し方: 「行を押して選ぶ → 帯（`#recordActionBar`）の『帳票』を押す」を網の土台 `wait.js` の `openRecordReport(page,{has,not})` の1つにし、
11か所すべてをそれで呼ぶ（人と同じ道・書き写さない）。どの行かは字で選べる（`has`＝含む字・`not`＝含まない字）。
