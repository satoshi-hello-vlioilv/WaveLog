# §9.122 測定画面の再設計 第0段: 中核を書き出してから組み替える

測定画面を「準備 → 測定 → 確認」の3段へ組み替えるにあたり、**組み替える前に
いま出来ていることを回帰テストへ書き出した**（`tests/test_mcore.js`、35件）。
組み替えてからでは「前はできていた」を証明できない。

調べて分かったのは、**`#deviceInput` を動かしているテストが1件も無かった**
こと。測定器からの転送 → セル送り → 判定の印 → 進捗 → 保存という、
この画面のいちばん中心の流れが無防備だった。

#### 固定するのは振る舞いであって配置ではない

ペインの幅もタブの数もこれから変わる。そこを固定すると組み替えた瞬間に
落ちて、安全網ではなく足枷になる。見るのは「入れた値が正しい場所へ入り、
正しく次へ進み、保存される」だけにした。

#### 期待値は観測してから書く（憶測では3件外した）

| 憶測 | 実際 |
|---|---|
| `DT110+026.15`(ノギス)は `26.15` で入る | **`26.10`**。小数1桁へ丸めてから2桁で格納する2段階の丸め |
| 開いたらすぐ転送を受けられる | 既定の選択は母材＝手動入力の項目。**受信の帯ごと`display:none`**で、寸法ゼロの要素にフォーカスは載らない |
| 手動入力の `28.25` はそのまま入る | **`28.3`** |

**母材のあいだ転送を受け付けないのは正しい振る舞い**で、直す対象ではない。
「開いたらすぐ受け付ける」と書いていたら、正しい実装を落とす網になっていた。

#### 受信欄のDOMを作り直さない（この再設計でいちばん危ない制約）

測定中は `#deviceInput` にフォーカスが載り続けていることが動作条件で、
外れると画面は「伝送入力停止中」になり転送を受けない。そして**フォーカスは
そもそも外れない**——受信欄が再描画の対象（`renderMeasureGrid`）の外に
あるからで、`refocusDeviceInput()` はあくまで保険。

つまり**②測定で項目を切り替えるたびに受信欄ごと組み直す実装にすると、
測定そのものが止まる**。過去にこの周辺で実機だけの不具合が2件出ている
（多条の連続入力が崩れる／IMEセッションが残って転送文字列が二重になる）。
Linuxでは再現しないので、**機械で見張る**しかない。

#### 網が最初は効いていなかった

`refocusDeviceInput()` を無効にしても **35/35 PASS のまま**だった。原因は
テストの送信ヘルパーが毎回 `page.focus('#deviceInput')` していたこと——
「転送のあとフォーカスが戻る」ことを**自分で戻してから**確かめていた。
実機の測定器は間にクリックを挟まず送り続けるので、こちらからフォーカスを
触らない形へ直した。その状態で「再描画のたびに受信欄を作り直す」欠陥を
注入すると**12件が落ちる**（転送が1件も入らない・「伝送入力停止中」）。
**注入が通ったら、その網は無い。**

#### 画面のidと保存側の記録IDは違う

後片付けで消し損ね、残った実績が計画外実績としてタイムラインに出て、
**内容の無関係な `test_scdrop` を落とした**（§9.121の再来を自分でやった）。
画面の `S.measure.id` は `|L0001|K0001|C001` だが、共有DBには設備名が
前に付いた `テスト設備A|L0001|K0001|C001` で入る。**前置きの規則を推測せず、
一覧を引いて末尾一致で消す。**

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **測定中は受信欄(`#deviceInput`)のDOMを作り直さない・動かさない**（§9.122）:
  測定中はこの欄にフォーカスが載り続けていることが動作条件で、外れると画面は
  「伝送入力停止中」になり**転送を1件も受けない**。**フォーカスはそもそも
  外れない**——受信欄が再描画(`renderMeasureGrid`)の対象の外にあるからで、
  `refocusDeviceInput()`は保険にすぎない。3段構成へ組み替えるとき、項目の
  切り替えで受信欄ごと組み直すと**測定そのものが止まる**（過去に周辺で
  実機だけの不具合が2件出ている: 多条の連続入力が崩れる／IMEセッションが
  残って転送文字列が二重になる）。**Linuxでは再現しない**ので、
  `tests/test_mcore.js`が機械で見張る（受信欄を作り直す欠陥を注入すると
  12件落ちることを確認済み）。**受信の帯は測定器を使う項目でだけ出る**
  （既定の「母材・揃い/肉厚/長さ」は手入力なので`display:none`。寸法ゼロの要素にフォーカスは
  載らない＝そのあいだ受け付けないのが正しい）。
  **テストが自分で`page.focus('#deviceInput')`を書かないこと**——「転送の
  あとフォーカスが戻る」ことを自分で戻してから確かめる形になり、網が空振り
  する（実際に`refocusDeviceInput()`を無効にしても35/35 PASSのままだった）。
  実機の測定器は間にクリックを挟まず送り続けるので、**こちらからフォーカスを
  触らない**のが実機相当。
  **測定レコードの後片付けは末尾一致で消す**——画面の`S.measure.id`は
  `|L0001|K0001|C001`だが、共有DBには設備名が前に付いた
  `テスト設備A|L0001|K0001|C001`で入る。画面のidだけで消すと当たらず、
  残った実績が計画外実績としてタイムラインに出て**無関係な`test_scdrop`が
  落ちた**（§9.121と同じ壊れ方を自分でやった）。
