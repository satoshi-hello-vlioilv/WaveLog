# §9.546 デスクトップ版への移行 P2——Rust の窓（`desktop/`・Tauri）と、Start.vbs の「desktop」（利用者の指示）

索引: [決定記録](README.md)｜設計: [`docs/DESKTOP_MIGRATION_DESIGN.md`](../DESKTOP_MIGRATION_DESIGN.md)｜前: [§9.545](9.545.md)

## 利用者の言葉

「1も2も進めてください」（2＝P2: Rust の窓・Windows の CI で本物の WebView2 の自己診断）。
事前の答え: ①exe は手元へ写してから使う ②Defect-Pitch-Analyzer の exe は社内で動いた ③ブラウザ版と併存。

## 決めたこと

- **窓は Defect-Pitch-Analyzer と同じ作り**（枠・振り分け・監督を写し、WaveLog の名前と決まりへ直した）。
  - `frame.rs`（枠）・`sidecar.rs`（子の Python を起こす・番号で答えを返す・止まったら起こし直す）・
    `router.rs`（`/static/`は Rust、それ以外は Python）・`locate.rs`（program・Python・作業場所）・`main.rs`（窓）。
  - 自前の仕組みの名前は`wavelog`（`backend/config.py`の`DESKTOP_SCHEME`と同じ）。
- **連結した CSS（`/css/app.css`・`/css/boot.css`）は Python が作る**ので、Rust が直に返すのは`/static/`だけ。
  版付き（`?t=`）は長く使い回す——ブラウザ版の`cache_policy`と同じ答え。
- **終わり方は Python の片付けの1箇所を通す**: 窓を閉じる→入力が閉じる→`watchdog._exit()`。画面の「アプリを終了」
  （`/api/app/quit`）は今までどおり Python が答えて片付け、窓は**中身が終わるのを待ってから**閉じる（6秒まで）。
  入力を閉じてから止めるまでの待ちは5秒（片付けの持ち時間3秒を途中で切らない）。
- **枠の約束の版（`protocol`）が窓と中身で違えば起こさない**——exe は手元へ写し、Python は共有から読むので、
  更新が届くと組み合わせがずれうる。起動画面が「開き直してください」と言う。
- **起動前の確認（`setup_check`）の進み具合は起動画面へ流す**（`progress`の知らせ）。知らせが途切れてから120秒で見切る。
- **Python はブラウザ版と同じものを使う**: Start.vbs は PATH の順に最初の`pythonw.exe`を起こすので、窓も
  **PATH を前から見て最初に`pythonw.exe`がある場所の`python.exe`**（並べ替えない）。端末の控え（§9.545）は
  Python が書き、Microsoft Store 版は自分にしか見えない写しへ書くので、違う Python だと2つの版が別の控えを見る。
  Store 版の入口（WindowsApps のリンク）は**リンクをたどらずに**在るかを見る。
- **ファイルのドロップは画面に渡す**（`disable_drag_drop_handler`）。マスタの取り込みがエクスプローラーからのドロップを読む。
- **外のページ（LotDsp）はいつものブラウザ（Edge）で開く**（ログインと LotData-Link はそちら・§9.521）。
- **起動画面（`desktop/splash/index.html`）は待機画面・アプリ内の覆いと同じ色・同じ地**。トークンと地を写し、
  `test_boot.py`が3つ目の写しとして一致を見張る。
- **アイコンは`backend/app_icon.py`の1箇所が描く**（`build.rs`が作るたびに書き出す。`.ico`をリポジトリへ置かない）。
- **Start.vbs に引数「desktop」**: `WaveLog.exe`（Start.vbs の隣）を`%LOCALAPPDATA%\WaveLog\desktop\<大きさ-更新時刻>\`へ
  写して起動し、`WAVELOG_PROGRAM_DIR`で program の場所を渡す。exe が無い・写せないときはブラウザ版で起動する
  （入口は Start.vbs の1つのまま・§9.405）。古い版の写しは窓が起動のたびに**消せたものだけ**消す（動いている版は掴まれている）。
- **窓の記録**は作業場所の`logs/desktop.log`（探した Python・起動の秒・終わり方）。Python の記録とは別。
- **CI**（`.github/workflows/desktop.yml`・windows-latest）: Python の網（`test_portdep`・`test_terminalstore`・`test_sidecar`）を
  Windows で回す → `cargo test` → `cargo build --release` → exe を Start.vbs の隣に置き、**`cscript Start.vbs desktop`で起こして**
  本物の WebView2 で自己診断（写す道そのものを通す）。exe と結果は Artifacts に置く。

## 撤回した案

- **起動画面を新しい意匠で作る**——待機画面・アプリ内の覆いと色が違うと、引き継ぐ瞬間に色が飛ぶ（§9.411）。同じトークンを写した。
- **終了ボタンを窓（Rust）が直に答える**（Defect-Pitch-Analyzer の形）——WaveLog の終了は片付け（書込役・編集セッション・在席）を
  通すことが要件（§9.301 ②）。答えるのは Python のまま、窓は中身が終わるのを待つ。
- **Python の候補で Microsoft Store の入口を後回しにする**（Defect-Pitch-Analyzer の順）——ブラウザ版と違う Python を選びうる。
  PATH の順をそのまま使う。

## 分からないこと

- Windows 実機の WebView2 での印刷（隠した`<iframe>`）・保存（`Content-Disposition`）・ファイルのドロップの道（`text/uri-list`）。
  CI の自己診断は画面を操作しないので、ここは**分からない**。
- Box Drive が、動いている exe の更新をどう扱うか（写す方式にしたので実害は出ない見込み）。
