# §9.379 刃組ガイダンス4点: 入口・刃の選び方・端部の表・フィンガー（利用者の指示）

利用者の言葉:

> １）メインメニューからは刃組ガイダンスに行けないようにしてください。
> ２）刃マスタの状態は「一般」、「メンテナンス中」、「専用」の3パターンを準備し、
> 基本的に「一般」のものが選択される。「専用」のものが選択される条件を、設備単位で
> 「刃選択マスタ」を準備し、条件テーブルで組んで設定できるようにすること。
> ３）両脇の表を右レールに移し、そちらを右メニューにデフォルト表示。右メニュー内を
> タブで切り替えて全体も見られるようにする。
> ４）フィンガーパターンについても使用するフィンガーの描写を上下軸と板の間の押さえと
> して、板の両側に配置。幅に応じた選択をさせ、加えてください。（フィンガーの形状や
> 本数については添付HTML参照）マスタがなければ追加実装をお願いします。

添付は図面 **N2-10689-1 / DK4-0300 LS-4**（布入ベークライトフィンガー）を
three.js で立体にした1枚もの。全長 560 ／ 板厚 20±0.3 ／ W寸法は14種で合計790本、
両端を上下両面から片側 16.7°（挟角 33.4°）で研削し先端にランドを残す、とある。

## 1. 入口は段取りの行だけ

刃組は**「予定のどの段取りの刃組か」が決まって初めて意味を持つ**。左メニューから
開けると、どのロットの刃組なのかを人が思い出して入れ直すことになる。
`registerView` の `nav` も外した（選択状態を点ける相手が居ない）。

## 2. 刃の状態は3つ／「専用」は刃選択マスタの条件で選ぶ

以前は 使用中／研磨中／待機／使用不可 の4つで、**「いま軸に載っているか」と
「選んでよいか」が混ざっていた**。載っているかは刃組履歴（台車）が答えるので、
状態が二重に持つ必要はない。**状態が答えるのは「選ばれるか」の1点だけ**にした。

`刃選択マスタ`（8枚目の表）は**表示ルールマスタと同じ作法**。1行＝1つの決まりで、
設備ごとに持ち、上から見て**最初に当たった1行**が効く。条件は行ごとに数が
変わるので JSON の配列で持ち、**同じ行の条件はANDで見る**。「または」は行を
分けて書く——1行に AND と OR を混ぜると、読む側が優先順位を推測することになる。

**条件が1つも無い行は当たらない。** 「いつでも当たる行」を書けてしまうと、
「一般が既定」という約束が静かに崩れる。網で固定した。

判定は**サーバー（`pick_group`）と画面（`blade-core.js` の `pickGroup`）の
2箇所**にある（画面は文脈を手元に持っているので往復させたくない）。
2つあるものは必ずずれるので、**同じ入力に対して同じ答えを返すこと**を
両方の網で固定した。欠陥注入（「条件が空でも当たる」）で**両方が独立に赤くなる**
ことを確かめてある。

画面は「なぜその刃か」を手順バーの自動群に出す。条件に当たったのにその組の刃が
未登録のときは、**黙って一般へ落とさず**「一般（○○ の刃が未登録）」と理由ごと出す。

## 3. 端部の表を右レールへ（§9.378 で測った器の話の続き）

§9.378 で、模式図はすでに列の幅を使い切っており、**横へ広げる唯一の手は器の側**
だと分かっていた。両脇の 168px を詰めても戻るのは16pxで、根本は両脇の表そのもの
——と報告して判断を仰ぎ、ここで移す許しを得た。

実測: **760px → 1104px（+45%）**（1728×1152 で測定）。図の段は
`168 | 760 | 168` の3列から1列になった。レールの段は
**端部／所要／台車差分／刃の状態**の4つで、開いたときは端部が出る。

端部の表は「組む前に一度見る」もので、模式図のように常時見比べるものではない
——常時載せる面積は「頻度 × 重要度」で配る（§CLAUDE 1）。
表そのものは `renderEnds()` が id で書き込むので、**描き手は変えていない**。

## 4. フィンガーは板押さえ

以前は輪（ゴムリング）と同じ場所に「指」と書いた帯を出していた。それでは
**「軸に何かが被っている」としか読めず**、どこを押さえているのかが図から
分からない。上下の軸と板のあいだ、**板の両側**へ描くようにした。上軸の区間は
板の上、下軸の区間は板の下——**どちらの軸から差し込まれた押さえかが、
置き場所だけで分かる**。

`フィンガーマスタ` へ **全長・厚み・研削長・研削量** を足した（既定は図面の
改造後＝560 / 20 / 20×6）。**登録が空の行はこの既定で描く**——寸法が空だと
図が描けず、現場には「フィンガーだけ出ない」としか見えない（§9.231）。
初期セットも製作表どおりの幅14種（10 ／ 20〜30 の1mm刻み ／ 50 ／ 100・合計790本）
にした。20〜30 に1mm刻みがあるのは条幅に合わせて選ぶためで、**間引くと
選べる幅が無くて区間を埋められない条が出る**。

### 踏んだ罠: 研削の向きを1つ取り違えた

最初、図面の先細り（20×6）を**軸方向（横）へ**描いた。実際に見ると波打った
塊が並ぶ絵になり、そこで気づいた——**研削は「全長×厚み」の面にある**。
全長 560 は板の流れる向き、つまりこの図では**紙の奥行き**なので、
軸方向から見た形は **幅×厚み の四角**であって先細りは見えない。
横へ描くと、削る向きを1つ取り違えた絵になる。奥行きの形は立体図が受け持つ。

添付の HTML はこの区別を `profile(run, drop)` が `x=長手, y=板厚` を返し、
それを `W だけ押し出し` ていることで表していた——**押し出す向きがW**なので、
W方向の断面に研削は出ない。読み違えたのはこちらの誤りである。
