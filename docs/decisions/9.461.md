# §9.461 基準面（基準原点）をOS／DSで切り替える——既定はDS・フローティングシートは反対の端（利用者の指示）

索引: [決定記録](README.md)

利用者の指示:

> 今はOSを基準面(基準原点)にDSにフローティングシートとしていますが、逆にもできるようにしてください。
> 基準原点を変更したら、中心位置の測り方も連動して変更してください。
> また、この機能の実装に合わせて、デフォルトはDSを基準面(基準原点)にOSにフローティングシートとしてください。

---

## 何が起きていたか（§9.456・§9.457 の決め打ち）

- 材料の位置を刻みへ寄せる `slip` は**OS端**の区間長を刻みの倍数にしていた——端数の出ない端＝OS。
- フローティングシートが押さえる端（押さえ代の幅を持たせる・端数に数えない）は**最後の区間（DS端）**。
- 板の中心は**OSから**の距離。
- 断面図・模式図・端部の表・説明の字も「DS端＝シート」で書いていた。

## 物差し（純粋な計算 `eval_datum.js`・元板巾1000〜1180×4通りの条・200面）

| 物差し | 前 | 後 |
| --- | --- | --- |
| DS基準・有効長1599.63: シートの側でない端に残りが出た面 | **200** | 0 |
| DS基準・有効長1599.63: シートの側（OS端）に残りが出た面 | 0 | 200 |
| DS基準・中心700: 基準面から測った板の中心と700の差の最大 | **200mm** | 0 |
| OS基準（前と同じ形）: 同じ3つ | 0／200／0 | 0／200／0 |

## どう直したか

- 答えは `blade-core.js` の `datumOf()` の1箇所（`刃組基準値`の「基準面」＝`datumSide`・
  `'DS'`／`'OS'`・読めなければ既定の **DS**）。サーバーは `datum_side()` の1箇所で読み分ける。
- `centerOf()` は**基準面からの距離**（`value`）と、同じ位置をOS端から測り直した値（`os`）を返す。
  計算の座標はOS端が0のまま。マスタの鍵は `centerFromOS` → **`centerFromDatum`**
  （列名「板の中心」は同じ）。
- `buildLayout()` は**基準面の側の端**を刻みへ寄せ、シートの側の区間（`A.floatZ`）を返す。
  押さえ代の幅（`planZones`）・端数に数えない（`fit.spacerGap`）・押さえている量
  （`fit.floatSeat`、`side`＝シートの端）・上下左右差の足し込む向き（`assemblyError`）は、
  みな `floatZ` を見る。
- 記録（`condOf`）に基準面も残し、記録から組み直すときは、いまの基準面と違えば中心を測り直す。
- 模式図・断面図: シートがOS端に来るときは、スペーサーを基準面（刃の側）へ寄せて積み、残りを
  OS端へ空ける。3Dのシートは反対の端へ、青い印は基準面の端へ。OS端にシートが載るときは
  軸受・ギヤボックスをシートの幅ぶん外へ逃がす（**図面に寸法が無い概寸**・§9.459）。
- 字: 中心の欄の単位（`mm（DSから）`）、端部の説明、端部の表の「フローティングシート」の行、
  上下左右差の説明、押さえ代を超えたときの帯。

### 取り違えかけたこと

**部材を入れる向き**（DS側＝台車の開く側から通す）と**押し付ける向き**（基準面）は別の軸。
最初は上下左右差の説明を「${反対}側から部材を入れ」と書き換えたが、入れる向きは機械の事実で
基準面では変わらない。取り付ける順（OS端が先）も同じ。直した。
