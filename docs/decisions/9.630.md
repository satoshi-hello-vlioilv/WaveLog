# §9.630 ダッシュボードを初期画面に・既定「生産の状況」（予定と実績のガント・いまの作業・生産性・品種の ABC）・元を選び直せない不具合・測定実績の列（入力した項目を左に・作業開始で並べる）（利用者の指示）

索引: [決定記録](README.md)｜前: [§9.629](9.629.md)｜関係: [§9.628](9.628.md)・[§9.612](9.612.md)・[§9.611](9.611.md)・[§9.597](9.597.md)・[§9.392](9.392.md)・[§9.288](9.288.md)

## 経緯（利用者の言葉）

> １）測定実績のリストに、測定項目から入れたデータもリスト上に表示し、特にその作業開始終了をアプリ上で入力した開始＆終了時刻を表示しソートしてリストにするようにしてください。列は入力項目すべてです。アプリ側で使用し入力したデータを優先的に表示し、列へ結合して追加しただけで直接的に使用されていないデータは列右側へお願いします。
> ２）作業実績（実績の時刻を取り込んだものまたはアプリ内で登録した作業時刻）および作業予定の予定時刻を組み合わせて１つのガントチャートをダッシュボード上に作ることができるようにしてください。またそのガントチャートは規定にしてください。
> ３）ダッシュボードのデータの参照元を切り替えがうまくいきません（写しが終わっていないだけでデータが手元にないので、できないのか不具合なのか判断できません）
> ４）ダッシュボードの規定には、現在の作業ロットもしくは設備停止名称と予定完了時刻の表示、本日の作業ロット数＆「良品重量」と今月の作業本数と生産性表示、今月のABC分析、品種は「用途名」×「縦割り数（丈数）」×「横割り数（条数）」を入れてください。
> ５）左メニューのダッシュボードの位置はメニュー上部に持ってきて、起動時の初期画面にしてください。
>
> （作業の途中で）UIUX修正ルール変更です。合格点は80点以上に変更し、修正した内容は画像を自分で確認してから別エージェントに依頼することに変更して

## ③ 元を選び直せない——不具合だった（写しの待ちではない）

- **物差し**: 組む所の「データ」の選択肢のうち選べる数（`test_dashsrc`）。**直す前 0/5 → 直したあと 5/5**。
- 原因: §9.628 で LotScope から移したとき、選択肢を`x.place`（置き場が設定されているか）で押せなくしていたが、WaveLog のサーバーはその鍵を返さない。
  全部の元が「（場所が未設定）」で`disabled`だった。写しの有無とは無関係。
- いまは元ごとの状態をサーバーが答える（`sources.source_state()`の1箇所・待たない・写さない）: `ready`／`copying`（共有の元をまだ手元へ写せていない＝選べる。
  選ぶと組む所が「写し終えると、このパネルを数えます」と言い、写し終えたら読み直す）／`unset`（置き場が空＝選べない）。
- 合わせて: 役割で書いた元（組み込みの`role:仕掛`）は、選択肢に同じ鍵が無いので先頭の「測定データ」が選ばれて見えていた。いまは役割を担う元を選んで見せる。

## ⑤ ダッシュボードをメニューのいちばん上・起動時の画面

- 左メニューの先頭に「ホーム」の群（`#homeNav`）を置き、ダッシュボードはそこ（前は上から4つ目の群「分析」の中）。
- 起動時の画面は`WL.startView`の1箇所（既定はダッシュボード）。測定だけをする端末のために「表示」の節「起動時に開く画面（次の起動から）」で仕掛一覧を選べる（端末に覚える）。
- ダッシュボードは自分の読み込みが済んだら開く（元データの一覧＝`/api/catalog`を待たない）。仕掛一覧の初期化の中で開いていた最初の形は、
  起動直後の1回目に20秒の待ちで1度落ちた（理由は**分からない**。再現しなかった。待つ依存そのものを外した）。
- 網の土台（`harness.js`）は起動時の画面を「仕掛一覧」にして始める（228本の網が起動直後の仕掛一覧を前提に書いてある）。網が自分で作る文脈（`newContext`・`newPage`）にも当てる。
  既定を見るのは`test_homenav`（`start:'dashboard'`）。

## ② 予定と実績を重ねたガント

- 元は作業予定（`plan`）だけ（予定の時刻を持つのは予定だけ）。パネルの`ops.plan`で重ねる（組む所の「見せる物: 実績だけ｜予定と実績」）。
- **実績の棒**: 予定の行の実績（`schedule_calc._actual_view()`＝測定データの作業開始・終了／手で入れた時刻〈§9.514〉／完了突合で取り込んだ時刻〈§9.595〉／開始・終了の印〈§9.611〉）。
  出どころは`actual_from()`の1箇所で列「実績の出どころ」に持ち、凡例の説明と元の名前（「作業予定（実績: 測定データ・手入力）」）が言う。
- **予定の枠**: まだ終わっていない行（作業中・予定・設備停止）の予定開始〜予定終了。**作業中の行は作業開始＋見積**——予定の計算では作業中の予定終了はいつも「いま」
  （`_ongoing`）なので、それを使うと予定完了がいまの時刻に張り付いて見えた（2回目の採点で名指し）。稼働率・本数には入れない。
- 期間に「今日から n 日」（`ahead`）を足した（先の予定まで見る）。ただし既定は「今日」: 2日にすると、まだ来ていない明日の勤務時間を稼働率の分母に入れる（1回目の採点）。

## ④ 既定「生産の状況」

| パネル | 数え方 |
| --- | --- |
| 本日の作業ロット・本日の良品重量 | 測定データ（作業開始の作業日が今日）のロット数・良品重量の合計 |
| 今月の作業本数・今月の生産性 | 今月のロット数・**合計の比**（良品重量の合計 ÷ 作業時間の合計〈分〉× 60 ＝ kg/時） |
| いまの作業（左上） | 設備ごとに 作業中のロットか設備停止の名前・予定完了（作業開始＋見積）・あと何分／何分遅れ・進み具合の帯・次の予定。作業も次の予定も無い設備は「済み」「予定なし」の札で1行 |
| 本日の予定と実績 | ②のガント（行の名前の下に いまの作業 は書かない＝`nowRow:false`。予定も実績も無い設備も左上が言う） |
| 今月の品種の ABC 分析 | 品種＝用途名 × 縦割り数（丈数）× 横割り数（条数）の3列の組合せ。丈数・条数は「2丈」「3条」の字（軸と表で単位を推測させない） |

- **合計の比**（集計の種類`ratio`・`per`＝割る列）を足した。生産性を1行ずつの比の平均にすると、短い作業の比が効きすぎる。両方が数に読める行だけを足す。
- 良品重量は記録の操業データ「良品重量」→ 仕掛の行の「BOX実績_良品重量」→ 名前に「良品重量」を含む仕掛の列の順（`good_weight()`の1箇所・測定を始めたときの写し）。
  **どの列を良品重量とするかは、利用者の言葉（「良品重量」）と測定画面の換算（`BOX実績_良品重量`）から決めた。現場のデータに別の列があるかは分からない。**
- 「いまの作業」は visual `now`（`_now_one()`）。ガントの行の名前の下にも書ける（`nowRow`）が、既定は左上の1枚だけが言う
  （1〜5回目はガントの行の名前の下に書いたが、主役が小さな字に埋もれた。6回目に左上へ移した）。
- 段は 9（前は 8）。1536×864 でガントの行が線に潰れ、ABC の8品種が切れた（5回目の採点）。ガントの行は 24〜80px（入らなければ「ほか n 台」）、
  ABC の表の行は 17〜36px で下の空きを埋める。
- ABC の設備の札は既定で伏せる（出す項目「設備の札」＝`tabs`）。設備で絞る所が帯と2か所あった（7回目の採点）。パレート図の棒の上に A/B/C の字（色だけで言わない）。
- 前の既定「稼働状況」（§9.64）は2つ目の組み込みとして残す。

## ① 測定実績の列

- **物差し**（`test_acinput`）: 既定で出ている「測定画面で入れた項目」の列の数。**直す前 0/52 → 直したあと 51/51**（見本の設備）。
  結合で写しただけの列が入力した項目より左にある数 0・同じ値の列の重複 0・作業開始の順・見出しで並べ替え。
- 群の使い方はサーバーの`actuals.group_use()`の1箇所（input＝準備で決めた値・操業データ・作業時間／calc＝計算した値／joined＝仕掛・品質から写した値）。
  記録にあってマスタに無い操業データの項目（名前を変えた・消した）も入力した項目の列（値が入っている項目は伏せない・§9.392）。
- 並び: 記録の基本 → 測定画面で入れた項目（作業開始・作業終了・実働が頭）→ 作った値 → 仕掛から写した値（既定は伏せる）。見出しの上の帯が群と列の数を字で言う。
- 選んだ期間に値の無い列は表から外し、帯の「この期間に値の無い列 N　出す ▸」の1押しで出す（5回目は値なしの群として 47 列が横に続き、
  6回目は1列に畳んだが表の右端で切れて読めなかった）。
- 「記録の基本」の群（#〜更新者）は横に送っても残す（`.ac-fix`・席は描いたあとに見出しで測る）。群の途中（ロット番号まで）で切ると帯が割れて
  「記録の基本」が2回出た（8回目の自分の確認）。続きの群の名前は固定の列の右から置く（`stickBand()`）——sticky の`left`に固定の幅を渡すと、
  帯の名前がその約2倍の位置へ出た（実測 528px を渡して 1073px。理由は**分からない**。計算で置く形にした）。
- 並べ替えの印 ⇅ はどの見出しにも（並べている列は「▲ 古い順」）。数の列は見出しも右寄せ。どの列も下限は見出しの字の幅。
- 前は**保存した列の並びを一覧が使っていなかった**（`visibleColumnKeys()`は候補の順のまま）。いまは群の順の中で保存した並び。
- 作業開始・作業終了は 132px で「08:…」と切れていた → 規格の幅（`--w-md`）。伸びる列の下限は見出しの字の幅。数の列は揃えの道具へ「数」と渡して右寄せ（`al-l`が`ac-num`に勝っていた）。
- 帳票の操作の列（行ごとのボタン）は既定で出さない。行を押すと選ぶ・2回押すか行に乗せて出る「帳票 ↗」でその1件の帳票。開き方は帯の「帳票 ⓘ」
  （文で書くと 1536 で帯が3段に折れた・7回目の採点）。

## 画面の作り（E の手順）

途中で利用者が手順を改めた（合格はどの回も80点以上・直した物は自分で画像を確かめてから別のエージェントへ）。各回5案以上、
1728×1152 と 1536×864 で撮り、採点は別のエージェント（採点表は 加点＝わかりやすさ25・視覚化15・美しさ15・統一感10・使いやすさ20・正しさ／読みやすさ15、
減点＝隠れる・切れる・重なる／同じ情報が2箇所／押せそうで押せない／色だけ／大きな空き／1536 で崩れる）。

| 回 | ダッシュボードの最高 | 測定実績の最高 |
| --- | --- | --- |
| 1 | 58（予定完了がいまに張り付く・稼働率の分母に明日） | 69（列が切れる・帳票の列が場所を取る） |
| 2 | 73（予定の枠の作業中） | 70（並べ替えの字が2か所・数の列の間が空く） |
| 3 | 75（予定の無い設備の行が空く） | 76（値なしの列が多い） |
| 4 | 66（後ろの予定がずれない） | 70（値なしの47列・単位） |
| 5 | 68（1536 でガントが線に潰れる） | 70（畳んだ列が切れる・案の違いが小さい） |
| 6 | 71（予定なしが2か所・主役が小さい） | 73（帯が割れる・数の列の空き・帯が3段） |
| 7 | 71（設備で絞る所が2か所・色だけの ABC） | **82（U2・合格）** |
| 8 | **83（T1・合格）** | — |

入れたのはダッシュボードの8回目の T1（既定「生産の状況」そのもの）と、測定実績の7回目の U2（入れた項目の帯を濃い地＋太い上線）。残った軽微な指摘: ガントの下の空き・帯の端の短い線。前後の採点は下の「前と後」。

## 踏んだ誤り

- 見本の測定記録が予定の行に当たらなかった: 予定の行の登録日時が「いま」で、それより前に終わった記録は当てない（§9.612・製品の正しい決まり）。
  さらに当てる鍵は ロット番号・鋳造番号・製造材質 の3つ。撮影の材料だけ、予定を3日前に入れたことにして鍵をそろえた。
- ガントの行を描く関数の中で、変数`c`が棒の色の名前に上書きされていて、「札を下3桁にそろえる」が実績の棒に効いていなかった（自分の画像の確認で見つけた）。
- 変更前の値を測り直そうとして段取りを誤った（⑤の前の位置は構造から報告）。
