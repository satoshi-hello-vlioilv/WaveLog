# §9.353 「選ばれた札の見た目」は1箇所で決める。撮り比べには揺れの床がある

`docs/REVIEW_2026-09.md` §6.3 3-19「部品の族を減らす」の第1弾。**値は1文字も変えない**
（同じ宣言を同じ要素へ当てているだけ）。

## 何が起きていたか

「選んだ札のほうが濃い」（§9.229 ③）を、**族ごとに各自書いていた**。実測:

| 測ったもの | 数 |
| --- | --- |
| 選択中（`.is-on`／`.active`／`[aria-selected]`）の規則 | 168 |
| その規則の根（族） | 110 |
| 宣言セットの種類 | 109 |

**同じ3行（`background:var(--teal)` / `border-color:var(--teal)` / `color:#fff`）を23族が
書いて**おり、7族が縁なし版、4族が淡い面版…と続く。1つ直すと残りとずれる
（§9.229 ②で1族だけ直したときに、そうなった）。

## 決めたこと

1. **宣言セットが完全に一致する族は、`90-state.css`（`@layer state`）の1規則へ束ねる。**
   セレクタをカンマで並べ、宣言は1組だけ書く。9つの型に 60規則が入った:
   濃い面（縁つき23／縁なし7／字は各自4）・紺の面（縁つき3／縁なし4）・
   淡い面（4／字は各自3）・中の字（白6／`--teal-dark` 6）。
   規則は **168→117**。
2. **置き場は `@layer state`。** component 層のどの規則よりも後に効くので、族の側で
   打ち消されない。「選択中の見た目」という**状態**を state 層が持つのは層の定義どおり。
3. **足すときは束ね規則へセレクタを1つ足す。** 族ごとの規則を新しく作らない——
   `test_csslint` が「束ねた型と同じ宣言セットを族が自前で書いていないこと」を見る
   （注いだ3行を数える自己検査つき）。
4. **`:hover` と同居していた規則は分ける**（`.suggest-chip:hover,.suggest-chip.active`）。
   `:hover` は元の場所に残し、`.active` だけを束ねへ移した。

## 撮り比べには揺れの床がある（この回の一番の収穫）

`tests/visual` の base↔head は **9枚が相違・最大35画素（0.003%）**。すべて `f5f7f7→f6f8f8`
のような**1階調の差**で、文字やアイコンの縁のアンチエイリアスだった。

「1画素も変わらない」を確かめるつもりが**0にならない**ので、**同じコードで2回撮って比べた**:
**47枚中11枚が相違・最大1,767画素（0.104%）**。つまり撮り比べには床があり、
**その床は今回の差より1桁大きい**。だから「束ねによる見た目の変化は無い」と言える。

- **再実行で緑になったからフレーク、で片付けない**（§9.200）——**床を測ってから比べる**。
  床より小さい差は「同じコードでも出る差」で、床より大きい差だけが変更由来。
- §9.350 の1回目（47枚全部が相違・最大63%）は床の**数百倍**だったので、迷う余地が無かった。
  今回のように床に近い差が出たときこそ、床を測る。

## 網が守っていること（注入で確かめた）

束ね規則を消すと `test_oppad` の「選んだ札は面か濃い文字で先に立つ（選んでいない札に
負けない）」が落ちる。ただし**落ちるのは1件だけ**——23族のうち画面の網が見ているのは
一部で、残りは `test_csslint` の「族が自前で書かない」だけが守っている。
**束ね規則からセレクタを1つ落としても、多くは静かに素の見た目へ戻る。**

## まだやっていないこと

REVIEW の 3-19 は「共通クラス（`.wl-tabs`／`.wl-steps`／`.wl-seg`）を作り、各画面の要素へ
**追加する**」まで書いている。そこは**寸法（余白・角丸・高さ）も揃う＝見た目が変わる**ので、
利用者へ確認してから。ここまでは CSS だけで、HTML/JS には触っていない。
