# §9.396 入力内容を「母材 ⇔ 製品」の階層にし、葉の呼び名を量へそろえる（利用者の指摘）

利用者の指摘（原文）:

> **丈毎ってネーミング粒度というか階層というかレイヤーが違う言い方のような
> 気がして、何か良い言い方ないでしょうか？**
>
> **測定値に対するネーミングの方が入力内容、測定内容としては階層が一致する
> ように思います。そのあたりのアイデア無いですか？母材も一緒。**
>
> **実際に階層を作ってボタン化するのはアリかも。ネーミングと共にデザイン案
> 作ってキャプチャで見せて**

## 1. 何が「層が違った」のか

②測定の「入力内容」は9項目を**1列**に並べていた。分解すると3つの層が
混ざっている。

| 項目 | 言っていること | 「〇〇を入れる」と言えるか |
| --- | --- | --- |
| `母材` | 測る**対象物**（コイル1本） | ✕ |
| `丈毎` | 数える**単位・頻度** | ✕ |
| 板厚・板幅・ラテラルボー・バリ・テレスコープ・巻ずれ・フラットネス | 測る**量** | ○ |

しかも件数の分母が **1／4／18** と項目ごとに違うのに、**その理由が画面の
どこにも出ていなかった**。「丈毎」という語が違和感を出していたのは、
**この違いを1語で背負わされていた**から。

**解き方**: 層の言葉は**群の見出しへ上げ**、並ぶボタンは**量だけ**にそろえる。

## 2. 母材の相手は「製品」——コードが既に持っていた対

利用者の指摘「母材と同じ作業後の製品（ライン内での作業後のワーク）を表す
言葉を持ってこないといけない感じもあります」を受けて実ファイルを当たると、
**内部名がもともと対を持っていた**。

| 側 | コードの名前 |
| --- | --- |
| 作業前 | `m.mother` ／ `data-mother` ／ `motherKeys()` |
| 作業後 | `m.product.rows` ／ `PRODUCT_CHOICES` ／ `productLength` ／ `blankProductRow()` ／ `rpShowProduct` |

さらに **丈＝縦割数（`verticalCount`）・条＝横割数（`horizontalCount`）**で、
測定値は `measurements[項目][丈位置][条]` の**2軸のマス目**。つまり
**丈と条は並列の群ではなく、「製品」の下の2つの単位**。3群フラットは
この関係を平らに潰していた。

## 3. 決めた形（3層）

```
母材 │ コイル1本ごと ──────────
     │   [ 全長                     済 ]
     │     手計算・MIN/MAX・前後オフ
─────┼─────────────────────────
製品 │ 丈ごと ────────────────
     │   [ 寸法・外観              2/4 ]
     │     長さ・肉厚・外観・巻ズレ・エッジ・備考
     │ 丈位置 × 条ごと ───────────
     │   [ 板厚 ][ 板幅 ][ ラテラルボー ]…
```

- **左のラベル列＝群（もの）**、**右の小見出し＝単位（分け方）**、その下が**量**。
- **顔ぶれと並びは `WL.measureItem.GROUPS` の1箇所**が持つ。`ALL` と食い違わ
  せないこと（`tests/test_msteps.js` が見張る）。
- 設備で伏せた項目（§9.392）が群ごと消えたら、**その小見出しも出さない**
  ——見出しだけ残ると「押せるものが無い行」ができる。

**ラベル列の幅は群の名前で決まる**（`母材`/`製品`＝2文字→ `--fs * 2.6` ＝36px）。
単位を左へ置くと `丈位置×条ごと` の7文字が幅を決め、**チップが 262→211px まで
痩せる**（実測）。単位を右の小見出しへ出したのはこのため。

## 4. 葉の呼び名は「発明しない」

| 旧 | 新 | 根拠（実ファイルから） |
| --- | --- | --- |
| `母材` | **`全長`** | 母材カードの**入力欄8つがすべて長さ方向**（手計算・全長・MIN・MAX・前後オフ×4）。元幅・屑幅・計算全長は `<output>` で入力欄ではない |
| `丈毎` | **`寸法・外観`** | 丈の表の**入力列7つが2系統**——寸法（長さ・肉厚）と見た目（外観・巻ズレOS/DS・エッジ形状）。判定は自動 |

**`丈毎` は語として消える。**「毎」＝単位の意味は見出しの `丈ごと` が引き受ける。
`母材` は**群の名前として生き残る**（消えたわけではない）。

撤回した候補: `仕上り`（広すぎて何も絞らない——板厚も板幅も「仕上り」）、
`出来ばえ`（良し悪しの判断を含む語。ここに入るのは測った値そのもの）、
`品位`（見た目の等級を指し、長さ・肉厚を覆えない）、
**名前を付けず中身を全部並べる**案（`長さ・肉厚・外観・巻ズレ`＝12文字。
実測で md は余り23px だが **lg で1px 溢れて `…` になり**、しかも
「エッジ形状・備考」まで入らないので**言い切れていない**）。

## 5. 2行チップ——名前と中身を同じ行で競わせない

幅が足りない原因は「名前」と「中身」を1行に並べたことだった。**行を分ければ
両方出せる**。1行目＝他の7項目と同じ長さの量名＋件数、2行目＝その面で入れる
欄の顔ぶれ（`WL.measureItem.DETAIL`）。

**2行にするのは `DETAIL` を持つ2つだけ。** 条の7つは名前がそのまま量なので
書くことが無く、無理に足すと「条1〜9」を3回繰り返すだけになる（規則8）。
実測でも**9項目すべてに副題を付けると器から溢れる**（md 11px・lg 40px）。

## 6. マウスを乗せたときだけ起きること

| | すること | なぜ |
| --- | --- | --- |
| ① | **1px 持ち上げて影** | 「押せる」を**動き**で言う。色覚に依存しない |
| ② | 同じ単位の**仲間がまとめて薄く光る**（小見出しの文字と罫線もティールへ） | 「この7つは丈位置×条ごとの仲間だ」という**階層そのものを体験で教える**。説明を読ませずに構造が伝わる |

**淡さが命（9%）。** 濃くすると「選ばれている」と誤読され、選択中のチップの
枠（`is-current`）と競う。色は `color-mix` でトークンから作る——`rgba()` の
リテラルを増やさない（§9.350）。

## 7. 保存値も移す。旧綴りは**両側**で読み替える

§9.391 と同じやり方（保存値そのものを新しい綴りにし、`LEGACY_*` で吸収）。
コードに `丈毎` を残すと、次に読む人が**画面と DB で違う語を見る**ことになる。

- 画面: `WL.measureItem.LEGACY_MATERIAL` に `母材`、`LEGACY_PIECE` に `丈毎` を足す。
- サーバー: `MEASURE_ITEM_ALIASES` を新設。**設備マスタの `無効入力内容` は
  知らない綴りを黙って捨てる**ので、読み替えないと「外してあったはずの項目が
  復活する」という**遠い壊れ方**をする。

## 8. 踏んだ罠: 詳細度で負けて、名前と件数が中央へ寄った

`.type-chip--two{align-items:stretch;justify-content:center}` を
`30-measure.css` に書いたが、`.type-chip{align-items:center;justify-content:
space-between}` は `70-schedule.css` にある。**詳細度が同じなら後に読まれる
70が勝つ**ので、2行チップだけ名前と件数が縦の中央へ寄り、両端に分かれ
なかった（実画面のキャプチャで気づいた）。器を頭に付けて
`.mt-ug .type-chip--two` にする。

**同じ器の中で既存のクラスの宣言を上書きするときは、詳細度を必ず確かめる。**

## 9. 測った値（実測・表示サイズ md／lg）

| | md | lg |
| --- | --- | --- |
| ラベル列 | 36px | 40px |
| チップ幅 | 262px | 258px |
| 器の埋まり方 | 432/464＝93% | 463/464＝99.8% |

**器はほぼ満杯**。利用者は「詰める方向ではない」を選んだので、このまま入れる
——ただし**項目を増やすときは器の高さから先に考えること**。詰め手は測って
ある（小見出しを1本に減らすと 391/464＝84%、条を2列にしてラベル列を廃すと
308/464＝66%。ただし2列はラベル列を残したままだと**チップが127pxになり
「フラットネス」が切れる**）。
