# §9.68 パス設定を設定ページ形式へ / データ引継ぎの「現状→実行後」

**パス設定が下部で見切れて触れない**

マスタ管理の画面は「上部フォーム(追加・編集) + 下部一覧」という形をしている。
パス設定はこの形に載せていたが、中身は一覧を編集するマスタではなく
**設定画面**で、説明・9項目・RNE抽出の状態パネル・保存ボタンを全部
`.mm-form`へ入れていた。`.mm-form`はスクロールを持たないため、
`.mm-panel{overflow:hidden}`に切られて**下部が見切れ、保存ボタンごと
触れない**状態だった(スクロールバーも出ない)。

設定ページ形式(`.mm-form-page`)を用意して作り直した。

- フォーム自体を`flex:1;min-height:0`にし、中の`.mm-set-scroll`が
  **1本のスクロール領域**になる。下段の一覧枠は畳む
  (`.mm-form-page+.mm-list-wrap{display:none}`。畳まないと`flex:1`同士で
  高さを半分ずつ分け合い、設定側が不必要に狭くなる)。
- **`.mm-set-scroll>*{flex:none}`は必須**。縦並びflexの子は既定で縮むため、
  これが無いと各グループが枠内へ押し込まれ、`overflow:hidden`で入力欄ごと
  切り取られる(スクロールも出ない — 中身が縮んで収まってしまうため)。
  実際にこの状態を一度作ってしまった。
- 項目は「何のための設定か」でまとめ、**反映のタイミングを見出しに出す**。
  データの取得元／共有・複製＝「サーバー再起動後に反映」、RNE抽出／
  スケジュールの排他制御＝「保存後すぐ反映」。「保存したのに変わらない」
  の原因が再起動待ちであることを、触る前に分かるようにする。
- 保存ボタンは`position:sticky`で下端に貼り付け、どこまでスクロールしても
  押せる。
- 「保存値」と「いま効いている値」の対比表を同じスクロールの中へ入れ、
  食い違う行に「再起動待ち」を出す。**判定は表示文字列ではなく生の値で
  行う** — 表示側は現在値にエンジン種別「（sqlite）」を添えたり、未設定を
  「（既定）network」と書き換えたりするため、文字列比較では中身が同じ行まで
  再起動待ちに見えてしまう(実際にそう出た)。保存値が空＝既定を使う指定
  なので待ちにはしない。

**データ引継ぎで「今どうなっていて、実行するとどうなるか」を見せる**

PC引継ぎ専用の、取り消せない操作。以前は「取込先(新規/上書き)」と
「端末内(有り/無し)」が別々の列にあり、2列を突き合わせないと変化が
読み取れなかった。

- 上部を「**いまの状態** → **選択中の操作で起きること**」の2欄にした。
  左は件数(バックアップ総数・この端末にも有る・無い・取込可能な形式)、
  右は選択に応じて**実行前に**結果を言葉で出す(選択が空なら出さない)。
- 「この端末へ取り込む」と「バックアップから削除」は結果が正反対なので、
  右欄では**両方の結果を別々に**示す。取り込み＝新規追加/上書きの件数、
  削除＝バックアップから消える件数とスケジュール実績への影響、そして
  「この端末のデータ一覧は変わらない」ことまで書く。
- 行の列も「いまの状態 → 取り込むと」の1列に統合し、
  「端末内に無し → 新しく追加」「端末内に有り → 上書きされる」と読める形に。
- ボタンは色と仕切りで分ける(取り込む＝primary / 削除＝danger)。
  隣り合わせで同じ赤にすると押し間違いが起きる。
- 取り込みの確認をブラウザ標準の`confirm()`から共通の確認モーダルへ移し、
  新規/上書きの内訳を箇条書きで示す(§9.61の実績削除と同じ作法)。
