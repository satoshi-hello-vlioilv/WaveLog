# §9.191 コメント枠のD&Dとその場編集／紙の書き込み欄のパターン（利用者の指示）

利用者の指示: 「D&Dでコメント枠だけ追加、コメントする場合はスケジュールに
配置されたコメント欄をダブルクリックなどで編集モードに移行し入力したコメントを
入力するように使う。スケジュールの内容記入の枠もありなしが選べるようにして
ください。また、開始、終了での入力欄ではなく、備考という形での枠設定や、他
カスタムできるパターンを追加して、メニューもわかりやすくしてほしいです」。

**① 空の枠を落としてから書く。** コメントの入口（`#scCommentBtn`）を
**掴めるようにした**（設備停止のD&Dと同じ`dragstart`のハンドオフ）。落とすと
その位置へ**中身が空のまま**1行入り、そのまま編集に移る
（`scState.focusComment`を`renderTimeline()`の最後で拾う。書込後の`loadPlan()`で
描き直されるので、落とした直後に入力欄を作っても消える）。
**空のコメントを拒まないこと**——先に枠を置いてから書く、というのがこの指示の
中身なので、`plan_add`は`kind='コメント'`に限り空の本文を通す。

**② 置いたコメントはダブルクリックで直す。** 行の中に`textarea`を出して
その場で書き換える（Enterで確定・Escで取り消し・外れたら保存）。
ダブルクリックの割り当ては`canResume`→`canReport`→コメントの順で、
**どれにも当たらない行には「なぜ何も起きないか」をtitleで書く**。
書き換えは`plan_update`の`title`（`[予定名称]`）で、**コメント以外の種別では
repoが弾く**。**編集中は勝手に読み直さない**（`canAutoReload()`に
`scState.editingComment`を足す）——10秒ごとの見張りに入力欄を消されると、
書いている途中の文字が消える。時刻の動かない更新（本文だけ）では
`loadPlan()`まで戻さない（`opShiftsTime()`）。

**③ 紙の書き込み欄はパターンで選ぶ。** 「開始/終了」の2欄で固定だったのを、
**5つのパターン＋自由**にした（実績（開始・終了）／実績＋備考／備考だけ／
チェック欄／書き込み欄なし／自分で選ぶ）。プレビューの設定欄も
**「載せるもの」と「書き込む欄」の2つに分けた**——同じ場所に混ぜていたため、
どれが紙の列でどれが手書き欄なのかが読めなかった。パターンはラジオの
カードで、**選んだ瞬間に刷り上がりが変わる**（§9.186）。

固定は`tests/test_sccomment.js`・`tests/test_scprint.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **コメントは「枠を置いてから書く」**（§9.191、利用者の指示）: 入口
  （`#scCommentBtn`）は**掴んで落とせ**、落とすと**中身が空のまま**枠が入り、
  そのまま書ける状態になる（`scState.focusComment`を`renderTimeline()`の
  最後で拾う。書込後の`loadPlan()`で描き直されるので、落とした直後に入力欄を
  作っても消える）。**空のコメントを拒まないこと**（`plan_add`は
  `kind='コメント'`に限り空を通す。モーダルから入れるときは今までどおり必須）。
  置いた枠は**ダブルクリックでその場編集**（Enter確定・Esc取消・外れたら保存）で、
  **編集中は勝手に読み直さない**（`canAutoReload()`に`scState.editingComment`）。
  書き換えは`plan_update`の`title`で、**コメント以外の種別はrepoが弾く**。
  紙の**書き込む欄はパターンで選ぶ**（`WRITE_PATTERNS`）。**既定は
  `actual`＝実績を書いてもらう（開始・終了・確認の3欄）**——紙専用の列選択が
  無くなった（§9.235 ①）ので、以前の「紙の列で決めたまま」という既定の
  言い方は成り立たない。挙動そのものは変えていない（紙専用の列選択を
  触っていなかった設備では、以前もこれと同じ3欄が出ていた）。旧い保存値
  `'custom'`は読むときに`actual`へ読み替える。
  固定は`tests/test_sccomment.js`・`tests/test_scprint.js`。
