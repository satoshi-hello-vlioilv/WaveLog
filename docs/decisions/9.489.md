# §9.489 元データの列にも「この列の作り方」の式——計算列は「式を持ち、画面のデータに無い名前の列」（利用者の指示）

索引: [決定記録](README.md)

## 経緯

利用者の指示「表示列の編集機能で、すべての列で同じように機能があると思っていましたが、実は元データのところには
計算列と同じような項目は出ていないことが分かったので、元データのところでも、『この列の作り方』と書いてある項目の
計算式を入力することができる機能をすべて搭載してほしい」。

列の設定パネルは「式を持つ列＝計算列」と見ていた（§9.111 ⑦）。元データの列に式の段は出ず、`WL.listRules`の
「式にする」も「元のデータの列は式を持てないため」別の列を作っていた。

## 測って分かったこと（直す前・`tests/test_colsrcfx.js`）

| 物差し（4画面: 仕掛一覧・作業スケジュール表・測定実績・測定データ一覧） | 前 | 後 |
| --- | --- | --- |
| A 元データの列を選ぶと「この列の作り方」の欄が出る | 0/4 | 4/4 |
| B 元データの列の式が表のセルに出る | 1/4 | 4/4 |
| C 式を空にすると元の値に戻り、列が消えない | 3/4 | 4/4 |
| D 測定実績の**計算列**のセルに式の結果が出る | 空 | 出る |

B・C・D の内訳（網が見つけた、パネルの外の穴）:

- **仕掛一覧のロット番号**・**データ一覧の状態**は専用の描き方で、式を通っていなかった（状態は「何も設定していない
  列は既定の短い字」の判定に式が入っていなかった）。
- **作業スケジュール表**は「式を持つ＝計算列」で、式を空にした内容欄の項目が**空欄の計算列**になった。さらに保存時、
  式を持つ項目を内容表示マスタから外していたので、**元データの列に式を入れて保存するとその列が消える**。
- **測定実績・操業データの紙**は式を当てる道が無く、以前からの**計算列も空**だった（D）。

## 決めたこと

- **計算列＝式を持ち、かつ画面のデータに無い名前の列**。データの列かは画面が口で答える（`isData`・5画面）。
  答えない口は今までどおり「式を持つ＝計算列」。
- 式の段を出すのは計算列と**元データ・結合の列**（番号・ボタン・画面が作る列＝計算・操作は持たない）。
  元データの列では: 見出しの添え書きは「元の値を式で作り直します（空なら元の値のまま）」、空の式は誤りでない、
  自分の名前も式の候補（元の値を`[自分の名前]`で読む）、「この列を削除する」は出さない、式を空にしたら鍵ごと外す
  （NULL＝式なし。''は「式が空の計算列」・§9.234 ⑥）。左の一覧に「式」の札（計算列は分類が言うので付けない）。
- 行のその列の値は**`WL.cellFormat.rawOf()`の1本**（式があれば式の結果・無ければ行の値）。測定実績・操業データの紙が通す。
  式は元の行を読むので、自分を読んでも巡らない。式を解く控えは`fx()`の1箇所（`viewOf`と共有）。
- 作業スケジュール表: 計算列の見分けも内容表示マスタへの保存も`scContentDataSet()`（出している項目＋選べる項目）の1箇所。
  セルごとの判定は1行につき1回作る集合（`calcKeys`）で見る。
- 並べ替え・絞り込みは**元の値**に対して行う（計算列と同じ。段の説明にそう書く）。
