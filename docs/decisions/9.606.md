# §9.606 起動画面は段を順に1つずつ・版を上げる／戻すを言い分ける／現場段取りの並べ替えの関門をそろえる／クリアランス2桁／ラテラルボー判定／Enter で次の欄／品質メモ（利用者の指示・7項目）

索引: [決定記録](README.md)｜前: [§9.605](9.605.md)｜関係: [§9.138](9.138.md)・[§9.394](9.394.md)・[§9.555](9.555.md)・[§9.561](9.561.md)・[§9.580](9.580.md)・[§9.588](9.588.md)・[§9.592](9.592.md)

## 経緯（利用者の言葉）

> １）アプリ起動時の、版を戻すときと版をアップデートするときでメッセージを変えたり、起動時のアップデートしていることがもっとわかるような表現と、ステップの中で同時に2つぐるぐるしたり、手戻りがあるような動きに見えたりするような表現をわかりやすく秩序の見えるステータス表示に変えてほしいです。
> ２）設備作業者で段取り可の状態で厳密モードの時、並び替えができない不具合が発生しています。（略）並び替えはマスタの権限設定に応じて正しく設定されているか確認し修正をお願いします。
> ３）スリットクリアランスの入力桁数を小数点以下2桁に修正
> ４）ラテラルボー基準判定が不安定。別のタブから戻ってくるとNG表示される現象がありリフレッシュのタイミングなど表示が安定していない。NG後に正しい値を入れても再判定してくれない。
> ５）入力項目の移動をENTERキーでもできるようにしてほしい。
> ６）品質情報の下に入力できる欄を設けたい。
> ７）板厚と板幅を同じ項目に入れて同時に入力できるようにしたい。（7案を見せる・利用者が選ぶ）

## 1. 起動画面（desktop/splash・`test_splashorder`）

窓は版の確かめと Python の起動を**同時に**進める（§9.561）。起動画面は届いた順に塗っていたので、更新が見つかると
済んだ「版をそろえる」が回り直し、「アプリを起こす」と**同時に2つ**回り、帯が 20%→0% に戻っていた。

| 物差し（6場面を窓の順のまま流す） | 前 | 後 |
| --- | --- | --- |
| 同時に回る段の数（最大） | 2 | 1 |
| 手戻り（済んだ段が回る・帯が下がる） | 4場面×2件 | 0 |
| 上げる／戻すの言い分け | なし | あり |
| 写している間に前後の版が見える | なし | あり |
| 窓ごと開き直した新しい窓 | 0% からやり直し | 済んだ更新から |

- **いまの段だけを塗る**（`take()`）。後の段の知らせは控え（`pending`）、前の段が済んだら当てる。済んだ段へ後から来た知らせは
  title にだけ残す。帯は下げない（`paintPct` は最大値）。後の段の**失敗**だけは待たせずその段に出す。
- 版の段は形のある知らせ `splash.version({phase,…})`。字は起動画面の1箇所（`WORD`・`DOING`）。確かめの答えは**その場で**言う
  （`peek_in_background` の糸が送る。前は Python の起動を待ってから言っていた）。向きは `update::direction()`（数で比べる）。
- 更新が見つかったら版の段に帯の 0〜40%（`UPDATE_PCT`）を配る。止める前の Python の控えは捨てる（新しい版の起動へ持ち越さない）。
- exe ごと変わって開き直すときは `--updated <前> <新>` を渡し（`launch::relaunch`）、新しい窓は「済んだ更新」から続ける。
- 写す進み具合は `update::Step`（Copy／Swap）の型で渡す（字を窓で組まない）。
- 見た目は5案×2回を別の採点者が採点した（1回目 最高81点・2回目 r2 96点を採用）。入れた後の採点は 44点→93点→（指摘5点を直して）98点。
  採用した形: 見出しだけが向きを言う（地の無い ↑／↓ の字の印＋「新しい版へ更新しています」「前の版へ戻しています」）・見出しの下の
  版の行は最初から高さを取る（「いま 2.497.0」→「2.498.0」の角丸の札・戻すときは行き先の札が灰）・段の名前は向きと関係のない
  「版をそろえる」・写した数は段の説明に（帯の右は全体の %・物差しを1つに）・見出しの字と版の行と段の名前の左端を1本に（22px＋12px）。
  撤回した案: 段の中に小さな段（回る印が2つになる）・左のブランド面に版（目が往復する）・2つの箱の図（入力欄に見える）・戻すときに
  帯まで灰（「使えない」に読める）。

## 2. 現場段取りの並べ替え（`test_strictreorder`・`test_fieldreorder`）

**再現の条件（設備作業者・編集可・段取り可・対象設備＝その設備・厳密モード）では、直す前から並べ替えできた。**
厳密モード・区分を理由に止める判定はコードのどこにも無い。止まる道は「対象設備」の関門なので、そこを測った。

| 物差し | 前 | 後 |
| --- | --- | --- |
| M4 画面（`WL.fieldReorderAllows`）とサーバー（`field_reorder_equipment_allows`）の答えが食い違う組（12組） | 5 | 0 |
| M5 並べ替えできない端末で「並べ替えてください」と言う鍵の開始 | 29/29 | 0 |
| M6 設備を改名した後も段取りの権限が残るか | 消える | 残る |

- 画面も NFKC＋大文字で畳む（全角・半角の違いで画面だけ「できない」と答えていた）。
- アクセス権限マスタの `[現場段取り対象設備]` を改名の追従（`equipment_name_references()`）へ足した。
- できない理由は `reorderDeniedWhy()` の1箇所（鍵の開始の説明・掴んだときの断り）。アクセス権限マスタの一覧は、段取り可でも効いて
  いない行を「可 → 効いていない（対象設備が未設定／編集可否が閲覧のみ）」と言う（答えは `permission_capabilities()`）。
- **利用者の端末で何が止めていたかは分からない**（推測で埋めない）。候補は対象設備の未設定・綴りの違い・改名の3つで、どれも直した。

## 3. スリット クリアランス 2桁（`test_seedrevise`）

0.13 と打つと 0.1 で記録されていた（種の小数桁 1）。種を 2 にし、既存のマスタは `SEED_REVISIONS`（前の種の値のままの行だけ・
パス設定マスタの印で1度だけ）で上げる。最初は「改めた日より前に更新された行」で1度だけを作ったが、網が「今日が区切りより前なので
2回目も当たる」ことを捉えた。同じ役目は母材の欄（§9.232）がパス設定マスタの印で持っていたので、そちらへ寄せた。

## 4. ラテラルボーの判定（`test_lateraljudge`）

| 物差し | 前 | 後 |
| --- | --- | --- |
| L1 正しい値へ打ち直しても残る NG の札 | 1 | 0 |
| L3 描き直しの途中に別の項目の公差で判定された欄 | 1 | 0 |
| L4 基準（指示_ﾗﾃﾗﾙﾎﾞｰ）が後から届いても判定し直されない欄 | 1 | 0 |

- 判定は**欄の項目**で基準を引く（`WL.measureItem.typeOfKey`）。いま選んでいる項目（`#measureType`）で引いていたので、描き直しの
  途中に板幅の公差で判定され、別の画面から戻った瞬間にラテラルボーが NG になっていた。
- NG の札は `judgeInput()` が打つたびに付け外す（描くときしか作っていなかった）。札を持つのは描いたときにいま測る列の欄（`.is-judged`）。
- 仕掛の完全な行が後から届いたら `afterSourceRefresh` で判定と見出しを出し直す（`rejudgeInputs()`・表を作り直さない）。

## 5. Enter で次の欄（`test_entermove`）

測定画面の入力欄 45 のうち 37 が Enter で進まなかった→0。`WL.base.enterMoves(root)` の1箇所。Enter を自分で使う欄（測定表の
「次の条」・候補の器・変換中・測定器の受信欄 `data-enter-own`）からは奪わない。受信欄を外さないと、自動転送の区切りの Enter で
焦点が移り、続きの転送が行き場を失う（§9.122）。

## 6. 品質メモ（`test_qualitynote`）

専用の欄を作り込まず、操業データ項目マスタの置き場を1つ足した（`PLACE_QUALITY`＝「品質情報の下」・器 `#qualityOpGrid`）。
最初の1欄「品質メモ」（文字・12マス）はパス設定マスタの印で1度だけ置く（消せば戻らない）。群が1つだけなら群の見出しを出さない
（すぐ上の「品質情報」と重なる）。

## 7. 板厚と板幅を同時に入れる — 7案（利用者が A の表＋F の振り分けを選んだ・実装は [§9.607](9.607.md)）

§9.138 で分けた理由（進捗の合算・枠の数の違い）を解く形で7案を作った（A 上下2段の表・B 左右2枚・C 丈位置ごとのカード・
D 断面図の上に欄・E 1行＝1丈位置・F 測定器で振り分け・G 次の1枠を大きく）。比べるページで利用者に見せ、選ぶのを待つ。
