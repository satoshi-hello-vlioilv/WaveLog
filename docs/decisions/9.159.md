# §9.159 条の色を並び順から切り離す・押した結果を返す・基本情報の余白・判定公差を畳む

v2.56.0を実機で確認した利用者からの4件。

#### ① 条の設計

**色はロット番号だけで決める。** `splitLotColorMap()`は`sources`の、
`appliedLotColorMap()`は`groups`の**添字**で色を配っていた。どちらも並び順に
依存するので、**条を1つ動かすとロットと色の対応が入れ替わる**——図・測定表の
ロット列のバッジ・幅分割パネルの丸が同時に別の色になった（実機で報告
「D&Dで入れ替えた瞬間色味が変わる」）。色は「どのロットか」を指す印なので、
並びで変わってはいけない。ロット番号を**辞書順**に並べて配る
（`WL.lotColors.map()`の1箇所）。基本情報の「分割ロット」も同じ順にしたので、
色の並びと文字の並びが一致する。

**配色は彩度を一段落とした8色**にした（利用者の指示「色彩が少しきついので
調和しやすいカラーコーディネートで」）。原色（#dc2626・#2563eb 等）を並べると
図が騒がしく、**公差外の赤・掴んでいる印といった「意味のある強い色」が
埋もれる**。異常位置判定の図（§9.101）は先にこの配色へ移してあり、
**同じロットが2つの画面で違う色**になっていた——`defect-locator.js`が同じ趣旨の
配列を自前で持っていたため。配色は`lot-split.js`が持ち、`defect-locator.js`は
`WL.lotColors`を見る。

**押した結果を画面に返す。** タップは並びを変えないので、返すものが無いと
「反応しない」と読まれる（利用者の指摘「クリックしてもどれをクリックしたか
わからない」）。押した条へ`is-selected`を付ける。印は**内側**に描く
（`box-shadow:inset`）——`outline`にすると絶対配置で並ぶ隣の帯が上に来て、
印の片側だけが消える。並べ替えたら選択は動いた先へ付いていく。

**説明の行を増やさない。** 押した条の説明（`#splitVisualDetail`）は図の下の
独立した行で、`hidden`で畳んでいた。そのため**押すたびに行が1本増え、図が
24px縮んでいた**（実測201px→177px。「クリックしたら条の図形のサイズが変わる」）。
操作の案内（`#splitVisualHint`）と同じ1行を使い、選ぶ前は案内・選んだ後は説明を
出す。どちらも1行なので高さは動かない。

**OS／DSは軸の名前であって帯ではない。** 面と角丸を与えていたため、隣の屑帯
（同じ灰色の四角）と同じ種類のものに見えていた（「屑条みたいな見た目のバッジで
わかりにくい」）。塗りを外して文字だけにし、図に接する側へ細い縦線を引く。
読み方（オペレータ側／駆動側）は30pxの器に入らないので、図の下の案内に文で書く。

#### ② 基本情報

**「分割ロット」は重複を落として並べる。** 材料の`splitGroups`は「連続した
区間」なので、同じロットが離れて置かれると`A・B・A`と2度出ていた（実機で
「N526C52・N526C53・N526C51・N526C53」）。ここが答えるのは「何と何に分かれるか」
であって並び順ではない（並び順は図が持つ）。

**ラベル列はいちばん長いラベルの実寸から決める。** `6em`／`7em`と書いてあったが、
**ラベルは`--fs`(14px)で描かれている**——`30-measure.css`が`--fs-micro`を指定して
いるのに、後から読まれる`40-records.css`の`.field label{font-size:var(--fs)}`が
同じ詳細度で勝つ。効かない指定を前提に幅を計算すると必ず外す（`--fs-micro`基準の
68pxにしたら6文字のラベルが省略記号になった）。`--w-info-label`＝
`calc(var(--fs) * 6.2)`の1本にし、**詳細だけ`7em`という2種類目をやめた**
（2種類あると詳細を開いた瞬間に値の左端が14pxずれる）。

**列数は中身の長さで決める。** 識別番号・製品（鋳造No.・オーダーNo.・引当No.・
用途コード・取引先・納入先）は2列に割ると値へ渡せる幅が94pxしか無く、実データの
会社名はほぼ必ず切れていた。この6項目は全幅にする（値へ288px）。値が短い品質規格
（「2C」「3」）は2列のまま。

**品質情報は縮む側にしない。** `flex:1 1 auto;min-height:0`だったため、詳細を
開いて中身が器を超えると**このブロックが先に潰れて高さ9pxになり**、しかも潰れた
ぶんペインのスクロール量も増えないので**下まで送っても出てこなかった**
（実機で「品質情報が見れなくなる」）。`flex:1 0 auto`（余りは受け取るが縮まない）
にすると、溢れたぶんはペインのスクロールになり下まで送れば読める。

#### ③ 判定公差の切り替え

**選べるときも、開くまでは出さない**（利用者の指示「折りたたんで通常非表示に」）。
既定は製造公差のままでほぼ触らないのに、測定中いちばん見る帯に選択欄が常設されて
いた。いま効いている公差はヘッダーの文脈バーが「判定公差 製造公差」と常に言って
いる（§9.129「同じ情報を2箇所に出さない」）ので、ここに要るのは「変えたいときの
入口」だけ。**消さずに畳む**——切り替えは業務で必要な操作なので、1回押せば必ず
出せる場所に残す。

#### ④ 入力内容

**②では`#measureTypeGroup`のラベルがカードの題**として読まれるのに、色も大きさも
本文のままだった（実測 #60747b/14px/400、カードの題は teal/15px/800）。題名は
`<label>`直下のテキストノードなので器そのものへ題の意匠を与える——中の部品は
自分で色と大きさを宣言しているので巻き込まれない。

**選んでいる項目の印を外側に描かない。** `outline:2px`＋`outline-offset:1px`は
要素の外3pxへ描かれるため、器いっぱいに並ぶ一覧では**選んだ1つだけがカードの
内側の縁を越えて**いた（実測2px。利用者には「ボタンがカードからはみ出している」と
見えた）。内側の枠にすれば箱の大きさは変わらない。あわせて幅を中身から決めて規格へ
丸めた（必要133px→`--w-xl`＝308px。`--w-md`(154px)まで詰めると押す的として
小さすぎる）。`em`は器の文字で解かれるので、題として`--fs-title`を与えた器の中では
`--fs`へ戻してから使う。

#### 網

固定は `tests/test_splitlive.js`（色の安定・押した結果・OS/DS）と
`tests/test_msteps.js`（分割ロット・ラベル列・品質情報・入力内容・判定公差）。
**検証用データは重なっていない**ので、分割ロットの重複は`splitGroups`へ
`B→A→B`を注ぎ込んで確かめる（注がずに見ると直す前でも通る）。判定公差も
オーダー公差が1件も無いため、材料を入れてから見る。

**素通りに注意した2点。**
- 図の色は候補の控え（元の順のまま）から来るので、**添字で配る実装へ戻しても
  図だけは動かない**ことがある（実際に注入して確かめたら、落ちたのは測定表の
  バッジ側だけだった）。配る関数`WL.lotColors.map()`を直に呼んで、順番に
  依らないことも見る。
- 説明欄の行を`hidden`で畳む実装へ戻す注入は、**HTMLの位置を戻さないと再現
  しない**（JSだけ戻しても操作の行の中にいるので高さが動かない）。

あわせて、**HEADの時点で落ちていた4件**を直した（どれもこの変更とは無関係の
「決めごとを変えたときに一覧を直し忘れた」もの）。
`test_maint`の「基本情報は常時8項目」は分割が無いロットでは5項目が正しい
（§9.144で分割ロットの行を出さないと決めた）ので、数ではなく項目名で見る。
「意味のかたまりで見出し」は§9.154で品質規格の群を足した時点で4つになっている。
`test_course`の「コース欄は全幅を使う」は`fullWidth>gridWidth*0.7`という割合の
しきい値で、**ラベル列を98px→87pxと狭くして値を広げた変更で落ちた**
（210/316=66%も221/316=70.0%もどちらも全幅の行）。**器の右端に届いているか**で
見るよう書き換えた。
