# §9.144 ①の骨子改訂と品質情報の面（実装）

利用者から①の割り付けそのものの変更指示が出た。

> 基本情報1×3(左)、条の設計の視覚化表示3×1(中央～右)、準備の入力1×2(中央下)、
> 条の設計の詳細ロット情報2×2(右下)に変更。品質規格はタブに回し、品質情報を
> 基本情報に移動。条の設計は2分割して配置、条割を実行ボタンは廃止して
> リアルタイム変更とする。

| カード | 位置 | 中身 |
|---|---|---|
| 基本情報 | `1×3`（列1・行1〜3） | 識別8項目＋公差＋**品質情報の本文** |
| 条の設計・視覚化 | `3×1`（列2〜4・行1） | 幅の割り付けの帯（並べ替える器） |
| 準備の入力 | `1×2`（列2・行2〜3） | 誰が測るか／測定表の形／使う機材／いつもと同じ設定 |
| 条の設計・内訳 | `2×2`（列3〜4・行2〜3） | 子ロット候補＋条割プレビュー |

4×3のマスを **3+3+2+4=12** でちょうど使い切る。品質カード（`.quality-pane`）は
解体し、品質規格は基本情報カードのタブ裏（§9.145）へ、品質情報の本文は
基本情報カードの中へ移した。

#### 品質情報は「カードの残り」をそのまま受け取る

利用者の指示「残りのエリアを品質情報の枠に当ててください」。基本情報が縦3マス
になったことで、8項目と公差を置いても**約600px余っていた**（実測）。器は
`display:flex`の縦積みにし、`.quality-info-block`だけ`flex:1 1 auto`で伸ばす。
**gridのままにしない**——行の数がタブの表裏で変わるため、どの行を`1fr`にするかが
決まらない。

見た目も作り直した。読み取り専用の本文に入力欄の枠を付けない（§9.129）ので、
枠を外して地色を一段落とし、左に3pxの印を1本置く（異常があれば赤）。見出しには
**件数を文字で**添える（`異常なし` / `異常 2件`）——状態を色だけで伝えない。
件数は`qualityText()`が作る`(1) …`の印の数で、**値は`.value`への代入で入り
DOMは変わらない**ので、代入した2箇所（開いたとき／共有DBから読んだとき）が
`paintQualityInfo()`を呼ぶ。

実測: カード下の空き 600px → **9px**、はみ出し 0。
