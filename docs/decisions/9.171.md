# §9.171 フィルタの持ち出し・取り込み（利用者の指示）

利用者の指示は「全てまたは各一覧単位でフィルタ機能の部分だけ、エクスポート
インポートできる機能」。登録フィルタはマスタ（`フィルタプリセットマスタ`）に
あるが、**端末を増やすたびに同じ条件を作り直していた**。

置き場は**登録フィルタ一覧モーダルの中**。モーダルを増やさず、一覧の上へ差し込む
——何が出て行くのか・何が入ってくるのかを、実物の一覧を見たまま確かめられる。

- **運ぶもの/運ばないものを画面に書く。** 同じ「フィルタ」でも、条件そのもの
  （誰が見ても同じ）・この端末で付けた「デフォルト」「鍵」の印（端末ごとの設定）・
  使用回数（統計）は性質が違う。前二つは運べば役に立ち、統計は運んでも意味が無い。
- **印は名前で運ぶ。** プリセットIDはマスタの連番なので、別のPCへ持って行くと
  必ず食い違う（IDで運ぶと、まったく別の条件に鍵が付く）。取り込み側は登録の
  戻り値のIDへ名前で当て直す。
- **書き出しは全モードぶん数え直す**（`ioFetchAll()`）。一覧のモーダルが読むのは
  今の一覧ぶんだけ（`S.filterPresets`）なので、そのまま使うと「すべて」が
  今の一覧だけになる。マスタへ書けずこの端末だけに控えたぶんも出す——書けなかった
  からこそ、他のPCへ運ぶ手立てが要る。
- **既定は「いま開いている一覧」だけ**、ひと押しで全部（Hick: 既定は狭く、
  広げるのは1操作）。逆に取り込みは**既定で全部**——そのファイルを選んだ人は
  中身を入れたいから選んでいる。要らないものだけ外せばよい。
- **取り込む前に中身が分かる。** 何件・どの一覧・新規か同名か。**この端末に無い
  データの一覧はそう書く**（`/api/catalog`と突き合わせる。入れても一覧に出ない）。
  カタログが読めなければ黙って判定をやめる——「無い」と言い切るより何も言わない
  ほうがまし。
- **同じ名前があったときの扱いを選べる。** 登録APIは名前＋対象で上書きするので、
  「そのままにする」は画面側で飛ばす。印は**取り込んだ名前のぶんだけ**書き換える
  （触っていない登録のデフォルト・鍵を巻き添えにしない）。
- **壊れたファイルは理由を書いて断る**（何を選べばよいかまで書く）。

サーバーは足していない。書き出しはブラウザの中でJSONを組み立てて保存し、
取り込みは既存の`POST /api/filter-presets`を1件ずつ通すだけ。

固定は`tests/test_filterio.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **フィルタの持ち出し・取り込みは「フィルタだけ」**（§9.171、`static/js/list/filters.js`）:
  登録フィルタ一覧モーダルの中に置く（**モーダルを増やさない**——何が出て行くのかを
  実物の一覧を見たまま確かめられるのが値打ち）。**印（デフォルト・鍵）は名前で運ぶ**
  ——プリセットIDはマスタの連番なので、別のPCでは必ず食い違う（IDで運ぶと無関係な
  条件に鍵が付く）。**使用回数は運ばない**（端末ごとの統計）。**運ぶもの・運ばない
  ものは画面に書く**。書き出しは`ioFetchAll()`で**全モードぶん数え直す**
  ——`S.filterPresets`は今の一覧ぶんしか持たないので、そのまま使うと「すべて」が
  今の一覧だけになる。既定は**書き出し＝今の一覧だけ／取り込み＝全部**（選んだ
  ファイルは入れたくて選んでいる）。**この端末に無いデータの一覧はそう書く**
  （`/api/catalog`と突き合わせ、**読めなければ黙って判定をやめる**）。印を書き換える
  のは**取り込んだ名前のぶんだけ**（触っていない登録を巻き添えにしない）。
  **サーバーは足していない**（既存の`POST /api/filter-presets`を1件ずつ通す）。
  固定は`tests/test_filterio.js`。
