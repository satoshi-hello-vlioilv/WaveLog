# §9.120 列の設定パネルを差し替え口で使い回す（内容欄も同じ画面へ）

タイムラインの「内容」欄は専用の小さなモーダルで「どの項目を出すか」だけを
選べた。だが内容欄も**列レイアウトマスタに乗った列**（§9.88 段6）なので、
並び・幅・表示名・書式・読み替えは仕掛一覧とまったく同じ仕組みで効く。
設定画面を2つ持つ理由が無い——覚えることが2倍になり、片方にしか無い機能が
できる（実際、内容欄には書式も読み替えも入出力も無かった）。

#### 作り直さず、差し替え口を外へ出した

`list-columns.js`（931行）は既に`WL.columnLayout`という汎用の保存層に
乗っており、プリセットもファイル入出力も`target`で切り替わっていた。
画面に固定されていたのは**5点だけ**:

```
target   … 保存先のスコープ文字列
keys     … 候補の全列
joined   … 「結合」列の判定（S.joinQuality）
rows     … 見本に使う実データ（S.rows）
valueOf  … 値の取り出し（row[列名]）
```

これを`open(source)`で差し替えられるようにした。**仕掛一覧の側は既定の口を
そのまま使う**ので、動きは1つも変わらない——汎用化のために既存の画面が
変わるなら、それは作り直しであって流用ではない。

あわせて、**対象ごとに違ってよいもの**も口へ出した:
見出しの言葉、使う分類（内容欄は「元データ」だけ）、使える機能
（内容欄に計算式は無いので**ボタンごと消す**——押せるのに何も起きないのは
壊れているようにしか見えない）。

#### 保存先が2つに分かれる

内容欄は「どの項目を出すか」だけスケジュール内容表示マスタが持ち、それ以外は
列レイアウトマスタ。**画面は1つにまとめ、振り分けは差し替え口の1箇所**で行う。
利用者は「内容欄の設定」を1画面で済ませたいはずで、保存先が2つあるのは
実装側の都合だから。

同じ理由で、**「出す/出さない」の初期値も口が答える**。列レイアウトマスタの
hiddenは空なので、そのまま使うと候補が全部チェック済みになり、保存した瞬間に
**選んだ覚えの無い項目まで内容欄へ並ぶ**（実際にそうなった）。

**項目名の日本語化も口が答える**（`labelOf`）。内容欄のキーは`lotNo`・
`purposeName`というalias名なので、そのまま並べると**タイムラインの見出しは
日本語なのに設定画面だけ生のキー**というちぐはぐな状態になる（通しテストが
「生のまま4件」で捕まえた）。表示名 → 口の呼び名 → キー、の順に落とす。
**既定の口は`labelOf`を持たない**——仕掛一覧の列名は元から日本語なので、
持たせると「同じ名前を言い換える表」を1つ増やすだけになる。

#### 読み込みは「当たらないものを黙って捨てる」だけでは足りない

元データの項目名は変わることがあり、保存した設定に無くなった列名が混ざる。
当たらない列を捨てるのは正しい（そこで止めると、1つ変わっただけで設定全体が
使えなくなる）が、**捨てたことを必ず言う**。以前は「読み込みました」とだけ
出ており、10列ぶんの設定を読んで2列しか当たらなくても気づけなかった。
幅・表示名・書式・読み替えも今ある列だけに絞る（丸ごとコピーしていたので、
消えた列の設定がゴミとして残っていた）。

#### 専用モーダルは消した

設定画面が2つ残ると、どちらが正か分からなくなる（§9.96）。ただし
**消す範囲を行番号で機械的に切ってはいけない**——`contentValueOf`・
`contentItemLabel`・`contentCandidateKeys`はモーダルと同じ場所にあるが
**タイムラインの見出しとセルが使っている**道具で、まとめて消したら
行が1つも出なくなった（例外も出ないので、画面が空になるまで気づけない）。

固定は`tests/test_sccontent.js`（19件）。3つの欠陥（初期値の口を外す／
計算式のボタンを出す／飛ばした件数を言わない）を入れ直して落ちることを
確かめてある。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **列の設定パネルは差し替え口で使い回す**（§9.120、`WL.listColumns.open(source)`）:
  画面に固定されていたのは`target`/`keys`/`joined`/`rows`/`valueOf`の5点だけ
  なので、口を外へ出して切り替える。**仕掛一覧側は既定の口をそのまま使う**
  （動きが変わるなら流用ではない）。対象ごとに違ってよいもの——見出し・使う
  分類・使える機能——も口が答え、**使えない機能はボタンごと消す**（押せるのに
  何も起きないのは壊れて見える）。タイムラインの内容欄は`timeline:<設備>`で
  同じパネルを開き、**「どの項目を出すか」だけスケジュール内容表示マスタ**、
  残りは列レイアウトマスタへ振り分ける（画面は1つ、振り分けは口の1箇所）。
  **「出す/出さない」の初期値も口が答える**——列レイアウトマスタのhiddenは
  空なので、そのまま使うと候補が全部チェック済みになり、保存した瞬間に
  選んだ覚えの無い項目が並ぶ。**項目名の日本語化も口が答える**
  （`labelOf`。内容欄のキーは`lotNo`/`purposeName`というalias名なので、
  そのまま並べるとタイムラインの見出しは日本語なのに設定画面だけ生のキー、
  というちぐはぐな状態になる。表示名→口の呼び名→キーの順に落とし、
  **既定の口は`labelOf`を持たない**＝仕掛一覧は今までどおり）。
  設定の読み込みは**今ある列だけに当て、
  飛ばした件数を必ず言う**（黙って捨てると、項目名が変わったことに
  気づけない）。**モーダルを消すときは行番号で切らないこと**——
  `contentValueOf`等はタイムラインの見出しとセルが使う道具で、まとめて
  消すと**例外も出ないまま行が1つも出なくなる**（実際に起きた）。
  固定は`tests/test_sccontent.js`。
