# §9.318 渡したことと、見えていることは別。見えていなければアプリを直接開く

設計書（`SCHEDULE_MODE_DESIGN.md`）に節が書かれないまま、`CLAUDE.md` の
規則としてだけ残っていた回。本文は下の「守ること」。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **渡したことと、見えていることは別。見えていなければアプリを直接開く**
  （§9.318、利用者の報告「起動時、うまくいかなくてhtmlを後から直接クリックして
  起動しています」）: 送られた「起動の状況」（§9.316）では、待機画面の写しは
  **在って・読めて・渡して・3秒後も読める**と全部そろっているのに、ブラウザは
  `ERR_FILE_NOT_FOUND`だった。**`os.startfile()`の成功は「ブラウザが開けた」を
  意味しない**——隔離・同期・掃除・関連付け・復元タブ・私的な写し、原因はいくらでも
  あり、こちらから見える事実だけでは1つに絞れない。**原因を1つずつ潰す前に、
  辿り着けることを保証する。**
  待機画面は`/api/ready.js`を**繰り返し**読みに来る（`loading.html`の生存確認）ので、
  **1件も来なければブラウザには出ていない**と言い切れる。サーバーが応答してから
  `WAITING_SEEN_GRACE_SEC`(12秒)待ち、**待機画面からも本体のタブからも**問い合わせが
  無ければ`webbrowser.open(app_url())`を**1回だけ**。印は`boot_status.waiting_seen()`と
  `watchdog.active_tab_count()`の2つで、判定は`start_app._browser_reached_app()`の1箇所。
  **サーバーが立たなければ開かない**（接続拒否の白い画面を出さない）。
  **黙って開かない**（§4。理由をログへ1行）。**多重起動の判定を抜けてから起こす**
  （既存インスタンスへ委譲して戻る道で余計なタブを開かない）。
  **健全な端末では一度も走らない**（待機画面は数秒で名乗り出る）。
  **唯一つじつまの合う道**は**Microsoft Store 版のPython**（`\WindowsApps\`の下）で、
  MSIXの入れ物が`%LOCALAPPDATA%`への**書き込み**を
  `%LOCALAPPDATA%\Packages\<パッケージ>\LocalCache\Local\…`の**私的な写し**へ回す
  ——**このアプリは読めるのにブラウザは読めない**（別プロセスは元の場所を見る）。
  **推測で置き場を変えないこと**——`paths.msix_private_copy()`が「1つ書いてみて、
  私的な写しの側に**実際に現れたか**」だけを見て、現れたときだけ
  `paths.browser_dir()`がブラウザからも見える場所（ホーム直下→アプリの隣）を選ぶ。
  **既定は`runtime_dir()`のまま**で、健全な端末は1バイトも変わらない。
  **待機画面と進捗ファイルは必ず同じ場所**（`<script src="boot_status.js">`が相対）
  ——`setup_check.waiting_page()`と`boot_status.status_path()`は同じ`browser_dir()`を見る。
  **やったことをそのまま言うこと**——`copy_waiting_page()`は**何もしなかったとき**も
  写しのパスを返すので、戻り値が在れば「更新しました」と書いていたログが
  **直したはずの§9.314の競合がまだ起きている**ように読め、原因を探す側を丸1往復
  遠回りさせた。`say`で受けて実際の文をそのまま出す。
  固定は`tests/test_bootopen.py`——**猶予の「あいだ」に名乗り出る形まで見ること**
  （ブラウザの立ち上がりは数秒かかるので現実にいちばん多い。最初の1回だけを見る網は、
  猶予の中で見るのをやめた実装を素通りさせる。実際に素通りした）。
