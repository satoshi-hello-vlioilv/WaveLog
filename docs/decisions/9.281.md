# §9.281 帳票プレビューに用紙の切れ目を出す（利用者の指示）

> 帳票レイアウトのプレビューで基準A4サイズ単位でどこで切れ目になるかわかる
> ことは重要なので、シームレスに繋いで表示するのではなく印刷プレビューらしく
> どこで用紙が区切られて表示が切れるかわかるようにしてください。

#### 何が起きていたか

`.rp-page`は`min-height:297mm`の**1枚もの**で、中身が溢れるとそのぶん伸びる
だけだった。見本のロットで実測すると**516.5mm＝A4 1.74枚**で、`page.pdf()`で
刷ると**2ページ**になる。ところが画面は1枚の長い紙として繋がって出るので、
**どこで紙が変わるのか・どの塊が途中で切れるのかが読めない。**

さらに、収まりを言う帯（`#rpPageFit`）が**嘘をついていた**——

```js
const avail=(pr.height/(scale||1));   /* ← 伸びた紙自身の高さ */
const over=inner-avail;               /* → 常に 0 */
```

比べる相手が**紙自身**なので、どれだけ溢れても必ず
`A4縦 1枚（残り Nmm）`になる（利用者のキャプチャがまさに「1枚（残り4mm）」）。
mmの換算も`avail`から作っていたので、数そのものも狂っていた。

#### 直し方

**物差しは紙の「幅」から作る**（`rpSheetFacts()`）。高さは中身が溢れると
伸びるので基準にできないが、幅は210mm（横向きは297mm）で動かない。

```
px/mm = 紙の実幅 ÷ (縦向き 210 / 横向き 297)
中身mm = 中身の下端 + 下の余白8mm
枚数   = ceil((中身mm − 0.5) ÷ 1枚ぶん)
```

**答えるのは`rpSheetFacts()`の1箇所**——切れ目の描画・収まりの帯・切れる塊の
印がすべてここを見る（別々に数えると「帯は1枚と言うのに紙は2枚ぶん出ている」
が作れる。実際にそうなっていた）。

見せ方は3つ:

1. **紙をA4何枚ぶんかで区切る**（`--rp-sheets`）。最後の紙の余りもそのまま
   見えるので「あとどれだけ置けるか」が読める。
2. **切れ目に断ち切りの印**（点線＋左右の余白に立てるトンボ＋紙の縁の影）と、
   1枚ずつの枠、左の余白へ縦書きの「1枚目」「2枚目」。
3. **切れ目にかかる塊へ印**（`is-cut`）と、帯に**件数を文字で**（§3）。

**中身は動かさない。** 実際の紙は切れ目でずれるわけではないので、隙間を空けて
下の中身をずらすと**プレビューと刷り上がりが食い違う**（§9.242 ⑦の「プレビュー
どおりに刷る」が崩れる）。ずらす代わりに縁・札・印の3つで読ませる。

**刷る側へは持ち込まない**——`rpPageHtmlFor()`が`.rp-sheets`を写しから外し、
`--rp-sheets`も落とす（残すと紙に点線が刷られ、中身より背の高い紙になる）。
`@media print`でも伏せてある（`bulkPrintNow`は実DOMを刷るため）。

**紙は`#reportContent`そのもの**（`.rp-report.rp-page`）。
`#reportContent .rp-page`と書くと1つも見つからない（実際に踏んだ）。

#### 網

`tests/test_rpprint.js`（枚数ぶんに区切る／切れ目が1枚ぶんごと／枠と札／
切れる塊の印と理由／帯が枚数と超過と件数を言う／刷る書類には持ち込まない／
**1枚に収まるときは何も出さない**）。

**見本のロットで確かめること**——検証用のレコードは1枚に収まるので、
そのままでは切れ目の道を一度も通らない。**枚数は決め打ちにしない**
（見本の中身は設定で変わるので、数を書くと直っていても落ちる網になる）。

**欠陥注入4件**（①物差しを紙自身の高さから作る＝直す前の姿 ②紙を1枚ぶんの
倍数まで伸ばさない ③切れ目の層を描かない ④刷る写しから外さない）で、
それぞれ落ちることを確認済み。

#### 追補: ページ間は「背景と同じ色の余白」（利用者の指示）

> ページ毎に表示するようにみたい事もあるので、各ページ間は完全な背景と同じ色の
> 余白が欲しいです。よくある印刷プレビューの作りです。

**紙を1枚ずつに割り、あいだへ本物の余白を空ける**（`.rp-paged`／`--rp-gap`＝10mm）。

- **余白の色は書かない。** 紙の器（`.rp-page`）を透かして`.rp-scroll`の地を
  そのまま見せるので、背景色を変えても余白は必ず同じ色になる（色を2箇所に
  書かない）。白い紙と影は`.rp-sheet`が持つ（器の背景と影は落とす）。
- **中身は1枚ぶんずつ下へずらす**（`--rp-shift`）。各紙の中での位置は1mmも
  変わらないので、刷り上がりとは食い違わない（§9.242 ⑦）。
- **切れ目にかかる塊は切って、続きを次の紙の頭へ置く**（`--rp-clip-*`＋
  `.rp-blk-tail`の写し）。写しは`data-rp-block`と`id`を持たないので、
  置き場所を数える処理（`rpFreeCells`等）からは見えない。
- **計算した数はカスタムプロパティで渡す**（`tests/test_csslint.py`）。
  ずらす・切るの使い方はCSSに残す。

**組み換え中はつなげたまま**——掴んで置く座標は`rpLocal()`と`rpFreeCells()`が
`getBoundingClientRect()`から解いているので、塊をずらすと**落とす先が余白の
ぶんずれる**。組み換えは1枚のキャンバスの上で行い、どこで紙が変わるかは点線が
言う（**見え方が場面で違うことは帯の`title`に書く**・§4）。

**測る前に必ず片付ける**（`rpClearSheets()`）——ページに割ると塊へ`transform`が
付くので、外さずに`getBoundingClientRect()`で測ると位置を読み違える。
`rpFitAll`／`rpMarkOverflow`／`rpUpdateSheets`の頭で通す。

**高さが決まってから倍率を合わせ直す**（`rpRefitZoom()`）——`fitPage()`は
描いた直後＝**行の割り付けもページ割りも済む前**に測るので、「全体」が1枚目
しか映さないことがあった（実測85% → 押し直すと42%）。変わったときだけ
合わせ直す（毎回だとちらつく）。

**網は実際に描かれている位置で見ること**——`data-rp-shift`が付いていることだけ
を見る網は、**ずらす数を0にしても通る**（実際に素通りした）。紙は297mmで余白は
10mmしかないため「どれかの紙に入っている」でも足りない（ずらさなくても隣の紙の
範囲に入ってしまう）。**ずらした量÷余白＝その塊が乗る紙の番号**を突き合わせる。
**欠陥注入5件**（①ページに割らない ②中身をずらさない ③器を透かさない
④続きの写しを出さない ⑤組み換え中も割る）で落ちることを確認済み。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **帳票プレビューは用紙の切れ目を出す。物差しは紙の「幅」から作る**（§9.281、
  利用者の指示「基準A4サイズ単位でどこで切れ目になるかわかることは重要…
  シームレスに繋いで表示するのではなく印刷プレビューらしくどこで用紙が区切られて

  溢れるとそのぶん伸びるだけだった（実測516.5mm＝A4 1.74枚・刷ると2ページ）。
  さらに収まりの帯が**伸びた紙自身の高さ**と比べていたため、どれだけ溢れても
  必ず「1枚（残り○mm）」——**自分と比べていた**（実機のキャプチャがまさにこれ）。
  **高さを基準にしないこと**。幅は210mm（横向きは297mm）で動かないので、
