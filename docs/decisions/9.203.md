# §9.203 揃いは「選んで記録」——4桁の揃いコードを廃止し、6項目で持つ（利用者の指示）

> 入力項目で揃いコードで打ち込むところを、下記のような構造で選ばせて記録する
> 形に変更したいです。■エッジ形状 のこぎり状／テレスコ状 ■発生位置（発生範囲）
> 2/3以上発生／1/3～2/3発生／1/3未満発生 ■横移動パターン 不規則／規則的
> ■方向 前側／後側
> …コードを作らず廃止、エッジ形状、発生位置、規則性、方向、ピッチ、値の6種類で
> 管理する形に変更してください。さらに方向は前側/後側ではなくOS/DSに。
> …エッジ形状に「揃い綺麗」という評価を追加してください。

**4桁のコードは廃止した。** 桁の意味（1桁目=エッジ形状…）を覚えていないと
読めない値で、帳票にもDBにも数字しか残らなかった。名前をそのまま記録する。

| 項目 | 種類 | 選択肢 |
| --- | --- | --- |
| エッジ形状 | 選択 | 揃い綺麗 / のこぎり状 / テレスコ状 |
| 発生位置 | 選択 | 2/3以上発生 / 1/3〜2/3発生 / 1/3未満発生 |
| 規則性 | 選択 | 不規則 / 規則的 |
| 方向 | 選択 | OS / DS |
| ピッチ | 数値 | — |
| 値 | 数値 | — |

**判定の起点はエッジ形状。**「揃い綺麗」ならOKでそこで終わり——**内訳は
書かせない**（空にして押せなくする）。異常が無いのに5欄を埋めさせるのは、
できないことをできると見せるのと同じくらい悪い（§4/§2）。
「全丈 OK一括入力」は全丈を「揃い綺麗」にし、内訳と旧コードを消す。

**旧データは消さない。** 4桁コードで保存されたレコードは`alignmentCode`を
持ったままで、`judgeProductRow()`が「選び直していなければ旧コードで判定する」
で面倒を見る。画面にも判定の下へ「旧 1234」と小さく出す——コードを廃止した
からといって、記録されたものが読めなくなってはいけない。
**選択肢に無い値が入っていたら、その値を選択肢に足す**（`select.value`へ
無い値を入れると空文字になり、保存済みの記録が黙って消える。§9.160と同じ罠）。

**「入力済み」の判定は`PRODUCT_FILLED_KEYS`の1箇所**。`measure-progress.js`は
`productFilledKeys()`で**呼ばれたときに**読む（読み込み順に依存させない）。
`alignmentCode`だけを見ていると**新しく入力した行が1件も数えられない**ので、
判定の起点（`edgeShape`）を必ず含める。

列幅は選択肢の長さから決める（いちばん長いのは「1/3〜2/3発生」）。
**幅の数字だけを見る網では足りない**ので、選んだ文字が器に収まっているかを
実測で確かめる（`tests/test_msteps.js`）。
