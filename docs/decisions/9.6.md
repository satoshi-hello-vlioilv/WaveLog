# §9.6 モード別の表示差分

| 要素 | edit | view | schedule |
|---|---|---|---|
| 「作業スケジュール」ナビ | 表示 | 表示 | 表示 |
| タイムライン | 読み取り専用(現場段取り可なら並べ替え可、§9.4.1) | 読み取り専用 | 編集可 |
| 未着手分のドラッグ並べ替え | 現場段取り可否に従う | 非表示 | 表示 |
| 追加・削除・見積上書き・稼働カレンダー | 非表示 | 非表示 | 表示 |
| 仕掛一覧の「予定」列 | 非表示 | 非表示 | 表示 |
| 設備セレクタ | 自端末の使用設備で固定表示(選択UIなし) | 全設備選択可(`▾`) | 全設備選択可(`▾`)、予定追加時は必須 |
| 換算係数の管理画面 | 参照のみ | 参照のみ | 上書き可 |

- **編集モード(測定作業中の端末)は、ナビの「作業スケジュール」を開くと
  `currentConfiguredEquipment()`(使用設備の登録値)のスケジュールが
  自動的に開く**。設備を選ぶ操作自体が無い(要望どおり「測定作業時は選択
  設備のスケジュールを開く」)。使用設備が未登録の端末は、仕掛一覧と同じ
  案内(`list-view.js`の`setup-first`と同型)で「まず使用設備を設定して
  ください」を表示し、スケジュール自体は開かない。
- **スケジュールモードは特定の設備に紐付かない**。ヘッダーの設備セレクタで
  どの設備のスケジュールでも切り替えて作成・編集できる(要望どおり
  「スケジューラとしてログインした場合はどの設備のスケジュールも作成可能」)。
- `POST /api/schedule/plan/add` は `equipment` が必須で、未選択のまま追加
  しようとするとボタン自体を無効化する(サーバー側の400は最終防衛、§8.2)。
  これにより「どの設備の予定として登録したか」が常に一意に決まる。
- 編集モードで設備セレクタを出さない(選ばせない)のは、測定端末で
  他設備の予定を眺める用途が無く、誤読(他設備の予定を自分のと思う)の
  リスクの方が大きいため。
