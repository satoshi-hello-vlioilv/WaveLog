# §9.384 自分の錠に自分が締め出されて56件が消えた（利用者の不具合報告）

報告（VER2.271.0・LS4）:

```
何をしようとしたか: いくつかの変更を反映できませんでした
起きたこと: 他の端末がマスタを更新中です（Norio-Mori／NLM-NGY-260522、あと約19秒）。
サーバーの返事: HTTP 409      件数: 56   操作: update,add
[この端末] 端末: NLM-NGY-260522   ログイン: Norio-Mori   編集権: 自分が持っている
```

**核心は、ロックを持っている端末と弾かれている端末が同一だったこと。**
知らせに出ている「他の端末」が、報告者自身の端末だった。

## 原因

`acquire_lock()` が「今の持ち主が自分か」を一度も見ていなかった。

`release_lock()` は共有・クラウド越しでは**消せないことがある**（消せなくても
「TTLで自動的に切れます」と警告だけ残して先へ進む作り）ので、残った自分の錠が
自分を締め出し、TTLの20秒ぶん保存が全部断られていた。

**残っているのが自分の錠なら引き継ぐ**ようにした（消してから取り直すと、その
すき間に他の端末が入れるので、新しい合言葉で上書きして期限を延ばす）。同じ端末の
中の同時書込は `_write_lock`（プロセス内のRLock）が既に1本にしているので、
引き継いでも排他は壊れない。

見分けるのは端末の呼び名とログインIDで、**名乗れない端末は「自分」と言わない**
——空の呼び名で全部引き継げると、端末名を取れない環境で排他が消える。

## もう半分の「消える」

再試行が**3回＝約4秒**で尽きており、**20秒続く錠**を待ちきれずに巻き戻して
いた（＝待てば通ったはずの書込を捨てていた）。409のときだけ回数と間隔を伸ばし、
錠が切れるまで（およそ25秒）粘る。

**423は伸ばさない。** 編集権を他の人が持ったのは錠と違って待っても戻らず、
状態が変わったという知らせなので早く言うほうがよい。最初は409と一緒に伸ばして
しまい、`test_scfail` の「失敗したら行は戻る」が赤になって気づいた（9回粘ると
知らせが25秒遅れる）。

## 確かめ方

欠陥注入で、直す前のコードに戻すと**報告とほぼ同じ形**で赤になる:

```
FAIL: 自分の錠が残っていても自分は取れる
      -- 他の端末がマスタを更新中です（me／PC1、あと約19秒）。
```

端末違い・ログイン違い・名乗れない端末は今までどおり断ることも固定した
（引き継ぎを広げすぎない）。
