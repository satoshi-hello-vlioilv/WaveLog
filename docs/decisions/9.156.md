# §9.156 条のまとめ帯を廃止し、図を1つに統合して1条ずつ並べ替える

利用者の指示:「条のまとめ表示は不要なので、図は1つに統合して、並べ替えが
できるものをください。スクロールレス設計で配置をお願いします。屑幅の表示、
1条毎の表示、D&D操作可能、条情報と公差情報などの連動をお願いします。」

#### 同じ見た目の帯が2つ並んでいた

`splitBandHtml()` が描く**ロット単位のまとめ帯**（掴めない）と、
`.split-visual` の**1条ずつの帯**（掴める）が同じ見た目で縦に並んでいた。
**動くほうと動かないほうの区別が付かない。** まとめ帯は関数ごと廃止。
ロット・条数・幅は1条ずつの帯とその `title` が持っている。

#### 候補が取れないときも1条ずつ出す

実機では子ロット候補の取得に失敗することがあり、そのとき
`splitSourceRows()` が空を返して**図そのものが出なかった**（「条割の対象と
なる子ロットがありません」）。確定済みの割当（`settings.splitGroups`）が
あるならそこから引き直す（`rowsFromAppliedGroups()`）。

#### 控えの並びより確定済みの割当を優先する

`splitSequence`（控え）に前のロットのものが残っていると、9条の器に2条ぶんの
名前しか入らず7条が「未割当」になった。`seedSplitDefaults()` は
`appliedSequence()` と食い違ったら**割当のほうへ合わせる**——図が測定表と
違うものを指すくらいなら、割当から引き直すのが正しい。

固定は `tests/test_splitlive.js`・`tests/test_scsplit.js`。
