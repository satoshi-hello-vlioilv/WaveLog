# §9.382 刃組の確定保存に「予定本数」と「1本目の材料」を載せる（利用者の指示）

利用者の言葉:

> この刃組で決定となったときに選択及び決定が入ったらそのデータを確定保存する
> 仕組みが必要です

刃組スケジュール一覧（§9.383）が読むのは**この1件**なので、そのとき決まって
いたことを全部ここへ置く——別々の場所から集め直すと、後から片方だけ変わって
食い違う。

| 残すもの | 置き場 |
| --- | --- |
| 台車・刃セット | `carriage` ／ `detail.set` |
| 板押さえ・部材の員数 | `cond.hold` ／ `spacer`・`ring`・`finger` |
| クリアランス・ラップ | `cond.clearance` ／ `cond.overlap` |
| 予定本数・1本目の材料 | `detail.run`（予定から運ぶ・ここで足した） |
| どの段取りの行から開いたか | `detail.from` ／ `detail.stopId` |

## 数える単位が条と違う

予定本数は `bladeRunPlan()` が予定から数える。**条（子ロット）は数えない**
——切るのはコイル1本で、子は同じ1本を割ったものなので、数えると条の数だけ
水増しされる。数える範囲は**次の刃組まで**（同じ刃で流せるあいだが1つの段取りの
持ち分）。

条の割付（`bladeSeedLots`）とは数える単位が違うので**関数を分けた**——図に出せる
条は9本で打ち切るが、**本数は打ち切ってはいけない。**

読めない材質・用途は**空のまま**渡す（0や既定で埋めない・§9.231）。記録に
「材質 空欄」と残るほうが、嘘の値が残るより直せる。

残る内容は**押す前に見せる**。予定から開いていないときは「その2つは残りません」
とその場に書く（§CLAUDE 4・6）。実機で確かめた表示:

```
予定本数 7 本　1本目 L1（SPCC / t1.6 / 幅1200 / 外装）
```
