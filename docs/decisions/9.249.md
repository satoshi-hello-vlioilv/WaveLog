# §9.249 不要ファイルの掃除・専用タブを持たないマスタの編集・帳票ブロックの編集窓・テストの統合（利用者の指示）

利用者の指示（4件）:

> １）溜まってくると問題なので、**不要なキャッシュファイルや不要なバックアップ
> ファイルを削除する機能**を実装してください。**いらないものや世代の古いものは
> 定期的に削除**するような機能も欲しいです。
>
> ２）**テーブル生データ内で閲覧可能なマスタかつ、テーブル生データマスタの配置
> された階層にないものは、この階層に配置し、編集可能な形に実装**してください。
>
> ３）**帳票ブロックマスタに関して、モーダルを大きく**してください。大きくした
> モーダルに合うように**バランスよく再構築**して、もっと**わかりやすく視覚化**
> した形で表示を工夫し設定しやすいものを作成してください。**文字が多いわりに
> わかりにくく、情報の階層化、チャンク化も駆使**し、UIUX設計には徹底的に
> わかりやすさと使いやすさ、美しさにこだわってください。
>
> ４）（別件）アプリおよびコードのチェックにおける**不要なテスト、不要なファイル
> は削除**してください。**重複しているテストは統合**できるか確認し必要に応じて
> 統合して最適化してください。

#### ① 不要ファイルの掃除（`backend/file_cleanup.py`）

アプリが動くうちに増えるのは、どれも**作り直せるファイル**だった——共有DBの
写しの古い世代・置き換えの途中で残った一時ファイル・世代送りしたログ・RNE抽出の
控え・Pythonのバイトコード・置き場を変える前の作業フォルダ。溜まっても壊れない
かわりに、**誰も消さないので増え続ける**。

- **触ってよいのは「消えても取り直せるもの」だけ。** `master.sqlite3` /
  `records.sqlite3` / 共有スケジュール / 仕掛・品質の原本は、このモジュールから
  **見えるところに一切出てこない**（§9.109の線引きと同じ）。網
  （`tests/test_cleanup.py`）はまず「本物のデータがどの種別にも現れないこと」を
  見る——掃除の道具は、消えないことのほうが先。
- **判定は1箇所**（`CATEGORIES`／`survey()`／`run()`）。画面は返ってきた種別を
  そのまま並べるだけで、要る・要らないの規則を持たない（§9.163）。持たせると
  「画面が消えると言ったものが残る」が作れる。
- **一時ファイルは若いうちは触らない**（60分）。いま書いている最中のものを消すと、
  書き手が「書けたはずのものが無い」という**直しようのない**壊れ方をする。
  同じ理由で、**いま読んでいる写しの世代**（台帳が指す世代）と**いま書いている
  ログ**は残す。残す理由は1件ずつ文字で出す（推測させない・§CLAUDE 6）。
- **自動で消してよい種別は`auto=True`の5つだけ。** バイトコードと古い作業
  フォルダは**押したときだけ**——前者は消すと次の起動が一度だけ遅くなり、
  後者は中身を確かめてから消したい。「作り直せる＝勝手に消してよい」ではない。
- **消せなかったことを失敗にしない**（§9.108）。Windowsでは誰かが開いている
  ファイルを消せないが、それは待てば消せるので次の周回へ回すだけでよい。
  ただし**黙らない**——件数と理由をトーストに出す。
- 定期実行はパス設定マスタ（`cleanup_auto_enabled` / `cleanup_interval_sec` /
  `cleanup_keep_days` / `cleanup_keep_generations`）。**呼ぶたびに読み直す**ので
  再起動は要らない。既定は入・6時間ごと・3世代・14日。

画面（マスタ管理 >「不要ファイル掃除」）の作り:

- **面積は「いま何MB片付くか」とボタンへ配る**（§CLAUDE 1）。ここへ来る人は
  それを見に来ている。**いま空の種別は1行の札へ畳む**——溜まっていないのが
  ふつうの状態なので、そこへ画面の大半を割くと肝心の「消せるもの」が埋もれる。
  **畳んでも消さない**（何を見ているのかが分からなくなる・§CLAUDE 12）。
- **上の帯と下のボタンが食い違わないこと。** 最初は「自動掃除の対象だけを
  既定で選ぶ」にしていたが、そうすると帯が「8.2MB片付けられます」と言って
  いるのにボタンが押せない、という**画面が自分の言ったことを否定する**状態が
  作れた。既定は**消せるものがある種別すべて**にし、押す前に**何が消えるかを
  1件ずつ並べた確認**を1回だけ出す（§9.170・§9.193）。
- 種別ごとに「消し方」「いちばん古いもの」「消えるファイルの名前と大きさ」
  「残すものとその理由」を出す。**自動掃除の対象外**であることも文字で言う。

#### ② 専用タブを持たないマスタを、階層の中で編集する（`backend/routes/master_tables.py`）

`master.sqlite3`の表のうちマスタ管理にタブを持たないものは、これまで
**「テーブル生データ」から眺めることしかできなかった**。直したいときは
その表を書いている画面（列の設定パネル・登録フィルタ・行の色…）を思い出して
探しに行く必要があり、**どこからも直せない表**（移行済みの旧マスタ）も
混ざっていた。

- **対応表はサーバーの1箇所**（`COVERED_BY` / `EDITED_FROM` / `RETIRED` /
  `NOTES` / `SHORT_LABELS`）。画面へ写すとタブを1つ足すたびに2箇所直すことに
  なる（§9.163）。**腐りは`tests/test_rawmaster.py`が機械で見る**——
  `COVERED_BY`が指すタブのキーが`MASTER_DEFS`に実在するか。指し先が消えると、
  その表は「専用タブがある」と言われたまま**どこからも開けない行き止まり**になる。
- **鍵はrowid。** 列レイアウトマスタのように自然キーを持たない表でも1行を
  名指しできる唯一の手立て。**主キーと監査列は送っても書き換わらず**、
  更新者ID・更新日時はサーバーが埋める。**送っていない列は消さない**（部分更新）。
- **新しい画面を作らない**（§9.120）。サーバーの答えを`def`の形へ翻訳するだけで、
  一覧・編集モーダル・削除・検索は既存の汎用CRUDがそのまま動く。入力欄は
  **表の作り（PRAGMA）から組み立てる**ので、列が増えても書き足さない。
- **移行済みの表は読み取り専用**にし、移った先を書く（§CLAUDE 4）。直せると
  見せて画面が変わらないのは、押せないボタンより悪い。
- **削除の言い回しはdefが決める。** 有効フラグを持つマスタの削除は「無効化」
  だが、生の表は**本当に行が消える**——同じ文言で言うと嘘になる。
- 「テーブル生データ」も**行き止まりにしない**。表を選ぶと「この表は◯◯から
  編集できます」と出て、そのタブへ移れる。

#### ③ 帳票ブロックの編集窓（§9.217の作り直し）

以前は**11の欄が平らに並び**、どれも長い説明文を抱えていた。決めることは
実際には4段階で、しかも**紙のどこにどう出るか**は文字では伝わらない
（「6マス」が紙の何割かを頭の中で割り算していた）。

- **決めることを4つに束ねる**（チャンク化）: ① これは何の塊か → ② 何を載せるか
  → ③ 紙のどこへ出すか → ④ 出す・並び。①〜④は**実際に決める順番**なので、
  視覚導線と作業導線が一致する（§CLAUDE 14）。
- **窓を大きくして2段組み**（左＝決めること／右＝刷り上がりの見本）。
  幅は`min(1560px,97vw)`。見本は**A4の比（210:297）**の紙に12マスの格子を敷き、
  選んだ幅・高さの位置に塊を置く。**幅を押すとその場で形が変わる**。
- **見て選ぶ欄を3つ足した**（どのマスタでも使える汎用の型）:
  `choice-card`（絵・名前・一言の札）／`span-grid`（紙の12マスをそのまま押す）／
  `rows-pick`（縦棒の高さがそのまま行数）。**値は隠し欄が持つ**ので、
  `submitMaint`は型を知らなくてよい（§9.218 ②と同じ作法）。
- **`choice-card`は選択欄と同じ既定を持つこと。** `<select>`は先頭の選択肢が
  最初から選ばれている。札にした途端に「どれも選ばれていない」状態が生まれると、
  `data-when`で②の欄が丸ごと消えて**決めることが1つ消える**（実際に起きた）。
- **説明は短くし、続きは見出しの`?`（title）へ落とす**（§9.234 ①）。
  消すのではなく、読む順を変える。**窓の説明は一覧の説明と同じにしない**
  （`hintShort`。一覧のほうは「このマスタは何か」を書くので長い・§CLAUDE 8）。
- 固定は`tests/test_rbmodal.js`。**幅・高さは「見本が実際に変わること」まで見る**
  ——値が入ったことだけを見る網は、見本を描かない実装でも通る。

#### ④ テストの統合と後始末

**5本を減らし、重複していた確認を1箇所へ寄せた**（1,624件→同数のまま、
ブラウザの立ち上げが6回減る）。

| まとめた先 | 取り込んだもの | なぜ |
|---|---|---|
| `test_headbar.js` | `test_hdr.js`（3グループと寸法）／`test_hdctx.js`（画面名と名残） | どれもヘッダーを見るために同じ起動を3回待っていた |
| `test_master.js` | `test_p11.js`（統合パネルとタブ）／`test_p11c.js`（編集モーダルの一周） | 同じマスタ管理を3回開いていた。「p11」は当時の作業フェーズ番号で中身を言っていない |
| `test_nav.js` | `test_navdyn.js`（後から足されるナビのツールチップ） | 同じMutationObserverの仕掛けを2本で見ていた |
| `test_uisize.js` | `test_calscale.js`（カレンダーの寸法追随） | 見ている軸は同じ（表示サイズ） |

寄せた確認:

- **作業可否の索引（§9.57）は`test_audit.js`が持つ。** 同じ前提（仕掛に無い
  ロットの予定を1件作る）と同じ確認が`test_nav.js`にもあり、**2本が同じ索引を
  2回組んでいた**。索引は問い合わせ回数の話なので、回数を数えている側へ寄せた。
  おかげで`test_nav.js`は**モードを切り替えなくなり**、「`test_nav`がscheduleの
  まま終わって後続が落ちる」（tests/README.md）の種そのものが消えた。
- **「文字サイズのリテラルpxは印刷物とサイズ見本だけ」は`test_csslint.py`だけ
  が見る。** まったく同じ検査が`test_theme.js`にもあったが、あちらは
  **ブラウザを立てて**同じCSSを読み直していた。静的な検査は
  **ブラウザを立てずに1秒で**回り、しかも常に回る（`pick_tests`のALWAYS）。
- **後始末を足した。** 旧`test_p11c.js`は登録した行を消しておらず、
  実行のたびにアクセス権限マスタと分類マスタが1行ずつ増えていた（§9.121）。
  旧`test_calscale.js`が吐いていた`cal_sm.png`／`cal_lg.png`（誰も読まない
  置き土産）も撮らない。

**統合の線引き**——「同じ画面を見るために同じ起動を待っているか」で決めた。
主題が違うもの（フィルタの6本など）はまとめない：1本が1,000行になると、
落ちたときにどの約束が壊れたのかを読み解くほうが高くつく。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **掃除してよいのは「消えても取り直せるもの」だけ**（§9.249 ①、利用者の指示
  「不要なキャッシュファイルや不要なバックアップファイルを削除する機能」）:
  判定・削除・定期実行は`backend/file_cleanup.py`の**1箇所**が持ち、画面は
  返ってきた種別をそのまま並べる（§9.163。2つ持つと「画面が消えると言った
  ものが残る」が作れる）。**master.sqlite3 / records.sqlite3 / 共有スケジュール /
  仕掛・品質の原本は、このモジュールから見えるところに一切出てこない**

  現れないこと」を見る。**一時ファイルは60分より若いものに触らない**
