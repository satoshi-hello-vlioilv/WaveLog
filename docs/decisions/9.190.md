# §9.190 「いつも適用（固定）」は1つの印（利用者の指示）

利用者の指摘: 「鍵をかけても画面を切り替えると解除されてしまいます。……
フィルタの鍵は、他の一覧で使えないという意味ではなく、**適用したフィルタから
外せなくなるという意味のフィルタロック**です。つまり鍵マークはデフォルトに
すると同義です。混同する場合はデフォルトチェックだけで、フィルタの登録欄には
鍵マークは不要ですね」。

**言葉の取り違えがあった。** 実装は「デフォルト（開いたときに自動で入る）」と
「鍵（外すときに確認する）」の2つの印を別々に持たせていたが、利用者にとっては
**1つのこと**——「この条件は、いつも入っていてほしい」——だった。

**① 印を1つにする。** 登録フィルタ一覧のチェックは
**「いつも適用（固定）」**の1つだけにし、鍵のボタンは消した。保存するときは
`isDefault`と`isLocked`を**必ず2つそろえて**送る（`setAlwaysOnPreset()`）。
読むときは**和集合**で見る（`alwaysOnIdsFor()`）——過去に片方だけ立った行が
残っていても、意図どおり「いつも適用」として扱う。外すときは確認を挟む
（外れないことに値打ちがあるものが、うっかり外れないように）。

**② 真因は403だった。** 「画面を切り替えると外れる」の直接の原因は、
`masters.filter_preset_marks` が書込ガードの例外表（`_ENDPOINT_EXTRA_MODES`）に
**無かった**こと。scheduleモードの端末では印のPOSTが403で弾かれ、しかも画面が
`.catch(()=>{})`で握り潰していたため、印は**端末の控えにしか残らなかった**。
次に登録フィルタを読み直した瞬間に`absorbServerMarks()`がサーバーの答え
（印なし）で控えごと消す——これが「鍵が外れる」の正体。**握り潰しをやめ、
届かなければ画面に出す**（何が起きたか分からないまま設定が消えるのが一番悪い）。
`filter_preset_owner`も同じ穴だったので一緒に開けた。

**③ 印の写しは利用者IDごとに読み直す。** `ensureMarkMaps()`が**一度だけ**
写しを作って以後使い回していたため、利用者IDが`/api/whoami`から届く前
（§9.184）に作った空の写しが、IDが届いたあとに**本人の置き場へ書き戻され、
触っていない一覧の印まで消していた**。他は全部「呼ぶたびにIDを引く」約束
なのに、ここだけメモ化していた。**IDが変わったら読み直す。**

なお**閲覧モードは今も塞がったまま**（`filter_preset_register/delete/use`と
同じ扱い）。閲覧端末で「いつも適用」を付けると保存できない旨のトーストが出る
——黙って消えるよりはよいが、開けるかどうかは別に決める必要がある。

固定は`tests/test_filterlock.js`（§9.184の`test_filterkeep.js`と対）。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **「いつも適用（固定）」は1つの印**（§9.190、利用者の指示）: 「デフォルト」と
  「鍵」は同じことを指していた（＝この条件はいつも入っていてほしい）ので、
  登録フィルタ一覧のチェックは**1つだけ**にした。保存は`isDefault`と`isLocked`を
  **必ず2つそろえて**送り（`setAlwaysOnPreset()`）、読むときは**和集合**で見る
  （`alwaysOnIdsFor()`。片方だけ立った古い行を落とさない）。**外すときは確認する。**
  「画面を切り替えると鍵が外れる」の真因は`masters.filter_preset_marks`が
  `_ENDPOINT_EXTRA_MODES`に無く**scheduleモードで403**だったことで、画面が
  `.catch(()=>{})`で握り潰していたため誰も気づけなかった——**印の保存が
  失敗したら画面に出す**こと（次の読み直しで`absorbServerMarks()`が控えごと
  消すので、黙ると設定が消えたようにしか見えない）。**`ensureMarkMaps()`は
  利用者IDごとに読み直す**——1回で固定すると、IDが届く前に作った空の写しが
  本人の置き場へ書き戻され、**触っていない一覧の印まで消える**（§9.184と同じ
  「呼ぶたびにIDを引く」約束）。閲覧モードは今も塞がったまま。
  固定は`tests/test_filterlock.js`。
