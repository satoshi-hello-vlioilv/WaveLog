# §9.151 横軸を「その条自身の公差に対する位置」にする（異幅分割）

利用者の指示。

> 自分の公差に対する位置で作り変えて下さい。ようはそれぞれ条の相対値って
> 事ですよね。ロット帯入れてわかりやすくして下さい。幅そのものの違いは
> 見えなくて良いです。

#### 何が壊れていたか（実測）

§9.150で図を「縦＝条・横＝測定値」にしたが、横軸は**絶対値**のままだった。
異幅分割（幅300±1が2条／幅500 +3/−1が2条）で実測すると:

| 選択中 | 軸 | 条1(300.20) | 条2(299.50) | 条3(500.50) | 条4(502.00) |
|---|---|---|---|---|---|
| 条1 | 299.0〜301.0 | OK | OK | **端で赤** | **端で赤** |
| 条3 | 499.0〜503.0 | **端で赤** | **端で赤** | OK | OK |

軸が「いま選んでいる条」の公差で決まるので、**条を移るたびに全部の点が動き**、
他方の子ロットの点は端に張り付いて赤くなる。**4条とも自分の公差では合格**で、
表のセルは正しく合格判定していた——**図だけが嘘をついていた**。

スウォームのころも同じ欠陥だったが、点の雲だったので気づけなかった。
**行が条に対応したことで誤りが見えるようになった**、が正確なところ。

#### 単位をその条自身の公差にする

```
0 ＝ 基準 ／ −1 ＝ 下限 ／ ＋1 ＝ 上限
x = (測定値 − その条の基準) ÷ その条の公差（＋側は plus、−側は minus で割る）
```

非対称公差では**基準を境に折れる**（＋3/−1なら右半分は/3、左半分は/1）。
絶対値の線形補間ではない。これで「どの条も自分の公差のどのへんか」を
1本の軸で比べられる。実測では幅300の`+0.5`と幅500の`+1.5`（どちらも
自分のプラス公差の半分）が**同じ横位置**に出る。

**幅そのものは軸から消える。** 利用者の判断——絶対値だと幅狭の条が描画する
意味がないくらい潰れ、軸を2本に割ると見やすさと見栄えを失う。幅は測定表と
ロット列が持っている。

条ごとの公差は**セルのNG判定と同じ`toleranceDetail(kind,j)`から取る**。
ここだけ別の出どころにすると、図と表で判定が食い違う（今回がまさにそれ）。

#### 帯は行ごとに描く

両側公差なら下限→−1・上限→＋1で**全行の縁がそろい、1本の帯に見える**。
片側公差（プラスかマイナスが0）の条だけ縁が寄り、「その条は基準が限界と
同じ」が図に出る。分岐を持たず、行ごとの`--r-low`/`--r-high`という1つの
仕組みで両方を satisfies する。

#### ロットの色帯

行の左端に3pxの色帯を重ねる。色は測定表のロット列・条割の帯と同じ配色で、
**どの条がどの子ロットか**が図だけで追える。**`border-left`にしないこと**
——内容の箱が縮み、点の`left:%`が最大3pxずれる。

#### 写像は1本だけ

`WL.toleranceScaleView`（絶対値・縦向き）は廃止し、`WL.toleranceRelView`
1本にした。図と先読みリング（転送中の速報）が別の式を持つと、リングと確定後の
点が別の場所に出る。リングは**測定器から1文字届くたび**に動くので、
40条ぶんの公差を引き直さないよう、**表示範囲は図が持っている値**
（`data-viewlo`/`data-viewhi`）を読み、引くのは**いまの条1件だけ**。

#### 固定は`tests/test_tolscale.js`（32件）

新設は「基準は0・上限は+1・下限は−1」「範囲の中点は0にならない（基準に錨を
下ろしている）」「下限と上限が基準から等距離」、そして**異幅分割の一式**：
全条が公差内と判定されるか／自分の公差で同じだけ上振れした条が同じ横位置に
出るか／両側公差なら帯の縁が全条そろうか／子ロットの色帯が2ロットで2色か。
