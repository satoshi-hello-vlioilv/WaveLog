# §9.48 メイン画面ヘッダーの再設計

ボタンとバッジが増えるたびに継ぎ足してきた結果、高さも角丸も字送りも
バラバラで、**何が状態表示で何が操作なのかが見た目から分からない**状態に
なっていた。役割で3つに分ける。

| グループ | 中身 | 性格 |
|---|---|---|
| `.hd-context` | ファイル名・鮮度(§9.46) | 今どのデータを見ているか |
| `.hd-status` | モード・現場段取り・使用設備 | **この端末の状態** |
| `.hd-actions` | 検索・表示件数・再読込・表示サイズ・印刷 | **一覧への操作** |

- 状態は`.hd-chip`(**見出し+値の2段**)。「編集モード」とだけ書いてあるより
  「モード / 編集モード」の方が、何を表す表示なのかが読んで分かる。
  値は状態で色が変わる(`.hd-chip-mode.is-view`/`.is-schedule`、
  `.hd-chip-equip.is-unset`、`.is-warn`)。
- 操作は`.hd-btn`/`.hd-search`/`.hd-field`。裸の`<input>`/`<select>`ではなく
  `<label>`が枠を持ち、`表示件数`のような**項目名を枠内へ入れる**。
- **全コントロールが`height:var(--ctl-h)`・`border-radius:8px`**。左ナビ項目と
  同じトークンなので、表示サイズ(5段階)を変えても崩れない。
- 幅1180px以下では文字と余白を詰めて1行を保つ(折り返すとヘッダーが2段に
  なり、下の一覧が跳ねる)。
