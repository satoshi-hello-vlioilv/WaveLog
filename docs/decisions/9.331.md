# §9.331 マスタ管理のタブは「いつの分の応答か」で描く

### 症状

`test_stopeq` が**通しでだけ落ちていた**（単独では通る）。落ちるのは
`page.click('#masterMaintAdd')` のタイムアウトで、そのときの画面を撮ると——

    見出し: 設備停止マスタ
    中身  : 操業データ項目の盤（`op-bar` / `opEqPick`）
    追加ボタン: 無い

**見出しだけ切り替わって、中身は前のタブのまま**だった。

### 原因

マスタ管理の描き直しは `loadMaintInner()` の1箇所（§9.324 R3）だが、
**取りに行ってから描く**——専用の画面（`special:`。操業データ項目の盤など）は
`sp.load()` の中で `/api/operation-item-master` を待ってから
`#masterMaintForm` を書く。

タブを切り替えても**前の取得は止まらない**ので、

1. マスタ管理を開く → 先頭の「操業データ項目」の盤が取りに行く（遅い）
2. 別のタブ（設備停止）へ移る → 見出しと汎用の一覧が描かれる
3. **1の応答が届いて盤を書き込む** → 2で描いた一覧を上書き

という順になる。§9.200 で作業予定について書いた
「取りに行った応答は『いつの分か』で捨てる」と**まったく同じ形**が、
マスタ管理では手当てされていなかった。

**手元にマスタを置いた端末では往復が一瞬なのでほとんど起きない。**
マスタを共有に置くと1回の取得に数秒かかる（§9.263／§9.273）ので、
**現場ではむしろこちらがふつう**——そして「マスタ管理を開いてすぐ目当ての
タブを押す」はいちばん多い操作。

### どうしたか

`loadMaintInner()` が**世代**（`maintState.loadGen`）を1つ持つ。

- **汎用の一覧**: 取得のあと、世代が変わっていたら**描かない**
  （`maintState.items` も書き換えない——控えまで書くと、いま開いているタブの
  一覧が前のタブの中身で並ぶ）。読み込み失敗の文言も同じ。
- **専用の画面**: 自分の中で描いてしまうので、捨てるだけでは戻らない。
  **負けたほうが今のタブを描き直す**（`sp.load()` が済んだ時点で世代を見て、
  変わっていたら `loadMaintInner()` を呼び直す）。呼び直しは世代を上げるので
  それ以上は続かない。

**専用の画面15本へ門を配らないこと**——配ると、画面を1つ足した人が
書き忘れたところだけ静かに戻る（§9.324 R3 で `if` を並べるのをやめたのと
同じ理由）。門は `loadMaintInner()` の1箇所。

### 網（`tests/test_mmswitch.js`）

**応答をわざと遅らせる**（`page.route` で2秒。§9.312 と同じ理由）——
遅らせない網は**直す前でも通る**。

- 遅い盤 → 汎用の一覧へ移る: 見出し・前の盤が残っていないこと・
  **「追加」が押せること**まで見る。
  **「見出しが変わった」だけを見ないこと**——見出しは取りに行く前に書くので、
  上書きされていても必ず通る。
- 汎用 → 汎用でも同じ（前のタブの行が一覧に並ばない）。
- 遅い盤のタブへ**戻れる**こと（描き直す作りで戻る道を塞いでいないか）。

2つの門を**別々に外して**、それぞれ落ちることを確かめてある
（専用側を外すと2件・汎用側を外すと1件）。

### この赤を「順番のせい」で片付けないこと

`test_stopeq` は単独では通るので「テストの順番の問題」に見えたが、
**落ちた理由は本物**だった（§9.234 ⑧ と同じ）。先行する2本が重いぶん
サーバーの応答が遅くなり、現場で起きる順序が検証環境で再現していただけ。

回した網: `test_mmswitch`・`test_stopeq`・`test_master`・`test_opdata`・
`test_rawmaster`・`test_storageui`・`test_filter`・`test_adhoc`。
**フルスイートは回していない。**

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **マスタ管理のタブは「いつの分の応答か」で描く**（§9.331、`loadMaintInner()`）:
  描き直しは1箇所に集めてあるが**取りに行ってから描く**ので、取りに行っている
  最中に別のタブへ移ると、**後から届いた前のタブの盤が今の画面を上書きする**
  ——見出しだけ新しいマスタで中身は前の盤（実際に「設備停止マスタ」の見出しの下に
  操業データ項目の盤が出て、「追加」が押せなくなった）。§9.200の「取りに行った
  応答は『いつの分か』で捨てる」と同じ形。世代（`maintState.loadGen`）を1つ持ち、
  **汎用の一覧は描かない**（`maintState.items`も書き換えない——控えまで書くと、
  いま開いているタブの一覧が前のタブの中身で並ぶ）、**専用の画面は負けたほうが
  今のタブを描き直す**（自分の中で描いてしまうので、捨てるだけでは戻らない）。
  **専用の画面15本へ門を配らないこと**（§9.324 R3。配ると、画面を1つ足した人が
  書き忘れたところだけ静かに戻る）。**手元にマスタを置いた端末では往復が一瞬なので
  ほとんど起きない**——共有に置くと1回数秒（§9.263／§9.273）で、「開いてすぐ
  目当てのタブを押す」はいちばん多い操作。固定は`tests/test_mmswitch.js`
  ——**応答をわざと遅らせること**（§9.312。遅らせない網は直す前でも通る）、
  **「見出しが変わった」だけを見ないこと**（見出しは取りに行く前に書くので、
  上書きされていても必ず通る。「追加」が押せるところまで見る）。
