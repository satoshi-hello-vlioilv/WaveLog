# §9.338 状態チップの色——正常は中立、橙は「設定要」、赤は使わない（REVIEW 4-1 ①）

## 何が問題だったか

ヘッダー右上の状態チップで、**同じ橙が2つの違う意味**を持っていた。

| チップ | 状態 | 前の色 | その橙の意味 |
| --- | --- | --- | --- |
| 現場段取り **並べ替え可** | **正常** | 橙 | （意味なし） |
| 現場段取り **設定要** | 手を打つ | **赤** | 危険 |
| 使用設備 **未設定** | 手を打つ | 橙 | 設定要 |

**色が逆に付いていた。**

- 正常な「並べ替え可」が**全画面でずっと橙**（`.hd-chip-static` は
  `--warn-bg`/`--warn-border`/`--warn-fg`）。橙は「要注意」の色なので、
  何も起きていないのに毎回そこへ目が行く。しかも**隣の「使用設備 未設定」
  （本当に手を打つべき状態）と同じ色**だった。
- 本当に手を打つべき「設定要」のほうが **赤（`--danger-*`）**。赤は
  「取り消せない・危ない」の色で、実績削除の `.sc-row-btn-danger` などが使う。
  設定が足りないだけの状態に使うと、**色が実際より重い意味を語る。**

## 決めたこと

| 状態 | 色 | 根拠 |
| --- | --- | --- |
| 並べ替え可（正常） | **中立**（素の `.hd-chip`＝白地・`--line` の枠） | 正常は目を引かせない |
| 設定要 | **橙**（`--warn-*`） | 隣の「使用設備 未設定」と同じ意味・同じ色 |
| 赤 | このチップでは使わない | 赤は取り消せない操作に残す |

- 変えたのは**CSSの2箇所だけ**（`20-shell.css` の `.hd-chip-static` を消して
  素のチップへ戻す／`90-state.css` の `.hd-chip-static.is-warn` を danger →
  warn へ）。**振る舞い・表示条件・文言は1文字も変えていない**
  （`access-mode.js` は触っていない）。
- **文字は今までどおり**「並べ替え可」「設定要」と出る——色を中立にしても
  情報は1つも減らない（§3「状態は色だけで伝えない」）。

## 踏んだ罠——`transition` の途中を読んだ

網を書いたとき、クラスを足した**直後**に `getComputedStyle` で色を読んだ。
`button.hd-chip` は `transition:border-color .12s,background .12s` を持つので、
**遷移の途中（＝前の色）**が返る。「使用設備 未設定」が白のまま読めて、
直したはずのCSSを疑うことになった。

**片方だけ正しく読めたことが手掛かりだった**——現場段取りチップは
`<span>` なので `button.hd-chip` の遷移が掛からず、最初から正しい橙を返して
いた。同じCSSの隣り合う2つで読めた／読めなかったが分かれたので、CSSでは
なく読み方の問題だと分かった。

CLAUDE.md §9.229 ⑥ に「**押した直後に読まない**——`background-color .15s` の
遷移の途中が返り、効いていないように見える」と既に書いてあった罠を、
そのまま踏んだ形。クラスを足してから **300ms 待ってから読む。**

## 網（`tests/test_headbar.js`）

**宣言ではなく描かれた色で見る**（§9.229 ⑥）。4件:

1. 正常の「並べ替え可」は中立（地に色を足さない）
2. 「設定要」は正常と違う色で言う
3. 「設定要」は「使用設備 未設定」と**同じ**橙（地・枠・文字の3つとも）
4. 「設定要」に**危険の赤を使っていない**

**両方向を見る**のが要点——前は「正常＝橙／設定要＝赤」だったので、
片側だけの網（例えば「設定要は橙」だけ）は、正常も橙のままの実装を通す。

危険の色は**トークンを器に載せてブラウザに解かせて**比べる
（`#rrggbb` と `rgb(...)` はそのままでは比べられない）。

A/Bで確かめ済み——前の色に戻すと **3件**（1・3・4）が落ちる。
