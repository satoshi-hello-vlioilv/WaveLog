# §9.256 操業データの「自動」項目を式で作る（利用者の指示）

利用者の指示:

  「操業データの選択肢のところに、取得データから組み合わせたり、計算式を
   組み合わせたり、条件式を組み合わせて、式を設定することで『自動』項目を
   作成できるようにしたいです」

#### ① 評価器を作らない。既にある2つの上に乗せる

要る道具は**もう両方ある**:

- **式の評価** … §9.111 の `WL.formula`（`eval` を使わない字句解析→構文解析→
  評価）。`+ - * / %`／`= <> < <= > >=`／`and or not`／`if(条件, 真, 偽)`／
  `round abs num concat left right len trim upper lower coalesce` が揃っている。
- **自動で入る値の1行** … §9.234 ② の `[自動値]`。置き場・幅・単位・寄せ・
  意匠・記録表示が**ふつうの項目とまったく同じ**に効く土俵。

だから足したのは`[自動値]`の語彙に **`式`** を1つと、式そのものを持つ列
`[自動計算式]` だけ。**2つ目の評価器を作らない**（§CLAUDE「同じ処理を
2つ持たない」）——作ると、列の計算式で直した挙動がこちらに届かない。

#### ② 書くのは「呼び名」。鍵の綴りを覚えさせない

式は `[製造板厚]`・`[条数]`・`[OS31795速度]` のように**画面に出ている名前**で
書く（§CLAUDE 2「思い出させない」）。`lot.mfgThickness` という鍵は
利用者からは見えない。参照できるのは2種類:

- **取得データ** … `AUTO_VALUES` の22件（仕掛・測定の記録・計算した値）
- **同じ設備の他の項目** … 人が打つ欄・自動で入る欄・他の式、どれも

**候補は押して入れる**——名前を思い出して打つのではなく、設定窓の一覧から
選んで挿す。**自分自身は候補に出さない**（必ず循環するので）。

#### ③ 綴りはサーバーが持つ。画面に書き写さない

`式`という鍵は`operation_repo.AUTO_FORMULA_KEY`の1箇所だけが持ち、
`/api/operation-item-master` と `/api/operation-form` の両方が
`autoFormulaKey` として返す。**画面へ書き写さないこと**——
`tests/test_opauto.js` の「画面のJSに鍵の綴りを書き写していない」が
機械で見張っており、実際にこれで捕まえた（一度書き写して落ちた）。

#### ④ 壊れた式は書いている時点で断る

§9.111 と同じ約束。**評価まで待つと、実データが全部空になってから気づく。**
保存の前に断るのは3つ:

- **式として読めない**（`WL.formula.check()` が理由を返す）
- **知らない呼び名**（候補に無い名前は、評価時にはただの空文字になるので、
  打ち間違えると「いつも空欄の欄」が黙って出来上がる）
- **自分自身の参照**（値が決まらない）

#### ⑤ 式どうしの参照は落ち着くまでまわす

式が別の式を参照できる以上、**上から1回だけ解くと並び順で答えが変わる**
——いちばん分かりにくい壊れ方なので、変化が止まるまで数回まわす。
**循環は回数で打ち切って空欄**にする（保存前に断ってはいるが、古い設定が
残っていても画面が固まらないように、実行側にも最後の砦を置く）。

#### ⑥ 「式で作る」は何個でも置ける

固定の鍵（ロット番号など）は**同じ値が2箇所に出る**ので1つに絞っているが
（§CLAUDE 8）、式は1本ごとに別の値を作る道具なので、1つ置いたら選べなく
なっては困る（§CLAUDE 4）。

**確かめるときの落とし穴**: 「欄が出る」「保存できた」だけを見る網は、
値を1つも計算しない実装でも通る。**計算された値そのもの**を見ること
（実際、`compile()`が返すのは関数ではなく`{columns,run}`で、
関数として呼んでいた誤りをこの網が捕まえた）。式を送らない保存で
**式が消えないこと**も見る（§9.212 ②）。
固定は`tests/test_opformula.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **操業データの「自動」項目は式で作れる。評価器は増やさない**（§9.256、
  利用者の指示「取得データから組み合わせたり、計算式を組み合わせたり、
  条件式を組み合わせて、式を設定することで『自動』項目を作成できるように」）:
  足したのは`[自動値]`の語彙に`式`を1つと、式を持つ列`[自動計算式]`だけ。
  **式の評価は`WL.formula`**（§9.111。`eval`を使わない自前の解析器）、
  **1行の土俵は`[自動値]`**（§9.234 ②。置き場・幅・単位・意匠・記録表示が
  ふつうの項目と同じに効く）——どちらも既にあるので**2つ目を作らない**。
  **書くのは呼び名**（`[製造板厚]`・`[条数]`・`[他の項目名]`）で、鍵の綴りは
  利用者に見せない（§2）。候補は**押して入れる**、**自分自身は候補に出さない**
  （必ず循環する）。**鍵の綴りはサーバーが答える**（`AUTO_FORMULA_KEY`を
  `autoFormulaKey`で両方の口が返す）——画面へ書き写すと
  `tests/test_opauto.js`の「画面のJSに鍵の綴りを書き写していない」が落ちる
  （実際に一度落ちた）。**壊れた式・知らない呼び名・自分自身の参照は保存の
  時点で断る**（§9.111。評価まで待つと実データが全部空になってから気づく）。
  **式どうしの参照は落ち着くまで数回まわす**——上から1回だけ解くと並び順で
  答えが変わる。循環は回数で打ち切って空欄（保存前に断ってはいるが、古い設定で
  画面が固まらないように実行側にも最後の砦を置く）。**「式で作る」は何個でも
  置ける**（固定の鍵は同じ値が2箇所に出るので1つに絞るが、式は1本ごとに別の値を
  作る道具・§4）。**確かめるときは計算された値そのものを見ること**——
  「欄が出る」だけを見る網は値を1つも計算しない実装でも通る（`compile()`が
  返すのは関数ではなく`{columns,run}`で、関数として呼んでいた誤りをこの網が
  捕まえた）。固定は`tests/test_opformula.js`。
