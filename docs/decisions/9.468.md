# §9.468 一覧の道具の帯は2段（すぐ使う操作／常に見る状態）・決めたら触らない設定は「☰ 表示」へ・開いた窓はその場で閉じる（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

> 仕掛一覧をスケジュールと並べて表示する場合、統一感もなくバラバラしていてメニューがゴチャつきます。
> すぐに必要な機能とそうでもない機能、常に見えていないといけない表示と調べてわかればよい表示に分けて、
> 機能を維持しつつ使いやすいUIUX設計でメニュー構成を見直してほしいです。一度表示したフィルタ機能も
> 閉じ方がわかりにくかったり使い勝手の面も工夫して設計をお願いします。

確かめたこと（利用者の答え）: 「2段：操作＋状態（推奨）」「単独の一覧にも当てる（推奨）」。

| 物差し | 前 |
| --- | --- |
| 一覧の上の帯の段数 | 5段 |
| 帯の高さ（一覧の本文へ回せない高さ） | 236px |
| 帯の中の枠（群の囲み） | 4つ（それぞれ別の見た目） |

## 分け方

| 分類 | 何 | 置き場 |
| --- | --- | --- |
| すぐ使う操作 | プリセットの切り替え・効いている条件・その場フィルタ | 1段目（常に見える） |
| 常に見る状態 | 元データの時刻（押すと再読込）・件数とページ・結合（足した列数・失敗）・色の印 | 2段目（読む行・枠なし） |
| 決めたら触らない設定 | 表示列・行間・並び（いつも使う並び）・表示件数・子ロットの畳み | 「☰ 表示」の浮きパネル（1段目の右） |
| たまに使う操作 | 条件を追加・条件を作る・登録一覧・全解除 | ⋯ |
| 調べてわかればよい | 結合の相手・行数、どこで切ったか | 札の`title`（狭い器では短い名乗り） |

## 直したこと

- 帯を2段にした（1段目＝絞り込みのバー＋「☰ 表示」、2段目＝`#listToolbar`の状態の行）。群の枠はやめた
  （枠の中に枠を作らない）。**IDは変えない**（配線と網がそのまま効く）。
- 「☰ 表示」は`WL.popMenu`で開く浮きパネル（`.wl-menu`・`role=dialog`）。名前の列は固定幅で欄の左端が
  そろう。いつも使う並びのメニューは**パネルの中で開く**（浮きパネルの中に絶対配置を作らない）。
  ボタンは絞り込みのバーの席（`#filterBarSlot`）へ`placeViewButton()`が移す——バーが無い一覧では帯の先頭。
- 「＋ 条件を追加」は⋯の先頭へ畳んだ（運用の主動線はプリセットとその場フィルタ・§9.286 ①）。
- **開いた窓はその場で閉じる**: その場フィルタの行の右に ✕、条件を作るの見出しに「✕ 閉じる」。Escは
  バーぜんたいで受ける（入口のボタンに焦点が残っていても閉じる）。開くのは**同時に1つ**。開いたら
  押せる最初の欄へ焦点を置く。値の入った欄のEscは今までどおり先に「解除」。
- スケジュールと並べたとき: プリセットは**名前だけ**（当てていないときは「プリセット▾」＝役の名前だけ）、
  結合は短い名乗り（`data-short`・全文は`title`と読み上げ）、ページの真ん中の最小幅を外す。

| 物差し（幅380px・スケジュールと並べたとき） | 前 | 後 |
| --- | --- | --- |
| 帯の段数 | 5 | 2 |
| 帯の高さ | 236px | 81px |
| 帯の中の枠 | 4 | 1（絞り込みのバーの面） |
| 一覧の先頭行の高さ | y=348 | y=193 |
| 開いた窓の中の閉じる道（条件を作る／その場フィルタ） | 0／0 | 1／1 |
| Escで閉じる（条件を作る／その場フィルタ） | ×／× | ○／○ |
| 同時に開いている窓 | 2まで | 1 |
| 単独の一覧（1728px）の帯 | — | 2段（42＋30px）・「表示」のパネルの左端 5／5 そろう |

## 固定する網

- `test_filter.js` … 条件を追加は⋯の中／その場フィルタは ✕ がありEscで閉じる／開くのは1つ／条件を作るは ✕ で閉じる
- 表示列・表示件数・いつも使う並びを触る網は`W.listView(page)`で「☰ 表示」を開いてから押す（人と同じ道）
