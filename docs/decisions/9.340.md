# §9.340 読み込みの秒数は「遅いときだけ」出す。「遅い」の答えは1箇所（REVIEW 4-1 ④）

## 何が問題だったか

一覧のツールバーに **「0.2秒」** のチップが**常に**出ていた。

作業スケジュールは §9.198 で既にこう決めてある——

> サーバーが返した内訳をそのまま出し、**遅いときだけ見えるところへ出す**
> ——速いときに毎回ミリ秒を並べても読まれない。

ところが一覧だけ守れていなかった。しかも `renderLoadChip()` の頭には
「**遅かったときだけ**目立たせる(速いときに出しても読む理由が無い)」と
書いてあり、**説明と実装が食い違っていた**——実際に切り替えていたのは
`is-slow` の**色だけ**で、出す／出さないは切り替えていない。

さらに「遅い」の答えが **2つ**あった。

| | しきい値 |
| --- | --- |
| 作業スケジュール（`SC_SLOW_MS`） | 1200ms |
| 一覧（`renderLoadChip`） | 1500ms（しかも色にしか効かない） |

## 決めたこと

- **「この読み込みは遅いか」の答えは `WL.slowLoadMs`（`base.js`）の1箇所**
  （§9.163）。値は作業スケジュールの 1200ms をそのまま採ったので、
  **スケジュール側の見え方は1pxも変わらない**（§9.132）。
- 一覧のチップは **`WL.slowLoadMs` を超えたときだけ出す**。速いときは
  `hidden`。出ている＝遅い、なので素の見た目も警告色でよい。
- **内訳の入口は消さない**（§4）。チップの `title` は速いときに消えるので、
  **鮮度チップの再読込メニューへ内訳を移した**——作業スケジュールが浮き
  メニューに「読み込みの内訳」を持つのと同じ形（§9.300 ①）。
- **文言は1箇所**（`loadBreakdownLines()`）。チップの `title` とメニューの
  両方がここを読む。2つ持つと片方だけ直した状態が作れる。

## 網（`tests/test_listcache.js`、7件）

- 速いときは**出ない**／遅いときは**出る**／遅いときは色でも言う（`is-slow`）／
  速いへ戻ると**また消える**（出しっぱなしにしない）
- **チップが出ていなくても再読込メニューから内訳を読める**（入口を消していない）
- 「遅い」の答えが1箇所にある（`WL.slowLoadMs`）——**網は数を書き写さない**。
  写すと、しきい値を直したときに網だけが古い約束のまま残る。

**「速いときに消える」と「遅いときに出る」の両方を見る**のが要点。片方だけの
網は、**常に出す実装（＝直す前）も、二度と出ない実装も通す。**

遅い側は **`page.route` で `/api/table` の応答をわざと遅らせて**作る（§9.312）。
内訳の数を書き換えて「遅いことにした状態」を作ると、**本当に出るかを一度も
通らない。**

A/Bで確かめ済み——常に出す形へ戻すと3件落ちる（実測でそのとき出ていたのは
「0.1秒」）。
