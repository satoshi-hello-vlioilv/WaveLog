# §9.505 一覧の上部メニューを「1面1サイズ」に——並びは「絞り込む→見せ方」、⋯は「条件」の面へ、言葉を1つずつ見直す（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

> 一覧類の上部メニューの文字がサイズ感がバラバラな印象です。
> メニューの文字のサイズとボタン類のUIのサイズとデザインや形状の統一感を出してスッキリした印象にしたいです。
> ポップオーバーメニュー内の文字列も同じなので、…使う頻度にも応じたわかりやすく使いやすい直感的に使える
> 探しやすい、究極は探させない考えさせない先を読むUIUXを目指してメニューの再設計再構成して下さい。
> メニューに使う表現としての文字列1つ1つにも拘って的確な表現になっているか、改めて再設計して下さい。

> 作業スケジュール一覧もお願い

案（測った値・案の見本のキャプチャ・言葉の表）を見せてから進めた（利用者の答え「続けて」）。
進め方は段に分けた——**段1 ＝ 仕掛・品質の帯と、そこから開く面**（この節）。作業スケジュールの帯と面（段2）、
データ一覧・実績の帯（段3）は続きの節で扱う。

## §9.449 との関係（なぜ今度は揃えるのか）

§9.449 で「浮きメニューの寸法を揃える」を**一度却下**された（列見出し 12→13px・項目 24→36px）。
今回はそれと逆向きではない:

- **動かしたのは字の大きさだけ**。項目の余白は変えていない——ただし項目の高さは中身なりなので、字を 13→12px に
  したぶん **34→32px に低くなった**（4面・下の表）。却下されたのは「高さを36pxへ上げる」と「12→13px に大きくする」方向で、
  今回はどちらもしていない。
- 揃えた値は **12px**——却下のとき利用者が残した列見出しの値そのもので、§9.476 で利用者が「表示」パネルに
  選んだ「字は1つ・差は太さと濃さ」の作法。**利用者が既に選んだ形を、ほかの面へ広げた**。
- 「読む人に何が良くなるか」（§9.449 の教訓）: **字の大きさは重要度として先に読まれる**（前注意的な処理）。
  同じ役目（ボタンの名前・いまの値・補足）が面ごと・ボタンごとに違う大きさで書かれていると、重要度が違うのかと
  読み直すことになる。1面の中の字を1つにすると、役目の差は太さと濃さだけが言うので、読み直しが要らない。
  さらに**9.5px の字が消える**（§9.444 で「小さすぎる」とした寸法が、プリセットと⋯の説明に残っていた）。

## 測った（評価関数）

物差しは3つ——帯の中の**字**の大きさ・**押す物**の高さ・角丸の種類（`test_listbar.js`の4節と同じ数え方）。
数えないもの: 開く印「▾」（字ではなく記号・1種）、押す物の**内側**の部品（検索欄の中の入力・ページめくりの
中の ‹ ›——外側の器が高さを持つ）。1728×1030（利用者の 2160×1440・125% 相当）・単独の仕掛一覧。

| 物差し | 前 | 後 |
| --- | --- | --- |
| 帯の字の大きさ | **4種**（10・11・12・14px） | **1種**（12px） |
| 帯の押す物の高さ | **2種**（1段目 30／2段目 26px） | **1種**（30px） |
| 帯の押す物の角丸 | **2種**（8・10px） | **1種**（8px） |
| 1つのボタンの中の字 | 「プリセット」11px＋「なし」14px＋「▾」11px | 12px（名前 500・値 800） |
| プリセットの面の字 | 4種（9.5・12・13・14px） | 1種（12px） |
| ⋯の面 → 「条件」の面の字 | 2種（9.5・14px） | 1種（12px） |
| 再読込の面の字 | 3種（11・12・13px） | 1種（12px） |
| 列見出しの右クリックの字 | 2種（11・12px） | 1種（12px） |
| いつも使う並びの字 | 2種（11・12px） | 1種（12px） |
| 帯と面の**いちばん小さい字** | **9.5px** | **12px** |
| 表示列までの手数 | 2（「☰ 表示」→「表示列を編集」） | **1**（帯の「表示列」） |
| 「表示」という名のボタン | **2**（ヘッダー・帯） | **1**（ヘッダー） |
| 同じ働きに2つの名前 | 1組（「全解除」と「全部外す」） | 0 |
| 一覧の無い画面に出る「一覧を検索」 | 1（実績の画面・打っても何も起きない） | 0 |

帯の高さは2段目が 26→30px になったぶん **4px 高くなった**（1段目は元から 30px）。

## 直したこと

### 並び（左から、する順）

```
1段目: [🔍 一覧を検索] [プリセット なし▾] [▼ 条件 ⓪▾] [列で絞り込む]            [▦ 表示列] [表の見せ方▾]
2段目: [元データ 9/17 10:14 ⟳]  全 2,003件  [‹ 1–1,000 ›]  （結合・色の札）
```

- 左の群＝**絞り込む**（広い→狭い: 文字で探す → 組み合わせ → 条件 → 1列だけ）。右端の群＝**見せ方**。
  群は近さで分ける（枠で囲まない・§CLAUDE 画面基準 10）。
- **「一覧を検索」をヘッダーから帯の先頭へ移した**。絞り込みの仲間なのに帯から離れていたうえ、ヘッダーに居たので
  **実績の画面にも出て、打っても実績の表には何も起きなかった**（§CLAUDE 画面基準 4。検索は仕掛・品質の一覧を
  読み直すだけ）。帯は一覧と一緒に分割表示・ポップアップへ運ばれるので、**作業スケジュールの仕掛一覧でも
  文字で探せるようになった**（前はヘッダーごと伏せられて探せなかった）。
- **表示列を帯へ直に出した**（`#listColumnBtn`・`fa-table-columns`）。§9.476 で「よく使う」を受けてパネルの
  いちばん上へ置いたが、まだ2手だった。データ一覧・実績・作業スケジュールと**同じ名前・同じ印**になる。
- **⋯を無くし、中身を「条件」の面の下半分へ**移した。⋯は中身を言わず、しかも中身の4つは全部が条件の操作で、
  状態（効いている条件）と操作（足す・作る・外す）が別の面に分かれていた（§CLAUDE 画面基準 2）。
  「条件」のボタンは**0でも押せる**（足す入口もこの面にある）。

### 寸法（1面1サイズ）

- 帯の中は**字1つ・高さ1つ・角丸1つ**。値は**置き場1つ**（`#genericFilterBar,#listToolbar{--lt-h;--lt-fs}`）で、
  作業スケジュールの狭い器（分割・ポップアップ）は**置き場の値だけ**を宣言し直す（26px・11px）——§9.449
  「揃えるのは値ではなく値の置き場」。前は狭い器の中でも 10・11・12px、26・30・34px が混ざっていた。
- 差は大きさではなく**太さと濃さ**: 名前（「プリセット」「条件」「元データ」）＝500・薄め、値＝800、ボタン＝700。
- 開いたときの行（列で絞り込む・条件を作る）も帯の一部として同じ置き場を使う（前は欄だけ 14px）。
- 2段目の「元データ」は押せる物なので**押す物の顔**にした（前はチップの顔・角丸10px・26px）。
- 一覧から開く面（プリセット・条件・表の切り替え・再読込・列見出し・いつも使う並び・候補）は**字1種（12px）**。
  見出し＝800・項目＝700・説明＝400で薄く。余白は変えていない（項目の高さは字のぶんだけ 34→32px・下の表）。
- 字は**器ではなく中身へ**当てる。器の幅は`em`（`--w-*`）で決まっているので、器の字を変えると幅まで動く
  （いちど器へ当てて、表の切り替えの最小幅が 308→264px に縮んだのを網で見つけて戻した）。

### 言葉（いま → 後）

| 前 | 後 | 理由 |
| --- | --- | --- |
| ☰ 表示 ▾ | **表の見せ方 ▾**（行間・並び・表示件数・子ロット） | ヘッダーの「表示」（この端末の見え方）と同じ名前だった。作業スケジュールの同じ役のボタンも「表の見せ方」 |
| （パネルの中）表示列を編集 | 帯の **表示列** | 1手で届く。全部の一覧で同じ名前 |
| ▼ 0件 ▾ | **▼ 条件 ⓪ ▾** | 数えているのは条件の数。「件」は2段目の行の数（全 2,003件）と同じ単位に読めた |
| その場フィルタ | **列で絞り込む** | することを動詞で言う（「その場」「フィルタ」は覚えないと分からない） |
| （条件の面の札）その場 | **一時** | 登録しない、を言う |
| ⋯ → 条件を追加 | **条件を検索して足す** | 足し方の違い（検索）を言う |
| ⋯ → 条件を作る | **条件を作る・登録する** | ほかと違うのは「登録できる」こと |
| ⋯ → 登録一覧／窓の題「登録フィルタ一覧」 | **登録した条件とプリセット** | 何の一覧かを言う。入口と窓の題を同じ語に |
| ⋯ → 全解除 ／ 条件の面 → 全部外す | **条件を全部外す**（1つ） | 同じ働きは1つの名前 |
| プリセットの面「登録一覧で組み合わせを作る／直す」 | **登録した条件とプリセットを開く** | 行き先の名前と同じ語 |
| 条件を作る「カラム／比較／検査値」 | **列／比べ方／値** | 「検査値」は検査の値と読める誤った語。ボタンは「列」なのに欄は「カラム」だった |
| 列で絞り込むの欄「先にカラムを…」「カラムと条件を…」 | **列**・**比べ方** | 同じ物に2つの語を使わない |
| 0件の案内の出どころ「検索欄／フィルタ／その場フィルタ」 | **一覧を検索／条件／列で絞り込み** | 帯のボタンの名前と同じ語 |
| 条件を検索して足す欄 | 頭に「＋条件」と名乗る | 隣の「一覧を検索」と同じ顔にしない（§9.345） |

変えなかった語: 「プリセット」（マスタ・登録の窓でも使う語）、「元データ」「再読込」（ほかの画面と同じ語）。

## 動かした値（キャプチャに写らない面も含めて全部・§9.449 の教訓）

`tests/fixtures/menu_look.json`（13面×17項目）との差は下のとおり（網が控えを書き直させる）。

| 面 | 動いた値（`test_popmenu.js` の13面×17項目の控えと比べて） |
| --- | --- |
| 表の切り替え | 項目の字 13→12px／項目の高さ 34→32px |
| 再読込 | 項目の字 13→12px／項目の高さ 34→32px |
| 組み合わせ（プリセット） | 項目の字 13→12px／項目の高さ 34→32px |
| 条件 | 項目の字 13→12px／項目の高さ 34→32px |
| 残りの9面（列見出し・予定の行・入れ子・測定データ一覧・モード・同期・説明のヒント・見本・「表示」） | **0** |

控えの13面×17項目では **8件**。控えが見ていない所（面の中の見出し・説明・札）で動かしたもの:

| 面 | 動いた値 |
| --- | --- |
| プリセット | 見出しの補足・項目の説明・群の名前・足元の断り 9.5→12px（見出し 14→12px） |
| 条件（旧⋯を含む） | 見出しの補足・札（固定／一時）9.5→12px、変数の添え字 11→12px、⋯の項目 14→12px・説明 9.5→12px |
| 表の切り替え | 見出しの補足 9.5→12px、見出し 14→12px |
| 再読込 | 内訳 11→12px、項目の説明 11→12px |
| 列見出し・予定の行の右クリック（`.col-head-menu`を共有） | 見出し・群の名前・幅の状態・説明・色見本の字 11→12px |
| いつも使う並び | いまの並び・空の断り 11→12px、並びの札 11→12px |
| 条件の候補（条件を検索して足す） | 群の名前・札・添え字・空の断り 9.5／11→12px |
| 狭い器（作業スケジュールの分割・ポップアップ）の帯 | 字 10・11・12px→11px、押す物 26・30・34px→26px、左右の余白 7〜10px→4px。1段目に入れるため「条件」「表示列」の字と「表の見せ方」の「表の」を畳む（印と読み上げは残す） |

**予定の行の右クリック**（作業スケジュール）は列見出しと同じ器なので、段1で群の名前 11→12px が一緒に動いた（段2の先取り）。
