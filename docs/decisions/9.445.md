# §9.445 起動アイコンはどのモードからも作れる——盤は「表示」へ、名前は作った側が残す

索引: [決定記録](README.md)

利用者の問いと指示:

> どのモードからも使えるショートカット作成はどのボタンから作成出来ますか？

> 2の案で修正して（＝「この端末だけに効く設定」として、ヘッダーの「表示」に
> ショートカット作成の節を1つ足す。入口は1つのまま）

---

## ① 測った（評価関数）

「**デスクトップに作る**」を押せるところまで、どのモードから・何手で行けるか。
（この容器はLinuxなので、Windows端末の状態は `GET /api/app/shortcut` の答えを
差し替えて再現した。作成のPOSTは投げていない。）

| モード | 直す前 | 直したあと |
| --- | --- | --- |
| 編集 | ○ 2手（マスタ管理 → 共通設定） | ○ **1手**（ヘッダー「表示」） |
| 閲覧 | ○ 2手（マスタ管理 → 共通設定） | ○ **1手**（ヘッダー「表示」） |
| スケジュール | **× 到達できない** | ○ **1手**（ヘッダー「表示」） |
| 設定を直せる面 | 1（共通設定） | **1**（「表示」）＝増やしていない |
| 押すと無関係な画面が開くボタン | **1**（読み込みの見せ方の行き先） | **0** |

---

## ② 何が食い違っていたか

**サーバーは3モードとも通していた**（`access_mode._ENDPOINT_EXTRA_MODES` の
`core.app_shortcut_create`＝`{'edit','view','schedule'}`。§9.410 で
「現場の端末（scheduleモード）・閲覧専用の端末こそ入口のアイコンが要る」と
書いてある）。**無かったのは画面の入口のほう**。

マスタ管理のタブは、スケジュールモードでは `maintDefVisible()` が
`/api/schedule/` のマスタと読み取り専用のものだけを残す（実測5枚:
勤務形態・換算係数・設備停止・設備停止の時間・テーブル生データ）。
盤が置いてあった**共通設定（`/api/path-config-master`）はこの5枚に入らない**
ので、現場の端末では**入口そのものが無い**——押しても何も起きないのではなく、
探しても見つからない状態だった。

**権限を開けただけでは機能は届かない。** 開けた側と画面の入口は、別々に
確かめること（§9.207 が列の設定で踏んだのと同じ取り違え）。

---

## ③ 直し方——入口は増やさず、「表示」へ節を1つ

§9.421・§9.444 の作法をそのまま使う。**「この端末に覚える設定」の入口は
ヘッダーの「表示」の1つ**で、増やすのは節だけ:

```
WL.lookSettings.register({
  key:'shortcut', title:'デスクトップの起動アイコン',
  render(host){ … },      // when は持たない＝どの画面・どのモードでも出す
});
```

- **`when()` を持たせない**のがこの節の値打ち。画面にもモードにも依存しない。
- **作れない端末では盤を伏せ、理由を字で書く**（「この機能はWindowsでだけ
  使えます（この端末は linux）」）。押せるのに何も起きないボタンを残さない
  （§CLAUDE 4）。
- **共通設定に残すのは、いまの状態と行き先だけ**（§9.433 で読み込みの見せ方に
  使ったのと同じ作法）。設定の持ち主は1箇所のまま、面が2つあるだけ。

### 節の並びは「することの順」

```
デスクトップの起動アイコン
まだ作っていません                      ← いまどうか（色だけで言わない）
[ デスクトップに作る ]                  ← 次にすること1つ
作成先 C:\…\測定伝送システム.lnk        ← 押す前に読める出どころ
起動するもの D:\WaveLog\Start.vbs
▸ 名前と絵を変える  いま: 測定伝送システム／アプリのマーク   ← 畳む
```

**名前と絵は畳む**（§CLAUDE 1「面積は頻度 × 重要度」）——端末ごとに1回
決めれば済むものに常時3行を割かない。畳んだ札には**いまの値**を書く
（§9.433）ので、開かずに何で作られるか読める。畳みのおかげで窓は
**570px**（畳まないと708px、絵をファイル指定にすると上限720pxを超えて
スクロールが出ていた）。

すでに在るときはボタンの字が「**作り直す**」になる——押して起きるのは
「作る」ではなく「同じ名前のものを作り直す」なので（§CLAUDE 4・6）。

---

## ④ 名前と絵は「作った側」が残す

盤を移したことで、**保存の道が無くなる**のが次の問題だった。名前と絵は
共通設定の欄（`data-pc-field`）として保存されていた（§9.433）が、その画面は
スケジュールモードでは出ない。残らないと、`status()` は名前からファイルを
探すので**作ってあるのに「まだ作っていません」**と出続ける。

そこで **`desktop_shortcut.create()` が成功したときに残す**（`remember()`）。

- 書くのは `shortcut_name` / `shortcut_icon` の**2鍵だけ**。置き場・読み込み先は
  ここからは一切触らない（あちらは編集モードの画面が持つ）。
- 残せなくても**作成そのものは成功として返す**（理由は1行残す・§9.328）。
- 画面の欄へ出すのは `status()` の **`savedName`**（残してある名前そのもの）。
  `name` は「空なら既定へ倒した結果」なので、欄へ出すと**決めていない名前を
  決めたように見える**（空欄なら既定が薄い字で出る）。

「作るときは渡された値をそのまま使う」（§9.433）は変えていない——保存値で
上書きすると「アプリのマーク」を選んだのに前の絵で作られる。

---

## ⑤ ついでに直した——開けない行き先を押す形にしない

同じ窓の「読み込みの見せ方」は**共通設定への行き先**（§9.436）で、
スケジュールモードでは開けない。実測すると、押すと**換算係数マスタが開いて**
いた（身に覚えの無い画面へ飛ぶ）。

開けるかを答えるのは**名乗り手**（`WL.openLookSettings.available()`）で、
その判定は `maintDefVisible()` の1箇所のまま（`WL.mm.maintTabOpenable(key)` で
聞くだけ・規則を写さない）。開けないときは `button` ではなく `div` で出し、
「このモードでは開けません」と書く（§CLAUDE 4）。

---

## ⑥ 固定した網

- `tests/test_uisize.js`（+13件）: 節が「表示」の中に在る／作れない端末では
  理由を字で出しボタンを見せない／**edit・view・scheduleの3モードとも**盤が出て
  作るボタンが1つ／作成先と起動するものが読める／名前と絵は畳んで札に
  いまの値／字は11px以上で窓が縦に溢れない／行き先は開けるときだけボタン。
- `tests/test_setpage.js`（+2件）: 共通設定に名前・絵の欄が**無い**こと
  （設定を直す面を2つにしない）と、状態と行き先は**在る**こと。
- `tests/test_shortcut.py`（+5件）: `savedName` を返す／`create()` が
  `remember()` を呼ぶ／残すのは2鍵だけ／残せなくても作成は失敗にしない。

Windows専用の道（実際に `.lnk` を作るところ）は、この端末では動かせないので
**網も「Windows以外では理由を付けて断る」までしか見ていない**（§9.410 のまま）。
