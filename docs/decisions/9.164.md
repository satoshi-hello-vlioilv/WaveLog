# §9.164 データ一覧の列幅と見出しの右クリック（利用者の指示）

利用者の指示は「列幅の調整を他の一覧と同じように変更可能に。通常はオートフィット、
右クリックメニューも同じ機能を」。§9.162で表示列の**設定パネル**は仕掛一覧と同じ
ものを使うようにしたが、**見出しそのものの操作**（幅を引く・右クリック）は
仕掛一覧にしか無かった。

同じ道具を使う。新しく作ったのは差し替え口だけで、判断や見た目は増やしていない。

- **`WL.columnWidthGrip(grip, opts)`**（`list-view.js`）: 掴む→追う→離す→保存という
  手順はどの一覧でも同じで、違うのは**引いている最中の見せ方**だけ。表(`#grid`)は
  colgroupの`<col>`、データ一覧はCSSグリッドなので`--rec-cols`を組み直す。
  `locked`/`startWidth`/`preview`/`commit`/`reset`の5点を渡す。
  **`#grid`側も同じ関数へ寄せた**——書き写すと、直したときに片方だけ直った状態になる。
- **`WL.openColumnHeaderMenu(ev,col,target,allColumns,src)`**: 5つ目の引数が差し替え口
  （`keys`/`label`/`currentWidthOf`/`refresh`/`openPanel`/`persist`）。**答えない口は
  仕掛一覧のふるまいのまま**なので、既定の呼び出しは1つも変わらない。

データ一覧だけが持つ約束が1つある。**「一度も保存していないうちは既定の15列」**
（§9.162）なので、幅を1回引いただけで並びを保存する瞬間に**隠す列を種まき**しないと、
次の描画から候補44列が全部並ぶ。判定は`recordInitialHidden()`の1箇所が答え、
一覧・設定パネル・見出しからの保存の3つが同じ関数を見る。

**閲覧モードでは取っ手ごと出さない**——列レイアウトマスタの保存はedit/scheduleにしか
開いていないので、掴めても保存で弾かれる。判定は`recordColumnsEditable()`の1箇所。

固定は`tests/test_reccols.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **見出しの操作（列幅・右クリック）は1つの道具を使い回す**（§9.164）:
  `WL.columnWidthGrip(grip,opts)`が「掴む→追う→離す→保存」を持ち、違うのは
  **引いている最中の見せ方**だけ（表はcolgroupの`<col>`、データ一覧はCSSグリッド
  なので`--rec-cols`を組み直す）。`WL.openColumnHeaderMenu(ev,col,target,allColumns,src)`
  の5つ目が差し替え口（`keys`/`label`/`currentWidthOf`/`refresh`/`openPanel`/`persist`）で、
  **答えない口は仕掛一覧のまま**。**書き写さないこと**——同じ処理を一覧ごとに
  持つと、直したときに片方だけ直った状態になる。データ一覧は
  「一度も保存していないうちは既定の15列」（§9.162）なので、**見出しから初めて
  保存する瞬間に隠す列を種まきする**（`recordInitialHidden()`の1箇所が答え、一覧・
  設定パネル・見出しの3つが見る）。忘れると幅を1回引いただけで候補44列が並ぶ。
  閲覧モードでは取っ手ごと出さない（`recordColumnsEditable()`）。
