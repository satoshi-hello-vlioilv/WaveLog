# §9.595 BOX実績の突合——設備ごとの実績ファイル（実績_{設備}.sqlite3）で当たったら、開始・終了を作業時間にして完了へ・当たった行は予定へ残す（7案→組合せ→3回目の O／L・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.594](9.594.md)｜関係: [§9.364](9.364.md)・[§9.365](9.365.md)・[§9.367](9.367.md)・[§9.514](9.514.md)・[§9.582](9.582.md)

## 経緯（利用者の言葉）

> 実績データを「\\Nlmsrvngy03\Read\【New】実績」に配置する。（このデータは過去1カ月までさかのぼった最新の実績であるが、
> 順次更新され、1か月以上経つものは保持されないので、データを突き合せたらこちらで保持する機構を設けておく必要がある）
> 実績_LS4.sqlite3といったような、「実績_＊＊＊.sqlite3」の＊＊＊が設備名となるファイルを検索設備名が一致するものを
> 突合せ対象とし、「ﾛｯﾄ番号」、「鋳造番号」、「BOX番号」をキーとして突合せを行い、データを取得する。取得したデータの中から、
> 「BOX実績_作業開始_日付」と「BOX実績_作業終了_日付」を使って作業時間を登録し、完了データへ移行する仕組みに変更したい。

確かめた4つ（利用者の答え）: BOX番号は**仕掛にある**／完了は**実績に当たったら**（仕掛に残っていても）／残すのは
**当たった行だけ**（予定を開いたときに加え、**裏で定期にも**）／2つの日付の列は**時刻まで**持つ。

## 1. 物差しと前後の値

同じ材料（仕掛に残る2件・仕掛から消えた2件・どれも実績に当たる・うち1件は時刻が逆転）で、実績のある予定4件を数えた
（`tests/test_boxactual.py`の場面。旧は main 73c2163 のコードで、旧が表せるいちばん近い形＝1つのファイル・同じ3つの鍵・開始の列なし）:

| | 完了 | 時刻つきで完了 | 別の設備のファイルへ取り違え |
| --- | --- | --- | --- |
| 旧（73c2163） | 2/4 | **0/4** | 測れない（設備ごとのファイルを読めない） |
| 新（旧い形の定義のまま） | 2/4 | 0/4 | — |
| 新（BOX実績突合） | **4/4** | **3/4** | **0** |

残る1件は終わりが始まりより前の行で、**作業時間にしない**（完了にはし、時刻は人に入れてもらう）。新しいコードでも旧い形の
定義なら旧と同じ答え（今まで動いている現場の見え方は変わらない）。

## 2. 決めたこと

1. **データソースは「ファイル名の型」を持てる**（`データソースマスタ[ファイル名の型]`・例 `実績_{設備}.sqlite3`）。
   型を持つ行の置き場は**フォルダ**で、型に合うファイルが設備ごとに1つずつの読み先になる。型の答え・フォルダの一覧・
   設備で引く道は`db_access`の1箇所（`normalize_file_pattern()`／`pattern_files()`／`cfg_for()`／`source_pattern()`）。
   設備名は`normalize_equipment_name`で比べる（`実績_ＬＳ４.sqlite3`も LS4）。**フォルダを1つの表として開かない**
   （`cfg()`が理由を言って断る・一覧に足す結合の相手にもしない）。
2. **写しの係は設備ごとに1ファイルずつ写す**（鍵`<鍵>@<設備>`）。共有は直接読まない約束（§9.582 R8）はそのまま。
   フォルダを読めない理由は**変わったときだけ**記録へ残す（写しの係が毎周呼ぶので同じ1行で埋めない）。
3. **完了突合に「開始日時列」と「完了の条件」**（`[開始日時列]`・`[完了の条件]`＝`gone`／`hit`）。
   `hit`（実績に当たったら）は**仕掛を見ずに**相手で探し、当たれば完了。`gone`（空欄・今まで）は仕掛から消えたら。
   保存は**送らなかった鍵を消さない**（古い画面の保存で設定が消えない）・完了突合でない行には残さない。
4. **探すのは予定の設備と名前が一致するファイルだけ**（`actual_match._source()`）。別の設備のファイルに同じロットが
   あっても当てない。明細（予定へ入れた時点の仕掛行の写し）に無い鍵（BOX番号）は**いまの仕掛の行**から補う——
   ロット番号＋鋳造番号で**1行に決まるときだけ**（2行あれば「分からない」）。
5. **完了の道は`_done_by_join()`の1本**（保存済み・実績に当たった・仕掛から消えて当たった、の3つが同じ形）。
   開始・終了が両方読めて逆転していなければ**作業時間**（`join_times()`）。形は手で入れた時刻と同じで、出どころは
   「実績データ（定義名）」。**人が入れた時刻が先**（手入力があれば使わない）。
6. **当たった行を予定へ残すのは`actual_keep.persist()`の1箇所**。呼ぶ道は2つ: 予定を開いたとき（§9.364からの道）と、
   **書込役の端末の裏の見回り**（`actual_keep.start()`・既定15分・`actual_keep_interval_min`）。上書きはしない。
   残す形に開始・完了・定義名・条件を入れ、相手から消えたあとも同じ答え（完了・時刻つき）になる。
7. **一度きりの登録**: データソース`BOXACT`（`\\Nlmsrvngy03\Read\【New】実績`・`実績_{設備}.sqlite3`・一覧に出さない・
   役割は「実績」が空いていれば実績、埋まっていればその他）と、完了突合「BOX実績突合」（ロット番号＝ﾛｯﾄ番号・鋳造番号・
   BOX番号、開始＝BOX実績_作業開始_日付、終了＝BOX実績_作業終了_日付、実績に当たったら）。目印で1回だけ。
   入れた行は**この起動から**読めるようにする（`adopt_data_source()`・既にあるキーの読み先は変えない）。
   登録したあとは普通の行で、データ接続・クエリ結合から直せる（§9.367）。

## 3. 画面（E の手順・1728×1152 と 1536×864 で撮って採点）

基準と重み（先に決めた）: 理解性25・視覚化20・操作性15・面積15・一貫性15・誤りの防止10。

撮って見えた今の悪い所: ③の説明が**古い**（「当たらなければ着手」——§9.514で完了へ改めたのに残っていた）・
`**作業完了**`の印が**字のまま**出ていた・いつ完了にするか／開始の列を**決める所が無い**・⑤の下見が設備の違う同じ
ロットを「2件以上あったキー 6件」と**誤って数えていた**・どの設備のファイルを読んだか言わない・データ接続では型を
入れる所が無く、③が**フォルダを開こうとしてディスク I/O のエラー**を出していた。

| 回 | クエリ結合（完了突合の③） | データ接続（②の共有フォルダ） |
| --- | --- | --- |
| 1回目（A〜G） | G 78・C 76・B 73・F 70・D 66・A 62・E 59 → 80未満 | C 78・G 75・D 73・A 67・E 65・F 63・B 60 → 80未満 |
| 2回目（組合せ H〜K＋上位3） | I 85・K 84・G 78・H 77・C 76・B 73・J 70 → 90未満 | K 83・I 80・J 80・H 79・C 78・G 75・D 73 → 90未満 |
| 3回目（組合せ L〜O＋上位3） | **O 91**・L 88・M 86・I 85・K 84・N 83・H 77 | **L 85**・M 84・K 83・N 82・O 82・I 80・J 80 |

- **クエリ結合は O**: ③「いつ完了にするか — いまの条件」の札2枚（用途の札と同じ顔・語彙と中身はサーバーの
  `QUERY_JOIN_FINISH_WHEN`）→ 作業時間にする列（開始の列 → 終了の列）→ 見本の箱（下見で当たった1件の開始〜終了と
  1日（0〜24時）の中の位置・分・出どころ、当たった件数のうち作業時間を登録できる／時刻を読めない／逆転の内訳）。
  数えるのはサーバー（`probe_finish`の`sample`／`timed`／`inverted`）。⑤は読んだファイルを設備ごとに言う。
- **データ接続は L**: 共有フォルダの欄の下に「ファイル名の型（設備ごとのファイル）」、見つかった設備の札、例
  （実績_LS4.sqlite3 → 設備「LS4」）。型を入れると上の欄の名前が「共有フォルダ」に変わる。③は「完了突合の相手」を
  先頭に、使えないこと（一覧）は**1行**で言う（同じ理由を4行並べると、窓に収まらない 1536×864 で使える行が下へ押し出された）。
- 撮影の前後（1728×1152）: クエリ結合の窓の中身 1378→1413px（③に札と見本の箱が入り、④から完了時刻の欄が抜けた）・
  データ接続 810→709px（③の重複を畳んだ）。

## 4. ついでに直したもの（元から赤だった網）

`test_actualmatch`の4件（設備停止の行を借りる節）は、変更の前から同じ値で落ちていた。原因は**テスト設備Aの停止内容が
全部 有効=0**（8件）だったこと——`test_scstop`の後片付けが、種の名前と同じ**元からの行**（段取り替え・清掃）まで論理削除し、
ほかの本も借りた行を消して、借りる先が1件も無くなっていた。`make_fixture.fix_master()`が借りる3件を戻す（中身は触らない）。
`test_dsrestart`の「押すとデータ接続の設定が開く」は通しで1回だけ落ち、単独では緑だった。待ちが押す前から在る器
（`#masterMaintList`）で、一覧の取得が遅い回だけ行0を読む——**押した結果そのもの**（データ接続の行）を待つ形へ直した。
同じ並びで2回は再現しなかった（何が遅らせたかは**分からない**）。

## 5. 網

`tests/test_boxactual.py`（純粋・一時の置き場と一時のマスタ）: 型の読み方・設備名の切り出し・設備で引く・写しの対象・
仕掛に残っても完了・作業時間・別の設備へ当てない・BOX番号を仕掛から補う・逆転は作業時間にしない・残した写しで同じ答え・
定義の保存（送らない鍵を消さない）・一度きりの登録・下見（設備ごと・内訳・見本）・できることの判定。
画面は`test_qjoinui`（③の札・開始と終了の列・見本の箱・切り替え）。

**分からないこと**: 現場の`実績_＊＊＊.sqlite3`の表の名前と列の正確な綴り（`ﾛｯﾄ番号`の半角・全角）は見ていない。
列は正規化して引く（`ﾛｯﾄ番号`＝`ロット番号`）ので綴りのゆれは吸収するが、表が2つ以上あるファイルでは先頭の表を読む
（違えば定義の「相手の表」を選ぶ）。日付の列の書式も見ていない（ISO・`YYYY/MM/DD HH:MM[:SS]`・`YYYYMMDDHHMMSS`は読む）。
