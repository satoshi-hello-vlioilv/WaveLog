# §9.114 設備ごとの「1ロットあたり標準時間」（実績が無い間の見積）

見積は実績から作る換算係数モデル（§6、`backend/load_factor.py`）が出す。だが
**実績が1件も無い立ち上げ時**はモデルが組めず、全設備一律の暫定既定値
（120分）になっていた。1ロットの所要は設備でまるで違うので、そのままでは
最初のスケジュールが使い物にならない。

設備マスタへ `[標準時間分]` を足し、**その設備の実績が足りないとき**の
見積として使う。

#### 優先順位

```
① その設備自身の実績モデル      basis='equipment'
② 設備マスタの1ロットあたり標準時間  basis='equipment-standard'
③ 全設備をまとめたモデル        basis='pooled'
④ 全体の暫定既定値 120分        basis='default'
```

**②が③より先**なのが設計の要点。`pooled` は他の設備の実績まで混ぜた統計で、
設備ごとの差をならした値になる。1ロットの所要が設備でまるで違うからこそ
「設備単位で持たせたい」という要望なので、そこへ他設備の平均を当てると
**この設定が一度も効かない**（他設備に実績のある現場では機能として死ぬ）。

逆に**その設備自身の実績が溜まったら①が勝つ**。標準時間で実績を上書き
しないこと——上書きすると、実績が集まっても精度が上がらなくなる。

#### 空欄は「未設定」であって0分ではない

`normalize_standard_minutes()` が、空欄・0・負・数にならない文字を
すべて `None`（未設定）へ落とす。**0を「0分」として保存しない**のが要点で、
0分の作業は無いので、空欄のつもりの0を仕様として受け入れると予定が全部
同じ時刻に潰れる。上限は1440分（丸1日）で、これは入力ミスの歯止め
——超える値を入れるとタイムラインが何日も先まで伸びて読めなくなる。
一覧では未設定を「120分（既定）」と書く（「0分」と出さない）。

#### 画面には「どれが使われたか」を出す

同じ数字でも、実績から出したのか・現場が入れた標準時間なのか・何も無いので
暫定なのかで、当たる見込みがまるで違う。行の見積へ `~` を付け、
ツールチップと「見積の根拠」で理由を書く。**設備の標準時間と暫定既定値は
言い分ける**——前者は登録済みの値なので直せば効き、後者は設備マスタが
未設定という別の状態で、打つ手が違う。

#### 設備タブはインラインのまま

項目が4つになり、マスタ管理のモーダル化の基準（`EDITOR_MODAL_MIN_FIELDS`=4）に
かかる。だが**どれも短い1行**でフォームは縦に伸びないので、モーダルにする
理由（一覧を圧迫する）が当てはまらない。`editorModal:false` で明示的に外す。
**しきい値そのものは動かさないこと**——5へ上げると設備停止（4項目）・
勤務形態（4項目）が黙ってインラインへ戻り、頼まれていない画面が変わる。

固定は`tests/test_eqstd.py`（14件。優先順位4段すべて・空欄の扱い・列が無い
古いDBでも落ちないこと）。標準時間を使う分岐を外すと落ちることを確かめてある。
