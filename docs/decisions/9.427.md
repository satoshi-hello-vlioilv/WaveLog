# §9.427 レイヤ名の綴り違いで、刃組画面の「選ばれた札」が全部死んでいた

索引: [決定記録](README.md)

利用者の報告「3D断面図バッジのONOFFの状態がバッジから読み取れません」。

## ① 何が起きていたか

`static/css/72-bladeset.css` の先頭が **`@layer components {`（複数形）**だった。
レイヤの並びを宣言しているのは `00-base.css` の1行だけで、そこに在るのは
**`component`（単数）**——**宣言に無い名前を書くと、そのレイヤは「宣言済みの
全部の後ろ」に置かれる**（CSSの決まり。最初に現れた順に末尾へ足される）。

つまり `72-bladeset.css` は `state` / `mode` / `print` / `utility` **より後**に
なっていた。結果として、`90-state.css` が1箇所で持っている
「選ばれた札の見た目」（§9.353）が**刃組画面では1つも効いていなかった**:

| 効いていなかったもの | 見え方 |
| --- | --- |
| `.bs-tg.is-on` ＋ `::before` | 入切4つ（板・刃・ゴムリング・スペーサー）が**全部「入」なのに点が白いまま** |
| `.bs-chip.is-on` | 模式図／断面図／立体図、端部／所要／台車差分／刃の状態が**どれも同じ顔** |
| `.bs-hide button.is-on` | 薄く／線だけ／出さない の**選ばれている1枚が分からない** |
| `.bs-stage3 .bs-btn.is-on` | 段取り（①②③）の済んだ手順が分からない |
| `.bs-g tr.is-pick>td`・`.bs-opts label.is-on`・`.bs-sc.is-on` | 同上 |

`!important` より静かで、`!important` より強い。**1文字**である。

**同じ誤りが `89-loaders.css`（§9.421）にもあった**——綴りを写したため。
両方直した。

## ② なぜ気づけなかったか

- **網は「入」を `aria-pressed` と `is-on` で見ていた。** 印は正しく付いており、
  **見た目だけが付いていなかった**——「印が付く」と「読める」は別のこと。
- `test_csslint.py` は「**レイヤの外に書いていないか**」を見ていたが、
  **名前が正しいか**は見ていなかった。綴り違いは「レイヤの中」なので素通りする。
- 局所の `[hidden]{display:none}` が**14行**書き足されていた（`.bs-stage[hidden]`
  等）。これはこの穴の**対症**で、`@layer utility` の `[hidden]` が負けるから
  必要だった。直したあとも残してある（§9.377 の決まりどおりで、害は無い）。

## ③ 直し方と、二度と起きないようにする網

1. **綴りを直す**（`component`）。刃組画面・読み込み中の並びの両方。
2. **`test_csslint.py`**: 使っている `@layer <名前> {` が**宣言した8つの中に
   在る**ことを見る。綴りに依らずこの種の事故を全部拾う（1段目・サーバー不要）。
3. **`test_bladeui.js`**: 「入」と「切」の札の**実際に描かれた地の色が違う**ことを
   見る（4.8c）。レイヤの並びが正しくても、当てる先を間違えれば同じ結果に
   なるので、**画面の側からも**固定する。

**欠陥注入で確かめた**: 綴りを `components` へ戻すと
`test_bladeui` が **5件**、`test_csslint` が **1件** 落ちる。戻すと緑。

## ④ 残る決まり

- **レイヤ名は宣言した並びの中から選ぶ。** 新しい名前を書きたくなったら、
  先に `00-base.css` の宣言へ足す（足さずに書くと、**全部に勝つ**）。
- **「選ばれている」は見た目で確かめる。** `is-on` が付いていることは、
  読めることの証拠にならない（§CLAUDE 3 状態は色だけで伝えない、の一段手前
  ——色すら出ていなかった）。
