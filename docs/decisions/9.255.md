# §9.255 単位「内部」を各UIへ・移行済みマスタの復活・削除窓の高さ・他PCの待機画面・組み換え帯（利用者の指示）

#### ① 帳票の組み換え帯は1行。畳んでよいのは「言い回し」だけ

利用者の指示「帳票表示画面の上部がごちゃついているので…コンパクトに
2行分くらいに」。帯に残すのは**決める2つ**（やめる／保存）だけで、
取り消せない「既定に戻す」は`⋯`の中へ離す（§CLAUDE 5）。`⋯`の面は
**帯の子のまま`position:fixed`で浮かせる**——`body`直下へ出すと「帯の中に
在るか」を見る網が空振りする。**開いた器は必ず控える**（§9.222 ①）。

**ここで一度やり過ぎた。** 畳む過程で、次の3つまで一緒に落としていた
（自分の網が捕まえた）:

- パレットの札 `6マス×20行` → `6×20`。**単位を落とした**——`6×20`は
  「6行×20列」とも「6mm」とも読める（§CLAUDE 6）。
- パレットの「掴んで／落とすと外れる／**押すだけでも出せる**」を`title`へ。
  「押すだけでも出せる」は**札の形からは読めない**うえ、掴めない環境での
  唯一の道でもある（§CLAUDE 4）。
- 見本の札の「**保存されません**」を`title`へ。これは「見本だ」という
  分類ではなく、**取り違えを防ぐ唯一の事実**で、触る画面では`title`が
  読めない（§9.222 ④）。

**畳んでよいのは言い回しであって、単位・できること・取り違えを防ぐ事実は
別物。** 収まりの知らせも「A4縦 1枚（残り18mm）」まで詰めたが、
**枚数と残り／超過のmmは落としていない**——長い言い回しだけが`title`へ移る。

#### ② 塊の中身は縦のマス数も持てる

利用者の指示「単純に何列何行だけでなく、データ内もグリッドに対応する形で
細かく調整できるように」。`rows`を`[ラベル,値,{span,rows,blank}]`で持ち、
`grid-row:span`で解く。**詰め方は`dense`**——縦に伸ばした項目の隣が空くので、
後ろの1マスの項目がそこへ入る（そこも空けたいときは「空きマス」を置く）。
§9.245の「マス数と空きマスはそのまま渡す」は壊さない。

#### ③ 移行済みの旧マスタが、消しても復活していた

利用者の報告「移行済みデータをすべて消したはずが、復活しました。
旧マスタは無ければ表示しない形にしたいです」。

原因は`migrate_legacy_choice_masters()`が読む`_legacy_source_rows()`で、
**元の6マスタを`ensure_*`で開いていた**こと——測定画面を1回開くだけで、
消したはずの7つの旧マスタが**空の表として作り直されて**いた。しかも
「読めなかった表」を`failed`へ数えていたため、**移行済みの目印が永久に
立たず**、開くたびに写しを試し続けていた。

直し方は2つで、**両方要る**:
- **無ければ作らない**——`tables(c)`に在るときだけ読む。`ensure_*`を通さない。
- **無いのは失敗ではない**——消した端末・新規導入の端末では最初から無いので、
  `failed`へ数えない。数えると目印が立たず、上の`ensure_*`と組で
  「毎回復活する」になる。

一覧は実在する表から作るので、消した表はナビからも消える。

#### ④ 範囲の札が3段に折れて、削除の窓が画面より高くなっていた

利用者の報告「ロールマスタの削除機能で対象が多い時にモーダルの範囲が
ウィンドウの高さを超え、ボタンを操作不能となり身動きが取れなくなりました」。

§9.251 ⑤の範囲の札（丸ぽち／設備名／件数）が**1行3段**に折れており、
設備が13件あると窓が画面より高くなって「削除する」にも`×`にも手が届かない。
**1行を1段に戻し、あふれたぶんは一覧の中でスクロールさせる**。あわせて
**設定の窓は画面より高くならない**ようにした（本文だけがスクロールする）
——器の高さを与えて`flex:1;min-height:0`の鎖を通す（§9.254 ①と同じ形）。

**確かめるときは対象を実際に増やすこと**——設備が2〜3件の検証用データでは
窓は画面に収まるので、**直す前でも通る**。

#### ⑤ 他のPCで待機画面（モーダル）が出ない

原因は2つ。
- `%LOCALAPPDATA%`が書けない端末で、**待機画面を開く前にプロセスが死んで
  いた**（黒い画面すら出ないので、利用者からは「何も出ない」としか見えない）。
  置き場は書ける場所を順に探して落ちる。
- 手元に写しが無いとき、**アプリ本体（クラウド同期フォルダー）から
  `loading.html`を読みに行っていた**——未ハイドレートだと十数秒かかり、
  そのあいだ何も出ない。**本体を読まずに組み込みの簡易画面で先に開き**、
  本来の写しは裏で作り直す（次の起動から本来の意匠・段階表示になる）。

**`app_url()`の直開きは最後の手段のまま**——サーバー未起動の`http://`を
開かせると、ブラウザの接続拒否画面が出る（利用者からは「エラー画面」に見える）。

#### ⑥ 起動時の白画面（指示書「改善①」）は、5点とも既に入っていた

指示書の5点を1つずつ実物で確かめた結果、**すべて実装済み**だった:

| 指示 | 実装 |
|---|---|
| 文書境界の背景色をそろえる | `index.html`の`<html style="background:#0d2029">`（§9.92） |
| `#appBoot`を最初のペイントで見える静的HTMLに | `index.html`に直書き＋`boot.css`（`00-base`+`95-boot`）だけで意匠が出る |
| 遷移に待ちを足さない | `loading.html`が`requestAnimationFrame`2回で`location.replace` |
| 早く外しすぎない | ブラウザ側4段階で解除＋8秒／12秒の保険 |
| 版付き資材を長期キャッシュへ | `app.py`の`cache_policy`が`?t=`付きに`immutable`（§9.97）。`asset_token`は資材の最新更新時刻なので**起動ごとには変わらない** |

**残る遅さは`import`（実測21秒）**で、これは指示書自身が別件としている。
`.pyc`はローカルへ逃がしてあるが、Pythonは**元ファイルの更新時刻と大きさで
古さを判定する**ため、`import`のたびに本体（クラウド同期フォルダー）の
`.py`へ触りに行く——そこでハイドレート待ちが起きる。
**これを消す唯一の手はハッシュ検証を外した`.pyc`（`UNCHECKED_HASH`）だが、
採らない**——CLAUDE.mdの「刻印は速さの門であって正しさの門ではない。
見誤っても古いコードは動かない」という安全側の性質を、そこだけ崩すことに
なる（古い`.pyc`が黙って動く）。**本体を手元へ置く以外に根治は無い。**

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **ブラウザへ渡したファイルを、その起動のあいだ差し替えない**（§9.314、利用者の報告
  「自分のPCでは起きないが、他のPCでは起動に失敗して待機画面が
  `ERR_FILE_NOT_FOUND`になる。**直接そのhtmlをクリックすると正しく起動する**」）:
  待機画面の写しは起動のたびに裏で作り直す（§9.255 ③）が、書く先が
  **いまブラウザへ渡したばかりの`loading.html`そのもの**だった。本体
  （クラウド同期フォルダー）の読み出しが遅い端末では、その差し替えが
  **ブラウザの立ち上がり中**に起きる（実測: 渡した1ms後ではなく1.2秒後）。
  **アプリを手元に置いた開発機では読み出しが一瞬で終わり、差し替えはブラウザが
  起動する前に済むので一度も再現しない**——「自分のPCでは起きない」の正体はこれ。
  §9.108／§9.270の「**自分が読んでいるファイルは名前を差し替えない**」を、
  待機画面でだけ破っていた。いまは`copy_waiting_page()`が
  **`loading.next.html`（次の起動用）へ書き**、実際に使う名前へ移すのは
  `promote_waiting_page()`＝**起動のいちばん最初**（まだ誰も開いていない時点）
  の1回だけ。**中身が同じなら何もしない**（差し替えの機会を1回減らす）。
  **開く直前にもう一度「読めるか」を確かめる**（`_readable_safe()`）——存在確認
  だけでは足りない（隔離されて0バイト・たった今消えた、が起こりうる）。読めなければ
  組み込みの簡易画面を書き直して開き、理由を`launcher.log`へ1行残す（§4）。
  **アプリは動いているのに利用者からは起動失敗にしか見えない**のがこの壊れ方の
  質の悪さで、原因が外（ウイルス対策・同期・掃除）にあっても同じ絵になる。
  **網は本体の読み出しをわざと遅くして測ること**——速いままだと、直す前でも
  差し替えが先に終わって通る（§9.108の「Linuxでは何も起きない」と同じ罠）。
  固定は`tests/test_faststart.py`（2つの欠陥で落ちることを確認済み）。
- **移行済みの旧マスタは「無ければ作らない」**（§9.255 ③、利用者の報告
  「移行済みデータをすべて消したはずが、復活しました。旧マスタは無ければ
  表示しない形にしたいです」）: `migrate_legacy_choice_masters()`が読む
  `_legacy_source_rows()`が**元の6マスタを`ensure_*`で開いていた**ため、
  **測定画面を1回開くだけで7つの旧マスタが空の表として作り直されて**いた。
  直すのに要るのは**2つとも**——①`tables(c)`に在るときだけ読む（`ensure_*`を
  通さない）②**無いのは失敗ではない**（`failed`へ数えない）。数えると
  移行済みの目印が永久に立たず、開くたびに写しを試し続けるので、①だけ直しても
  再発する。一覧は実在する表から作るのでナビからも消える。
  固定は`tests/test_rawmaster.py`。
- **選ばせる札が3段に折れると窓が画面より高くなる**（§9.255 ④、利用者の報告
  「対象が多い時にモーダルの範囲がウィンドウの高さを超え、ボタンを操作不能」）:
  §9.251 ⑤の範囲の札（丸ぽち／設備名／件数）が1行3段に折れ、設備13件で
  「削除する」も`×`も画面外へ出ていた。**1行は1段**にし、あふれは一覧の中で
  スクロールさせる。**設定の窓は画面より高くしない**（器の高さを与えて
  `flex:1;min-height:0`の鎖を通す・§9.254 ①）。**確かめるときは対象を実際に
  増やすこと**——2〜3件の検証用データでは窓が画面に収まるので**直す前でも通る**。
  固定は`tests/test_rollwipe.js`。
- **畳んでよいのは「言い回し」だけ。単位・できること・取り違えを防ぐ事実は別**
  （§9.255 ①、利用者の指示「コンパクトに2行分くらいに」）: 帯を1行へ畳む過程で
  ①札の`6マス×20行`を`6×20`にして**単位を落とし**（「6行×20列」とも読める・§6）
  ②「**押すだけでも出せる**」を`title`へ落とし（札の形からは読めず、掴めない
  環境での唯一の道・§4）③見本の札の「**保存されません**」を`title`へ落とした
  （分類ではなく取り違えを防ぐ唯一の事実で、触る画面では`title`が読めない・
  §9.222 ④）——の3件を一度に作った。**数と単位は詰めるときの対象外**で、
  詰めてよいのは長い言い回しのほう（それは`title`が持つ）。
- **起動の白画面は入り口が5つとも塞がっている。残るのは`import`の21秒**
  （§9.255 ⑥）: 文書境界の背景色（`<html style="background:#0d2029">`）・
  最初のペイントで見える静的な`#appBoot`・rAF2回での`location.replace`・
  4段階＋保険での解除・版付き資材の`immutable`（`asset_token`は資材の最新更新
  時刻なので**起動ごとには変わらない**）——全部入っている。**残る遅さは
  クラウド同期フォルダー上の`.py`のハイドレート待ち**で、`.pyc`をローカルへ
  逃がしても**Pythonが元ファイルの更新時刻と大きさを見に行く**ため消えない。
  **`UNCHECKED_HASH`の`.pyc`は採らないこと**——「見誤っても古いコードは
  動かない」という安全側の性質をそこだけ崩す（古い`.pyc`が黙って動く）。
  根治は本体を手元へ置くことだけ。
