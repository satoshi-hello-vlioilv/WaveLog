# §9.320 測定の桁は「測定器が保証できるところまで」

設計書（`SCHEDULE_MODE_DESIGN.md`）に節が書かれないまま、`CLAUDE.md` の
規則としてだけ残っていた回。本文は下の「守ること」。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **測定の桁は「測定器が保証できるところまで」**（§9.320-C、利用者の指示
  「測定機器によって保証できる測定精度が違うため、最終的な測定値は自動転送で
  判断される測定機器の情報で見極めデータの桁数を変更するように」）:
  §9.242 ②の「板幅は測定器によらず小数2桁」は**撤回した**——あれは
  「入口が両方1桁へ丸めていたのでノギスの2桁目が必ず0だった」という
  **不具合**を直した副作用で、器ごとの精度をそろえる根拠は無かった。
  コンベックスルールで測った値に2桁目を書くのは、**測っていない桁を
  測ったことにする**（§CLAUDE 6）。**マイクロメータ3桁／ノギス2桁／
  コンベックスルール1桁**を`MEASURE_DEVICE_DIGITS`の1箇所が持つ
  （`base.js`）。**器は記録の中に持つ**（`settings.deviceOf`）——画面の
  変数だと続きを別のPCで開いたときに桁が変わる（§9.91と同じ理由）。
  **判定した器は今ある1行の中で言う**（`#measureHeadBadges`。利用者の
  指示「表示のエリアを無理やりつくらず今あるスペースにうまくなじませて
  コンパクトに」）——行は増やさない。**転送を受けていなければ出さない**
  （§CLAUDE 4「できないと書く」の逆——常設すると場所だけ取る）。
  固定は`tests/test_devdigits.js`。
- **公差の桁は測定値と同じにそろえる**（§9.320-D、利用者の報告「板厚製造
  公差の表示が桁数溢れしている」）: 生の`range`は`1.475`が
  `1.4749999999999999`のように出る——二進では表せない値の引き算なので
  必ず起きる。判定は生の範囲のまま行い、**画面だけを`fixedToleranceValue()`
  で丸める**（§9.242 ②と同じ関数）。
- **フラットネスの全〇は「印を持つボタンだけ」を拾う**（§9.320-B、利用者の
  報告「全〇ボタンが使えません」）: `bindFlatnessInputs()`が`.flat-pick`を
  全部（＝全〇ボタンも含めて）拾っており、**先に付けた全〇の処理を
  上書きして**いた——押すと`btn.dataset.sym`＝`undefined`がいまの1マスへ
  入る。**器の名前ではなく`[data-sym]`の有無で拾う**（§9.233 ③）。
- **帳票の半自動の塊も、渡していない設定は消えない**（§9.320-E、利用者の
  指示「基本情報を含む、半自動登録内容の項目は内部データ修正してもほぼ
  修正が効きません……使えるように」）: `block_upsert()`が`content`／
  `span`／`rows`／`enabled`／`equipment`を**全部既定値へ倒して**おり、
  列数だけを送る呼び出しでも`[内容]`が空へ消えていた——空の塊は
  `rpMergeBuiltin()`がコードの既定の描き手へ落ちるので、**列数も表組みも
  ラベルの位置も一切効かなくなる**（設定は保存できて盤にも出るのに紙が
  変わらない・§4。§9.212 ②と同じ形で8度目）。**渡していなければ今の値の
  まま**（§9.212 ②）。**既定セルしか持たない4塊**（品質等級・寸法・
  品質情報・母材実績）は`[内容]`が最初から空だったので、この直しだけでは
  今までどおり効かない——`seed_default_cells()`が**1度だけ**既定の中身を
  入れる（`default_cells()`は「いま紙に出ている形」そのものなので、
  入れても紙は1マスも変わらない・§9.132）。**目印はパス設定マスタ**
  （`seed_mother_builtins`と同じ作法）——「空なら入れる」にすると、
  利用者が中身を消してコードの既定へ戻す道が塞がれる。
- **紙の測定データ・丈別データの表は本文と同じ大きさ**（§9.320-D、利用者の
  指示「十分に表示エリアが確保できている場合は通常のサイズを他のベース
  の文字サイズと合わせられるように」）: 実測すると2つの表だけ7.5pxで、
  他（`.rp-field`本文・`.rp-dim-table`）は8.5pxだった——**縮んでいたので
  はなく、地の大きさが違っていた**（`--rp-fit`は掛かっておらず器には
  余りがあった）。地を8.5pxへそろえ、**入らないときだけ**今までどおり
  詰めて縮める（`rpFitBlockBodies()`の段）。横に切れるセルは実測で
  7.5pxでも8.5pxでも0件——広げても文字は切れない。
- **ピッチ判定の塊は器の幅で段を切り替える**（§9.320-F、利用者の指示
  「横幅を狭くしてもきれいに収まるように。ラベル上下など使えそうな
  カスタム機能には対応させて」）: `@container`で3段——広い（180px、
  紙のマス数6）は今までどおり2列、狭い（119px、4マス）は1列、
  もっと狭い（88px、3マス）は**ラベルを上・値を下**。「ラベル上下」は
  設定ではなく**幅で自動**にする——この塊の中身は計算で作るので盤の
  マスを持てず（§9.274のセルが無い）、設定を置いても当てる先が無い
  （§4）。候補の表は狭い段で接触面・径の列を落とし、**落とした列は
  行の`title`へ残す**（§4）。固定は`tests/test_rptext.js`。
- **測定画面のレールは「通常使うボタン」だけにする**（§9.320-G、利用者の
  指示「『保存して一覧へ』ボタンが実質2つの機能を兼ね備えている形なので
  『データ一覧を開く』と『いますぐDBへ保存』の2つのボタンは不要」）:
  以前は測定値を打っても**「保存して一覧へ」か「測定を完了」を押すまで
  DBへ入らず**、15分ごとのタイマーは保存済みで送信に失敗した分の再送
  だけだった。ボタンを消すだけでは、測定を続けながらDBへ入れる唯一の
  手立てが消え、バッジは最後まで「未保存」と言い続けることになる
  （§CLAUDE 6）。**利用者の指示で前提のほうを本当にした**——
  `markDirty()`が`WL.autoSave.schedule()`を呼び、1.5秒落ち着いてから
  `collect()`→`reliablePut()`→`backupAndTrackSync()`を1回だけ通す
  （§9.273「共有越しでは数秒かかる」と同じ理由で落ち着かせる）。
  **測定中の転送には触らない**（§9.122）——値を書くこととバッジの文字
  だけで、`renderMeasureGrid()`も`#deviceInput`も触らない。
  **`lockCounts()`は呼ばない**——`saveLocal()`は条数・丈数を固定するので、
  裏で走らせると打ち始めた瞬間に条数を変えられなくなる。**新しいバッジは
  足さない**（利用者の指示どおり）——`#localState`（既存）が
  「未保存（画面の中だけ）」→「DBへ保存しています…」→「DBへ保存済み」と
  言う。失敗も黙らない（「後で自動的に再送します」まで書く）。
  固定は`tests/test_devdigits.js`。
