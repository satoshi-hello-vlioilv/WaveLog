# §9.260 共有の置き場を1枚で見せる（利用者の指示）

> マスタの管理画面の共有設定の部分も今回の改良に合わせて設定しやすいように
> わかりやすく作り替えてほしいです。

共有の設定は3つある——**作業予定**（`schedule_share_path`）・**測定データ**
（`records_share_dir`、§9.258）・**マスタ**（`master_db_path`）。ところが
直す場所も効くタイミングも別々で、画面の3箇所に散っていた。しかも
**マスタは画面のどこにも出ていない**（`config/local.json`だけ・鶏と卵のため）
ので、共有へ移そうとしても「いまどこにあるのか」を確かめる手立てが無かった。

共通設定の章を「共有スケジュール」から**「共有の置き場」**へ改め、先頭に
3行の一覧を置く。行ごとに**いまどこか（実際のパス）／置き場の種類／
直す場所／効くタイミング**を出し、直せない行は理由を書く（§4）。

**判定は`_share_layout()`の1箇所**（§9.163）。「UNCかどうか」「クラウド同期か」
「同じ根の下か」を画面でも判定すると答えが2通りになり、片方だけ直した状態が
作れる。画面は受け取った答えを並べるだけ。

**置き場の種類は必ず文字で出す**（§3）——共有に置かれている行は左に色の帯を
付けるが、色だけでは伝えない。

**飛び先は行が持つ印**（`jump`）。以前は`#pcGoRecords`という決め打ちのボタンを
図の下に置いていたが、置き場が増えるたびにボタンと配線を足すことになる。
行の印にすれば画面は触らなくてよい。

**「3つとも同じ場所の下です」と言うのは3つとも決まっているときだけ。**
2つだけを見て同じ根だと言うと、**まだ置いていないものまで置いた気にさせる**。
逆に、揃っていないときに「バラバラです」とは書かない——揃っていない置き方が
悪いわけではないので、直す必要のない状態を不備に見せない。

**マスタが共有の置き場に対応していないことを書く**（§4）。§9.258で測定データは
設備ごとに分けて「1ファイル1書き手」を構造として満たしたが、マスタは全端末が
同じ1ファイルへ直に書く。共有越しの書き込みが重なると壊れうるので、
そのことを画面に出す（黙って置かせない）。

固定は`tests/test_pcshare.js`。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **共有の置き場は1枚で見せる。判定はサーバーが持つ**（§9.260、利用者の指示
  「マスタの管理画面の共有設定の部分も今回の改良に合わせて設定しやすいように
  わかりやすく作り替えて」）: 共有の設定は3つ（作業予定・測定データ・マスタ）
  あるのに、**直す場所も効くタイミングも別々**で画面の3箇所に散っており、
  **マスタは画面のどこにも出ていなかった**（`config/local.json`だけ）。
  共通設定の章「共有の置き場」が3行で並べ、行ごとに**いまどこか（実際のパス）／
  置き場の種類／直す場所／効くタイミング**を出す。**判定は`_share_layout()`の
  1箇所**（§9.163）——「UNCかどうか」「同じ根の下か」を画面でも判定すると
  答えが2通りになる。**種類は必ず文字で出す**（§3。色だけにしない）。
  **飛び先は行が持つ印**（`jump`）——増えても画面は触らなくてよい。
  **「揃っている」と言うのは3つとも決まっているときだけ**（2つだけを見て

  `master.sqlite3`へ直に書くので、共有越しの書き込みが重なると壊れうる。
  固定は`tests/test_pcshare.js`。
