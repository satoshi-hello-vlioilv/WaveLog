# §9.133 測定画面の作り直し（階層・定位置・入力欄）

> 利用者からの11項目の指摘（抜粋）。「左メニューに掛かる範囲で上部進捗タブ
> バーが配置されていますが、左の開始位置は揃えた方が良いです」「基本情報は
> …簡素化してください」「入力させる項目は折りたたまず、すべて見せる」

実測（1920×1080・表示サイズ「中」、本文 1747×921）で確認した内容。

| 指摘 | 前 | 後 |
|---|---|---|
| 進捗バーの左端 | バー`x=7` / 本文`x=167`（160pxずれ） | 両方`x=167` |
| ロット情報の文字 | 12px（本文14px） | 14px |
| ①のスクロール | `#operator`が**5,394px** | 0件 |
| 基本情報の位置 | ①③は左・②だけ右端(`x=1537`) | 3段とも`x=175`・高さ189px |

- **進捗バーは本文と同じ列**。以前は`1/-1`で操作レール（測定画面の左メニュー）
  の上まで伸びていた。階層は「タイトル → メニュー → 進捗 → 測定」で、
  **メニューの方が上位**なのだから進捗がその上に乗ってはいけない。
- **基本情報は常時8項目**（ロット№/検査No./用途名/材質/調質/板厚/板幅/板丈）。
  残りは「詳細を見る」で読める——**消したのではなく畳んだ**。
- **入力させる項目は折りたたまない**。畳むと現在値を要約でもう一度書くことに
  なり、同じ情報が2箇所に出る。場所は実測で足りていた。
- **よく使う選択肢を上へ**（`選択履歴マスタ`）。実データのオペレータは171人で、
  五十音順では毎回探すことになる。回数は`/api/measurement/context`へ相乗り
  させる——別APIにすると「選択肢は出たが並びは前のまま」の瞬間ができる。
  数えるのは人と機材だけで、2択は並べ替えない（順番が動くと選び間違える）。
- **`openInfoWall`は`[data-leftpanel]`を触らない**。全部開けてしまい、③で
  品質規格と分析が同じ場所に重なっていた（実測 y=398）。
