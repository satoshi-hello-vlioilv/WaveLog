# §9.580 起動画面は窓と覆いで同じ「分割カード・4段」、初期画面は仕掛一覧の上に「作業予定」の帯を1行（7案→組合せ7案から H4・利用者の指示）

索引: [決定記録](README.md)｜前: [§9.579](9.579.md)｜関係: [§9.411](9.411.md)・[§9.544](9.544.md)・[§9.51](9.51.md)・[§9.92](9.92.md)

## 経緯（利用者の指示）

> 起動画面と初期画面を有料版の製品くらいのクオリティにいい感じにしてほしいです。
> 画面表示やUIの修正部分の実装は、より自律的・自動的かつ高度に行えるようにルールを一部変更です。まず5案を検討し、…方向性が違う解決策を2案追加し、7案で画面を確認してスコア評価する。…組合せ案を4案追加し、前の案のうちの上位3案と合わせて、2回目の評価を7案を再評価して…1案を決定して実装してください。

手順は CLAUDE.md の E（7案→必要なら組合せ4＋上位3）。重みは撮る前に決めた: 品格25・一貫性15・分かりやすさ15・次の一手15・実装の小ささと整合15・待ちの体感15。撮る大きさは 1728×1152 と 1536×864。

## 4. 決めたこと

- **見せる段は4つ**（`backend/boot_status.PHASES`の1箇所: 版をそろえる → アプリを起こす → 画面を組み立てる → 準備完了）。覆い（`#appBoot`）はテンプレートがこの表を回して描き、窓の起動画面（exe に入るので写し）は同じ鍵・名前・一言を持つ（`test_boot.py`が一致を見張る）。上の10段（中身の6段＋画面の4段）は進み具合の分母として残す（覆いは60%から始まる）。
- **窓の段 → 見せる段**: update→版をそろえる／python・backend→アプリを起こす／open→画面を組み立てる。python・backend の細かな字（Python の場所など）は段の`title`にだけ残し、画面に出すのは「いま」と注意（warn）・失敗（bad）だけ。窓の進み具合は「アプリを起こす」が済んだ時点で60%にそろえる（覆いが60%から引き継ぐので、切り替わっても棒が戻らない）。
- **§9.411 の「流れる帯」は撤回**（段の字が帯の端で切れ、窓の起動画面と別の意匠だった）。波紋は残し、左のブランドの面の中だけで完結させる。
- **初期画面の帯は1行・高さ固定**（`#planStrip`・`schedule/plan-strip.js`）。出すのは仕掛の一覧で設備が決まっているときだけ（設備が無ければ上の設定の帯が言う）。一覧の道具を伏せる`:is()`（90-state.css）にも入れた。
- **数え方と始め方は予定の画面の答え**（`WL.scheduleView.digest()`／`start()`）。作業ロットだけを数え（子は親の1本・§9.493）、次の1本は「予定」のうち**この設備に仕掛かっている**最初の行（開始ボタンと同じ判定・§9.51）。押すと予定の行の「開始」と同じ`startWorkFromEntry()`を通る——測定画面の入口を2つにしない。`workableOf()`／`startWorkFromEntry()`は設備を引数でも受ける（渡さなければ予定の画面の設備）。
- **次にすることは1つ**: 測っている途中があれば「測定の続きを開く」、無ければ「次の測定を始める」。始められるロットが無いときは理由を字で言い、塗りは「作業スケジュール」へ移す。読めなければ理由を字で（縁は橙）。

## 5. 確かめたこと

- `test_boot`（13）・`test_bootui`（23・窓の起動画面の段の進み方・技術の言葉が画面に出ないこと・失敗の字を足した）・`test_planstrip`（13・新規）。
- 欠陥注入: 帯を常に出す → `test_planstrip`の「品質の一覧では出ない」「設備が無ければ出ない」で落ちる／押したときに別の行を渡す → 「押すとそのロットの行で測定を開く」で落ちる。窓の進み具合の誤り（済んだ時点で35%）は網が見つけて直した。
- 網の罠（踏んだ）: 押した結果を「行が渡った」だけで待つと、断りの窓が出たときに網が終わらない。「行が渡った」か「窓が出た」のどちらかで待つ。窓の器は初めて開くときに作られるので、`?.hidden`の否定で「出ている」と読まない。
