# §9.550 デスクトップ版の窓の中では LotData-Link が入っているかを確かめられない——「入っていません」と言い切らず、確かめる道を1つ出す（利用者の選んだ候補 1-A）

索引: [決定記録](README.md)｜設計: [`docs/DESKTOP_MIGRATION_DESIGN.md`](../DESKTOP_MIGRATION_DESIGN.md) §4-3｜前: [§9.549](9.549.md)｜関係: [§9.521](9.521.md)

## 経緯

§9.548 で起動はデスクトップ版（exe の窓・WebView2）だけになった。使用設備の設定③（ロット問い合わせのログイン）は、
Edge の拡張 LotData-Link が画面へ付ける名乗り（`<html data-lotdsp-ext="版">`・§9.521）を見て「入っています／入っていません」を
言っていた。**拡張は窓（WebView2）の中では動かない**ので名乗りは来ず、**入れてある端末でも「LotData-Link: 入っていません」と
言い切り、入れ方の手順を出していた**——現場の全員が、入れてある物を探すことになる。設計書 §4-3 で「デスクトップ版からは
確かめられない・Edge で登録する、と言い分ける」と書いたまま、手を付けていなかった（P4）。

利用者の言葉: 「次に取り組む候補を教えて」への答えの 1-A に「1-Aから進めてください」。

## 決めたこと

- **窓の中かは`WL.base.inDesktopShell()`の1箇所が答える**（`location.hostname==='wavelog.localhost'`、Windows 以外は
  `wavelog:`——`desktop/src/main.rs`の`app_base`と同じ）。開発と網の HTTP の入口（127.0.0.1）は窓ではない。
- 窓の中の設定③（`paintLotdspInShell()`）:
  - 状態の札は「**この窓からは確かめられません**」（中立の色＝`is-instant`）。分からないことを分からないと書く。
  - 事実を2つ言う: ロット№を押すとロット問い合わせは **PC の既定のブラウザ**で開く（窓の`open_outside()`）／
    LotData-Link は Edge の拡張なので、この窓からは見えない（既定のブラウザが Edge でない PC では効かない）。
  - **確かめる道を1つだけ押せる形に**: 「ロット問い合わせをブラウザで開いて確かめる」（`WL.base.openLotDspHome()`・
    ロットを指定しない入口）。開いた先で、ログイン不要ならそのまま／登録の帯が出たら登録／帯が出ずにログインを求められたら入っていない。
  - 入れ方の手順は**畳んで残す**（`.lnk-more`。主の道ではない）。最後の1行だけ「Edge でロット問い合わせを開き直すと登録の帯が出る」
    （`lotdspInstallSteps(done)`——手順は同じで、終わりの確かめ方だけが違う）。
  - 登録画面を頼む合図（`wl:lotdsp-options`）のボタンは出さない（窓の中では誰も聞かない＝押しても何も起きない）。
- 名乗りを見る3つの形（入っている／古い同梱の拡張／入っていない）は**残す**。開発と網の入口をブラウザで開いたときには正しく働き、
  LotData-Link との約束（名乗りの名前）を網が見張り続けるため。

## 撤回した案

- **名乗りを見る3つの形を消し、窓の形だけにする**——利用者の起動では見えなくなったが、別のリポジトリ（LotData-Link）との約束を
  網で見張る場所がなくなる。器は小さく（約30行）、窓の中では1行目で分かれるので残した。
- **窓から LotDsp を必ず Edge で開く**（Rust の`open_outside()`で Edge を名指しする）——LotData-Link が効く道としては正しいが、
  窓の振る舞いが変わり、Windows の実機で確かめる必要がある。今回は画面の字だけにし、候補として残す（下の「分からないこと」）。

## 踏んだ罠

- **網のブラウザから`wavelog.localhost`へ届かない**。Chromium はこの環境のプロキシを起動時に決め、`*.localhost`を素通しにしない
  ので、読み込みが返らず評価の台本が止まった（`timeout`で終わり、後片付けは`with_fixture.sh`の`trap`が済ませた）。網の土台は変えず、
  その網の中で`route`を張り、同じサーバーから取り直して返す（`location`は`wavelog.localhost`のまま＝窓と同じ判定を通る）。
- **テンプレートの改行は画面で空白になる**。文の途中で行を折ると「開きます。 自動ログイン」と空白が入った（撮って気づいた）。文の途中では折らない。

## 網のランナーが止める合図で止まらなかった（この版で直した）

確かめに`tests/run_all.sh --changed`を回したところ、`base.js`（土台）を触ったので**全件へ倒れた**（指示の無い通しを始めて
しまった。私の確認不足）。止めようと外側のランナーへ TERM を送ると、後片付け（パス設定を本番へ戻す・錠を外す）は走ったが、
**ランナーは終わらずに次の本へ進み**、本番へ戻したパスのまま・錠なしで回り続けた。原因は`trap '後片付け' EXIT INT TERM`
——INT/TERM にも後片付けだけを当て`exit`しないので、bash は後片付けのあと処理を続ける。`timeout`で切れたときも同じで、
`with_fixture.sh`が止まらなかったのも同じ形だった。

直し: 後片付けは`EXIT`の1回だけ、INT/TERM は`exit 130`／`exit 143`（`run_all.sh`・`with_fixture.sh`）。
物差し（短い5本を回し、1本目のあとに TERM）: **TERM のあとに走った本 4 → 0**、ランナーは終わり、錠と退避ファイルは片付く。

分からないこと: 「元へ戻した」パス設定そのものが、この作業環境では検証用フィクスチャを指していた（この確かめより前から）。
いつからかは分からない。`db/master.sqlite3`は git が持たないので、現場の PC には届かない。
