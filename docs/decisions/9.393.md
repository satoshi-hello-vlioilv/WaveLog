# §9.393 丈毎に「外観」と「巻ズレ（OS/DS）」を足す（利用者の指示）

利用者の指示（原文）:

> **４）丈毎の項目に、外観を追加し、「○」「△」「×」を入れられるように
> してください。**
>
> **５）丈毎の項目に、巻ズレの項目を追加し、OSDSを分けて入力できるように
> してください。**

確認して決めたこと（`AskUserQuestion`）:

| 迷い | 決めたこと |
| --- | --- |
| 巻ズレの持ち方 | **丈毎に新しく足す。既存（条ごとの入力内容「巻ずれ」）は残す** |

## 1. 「巻ズレ」は2つある。同じ名前だが別のもの

| どこ | 何を測るか | どう入るか |
| --- | --- | --- |
| 入力内容「巻ずれ」（従来） | **条ごと**（`m.measurements.offset[丈位置][条]`） | 測定器から受ける |
| 丈毎の「巻ズレ OS/DS」（今回） | **丈ごと**（`m.product.rows[i].offsetOs/offsetDs`） | 手入力 |

**どちらも残す。** 利用者の選択が「丈毎に新しく足す・既存は残す」だったのは、
条ごとの記録を消すと**過去の測定データが読めなくなる**から。名前が同じでも
数える単位が違うので、置き場も別（§CLAUDE 6「出どころ・単位を画面に出す」
——画面でも紙でも「巻ズレ OS」「巻ズレ DS」と**OS/DSまで書いて**区別する）。

## 2. 外観の記号は **フラットネスと同じ3つ**

`〇`（U+3007）／`△`／`×`。フラットネス（条ごと）が既にこの3つを使っている
ので、**同じ意味の記号を画面ごとに変えない**——`○`（U+25CB）と`〇`が混ざると、
読む側は別物だと思う（§CLAUDE 3）。

**判定には効かせない。** 揃いの合否はエッジ形状と値(mm)から出す（§9.204）
ので、外観で色を付けると「どちらが合否なのか」が読めなくなる。

## 3. 内訳の段に勝手に出さない

丈の表は「主役の行」と「異常のときだけ出る内訳の段」の2階建て（§9.203）。
内訳の段は `PRODUCT_CHOICES.filter(d=>d.k!=='edgeShape')` で顔ぶれを決めて
いた——つまり**「エッジ形状以外」が全部内訳へ出る**作りで、外観を選択肢へ
足した瞬間に内訳の段にも現れた。

顔ぶれは `PRODUCT_DETAIL_KEYS` で選ぶよう直した。**「〜以外」で集合を作らない**
——主役の列へ欄を1つ足すたびに、裏側が黙って増える。

## 4. 器は中身の長さから（§CLAUDE 11）

列は6つ → 9つになった。**外観にエッジ形状と同じ幅を与えない**——中身は
記号1文字なので、12.6em を配ると備考の取り分が消える。`--prt-c-look` は
6.2em（実測74px）。

実測（1920×1080・右の作業面855px）:
丈29 / 長さ91 / 肉厚91 / 判定55 / **外観74 / 巻ズレOS 91 / 巻ズレDS 91** /
エッジ形状151 / 備考154 ＝ 表829px（**溢れ −13px**）。
`tests/test_msteps.js` が溢れを測り直す。

## 5. 紙は「中身のある列だけ」出す（指示の7件目）

> ７）１）〜６）の対応により帳票の連動が必要な部分はフレキシブルに対応し
> 連動して正しく表示・非表示するように改修してください。

紙の「丈別データ」は **外観の見出しだけが在って中身が空**だった（列を作った
当時、記録する場所が無かった）。§9.393で記録できるようになったので、
ここで初めて中身が入る。

そのうえで、外観・巻ズレ(OS/DS)は**1件も書いていなければ列ごと出さない**:

- 空欄の列は紙の幅を食うだけで、読む側には「まだ書いていない」のか
  「この設備では測らない」のかも分からない（§CLAUDE 4・§9.107）。
- 列幅は**出す列だけで100%に配り直す**。合否だけで追加の列も無いときは
  **今までの紙のまま**（列幅を1つも触らない）。

見本（`report_block_repo._sample_product_rows()`）にも外観・巻ズレを入れた
——空のままだと、**見本では列ごと消えて確かめられない**。

## 6. 固定した網

| 網 | 何を止めるか |
| --- | --- |
| `tests/test_msteps.js` | 列が9つ・外観は〇/△/×・打った時点でレコードへ入る・**内訳の段には出さない**・列を足しても横に溢れない |
| `tests/test_rpblocks.js` | **書いていない記録では列を出さない／書いた記録では出て値が載る**（空欄は「-」） |

**欠陥注入で確かめた2件**:

1. 紙の列の絞り込み（`filledIn`）を外す → 「書いていない記録では出さない」が赤。
2. 主役の行から外観の欄を落とす → 画面の2件が赤。

## 7. 踏んだ罠: 見本の記録を置きっぱなしにして4件が赤になった

紙の検査に外観入りの記録（`RPPROD-LOOK`・2丈）を注ぎ込んだところ、**後ろの
節の「詰め」の検査が4件落ちた**。あとの節は「いま開いている紙」を狭いマスへ
押し込んで**余白が詰まること**を見るが、2丈の小さな表では**詰めずに収まって
しまう**（`dense===1`・`pack:[]`）。

**使い終わった見本はその場で消す**（§9.351）。後片付けを最後にまとめると、
その間に走る節が別の材料を見ることになる。
