# §9.179 開いたときの表示と、カーソル位置への追加（利用者の指示）

利用者の指示は「スケジュールモードのスケジュール表と仕掛を開いたタイミングの
デフォルト表示位置入れ替えや初期状態はスケジュールだけなど、表示設定もできるように。
スケジュールだけ開く場合はスケジュール追加方法をカーソルがあっている位置に追加する
形とし、カーソルがあっている位置がゴーストで間が空き、クリックやダブルクリックで
仕掛モーダル、設備モーダルが起動するように」。

#### 開いたときの表示（`⚙ 表示`）

`scLayoutPrefsV1`に2つだけ持つ。**設備ごとではなく端末ごと**（見え方の好みは人に
付く）。

- **開いたときの表示**: `last`（前回のまま。既定＝今までの挙動）／`split`／`schedule`。
  既定を変えないのは、わざわざ選んでいない人の見え方を変えないため。
- **仕掛一覧の位置**: 左（既定）／右。`.sc-split-wrap.sc-swap`が**列の定義と区画の
  両方**を入れ替える——片方だけだと幅は入れ替わったのに中身が元の側に残る。

#### カーソル位置へ入れる

仕掛一覧を畳んでいるときはドラッグで入れる相手が画面に無い。行と行のあいだに
カーソルを置くと**本当に隙間が開き**、そこを押せば入れる相手を選べる。

- 隙間は**行の流れの中へ挟む**。浮かせて重ねると下の行が1行ぶん隠れて読めなくなる
  （実際にそうなった）。
- **隙間の上に来たら位置を計算し直さない。** 隙間は流れの中にあるので、出し入れの
  たびに下の行が上下する——そのたびに計算すると隙間が行き来して掴めない。
- 隙間には**何ができるかを書く**（クリック＝仕掛から選ぶ／ダブルクリック＝設備停止）。
  押せるだけの空白を作らない。
- 相手は**動かせる予定（未着手）の行だけ**。着手・完了のあいだに入れても並びは
  変わらないので、そこには隙間を出さない。
- 入れる位置は`plan_add`の`position='before:<予定ID>'`で**追加と同じ書込サイクル**で
  決める。画面で足してから並べ替えAPIを叩く形にすると、2往復のあいだに別のPCの
  変更が挟まる（共有DBは1件ずつ取得→適用→反映する）。**指定の行が見つからない／
  動かせない状態なら末尾へ落とす**——例外にすると、開いたまま他のPCが着手した瞬間に
  「追加できません」になる（入れたい位置が消えただけで、追加そのものはしたい操作）。
- 楽観描画の行も**その位置へ置く**。末尾へ足すと、サーバーから返ってきた瞬間に行が
  飛んだように見える。

固定は`tests/test_scinsert.js`。
