# §9.165 列表示マスタ（表示マスタ）の廃止（利用者の指示）

利用者の指示は「各、個別の読み込みデータに対して列表示のカスタムができるように
なっているので、機能としては劣化したものをマスタに持っていて重複している。
このマスタからは削除して」。

`表示マスタ`は**対象=DB単位・行の存在＝非表示**というブロックリストで、
`/api/table`が戻りの列から落としていた。同じことを列レイアウトマスタが対象
（`list:<DB>:<表>`／`timeline:`／`print:`／`records:list`）ごとに、並び・幅・表示名・
書式・読み替え・計算式まで含めて持つようになったので、機能として劣った重複だった。

**サーバーが列を落とすと、画面側は落ちた列を選び直せない**（設定パネルの候補にすら
出ない）。だから落とす役は画面だけが持つ。消したのは
マスタ管理の「列表示」タブ、`/api/column-display-master`の2本、
`master_repo`の`表示マスタ`ブロック、`/api/table`の非表示列の除外。

`include_hidden`は**受け取っても何もしない**（古い呼び出しを落とさないためだけに
残す。新しく付けないこと）。呼んでいた側（条割の判定・スケジュールの作業可否）は
外した——付いたままだと「サーバーがまだ列を落とす」という誤解が残る。
物理テーブルは消していないので、中身は「テーブル生データ」で見られる。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **どの列を出すかはサーバーが決めない**（§9.165）: 以前は`表示マスタ`
  （マスタ管理の「列表示」タブ、対象=DB単位・行の存在＝非表示）が
  `/api/table`の戻りから列を落としており、内部計算用の問い合わせだけ
  `include_hidden=1`で逃がしていた。**この仕組みは廃止した**——同じことを
  列レイアウトマスタが対象（`list:<DB>:<表>`／`timeline:`／`print:`／
  `records:list`）ごとに、並び・幅・表示名・書式・読み替え・計算式まで
  含めて持つようになり、機能として劣った重複だったため。**サーバーが
  落とすと画面側は落ちた列を選び直せない**（設定パネルの候補にすら出ない）
  ので、落とす役は画面だけが持つ。`include_hidden`は受け取っても何もしない
  （古い呼び出しを落とさないためだけに残してある。**新しく付けないこと**）。
  **内部の問い合わせは
  `columns=`で要る列だけ頼む**（§9.94）——実データは200列を超えるため、
  「そのロット番号が居るか」を見るだけの問い合わせでも1回450KBになり、
  受け取ったJSONを解くたびに画面が数百ms止まる（実機で「一覧に切り替えると
  固まる」と報告された原因の半分）。`columns=`が効くのは**戻す量だけ**で、
  絞り込み・並べ替えの対象は絞らない。1つも当たらなければ絞らない
  （打ち間違えたときに空の表を黙って返さない）。同じ理由で、先頭一致を
  何本も投げる場面は`starts_any`（カンマ区切り）で1回にまとめる。
