# §9.526 刃セットのカテゴリ・使用状態／刃選択の条件は4項目／フィンガーは材質（利用者の指示）

索引: [決定記録](README.md)

## 利用者の言葉

「１）刃のセットの使用状態を切り替えられるようにしてください。使用中、研磨中
２）カテゴリを追加して通常刃、専用刃の選択も追加してください。
３）刃の選択マスタは、板押さえ方式と板厚と材質と調質から選べるようにしてください。
４）フィンガーは名称入力欄は不要、その代わりにフィンガー材質というカテゴリを追加し、ベークライトとアルミニウムを登録して、既定はベークライトにしてください。」

利用者の選択: 使用状態・カテゴリは**セット（組）ごと**／刃選択の条件は**4項目に絞る**（すでに書いた決まりは効かせる）。

## 測った（評価関数）

| | 前 | 後 |
| --- | --- | --- |
| セットの切り替え口 | **無い**。刃1枚ずつの「状態」（一般／メンテナンス中／専用）に「選べるか」と「どんな時に選ばれるか」が混ざっていた | マスタ管理 > 刃組 > **刃セット**。組ごとに2つの札（カテゴリ／使用状態）を押すとその場で保存 |
| カテゴリの語彙 | 無い（「一般」「専用」が状態に混ざる） | 通常刃／専用刃 |
| 使用状態の語彙 | 無い（「メンテナンス中」が状態に混ざる） | 使用中／研磨中 |
| 刃選択で選べる項目 | 7（板厚・元コイル幅・条数・条幅最小・条幅最大・材質・ロット番号）——**板押さえ方式0・調質0** | 4（板押さえ方式・板厚・材質・調質） |
| 前の項目で書いた決まり | — | 読んで効かせる（直す窓では「（前の項目）」と名乗って残る） |
| 板押さえ方式の比べ方 | — | ＝／≠だけ（大小・範囲・含むは当たらないので出さない） |
| フィンガーの窓 | 名称が**必須**・材質の欄なし | 名称の欄なし・材質（ベークライト／アルミニウム・既定ベークライト） |
| フィンガー1本の見分け方 | 設備＋名称 | 設備＋幅＋材質（同じ組の2行目は断る） |

## 決めたこと

- **刃セット＝設備＋組**。新しい表`刃セットマスタ`（設備名・組・カテゴリ・使用状態）が答えの1箇所。
  刃の行はサーバーが自分の組のセットのカテゴリ・使用状態を**名乗って**返す（`blade_rows()`）。
- 行がまだ無い組は**刃の`状態`から起こした初期値**（`_legacy_set()`）: 専用が1枚でもあれば専用刃、
  全部メンテナンス中なら研磨中、ほかは通常刃・使用中——今までの選ばれ方とできるだけ同じにする。
  刃の`状態`は**読むだけ**（窓からは外した）。「初期値へ戻す」は`reset`（登録を消す・§9.243）。
- 切り替えは**送った項目だけ書く**（§9.212 ②）。盤の札は押すとその場で保存（1手で終わる操作に
  保存ボタンを探させない）。研磨中の行は地の色に加えて「刃組ガイダンスで選ばれません」と**字で**言う。
- ガイダンスの選び方（`applyBladePick()`）: ふつうは**通常刃・使用中**、決まりに当たれば**その組の専用刃・使用中**。
  当たっても使える専用刃が無ければ通常刃で描き、理由（`missing`）を持って「使えない」と言う。
  使えるかは`selectable()`の1箇所（セットを名乗らない材料は今までの`状態`で見る）。
- 刃選択の条件: 板押さえ方式は`holdPick()`の答え（`bladePickCtx()`で後から足す——`holdPick`が`pickCtx`を
  読むので中へ入れると回り続ける）、材質・調質は1本目の仕掛の行（製造→オーダー）。
  前の項目は`BLADEPICK_FIELDS_LEGACY`／`pickFieldsLegacy`——保存でも判定でも落とさない。
- フィンガー: 呼び名は材質＋幅から作る（`finger_label()`・`[名称]`の列は読むだけ）。選択欄の候補は
  サーバーが答える（`optionsKey:'fingerMaterials'`→`selectOptionsOf()`）。
- 語彙は`_vocabulary()`へ切り出した（`context()`の長さを増やさない）。
- ルートは`blade-sets`の2本で`bladeset.py`が20本（上限）。次に足すときは段を分けること。

## 分からないこと・残したこと

- フィンガーの材質で図の色を変えるかは決めていない（いまは材質によらず同じ色）。
- 同じ組に「一般」と「専用」が混ざっていた設備は、組ごと専用刃になる（セットごとに決める選択による）。
