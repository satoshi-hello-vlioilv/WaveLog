# §9.422 消した部材の見せ方を選べるようにする（薄く／線だけ／出さない）（利用者の指示）

索引: [決定記録](README.md)

利用者の指示（要旨）:

> 表示バッジを OFF にしたときの見せ方を、透過／ワイヤーフレーム／完全消去から
> 選べるようにしてほしい。選び方は「隠し方」を別に1つ選んでおく形で。

## ① なぜ「消す」だけでは足りないのか

立体図・断面図の「表示」は、板・刃・ゴムリング・スペーサーを1つずつ切れる。
切る理由はたいてい**「刃だけを見たい」**で、「その部材が無いことにしたい」では
ない——スペーサーを消して刃を見たあと、**どこにスペーサーが居たか**をもう一度
知りたくなる。消してしまうと、そのたびに入れ直して目で位置を覚え、また消す
ことになる（§CLAUDE 2「次にすることを1つだけ指す」に反して、**同じ操作を
往復させている**）。

だから消し方を3つにした:

| 選ぶ | 何が起きるか | どんなときに |
| --- | --- | --- |
| **薄く** | 同じ色のまま薄く残る（`opacity .13`） | 刃を見ながら、部材の居場所も同時に読みたい |
| **線だけ** | 輪郭のワイヤーフレームだけ | 位置と境目だけ確かめたい |
| **出さない** | まったく描かない（**今までの動き＝既定**） | 何にも邪魔されたくない |

**色は変えない。** 薄くするだけにしておくと、透かした先でも「何の部材か」が
そのまま読める——薄いときだけ灰色にすると、スペーサーとゴムリングの区別が
消えて、位置は分かるが**何が在るか**が分からなくなる。

## ② 置き場は「表示」と同じ群の中（別の群に離さない）

隠し方は**上の入切にかかる設定**で、単独では何もしない。別の群として並べると
「表示／隠し方／段取り／視点」の4つが対等に見え、**何に効くのか**を押す人が
推測することになる（§CLAUDE 「推測させない」）。同じ群の中へ、区切り（
`.bs-hud-sep`）と小さな見出し「消したものは」を挟んで置いた——
**「消したものは｜薄く／線だけ／出さない」と1つの文として読める。**

作りは**セグメント**（`.bs-hide`）で、入切のトグル（`.bs-tg`）とは分ける
（§9.247）。トグルは点が付くかどうか、セグメントは押した札のほうが濃い。
濃さの規則は `90-state.css` の束ね規則へ1行足すだけにする（§9.353）。

並びは**残る量の多い順**（薄く → 線だけ → 出さない）。「どれだけ残るか」という
1本の物差しの上に3つが並ぶので、押す先を数えずに選べる。

## ③ 知らせの文に隠し方まで書く

「スペーサーを非表示にしました」で終わると、**薄く残っている物を見て
「効いていない」と読まれる。** 呼び名は `HIDE_WORD` の1箇所に持ち、

- 消したとき … 「スペーサーを非表示にしました（薄く残します）。」
- 見せ方を変えたとき … 「消した部材は薄く残します。」
  何も消していなければ **「（いまは何も消していないので、「表示」で切ったときに
  効きます）」** まで言う（§CLAUDE 6「効くタイミングを書く」）。

## ④ 作りは「材質を差し替える」1本（入切の分岐を部材ごとに増やさない）

素朴に書くと `if (sh.liner) { …描く… } else if (D3.hide === 'ghost') { …薄く描く… }`
が部材の数だけ増える。そうではなく、**材質を返す1つの関数**に寄せた:

```js
function skin(T, on, key, o) {
 if (on) return matOf(T, key, o);
 const spec = HIDE_SPEC[D3.hide];          /* gone のときは undefined */
 return spec ? matOf(T, key + '~' + D3.hide, Object.assign({}, o, spec)) : null;
}
```

呼ぶ側は **「材質が無ければ描かない」** だけになる（`if (liner) { … }`）。
`gone` を足すのも消すのも `HIDE_SPEC` の1箇所で、部材を増やしても分岐は増えない。

材質の名前に隠し方が入る（`liner~ghost`）ので、**描いた物そのものから
「透かして在る」を数えられる**——網が絵の見た目ではなく組み立てている物で
見分けられる（`view().skins`）。

## ⑤ 薄く残しても「字」は増やさない

寸法の字（`D3.dims`）・板の札（`D3.marks`）・入側／出側の札は、**今までどおり
`D3.show` で落とす。** 残すのは「そこに在る」ことを見せるためで、寸法まで
並べると、消して減らしたはずの**読む物が戻ってしまう**（§CLAUDE 1「面積は
頻度×重要度で配る」）。

網はこれを数で見る: 「出さない」と「薄く」で**字の数が同じ**であること。

## ⑥ 既定は「出さない」

今までの動きをそのまま既定にした。見せ方は端末に覚えない（`D3` の中だけ）
——「表示」の入切も覚えていないので、**同じ軸のものを片方だけ覚えると
食い違う。**

## ⑦ 踏んだ罠: 「開き直すと帯が作り直される」は思い込みだった

見せ方を選んだあと画面を離れて戻ると、**帯のHTMLが既定の姿に戻って中の状態と
食い違う**と考え、`attach()` で札を塗り直す手当てを入れた。**欠陥注入で確かめたら
素通りした**（手当てを外しても網が緑のまま）ので実物を読み直すと、帯を作るのは
`ensurePanel()` の1箇所で、

```js
function ensurePanel() { if (panel) return panel; … }
```

**すでに在れば作らずに返す**。`wire()`（したがって `attach()`）もその中で一度だけ
走る。つまり帯は一度作って使い回されるので、札の見た目は消えも戻りもしない
——**直す相手が居なかった。** 手当てと、その手当てのために書いた網は撤回した。

教訓は2つ。**①「あるはずの不具合」を実物で確かめてから直す**（この手当ては
何も直さない行で、読む人には「ここは食い違う場所だ」という誤った説明として
残る）。**②緑は証拠にならない**——欠陥注入をしていなければ、意味の無い行と
意味の無い網を両方とも残していた（§9.102・§9.399）。

## 実測（検証用フィクスチャ・120mm×5条）

| | 組み立てている物 | 薄い／線だけの物 | 寸法の字 |
| --- | --- | --- | --- |
| 全部出す | 51 | 0 | 96 |
| スペーサーを切る（出さない） | 45 | 0 | 30 |
| スペーサーを切る（薄く・線だけ） | 51 | 6 | 30 |

字が 96 → 30 に落ちる（スペーサーの字が 66）のは、**薄く残しても字は出さない**
から。ここが `drawn()` に変わると 96 のまま戻り、網が落ちる（欠陥注入で確認）。
