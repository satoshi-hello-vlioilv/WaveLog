# §9.94 一覧を開いたときに画面が固まらないようにする

**症状。** 「一覧に切り替えるときに初回のデータ取得でブラウザがフリーズする
ほどの状態になっている。」

**実機に近い形(200行 × 214列)で再現して測った。** メインスレッドが止まって
いた時間は**合計10.3秒 / 44回**、うち一覧が出た直後に**3.4秒の1塊**。
原因は独立した3つだった。

| # | 原因 | 実測 |
|---|---|---|
| 1 | 列幅を決めるためにブラウザが全セルを測っていた | 3.4秒の1塊 |
| 2 | 行ごとの追い判定が1行1往復、しかも全列を運んでいた | 67往復・約30MB |
| 3 | 42,800セルを一度に渡していた | その間ずっと操作不能 |

**1. 列幅はこちらが全列ぶん指定する。** 既定の`table-layout:auto`は
「どの列をどこまで広げるか」を決めるために全セルの自然幅を測る。列が多い
ほど効いてくる。→ `table-layout:fixed`にして、`renderGridInner()`が
**全列に幅を入れる**(`estimateColumnWidth()`が見出しとデータの先頭40行から
字幅で見積もる。半角0.55em/全角1em、下限52px・上限320px。利用者が決めた幅が
あればそちら)。**入れ忘れた列は等分に割られて潰れる**ので、先頭の
選択・予定・行番号・分割・測定の列にも必ず入れる。
決め打ちにする以上、入り切らない値は省略記号になるため、**切れたセルには
必ず生の値の`title`を付ける**(読めない文字が黙って消えるのは、狭い列より悪い)。

**2. 追い判定は「あとで・まとめて・軽く」。** 分割ありの子ロット確認
(`findMissingChildLots`)と子カード行の親逆引き(`findParentLotFor`)は、
一覧を読むのに要らない——印を後から足すだけ。それを描画の直後に、行ごとに
`/api/table`(全列・50行)で投げていた。

- **あとで**: `requestIdleCallback`で手が空いてから始める。一覧が出た時点では
  1本も投げない。
- **まとめて**: `prefetchLotPrefixes()`が1画面ぶんの先頭5桁を集め、
  **`starts_any`**(「この先頭のどれかで始まる」)で25件ずつ1回にまとめる。
- **軽く**: **`columns=`**で要る列だけ頼む(ロット番号と子カードだけ)。
  実データは200列超なので、1回450KBが数KBになる。
  ただし**測定を開く側は全列のまま**——あちらは親ロットの板厚・公差まで
  使うので、軽い行を渡すと壊れる(`{light:true}`で呼び分ける)。

`columns=`は**戻す量にだけ効く**。絞り込み・並べ替えの対象(`cs`)は絞らない。
1つも当たらなければ絞らない(fail-open)——列名を打ち間違えたときに空の表を
黙って返すのが一番困る。

結果: 追い判定の往復 **67 → 3**、要求総数 82 → 18。

**3. 大きい表は少しずつ並べる。** セル数に比例してレイアウトが重くなるのは
罫線もCSSも外した素の表でも同じで(42,800セルで約0.9秒)、書き方の問題では
なく**セルの数そのもの**。一度に渡せばその時間が1つの塊になる。
→ 最初の一塊(約700セル)を出してから、`requestAnimationFrame`で継ぎ足す。
**継ぎ足しは1回ごとに表全体のレイアウトが起きる**ので、細かく割るほど合計が
増える(実測: 20行ずつで合計4.7秒、5行ずつだと7.3秒)。そこで**最初だけ
小さく、あとは倍々**にする(上限9,000セル)——最初の一画面はすぐ出て、
以降は回数を減らす。**8,000セル以下の表は分けない**(分けても速くならず、
「行が後から生えてくる」動きだけが増える)。
継ぎ足しの途中で描き直されたら世代(`gridGeneration`)が変わるので止める。
追い判定は**全部並べ終えてから**始める(途中で始めると、まだ作られていない
行の印を付け損なう)。

結果: **止まっていた時間 合計10.3秒 → 3.7秒、最長 3.4秒 → 0.66秒**、
一覧が出るまで 744ms → 577ms。

固定は`tests/test_listperf.js`(全列に幅が入っていること・`table-layout:fixed`・
切れたセルのtitle・追い判定が描画後でまとめて軽いこと・継ぎ足しが最後まで
走って全行そろうこと)と`tests/test_tablequery.py`(`columns=`が戻す量にだけ
効くこと・`starts_any`が1件ずつと同じ結果になること・壊れた指定で落ちないこと)。

## 守ること（`CLAUDE.md` から移した規則の本文）

CLAUDE.md には見出しの1行だけを残してある。ここが本文。

- **一覧の描画で「ブラウザに測らせない・一度に渡さない」**（§9.94、
  `tests/test_listperf.js`）: `#grid table`は`table-layout:fixed`で、
  **全列ぶんの幅を`renderGridInner()`が必ず入れる**（`estimateColumnWidth()`
  が見出しとデータの先頭40行から字幅で見積もる）。`auto`へ戻すと列幅を
  決めるために全セルを測り、200行×214列で**3.4秒メインスレッドが止まる**。
  幅を決め打ちにする以上、**切れたセルには生の値の`title`を必ず付ける**。
  8,000セルを超える表は`requestAnimationFrame`で継ぎ足す。**継ぎ足しは
  1回ごとに表全体のレイアウトが起きる**ので細かく割るほど合計は増える
  （20行ずつ4.7秒 / 5行ずつ7.3秒）。最初だけ小さく・あとは倍々にしてある。
  行ごとの追い判定（分割ありの子ロット確認・子カード行の親逆引き）は
  **一覧を描き終えてから・手が空いてから**（`requestIdleCallback`）始め、
  先頭5桁は`prefetchLotPrefixes()`でまとめて引く。**測定を開く側は全列のまま**
  ——親ロットの板厚・公差を使うので、軽い行（`{light:true}`）を渡すと壊れる。
- **仮想行の先取りは「画面の高さ」から決める**（§9.297、利用者の指摘「仕掛
  データなどの一覧のスクロールの速度が速いと描画が間に合わないケースがあります。
  少しだけ描画範囲を広くしてスクロールに確実に追従するように」）: 組み直しは
  `requestAnimationFrame`にまとめてあるので**1フレームは必ず遅れる**。その
  1フレームで画面より多く動くと、上下の詰め物（スペーサ）がそのまま見える。
  **前後に画面1つぶん**（`VIEW_BUFFER=0.9`）を先に作る。**固定の行数にしない
  こと**——器の高さは表示サイズと窓で変わるので、14行では小さい画面で余りすぎ、
  大きい画面で足りない（実測: 26行の画面で14→23/25行へ）。**上限は置く**
  （`OVERSCAN_MAX=60`。行が多いほど1回の組み直しが重い・§9.94）。
  **網は定数を読まないこと**——器の高さから決める作りでは読めない。
  **画面の外に何行あるか**を実測で数える（`tests/test_allrows.js`）。
