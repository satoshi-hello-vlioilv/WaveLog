# §9.343 初回の案内は1箇所。空の器は「ここに何が出るか」だけを言う

`docs/REVIEW_2026-09.md` 4-2 ⑨ の指摘:「初回画面の案内が2箇所（上の帯と
表の中のカードが同じ文）。画面基準8」。

## 何が起きていたか

使用設備が未登録のとき、仕掛一覧には**同じ見出しが2つ**出ていた。

| | 見出し | 本文 | 押すもの |
| --- | --- | --- | --- |
| 上の帯（`#equipmentSetupBanner`） | 最初に使用設備を設定してください | 測定を開始する前に、この端末で使用する設備を登録します。 | **「使用設備を設定」ボタン** |
| 表の中（`.setup-first`） | **最初に使用設備を設定してください** | この端末で使用する設備を登録すると、仕掛一覧を設備で絞り込んで表示できます。**上の「使用設備を設定」から登録してください。** | なし |

見出しは**一字一句同じ**。しかも表の中の本文は「**上の**『使用設備を設定』
から」と、帯を指し返している。読む側は同じ文を2回読んで、**同じことだと
確かめる**作業をさせられる（画面基準8「同じ情報を2箇所に出さない」——
同じ文が並ぶと「違うことかもしれない」と読み直すことになる）。

さらに、表の中のカードには**枠と面**が付いていた。読むだけの案内に入力欄風の
枠を与えると押せそうに見える（画面基準10）。

## 決めたこと

**見出しと「次にすること」は帯が持つ。表の中は「この場所に何が出るか」
だけを言う。**

```
使用設備を設定すると、ここに仕掛一覧が出ます。
```

1行。見出しなし、枠なし、帯を指し返さない。

**なぜ表の中を空にしないのか。** 空の器は「壊れているのか、まだ何も無いのか」
を答えない。ここに何が出る場所なのかを言うのが、この1行の役目
（「推測させない」）。**行き先の案内は帯に1つあれば足りる。**

**器も一緒に減らした**（§9.126「中身を減らしたら器も減らす」）。中身が
1行になったのに、20px の内側余白と枠と面を持ったカードのままにすると、
1行の情報に3行ぶんの場所を使う。

## 網

`tests/test_uiux.js` に3件。**使用設備を入れる前に見る**のが要点——この
テストは途中で `AccessMeasurementConfiguredEquipment` を入れて設定済みの
画面へ移るので、**未設定の見え方を確かめられるのはその前の一瞬だけ**。

- 未設定なら帯が出て、次にすることを指す
- **同じ見出しを表の中で繰り返さない**
- 表の中は「ここに仕掛一覧が出ます」と言い、「上の…」と指し返さない

A/Bで元の文へ戻すと2件落ちる。
