    したいのですが可能でしょうか。セグメントのデザインと詰め込み具合は

  ③「帳票の印刷機能で、印刷ボタンを押すと、WEBブラウザまたはWINDOWSの機能の

#### ① セグメントとトグルの作り分け、選ばせ方を2つ足す

**§9.220 ①で`ラジオ`と`タブ`について書いたのとまったく同じ話**が、
`セグメント`と`トグル`で起きていた——実測すると、どちらも

    地色の帯（`--surface-2`）＋内側2pxの隙間＋浮いた札を`--teal`でベタ塗り＋白文字

で、違いは札が`flex:1 1 0`（等幅）か中身なりかだけだった。名前が2つあって
見た目が同じなら、選ばせる手間だけが残る。

**セグメントは1行も触らない**（利用者が気に入っている側を勝手に変えない）。
トグルを**1枚の枠を割った形**へ作り直した:

| | セグメント | トグル |
|---|---|---|
| 器 | 地色の帯 | 白い枠 |
| 隙間 | 内側に2px | 無し（縁まで） |
| 選んだ札 | ベタ塗り＋白文字 | 淡く染める＋色の付いた文字 |
| 幅 | 器いっぱいを等分 | 中身なり |
| 仕切り | 隙間そのもの | 1pxの線 |

「対（つい）」であることは**形が語る**——1枚の枠が2つに割れていれば、
どちらか一方という意味は説明せずに読める。

**色の軸からトグルのベタ塗り上書きを外すこと**——`[class*="opf-c-"]
.opf-toggle-btn.is-on{background:var(--opf-hue);color:#fff}`が残っていると、
**色を選んだ欄だけセグメントと同じ見た目に戻る**（§9.227 ①「色を選んでも
メタファーを変えない」）。素の指定が`color-mix(… var(--opf-hue) …)`なので、
器で色が決まればそのまま効く——**同じことを2箇所に書かない**。

足したのは2つ。ここでも規則は同じで、**足すのは「選ぶ状況が違うもの」だけ**
（見た目の違いは意匠の軸が持つので、色違いを種類として増やさない）。

  - **メニュー** … 押した欄の**すぐ下**に浮く軽いメニュー。数個を目を
    動かさずに選ぶとき。`一覧`は画面のまん中に開く大きな窓＋絞り込みで
    「選択肢が多いとき」向きなので、**開く場所も中身も違う**。
  - **切替** … ボタン1つ。**押すたびに次の選択肢へ**進み、一巡する。
    札を並べる場所が無い狭いマスで2〜4個を切り替えるとき。
    **いま何番目か（`2/4`）と次の値を必ず文字で出す**——押した先が見えないと、
    目当ての値まで何回押すのか数えることになる（§2「推測させない」）。

**`一覧`と`メニュー`を同じ顔にしないこと**——足した直後は両方とも
「▾の付いた1行の欄」で、まさに今回指摘された形（名前が2つで見た目が同じ）に
なっていた。`一覧`の合図は**器から仕切った`☰`**（窓が開く）、`メニュー`は
**その場に垂れる`▾`**（開くと反転する）に分けてある。

**浮くものは`body`直下**（§9.201）なので`--opf-*`が継承されない。開くときに
**欄で解決済みの値を写す**（`carryLook()`）——規則を窓の側へ書き写さない。
これが「一覧が踏襲されていない」の正体で、意匠で`大きめ`を選んだ欄から開いた
窓だけが4pxの角のままだった。

「角丸が踏襲されていない」はもう2つあった:

  - **プルダウン** … `.opf-host`は高さ（`--opf-h`）だけを素の`<select>`／
    `<input>`／`<output>`へ配っており、**角丸を配っていなかった**。器を被せる
    形は全部効いていたので、**プルダウンの欄だけが揃わない**という気づき
    にくい食い違いになる。
  - **カード** … 説明（`choiceNotes`）を1つも持たないとき、`1.5倍`の高さの
    まま文字が上に張り付いた**空箱**が並んでいた。カードは「選ぶのに説明が
    要る」ための形なので、説明が無いときはふつうの札の高さで真ん中へ置く。
    印（`is-plain`）は`buildWidget()`が付ける——**`:has()`に頼らない**
    （当たらなかったときに誰も気づけない・§9.218 ②）。

**丸めきり（ピル）を新しく作らないこと**（§9.227 ①）——`切替`の`↻`の印を
1.4em四方の丸い面にしたところ、角丸が高さの半分に届いて`tests/test_oppad.js`
が落ちた。丸のままでよいのは「形そのものが意味を持つ部品」（丸ぽち・入切の
つまみ・メーターの帯）だけなので、**色の付いた字**にとどめてある。

**手打ちの席が無い形では、設定を押せなくして理由を書く**（§4）。
`入切`（スイッチ1つ）と`切替`（ボタン1つ）には打ち込む場所が出せない。
以前は`入切`で手打ちを入にでき、盤には「手打ち可」の印が出るのに測定画面では
打つ場所がどこにも無かった。判定は`operation_repo.free_text_ok()`の**1箇所**で、
**効く側を挙げて残りを導く**（§9.233 ④の`unit_in_ok`と同じ作法）。
保存値は`freeTextSaved`に残す——形を戻せば復活する。

固定は`tests/test_opwidget.js`。**見本の絵ではなく本物の部品を見る**
（`WL.opData.previewWidget()`は測定画面と同じ`buildWidget()`）。
**片側だけを見ないこと**——「トグルが変わった」だけを見る網は、セグメントを
一緒に壊しても通る。

#### ② 帳票の塊を子ロットごとに繰り返す

§9.244で足したのは**既定の「測定値の統計」の表**だけで、**帳票ブロック
マスタで自分が作った塊**からは`stat.*`（§9.242 ⑨）を子ロット単位で引けな
かった——全部の条をまとめた1組しか出ない。異幅分割のロットは1件の測定
レコードの中に子ロットが複数あるので（`settings.splitGroups`）、子ロットごとの
板幅MIN/MAXを紙に出す手立てが無かった。

**塊のほうを子ロットの数だけ繰り返す**のがいちばん短い道。値の作り方
（`rpStat`）も紙の組み方（`reportSection`）も既にあるものをそのまま使え、
「どの項目を出すか」は今までどおり`[内容]`が持つ。

帳票ブロックマスタに`[繰返]`を足した（`''`＝このロット全体／`'子ロット'`＝
分割後の子ロットごと）。**エリアの塊では繰り返さない**——値を出さない塊を
子ロットの数だけ並べても、同じ枠が増えるだけ（§4）。

  - 繰り返すと**子ロットの数だけ節**が出て、見出しに**子ロット番号と条の
    範囲**が付く（`幅の統計　CHILD-A（1〜2条）`）。同じ名前の節が並ぶと、
    どれがどの子ロットのものか読めなくなる（§2）。
  - 中の`stat.*`は**その子ロットの条だけ**から数え直される。
  - **条に紐づかない項目は`—`＋理由**（§4）——板厚は丈位置ごとにOS/CL/DSの
    3点、板丈・肉厚も丈ごとなので、どの子ロットのものとも言えない
    （§9.214／§9.244で書いたとおり）。空欄にすると「測っていない」と読める。
  - **分割の無いロットでは1回だけ**描く（＝今までとまったく同じ）ので、
    設備の紙を分割あり・無しで分ける必要が無い。

`lot.no`／`lot.range`／`lot.strips`／`lot.index`／`lot.count`を候補に足した。
**繰り返していない塊では親ロット自身へ落ちる**ので、どちらに置いても空欄に
ならない。**`basic.lotNo`と別に持つこと**——あちらは測定レコードの親ロット
番号で、子ロットごとに繰り返しても値は変わらない。

**自作の塊も、中身を差し替えた既定の塊も同じ`rpFieldsSection()`を通す**
——別々に持つと、片方だけ繰り返す状態が作れる。

固定は`tests/test_rpprint.js`。**紙になる節そのものを見ること**——値を1つ
引くだけの網は、繰り返しが効いていなくても通る。**もう片側（繰り返さない塊）
も見ること**——片側だけを見る網は、いつも繰り返す実装でも通る。

#### ③ 印刷ボタンを押すとプレビューが2回出る

`rpPrintFrame()`（§9.244）は書類の**用意ができた合図を2つ**持っている:

  1. `<iframe>`の`load`
  2. 書き込んだ`<link rel=stylesheet>`の読み込み数え

`document.write`では`load`が飛ばないことがあるので、**片方だけでは足りない**
——だから2つあること自体は正しい。問題は**どちらも`go()`へ入るのに、`go()`に
多重防止が無かった**こと。`w.print()`が2回走る。

`finish()`の`done`では止められない——**`print()`は`finish()`より前に呼ばれる**
ので、2回目は「ダイアログを開いてから何もしない」形になる。実機では1回目の
ダイアログが閉じるまでJSが止まるため、**キャンセルした直後に2枚目が開く**
という見え方になる（利用者の報告そのもの）。

`go()`を一度きりにした。**合図のほうを1つに減らさないこと**——どちらが先に
来るかは端末で変わるので、早いほうで刷って遅いほうは捨てるのが正しい。

固定は`tests/test_rpprint.js`。**「窓が出たか」ではなく回数を数えること**
——1回目だけを見る網（既にあった「刷る書類そのものを測る」網）は2回呼ばれて
いても通る。実際に通っていた。

  あり・無しで分けなくてよい。`lot.no`/`lot.range`/`lot.strips`/`lot.index`/
  `lot.count`を候補に足し、**繰り返していない塊では親ロット自身へ落とす**
  （どちらに置いても空欄にならない）。**エリアの塊では繰り返さない**（§4）。
  **自作の塊も中身を差し替えた既定の塊も`rpFieldsSection()`の1本**を通す。
  固定は`tests/test_rpprint.js`——**紙になる節そのものを見ること**（値を1つ
  引くだけの網は繰り返しが効いていなくても通る）。
- **印刷の合図は2つ持ってよいが、刷るのは1回だけ**（§9.247 ③、利用者の報告
  「印刷ボタンを押すと…キャンセルボタンを押すと、もう一度同じプレビューが
  出てきます」）: `rpPrintFrame()`は「書類の用意ができた」合図を
  **`<iframe>`の`load`**と**`<link>`の読み込み数え**の2つ持つ（`document.write`
  では`load`が飛ばないことがあるので**片方だけでは足りない**）。どちらも
  `go()`へ入るので、**多重防止が無いと`w.print()`が2回走る**。
  **`finish()`の`done`では止められない**——`print()`は`finish()`より前に
  呼ばれるので、2回目は「ダイアログを開いてから何もしない」形になる。実機では
  1回目が閉じるまでJSが止まるため、**キャンセルした直後に2枚目が開く**。
  `go()`を一度きりにする。**合図のほうを1つに減らさないこと**（どちらが先に
  来るかは端末で変わる）。固定は`tests/test_rpprint.js`——**「窓が出たか」では
  なく回数を数えること**（1回目だけを見る網は2回呼ばれていても通る。実際に
  通っていた）。
