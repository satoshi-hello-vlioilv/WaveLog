# 一覧の見せ方（列表示定義）設計

対象: 仕掛一覧・品質データなどの一覧グリッドと、作業スケジュールの
タイムライン。並び順・列幅・表示名・書式・読み替え・行間を、利用者が
画面から調整できるようにする。

---

## 1. 何を解こうとしているか

要望は7つあるが、**同じ問題が形を変えて出ている**。

| 要望 | 実体 |
|---|---|
| 項目の並べ替え（D&D） | その列を**どこに**置くか |
| 列幅の調整（D&D） | その列を**どれだけの幅で**見せるか |
| 表示項目名で表示したい | その列を**何という名前で**見せるか |
| 小数点以下の桁数 | その列の値を**どう整形して**見せるか |
| 日付・時刻の書式 | 同上 |
| 「00」→「なし」の読み替え | その列の値を**別の言葉に置き換えて**見せるか |
| 行間の調整 | 一覧**全体**をどの密度で見せるか |

前の6つはすべて「**列の見せ方**」で、最後の1つだけが「一覧全体の見せ方」。
したがって**器は2つ**でよい。設定項目ごとにマスタや画面を増やすと、
利用者は「これはどこで設定するんだったか」を毎回思い出すことになる。

### 設計方針

1. **1つの列の設定は1箇所に集まっている。** 名前・幅・書式・読み替えを
   別々の画面に散らさない。
2. **設定した結果がその場で見える。** 実データを使ったプレビューを常に
   横に置く。書式や読み替えは、文字列の仕様を読んで想像するものではなく、
   結果を見て決めるもの。
3. **よく使う操作は表の上で直接できる。** 並べ替えと幅は、設定画面を
   開かずヘッダーのD&Dで完結する。設定画面は「細かく詰めたいとき」の場所。
4. **読み替えは列に紐づけない。** ルールに名前を付けて登録し、複数の列から
   使い回す。「00→なし」を列の数だけ書かせない。

## 2. データの持ち方（マスタ3つ）

### 2.1 列表示定義マスタ

**1行 = 1つの対象の1つの列**。「その列をどう見せるか」を全部持つ。

| 列 | 意味 |
|---|---|
| 対象 | 画面のスコープ。`list:<DBキー>:<テーブル>` / `timeline:<設備名>` |
| 列名 | データ側の実カラム名（**これが唯一の同一性**。表示名は変えてよい） |
| 表示名 | 画面に出す名前。空欄なら列名をそのまま使う |
| 表示順 | 小さいほど左 |
| 幅 | px。空欄なら内容に合わせる |
| 表示 | 0=隠す / それ以外=出す（**NULLは表示**。列が増えても勝手に隠れない） |
| 書式種別 | `''`(そのまま) / `number` / `datetime` / `text` |
| 書式パターン | 日付時刻のパターン（`yyyy/MM/dd HH:mm` 等） |
| 小数桁 | 数値の小数点以下の桁数 |
| 桁区切り | 数値の3桁区切りの有無 |
| 単位前 / 単位後 | 数値の前後に添える文字（`¥` / `mm` 等） |
| 読み替えルール | 表示ルールマスタの**ルール名**（空欄なら読み替えなし） |

**行が1件も無い対象＝未設定＝既定の見せ方**（他マスタと同じ互換ポリシー）。
知らない列名の行は無視するので、データ側の項目が増減しても壊れない。

### 2.2 表示ルールマスタ（読み替え）

**1行 = 1つのルールの1行分**。ルール名でまとめ、表示順の上から評価して
**最初に当てはまったものを採用**する（Excelの条件付き書式と同じ考え方。
「上から順に見て、最初に当てはまったものを表示する」とだけ覚えればよい）。

| 列 | 意味 |
|---|---|
| ルール名 | 使い回しの単位（例: `有無フラグ`, `合否`） |
| 表示順 | 上から評価する |
| 条件JSON | 条件の配列（AND）。空配列＝**どれにも当てはまらなかったとき**（既定行） |
| 表示値 | 当てはまったときに見せる文字列 |
| 色 | 任意。バッジの色（`ok` / `ng` / `warn` / `muted` / 空欄） |

条件1つの形:

```json
{"left":{"kind":"self"},              // この列の値
 "op":"eq",                            // 演算子
 "right":{"kind":"value","value":"00"}}
```

- `left` / `right` は `self`（この列）・`column`（**他の列**）・`value`（固定値）
  のいずれか。他の列を参照できるので「区分が3のときだけ○○と出す」が書ける。
- `op`: `eq` `ne` `contains` `startsWith` `endsWith` `empty` `notEmpty`
  `gt` `ge` `lt` `le` `between` `regex`
- 数値比較は両辺を数値として解釈できたときだけ数値比較、そうでなければ
  文字列比較（項目の型が揺れる実データに合わせる）。

### 2.3 一覧表示設定マスタ（行間）

| 列 | 意味 |
|---|---|
| 対象 | 列表示定義マスタと同じスコープ文字列 |
| 行の高さ | 行の高さの段階（1〜5。既定3） |

行間だけのために列表示定義マスタへ「列名が空の行」を混ぜると、
**列の設定と一覧の設定が同じ表に混ざって読めなくなる**ので分ける。

## 3. 1つのセルが表示されるまで

順序を固定する。**読み替えが先、書式が後ではない**——読み替えは生の値を
見て判断し、当たれば整形せずその言葉を出す。

```
生の値
  ├─ 読み替えルールあり？ → 上から評価 → 当たった → 表示値（＋色）で確定
  │                                    → どれも当たらない → 次へ
  └─ 書式種別で整形
        number   … 小数桁で丸め → 桁区切り → 単位を前後に添える
        datetime … パターンで整形（解釈できなければ生の値をそのまま）
        text     … 前後の空白を落とす
        ''       … そのまま
```

**整形に失敗したら生の値を出す。** 空欄になるより、見慣れない形でも
値が見えるほうがよい（現場で「消えた」と判断されるのが最悪）。
実装は `WL.cellFormat`（`static/js/base.js`）。失敗と判定するのは
「数値として読めない」「日付として読めない」「**日付を持たない値に
`yyyy` を要求した**」の3つ。値が空欄のときは書式を通さず空欄のまま
出す（単位や `0.00` だけが並ぶ列にしない）。整形して表示が変わった
セルは、マウスを乗せると元の値が出る。

日付時刻のパターンは日=`d` 月=`M` 時=`H` 分=`m` と大文字小文字で
区別する（Excel の「文脈で月か分か決まる」は説明できないので採らない）。
`'リテラル'` で囲んだ文字はそのまま出る。よく使う形は選択肢から選べる
ので、書き方を覚えなくても使える。

## 4. 画面（UI/UX）

### 4.1 表の上で直接できること

| 操作 | 見え方 |
|---|---|
| 列の並べ替え | ヘッダーを掴んで左右へ。落とす位置に縦線が出る |
| 列幅 | ヘッダーの右端をドラッグ。ダブルクリックで内容幅に合わせる |
| 並び替え | ヘッダーのクリック（現状どおり） |
| 行間 | ツールバーの行間スライダー。動かすと即座に反映 |

いずれも**離した時点で保存**し、小さく「保存しました」を出す。
確認ダイアログは出さない（すぐ元に戻せる操作のため）。

### 4.2 列の設定パネル（左右2ペイン）

```
┌ 列の設定 ─────────────────────────────────────────┐
│ [検索        ]   行間 [—──●──+]  ①               │
│ ┌── 列（D&Dで並べ替え）──┐ ┌── ロット番号 の設定 ──┐│
│ │ ☑ ⠿ ロット番号        │ │ 表示名  [ロットNo    ] ││
│ │ ☑ ⠿ 用途名           │ │ 幅      [120] px      ││
│ │ ☐ ⠿ 製造材質         │ │ 書式    ( )そのまま     ││
│ │ ☑ ⠿ 板厚             │ │         (●)数値        ││
│ │ ☑ ⠿ 検査日           │ │   小数桁 [2] ☑桁区切り  ││
│ │ ☑ ⠿ #（行番号）      │ │   単位   前[ ] 後[mm]  ││
│ │ ☑ ⠿ 測定（ボタン）    │ │ 読み替え [有無フラグ ▾]  ││
│ └───────────────────┘ │          [ルールを編集] ││
│                          └──────────────────────┘│
│ ── プレビュー（実データの先頭3件）──────────────── │
│  ロットNo   用途名    板厚      検査日      測定    │
│  L0055      一般用材  1.20mm   2026/08/11  [開く]  │
│  L0056      一般用材  0.80mm   2026/08/10  [開く]  │
│ ────────────────────────────────────────────── │
│                          [既定に戻す]  [保存]      │
└──────────────────────────────────────────────┘
```

- **左は全列の一覧**。チェックで表示/非表示、⠿を掴んで並べ替え。
  `#`（行番号）・`分割`・`測定`・`予定` といった**計算列・ボタン列も同じ
  一覧に並ぶ**（要望4）。これらは書式や読み替えを持たないので、右ペインは
  幅と表示名だけになる。
- **右は選んだ1列の設定だけ**。一度に見せる情報を絞る。
- **下は実データのプレビュー**。設定を変えるたびに更新する。
  「参考データが隣に表示されていると分かりやすい」への答えで、
  ここが**この画面の主役**。文字だけの設定表にしない。

### 4.3 読み替えルールの編集

パネルの「ルールを編集」から開く。ルールは列に属さないので、
マスタ管理からも同じ画面へ入れる。

```
┌ 表示ルール「有無フラグ」 ───────────────────────┐
│ 上から順に見て、最初に当てはまったものを表示します    │
│                                                  │
│ ⠿ もし [この列 ▾] [＝ ▾] [00        ]           │
│      → 表示 [なし    ] 色[—  ▾]      [＋条件] [×]│
│ ⠿ もし [この列 ▾] [＝ ▾] [01        ]           │
│    かつ [区分   ▾] [＝ ▾] [3         ]     [×]  │
│      → 表示 [あり(特) ] 色[● 注意▾]   [＋条件] [×]│
│ ⠿ もし [この列 ▾] [＝ ▾] [01        ]           │
│      → 表示 [あり    ] 色[● 良 ▾]    [＋条件] [×]│
│   どれにも当てはまらないとき → 表示 [(元の値)  ]   │
│                                       [行を追加]  │
│ ── 試してみる ────────────────────────────── │
│  実データ  00 → なし / 01 → あり / 02 → 02       │
└────────────────────────────────────────────┘
```

- 1行が1つの読み替え。**「もし〜ならば〜と表示」の日本語の順**に並べる。
- 条件を足すと `かつ` でぶら下がる（AND）。ORは行を分ける
  （「ORもANDも1画面で」は破綻しやすいので、**行＝OR、行の中＝AND**と決める）。
- 左辺で **他の列** を選べる。列の選択肢は、その一覧の実際の列名から作る。
- **試してみる**欄に実データでの結果を出す。保存前に必ず結果が見える。

## 5. 作業スケジュールへの適用

タイムラインの「内容」欄は、選んだ項目ごとの**独立した列**にする。

```
変更前  | 区分 | 日付 | 時刻 | 内容                          | 作業 |
                            | L0055 / 一般用材 / A5052 / H34 |

変更後  | 区分 | 日付 | 時刻 | ロット番号 | 用途名 | 材質 | 調質 | 作業 |
                            | L0055     | 一般用材| A5052| H34 |
```

列の並び・幅・表示名・書式・読み替えは、対象 `timeline:<設備名>` として
**一覧とまったく同じ仕組み**で効く。タイムライン専用の設定画面は作らない
（覚えることを増やさないため）。どの項目を出すかは既存の
スケジュール内容表示マスタが引き続き決める。

行の高さがばらついて見える件は、**内容の量で行の高さが変わらないように
する**のが本質。列に分ければ1セル1値になるので、まずここで大きく揃う。
残りは実測して詰める。

## 6. 作業順

前の段が次の段の土台になる順に並べてある。各段は単体で動く状態で終える。

| 段 | 内容 | なぜこの順か | 状態 |
|---|---|---|---|
| 0 | **作業スケジュールの行高を均等化** | 既にご報告いただいている不具合。他と独立して先に潰せる | 済 |
| 1 | **一覧の列操作**（並べ替えD&D・幅D&D・表示/非表示） | 基盤は実装済み。画面へ適用するだけで日々の操作が楽になる | 済 |
| 2 | **列の設定パネル**（表示名・行間・プレビュー・計算列/ボタン列） | ③④⑤を載せる器。ここができると以降は「右ペインに項目が増える」だけ | 済 |
| 3 | **書式**（数値の小数桁・桁区切り・単位／日付時刻のパターン） | 器の上に載せる。プレビューがあるので設計・確認が速い | 済 |
| 4 | **読み替えルール**（表示ルールマスタ＋条件式ビルダー） | 最も作り込みが要る。他の列を参照するため、列の一覧が確定してから | 済 |
| 5 | **いつも使うソート** | 独立。フィルタと同じ構成なので短い | 済 |
| 6 | **タイムラインの内容欄を独立列へ** | 1〜4の仕組みをそのまま適用するだけで済む | |

各段でやること: 実装 → Playwrightで実測 → 回帰テスト追加 →
`tests/run_all.sh` 全通し → docs/changelog → コミット。

## 7. 決めておくこと（実装中に迷わないため）

- **列名（データ側）が同一性。** 表示名を変えても設定は追随する。
  逆にデータ側の列名が変わったら、その列の設定は付いていかない（別の列）。
- **設定はマスタ（共有）に持つ。** 端末ごとではなく運用として揃える。
  端末固有にしたい要望が出たら、そのとき別軸を足す。
- **fail-open。** 定義が読めない・壊れている場合は既定の見せ方で一覧を出す。
  一覧が出ないほうが困る。
- **保存は全置換。** 対象ごとに丸ごと入れ替える。部分更新にすると
  並べ替えと幅変更が競合したときにどちらが正か決まらない。
