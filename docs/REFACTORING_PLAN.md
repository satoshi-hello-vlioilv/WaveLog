## 0. 原則

1. **挙動を変えない**。リファクタのコミットに機能追加・不具合修正を混ぜない
   (不具合を見つけたら別コミットに分ける。§9.66〜§9.69 の修正はこの計画の
   準備中に見つかり、先に個別へ切り出した実例)。
2. **1フェーズ = 1コミット = 回帰グリーン**。フェーズ完了の条件は
   回帰テスト全件PASSと差分レビューのみ。途中で止めても壊れない順に並べる。
3. **実測で優先順位を決める**。以下の各フェーズには「このセッションで実際に
   踏んだ事故・手間」を根拠として付す。憶測の美化はしない。
4. バージョン規約: リファクタのコミットも `APP_VERSION` のpatchを上げ、
   CHANGELOGへ「内部整理・挙動の変更なし」と明記する(利用者が更新履歴で
   「何も変わっていない」ことを確認できるようにするため)。

## 0.2 分割・統合の判定基準

「大きいから割る」「小さいから混ぜる」では判断しない。基準は次の4つで、
**分割の解消(統合)も同じ基準で判定する**。

1. **プロセス境界・実行契約があるものは独立ファイル必須**。
   サブプロセスとして起動される(`rne_worker.py`)、利用者や運用が直接実行する
   (`start_app.py`/`process_manager.py`)、他importより先に読まれる必要がある
   (`_pycache_bootstrap.py`)——これらは行数に関係なく分割が正しい。
2. **依存の方向が違うものは独立が正しい**。起動側と業務側の両方から使われる
   (`logging_setup.py`/`boot_status.py`/`paths.py`)モジュールをどちらかへ
   混ぜると、逆方向のimportが生まれる。
3. **統合候補は「誰からも参照されない自己完結」と「名前と中身の乖離」**。
   公開ゼロ・参照ゼロの独立IIFE(実測: `worktime-benchmark.js`)や、
   ファイル名が責務を表していないもの(`measurement-worklog.js`の92%が
   マスタ管理)が対象。
4. **ファイル数のコストは言語で違う**。JSは`index.html`の読み込み順を手で
   管理しており1ファイル=管理コスト1件。Pythonはimportが明示的で
   ファイル数自体のコストはほぼ無い——**小さいだけのPythonモジュールは
   統合しない**。

#### 通しで回して初めて見つかったテスト側の欠陥

常設化の本体はここまでだが、**全件を通しで回すまで見えていなかった欠陥が
7件あった**。個別に動かしている限り表に出ないものばかりで、
「安全網を常設する」ことの実利がそのまま出た形になる。とくに4〜6は
「単体では通るが通しで回すと落ちる」順序依存で、しかも**修正するたびに
別のテストが落ちた**——1本ずつ潰すのではなく、状態を毎回揃える仕組み
(`reseed`)を入れて初めて安定した。

1. **落ちたテストがブラウザを閉じない** — Playwrightの終了処理は
   `process.exit(2)`で飛ばされるためChromiumが残る。残った画面は設備の
   編集セッションを掴んだままハートビートを打ち続けるので、後続の
   スケジュール系の書込が全て「編集中です」で弾かれる。
   **1本のFATALから8本が連鎖して落ちていた**(ロックが設定できない・
   並べ替えが反映されない、と一見別々の不具合に見える形で)。
   全37本の終了処理で必ず閉じるようにし、取りこぼしに備えて
   ランナー側でも1本ごとに掃除する(`reap_browsers`。
   `--user-data-dir=/tmp/playwright_chromiumdev_profile`で絞るため
   Playwrightが起動したものだけが対象)。
2. **ヘルパーの移設漏れと、実環境依存の設備名** — `test_scperm.js`が呼ぶ
   `setperm.py`を移していなかった。加えて同テストは設備`LS4`/`LS9`を
   前提にしており、フィクスチャに無いため行が0件になっていた。
   ヘルパーを追加し、設備名をフィクスチャの`テスト設備A`/`テスト設備B`へ。
3. **残っていた固定待ち** — `waitForTimeout`で描画完了を待っていた箇所が
   `test_screport.js`/`test_scperm.js`に残っており、直前のテストが残した
   状態次第で落ちた。行の出現そのものを待つ形へ変更。
4. **行を添字で掴んでいた** — `test_scperm.js`が`.sc-row-line`の2番目を
   並べ替えの対象にしていたが、他のテストが残した計画外実績
   (`data-id`が`actual:`で始まる行)がタイムラインの先頭に載るため、
   実績行を掴んでキー操作が何も起こしていなかった。単体では通り、
   **通しで回すと落ちる**典型。予定行だけを選ぶよう変更。
5. **テスト間でフィクスチャを戻していなかった** — 4の修正後、今度は別の
   3本が落ちた。`test_screorder.js`は並べ替えを実行し、ロックを掛けて
   から外す。その後片付け前にFATALで落ちるとロックが残り、後続の
   `test_scperm.js`の並べ替えが黙って効かなくなる。さらに並べ替えの結果
   自体がフィクスチャに残るため、**次の実行は前の実行の並び順から始まる**。
   実行のたびに結果が変わるのでは安全網にならないので、ランナーが
   **1本ごとに作業予定を種データへ戻す**ようにした(`reseed`)。
   併せて、行が取れないまま`.focus()`を呼んでFATALになり後片付けを
   飛ばしていた箇所を、FAILとして記録して`finally`で必ず解除する形へ。
   共有スケジュールDBは、gitが持つ原本ではなく`db/test_fixture/work/`の
   **作業用コピー**を使う。原本を直接書き換えると、テストを回すたびに
   追跡ファイルが変わり`git status`が汚れ続け、意味のないバイナリ差分が
   コミットに混ざる。
6. **テスト自身がロックした行を掴んでいた** — `test_sclock.py`の
   「作業中の直後の予定」は、ロック(固定開始)した行が現在時刻に追随せず

   同ファイル内の別の検証(`free_first`)は既にそうしていた。
7. **`trap`ではコンテナの死に対応できない** — 実行中にコンテナが再起動し、
   復元が走らないままパス設定が検証用フィクスチャを指して残った。**その状態で
   次の実行が「今の値」を退避すると、退避されるのはフィクスチャのパス**で、
   本来の設定が上書きで永久に失われる。退避値を`tests/.saved_paths.json`へも
   書き、復元できたら消す方式に変更。ファイルが残っていたら前回が復元前に
   終わった証拠なので、次の実行はそちらを真として復元する。
